手里是复印件：Glean 握着 agent 必经的权限层，但原件在别人手里

总体判断

这份是什么：按 101 memo 的路径走一遍 Glean。它没有上市，没有季报和业绩会，"管理层发言" 只有公司新闻稿、CEO Arvind Jain 的几次播客 (20VC、TNW) 和 Glean:GO 发布会。Knowledge Base 里直接谈 Glean 的材料不多 (约 8 份)，所以本篇一共用了 24 份材料，大半是周边材料：评估过或在用 Glean 的客户、做过同类产品的人 (前 Dropbox Dash 负责人)、渠道商 (NTT Data)、微软一线、以及 Atlassian、Asana 管理层谈"上下文层"和 MCP 的原话。估值对照 2025 年 6 月 F 轮 $72 亿和 Forge 二级市场价。

Executive Summary

一句话：Glean 是这批公司里产品最像"agent 最大公约数"的一家：它把公司 100 多个系统的内容连同每份文档的权限拉进一个索引，员工或 agent 提问时只看到自己有权看的东西。增长是真的 (ARR 15 个月从 $1 亿到 $3 亿)，但它不拥有权限本身，只是复制了一份；源系统厂商 (Slack、Atlassian、微软) 正在收回复制权、自己做搜索和 MCP，模型厂商 (ChatGPT、Claude) 正在把连接器聚到自己的入口。不买 $72 亿的价格；二级市场 Forge 价约 $57 亿接近合理但不便宜；值得买的价格是 $40–50 亿 (约 $27–34/股，NTM 收入 8–10 倍)。

增长：真的，而且不靠新功能噱头。公司公告 ARR $1 亿 (2025-02) → $2 亿 (2025-12) → $3 亿+ (2026-05)，$100 万以上合同一年约 3 倍，Fortune 500 客户一年近翻倍，85% 以上客户在 5 个以上部门使用，周活/月活 45%。CEO 自己说"正处圈地阶段"，被团队推着加大投入。但 5 月之后没有新数字；Forge 价一年跌了 36%，隐含估值从 $72 亿降到约 $57 亿，卖单是买单的 10 倍。

护城河：在"权限 + 排序"，不在连接器。NTT Data 的评估者说 Glean 在 SharePoint 上的检索准确度"明显更高"；Glean 自测比 ChatGPT company knowledge 准 1.9 倍、比 Claude 准 1.6 倍。但连接器本身正在被商品化：Rakuten 的 AI 负责人说用 Claude Code 写一个连接器不到一小时；评估过 Glean 的医疗客户说它和 Sana "黑盒上一样"，切换难度只有 2–3 分 (满分 5)。

三个威胁，按严重程度：(1) 微软捆绑：CEO 亲口说销售中最常听到的拒绝理由是"我们已经用 Copilot 了"；Copilot 付费席位已过 3,000 万，$30/月，主要用途正是"搜内部资料"。(2) 入口被模型厂商拿走：一家同时买了 Glean 的 AI 原生公司，员工的日常入口已经是 ChatGPT/Claude agent，它们直接读 Slack 做每日摘要；CEO 承认客户"每天"都在问 Claude 用 MCP 就能连系统，Glean 还有什么用。(3) 源系统收回数据：Slack 2025 年把第三方读取限到每分钟 1 次、禁止索引存储，Glean 在 Slack 上只能退回"实时现查"，搜索质量下降；Atlassian 把自己的 Rovo 搜索捆进订阅。

和 agent 最大公约数的关系：权限层确实是每个 agent 绕不开的门，但这扇门的"钥匙"在身份系统 (Entra、Okta) 和各个源系统手里，Glean 只是抄了一份门禁名单。当源系统说"数据原地调用、不许搬走"时 (Slack 已经这么做)，抄名单的人最被动。它的计费单位还是席位，不随 agent 用量增长 (一位客户内部人说 Glean "费用相对固定")，正在用 Flex credits 往按量转。

实心柱是公司公告的 ARR (只计软件订阅，不含服务；TechCrunch 指出因为有按量部分，$300M 更接近 run-rate)。虚线柱是我的推算：12 月到 5 月平均每月新增约 $1,800 万，假设之后放慢到每月约 $1,600 万，10 月约 $3.8 亿。Glean 过去每半年左右公布一次里程碑，5 月之后没有再公布，CEO 在 8 月的 Glean:GO 上拒绝回答能否做到 $10 亿收入。

公司基础

它是做什么的：技术和用例

一句话：Glean 是"公司内部的 Google + ChatGPT"。员工在一个框里问"上季度和沃尔玛的续约谈到哪了"，它同时去 Slack、邮件、Salesforce、Google Drive、Confluence、Jira 里找，挑出这个人有权限看的那几段，交给大模型写成一段带出处的回答。现在它还做 agent：不只回答，还去执行 (建工单、写邮件、更新 CRM)。

出身：2019 年由 Arvind Jain 创办。他在 Google 做了十多年搜索工程，之后联合创办了数据备份公司 Rubrik (已上市)。起因是他在 Rubrik 发现员工找不到公司内部的东西。所以 Glean 最早是一家"企业搜索"公司，2023 年起把搜索结果喂给大模型 (RAG，检索增强生成)，变成"企业 AI 助手"，2025 年起做 agent 平台。

先有体感：从最笨的办法开始

一家 1 万人的公司，知识散在 100 多个系统里。员工想知道"给欧洲客户的退款政策最新版是什么"，最笨的办法是自己去每个系统里搜：Confluence 搜一遍，Google Drive 搜一遍，Slack 搜一遍，再问同事。每个系统的搜索框各不相同，搜出来的结果也不知道哪个是最新的。把这件事做成"一个框、一秒钟、一个准确答案"，要过六关：

  1. 连接器 (接进来)。每个系统一个接口，用对方的 API 把内容拉出来，之后持续增量同步 (有人改了文档，几分钟内要更新)。难点是数量和脏活：100 多个系统，每家 API 不同、有限速、会改版。Glean 说有 100+ 到 250+ 个连接器。这一关正在变容易：现在用 Claude Code 写一个基础连接器不到一小时，各家 SaaS 也开始自带 MCP 接口。
  2. 权限 (最关键的一关)。每份文档谁能看，在每个源系统里规则都不一样：Google Drive 是"知道链接的人"或指定人，Slack 是频道成员，Salesforce 是角色层级加共享规则，SharePoint 是层层继承。Glean 要把每份文档的权限和内容一起拉进来，并且跟着源系统实时变 (有人离职、被移出频道，几分钟内要生效)。错一次的代价是实习生搜到 CEO 的薪酬表、销售看到并购文件。这是企业不敢让 ChatGPT 直接读 SharePoint 的原因，也是 Glean 卖给 CIO 的核心理由。
  3. 索引 (找得到)。把几十亿段文字做成两套索引：关键词索引 (像书末的索引，搜"SOC 2"必须精确命中) 和向量索引 (按意思搜，"退款政策"能找到写着"退货及补偿规定"的文档)。两套一起用叫混合检索。Glean 说它累计索引了 270 亿份以上文档。这一关的技术是公开的，Elastic 等都能做。
  4. 排序 (找得准)。这是 Jain 的 Google 本行，也是最难抄的一关。公开网页有链接和海量点击，谁被引用多谁排前面；公司内部没有这些信号，一份文档可能一辈子只被 20 个人打开。Glean 用的是"知识图谱"：谁写的、谁最近看过、作者和提问人是不是一个组、这份文档在 Slack 里被转了几次、是不是最新版。同一个问题，销售和工程师看到的排序不同。专家说 Glean "检索准确度明显高于" 同类，靠的就是这一关。
  5. 生成回答 (RAG)。把排在前面的几段原文和问题一起交给大模型，让它写成带引用的回答。Glean 不自己训练模型，可以接 GPT、Claude、Gemini 或开源模型，约 70% 的请求自动路由到合适的模型。CEO 说 90% 以上企业任务用便宜的模型就够，这是它卖给 CFO 的"省 token"故事。
  6. Agent (去执行)。多步任务：读几个系统 → 推理 → 动作 (在 Jira 建单、给客户起草邮件、更新 Salesforce 字段)。动作必须以发起人的身份执行，不能越权。2026 年 8 月 Glean 发布了 "Independent agents"，让 agent 有自己的身份和权限。

为什么"直接用 MCP 连所有系统"不等于 Glean：MCP 是 2024 年底 Anthropic 推出的一个通用插头标准，让 ChatGPT、Claude 这类助手可以现场调用各家 SaaS 的接口。它解决了第 1 关 (连接)，权限也由各家系统自己把关。但它没有第 3、4 关：没有统一索引和跨系统排序。每次提问，模型都要现场去 10 个系统各搜一遍，再自己判断哪条最相关，各家自带的搜索又很弱。Jain 的说法是这像"暴力破解"，又慢又费 token；Glean 自测说 Claude 先调 Glean 拿上下文，速度快一倍、token 用量减半。空头的回答是：模型越来越强、越来越便宜，各家 SaaS 自带的搜索在变好 (Atlassian 说接上自己的 Teamwork Graph 后结果好 48%、token 少 44%)，"现查"的质量够用之后，就不需要再养一份复制的索引。这是 Glean 这笔投资的核心分歧。

客户买回去之后的一天：八个部门怎么用

以一家 1 万人的软件公司为例。下面的场景来自 Knowledge Base 里的客户和专家纪要、Glean 公开案例和产品文档；标了"纪要"的是专家原话里的真实用法。

  • 1. 新员工 (全员)。入职第一周问"报销怎么走""我们的产品和竞品比差在哪""谁负责欧洲区定价"。以前要问 5 个同事，现在一个框回答，并给出原文链接。纪要：一家 120 人的公司评估 Glean 时，最看重的就是新销售入职时跨 Slack、Jira、Google Drive、Confluence 找产品和客户信息，评估者说用户粘性"极高"。
  • 2. 工程 (值班排障)。凌晨支付服务报错，值班工程师把报错信息贴进去，Glean 找出上次类似事故的 Slack 讨论、复盘文档、相关 Jira 工单和修过这段代码的人。纪要：Glean 自己的工程团队做了一个分诊 agent，自动处理约 95% 的生产问题，替代了 15 人的值班轮岗，但每月花 $100 万 token，比人还贵 (CEO 原话)。
  • 3. 客服。客户问"你们的 API 支持欧盟数据驻留吗"，坐席在工单旁边直接拿到答案和出处，并看到这个 bug 在 Jira 里的修复状态。纪要：CEO 说客服是 ROI 最清楚的场景，坐席每天结案从 10 个到 12 个，因为他们大量时间都在读知识库、给客户摘要。
  • 4. 销售。见客户前问"这家客户过去一年跟我们谈过什么、有哪些未解决的问题"，Glean 汇总 Salesforce 机会、Gong 通话记录、邮件和内部 Slack 讨论，生成一页会前简报；收到 200 题的安全问卷 (RFP)，agent 从过往答案里自动填好 80%。纪要：NTT Data 评估的横向 AI 用例里，RFP 自动化排在前面。
  • 5. HR / 员工服务。"育儿假在德国是几周""401k 匹配比例"。同一个问题，德国员工和美国员工看到的答案不同，因为政策文档的权限和适用地区不同。
  • 6. IT 服务台。"VPN 连不上""怎么申请 Figma 席位"。先给答案，答不了就自动开工单。这正是 Moveworks (已被 ServiceNow 以 $28.5 亿收购) 的地盘，所以 IT 是 Glean 和 ServiceNow 交锋最多的场景。
  • 7. 法务。"我们和哪些客户签过无上限赔偿条款""2023 年欧洲基础设施合同批准过哪些合规例外"。合同库权限极严，只有法务能看到。纪要：Salesforce 一位工程师举的企业搜索典型问题就是这一句，企业审计显示知识工作者每周省 3–5 小时。
  • 8. 管理层和产品经理。"我团队这周做了什么"：从 Jira、Slack、文档自动汇总周报；新加入一个项目，让 agent 把过去三个月的决策和争论整理成一页。纪要：一家买了 Glean 的 AI 原生公司里，员工把"每天汇总 Slack 各频道要点"交给了 ChatGPT/Claude agent，而不是 Glean。这是 Glean 最该担心的画面。

使用强度：公司说每用户每天约 5 次查询，周活/月活 45%。外部数据更冷：一家制造业客户说普通员工每天最多用 AI 两三次 (改邮件、查 Outlook、做 PPT)；Deep|LLM 调研里欧洲一家保险公司 Copilot 全员可用，但只有 2–3% 的人产生实际业务价值；CEO 自己说用量是幂律分布，5% 的人每月花 $1–1.5 万 token，大多数人约 $20。按席位收费的产品，靠的是那 95% 的轻度用户也愿意续费。

常见疑问

  • "为什么不直接用 Copilot？"Copilot 在微软自家数据 (Outlook、Teams、SharePoint) 上有天然优势，第三方系统靠 Copilot connectors 接，质量和数量都弱于 Glean。买 Glean 的多是"不全押微软"的公司：用 Google Workspace、Slack、Atlassian 的科技公司 (Databricks、Canva、Duolingo、Reddit 都是客户)。但只要公司已经是 E5 客户，$30 的 Copilot 很难被一个 $50–75 的独立产品打败。
  • "它是不是向量数据库？"不是。向量数据库 (Pinecone、Elastic、MongoDB 的向量检索) 是零件，Glean 是成品应用：连接器、权限、排序、界面、agent 都做好了，IT 开通后员工直接用。一位前 Orion 高管说 Glean "只是向量库加距离算法"，这是外行的误读，但也说明买方未必看得出它的技术差异。
  • "和 Elastic 是什么关系？"Elastic 是引擎，Glean 是整车。Elastic 曾经有自己的 Workplace Search (Glean 类产品)，已经停掉。
  • "Slack 关 API 到底意味着什么？"2025 年 5 月 Slack 把非官方市场应用读取消息的速度限到每分钟 1 次、每次 15 条，并禁止第三方长期存储和索引消息。对 Glean 来说，大多数客户的 Slack 从"全文进索引、参与排序"降级为"提问时现场去 Slack 搜"，私信和私有频道只能关键词搜，"每日摘要"功能不再支持。只有拿到 Slack 书面豁免的客户例外。Slack 是很多科技公司最大的知识来源，这一刀切在要害上。
  • "会不会被 Snowflake / Databricks 吃掉？"基本不重叠。数据平台管的是结构化数据 (表格、交易、日志)，买家是数据团队；Glean 管的是非结构化文档和对话，按席位卖给 CIO，每份文档带个人级权限。Databricks 自己就是 Glean 客户和投资人。两边会在"给 agent 提供上下文"这一层相遇 (Snowflake、Databricks 都在做 catalog 和 MCP)，但不是今天的主战场。

放回 agent 最大公约数

我们之前把企业 agent 的一次任务拆成 9 步 (入口 → 读上下文 → 推理 → 调工具 → 授权 → 安全 → 写回 → 观测审计 → 成本治理)，分成三类：按量但可换、按门不可换、交集。Glean 横跨第 1 步 (入口) 和第 2 步 (读上下文)，并且复制了第 5 步 (授权) 的结果。按这个框架它的位置是：

  • 入口 (第 1 步)：可换，而且正在被换。Copilot、ChatGPT、Claude 都在抢，Glean 在入口之争里资源最少。
  • 读上下文 (第 2 步)：这是 Glean 真正的位置，属于"按量但可换"：每个 agent 步骤都要读数据，所以用量指数增长 (Glean 的 token 一个季度翻倍)；但供应商可换，因为源系统可以自己提供 (Atlassian Teamwork Graph、Asana MCP)。
  • 授权 (第 5 步)：Glean 不拥有，只是镜像。权限的原件在身份系统和源系统，这也是我们认为身份层 (Okta、SailPoint、CyberArk) 可能被低估的原因：Glean 的困境反过来说明，谁拥有原件谁就有定价权。Slack 收回 API 是"原件持有人"第一次公开行使这种权力。

结论：Glean 证明了"带权限的上下文"是 agent 的刚需，但没有证明它自己能长期拥有这一层。我们之前的"规律 3：数据原地调用不搬家，权限不随数据走"，Glean 是最直接的受害者。

买点

IPO 或二级市场的买点：股权估值 $40–50 亿 (约 $27–34/股，NTM 收入 8–10 倍，当前 ARR 11–13 倍)。在 $50 亿，基准情景不扣 SBC 年化约 15%、牛市 33%、熊市约 -10%；在 $40 亿，基准约 20%。理由是 Glean 的终局分歧比 Databricks 大 (入口可能被拿走)，所以要求比 DBX 更高的安全边际。Forge 现价 $38.90 (约 $57 亿) 高出买入区上沿约 15%，而且流动性很差 (可见买价只有约 $20/股)。

IPO 定价：如果 IPO 定在 $100 亿以上 (按银行通常要求高于上一轮)，基准情景回报为负，不参与。如果市场情绪差、IPO 在 $50 亿以下，而且 S-1 显示净留存 ≥ 120%、毛利率 ≥ 70%，值得参与。

敏感性：假设每用户 $60/月，ARR $3.8 亿约等于 53 万付费席位。如果一个 1 万人的客户把一半席位换成 Copilot，ARR 减少约 $36 万；需要大约 100 个这样的客户同时这么做，ARR 才少 10%。所以风险是慢性的，不会一个季度暴露。
