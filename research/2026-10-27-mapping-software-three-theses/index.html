软件三条线：上云、coding、agent 基础设施

把软件的变化归成三条线，套到 IaaS、PaaS、SaaS 和 IT 服务的 92 家公司 (含 PLTR、AMZN、GOOGL)，逐家打分，看谁受益谁受损、市场定价了多少、预期差在哪。

18.5x三条都拿的 EV/S 中位
3.6x受损组 EV/S 中位
+115%三条都拿组相对公允线
18家被 coding 打到 (T2 < 0)

一页结论

一句话：三条线是同一件事的三个时间点。上云是底盘 (还剩 70% 以上的工作负载没搬)，coding 是现在 (2026 年财报里已经看得见)，给 agent 配基础设施是下一波 (预算刚开始从试点转向生产)。三条线都在把钱推向同一处：按"机器干了多少活"收费的底层，并把钱从按"有多少人在用"收费的界面和人工那里拿走。

谁三条都拿：云厂商、SNOW、DDOG、NET、CRWD、PANW。它们按用量收费，工作负载、代码、agent 三者都会变成它们的账单。

谁受损：IT 服务 (印度外包、EPAM 最重)、席位型协作工具 (MNDY、HUBS、WIX)、按员工数收费的 HCM 和薪酬 (WDAY、ADP、PAYX)、靠"写软件贵"守住的长尾垂直软件 (CSU、ROP、TOI)。其中 coding 是唯一一条有大量输家的线。

PLTR 在哪：它是"部署层"，把 agent 放进真实业务流程并为结果负责。三条线里它主要吃第三条 (+2)，是 T3 最直接的受益者，但估值已经要求未来五年 40% 以上的复合增长。

市场已经定价了：三条都拿的一组 EV/S 中位 18.5 倍，受损组 3.6 倍。扣掉增速和利润率之后，前者仍比公允线贵 +115%，后者便宜 -30%。所以光说"谁受益"已经赚不到钱。

预期差可能在两处：(1) 吃到两条以上、但估值只在公允线附近的：SAP、DT、NOW、VEEV、ESTC；(2) 被归为受损但估值没打折的：ADP、PAYX、GTLB、ROP。

打分是判断，不是测算。标 R 的公司我们做过研究，分数有数据支撑；标 M 的公司来自 mapping 笔记加公开信息推断，可信度低一档。估值用 2026-10-26 的 mapping 估值库。

方法：每家公司回答三个问题

每家公司回答三个问题，每个问题打 -2 到 +2 分。

线问的问题+2 是什么样-2 是什么样
T1 上云迁移这件事里，你是目的地、搬家公司，还是被搬走的旧房子？目的地，按用量收费 (AWS、SNOW、DDOG)旧房子：本地硬件、本地防火墙 (CHKP、NTNX)
T2 coding 加速你的收费单位跟着"软件数量"涨，还是跟着"写软件的人数"涨？你能被"自己写一个"替代吗？软件、代码、部署越多收得越多 (SNOW Cortex Code、NET Workers、FROG 制品)按开发者席位收费，或者卖的就是写软件的人工 (EPAM、TCS、MNDY)
T3 agent 基础设施你是每个 agent 都必须经过的门，还是给人用的界面？数据、身份、记录、监控、安全、部署 (OKTA、SAIL、PLTR、AMZN)按人头收费的界面：agent 越多，人越少，你越少 (HCM、会议、文件)

净分 = 三项相加。净分高说明三股力量同向；但三条线时间不同，T1 已在报表里，T3 大多还在路上，所以 T3 得分高的公司是"未来的受益者"，不是"现在的受益者"。

为什么这三条能覆盖软件行业：软件公司收的钱，要么跟着工作负载走 (算力、存储、数据、监控)，要么跟着人走 (席位、员工数、人工小时)。上云和 coding 都让工作负载变多、让写软件的人变少；agent 让干活的人变少、让机器调用变多。所以三条线是同一个方向的三次推力。

市场已经怎么定价

左：各组 EV/S 中位数 (PLTR 和没有估值的 AMZN、GOOGL 不计)。右：先用全部 91 家公司拟合"EV/S 对收入增速和 FCF 利润率"的公允线，再看每组相对公允线贵多少 (中位数)。公允线来自质量 × 增长 mapping。

三条都拿的一组，增速中位只有 24%，但估值比同样增速和利润率的公司贵一倍多。市场不是按今天的增速给价，而是按"这三条线的方向"给价。反过来，受损组比公允线便宜三成，也已经打了折。

这意味着："谁受益"这个问题，市场已经大体答对了。能赚钱的地方只有两个，一是市场排错了的公司，二是时间：T3 还没进报表，谁先把"门"变成收费项目，谁就会被重估。

PLTR 放在哪

PLTR 是什么层：它不卖数据库、不卖监控、也不卖席位，而是把一家企业的数据、规则和流程建成一个模型 (Ontology)，再派工程师 (FDE) 驻场，把 agent 放进真实的生产流程，并对结果负责。用前面的比喻：如果 agent 是 1,000 个不知疲倦但没有常识的实习生，PLTR 就是那个把实习生安排进具体岗位、写好规则、并且出事了有人负责的公司。

公司层上云codingagentEV/S增速相对公允线理由
PLTR部署层 / 边缘平台+1+1+248.060%—拥有部署层 (Ontology + FDE)：收入 +93%、NDR 157%，新增 80-90% 来自老客户

三条线怎么打：T1 +1，PLTR 跑在各家云上，迁移对它是中性偏正；T2 +1，写代码便宜了，FDE 的交付更快、单个工程师能服务更多客户；T3 +2，是"部署层"本身。

和谁比：它和埃森哲在做同一件事 (把 AI 放进企业)，但收费方式相反。埃森哲按人头和小时收钱，coding 让小时变少；PLTR 按平台收钱，FDE 是成本不是收入。这就是为什么同一个趋势里 ACN 净分 0、PLTR 净分 4。

估值：EV/S 约 48 倍 (估算，不在 91 家估值库里)。我们 10 月 26 日的结论是基本面最好 (收入 +93%、FCF 利润率 63%)，但新增收入 80-90% 来自老客户，当前股价需要未来五年 40% 以上复合增长；买点 $130-150 (现约 $197)。

要盯什么

  • T3 是不是在变成收入：OKTA 和 CyberArk (PANW) 是否开始给"非人身份"单独定价；NOW 的 AI ACV (现 >$10 亿)；SAP 的 BDC；DDOG 的 MCP 和 LLM 监控。门开始收费，就是 T3 进报表。
  • T2 的输家是否在加速：印度 IT 服务的应用开发和维护收入；GTLB 和 TEAM 的席位增速；MNDY 和 HUBS 的新增客户。
  • 按员工数收费的是否被验证：WDAY、ADP、PAYX 的单客户员工数 (每家都会披露"每客户员工数增长"或"pays per control")。
  • 受益者的单价：DDOG 和 SNOW 都是量涨价跌；如果单价降得比量涨得快，"受益"就不变成收入。最大 AI 客户的去留是最好的先行指标。
