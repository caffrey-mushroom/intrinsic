Claude Duet 是 Anthropic 10 月 21 日放出的一个独立 app (research preview，排队申请)，让 Claude 当你的"主动型助理"：每天早上给你一份简报，白天每隔几个小时巡一遍你的邮箱、日历和接入的应用，有事才来找你；你交给它的活，它在自己的云电脑上做完，发消息、付款、签字、删除之前必须等你点头。它不是新模型，背后是 Opus 5.5；也不额外收费，但它在后台干的每一件事都算进你 Pro / Max 套餐的额度。

Duet 是把 Claude 从"你来问它才答"改成"它定时来敲门"。底下是同一个 Opus 5.5，变的是触发方式：用量不再取决于你开几次 app，而是取决于它每天巡几次、你交给它几件大活。

它适合的活有一条线：能等几个小时、最后一步可以让你点一下确认。早报、整理收件箱、追发票、约会议、做 deck 和模型都在线内；要秒级反应的盯盘、打电话、动钱、Microsoft 365 用户的工作流，现在都做不了。

对 token 需求是加项。按我的估算，一个正常使用的 Duet 用户每天约 120 万 token，是普通聊天用户的几十倍；按 API 标价折算每月约 $40，已经超过 Pro 的 $20。所以额度会卡住它，它更像把用户往 Max 推的产品，而不是靠自己收钱的产品。

竞争上它是第三个到场的：Meta Muse (9 月) 和 OpenAI Dots (9 月 29 日) 早了三到六周，形态几乎一样。差别不在模型，在谁能接进你的邮箱和办公软件：OpenAI 和 Microsoft 合作，Duet 目前还接不了 Microsoft 365。

Follow-up (复查 2026.11.22)

自己跑一天，量它吃了多少额度。 这是"每用户每天约 120 万 token"这个数唯一能做硬的办法，Anthropic 和所有评测都没公布一次巡查或一个任务的消耗。拿到资格后，用默认设置跑一个工作日，记下 5 小时额度和周额度用掉的百分比。如果一天就用掉 Pro 周额度的三分之一以上，说明我的估算偏低，"Duet 是 Max 的导流产品"更成立；如果一天不到 5%，第 7 节的 base 要往下砍一半。

巡查间隔会不会缩短，或者改成邮件一到就推送。 现在"每隔几个小时"是 Anthropic 为了省额度主动选的 (官网原话：一直查会更快用完额度)。如果改成实时推送 (Gmail 有 push 接口)，每用户的后台 token 会翻几倍，第 7 节的"后台每天"参数要从 0.6M 往 2M 以上调；如果一直维持几小时，后台部分是小头，增量主要看大任务。

额度和价格怎么调。 OpenAI 给 Dots 配了一个 $500/月 的新档。看 Anthropic 会不会为 Duet 单独加档、或者提高 Max 的额度。加了，说明后台用量大到值得单独收钱，是 token 加项的直接证据；不加、而是缩短 preview 名额或降 effort，说明算力是约束。

Team / Enterprise 和 Microsoft 365 什么时候上。 现在只有美国的个人 Pro / Max 用户，M365 不支持，Slack 支持有限。企业用户和 Outlook 是工作场景的大头。三个月内上了，Duet 的用户池从"美国个人付费用户"扩到企业座席；迟迟不上，而 OpenAI 已经在和 Microsoft 做 Agent 365 管理，企业这块会先被 Dots 拿走。

1. 是什么

一句话：Duet 是一个住在云端的 Claude 助理，定时巡查你接入的应用，有事来找你，你交代的活它自己做完，关键一步等你签字。

底层怎么工作

  • 同一个模型 (Opus 5.5，用户不能换，effort 由它自己定)，同一套记忆、skills 和连接器，跟你平时用的 Claude 共享
  • 多了三样东西：一个定时器 (每天早上 + 每隔几小时触发一次)；一台它自己的云电脑，带浏览器，你关机它也能继续干；一套审批流程，敏感动作先停下来等你点头
  • 所有对话在一条主线程里，可以按主题另开频道，频道之间共享记忆。Tasks 页列出在做的事和等你决定的事，Make 页放做好的文件 (deck、模型、dashboard)

贯穿全篇的比喻：顾问 vs 助理

普通的 Claude 是一个坐在办公室里的顾问：你推门进去问，他才回答，你走了他就停。Duet 是一个助理：

  • 巡查：每隔几个小时把你的邮箱、日历、Slack 翻一遍 (这就是"主动")
  • 跑腿：你交代的活他在自己的电脑上做，做完放你桌上
  • 签字：要以你的名义发信、付钱、签合同、删东西，先拿给你签字
  • 钥匙：你给他哪些应用的钥匙 (连接器)，他就只能进哪些房间。他拿到的是门卡，看不到你的密码

核心指标就两个：巡查间隔 (多久来一次，决定急事会晚多久到) 和每次巡查、每次跑腿要读多少字 (决定 token 用量，也就是决定额度够不够)。

和最近的替代品差在哪

Claude 里本来就有定时任务、Research、Cowork 这类能后台干活的功能。Duet 的不同是把它们收成一个"人"：一个入口、一条线程、它主动找你。同类产品是 Meta Muse 和 OpenAI Dots，三家都有自己的云电脑和浏览器、都在你离开后继续干、都在关键动作前要你批准，形态几乎一样 (见第 3 节对比表)。

拿来干什么：一个具体例子

拿你自己的工作流举例。今天：早上你让 Claude 跑 morning brief，看完邮件再一个个去开 thread 让它做 earnings preview、更新模型。用 Duet 之后：它 7 点自己把早报推给你，里面已经标出"LRCX 明天出业绩，preview 草稿已开始"；下午巡查时发现卖方新发了一份模型，自动放进 Make 页；你只需要在手机上看完、点"发布"。形态上和你现在用的"一个项目聊天 + 多个 thread"很像，区别是它会主动开工，而不是等你开口。

现在到哪一步

  • Research preview，排队申请，分批发邀请。只开美国的 Pro / Max 个人用户，Team / Enterprise 和海外都还没有
  • iOS、Android 独立 app，加上 claude.ai 网页版
  • 官方自己列的不足：会读错线程、判错轻重缓急；两次巡查之间来的事会漏；你还看不到它的浏览器在干什么；订票这类个人杂事还弱
  • 不支持：给别人打电话发短信、Microsoft 365、证券交易和账户间转账 (批准了也不行)；定时任务用不了自定义连接器 (Every 评测发现)

2. 机制：能力从哪来，卡在哪

把 Duet 干一件事拆成五段串起来，最弱的一段说了算：

段在干什么现在的水平谁定义
1 触发什么时候去看早上一次 + 每隔几小时。不是实时Anthropic，受额度和算力成本约束
2 读能看到哪些数据Google 系、Slack (有限)、Stripe 等。没有 Microsoft 365；定时任务用不了自定义连接器邮箱和办公软件平台 (Google、Microsoft) + 连接器作者
3 判断哪件事要紧官方自承"会判错轻重缓急"模型 (Opus 5.5) + 你的记忆和 skills
4 做在云电脑上干活文档、deck、模型、dashboard 强 (评测认可)；订票等个人杂事弱；你还看不到它的浏览器Anthropic (云电脑 + 浏览器)
5 签字敏感动作等你批发信、付款、签字、删除必须批；动钱转账、交易一律禁止你；规则由 Anthropic 定
  • 今天卡在第 1、2 段，不在模型。 模型够聪明是三家共同的前提；用户感受到的差别是"急事几小时后才知道"和"我的 Outlook 接不进来"
  • 第 1 段的旋钮在 Anthropic 手里，但它被钱绑住。 巡查越勤，每个用户每天读的字越多，额度越早用完。官网直接说了"一直查会更快用完额度"
  • 第 2 段的门在别人手里。 企业邮箱和日历大头在 Microsoft，而 Microsoft 在和 OpenAI 把 Dots 接进 Agent 365。谁定义瓶颈段，谁有议价权；在 M365 用户身上，Anthropic 现在是没拿到钥匙的那一方

一句话：Duet 的上限今天由"多久巡一次"和"能拿到哪些钥匙"决定，前者是成本问题，后者是平台问题，都不是模型问题。

4. 一句话规则

这件事的响应时限是不是长过巡查间隔 (几个小时)，而且所有不可逆的那一步都能停下来等你点一下？两条都是，就能交给 Duet。

  • "几个小时"是可量的：今天的巡查间隔。它缩短，规则的边界就外扩
  • "不可逆的那一步"指发出去、付出去、签出去、删掉。这些 Duet 一律等你；动钱转账和交易连等你都不行
  • 用这条规则：追一张逾期发票 (能等半天，发之前给你看) → 行；客户投诉要 10 分钟内回 → 不行；帮你卖一笔股票 → 不行

一句话：能等几个小时、最后一步能等你签字的活，交给 Duet。

7. 落到核心议题：token 是加项

聊天产品的用量是"你问一次它答一次"，你不开 app 就是零。Duet 把它变成"每人每天固定巡几次 + 偶尔一件大活"：用户不打开 app，用量也照样发生。这是对 token 需求的直接加项。问题只在加多少，以及谁付钱。

按 Opus 5.5 API 标价 (第三方转述：输入 $4、输出 $20、缓存读取 $0.20，每百万 token) 折算：85% 读命中缓存时，混合单价约每百万 $1.15，一个用户每天约 117 万 token，约 $1.35，每月约 $41。这比 Pro 的 $20 高一倍。这不是 Anthropic 的真实成本 (成本远低于标价)，而是说：如果它按 API 卖这份算力，值这么多；它选择含在套餐里，就只能靠额度和"几小时一次"控制用量。

计算器：拖参数

为什么不会更多

  • 额度是硬顶。 每个人能用的 token 被套餐额度封顶，Duet 只能在额度里重新分配：后台吃多了，你自己聊天就少了。所以"更多 token"最终要靠用户升级到 Max 才会兑现
  • 巡查间隔是 Anthropic 自己的阀门。 它选了几小时一次，就是在控制每用户成本
  • 用户池窄。 美国、个人、Pro / Max、排队。企业和海外都没开

谁拿钱

  • Anthropic：收入来自用户从 Pro 升到 Max (每人 +$80 到 +$180/月)，不是 Duet 本身。它也是对你 thesis 里"拿钱份额"那条线的又一个支撑：消费端越来越像 Apple 卖硬件那样卖整包体验，而不是按 token 卖
  • 算力和内存：后台 agent 读多写少、反复读同一段上下文，缓存命中高。这类用量对 KV 缓存的容量和保留时长要求更高 (同一个用户的上下文要留几个小时等下次巡查)，对 HBM 和 SSD 存 KV 是加项
  • 被挤压的：单点的邮件助手、日程助手、小企业的记账提醒类 SaaS。被三家大厂同时用"含在订阅里"的方式覆盖

一句话：Base 情形下 Duet 一年约相当于 $10 亿的 Opus 算力 (按 API 标价)，约占 Anthropic $650 亿 run-rate 的 1.5%；Bull 到 20% 左右。量是加项，钱主要通过 Max 升级收。

9. 最容易被误读的几点

大家以为实际
Anthropic 出了新模型同一个 Opus 5.5，新的是壳：定时器 + 云电脑 + 审批
免费送了一个助理不另收钱，但吃你的额度；按我估算 Pro 用户会明显更快撞线
它 24 小时盯着我的邮箱每隔几小时看一次，急事可能晚到几小时
它能替我花钱、管钱付款每笔要你批，用一次性虚拟卡；转账和交易一律不做
Anthropic 落后了晚了三到六周，形态几乎一样；真正的差距在 M365 和企业版，不在模型
它能接 6,000 个应用，比 Dots 多数法都是"市场里的连接器和插件总数"，质量和可用范围才是关键，而 Duet 在 M365 上是空白

一句话：Duet 是一个"几小时来敲一次门、要你签字"的助理，不是一个新模型，也不是一个替你全自动办事的代理人。
