可观测性竞争格局

把可观测性的竞争拆成三层 (工作流、数据存储、接口) 和三类客户 (传统大企业、中型与云原生、AI 实验室)，标出谁从谁手里拿份额、谁威胁哪一层；并逐条核对 Caffrey 的框架。

一句话格局

一句话：可观测性的竞争要拆成三层看，三层的格局完全不同。工作流层 (出事时工程师打开谁的界面) 在集中，Datadog 是赢家；数据存储层 (数据最后存在哪、按 GB 付给谁) 在分散，钱往更便宜的地方漏；接口层 (谁来问问题，人还是 agent) 正在重新洗牌。

你的框架基本是对的。要改的有三处：OpenAI 没有"全面迁到 ClickHouse"，只搬了日志，指标去了 Chronosphere，链路还在 Datadog；Grafana 不是"按数据价值收费"，它仍按量收费，只是会自动丢掉没人用的数据；OpenTelemetry 是行业标准，不是 Grafana 的。另外框架里漏了两股力量：安全巨头 (Cisco、PANW) 在抢日志预算，管道层 (Cribl、BindPlane) 在数据入库前就把量砍掉。

把你的各条放进三层：Splunk / New Relic / Dynatrace / Elastic 的故事都发生在工作流层和传统日志存储；Grafana、Chronosphere、ClickHouse / 湖仓的故事都发生在数据存储层；MCP 和 Claude Code 是接口层。Datadog 对三层的打法不一样：工作流层进攻，存储层主动让 (Flex Logs、Federated Logs、BYOC)，接口层自己先做 MCP 和 Bits。

逐条核对你的框架

逐条对照我们的专家纪要、业绩会和卖方材料。"对，补一句"表示结论成立、我们加了数字或例外；"部分对"表示一半成立；"要修正"表示和证据不一致。

你的说法核对结果证据和来源
DDOG 产品最强，在拿份额对，补一句拿份额对。"最强"要换个说法：它不是每一项都最强 (日志搜索 Splunk 强，自动根因 Dynatrace 强，价格 Grafana 便宜)，而是唯一每一步都够好、而且连在一起的。证据：非 AI 客户收入增速 19% → 23% → mid-20s (Q1'25 → Q1'26)；渠道专家估计 Datadog 净新增客户 +30%，Dynatrace 20–25%。
Splunk、New Relic 丢份额给 DDOG，因为被收购后客户不满对，补一句对。补两点：AppDynamics (2017 年被 Cisco 收购) 也是同一个故事；大型受监管金融机构不会拿 Datadog 去换掉 Splunk 做 SIEM (PNC 云平台专家)，所以 Splunk 守住的是安全日志，丢的是运维监控。
DT 主要赢传统大客户 (特别是金融)，首单 20 万；DDOG 通常 1–2 万再扩，所以正面竞争不多部分对数字对，口径要改：Harzog 原话是平均新单年费，Dynatrace "north of $200,000 a year"，Datadog "$10,000 or $20,000 a year"，不是严格的"首单"。Datadog 的起点其实更低，2024 年底起月消费 $500 就签约 (FundaAI 转述前销售)。"正面竞争不多"只对入口成立：到了大企业整合阶段两家会碰上。渠道专家说 Datadog 靠价格和商务弹性赢 Dynatrace；PNC 专家说复杂的老金融环境里 Dynatrace 更好。
Elastic 靠日志和搜索起家，基本是 win from Splunk对Malloy (前 Elastic)：全栈可观测性上 Elastic 很少从 Datadog、Dynatrace 赢单，"Splunk, absolutely"；Elastic 内部的竞争应对材料全部针对 Splunk。
Grafana 做的是 OTel 标准要修正OpenTelemetry (OTel) 是 CNCF 管的中立行业标准，2019 年由 OpenTracing 和 OpenCensus 合并而来，Datadog、Dynatrace 也都支持。Grafana 自己的是 LGTM 开源栈 (Loki 日志、Grafana 仪表盘、Tempo 链路、Mimir 指标) 加 Prometheus。准确说法：Grafana 最拥抱 OTel，所以在"不想被锁定"的客户那里最受益。
比 DDOG 便宜 20%对Conrad (前 Datadog 中端市场 AE，之前在 Grafana Labs)：Grafana Cloud "usually a reduction of around 20%. It's not as dramatic anymore as it was"。如果客户自己托管 Grafana Enterprise，省得多很多。
用来做低价值数据的监控对Conrad：企业按优先级分层，关键应用留在 Datadog / Dynatrace，开发测试环境、部分指标和日志分流到开源；"不差钱时首选 Datadog 或 Dynatrace，Grafana 排第三"。
开源起家，几乎所有工程师都用过对Grafana 仪表盘是事实上的行业标配；印度等地初创公司大量用 Grafana + Prometheus 开源栈，再升级到付费版 (前 Datadog 员工)。
计费逻辑是"按数据价值"而非"按数据量"要修正Grafana Cloud 仍按量收费：按活跃指标序列、按 GB 日志和链路、按用户。它的不同在于 Adaptive Metrics / Adaptive Logs 功能会找出没人查的数据，自动聚合或丢掉，客户就不用为它付钱。更准确的说法是"只为被用到的数据付钱"。这条来自 Grafana 公开的定价和产品页，我们的知识库里没有专家讲到这一点。
可以自托管，适合 OpenAI、Anthropic部分对能自托管对。但 AI 实验室自建走的不是 Grafana：OpenAI 日志用自建的 ClickHouse，指标给了 Chronosphere；Anthropic 底层存储也用 ClickHouse (FundaAI 渠道专家)。Anthropic 确实是 Grafana 的客户，但它同时是 Datadog 最大的客户之一，占收入低到中个位数，已续约并扩品 (前 Datadog 员工)。
很多客户算完 TCO 还是选 DDOG对，补一句有专家支持：渠道专家说 Grafana 用量上去后稳定性差、要招工程师调优，"往往会迁移去 DDOG"；另一位说 Grafana 主要用在初期搭建阶段。但也有反例：Acecamp 2026-06 一位运维负责人说核心指标在往 Grafana 迁，Datadog 支出没增长。Datadog 守单更多靠"大棒"：搬走一部分，剩下部分没了规模折扣，也用不了 Bits (ThirdBridge 2026-10-29)。
Chronosphere 25 年被 PANW 收购对，补一句2025 年 11 月宣布，2026 年 1 月完成，$33.5 亿。收购时 ARR 约 $0.85 亿 (TMTB 转述 PANW)，现在超过 $5 亿，其中有一家大客户的贡献。
主要是降本，拿走了 OpenAI 的订单 (churn from DDOG)部分对降本对：卖点是数据入库前先过滤、聚合、采样，价格比 Datadog 低 30–40% (FundaAI)。但拿走的只是 OpenAI 的指标，不是整单：日志早已去了自建 ClickHouse，链路还留在 Datadog。PANW 披露 Q4 有超过 $1 亿 ARR 来自一家 LLM 客户迁移 (没点名)。另外 Chronosphere 现在是 PANW 安全套餐的一部分，新客户里 50% 同时买了 XSIAM。
DDOG 长期最大威胁是 ClickHouse、Databricks、SNOW，因为存储和计算成为成本大头对Sid Roy (F500 渠道/服务伙伴 CTO)："Databricks、Snowflake、ClickHouse 会成为更大威胁，因为存储和计算是增长最快的成本"；F500 渠道专家 C 也这么说。要注意时间：Snowflake 侧专家说目前没看到业务从 Datadog 转向 Snowflake，Snowflake 收购 Observe 更像对自己客户加卖。
客户想把数据放进湖仓，只把要实时看的放进 DDOG对渠道专家："客户不愿为可观测性厂商的日志存储重复付费"，更倾向在 Snowflake / Databricks 自建湖仓存日志。Datadog CFO 也承认会主动告诉客户"你发了太多不需要的数据"。
OAI 已经全面迁移进 ClickHouse 的方案要修正不是全面。OpenAI 拆成三块：日志约 2025 Q3 搬到自建、基于 ClickHouse 的 "OLog"；指标 (约占其 Datadog ARR 的 40%) 2026 年中搬到 Chronosphere；链路 (APM) 继续留在 Datadog (MeritForum 汇总三位渠道专家)。
DDOG 的回应是 Federated Logs，让客户在 DDOG 界面查 ClickHouse / Databricks 的日志对，补一句对。CEO 在 Q2 2026 业绩会："federating logs enables users to query external data stores, including Databricks and ClickHouse"。同时推出 BYOC (日志留在客户自己的云里，用 Datadog 全套界面)，并宣布扩展到指标和链路。含义：Datadog 主动放弃一部分存储收入，换取守住工作流层。
客户用 Claude Code 自建 agent 通过 MCP 读 DDOG 数据，界面和 Bits 的价值被摊薄对，补一句管理层自己承认。CEO："part of our functionality is delivered to agents through MCP servers… part… to humans with UIs"；CPO Yanbing Li 说存在一场"interesting battle"：客户是用轻量 MCP、Datadog 自己的 agent，还是第三方跨厂商 agent 来消费数据。补两点：(1) 短期收入不受影响，因为按用量收费，agent 查和人查一样花钱，MCP 调用 Q1'26 环比 4 倍；(2) 风险集中在中型客户。ThirdBridge 2026-10-29 的专家说，模型越强、各家都开 MCP，"一个界面看全部"就越不重要，可以直接让 agent 跨六个平台找一条 trace，大企业暂时还不会这么做。

框架里漏掉的四股力量

你的框架讲的都是"可观测性公司之间"的竞争。还有四股力量来自旁边：

漏掉的力量它在做什么影响哪一层
安全巨头：Cisco (Splunk)、PANW (Chronosphere + XSIAM)、CrowdStrike (LogScale)可观测性和安全用的是同一批日志。安全厂商用"安全套餐"顺便把日志预算拿走；Datadog 反过来做 Cloud SIEM数据存储层 (日志预算)
管道层：Cribl、Datadog Observability Pipelines、Dynatrace 收购的 BindPlane数据入库前先过滤、去重、分流，热的去贵平台，冷的去便宜存储。本质是帮客户少付存储费数据存储层 (直接砍量)
Dynatrace 的 AI 补课2026 年以 $9.15 亿收购 Arize (LLM 评估和观测，ARR 约 $4,000 万，给 FY27 ARR 增速加约 2 个点)。说明 LLM 观测这块，Datadog 自己做、Dynatrace 靠买工作流层 (AI 应用)
云厂商自带：AWS CloudWatch、Azure Monitor基础功能便宜或免费，跨云和跨产品打通弱。是小客户的起点和价格天花板工作流层 (低端)
