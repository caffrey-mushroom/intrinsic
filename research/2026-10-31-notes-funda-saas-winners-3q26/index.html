1. 这份报告是什么，能信几分

Funda 是新加坡的独立研究机构（Consensus AI Technology），做"企业 AI 调研"系列专家访谈，我们 10-27 的企业 AI 支出研究就用过它的 Vol.1-6，PLTR v2 也用过它 10-27 的 Palantir 渠道调研。这份是它的季度 SaaS 赢家输家追踪，2026 年 10 月访谈 31 家企业的 IT/数据负责人，问"你们怎么用软件和 SaaS，账单在怎么变"。

读之前要知道的四个局限：

  • 样本偏 AI 先行者。附录里很多公司 AI 月支出几十万到几百万美元（法国药企估计每月 $3-4 千万，跨国人力公司每月 $4-6 百万）。这些公司的账单变化会领先，也会夸大平均水平。
  • 每个结论背后只有几家。Snowflake 的 8/8 里有几家是"预计会涨"而不是已经涨了；ServiceNow 的样本是 7 家。最常被引用的是同一家"美国诊断公司"，出现在至少 8 页里。
  • 引语是 Funda 截过的短句。我们没有访谈全文，下文引语照 deck 原样，说话人身份也只有 deck 给的那一层（如"CIO，美国诊断公司"）。
  • Funda 历来偏多。这是我们在 PLTR v2 里就标过的。这份 deck 几乎不谈单价下降，也不谈估值。

2. 核心框架：三条结论 + 三层成本

整份 deck 是三段论：

  1. 今天（Part 1）：记录系统和 agent 基础设施是赢家；能被重建或绕过的软件是输家。
  2. 长期（Part 2）：AI 把"写软件"的成本砍得很狠，SaaS 又在变"无头"（headless，见下），竞争会加剧。31 家里约一半已经用 AI 自建替换了某些工具。
  3. 但是（Part 3）：AI 降不了行业知识的成本，也替代不了厂商担责。没有一家在换核心系统。

串起这三段的是一张"三层成本"表，这是整份 deck 最有用的一页：

成本层包括什么AI 降了吗推论
1 · 写软件写代码、集成、测试大幅降低。几个人加 coding agent 就能做出以前要买的东西竞争加剧
2 · 运行软件升级、补丁、故障、安全、支持；出事时有人负责部分降低。agent 开始做重构和升级，但责任还在厂商竞争加剧，但更慢
3 · 行业知识写进系统里的行业规则；风控和监管的签字没有。仍需要多年客户积累和监管批准老厂商保住优势

Source: Funda deck p.20。

和我们的对应：这几乎就是我们 10-27 的修正版框架："软件 = 功能 + 规模化运维 + 状态/信任；agent 只把功能变便宜。"Funda 的第 1 层 = 我们的"功能"，第 2 层 = "运维"，第 3 层 = "状态/信任"。两边独立得出同一个结构，可以当作互相印证。

3. 观点一：记录系统是净赢家

"记录系统"（system of record, SoR）严格说指业务"以它为准"、在里面下单改状态的那套系统：客户和商机记在 Salesforce，IT 工单和资产记在 ServiceNow，订单和财务记在 SAP。Snowflake/Databricks 严格说不是 SoR，是数据平台：它们存的是从这些系统复制过来、用来分析的历史数据副本，业务不在里面发生。Funda 把四家放在同一组，是因为赢的逻辑相同（agent 越多、调用越多、账单越高，而且收费都不跟人头挂钩），不是因为它们是同一类系统。我们 10-27 的讨论也是这样分的：实时读写业务数据走 SoR，分析和历史数据进 SNOW/DBX。

Funda 给了三个原因：

原因 1：企业直接买厂商自带的 agent

因为 agent 要"靠近数据"，厂商自带的 agent 就坐在数据和流程里面。名词解释：Agentforce 是 Salesforce 的 AI agent 产品，按 token 或按动作计费；Now Assist 是 ServiceNow 的 AI 助手/agent；AI Control Tower 是 ServiceNow 新出的"AI 治理"产品，用来登记、管控公司里所有 AI agent。

  • 美国诊断公司：ServiceNow 席位减 16%，但 Now Assist 花费 +13%，Control Tower +6-7%，净 +8%（实际）。Salesforce 未来 6 个月总支出预计 +12%，agent 在销售打电话前写客户简报、通话后写回纪要。
  • 全球药企：ServiceNow 支出 +20-30%，不断加 HR 等非 IT 模块，替掉单点工具。
  • 澳洲医疗分销商：手机上问"我的订单到哪了"，agent 去 SAP 里查；每年多付约 $8 万（agent 约 $2.5 万，其余是 Data Cloud 和 SAP 集成），少招 2 个人。
  • 瑞士消费品公司：AI 已占 Salesforce 账单的 10%，还在涨。
  • 美国区域银行：agent 每周分拣 8 万件客户投诉，合规签字。

原因 2：外部 agent 调用按动作收费

名词解释：MCP（Model Context Protocol）是 Anthropic 提出的标准接口，让任何 AI agent 都能"插上"某个系统去读写数据，相当于给软件装了一个 agent 专用的 USB 口。Headless（无头）指软件把界面拿掉、所有功能都开放给 agent 调用，人可以不打开 Salesforce 的网页就完成工作。

Funda 的逻辑：就算企业用自己的 agent（例如用 Claude 写的工具）绕过 Salesforce 界面，只要它通过 API/MCP 读写 Salesforce，就按动作付钱。例子：欧洲电信公司用外部客服 agent 读写工单，目标减 20% 客服；美国诊断公司用 Claude 写的应用处理工单交接，约 10 个席位不再需要；美国宠物保险公司自建分类器同时调用 Salesforce 和 Zendesk 的 API，70-80% 的工单不经人手。

Funda 自己的算账：Salesforce 每个 agent 动作约 $0.10，一个 agent 每月处理 2,000 张工单、每张约 5 个动作，每月约 $1,000。它承认"今天很小"。我们补一笔对照：美国诊断公司说 Salesforce 每席位每年约 $800，10 个席位 = 每年 $8,000；上面这个 agent 一年 $12,000。也就是说按 Funda 的单价，一个 agent 大致能补回它替掉的 10 个席位，但很难大幅多收。这是我们的推算，不是 Funda 的。

原因 3：agent 查数据比人频繁得多，数据平台按算力计费

Snowflake 和 Databricks 不按人头收费，按查询消耗的算力（credits）收费，所以"查得越多付得越多"，跟员工数无关。

4. 观点二：agent 带来四类新需求（外加"agent 收费"）

这些是"两年前不存在的需求"。每一项都小，但企业把它当成共享平台成本来买，以后每个新用例都要经过它。

名词解释：AI 网关是公司里所有 agent 调模型的统一入口，决定谁能调哪个模型、每个任务给多少 token 额度、走哪条路由，类似给 AI 装一个总闸和电表（同类：LiteLLM、Portkey、Kong、Cloudflare AI Gateway、Azure API Management）。Langfuse/LangGraph 是开源的 agent 编排和追踪工具。Collibra 是数据目录和治理软件，药企 CDO 的比喻是"agent 是车，Collibra 是高速公路，上路的车越来越多"。AuditBoard（现名 Optro）是审计和合规软件。

PayPal 和 Pinterest 两个案例来自同一家加拿大口腔护理品牌（媒体预算约 $1,500 万）。PayPal 用 AI 做反欺诈，付款通过率从 94% 升到 97% 以上，同时费率从不到 3% 涨到 3.7%，品牌愿意多付因为多成交了。Pinterest 新的 AI 广告 agent 按用户此刻在搜什么（比如婚礼、笑容、照片）推美白产品，A/B 测试转化 4%，品牌今年在 Pinterest 的投放大约是去年的 3 倍（$3 万 → $9 万）。这两例样本只有一家公司、金额很小，更像"AI 能提价"的示意，不是行业结论。

两个推动力

(1) 软件变得便宜好写。Funda 的时间线：2025 年 4-5 月（GPT-4.1、Claude Sonnet 4）可靠性够了；2025 年 11 月 Claude Opus 4.5，"随便描述一下就能干"，新加坡电信认为这是拐点；2026 年 3-6 月 Microsoft Copilot Cowork 让非工程师也能用；2026 年 9 月 Claude Opus 5.5，能跑长任务、自己测试，每次运行比 Opus 5 快 30%+、便宜 40%。非洲投行说替换"在过去 3-4 个月明显加速"；欧洲电信一个原本要 1.5 年的重构，大部分交给了 Claude Code。

但"运行"比"写"难得多：澳洲分销商问"AI 写的代码开发者都不懂，谁来维护？"；宠物保险的顾问说"能做不代表该做，回过神来你已经在维护一套软件了"。

(2) SaaS 变"无头"。Salesforce Headless 360（2026 年 4 月，每个功能都对 agent 开放，约 $0.10/动作）、Claudeforce（2026 年 9 月，与 Anthropic 合作，37 个技能让销售在 Claude 里完成 CRM 工作，不用打开 Salesforce）、ServiceNow Action Fabric（2026 年 5 月，对"任何 AI agent"开放，按 Assist 计量）、Workday MCP server（2026 年 10 月，"不管谁做的 agent，都在 Workday 权限下运行"）。短期：每次调用都付费，比被绕过好；长期：agent 在前面干活，后面的系统可以一个模块一个模块地被换掉，用户感觉不到。

7. 为什么老厂商仍占优：四个理由

理由说法和证据
1 · 风控签字要好几年非洲投行："转折点与其说是模型，不如说是风控部门对 AI 的接受度。"风控要搞清楚 agent 能访问、记住、执行什么；每出一条安全新闻，接受度就清零一次
2 · 厂商带着整个行业的知识非洲投行："你买的与其说是软件，不如说是知识产权。"例：Murex（银行交易和风险系统）里有 80 多家银行的规则；单个企业只有自己的
3 · 监管希望有个厂商负责全球药企："让厂商去跟政策，而不是你自己追着政策跑。"隐私审查按每个 agent、每条数据流做；厂商跟踪政策并承担责任
4 · 迁移失败的代价远大于省下的钱美国诊断公司："他会为了在 Salesforce 上省一百万，冒一亿美元销售额的险吗？"集成要很多年；AI 工程师应该去做差异化的事

Funda 的最终结论：在更激烈的市场里，Salesforce、ServiceNow、Snowflake 保住优势；它们真正卖的是多年行业经验和对客户流程的理解，加上审批、业务规则、运营数据，以及在数据上计算的引擎。

框架层面：三处同意，三处不同意

同意：

  1. 三层成本 = 我们的"功能 / 运维 / 信任"。两边独立得出同一结构。Funda 补了一个我们没有的时间表：核心模块 3-5 年内不会被换，替换顺序是单点工具 → 界面 → 非核心模块 → 核心。
  2. 输家名单几乎一样。我们的"按席位卖的横向工具"和"BI、知识、胶水"对得上。Funda 没谈 IT 服务和外包，我们认为那是最大的输家（人工预算是 AI 的资金来源）。
  3. agent 运行要的东西（身份、安全、审计、网关）是新需求。和我们的"人以前隐性承担的东西现在要显性买"一致。

不同意或 Funda 没回答：

  1. "账单在涨"不等于"增速在加速"。Funda 的样本是 AI 先行企业，又多是"预计"。CRM 内生 7%、NOW 19-21% 都没有加速。我们 10-28 框架检查的结论仍然成立：闸门在被使用，但只有按用量计费的闸门真的收到了钱。
  2. Funda 几乎不谈单价。我们的核心规律之一是"量指数级涨，单价跌得更快"。Funda 自己的数据里就有：欧洲电信用量 +30-50%、谈降价把花费压平；Vol.3/Vol.6 里企业在用网关、路由、缓存压成本。网关本身就是压价工具。
  3. 数据平台的增长来源。Funda 讲业务 agent 查询，我们讲 coding agent 带来的迁移和工程活动（一部分是一次性的存量释放）。这个分歧决定 SNOW 的增速能维持多久，下一步要看迁移收入占比和 Cortex Code 带来的增量份额。

和 Funda 自己以前系列的张力：它 9 月的 Vol.2 说美国药企在 CEO/CFO 锁死总预算后"开始评估砍 ServiceNow/Salesforce"；这份里全球药企的 ServiceNow 却 +20-30%。可能是两家不同药企，但说明同一个机构的样本里两种方向都有。

对我们的影响

  • 不改任何结论和买点。Funda 证实的赢家（SNOW、CRWD、OKTA）都离买点很远；它指出的有预期差的方向（NOW、CRM 的按动作收费）还没有量级证据。
  • 可以加进跟踪的指标：(1) CRM 财报里 Agentforce/按动作收入和席位数的对比；(2) NOW 非席位收入占比和 Control Tower 的披露；(3) SNOW 收入里迁移 vs 新负载的拆分；(4) Funda 4Q26 tracker 里"核心模块替换"是否从 0 变成非 0，以及 SNOW/DBX 是否出现第一家减少的企业。
  • 值得挖的新线索：AI 网关（TrueFoundry、Kong、Cloudflare AI Gateway）作为"每个 agent 都要经过"的共享层，对 NET 是加项；以及 Collibra 这类数据治理在 MCP 时代的位置。
