结论

一句话：2026 年软件有结构性 beta，但分化比 beta 更显著。beta 集中在数据层和用量龙头；工作流骨架有长期逆风；单薄工具是 AI 输家；企业 AI 落地比想的慢。

  1. 上云在加速，数据库最快：非 AI 的云 (Gartner 口径) 18% → 22%，温和；数据层明显加速，SNOW 26% → 37%，Databricks 50% → 80%。原因：补 2023-24 年少花的钱；agent 要数据在云上；AI 把迁移成本打下来 30-70%。
  2. 数据流速提升，龙头受益：DDOG 25% → 36%。可观测性行业只涨 ~12%/年，DDOG 快是在抢份额，不是行业快。
  3. 行业 reward 好产品：份额往 DDOG、Databricks 走。反例是 MDB：产品不差，但 agent 默认选 Postgres，Atlas 两年平在 29%。
  4. Usage 龙头：DDOG 最好但最贵；SNOW 在加速但份额丢给 Databricks、AI 收入毛利低；FROG 量涨了但最大的 AI 客户按服务器付钱；MDB 吃不到 AI 的量。
  5. Seat 骨架：客户不走，seat 会掉。短期加速靠提价 (NOW 换贵套餐)、并购 (CRM 有机只有 6.4%)、逼迁云 (TEAM)，都是一次性的。NOW 的 AICT 是最大的 bet，2027 年前进不了报表。
  6. 单薄工具：MNDY 增速 30% → 15%。重置成本最低，Claude 一下午能搭个够用的。
  7. 复盘股价：2-4 月全板块砸过一轮，IGV 现在回到年初 (0%)。真涨的只有加速的 DDOG (+65%)、FROG (+49%)、SNOW (+36%)。GTLB、VEEV、TEAM 是超跌修正；NOW (-26%)、HUBS (-41%)、MNDY (-35%) 连年初都没回去。
  8. 企业 AI 落地慢：POC 到生产 5-10%。NOW AI ACV +65% 但有机 cRPO 减速；DT 有 1,000+ 家 AI 客户，但净新增 ARR 同比持平。业务 agent 的钱 2027 年以后。
  9. 怎么做：买 NOW；CRM、HUBS 小买 1/3；DDOG、SNOW 等板块砸；MDB 等 Atlas 过 30%；MNDY 等 Q3 NDR；DT 价格到了但基本面在变弱，不买。

1. 2026 年软件是有结构性 beta 的

1.1 企业上云加速，数据库上云的增速最显著，数据平台受益

结论：上云在温和加速：剔除 AI 后的云基础设施 (Gartner 口径，我们减掉 AI 部分) 18% (2025) → 22% (2026E)，是在补 2023-24 年优化期少花的钱。三家云厂商都说企业上云在加速：AWS 说核心计算和存储是几年来最快的增速，大型机这类"永远不会上云"的负载也在搬。加速最明显的是数据层 (数据库、数据平台)；SAP 这类 ERP 搬迁在 ~25% 的高位持平，不是没上云，是本来就在高速搬。

为什么现在要把数据搬上云：

  • 还技术债。过去几年数据基础设施投资不足，数据散在各个系统、各个机房里。做报表时还能凑合，做 AI 不行。
  • Agent 要的东西，本地机房给不了。(1) 数据要在一个地方、有统一的权限：agent 查一个问题要跨好几个系统，本地数据是一块一块的；(2) 算力要能弹性：agent 一次任务发几十上百个查询，峰值是平时的很多倍，本地机房按峰值买机器不划算；(3) 模型在云上：前沿模型都在云上跑，数据离模型近才快、才便宜。Deloitte 调查 (501 家美国企业) 里，agent 落地卡在数据的占 72%。

你提纲里两处要修正：

  • "监测行业大盘显著高于软件总盘"不成立。行业 ~12%/年，比软件慢。快的是 DDOG 一家：大客户里 DDOG 赢 DT 的比例在升；某 GSI 渠道里 DT 的转售额 $20M → $16M → $6M。真正"大盘快于软件"的是数据平台。

反作用力：量涨价跌。Databricks 的 token 一个月翻倍，收入只 +3%；MDB 的 token 涨 3-4 倍，Atlas AI 收入 ~2 倍。迁移积压是有限的，AI 原生客户的钱跟着实验室融资走。

1.3 行业 reward 好公司、好产品

  • 好产品拿份额，原因很简单：DDOG 一个平台 26 个产品、1,000+ 集成，装上就能用，工具整合时客户把 Splunk、New Relic、DT 的活并到 DDOG；Databricks 一开始就是给工程师写代码用的，agent 开发、流处理、非结构化数据这些新活天然是工程活；SNOW 开箱即用、免运维，财务和销售的口径都建在它上面，BI 守得住。
  • 份额往哪走：Databricks 2026 年在数据库管理系统里的份额超过 SNOW (我们估 4.3% vs 4.0%)；在头部 4 家数据平台里，SNOW 45% → 42%。SNOW 的加速有不少是 beta，它在丢份额给 Databricks。
  • 选工具的从人变成 agent。Agent 默认选最 AI native、网上文档最多、开源的工具。MDB 是最清楚的输家：管理层承认 coding agent "大多数时候在 JSONB 上选 Postgres"；Claude Code 测试里选 Mongo 0/125 次；Stack Overflow 调查 MDB 使用率 24% → 19%。反过来，SNOW 把 Cortex Code 插件放进 Claude Code 插件市场，主动争 agent 的默认选择。

2. 软件的分化很显著：可以拆成三类

2.1 Agent 驱动数据、工作负载提升，usage-based 的龙头显著受益

共性：agent 和 coding 让计量单位变多 (数据、查询、制品)；单价在降；最大的客户想自建；都贵，SBC 都高。量 > 价。ASP 撑不住、大客户压价，增速就可能 miss 预期。

DDOG - Observability 龙头，但是很贵不买

行业概况：

  • 公司的系统跑在几百上千台服务器上，DDOG 在做的就是在每台服务器上装一个小程序 (Agent)，收三类数据；以外卖 App 为例子，加入晚高峰时段下单的页面卡了 5s，DDOG 在做什么 (其在每个 Server 上都装了 Agent 并持续的收集三类数据)
    • 采集指标 (Metrics - 基础设施监控)：CPU、内存、每秒订单数这类随时间变化的数字，告警通常从这里响起 [会发给工程师，告警直接推入 Slack 和值班系统]
    • 链路追踪 (APM/Traces)：一次下单从手机出发，经过网关、订单服务、支付服务、数据库，记录每一站各花了多少时间，能直接看出是支付服务调数据库那一步慢了 4s [工程师用 DDOG 做排查 + 检修 (Agent 可以直接写了，工程师只要确认)]
    • 日志 (Logs)：每个程序写下的"刚才发生了什么"的文字记录，比如"支付超时，订单号 123，检修过程 xxx 全部被记录进日志"
  • 这是个好行业 - 因为本质上软件系统越来越复杂 (服务器 to 云上容器 to Agent)，人越来越看不过来，需求跟着复杂增长，急需要花更多的钱买更复杂的产品 (按量付费)；并且数据和排查习惯建立在某个平台后就很难切换

DDOG 的竞争优势是统一平台 + 最强的数据采集：

  • DDOG 的产品将上文的三类数据在同一界面整合串联，意味着它可以最及时的侦测 (然后告警) - 排查 - 发现 - 检修完成整个链路 (跳到那一次请求的完整链路，再看那一秒的日志，一路定位到代码)
  • 整个 Observability Workflow 一共是六个步骤：DDOG 最强的就是[数据采集] [进门处理] 和 [分析]
    • DDOG 是 Tech 公司做监测的实施标准，因此形成了双边网络效应 —— DDOG 在其成立之初就是服务 Tech 公司，因此最复杂的 Tech Stack 和最新的技术都必须做最快速的响应和集成；同时正是因为 DDOG 是科技公司标配，New SaaS 都会主动集成进入 DDOG - 这个积累持续了 15 年
      • 从数量看 DDOG 集成 1,000+，DT 和 New Relic 集成 500-600 个 (这两家数据在 23 年披露，可能现在更接近了)
      • 但区别不仅仅是数量，而是统一安装、串联、持续维护

行业是做什么的
数据库分两类。操作型是 App 的"收银台"：你在手机上下单、发消息、改头像，每一笔都要马上写进去、马上读出来 (Oracle、SQL Server、Postgres、MongoDB)。分析型是"财务部"：把所有收银台的数据汇到一起算总数 (SNOW、Databricks)。MDB 是操作型里最大的"文档型"数据库。打个比方：Oracle、Postgres 像按科目分好的账本，客户信息一本、订单一本、地址一本，看一个客户要翻三本对起来，加一个新科目要重画表格；MongoDB 给每个客户一个文件袋，所有东西装在一起，加东西直接塞进去。前者规矩，适合复杂对账；后者快，适合天天改版的 App。
怎么收钱
Atlas (~76% 收入)：MDB 替客户在 AWS、Azure、GCP 上运行数据库，按"集群规格 × 小时 × 节点数"收钱。例子：一家银行的手机 App 后台，主库 3 个 M60 节点 ($4.67/节点小时) + 异地容灾 2 个 + 搜索 2 个 + 测试 3 个，标价一年 ~$25 万，签年度承诺打 8 折后 ~$20 万。EA (~21%)：客户在自己机房跑，签 1-3 年订阅，许可部分 (~27%) 签约当季一次性确认，所以 EA 收入很跳。关键：按容量收费，不是按每次调用。同一个集群里周末多跑 10 万次 agent 查询，一分钱不多收，要等集群撑满、升规格或加节点才多收。GSI 专家：token 涨 3-4 倍，Atlas 里 AI 相关消费只涨 ~2 倍。
核心优势
不是入口，是存量。开发者入口在 Postgres (开源、免费、AI 学得最熟)。MDB 强在三处：原生分片、一个集群跨三朵云 (AWS DocumentDB、Azure Cosmos DB 都只在自家云)；文档模型和应用代码长在一起，迁出要改代码；搜索和向量放在同一个库里。数字：NRR 122%；$1M+ 客户 434 家，5 年复合 34%；$5M+ 客户 5 年复合 57%。客户越大长得越快，存量里几乎没有大客户整体迁走的案例。和同类模式 (开源起家 + 自管订阅 + 云上用量) 的 ESTC 比：收入 +30% vs +15%，NRR 122% vs 111%。
这一轮的 driver
Atlas 29% 拆开 (我们的估算)：(1) 老客户已有负载长大 ~17pt：手机银行用户和交易变多，主库从 M60 升到 M80 再加分片。主体，但单个负载会进入平台期。(2) 新负载和迁移 ~6-9pt：银行把 Oracle 上的客户资料、风控系统改写到 MongoDB。(3) 搜索和向量 ~2-3pt：$100K+ 客户里用 2 个以上产品的 42% → 48%。(4) AI-native 客户 ~1-2.5pt：2,200+ 家，只占 Atlas 3-5%，增速 165%。减项：客户优化降规格；新应用流向 Postgres。
为什么比 SNOW、DDOG 慢
(1) 新入口被截：新项目越来越多由 coding agent 搭，agent 默认 Postgres。Claude Code 在 125 个场景里选库，MongoDB 首选 0 次；Lovable 内置 Supabase，Replit 内置 Postgres；Stack Overflow 使用率 24% → 19%，Postgres 58%。CEO 自己说"你没法操纵提示词"。(2) 对手是默认选项：云厂商自家库 (Azure Postgres +55%、Cosmos DB +50%、DynamoDB) 和开源 Postgres；SNOW 买了 Crunchy Data、Databricks 买了 Neon，都在卖 Postgres。(3) 收费方式钝：按容量，量涨了要等撑满才变收入。(4) AI-native 客户少：占 Atlas 3-5%，DDOG 是 ~15%。所以数据库是 AI 的受益层，但 AI 的量先进了 SNOW、Databricks 和云厂商自家库。
还能吃 beta 吗
能吃迁移的 beta，吃不到 AI 的 beta。迁移：AI 写代码让 Oracle、SQL Server 老应用改写到 MongoDB 从 18-24 周缩到 4-8 周，管理层说打开了"$100 亿+ 迁移 TAM"；欧洲一家大零售商 Oracle ERP 迁过来，3 年 ARR 7 倍。但三个折扣：迁移产品 (AMP) CFO 说回报要到 FY28；从 Oracle 出来的客户多数平移到 Postgres (SQL 不用重写)，同样的 AI 也让"迁到 Postgres"变便宜；受监管客户的 AI 负载先落在 EA (自己机房)，不进 Atlas。所以 Atlas 没减速，也没加速。

行业是做什么的
程序员写的源代码像菜谱，编译打包后变成能直接运行的"成品" (容器镜像、npm/Python/Java 软件包、手机安装包，现在还有模型文件、MCP 工具包)。GitHub、GitLab 存菜谱；FROG 的 Artifactory 存做好的菜，是一家公司所有要上线的成品的正本。打个比方：连锁餐厅的中央厨房。冷库是 Artifactory (成品按批次存放，谁什么时候做的都有记录)；进货质检是 Curation (开源包先过一道门，有毒直接拒收)；出货抽检是 Xray (扫描漏洞)。门店 (生产服务器) 只从冷库拿货，不直接去菜市场买。为什么要有：2016 年有人从 npm 删掉一个 11 行的小包，全世界成千上万个项目当天构建失败；2025-09 起 Shai-Hulud 蠕虫三波感染 npm 上数百个包；Log4Shell 爆出时很多公司花几周才查清哪里用了 log4j。
怎么收钱
三种计量方式。云 (~53% 收入)：按每月存储 + 流量 GB 签年度承诺，用超了按贵 25-40% 的单价按月补交 (超额用量)；阶梯价越用越便宜 ($1.25 → $0.33/GB)。自托管 (~47%)：按服务器台数年付，和用量无关 (Enterprise X 3 台起 $5.1 万/年)。安全 (~7%，记在云里)：按开发者人头。例子：一家 1,000 名开发者的银行，云承诺每月 20TB 预付 $30 万；年中 AI 编程工具铺开，实际用到 24TB，多出 4TB 补交 $7.5 万；安全给 500 人买 $10 万；合规部门 3 台自托管 $5.1 万，合计一年 ~$53 万。我们估 2026 年收入 ~91% 是承诺，~9% 是超额。

2.2 Seat-based 但提供企业工作流框架的公司有长期逆风，短期加速靠提价

共性：按 seat 或员工数收费。客户不会走，这是他们组织公司的方式 (治理、安全、审计、习惯)。Seat 有长期风险，现在靠提价、新套餐、推上云撑增速。

核心是时间错配：提价一次性，跟着 3 年合同慢慢滚完；seat 下滑是复利。按用量收费的新钱能不能在提价滚完前接上，决定这一类。

分两层：全公司骨架 (NOW、CRM) 和部门级工作流 (GTLB、TEAM 管研发，VEEV 管药企)。部门级的 seat 风险看 agent 替的是不是这个部门的人。

传统业务
本质是工单流程：谁要什么、谁批、谁做、做完没有。最典型是 IT 服务台 (ITSM)：员工笔记本坏了提一张工单，系统派给 IT 人员、走审批、换机、关单。NOW 在 ITSM 份额 44% (行业 ~$115 亿)，95% 的 F500 在用。同一套流程往外扩：IT 运维 (ITOM)，底下是 CMDB (公司所有 IT 资产和它们之间关系的总账)；HR 服务 (HRSD)，入职、请假；客户服务 (CSM)；安全和风控 (加上收购的 Armis，管设备和网络资产)；销售 CRM (新业务，净新增 ACV 5 倍以上，基数小)；以及 Moveworks (员工 AI 助手)。
怎么收钱
按处理工单的人 (fulfiller seat) 每人每月收钱，提工单的员工不收钱。收费拆分 (我们估)：seat ~76%、按资产或员工 ~20%、按用量 ~1%。AI 自动化以后，同样的工单需要的人更少：NOW 自己说 AI agent 能关掉 80-85% 的同类请求；BNP 渠道说一家客户 IT 服务台省了 30-40%。所以 seat 是长期逆风。
NOW 的做法
(1) 换贵套餐：Standard → Pro (+50%) → Pro Plus (+60%) → 新 AI 套餐 (+20-30%)。Q3 续约客户 65-70% 换到新 AI 套餐。一次性，按 3 年合同滚，~2029 年滚完。(2) 按用量收：assist (AI 每干一件活扣一次)；Action Fabric (外部 agent 调 NOW 的动作，按调用)。(3) AICT：见下。(4) 扩新部门。
AICT 是什么
AI Control Tower：管企业里所有 AI agent 的"总账 + 调度台"。(1) 找出来：一家工业客户以为自己不到 500 个 agent，一查有 ~6,000 个；(2) 登记：每个模型、每个 agent 作为一条资产记进 CMDB；(3) 管住：权限、风险、合规审计、出问题一键关停 (kill switch)；(4) 算账：成本和 ROI。已对接 Anthropic、Google、Microsoft、OpenAI、Workday、Salesforce 的 agent。
为什么 NOW 最合适
(1) 它已经有 CMDB，"公司有哪些资产"本来就记在它这里，agent 只是新一类资产；(2) 审批、变更、审计流程本来就在它这里；(3) 对模型厂商中立，不自己卖模型；(4) CIO 本来就是它的买家。
AICT 的进展和空间
上线 6 个月 500+ 客户在用 (很多是新套餐打包送的)；交易规模环比翻倍以上。渠道：北美一家合作伙伴有 12 个以上 AICT 试点；一家医疗客户为试点每年付 $40 万以上，一家工业客户买了 ~$22 万；一家大型制造集团评估后估计全面推广 NOW 账单 +15-22%。所以长期空间是：每家大客户账单再加一两成，而且按资产收，不随 seat 掉。风险：客户很少信任一家厂商去管竞争对手的产品；MSFT Agent 365、Okta、OpenAI 都在做；低风险 agent 嫌贵；只有少数成熟客户现在就需要。2027 年才可能成为有意义的收入。

2.3 单薄的工具型公司重置成本大幅降低，是 AI loser

Set up：功能单一，价值主要在界面，AI 让重置成本大幅降低，企业可以直接自建或换 AI 原生的小工具。判断三问：一个小团队用 Claude 两周能不能搭个够用的？它有没有别的系统依赖的权威记录？用户是不是主要靠人在点？

做什么、怎么收钱
团队项目管理和看板 (任务、进度、负责人)，按 seat 和版本收费，AI credits ~1% 收入。客户偏中小。

A.1 OpenAI 用 ClickHouse 压 DDOG

数据实时性要求搬去哪时间
日志低：大部分是事后查自建 ClickHouse ("OLog")2025 年 Q3
基础设施指标中：看趋势，不一定要秒级Chronosphere (被 PANW 收购)2026 年上半年
调用链 (APM)、前端监测、合成监测高：出事时要马上定位留在 DDOG，8 月续了九位数合同
  • 为什么能拆：存储是最容易替换的一环。ClickHouse 这类列式数据库存日志、指标便宜很多；有工程师的大客户，一年账单超过 $2-5M 就值得自建。AI 让自建更便宜 (写代码、写查询都更快)。
  • 边界：COIN 2022 年 $6,500 万账单试过自建，最后拿到降价留下；SHOP 计划过自建，团队被裁。风险集中在最大的几个技术型客户，被拆的是"不要求实时的存储"，不是每天在用的排查流程。
  • 别的公司也一样：SNOW 的大客户把数据放在自己的 S3 上 (Iceberg 开放格式)，加工交给 Databricks、Spark，SNOW 只留交互查询。SNOW CEO 自己说："迁入变快，迁出也一样变快"。
