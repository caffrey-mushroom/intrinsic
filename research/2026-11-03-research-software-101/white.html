结论

一句话：2026 年软件有结构性 beta，但分化比 beta 更显著。beta 集中在数据层和用量龙头；工作流骨架有长期逆风；单薄工具是 AI 输家；企业 AI 落地比想的慢。

  1. 上云在加速，数据库最快：非 AI 的云 (Gartner 口径) 18% → 22%，温和；数据层明显加速，SNOW 26% → 37%，Databricks 50% → 80%。原因：补 2023-24 年少花的钱；agent 要数据在云上；AI 把迁移成本打下来 30-70%。
  2. 数据流速提升，龙头受益：DDOG 25% → 36%。可观测性行业只涨 ~12%/年，DDOG 快是在抢份额，不是行业快。
  3. 行业 reward 好产品：份额往 DDOG、Databricks 走。反例是 MDB：产品不差，但 agent 默认选 Postgres，Atlas 两年平在 29%。
  4. Usage 龙头：DDOG 最好但最贵；SNOW 在加速但份额丢给 Databricks、AI 收入毛利低；FROG 量涨了但最大的 AI 客户按服务器付钱；MDB 吃不到 AI 的量。
  5. Seat 骨架：客户不走，seat 会掉。短期加速靠提价 (NOW 换贵套餐)、并购 (CRM 有机只有 6.4%)、逼迁云 (TEAM)，都是一次性的。NOW 的 AICT 是最大的 bet，2027 年前进不了报表。
  6. 单薄工具：MNDY 增速 30% → 15%。重置成本最低，Claude 一下午能搭个够用的。
  7. 复盘股价：2-4 月全板块砸过一轮，IGV 现在回到年初 (0%)。真涨的只有加速的 DDOG (+65%)、FROG (+49%)、SNOW (+36%)。GTLB、VEEV、TEAM 是超跌修正；NOW (-26%)、HUBS (-41%)、MNDY (-35%) 连年初都没回去。
  8. 企业 AI 落地慢：POC 到生产 5-10%。NOW AI ACV +65% 但有机 cRPO 减速；DT 有 1,000+ 家 AI 客户，但净新增 ARR 同比持平。业务 agent 的钱 2027 年以后。
  9. 怎么做：买 NOW；CRM、HUBS 小买 1/3；DDOG、SNOW 等板块砸；MDB 等 Atlas 过 30%；MNDY 等 Q3 NDR；DT 价格到了但基本面在变弱，不买。

1. 2026 年软件是有结构性 beta 的

1.1 企业上云加速，数据库上云的增速最显著，数据平台受益

结论：上云在温和加速：剔除 AI 后的云基础设施 (Gartner 口径，我们减掉 AI 部分) 18% (2025) → 22% (2026E)，是在补 2023-24 年优化期少花的钱。三家云厂商都说企业上云在加速：AWS 说核心计算和存储是几年来最快的增速，大型机这类"永远不会上云"的负载也在搬。加速最明显的是数据层 (数据库、数据平台)；SAP 这类 ERP 搬迁在 ~25% 的高位持平，不是没上云，是本来就在高速搬。

为什么现在要把数据搬上云：

  • 还技术债。过去几年数据基础设施投资不足，数据散在各个系统、各个机房里。做报表时还能凑合，做 AI 不行。
  • Agent 要的东西，本地机房给不了。(1) 数据要在一个地方、有统一的权限：agent 查一个问题要跨好几个系统，本地数据是一块一块的；(2) 算力要能弹性：agent 一次任务发几十上百个查询，峰值是平时的很多倍，本地机房按峰值买机器不划算；(3) 模型在云上：前沿模型都在云上跑，数据离模型近才快、才便宜。Deloitte 调查 (501 家美国企业) 里，agent 落地卡在数据的占 72%。

你提纲里两处要修正：

  • "监测行业大盘显著高于软件总盘"不成立。行业 ~12%/年，比软件慢。快的是 DDOG 一家：大客户里 DDOG 赢 DT 的比例在升；某 GSI 渠道里 DT 的转售额 $20M → $16M → $6M。真正"大盘快于软件"的是数据平台。

1.3 行业 reward 好公司、好产品

  • 好产品拿份额，原因很简单：DDOG 一个平台 26 个产品、1,000+ 集成，装上就能用，工具整合时客户把 Splunk、New Relic、DT 的活并到 DDOG；Databricks 一开始就是给工程师写代码用的，agent 开发、流处理、非结构化数据这些新活天然是工程活；SNOW 开箱即用、免运维，财务和销售的口径都建在它上面，BI 守得住。
  • 份额往哪走：Databricks 2026 年在数据库管理系统里的份额超过 SNOW (我们估 4.3% vs 4.0%)；在头部 4 家数据平台里，SNOW 45% → 42%。SNOW 的加速有不少是 beta，它在丢份额给 Databricks。
  • 选工具的从人变成 agent。Agent 默认选最 AI native、网上文档最多、开源的工具。MDB 是最清楚的输家：管理层承认 coding agent "大多数时候在 JSONB 上选 Postgres"；Claude Code 测试里选 Mongo 0/125 次；Stack Overflow 调查 MDB 使用率 24% → 19%。反过来，SNOW 把 Cortex Code 插件放进 Claude Code 插件市场，主动争 agent 的默认选择。

2. 软件的分化很显著：可以拆成三类

2.1 Agent 驱动数据、工作负载提升，usage-based 的龙头显著受益

共性：agent 和 coding 让计量单位变多 (数据、查询、制品)；单价在降；最大的客户想自建；都贵，SBC 都高。量 > 价。ASP 撑不住、大客户压价，增速就可能 miss 预期。

DDOG - Observability 龙头，但是很贵不买

行业概况：

  • 公司的系统跑在几百上千台服务器上，DDOG 在做的就是在每台服务器上装一个小程序 (Agent)，收三类数据；以外卖 App 为例子，加入晚高峰时段下单的页面卡了 5s，DDOG 在做什么 (其在每个 Server 上都装了 Agent 并持续的收集三类数据)
    • 采集指标 (Metrics - 基础设施监控)：CPU、内存、每秒订单数这类随时间变化的数字，告警通常从这里响起 [会发给工程师，告警直接推入 Slack 和值班系统]
    • 链路追踪 (APM/Traces)：一次下单从手机出发，经过网关、订单服务、支付服务、数据库，记录每一站各花了多少时间，能直接看出是支付服务调数据库那一步慢了 4s [工程师用 DDOG 做排查 + 检修 (Agent 可以直接写了，工程师只要确认)]
    • 日志 (Logs)：每个程序写下的"刚才发生了什么"的文字记录，比如"支付超时，订单号 123，检修过程 xxx 全部被记录进日志"
  • 这是个好行业 - 因为本质上软件系统越来越复杂 (服务器 to 云上容器 to Agent)，人越来越看不过来，需求跟着复杂增长，急需要花更多的钱买更复杂的产品 (按量付费)；并且数据和排查习惯建立在某个平台后就很难切换

DDOG 的竞争优势是统一平台 + 最强的数据采集：

  • DDOG 的产品将上文的三类数据在同一界面整合串联，意味着它可以最及时的侦测 (然后告警) - 排查 - 发现 - 检修完成整个链路 (跳到那一次请求的完整链路，再看那一秒的日志，一路定位到代码)
  • 整个 Observability Workflow 一共是六个步骤：DDOG 最强的就是[数据采集] [进门处理] 和 [分析]
    • DDOG 是 Tech 公司做监测的实施标准，因此形成了双边网络效应 —— DDOG 在其成立之初就是服务 Tech 公司，因此最复杂的 Tech Stack 和最新的技术都必须做最快速的响应和集成；同时正是因为 DDOG 是科技公司标配，New SaaS 都会主动集成进入 DDOG - 这个积累持续了 15 年
      • 从数量看 DDOG 集成 1,000+，DT 和 New Relic 集成 500-600 个 (这两家数据在 23 年披露，可能现在更接近了)
      • 但区别不仅仅是数量，而是统一安装、串联、持续维护
    • 进门处理能力强本质是因为 DDOG 相当于是全链路集成，所有的数据在采集的时候就按照 DDOG 的标准做数据收集、打标、分发，并且有一支核心团队稳定高效的维护，而自建太复杂
      • 打个比方：1,000 家供应商用 1,000 种格式寄发票，要全部自动识别，记进同一套科目，并和订单、物流单对上，还要几秒内完成，同时服务 3 万家公司，而且对方随时会改发票格式。任何一张发票都不难，难的是全部、一直、自动地做对。这就是 15 年磨出来的那部分
    • 分析也是 DDOG 的强项 (但是 DT 并不弱，有些反馈甚至更强)
      • 因为 DDOG 在数据喂入的时候按照请求编号和服务名做好串联了 (获得了全视角 + 结构数据)，所以分析的门槛大幅度降低
      • 同时其数据和分析在一套体系下做实时计算，所以速度快 + 不会漏
      • 服务 3w+ 客户的数据，有数据飞轮
  • 从竞争格局上来看，DDOG 也是在显著 Gain Share 的

AI Agent 给 DDOG 带来了很好的 Beta：

  • 本质上这个行业就是对软件系统做跟踪 - DDOG 的 Rev Model 就是 Server Num x ASP + Logs Traffic x ASP
  • AI Agent 驱动企业上云 + Build Agent Workflow，意味着更多的 Server + 更多的 Agent (更多的 Logs)
    • 企业内，还有 Anthropic 和 OpenAI 们的 ChatGPT 和 Claude 的网页和 App 后端、API 网关、计费、登录、数据库、调度推理的 CPU 机器。每来一个请求，这些服务都要打日志、记调用链 - 都会转换成 DDOG 的收入，因此显著受益于 Agent
  • 同时复杂的 Agent 架构还驱动客户对整个系统做更全面的监测 - 买 DDOG 更多的产品 (提 ASP)

市场预期是什么，我们是否有预期差：

    • 低价竞争：切分，不是替换。关键应用留在 DDOG，冷日志、部分指标、开发环境流向 Grafana (便宜 ~20%)、Chronosphere (便宜 30-40%)。一家年付 $1.2M 的客户 2027 年续约评估换 Observe，概率 50/50。长期威胁是数据平台 (Databricks、Snowflake、ClickHouse)。

    • NRR 和留存：NRR ~120%，毛留存中到高 90%，2Q $100k+ 客户 4,720 家，贡献 ~91% ARR。
  • 3Q 趋势总结 (我们)：
    • 收入大概率超指引、落在买方区间。非 AI 加速 + OpenAI 3Q 见底，我们估 $1,190M (+34%)，指引 $1.14B (+29%)，买方 +33-36%。
    • 真正的考点是 4Q 指引。公司按 OpenAI 合同底线给指引，所以 4Q 指引上沿大概 $1,230-1,240M，刚好卡在买方 $1,239M (+30%) 的线上；2Q 就是收入超了、指引低于买方，股价一天 -19%。
    • 我们和市场的分歧不在 3Q/4Q，在单价。量在涨 (MCP、上云、多产品)，但单价在降：毛利率 83.0% → 79.6%、大客户切分存储。市场 2Q 电话会 21 个问题只有 1 个问账单和单价，没人问 Grafana/ClickHouse。

估值位置：

DT - 对比 DDOG 增速慢得多不买

行业概况：

  • 和 DDOG 是同一个行业 (可观测性)，同样在客户的服务器上装探针收三类数据。区别在打法：DT 装一个探针 (OneAgent) 就自动把整个系统的"地图"画出来 —— 哪个服务调哪个、跑在哪台机器上、依赖哪个数据库，出问题时 AI (Davis) 顺着地图往上游找根因
  • 例子：一家银行的手机 App 付款突然变慢
    • DT：告警响起，地图上直接标出是"支付服务 → 核心账务系统"之间新上线的一个版本把数据库连接占满了，7 分钟给出根因，运维一键回滚
    • 老办法：3-4 套工具 (服务器监控、日志、应用监控) 各看各的，人工对时间线，几个小时
  • 客户画像完全不同：DT ~4,100 家，平均 ~$50 万/年，银行、保险、政府这类有大量老系统 (大型机、老 Java)的复杂大企业；DDOG 3.3 万家，从科技公司起家往大企业走
  • 收钱方式：客户签一张年度"储值卡" (DPS，Dynatrace Platform Subscription)，按主机小时、日志 GB、查询量从卡里扣。DPS 已占收入 ~70%

竞争优势是"自动化 + 根因"，但只在复杂老系统里：

  • DT 最强的是 [自动采集] [依赖图] 和 [根因分析] 三站
    • 自动采集：OneAgent 装上就能看到代码级调用，不用改代码；对老 Java、大型机这种"没人敢动代码"的系统特别值钱
    • 依赖图 (Smartscape)：实时自动画，新服务上线自动出现在图上；DDOG 要靠打标签串，复杂老系统里打标签本身就是工程
    • 根因 (Davis)：有地图才能做因果推断，所以分析这站 DT 不弱于 DDOG，部分客户反馈更强
  • 但这个优势锁在了一个客群里
    • 产品复杂、首单 >$20 万/年，只有复杂的大企业用得起、用得好，所以老在金融客户里转；DDOG 首单 $1-2 万/年，找做新事的团队
    • DT 进入的企业几乎都已经有 DDOG (Bernd Harzog)，第一单不替换；到了工具整合那一步才正面对打，渠道说 DDOG 对 DT 的胜率在升
    • 结果：DT 份额 ~19% → ~18%，DDOG 份额 32% → 36%；DDOG 规模是 DT 的 2 倍、增速也是 2 倍

AI 给 DT 的 beta 小得多：

  • Rev Model：储值卡额度 (DPS) = 主机小时 x 单价 + 日志 GB x 单价 + 新模块；增长 = 老客户扩张 (NRR ~110%，贡献 ~2/3) + 新客户 (~1/3)
  • AI 推的是同一个量 (更多服务器、更多日志)，但落到 DT 身上打了折
    • 客户是银行、保险、政府，agent 上生产比科技公司慢一到两年
    • AI native 客户 (OpenAI、Anthropic 这类) 基本在 DDOG，DT 没有这块 ~10 个点的额外增长
    • 日志是 DT 想讲的第二增长曲线，但日志恰恰是最容易被 ClickHouse、S3 这类便宜存储拆走的一站
  • 过去两年的扩张有一块是一次性的：老 SKU 换成 DPS 时客户普遍多签额度，DPS 占比 ~70% → FY27E ~77%，这台引擎 FY28 后用完

市场预期是什么，我们是否有预期差：

  • 11-03 发的 Q2 FY27 没过关，股价 -12% 到 ~$48：
    • 收入没 miss：$579.9M，+17%，全年收入指引上调到 $2,330-2,340M
    • 但有机净新增 ARR $70M，同比持平，低于我们的及格线 $76M (管理层说几笔大的扩张单推迟到下半年)
    • 全年有机 ARR 指引 15.5-16.5% 没动，上调的 ~2pt 全是 Arize 并表；NRR 109% (-1pt)
  • 市场 (卖方) 在赌有机重新加速：
    • UBS (11-03) FY28 收入 +17.6%，隐含有机净新增 ARR 要从 ~$325M 涨 ~34% (这季同比 0%)
    • 我们的基本情景是 FY28 +17%、Arize 满一年后掉到 ~16%，有机 ~14-15%
  • 渠道调研：
    • 一家北美 GSI 的 DT 转售 3 年 $20M → $16M → $6M；欧洲集成商在大企业里 DDOG 对 DT 胜率在升
    • BTIG 10 月：DT 伙伴调研稳中向好，practice 增速中双位数到 ~20%
    • ThirdBridge 专家：Davis 新一代 "launched early"，功能还没跟上发布节奏
  • 预期差：市场在等有机加速，我们认为没有证据。现价 ~$47 碰到我们买点 $42-48 的上沿，但基本面这季在变弱，不因为价格到了就买。下一个检验在 2027 年 5 月 (Q4 FY27)：TTM NRR ≥113%、有机 ARR ≥17% 才上调

估值位置：

SNOW - 加速，但是还在丢份额给 Databricks不买

行业概况：

  • 企业把各个系统 (交易、App、ERP) 的数据拉到一个地方，加工干净，再拿来做报表、分析、训练模型、给 agent 查。以一家 2,000 家门店的超市为例：
    • Databricks 像中央厨房：工程师每晚写代码把收银流水、App 日志、PDF 发票加工成"每家店每个商品卖了多少"，再训练模型预测明天进多少牛奶 [买单的是 CTO、数据科学团队]
    • SNOW 像出餐快的前台：财务分析师周一早上打开看板看"上周华东区乳制品毛利率"，写一句 SQL 几秒出结果 [买单的是 CDO、分析和业务部门]
    • 很多大公司两家都买
  • 收钱方式：都按算力用量收费 (SNOW 叫 credits，Databricks 叫 DBU)，用了就确认收入；SNOW 产品收入占 96%
  • 这是个好行业 - 数据只会越来越多，而且 agent 把"一次提问"变成"几十次查询" (下图)，算力账单跟着变大；数据和口径建在一个平台上以后很难搬

SNOW 的竞争优势是"查询 + 共享"，但新负载在流向 Databricks：

  • 数据走 6 站，SNOW 只在[查询和 BI] 和 [共享] 两站最强
    • 查询：开箱即用、不用调优，分析师写 SQL 就能跑；核心传统数仓仍占 SNOW 消费 60-65%，增速 20-25%，慢但稳
    • 共享：企业之间直接共享数据不用拷贝 (比如零售商把销售数据共享给供应商)，用的人越多越难搬
    • 接入、存储、加工、AI 都有人比它强：加工是 Databricks 的主场，存储是云厂商的 (Iceberg 开放格式让数据可以不放在 SNOW 里)
  • 但 Databricks 在四个数上都领先
    • Databricks run-rate >$70 亿 (2026-08)，+80%；SQL 数仓 >$15 亿、+100% (直接抢 SNOW 的 BI)；SNOW 产品收入 +37%
    • $1M+ 客户 Databricks 1,000+ vs SNOW 828；NRR >140% vs 126%
    • 大客户整体互换极少 ("押一家 5-10 年")，正面交锋 SNOW 仍赢 ~60%；但新负载放哪家每年重新选。Thoughtworks SVP："不是 Databricks 正面赢了 Snowflake，是新增的活偏向工程重的 agent 构建和流处理，这本来就是 Databricks 起家的地方"

上云 + AI 给了 SNOW 很好的 Beta，但 AI 部分毛利低：

  • Rev Model：Credits 消耗 = 查询次数 x 每次查询的算力 x 单价；增长 = 老客户多用 (NRR 126%) + 新客户
  • 三个 driver
    • 数据迁移：SNOW 迁移收入 FY26 是 1.9 倍，Teradata 迁移 2-3 年缩到不到 3 个季度 (AI 帮着改写代码)
    • Cortex Code (CoCo)：帮工程师写数据代码的 AI，9,100+ 账户在用，贡献 ~12-15% 的增量消费；本质是工程师用 AI 写更多数据管道，跑更多 credits
    • AI 产品：FY27 指引 36% 里 AI 产品贡献 ~7pt (FY26 只 2pt)；但业务端还早，SNOW CoWork (给业务人员的 agent) 环比只 +11%，Databricks Genie 90% 的空间不活跃
  • 要分开看：AI 产品里一部分是转卖模型 token，毛利 ~55%，核心数仓 ~78%
    • 产品毛利率 76% → 74.7%，FY27 指引从 75% 下调到 74%
    • 扣掉 AI 产品，SNOW 自己的增速 ~29%，比总数低 7 个点

市场预期是什么，我们是否有预期差：

  • SNOW Q3 (12 月初)：指引 $1,588-1,593M，我们 $1,645M (+42%)，买方要 ~$1,640M。及格线：产品收入 ≥$1,640M、产品毛利率 ≥74%、RPO ≥+30%
  • 真正的问题是 FY28 首次指引 (2027 年 2 月)：迁移补课做完，核心回落，券商给 ~30%，我们只给 27%
  • 渠道：两家在分两类人的预算；CoCo 是这轮 SNOW 加速的主力之一；大客户不换平台，但新负载偏 Databricks
  • Databricks：Forge 二级市场 $288/股 (~$2,170 亿)，隐含 5 年复合 ~39%，我们基本情景 ~28%，买点 $150-170/股；IPO 定价 ≥$2,500 亿不参与
  • 预期差：市场在交易"加速"，我们看的是加速的质量 (AI 部分毛利低、迁移是一次性) 和 2027 年的回落

估值位置：

MDB - 按量收费，但 agent 带来的量没进它家等 Q3

行业概况：

  • 数据库分两类
    • 操作型是 App 的"收银台"：你在手机上下单、发消息、改头像，每一笔都要马上写进去、马上读出来 (Oracle、SQL Server、Postgres、MongoDB)
    • 分析型是"财务部"：把所有收银台的数据汇到一起算总数 (SNOW、Databricks)
  • MDB 是操作型里最大的"文档型"数据库。打个比方：Oracle、Postgres 像按科目分好的账本，客户信息一本、订单一本、地址一本，看一个客户要翻三本对起来；MongoDB 给每个客户一个文件袋，所有东西装在一起，加东西直接塞进去。前者规矩，适合复杂对账；后者快，适合天天改版的 App
  • 收钱方式
    • Atlas (~76% 收入)：MDB 替客户在 AWS、Azure、GCP 上运行数据库，按"集群规格 x 小时 x 节点数"收钱。例子：一家银行的手机 App 后台，主库 3 个节点 + 异地容灾 2 个 + 搜索 2 个 + 测试 3 个，标价一年 ~$25 万，签年度承诺打 8 折后 ~$20 万
    • EA (~21%)：客户在自己机房跑，签 1-3 年订阅，许可部分签约当季一次性确认，所以 EA 收入很跳

MDB 的竞争优势是存量，不是入口：

  • MDB 强在三处
    • 原生分片、一个集群跨三朵云 (AWS DocumentDB、Azure Cosmos DB 都只在自家云)
    • 文档模型和应用代码长在一起，迁出要改代码
    • 搜索和向量放在同一个库里
  • 存量很稳：客户越大长得越快
    • NRR 122%；$1M+ 客户 434 家，5 年复合 34%；$5M+ 客户 5 年复合 57%
    • 存量里几乎没有大客户整体迁走的案例
  • 但入口在丢：新项目越来越多由 coding agent 搭，agent 默认选 Postgres
    • Claude Code 在 125 个场景里选库，MongoDB 首选 0 次；Lovable 内置 Supabase，Replit 内置 Postgres
    • Stack Overflow 使用率 24% → 19%，Postgres 58%；CEO 自己说"你没法操纵提示词"
    • 对手是默认选项：云厂商自家库 (Azure Postgres +55%、Cosmos DB +50%) 和开源 Postgres；SNOW 买了 Crunchy Data、Databricks 买了 Neon，都在卖 Postgres

AI 给 MDB 的 beta 很小：能吃迁移的 beta，吃不到 AI 的 beta：

  • Rev Model：Atlas = 集群规格 x 小时 x 节点数。按容量收费，不是按调用：同一个集群里周末多跑 10 万次 agent 查询，一分钱不多收，要等集群撑满、升规格或加节点才多收。GSI 专家：token 涨 3-4 倍，Atlas 里 AI 相关消费只涨 ~2 倍
  • Atlas 29% 拆开 (我们估)
    • 老客户已有负载长大 ~17pt：手机银行用户和交易变多，主库升规格再加分片
    • 新负载和迁移 ~6-9pt：AI 写代码让 Oracle 老应用改写到 MongoDB 从 18-24 周缩到 4-8 周
    • 搜索和向量 ~2-3pt
    • AI-native 客户只有 ~1-2.5pt：2,200+ 家，只占 Atlas 3-5% (DDOG 是 ~15%)
  • 迁移也打折：从 Oracle 出来的客户多数平移到 Postgres (SQL 不用重写)；受监管客户的 AI 负载先落在 EA，不进 Atlas

市场预期是什么，我们是否有预期差：

  • Q3 FY27 (12 月初)：公司指引 Atlas ~26%，我们 ~29% ($608M)，买方要 ≥30%；这是 MDB 连续第 7 个季度"超指引但不过 bar"的位置。及格线：Atlas ≥28.5%、NRR ≥121%、FY28 首次 Atlas 指引 ≥24%
  • 市场关心的：Q2 电话会 9 位分析师，AI 和 Voyage 4 个问题、EA 3 个。没人问的：Postgres 和 coding agent 默认库、按容量计费、SBC。这几项恰恰是渠道里问得最多的
  • 渠道：多数看到 21-27%；一位全球 SI："客户新应用不再默认 MongoDB"；前 SVP Meghan Gill："如果只有一个竞争逆风，那就是 Postgres"
  • 管理层：CEO CJ Desai 9-28 去了 Meta，前任 Dev Ittycheria 回来暂代；CRO、首席客户官、AI 产品负责人都走了。新 CEO 再改一次销售提成是最大的执行风险 (2024 年那次让 Atlas 掉到 24%)
  • 预期差：市场把 MDB 当"AI 数据库受益股"，我们认为 AI 的量先进了 SNOW、Databricks 和云厂商自家库；现价隐含 5 年 ~18%，正好等于我们的基本情景：合理价，不便宜

估值位置：

FROG - AI 让"成品"变多，好公司，很贵不买

行业概况：

  • 程序员写的源代码像菜谱，编译打包后变成能直接运行的"成品" (容器镜像、npm/Python/Java 软件包、手机安装包，现在还有模型文件、MCP 工具包)。GitHub、GitLab 存菜谱；FROG 的 Artifactory 存做好的菜，是一家公司所有要上线的成品的正本
  • 打个比方：连锁餐厅的中央厨房
    • 冷库是 Artifactory：成品按批次存放，谁什么时候做的都有记录
    • 进货质检是 Curation：开源包先过一道门，有毒直接拒收
    • 出货抽检是 Xray：扫描漏洞
    • 门店 (生产服务器) 只从冷库拿货，不直接去菜市场买
  • 为什么要有：2016 年有人从 npm 删掉一个 11 行的小包，全世界成千上万个项目当天构建失败；2025-09 起 Shai-Hulud 蠕虫三波感染 npm 上数百个包；Log4Shell 爆出时很多公司花几周才查清哪里用了 log4j
  • 收钱方式
    • 云 (~53% 收入)：按每月存储 + 流量 GB 签年度承诺，用超了按贵 25-40% 的单价补交 (超额用量)
    • 自托管 (~47%)：按服务器台数年付，和用量无关
    • 安全 (~7%)：按开发者人头

FROG 的竞争优势是库房，不是扫描：

  • 库房是正本，安全长在库房上
    • 一个产品原生支持 60 多种包格式 (老对手 Sonatype Nexus ~15 种；AWS、Azure 的 registry 各管一种、只在自家云)
    • 云、自托管、混合用同一套代码，CFO："同行里没有第二家是混合的"
    • 换掉 = 全公司几千条流水线停工：GRR 97% 两年没动；一家前沿 AI 实验室自己做了个复制品，规模上去后撑不住，又回来了
    • 83% 的 Fortune 100 是客户，$1M+ 客户 40 (1Q24) → 97 家
  • 扫描在被商品化：2026-02-20 Anthropic 发布 Claude Code Security，FROG 当天跌 20% 以上

AI 给了 FROG 很好的 Beta，但量涨了钱没跟上多少：

  • Rev Model：云 = 存储和流量 GB x 单价 (承诺 + 超额) + 自托管 = 服务器台数 x 单价 + 安全 = 开发者人数 x 单价
  • AI 推的是 GB：AI 让每个开发者每小时产生成品从 1 次变成 10-20 次
    • Artifactory 里的二进制一年 +136% 到 180 亿个
    • "基础云增长"指引 (只算承诺) 从 30-32% 上调到 41-43%
    • 超额用量：CFO 说"绝大多数"云客户在超，我们估贡献 2026 年 ~6.5pt 增速，不在指引里
    • AI 实验室：4 家 (OpenAI 已 18 个月)
  • 但钱没跟上：
    • 量最大的客户不按量付钱：前 3 家前沿 AI 实验室全部自托管、按服务器付费、没买安全
    • 量涨价跌：同一个文件全公司只存一份，加上阶梯折扣 ($1.25 → $0.33/GB)；头部 10 个大客户用量只涨 20-40%
    • 超额不在合同里：续约时转成承诺，单价降 25-40%；CFO："We really, truly don't know" (能不能持续)

市场预期是什么，我们是否有预期差：

  • Q3 (11-05 盘后)：指引 $164-166M (+20%，只含承诺)，我们 $174.5M (+27.5%)、云 $97M (+53%)，和买方 bar (总收入 ≥+27%、云 54-55%) 基本一样，没有预期差
  • 2027：我们 $845M (+25%)；卖方 $853M，已高于公司 2023 年给的 FY27 目标上限 $825M
  • 市场关心的：Q2 电话会 13 个问题，安全 4 个、超额用量 3 个、OpenAI 零日 3 个。没人问的：每 GB 单价在降、SBC 和稀释、GitHub 和云厂商的竞争、Claude Code Security
  • 预期差：市场在交易"每季超多少"；我们认为胜负手是"量能不能以不太低的单价进合同"，第一次检验是 2027 年预算季的续约 (CFO 8-12 说客户对超支的"宽容度"会下降)。现价隐含 5 年 ~32-38%，比我们的加速情景 (~25%) 还高

估值位置：

2.2 Seat-based 但提供企业工作流框架的公司有长期逆风，短期加速靠提价

共性：按 seat 或员工数收费。客户不会走，这是他们组织公司的方式 (治理、安全、审计、习惯)。Seat 有长期风险，现在靠提价、新套餐、推上云撑增速。

核心是时间错配：提价一次性，跟着 3 年合同慢慢滚完；seat 下滑是复利。按用量收费的新钱能不能在提价滚完前接上，决定这一类。

分两层：全公司骨架 (NOW、CRM) 和部门级工作流 (GTLB、TEAM 管研发，VEEV 管药企)。部门级的 seat 风险看 agent 替的是不是这个部门的人。

NOW - Seats-base 的企业工作流骨架，客户不会走，但付钱的人在变少买

行业概况：

  • 本质是工单流程：谁要什么、谁批、谁做、做完没有。以员工入职为例：
    • 没有 NOW：HR 发邮件给 IT 开账号、给行政领电脑、给财务开报销权限，5 天
    • 用 NOW：一张入职单自动拆成 IT、行政、财务的子工单，按顺序派人、审批、关单，1-2 天
    • 加了 AI agent：开账号、配权限这类活 agent 直接做完，按人头收费的人工坐席这一步消失
  • 最典型是 IT 服务台 (ITSM)：NOW 份额 44% (行业 ~$115 亿)，95% 的 F500 在用；同一套流程往外扩到 IT 运维 (底下是 CMDB，公司所有 IT 资产的总账)、HR、客户服务、安全风控 (收购 Armis)、销售 CRM
  • 收钱方式：按处理工单的人 (fulfiller seat) 每人每月收钱，提工单的员工不收钱。seat ~76%、按资产或员工 ~20%、按用量 ~1%
  • 这是个好生意但有长期逆风 - 客户不会走 (流程、审批、审计都长在上面)，但 AI 让同样的工单需要的人更少：NOW 自己说 agent 能关掉 80-85% 的同类请求；BNP 渠道说一家客户 IT 服务台省了 30-40%

NOW 的竞争优势是"底座"：总账、审批、审计：

  • 入口两站 (提需求、分派) NOW 不是最强，Slack、Teams、ChatGPT 都能当入口；底座四站只有 NOW 全是"最强"
    • 一套数据 (CMDB) 跨部门复用：每多一个部门，下一个部门更便宜、换掉更贵
    • AI 换掉的是两头 (入口、执行的人)，中间的总账、审批、审计还在 NOW 里，而且 agent 越多用得越多
  • 新的 option 是 AI Control Tower (AICT)：管企业里所有 AI agent 的"总账 + 调度台"。一家工业客户以为自己不到 500 个 agent，一查有 ~6,000 个。NOW 最合适：CMDB 本来就记"公司有哪些资产"，agent 只是新一类资产；审批审计本来就在这里；对模型厂商中立。上线 6 个月 500+ 客户；一家大型制造集团估计全面推广 NOW 账单 +15-22%。2027 年才可能成为有意义的收入

AI 对 NOW 是逆风，短期加速靠提价：

  • Rev Model：Seat 数 x 每 seat 单价 + 资产 / 员工数 x 单价 + assist 用量
  • NOW 的做法
    • 换贵套餐：Standard → Pro (+50%) → Pro Plus (+60%) → 新 AI 套餐 (+20-30%)；Q3 续约客户 65-70% 换到新 AI 套餐。一次性，按 3 年合同滚，~2029 年滚完
    • 按用量收：assist (AI 每干一件活扣一次)；Action Fabric (外部 agent 调 NOW 的动作，按调用)
    • 扩新部门和并购：Armis、Moveworks
  • 核心是时间错配：提价一次性，seat 下滑是复利。AI 净新增 ACV +65%，有机 cRPO 却在减速，说明 AI 钱大部分是续约时换贵套餐换出来的，是替代不是叠加

市场预期是什么，我们是否有预期差：

  • Q3 本身没 miss：订阅 $3,988M、+20.5% (固定汇率)、cRPO +21%，都小超指引。杀股价 (10-29 一天 -27%) 的是 Q4 cRPO 指引只有 18.5% (买方要 19.5-20%)；扣掉 Armis，Q4 有机 ~16.5-17%

  • 预期差：现价隐含 5 年收入复合只有 ~7-9%，低于我们的减速情景，而有机还有 ~17%。市场已经按"seat 崩塌"定价了，所以是这组里唯一的买。1 月 FY27 指引扣并购订阅 ≥17% 且订阅毛利率 ~81%，加到 2/3；≤16% 停

估值位置：

GTLB - 研发部门的工作流，产品不如 GitHub，靠合规留下来不买

行业概况：

  • 一个平台把"写代码 → 审代码 → 自动测试构建 → 安全扫描 → 发布"全管了。例子：一家区域银行 1,000 名开发者，每次改代码都要在 GitLab 里提合并请求、过两个人审批、跑完自动测试和安全扫描、留下记录，审计来了能查到"谁改了什么、谁批的"

竞争优势是合规和"能装在自己机房"，不是产品：

  • 产品不如 GitHub
    • GitHub (MSFT) 2024 年年化收入已 $20 亿 (含 Copilot)，代码审查更好用，Copilot 是开发者最熟的 AI
    • MSFT 续企业协议时把 GitHub + Copilot + Azure 额度打折塞进去
  • 为什么还能赢
    • 治理和审计：一个平台从需求到上线全程留痕，银行、政府、军工审计要的就是这个
    • 能装在自己机房：GitHub 自建版功能少；GitLab Dedicated (单租户托管) 前 20 大客户里 ~14 家在用

AI 对 GTLB 是逆风：量变多了，钱不变：

TEAM - 今年的加速是"逼客户上云"一把，长期还是 seat 风险不买

行业概况：

  • TEAM 管研发和 IT 部门的工作：Jira 管任务 (ARR $25 亿+)、Confluence 管文档 ($15 亿+)、服务台类工单 ($10 亿+，+30%)

CRM - 客户记录系统，现金流最好，但有机只有 ~6-7%小买 1/3

    • 有 Salesforce：客户资料、购买记录、保修、派单在一张记录上，2 小时

行业概况：

  • 记录、协作、自动化三站 MNDY 最强；看进度和 AI 两站别人一样强甚至更强
  • 飞轮保护得了"客户不走"，保护不了"客户人数"
  • 份额 18% (2021) → 26% (2025)，另一个拿份额的是 Notion，而且快得多；没有财务和合规后果，换掉没成本

AI 对 MNDY 是逆风：

  • Rev Model：Seat 数 x 单价 (每升一档 +33-58%) + AI credits (最低包只让 Pro 账单多 ~4%)
  • 增速掉的主要是新客户 (22 → ~10.5pt) 和提价 (4.5 → ~1.5pt)；AI credits 今年只补回 ~1.5pt
  • $10 万+ 客户一年 +37%，但 NDR 112% → 109%：大客户在加，整体扩张在变慢

市场预期是什么，我们是否有预期差：

  • Q3 (11-09)：我们 +17.7%，和 Street 基本一样；及格线收入 ≥$370M、NDR ≥108%、Q4 指引 ≥+15%
  • 预期差：现价隐含每年 ~2-5%，远低于我们的减速情景 (~7%)；EV/NTM 收入 ~1.9x 是这组最便宜的。过及格线后低于 $95 买 1/3；不过关买点下调到 $65-75

估值位置：

HUBS - 中小企业的营销和销售工具，介于单薄工具和记录系统之间小买 1/3

行业概况：

  • 中小企业的 CRM 和营销自动化。以一家 30 人的 B2B 公司为例：
    • 一个线索从被 AI 搜索找到、看了博客、留了邮箱，到收到培育邮件、销售跟进、成为付费客户，HubSpot 管了 6 步里的 5 步
    • 中小企业没有复杂的权限、合规、系统集成，最容易被 Claude 复刻个够用的；但它存着客户联系人数据和营销流程，比 MNDY 厚
  • 收钱方式：~56% 按平台费和营销联系人数，~41% 按席位，credits ~2.5%；从 Starter 升到 Pro 标价 x4.5、升到 Enterprise x7.5

竞争优势是"内容 + 联系人 + 一张表 + 易用"：

  • 免费 CRM 和内容引流带来小客户，升档加 hub 后由合作伙伴锁住
  • HUBS 是 $1B 以上 CRM 厂商里增长最快的；比它快的都是 $0.3B 以下的 AI 原生和 monday CRM
  • 飞轮保护不了单 hub 小客户和引流入口 (AI 搜索在改变获客)

AI 对 HUBS 是逆风，"量"的引擎在减速：

  • Rev Model：客户数 x 每客户收入 (升档 + 加 hub)；客户数贡献从 16.5pt 掉到 ~7.5pt，每客户收入只贡献 2-3.5pt
  • 季度净新增客户从 ~10K 掉到 7K，下半年指引 5-6K；10 月裁员 ~7%
  • AI credits 在涨但 2027 年也只有 ~1.5pt；订阅毛利率被 AI 成本从 88% 压到 ~84%

市场预期是什么，我们是否有预期差：

  • Q3：我们 $934M (+15.4%)，略低于买方 bar、高于指引；及格线净增客户 ≥5.5K、NRR ≥101%
  • 预期差：现价隐含 5 年收入复合 ~3% (B) / ~8% (A)，低于 HUBS 历史上任何一年，也低于我们的基本情景 ~9%；所以小买 1/3，买点 $205-235

日志低：大部分是事后查自建 ClickHouse ("OLog")2025 年 Q3

  • 为什么能拆：存储是最容易替换的一环。ClickHouse 这类列式数据库存日志、指标便宜很多；有工程师的大客户，一年账单超过 $2-5M 就值得自建。AI 让自建更便宜 (写代码、写查询都更快)。
  • 边界：COIN 2022 年 $6,500 万账单试过自建，最后拿到降价留下；SHOP 计划过自建，团队被裁。风险集中在最大的几个技术型客户，被拆的是"不要求实时的存储"，不是每天在用的排查流程。
  • 别的公司也一样：SNOW 的大客户把数据放在自己的 S3 上 (Iceberg 开放格式)，加工交给 Databricks、Spark，SNOW 只留交互查询。SNOW CEO 自己说："迁入变快，迁出也一样变快"。
