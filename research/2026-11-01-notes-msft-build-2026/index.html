Microsoft Build 2026 主题演讲解读

Build 是微软每年最大的开发者大会。这份解读逐段讲发布了什么、对怎么收钱有什么影响，并对照五个月后的 FY27Q1 电话会看兑现情况。

这场大会讲了什么

一句话：Build 2026 (2026-06-02) 把微软的 AI 叙事从"Copilot 助手"换成"agent 的全套底座"：每个 agent 有自己的身份和许可证 (Autopilot)、在 Foundry 上托管、在 Agent 365 上被管、在 MXC 里被隔离、用 Microsoft IQ 拿上下文。五个月后的 FY27Q1 电话会，这些产品基本都按时出现在了数字里。

  • 这是 Nadella 和 Mustafa Suleyman (微软 AI)、Pavan Davuluri (Windows)、Thomas Dohmke (GitHub) 等人的开幕主题演讲，主题是"agent 优先"。没有财务数字，全是产品发布。
  • 对估值最重要的一条：Autopilot agent "拥有自身独立身份和生产力许可证"。也就是说 agent 本身要买 M365 许可证，人头少了，agent 的"坐席"可以补上。这是微软回答"AI 会不会让 M365 坐席萎缩"的产品层答案。
  • 治理层全面对外开放：Agent 365 管理"托管在任何地方的 agent，包括 AWS、GCP 以及 Azure"，"也支持使用任何框架构建的 agent"；MXC 隔离层让 OpenClaw 这类第三方 agent 在 Windows 上安全运行。微软的策略是不管 agent 是谁做的，身份、权限、审计都收在微软。
  • 基础设施：核心指标是"每美元每瓦特产生的 token 数"。过去 18 个月新增的数据中心容量超过 Azure 第一个十年的总和；自研 Maia 200 每美元 token 数比领先 GPU 高 30%；agent 工作负载里 CPU 和加速器的比例"可能接近一比一"，这是核心 Azure (CPU) 重新加速的产品逻辑。
  • 模型：一次发 7 个 MAI 模型，其中 MAI thinking one 号称整体质量优于 Sonnet 4.6、编码接近 Opus 4.6；Frontier Tuning 让企业用自己的数据把 MAI 模型调到接近 GPT-5.5 的效果、成本效率高 10 倍。核心意思是降低对 OpenAI 的依赖，并把企业的"私有数据"变成微软平台上的黏性。
  • GitHub：代码提交量"过去几个月呈抛物线式增长，增加了两倍"；新的 GitHub Copilot app 用一个订阅就能调 OpenAI、Anthropic、Google 的模型，还能让一个模型复核另一个模型。微软在编程上做的是"多模型路由平台"，而不是押注单一模型。
  • 市场反应冷淡。Acecamp 另一篇 06-11 的评论标题是"微软模型七连发，但掉队的事实仍然难以掩盖"，认为 MAI 模型"基本上属于个人演绎"。我们的看法：模型本身确实不是领先者，但 Build 的重点不在模型，在于把 agent 的身份、治理、隔离和上下文这几层收进微软，这几层不需要最好的模型。

逐段解读

这份解读的来源是 Acecamp 2026-06-04 发布的中文纪要，根据 Build 2026 开幕主题演讲整理成问答体，不是官方英文逐字稿 (KB 里没有找到英文 transcript)。所以下面每段只摘一句纪要原文，配我们的解读；纪要里个别产品名有转写错误 (例如把新的托管 PostgreSQL 写成 "Verizon DB")，以官方名称为准。

一、Windows 和本地 AI Windows / 设备负责人 有用
纪要原文：为支持本地代理循环 (local agentic loop) ，微软发布了两款将在Windows上以INVOX形式运行的模型
解读Windows 的新定位是"本地跑 agent 的机器"：本地模型、Surface Ultra (128GB 统一内存)、RTX Spark 开发机 (1 Petaflop)，以及让 Windows 跑在 NVIDIA DGX Station 上。对投资判断影响小：Windows OEM 收入跟着 PC 周期走 (Q1 -27%)，本地 AI 短期改变不了换机节奏。值得注意的是"本地运行，无需担心 token 使用成本"，本地推理对 Azure 的 token 收入是一个小的反向力量。
二、云基础设施：每美元每瓦的 token 数 Nadella / Azure 必读
纪要原文：微软云端基础设施的核心驱动公式是“每美元每瓦特产生的token数量” (tokens per dollar per watt)
解读这是理解微软 capex 的钥匙。微软把数据中心看成一台"电进去、token 出来"的机器，所有优化 (芯片、冷却、网络、模型) 都为了提高这个比值。两个关键数字：过去 18 个月新增容量超过 Azure 第一个十年的总和 (capex 有多猛)；Maia 200 每美元 token 数比领先 GPU 高 30% (自研芯片能省多少)。这个比值每提高一点，同样的 capex 就能撑更多收入，这正是我们 base case 里 capex 占收入要从 49% 降到 22% 的前提。
三、agent 需要大量 CPU Azure 必读
纪要原文：针对代理工作负载，CPU的重要性日益凸显，其与AI加速器的比例可能接近一比一。
解读这句话很重要但容易被忽略。训练大模型主要用 GPU，但 agent 干活时要调用工具、运行代码、查数据库、开浏览器，这些都跑在 CPU 上。如果 CPU 和 GPU 接近 1 : 1，那么 agent 普及不只拉动 GPU (AI 实验室、neocloud 也能卖)，还拉动传统云 (CPU、存储、数据库)，而这部分是 Azure 的老本行、毛利更高、竞争更少。五个月后 Q1 电话会 CFO 专门说"CPU 变现改善"是 Azure 超预期的原因之一，Amy Hood 还说"大家低估了 CPU、存储、内存"，和这里的判断一致。
四、Vera Rubin 和 token 成本 NVIDIA / Azure 有用
纪要原文：与Hopper相比，Grace Blackwell将token生成的成本降低了约30倍。
解读一代 GPU 让每个 token 的成本降低约 30 倍，这就是"智能变成越来越便宜的投入品"的硬件来源。对微软是双刃剑：成本降得快，Azure 的 token 单价也会跟着降，收入要靠用量增长更快来弥补。到目前为止用量增长更快 (Q1 Azure +48%)。Vera Rubin 被定位为"为代理时代设计"，Q1 电话会说已经装上了第一批。
五、Microsoft IQ 和数据层 Foundry / Fabric 必读
纪要原文：Microsoft IQ是一个统一的智能层，整合了Foundry、Fabric和Microsoft
解读数据和上下文层。三块：Work IQ (M365 里的邮件、会议、文档、SharePoint 手册)、Fabric IQ (企业运营数据)、Web IQ (Bing 的网页索引改造成给 agent 用)。这一层的意义是让任何 agent 都要"问微软"才能知道企业里发生了什么。另外 Foundry 上已有 120 多个模型，包括 Anthropic 的 Claude Opus 4.8，说明微软不押注 OpenAI 一家。Q1 电话会：近 6 万客户在用 Microsoft IQ，环比 +25%；同时使用 Foundry 和 Fabric 的客户 1.9 万。
六、MXC：让别人的 agent 在 Windows 上安全运行 Windows 有用
纪要原文：我们宣布OpenClaw将利用MXC在Windows上运行
解读MXC (Microsoft Execution Containers) 是一个隔离层，控制 agent 能碰哪些文件、能不能上网、能不能删东西。重点是它对第三方开放：OpenClaw、NVIDIA 的 Open Shell 都接入。Q1 电话会时 OpenAI Codex、Anthropic Claude Code、Meta Muse 都已采用 MXC。这是"AI 原生公司绕不开 MSFT"的又一个例子：竞争对手的 agent 跑在企业电脑上，安全隔离是微软的。目前不单独收费，价值在于加强 Windows 和 Agent 365 的黏性。
七、Foundry 托管 agent 和 Fireworks AI Foundry 有用
纪要原文：Foundry中的托管智能体 (hosted agents) 被设计为长时程智能体的运行时环境。
解读Foundry 从"选模型的地方"升级成"agent 的运行环境"：每个 agent 一个沙盒、带内存和状态、内置评估和自我改进。这是和 AWS Bedrock AgentCore、Google Vertex 正面竞争的产品。引入 Fireworks AI 的全部开放模型，进一步说明微软要做模型中立的平台。收费方式是按 token 和计算资源，属于 Azure 用量收入。
八、GitHub Copilot app 和 Rayfin GitHub 必读
纪要原文：通过单一的GitHub Copilot订阅，用户可以访问来自OpenAI、Anthropic和Google等主流模型。
解读GitHub 的定位是"agent 的工作台 + 多模型路由"。一个订阅调所有主流模型，一个模型写、另一个模型复核。Rayfin SDK 把 agent 写的应用一键部署到企业的 Fabric 租户，和 Replit 合作意味着在别人家写的应用，数据和部署落在微软。商业上：GitHub 在 2026-06 改成超额按用量计费，Q1 电话会说 agent 功能的 credit 消费翻倍、GitHub Copilot 是 M365 商业云超预期的主要来源。这是微软"按用量收钱"最先跑通的地方。
九、Agent 365：管所有云上的 agent Agent 365 必读
纪要原文：365支持托管在任何地方的agent，包括AWS、GCP以及Azure，也支持使用任何框架构建的agent。
解读这句话对估值很关键。Agent 365 扩展 Entra (身份)、Defender (安全)、Purview (合规) 给 agent，而且明确支持 AWS、GCP 上的 agent 和任何框架。意思是：即使企业的 agent 不跑在 Azure 上，治理也可以交给微软。这一层主要打包在 E5/E7 里，是 E7 ($99) 提价的理由。Q1 电话会：5,000 万个 agent 在册，环比 +30%；Purview 已审计 76 亿次 agent 活动。
十、Autopilot：agent 也要买许可证 M365 Copilot 必读
纪要原文：Autopilot agent是一种具有自身独立身份和生产力许可证的企业级agent
解读我们认为这是整场 Build 对 MSFT 估值最重要的一句。M365 按人头收钱，市场最大的担心是 agent 替代员工、坐席减少。Autopilot 的设计是每个 agent 有自己的身份和"生产力许可证"，可以在 Teams 群聊里当团队成员、在用户离线时继续工作，管理员像管员工一样审批和监控它。换句话说，微软在把 agent 变成新的"坐席"。如果这条路走通，人头减少的部分可以由 agent 许可证补上。目前没有公布 Autopilot 的定价，Q1 电话会也没有单独给数字，这是我们下一步要追踪的。
十一、MDASH：多模型安全扫描 安全 有用
纪要原文：MDASH是一个为安全领域设计的agent
解读100 多个 agent 协同找代码漏洞，在 Cyber Gym 基准上优于任何单一模型。商业意义是 GitHub Advanced Security 的升级 (Q1 电话会：GHAS 收入 +50%，MAI-Cyber 已支撑 MDASH 40% 的扫描、成本低 18%)。也说明微软的打法是"多模型组合 + 自研便宜模型做大部分活"。
十二、Copilot 的演进路线 M365 Copilot 有用
纪要原文：从2026年夏季开始，Copilot将整合编码功能，形成一个集聊天、协作和编码于一体的超级应用。
解读Build 预告的路线是 Chat、Cowork、Code 合并成一个超级应用，再加 Autopilots。Q1 电话会证实已经交付："把 Chat、Cowork、Autopilot 和 Code 整合进一个统一体验"，Nadella 称之为"新的工作操作系统"。执行按时，但 Copilot 坐席数仍未披露。
十三、MAI 七个新模型 Mustafa Suleyman / 微软 AI 必读
纪要原文：在独立的人工评估中，其整体质量优于Sonnet 4.6。
解读MAI thinking one 是微软第一个自研推理模型，350 亿活跃参数，号称整体优于 Sonnet 4.6、编码接近 Opus 4.6。注意比较对象是上一代模型 (当时 Anthropic 已发 Opus 4.8)，符合 Q1 电话会说的"落后前沿 3-6 个月，但训练成本只要一小部分"的定位。市场不买账 (Acecamp 06-11 评论)。我们的理解：微软不需要最强的模型，需要的是便宜的、可以大量承担 Copilot 和 GitHub 日常任务的模型，以降低推理成本和对 OpenAI 的依赖 (OpenAI 占 Q1 收入 11%)。
十四、Frontier Tuning：企业自己的模型 Foundry / M365 必读
纪要原文：在为麦肯锡的任务进行模型调优后，其胜率超过了GPT-5.5，同时成本效率也提升了十倍。
解读让企业用自己的数据和工作流 (M365 里的 Teams、Outlook、Excel 信号) 做强化学习，把便宜的 MAI 模型调到接近前沿模型的效果。卖点是"收益完全归属于企业自己"。对微软的意义：企业的私有数据、评估标准和调好的模型都沉淀在 Foundry 上，迁移成本很高。Q1 电话会的联合利华例子 (先用前沿模型，再换成用自己轨迹数据训练的 MAI 模型) 就是这条路径的实例。10 倍成本效率是微软自己的数据，需要谨慎看待。
十五、Discovery、Mayo Clinic、量子 科研 / 医疗 / 量子 可跳过
纪要原文：Majorana 2的量子比特寿命可达20秒，甚至长达一分钟。
解读远期项目：Discovery 科研 agent 平台正式发布 (Q1 电话会提到圣戈班案例)、和 Mayo Clinic 合作做医疗前沿模型、量子芯片 Majorana 2。对未来 3-5 年的收入影响很小，可跳过。

和我们 MSFT - Deep 的关系：Build 讲的是"六层"里第 3 层 (上下文：Microsoft IQ)、第 4 层 (平台：Foundry)、第 6 层 (治理：Agent 365、MXC) 的扩张，以及第 2 层 (应用) 从"人用的 Copilot"变成"agent 也要许可证"。这些都支持 Deep 的判断：微软最难被替代的是上下文和治理两层，而不是模型。但它们都没有改变估值的核心变量，也就是 capex 强度。

接下来要盯什么

  • Autopilot 的定价和是否单独披露"agent 许可证"数量。这是"agent 会不会变成新坐席"的直接证据。
  • Ignite 2026 (11-17 起) 会不会公布 Autopilot、E7 的进一步数字，或 Copilot 坐席数。
  • Agent 365 在 AWS、GCP 上管理的 agent 占比。如果大量非 Azure 的 agent 也交给微软治理，"治理层护城河"的判断就成立。
  • MAI 模型在 Copilot 和 GitHub 里承担的任务比例 (Q1：MAI-Cyber 占 MDASH 扫描 40%)，以及 OpenAI 占收入比例的变化。
  • 核心 Azure (CPU) 的增速。如果 agent 真的让 CPU 和 GPU 接近 1 : 1，核心 Azure 应该持续加速。
