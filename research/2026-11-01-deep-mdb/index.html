结论

一句话：MDB 是企业 App 背后的"账本数据库"，主要按"在云上租了多大的数据库集群、租了多久"收钱。增长是真的但是"老逻辑"：大企业把更多老应用搬上 Atlas，Atlas 已经 6 个季度停在 ~29%。AI 写新应用时入口在被 Postgres 拿走，AI 带来的量又被"按容量计价"打了折。现价 $353 (10-30 收盘) 要求未来 5 年收入每年涨 ~18% (不扣 SBC) 到 ~27% (扣 SBC)，我们的基本情景 ~18%，正好是"合理价"。结论：不买，放观察；买点 $290-325 (较现价低 ~8-18%)。

它怎么收钱：约 3/4 收入是 Atlas (MongoDB 替客户在 AWS、Azure、GCP 上运行数据库)，按"集群规格 × 小时 × 节点数"计费，大客户签年度承诺拿折扣，小客户刷信用卡按月付；约 1/4 是 EA (客户在自己机房跑，买年度或多年订阅，多年合同里的许可部分签约当季一次性确认，所以 EA 收入很跳)。计费单位是"生产负载占用的算力和时间"，不是人头，所以不怕"agent 替代人"；但也不是"每次调用"，所以 AI 的量要先撑满容量才变成收入。

为什么增长是真的：FY27Q2 Atlas $566M (+28.9%)，同比美元增量 $127M，连续 6 个季度创新高；NRR 122% (一年前 119%)；$1M+ 客户 434 家，5 年复合 34%。营业利润率一年里从 15% 到 24%，FCF 翻倍。和 SNOW 相比，MDB 毛利率稳 (76%)，没有 AI token 稀释的问题。

为什么还不买：(1) 不加速：Atlas 26% → 29% → 30% → 29% → 29.4% → 28.9%，CFO 自己说今天签的负载和历史上"没有大的不同"，AI-native 只占 Atlas 3-5%；管理层的中期目标只给 Atlas mid-20s。(2) 入口在丢：CEO 承认 coding agent 默认选 Postgres，Stack Overflow 使用率 24% → 19%，Claude Code 选库研究里 MongoDB 首选 0 次。今天影响很小 (新客户只占收入 3-4%)，但它决定 2-3 年后有没有新负载可长。(3) 管理层：CEO CJ Desai 上任 10 个月后 9-28 去了 Meta，前任 Dev Ittycheria 回来暂代，CRO 3 月就走了。(4) 股东经济学：SBC 占收入 ~20%，扣掉 SBC 后 FCF 收益率只有 0.3%；好在每年 ~$4 亿回购稳住股数。

和 10-21 MDB - 101 比：结论不变 (不买)，买点从 $280-310 小幅上移到 $290-325：FY27 收入我们从指引中值 $3.01B 上调到 $3.06B (按 200-300bp 的超指引惯例)，并统一了各家 Deep 的估值参数 (口径 B 毛稀释 2%/年、终局倍数按终局增速定)。股价从 $366 跌到 $353，还在买点上方 ~9%。Caffrey 说"DDOG、SNOW 的 play 基本就是收入加速 / 减速"，MDB 也是：每股价值对收入 CAGR 最敏感 (见 6.2)，而它的问题恰恰是不加速。

增长分型：A 类 (核心产品用量驱动)。MDB 和 DDOG、SNOW、FROG 一样，增长来自"客户把更多应用放上 Atlas、已有应用用得更多"，不是靠新产品提价 (MDB 的标价多年基本没变，Search、Vector 等新功能是按节点加量，不是让老客户换贵的套餐)。所以杠杆写成"每个客户账单的加减项"。要补一句：MDB 是 A 类里传导最"钝"的一家，按集群容量而不是按每次调用收钱 (见 1.3)。

这只股票在测试什么

1. 产品：它是什么、怎么运转、凭什么赢

1.1 一句话 + 一个例子

MDB 卖的是"应用的账本"。你手机上的 App、网站后台，每一次下单、发消息、改头像，都要写进一个数据库并能马上读出来，这叫操作型数据库 (OLTP，和 SNOW 那种"事后汇总分析"的分析型数据库是两类)。MongoDB 是全世界最大的"文档型"操作数据库：一个客户的资料、地址、订单可以存成一个嵌套的 JSON 样的"文档"，结构随时加字段，和程序代码里的对象长得一样。

一个好记的比喻：关系型数据库 (Oracle、Postgres) 像一套按科目分好的账本，客户信息一本、订单一本、地址一本，要看一个客户得翻三本对起来，加一个新科目要重新画表格；MongoDB 像给每个客户一个文件袋，所有东西装在一起，加东西直接塞进去。前者规矩、适合复杂对账；后者快、适合变化快的 App。下面这张图把一个应用从写原型到长大拆成 5 站，标出每站怎么收钱、谁最强。

三条产品线：Atlas (MDB 替你在 AWS、Azure、GCP 上运行和运维数据库，占收入 ~3/4)；EA (Enterprise Advanced) (客户在自己机房或私有云里自己运行，买订阅和支持，~1/4)；社区版 (免费，累计下载 1.5 亿次，是开发者入口)。2025 年 2 月收购的 Voyage AI 做 embedding / rerank 模型 (把文字变成向量)，按 token 收费，体量还小。再拿一个具体请求走一遍，看 agent 怎么改变数据库被用的方式和账单：

1.2 行业背景：为什么需要它

数据库分两类：操作型 (App 的"收银台"，每笔交易实时写进去：Oracle、SQL Server、Postgres、MySQL、MongoDB、DynamoDB) 和分析型 (公司的"财务部"，把所有收银台的数据汇到一起算总数：SNOW、DBX、BigQuery)。操作型是更老、更大的那块，过去 40 年由 Oracle 和 SQL Server 主导，跑在客户机房里、按 CPU 核买许可。过去 15 年两个变化让 MDB 长起来：(1) 应用从"一年改一次"变成"每周发版"，表结构经常变，文档模型比改关系型表快；(2) 应用上云，没人想自己运维数据库，托管服务 (Atlas、云厂商自家库) 取代自管。AI 加了第三个变化：应用数量暴增，但写应用的越来越多是 coding agent，而 agent 的默认选择是 Postgres (见 3.2)。行业全貌见 数据平台行业入门。

1.3 怎么收费

一句话商业模式：混合，但以用量为主。FY27E 约 76% 收入是 Atlas 用量制 (按集群规格 × 小时 × 节点数，大客户年度承诺、小客户按月刷卡)，约 21% 是 EA 自管订阅 (年度或多年合同，许可部分签约时一次性确认)，约 3% 是专业服务。

Atlas 的日常账单：一家银行的手机 App 后台。生产库用 M60 规格 (64GB 内存)，按高可用要求放 3 个节点 (1 主 2 副本)；监管要求异地容灾，在第二个区域再放 2 个节点；App 里的搜索 (搜交易、搜商户) 用 2 个搜索节点；开发和测试环境用 3 个小号 M30 节点；再加备份快照和出站流量。账单上每一行都是"节点 × 每小时单价 × 8,760 小时"：

EA 的日常账单：一家欧洲银行出于数据主权要求，核心系统必须在自己机房。它和 MDB 签 3 年合同，总价 $150 万 (示意)。会计上合同拆成两部分：期限许可 (~25-30%，示意取 27%，即 ~$405K) 在签约当季一次性确认，支持和更新服务 (~$1095K) 在 36 个月里按月确认。所以签一张 3 年大单，当季 EA 收入会跳一下，之后两年只确认服务费，这就是"EA 收入很跳、要看 ARR"的原因 (FY27Q2 EA 收入 +36%，剔除期限后的 EA ARR 只 +11%)。

收费单位谁算一个单位、怎么计数跟着什么涨AI 用量涨会多收钱吗
Atlas 数据节点小时 (主体)每个数据节点按规格 (M10 到 M700) 每小时计价；副本、分片、多区域都按节点成倍算数据量、读写量、高可用要求 (多区域、多云)要撑满才多收：同一个集群里多跑 10 万次 agent 查询不多收钱，只有容量不够、升规格或加分片时才涨
Atlas Flex / FreeFree 永久免费 (512MB)；Flex 按每秒操作数分档，封顶 $30/月原型和小应用的数量基本不：AI 原型和 vibe coding 项目多停在这里
搜索 / 向量节点小时独立的搜索节点 (S20-S80) 按小时检索 QPS、索引大小是：RAG 上生产、检索变多就要加节点
存储、备份、流量超出规格内含部分按 GB-月；快照按 GB-月；出站流量按 GB数据量部分：向量让单个文档变大
Voyage token每百万 token ($0.02-0.18)，前 2 亿 token 免费被向量化的数据量 + 查询次数是，直接按 AI 调用收；但单价很低，要很大规模才进数字
EA 服务器 / 内存按客户机房里跑 MongoDB 的服务器和内存规模报价 (不公开)客户自管部署的规模是，但一次签几年，体现为签约当季的跳升

承诺 vs 按需：大客户和 MDB (或通过 AWS、Azure、GCP 的 marketplace，约占总收入一半) 签年度承诺，承诺额越大折扣越多，每月按实际节点小时从承诺额里扣，用超了按承诺价补，用不完通常不退。小客户 (每季新增的 2,500-3,000 家几乎全是) 刷信用卡、按月按实际用量付。公司不披露两者比例，我们估承诺部分 ~85%。这对数字的含义有三点：(1) Atlas 收入按实际消耗确认，不是按承诺额平摊，所以它是"真实用量"的读数，客户一优化当季就看得到 (2022 年就是这样)；(2) RPO 主要反映承诺额和 EA 多年合同，不等于 Atlas 用量 (FY27Q2 RPO $1.52B +91%，被 EA 多年单和更长的 Atlas 承诺推高，不能直接当加速信号)；(3) 2024 年销售提成从"签大承诺"改成"看实际用量"，导致当年 Atlas 增速下滑，前 SVP Meghan Gill 说管理层后来又想往"承诺"那边拉回一点，"客户签了承诺会用得更多"。

thesis 押在哪种收费方式上：押在 Atlas 数据节点小时上，即"更多关键负载上 Atlas、已有负载长大"。EA 2026 年重新长起来 (ARR 连续 3 季双位数)，对总收入是好事，但它把一部分 AI 负载 (银行、政府想在自己机房里做 AI) 从 Atlas 分走，CFO 承认 Atlas 占比上升"比此前预期慢"。AI 收费最直接的 Voyage 和 Agent Engine 今天还小到不进数字。

价目表 (官网，2026-10-21)：Atlas Dedicated M10 $0.08/小时 (约 $57/月起)、M30 $0.61、M60 $4.67、M200 $17.98、M700 $40.48 (每节点小时，AWS)；Flex $0.011-0.041/小时，封顶 $30/月；搜索节点 S20 ~$0.12-0.15 到 S80 ~$3.26-4.22/小时；Voyage-4 $0.06、voyage-4-large $0.12 每百万 token；Atlas Infinite (2026-09 预览，存算分离) 存储 $0.30/GB-月；按请求计费的 Serverless 已于 2026-01-22 停用；EA 不公开报价。完整表见 MDB - 101 的"怎么收钱：计费单位表"。

1.4 逻辑上：AI 是受益还是受损

方向机制证据我们的判断
核心一行：收费单位变多还是变少收费单位 = 生产负载占用的节点小时。AI 让应用数量和读写次数变多，方向是变多；但按容量计价，量要撑满才升级，且一部分 AI 负载落在 EAtoken 涨 3-4 倍时，Atlas 里 AI 相关消费只涨约 2 倍 (GSI 专家)；CPO："周末多跑 10 万次 agent 查询不多收钱"变多，但传导钝。比 NOW、TEAM (人头可能变少) 好，比 SNOW、DDOG (按每次计算、按数据量) 钝。MDB 在用 Atlas Infinite (按实际用量的存算分离) 和 Agent Engine 试着把单位换得更"跟量走"
受益：agent 的记忆和状态agent 每一步的会话历史、状态、检查点都要存，输入输出都是 JSON、结构常变，文档数据库天然合适前沿实验室 4 周把聊天记忆从 Postgres 迁到 Atlas (读取快 10 倍)；Emergent 1,800 万个应用跑在 MDB 上 (投资者日)真实，但管理层自己说"从 MongoDB 起步的 AI 公司是少数"，多数是撞到规模瓶颈以后才来
受益：迁移变便宜AI 写代码让 Oracle、SQL Server 上的老应用改写到 MongoDB 变快迁移周期 18-24 周 → 4-8 周 (CEO 09 月)；欧洲大型零售商 Oracle ERP 迁 MDB，3 年 ARR 7 倍方向对，产品化要到 FY28；同样的 AI 也让"迁到 Postgres"变便宜
受损：入口coding agent 和 vibe coding 平台默认选 Postgres；SQL 有 50 年公开语料，模型"学得更熟"CEO："你没法操纵提示词"；CPO：要做"内容追赶"；Lovable 内置 Supabase；~90% vibe coding 新代码用 Postgres 或类 SQL (顾问估计)最重要的一条负项，今天收入影响小，3 年后影响大
受损：AI 的钱先流向别处企业 AI 预算先给模型、算力和分析平台 (SNOW、DBX 都推出了自己的 Postgres)，操作型数据库排在最后AI-native 只占 Atlas 3-5%；企业对客 agent 还没规模化 (安全、治理)时间问题多于方向问题

和其他几家的类比：DDOG 受益于软件系统更复杂；SNOW 受益于数据被查得更勤；NOW 受益于"要派活和验收的事变多"、受损于"干活的人变少"；MDB 受益于"应用变多、状态要存"，受损于"新应用不从它开始"、而且量要撑满容量才变钱。

为什么只有它把这三站做成了：出身和 15 年的专注。MongoDB 2009 年从一开始就是"为开发者写的文档数据库"，水平扩展 (分片) 是原生设计，不是后加的；2016 年推出 Atlas 时选择了"三朵云都上、一个集群可以跨云"，而 AWS DocumentDB、Azure Cosmos DB 只在自家云上。2018 年把开源许可改成 SSPL，云厂商不能直接拿去卖，只能做"兼容层" (兼容 API 但不是同一个引擎)。搜索和向量放进同一个库 (2019 年起 Atlas Search，2023 年 Vector Search)，客户不用再同步一个 Elasticsearch 或 Pinecone。

巨头为什么不能自己做：云厂商不是早就有文档数据库了吗？

先核对前提：巨头不但做过，而且一直在做。AWS 2019 年推出 DocumentDB (兼容 MongoDB API 的自研引擎)，2024 年又和微软一起支持开源的 DocumentDB (Postgres 上的 MongoDB 兼容层)；Azure 有 Cosmos DB (据称是 OpenAI 的主力数据库之一)；Google 有 Firestore；DynamoDB 是 AWS 上 NoSQL 的默认选项。结果是：MDB 在它们的地盘上长成了 $30 亿的生意，而且约一半收入就是通过它们的 marketplace 卖的。巨头做出来了但没赢下来，原因不是写代码：

  1. 跨云中立。大企业的应用分布在三朵云上；DocumentDB 只在 AWS、Cosmos DB 只在 Azure。MDB 一个集群可以跨三朵云，金融客户把它当作"不被一家云锁死"的工具。
  2. 兼容层不是本体。DocumentDB、Cosmos DB 兼容 MongoDB 的 API，但功能 (事务、聚合、搜索、向量) 总是落后一截，复杂应用迁过去会碰到不兼容；SSPL 让云厂商不能直接拿 MongoDB 引擎来卖。
  3. 开发者心智和 15 年的产品积累。MongoDB 是开发者"认识的那个"文档数据库，驱动、文档、社区都最全。
  4. 激励不同。对云厂商，数据库是卖算力的配套；客户跑 Atlas 也一样买它的机器，Atlas 的消费还能计入客户对云厂商的承诺额 (这是 marketplace 占一半的原因)。这一条是我们的判断。

所以巨头真正的威胁不是"做出一样的产品"，而是截走入口和预算：(1) "all-in 一朵云"的企业直接用已承诺的云预算买自家库；(2) 更重要的是新入口：AI 编程工具和 vibe coding 平台默认用 Postgres，而 SNOW (2025 年收购 Crunchy Data) 和 DBX (2025 年收购 Neon) 也在卖 Postgres，对"数据已经在 SNOW 或 DBX 里"的客户，新 agent 应用直接用它们的 Postgres 很顺手。这就是总结表里"重置成本"一行的意思：替代的是新应用，不是旧应用。

用了 Postgres 的企业还会买 MDB 吗？会，并存是常态

  • 并存是常态。几乎所有大企业两种都有：关系型跑财务、ERP、报表；MongoDB 跑变化快、规模大的 App 后台。埃森哲 AI 团队的专家说他们的客服 AI 方案同时用 Postgres 和 MongoDB，再加 Redis 做缓存 (Merit 08-14)。
  • 正面交锋发生在"新应用选什么库"那一刻。一位全球 SI 合作伙伴 (Merit 08-19)：已有 MongoDB 的客户在新应用上"不再默认 MongoDB"，而是延长决策、比较成本 (Postgres 免费)；AI 刚火时，即使客户已有 MongoDB，仍然选了 Pinecone、Weaviate 等专用向量库，MDB 靠收购 Voyage 才补上。
  • 双向的真实案例：向 MDB：一家前沿实验室 4 周把聊天记忆从 Postgres 迁到 Atlas；Emergent 用 Postgres 起步，agent 频繁卡在表结构迁移，用 eval 测过后换成 MongoDB (投资者日)；欧洲大型零售商把 Oracle ERP 迁到 MDB。离开 MDB：一家团队因运维负担改用 RDS Postgres + JSONB (InfoQ 转述，MDB - 101 引用)；Lovable、Replit 等平台把新项目默认放进 Postgres。
