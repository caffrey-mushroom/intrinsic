Kernel 是模型里每一步数学运算在芯片上的具体做法。这份 primer 讲清楚它是什么、为什么同一块芯片跑出来的速度能差几倍、它和 PyTorch、CUDA 是什么关系、会写的人为什么少，以及这些对 NVIDIA 和自研芯片意味着什么。把之前几次讨论 (CUDA 是什么、kernel 调优、TPU 外部化) 收成了一篇。

Kernel 决定了同一块芯片实际能干多少活：FlashAttention 只改了计算顺序，数学结果不变，GPT-2 训练就快了 3 倍。

标准运算有 NVIDIA 写好的库和编译器自动生成；真正要人手写的，是新的模型结构、特殊的数据形状和新芯片。会写的人很少，而且换一种芯片，就要从头写一遍。

NVIDIA 的护城河，具体就是这批已经写好的 kernel 和会写的人。AI 自己写 kernel 是唯一可能很快改变这一点的变量，但到 2026 年 7 月，经过严格验证，最好的模型写出来的 kernel 平均还是比 PyTorch 自带的慢。

Follow-up (复查 2027.02.28)

AI 写 kernel 的严格验证成绩。它是唯一能很快打破"会写的人少"这个瓶颈的变量。现在的基线：Meta 的 KernelBench-Verified 上，最好的模型平均速度只有 PyTorch 的 0.88 倍，每道题挑最好的一个样本，也只有约一半的题能跑赢。看到平均超过 1.2 倍、作弊被堵住，说明 kernel 不再靠人，AMD 和各家自研芯片追赶会明显加快；一直低于 1 倍，说明人仍然是瓶颈。

新模型在非 NVIDIA 芯片上的上线速度。这是 kernel 存量差距最直接的读数。现在的基线 (我们的判断)：新模型在 N 卡上通常发布当天就能跑得不错；在 TPU 上要靠 Google 和外部团队 (Inferact、RadixArk) 一个模型一个模型地写。看到 TPU、Trainium 也能发布当天上线且效率接近，说明护城河在变浅；仍然要等几周，说明没变。

同一个模型在不同芯片上的实测吞吐，随时间怎么变。它直接决定我们 1GW capex 比较里"每 MW 产出多少"那一项。现在的基线：SemiAnalysis 报道 TPUv7 在一个推理榜上一度超过 GB300，NVIDIA 随后组织工程师和 agent 加班追回。差距持续缩小，说明 kernel 差距在缩；来回拉锯，说明双方都在靠人堆，谁人多谁赢。

1. Kernel 是什么

一句话：kernel 是一段跑在 GPU (或 TPU) 上的小程序，负责把模型里某一步数学运算真正算出来。

底层怎么工作

  • 一个大模型说到底是一长串数学运算：矩阵乘法、attention、softmax、layernorm 等等。跑一次推理，背后要依次执行几百到上千个这样的步骤
  • 每一步要在芯片上跑起来，都得有人把细节写清楚：数据从哪里搬来、切成多大的块、几千个计算单元各算哪一块、算完放到哪里。这段"具体做法"就是 kernel
  • 同一个运算，可以有很多种写法，数学结果完全一样，速度可以差好几倍

一个贯穿全篇的比喻：厨房

  • GPU 是一个有几千个厨师的大厨房。每个厨师只会切和炒这种简单动作，但可以同时开工
  • HBM (显存) 是后面的大仓库：东西放得多，但离灶台远，来回一趟慢
  • 片上 SRAM 是每个灶台边的小台面：伸手就能拿到，很快，但只放得下一点点
  • 模型是菜单，kernel 是每道菜在这间厨房里的作业指导书 (SOP)：先从仓库拿哪些料、在台面上怎么摆、厨师怎么分工、做好的菜放哪

核心指标：算力利用率 (MFU)

厨师们实际在炒菜的时间，占全部时间的比例。理论峰值是所有厨师一刻不停地炒；实际上很多时间在等料从仓库运过来。Meta 训练 Llama 3 405B 时，在 8,192 到 16,384 颗 H100 上做到了 38–43%，这已经是业内顶尖的水平。也就是说，即使是最好的团队，一半以上的算力也在空等。

举个例子：FlashAttention

原来的 attention 做法，每算完一步，就把中间结果送回仓库，下一步再从仓库取出来。FlashAttention 把数据切成刚好放得下台面的小块，在台面上一口气做完几步，大大减少了跑仓库的次数。数学结果完全一样，GPT-2 训练快了 3 倍，长文本 (1K–4K 长度) 的任务快了 2.4 倍；省下来的内存，也让以前跑不动的 16K、64K 长度第一次能跑出有意义的结果。

现在到哪一步

  • 标准运算 (常见尺寸的矩阵乘法等)：NVIDIA 的现成库已经调得很好，大部分人直接用
  • 新的模型结构、新芯片：靠各家团队手写
  • 编译器能自动生成一部分 (见第 3 节)
  • AI 自动写 kernel：还在实验阶段，严格验证下还跑不赢现成实现 (见第 6 节)

一句话：厨房和菜单都一样，SOP 写得好坏，出菜速度能差几倍，这份 SOP 就是 kernel。

2. 机制：快慢从哪来

大多数时候，慢的不是"算"，而是"搬"。FlashAttention 的论文以 A100 为例：仓库 (HBM) 有 40–80GB，每秒能搬约 1.5–2.0TB；台面 (SRAM) 每个计算单元只有 192KB，但每秒能搬约 19TB。仓库比所有台面加起来还大约 2,000 倍，但台面快大约 10 倍。所以写 kernel 的核心问题是：怎么让厨师尽量少跑仓库。

写 kernel 常用的四招

手法做什么厨房里的意思
融合 (fusion)把几个小运算合成一个 kernel，中间结果不写回 HBM切、腌、炒在同一个台面上一口气做完，不把半成品送回仓库
分块 (tiling)把大矩阵切成刚好装进 SRAM 的小块每次只拿一台面装得下的料
用专用单元用好 Tensor Core、FP8 / FP4 低精度单元用上专门的切菜机，但得照它的规矩摆料
搬算重叠这一块在算的同时，下一块已经在路上厨师炒这锅的时候，下一锅的料已经在推车上

性能是三段串起来的，最弱的一段说了算

  • 算什么 (模型结构)：由模型团队决定
  • 怎么在这块芯片上算 (kernel)：由芯片厂的库、框架和编译器、各家 infra 团队决定
  • 芯片能算多快 (硬件)：由芯片厂决定

硬件参数可以在发布会上一次说清楚，kernel 却要一个运算一个运算地补。新模型、新芯片刚出来的时候，卡住的几乎总是中间这一段。

一句话：同一块芯片的实际产出，取决于 kernel 能让它少等多少料。

3. 和 PyTorch、CUDA、Triton 是什么关系

研究员写的是 PyTorch (或 Google 的 JAX)，几乎不碰 kernel。PyTorch 更像点菜系统：把菜单上的每道菜，变成厨房里一张张具体的工单。工单落到厨房，最后执行的还是 kernel。

几个常被混在一起的名字

名字是什么谁做的能跑在哪难度
PyTorch写模型用的框架，点菜系统Meta 起家，现归 PyTorch 基金会都能研究员日常
CUDA在 NVIDIA 卡上写 kernel 的语言和工具，外加一大本现成的 SOP (库)NVIDIA只有 NVIDIA难
cuBLAS / cuDNNNVIDIA 写好、调好的标准 kernel 库NVIDIA只有 NVIDIA不用写，直接调
CUTLASS写高性能矩阵乘法的模板库NVIDIA只有 NVIDIA难
Triton用类似 Python 的写法写 kernelOpenAINVIDIA、AMD中等
torch.compile自动把几个运算合并，并生成 Triton 代码PyTorchNVIDIA、AMD 等不用写
XLA / PallasGoogle 的编译器 / 手写 TPU kernel 的语言GoogleTPU (Pallas 也支持 GPU)中等到难
  • CUDA 不会自动把 kernel 写好。它是工具加一本现成的 SOP。用 CUDA 能写出很快的 kernel，也能写出很慢的
  • Triton 把门槛拉低了一截。OpenAI 2021 年说，用 Triton 不到 25 行代码就能写出和 cuBLAS 一样快的 FP16 矩阵乘法，这是很多 GPU 程序员做不到的。但这说的是最常见的运算；新结构和最后那截性能，仍然要懂硬件的人来抠
  • 每种芯片要自己的一套。CUDA kernel 搬不到 TPU 上，TPU 的 Pallas kernel 也搬不到 N 卡上。厨房布局不同，SOP 就得重写

一句话：研究员写 PyTorch，PyTorch 调 kernel，kernel 才真正在芯片上跑；CUDA 是 N 卡上写 kernel 的工具和现成的 kernel 库。

4. 一句话规则：什么时候要人手写

规则：这个运算的"结构、形状、芯片"三样里，只要有一样是现成库和编译器没覆盖到的，就要有人手写；三样都是常见的，直接用现成的就够了。

场景现成的能覆盖吗要不要手写例子
常见尺寸的矩阵乘法能 (cuBLAS)不用自己重写很难赢
新的 attention 结构不能要DeepSeek 自己写并开源了 FlashMLA、DeepGEMM
推理时 batch 很小、要求低延迟部分常常要把整个 decode 步骤写成一个大 kernel (megakernel)
新一代芯片的新指令 (比如 FP4)刚出时不全要新卡上市后，库要过一段时间才把新指令完全用上
非 NVIDIA 的芯片库薄得多大量要Google 请 vLLM 创始人的公司 Inferact 一起把 vLLM 搬上 TPU

为什么这件事值钱

利用率每提高一点，都是直接省下来的设备钱。用我们 v1 sizing 里的数算一遍：一个 1GW 的 VR NVL72 集群，IT capex 约 $41.6bn。如果 kernel 优化把利用率从 40% 提到 50%，同样的设备多出 25% 的产出；换个角度说，要达到原来的产出，只需要买 $41.6bn ÷ 1.25 = $33.3bn 的设备，相当于省下 $8.3bn。对每天跑几百亿 token 的实验室，这就是养一支 kernel 团队的理由。

算式：省下的 capex = IT capex × (1 − 原利用率 ÷ 新利用率) = $41.6bn × (1 − 40% ÷ 50%)。40% 和 50% 是举例用的假设，不是实测。

一句话：结构、形状、芯片三样都常见，用现成的；有一样是新的，就要人写，而写好的那部分直接变成省下来的 capex。

5. 会写的人为什么少

  • 要同时懂三样东西。芯片内部怎么搬数据、怎么算 (存储层级、专用指令)；数值精度会不会出问题 (FP8、FP4 下的溢出和误差)；这个运算在模型里是干什么的。三样都懂的人很少
  • 技能不能直接迁移。CUDA 上的经验搬到 TPU 要重新学一套内存模型和写法。过去十年，会写 TPU kernel 的人基本只在 Google 内部有市场，外面几乎没有人学
  • 活永远干不完。每出一个新的模型结构、每出一代新芯片，都要重新写一遍。不是写完就结束的工程，是一直要有人跟着

市场上看到的证据

  • Google 为了让 TPU 跑好 vLLM 和 SGLang，找外部团队一起开发：vLLM-TorchTPU 是和 vLLM 创始人创办的 Inferact 合作做的，SGLang 那边有 RadixArk 参与。连 Google 都要从外面借人
  • SemiAnalysis 报道，TPUv7 在一个推理榜上一度超过 GB300 之后，NVIDIA 组织了工程师加 agent 连夜优化追回。拉开或追回性能差距，靠的就是这批人
  • 推理服务商 (Fireworks、Together 等) 卖的就是"比你自己跑更快更便宜"，核心就是自己写的 kernel，比如 Together 的首席科学家是 FlashAttention 的作者
  • 薪酬：没有找到可靠的公开数据，这里不写数字

一句话：会写 kernel 的人要同时懂芯片、数值和模型，技能换一种芯片就要重来，活还永远干不完，所以连 Google 都要从外面借人。

6. 最容易被误读的几点

大家以为实际
CUDA 会自动把 kernel 做好CUDA 是工具加一本现成的 SOP。现成的只覆盖标准运算，新结构要人写
编译器 (torch.compile) 很快会取代手写编译器能自动拿到一部分好处；前沿实验室的关键 kernel 仍然手写，因为最后那截差距就是钱
芯片参数好，就能跑得好实际产出取决于 kernel 有没有写好。新芯片刚发布时的 benchmark，往往低估它半年后的水平
AI 已经能自己写 kernel 了2025 年的 KernelBench：模型写的 kernel 平均不到 20% 的题能跑赢 PyTorch。2026 年 7 月 Meta 做了更严格的验证：最好的模型平均速度只有 PyTorch 的 0.88 倍，还发现有模型靠跳过计算"作弊"

一句话：AI 写 kernel 在进步，但到 2026 年 7 月，严格验证下平均还跑不赢 PyTorch 自带的实现，"人少"这个瓶颈还在。

7. 对投资意味着什么

  • NVIDIA 的护城河是一个可以数的存量：多少个模型、多少个算子、已经有人花了多少工程师小时调好。中小客户和长尾模型没有能力自己写，这部分护城河最稳
  • 自研芯片要一个模型一个模型地补。Google、Anthropic 这样有全栈团队的玩家补得起，所以 TPU 能在最大的几个客户身上拿份额；没有团队的客户，买 N 卡最省事
  • 和我们 1GW capex 工作的关系：我们比的是每 GW 花多少钱，但客户真正比的是每 MW 能产出多少 token。这个产出差距，有很大一部分就是 kernel 差距，而且会随时间变。新芯片刚出来时的对比，容易低估还在补 kernel 的一方
  • 最大的变量是 AI 写 kernel。如果它真的能稳定跑赢人写的版本，门槛会大幅下降，最受益的是 AMD 和各家自研芯片，NVIDIA 的软件优势会变薄。这目前还只是"理论上可能"，严格验证的数据还不支持

一句话：kernel 是 CUDA 护城河的具体内容，自研芯片能不能追上，看的是人和 AI 写 kernel 的速度，而不是硬件参数。
