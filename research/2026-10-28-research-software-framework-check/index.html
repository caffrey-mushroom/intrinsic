用 11 家公司检验软件框架

拿 SNOW、DDOG、DT、ESTC、MDB、TEAM、NOW、CRM、FROG、GTLB、PLTR 的业绩会、投资者日、专家访谈和渠道 check，逐条检验"agent 给软件带来的变化"这套框架：哪条成立，哪条要改，漏了什么。

一页结论

结论：框架拆成六条来验。三条成立 (coding 先落地、人从干活变成验收、业务 agent 慢)，一条部分成立 (新 infra 需求成立，但只有按量计费的收到钱)，一条要改说法 (上云)，一条方向对但时间没到 (钱从人工和席位来)。另外要新增一条：量涨价跌。

最站得住的是"coding 先落地"。SNOW、DDOG、FROG、GTLB 的业绩会都看到代码和应用量在涨，按用量收费的已经收到钱。要补一句：coding 同时在帮客户省钱 (SNOW 自己的 coding 工具里，前十大技能之一就是成本优化)。

"agent 驱动上云"要改成"AI 让上云更急、也更便宜"。DDOG 的 CFO 确实说 AI 提高了上云的紧迫性，SNOW、MDB、PLTR 都说迁移时间砍了一半以上。但迁移是一次性的 (TEAM 前高管："搬到马路对面")，迁完消费会走平，开放格式也让"上了云"不等于"锁在你这"。

"agent 需要新 infra"成立，但要拆开看收不收钱。需求端证据很多：微软 FDE 负责人说七到八成项目卡在数据安全和规模化，SNOW 渠道说进生产后消费跳一个数量级，电信客户安全预算增速从 5-10% 提到 10-15%。门被用得很多：TEAM 经 MCP 建的工单是原来的 4 倍，DDOG 的 MCP 调用是原来的 22 倍。但只有按用量计费的门收到钱 (DT 的 agent 调用直接扣额度)，按席位计费的门白给 (TEAM："价值最终会回到我们")。治理这道门 (NOW AICT) 有了第一批收入，但客户在多家之间分着买。

"人只能监测和验证"成立，而且最能解释为什么 coding 先落地。GitLab 内部开发者已经转去做审查、合规和 QA，客户在加资深开发者来看 AI 写的代码；非代码领域落得慢，正是因为缺验证步骤 (只有约 5% 的企业建好了评估体系)。但验收本身也在被 agent 化，钱会流向能自动验证、留下记录的系统，而不是按人头卖的审查工具。

"业务 agent 慢、要部署层"成立。CRM 生产部署的客户只有高个位数比例，SNOW CoWork 账户环比 +11%。但一旦进生产，消费是 POC 时的约 6 倍。部署层谁拿，还没定：PLTR、模型公司 (Anthropic 900 多人的 FDE 团队)、数据平台都在抢。

"钱从人工和席位来"方向对，但还没变成现金。席位没掉 (CRM、TEAM、GTLB 管理层都说席位在涨)，省下的时间也没变成省下的钱 (NOW 保险客户：每人每月省 15 小时，还没转成现金)。反而看到另一件事：席位厂商在先涨价。NOW 新套餐涨 20-30%，CRM 升级涨 60-80%，TEAM 的 DC 版两年涨了两次。这是框架里漏掉的风险：等省下的人变成现金，涨上去的价能不能守住。

怎么读：每条框架后面放这 11 家里最有分量的证据，分成"支持"和"挑战"两边。证据来自我们给每家公司做研究时整理的业绩会、投资者日、行业会议、专家访谈和卖方 check，都是原话，旁边是说话人身份。非管理层专家附背景和局限。

3. 为什么 agent 需要新 infra

框架的说法：agent 干得快、覆盖广，企业得先把数据、权限、监控、安全这些以前靠人默默兜着的东西做成系统。如果成立，应该看到三件事：卡住企业的不是模型而是这些底座；从试点到生产，花的钱主要在底座上；底座的预算在涨。下面三件事都看得到，但也有反例。

卡住企业的不是模型，是数据、权限和集成

进生产以后，钱花在底座上

安全和治理预算在涨

挑战

判断：需求端成立，证据很多。微软 FDE 负责人说七到八成项目卡在数据安全和规模化，电商平台说集成能力比钱更紧，SNOW 的渠道说进生产后消费跳一个数量级，主要花在数据准备、RAG 管道和治理上，电信客户的安全预算增速从 5-10% 提到 10-15%。要补的是：底座有三到四成是企业自己搭的，而且底座里也分输赢，传统集成层被 MCP 绕过了。

门被用得很多

挑战

人只能验收：证据也在

判断：部分成立，要拆开。门确实成了必经之路，调用量是成倍涨的。但收不收得到钱，取决于计费方式：按量计费的 (DT、DDOG、SNOW) 已经开始收；按席位计费的 (TEAM、NOW 的大部分、CRM 的大部分) 还在白给，只能靠"价值最终会回来"。治理是新的门，有第一笔收入，但会被几家分着拿。

3c. 人从干活变成验收

框架的说法：agent 干得比人快、比人广，人跟不上，只能退到监测、测试和验证。如果成立，应该看到：干活的环节在变快，审查和测试成了瓶颈；人在往审查岗位挪；能不能验证决定了 AI 能落地到哪。三件事都有证据，但最硬的证据集中在写代码。

写代码：审查成了瓶颈，人往审查挪

能不能验证，决定 AI 能落到哪

机器还不够准，人必须兜底

挑战：验收本身也在被 agent 化，而且不一定有人为它付钱

判断：成立，而且是框架里最能解释"为什么 coding 先落地"的一条。写代码的证据最硬：GitLab 内部开发者转去做审查、合规和 QA，审查不够就积压；客户在加资深开发者来看 AI 写的代码；MR 数量翻倍。非代码领域落得慢，原因正是缺验证步骤，只有约 5% 的企业建好了评估体系。

要改两点。第一，验收本身也在被 agent 化 (一个写、一个测)，AI 代码审查已经商品化、单位经济性差，所以钱不会流向按人头卖的审查工具，而是流向能自动判断对错、留下记录的系统：可观测、测试、安全、治理。第二，规则清楚的工作 (L1 服务台) 里人会直接退出，"人兜底"只适用于对错难判、出错代价高的工作。

3b. 新增：量涨价跌

价在跌

但量可能涨得更快

判断：要加进框架。量涨价跌是这一轮的共同规律：token、存储、日志单价都在降，最大的客户会把非实时、高量、低价值的数据搬走。所以"受益"要拆成两个数：机器调用量涨多少，单价降多少。目前 DDOG、SNOW 是量赢了价；如果哪个季度用量还在涨但收入增速掉了，就是价追上来了。

4. 业务 agent 慢、部署层

慢

但进了生产，量是跳的

部署层谁拿：PLTR 不是唯一选项

判断：成立。慢是普遍的，各家口径都指向"大多还在试点"。但进生产后，量是 POC 的 2-6 倍，这就是 2027 年的上行空间。部署层要改一句：它是治理成熟之前的窗口期生意，PLTR 现在最强，但模型公司、数据平台和 SI 都在建同样的团队。

5. 钱从人工和席位来

方向在：人工被替代、预算被挪

但席位还没掉，省下的时间还没变成钱

判断：方向对，时间没到。能看到人工被拿掉的机制 (NOW 80-85% 的请求不用人)，也能看到预算开始从减员里来，但席位数还在涨，省下的时间还没变成现金。同时发现一件框架里没有的事：席位厂商趁 AI 叙事在升档涨价，现在的增长有一块是价格，不是用量。等客户真的少人的时候，这块涨价最先受压。

修正后的框架

  1. Coding 先落地 (现在，最强)：写软件便宜了，代码、应用、制品的量在涨，按用量收费的平台先收到钱 (SNOW、DDOG、FROG)。但同一批工具也在帮客户省单位消耗。按人收费的输家先表现为增速放缓 (GTLB)，席位还没掉。新应用的起点由 agent 的默认选项决定 (Postgres)。
  2. AI 让上云更急、更便宜 (底盘，有限)：迁移时间砍半，AI 提高了现代化的紧迫性 (DDOG 非 AI 客户再加速)。但这是存量释放：强制迁移会用完，迁完消费会走平，开放格式让上云不等于锁定。
  3. Agent 运行要过几道门 (下一波)：企业卡在数据、权限和集成上，不是模型；进生产后花的钱主要在底座。数据、身份权限、记录系统、监控、安全。门的调用量已经成倍涨。按量计费的门已经收到钱，按席位计费的门还在白给。治理是新门，会被几家分着买。
  4. 人从干活变成验收：能验证的工作先落地 (代码能跑测试)；审查和测试成为瓶颈，资深的人被挪去验收。验收本身也在被 agent 化，钱流向能自动判断对错、留下记录的系统 (可观测、测试、安全、治理)。规则清楚的工作里人直接退出。
  5. 量涨价跌 (新增)：token、存储、日志单价都在降，最大客户会把高量低价值的部分搬走。每家都要看两个数：机器调用量涨多少，单价降多少。
  6. 业务 agent 慢，但进了生产量会跳：大多数客户还在试点。进生产后，消费是 POC 的 2-6 倍。部署层是治理成熟前的窗口期，PLTR 最强，但模型公司、数据平台、SI 都在抢。
  7. 钱从人工和席位来 (方向对，2027 年以后)：机制已经看到 (L1 请求 80-85% 不用人)，但省下的时间还没变成现金，席位还在涨。席位厂商正在趁机升档涨价。等客户真的少人，这块涨价最先受压。

一句话：机器干活的量在涨，按量收费的先收钱，按人收费的先涨价。量涨赢不赢得过价跌，人工省下的钱什么时候流过来，决定下一轮谁赢。
