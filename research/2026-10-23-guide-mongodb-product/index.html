MongoDB 到底是干什么的

给第一次接触数据库的人：用一个外卖 App 讲清楚数据库、文档和表格的区别、Atlas 和 EA、谁用谁买、每一步怎么收钱，再配 8 个可以直接看产品的视频。

MongoDB 是干什么的

一句话：每个 App 背后都有一本"账本"，记着每个用户、每笔订单、每条消息。MongoDB 卖的就是这本账本，以及帮你保管、扩容、备份这本账本的服务。

它和别家的区别：传统数据库 (Oracle、MySQL、Postgres) 把账记成很多张 Excel 表格，用编号互相关联；MongoDB 把一件事 (比如一个订单) 的所有信息写在同一张"卡片"上，卡片上想加什么栏目随时加。

它怎么赚钱：主要靠 Atlas，也就是"我们替你在 AWS/Azure/Google 云上运行这本账本"，按你占用的机器大小和时长每月收费，占收入约 73%。其余主要是 Enterprise Advanced：客户在自己机房里运行，买许可和技术支持。

下面从零讲起：数据库是干什么的，两种记账方式有什么不同，MongoDB 卖哪几样东西，谁用、谁决定、谁付钱，一个 App 从原型到上线每一步花多少钱，最后是可以直接看产品界面的视频。

数据库是什么：一个外卖 App 的后台

拿一个外卖 App 举例。你点开 App 到收到饭，后台至少要"写"和"读"这些东西：

你在 App 上做的事后台要记下 / 读出的东西对数据库的要求
打开 App，看到"欢迎回来，小王"读你的账户：名字、头像、常用地址、会员等级几毫秒内读出来，几千万用户同时在读
浏览餐厅和菜单读餐厅资料、菜品、价格、评分、营业时间每家餐厅的字段都不一样 (有的有套餐、有的有辣度选项)
点"下单"写一笔订单：谁、哪家店、哪几道菜、地址、优惠券、支付方式不能丢、不能记两次，扣钱和下单要同时成功
看骑手在路上每几秒写一次骑手位置，读最新位置写入量巨大，高峰时段翻好几倍
搜"附近的麻辣烫"按关键词和距离搜餐厅全文搜索 + 地理位置查询
问 App 里的 AI 助手"推荐点清淡的"按语义找相似菜品 (向量搜索)，记住你这次对话说过什么AI 时代的新需求：向量检索、对话记忆

这种"App 在线时实时读写的账本"叫操作型数据库 (行业里叫 OLTP)。它和 Snowflake、Databricks 那种"事后把所有数据拉到一起做报表分析"的分析型数据库是两回事：前者是收银台，后者是财务部月底做报表。MongoDB 属于前者。

几乎每一个软件都需要一个操作型数据库，所以这是软件世界里最大、最古老的品类之一 (Oracle 就是靠它起家的)。客户一旦把账记在某个数据库里，就很少换：换数据库等于把整个 App 的"地基"挖出来重浇。这是这门生意粘性高的原因。

两种记账方式：表格 vs 文档

同一笔外卖订单，两种数据库的存法：

Postgres / MySQL / Oracle：拆成 4 张表
customers 表
id | 名字 | 电话
 7 | 小王 | 138...

orders 表
id   | customer_id | 店铺   | 状态
9001 | 7           | 张亮麻辣烫 | 配送中

order_items 表
order_id | 菜品   | 数量 | 单价
9001     | 麻辣烫 | 1    | 28
9001     | 酸梅汤 | 2    | 6

payments 表
order_id | 方式  | 金额
9001     | 微信  | 40

打开订单详情页时，数据库要把 4 张表按编号拼起来 (叫 JOIN)。加一个"礼物留言"栏目，要先改表结构 (叫 schema 迁移)。

MongoDB：一张"卡片" (文档)
{
  "_id": 9001,
  "customer": { "id": 7, "name": "小王" },
  "shop": "张亮麻辣烫",
  "status": "配送中",
  "items": [
    { "dish": "麻辣烫", "qty": 1, "price": 28 },
    { "dish": "酸梅汤", "qty": 2, "price": 6 }
  ],
  "payment": { "method": "微信", "amount": 40 },
  "gift_note": "生日快乐"   ← 只有这单有，随时加
}

打开订单详情页读一次就够。这张卡片的格式就是程序员代码里本来就在用的 JSON，所以写代码时不用来回"翻译"。

关系型 (表格)文档型 (MongoDB)
好处每个信息只存一份 (客户改名，所有地方一起变)；跨订单统计 ("上个月各品类卖了多少") 用 SQL 很自然；规则 (外键、唯一性) 由数据库保证开发快，需求变了直接加字段；一个对象一次读写，延迟低；数据量大了可以原生"分片"到很多台机器
代价结构改起来麻烦；数据量极大时横向扩展要靠额外方案复杂的跨表统计不如 SQL 顺手；同样的信息可能存在多张卡片里
适合财务、ERP、计费、对账商品目录、用户档案、内容、IoT 设备、游戏/社交对象、AI agent 的记忆
代表Oracle、SQL Server、MySQL、Postgres (开源、免费、最流行)MongoDB (最大)、AWS DocumentDB、Azure Cosmos DB

这几年的变化：边界在变模糊。Postgres 加了 JSONB，可以在表格里塞一列 JSON；MongoDB 也补上了事务。所以今天的竞争不是"谁能做"，而是"谁是默认选项"。这也是我们在完整研究里最担心的一点：AI 写代码时默认选 Postgres。

MongoDB 卖哪几样东西

MongoDB 的软件本身是开源的 (准确说是"源码公开"，2018 年改成了 SSPL 许可，防止云厂商直接拿去卖)。它卖的东西分四样：

产品是什么打个比方怎么收钱占收入
社区版 (Community)免费下载的 MongoDB 软件，自己装在自己的服务器上，自己维护免费的菜谱和厨具，自己做饭、自己洗碗不收钱。累计下载约 1.5 亿次，是开发者入口0
AtlasMongoDB 替你在 AWS、Azure、Google 云上运行数据库：开机器、装软件、备份、升级、出故障自动切换、数据多了自动扩容。客户只拿到一个连接地址带物业的酒店式公寓：拎包入住，按面积和住多久付钱按用量月结：集群规格 × 小时数 × 节点数，加存储、备份、数据传输；还可以加搜索节点、向量搜索、流处理。大客户签年度承诺换折扣，约一半收入经 AWS/Azure/Google 的云市场结算约 73% (年化约 $22 亿)
Enterprise Advanced (EA)商业版软件，装在客户自己的机房或私有云里，客户自己运维；包含企业级安全、管理工具和 24 小时技术支持自己买房自住，但买了品牌厨具 + 24 小时维修电话年度或多年订阅。多年合同里约 25–30% 作为"许可"一次性确认收入，所以 EA 收入一个季度高一个季度低约 25%
Voyage AI2025 年 2 月收购的 AI 模型公司，做 embedding (把文字变成向量) 和 rerank (给搜索结果重新排序)给账本配了一个"理解意思"的检索员按 token 收费，每百万 token $0.02–0.12；也嵌进 Atlas，写入时自动生成向量很小

为什么客户愿意付钱，而不是用免费的社区版或免费的 Postgres 自己搭？因为数据库"装上"不难，"运维好"很难：凌晨三点主机挂了谁来切换？双十一流量翻 10 倍怎么扩容？备份能不能真恢复？升级会不会把 App 搞挂？英国卫报 2018 年的例子正好说明这一点：他们自己运维 MongoDB，上 AWS 后出了两次故障，运维脚本要自己写，最后换到了 AWS 托管的 Postgres。他们离开的原因不是文档模型不好，而是不想自己运维。Atlas 卖的就是"这些麻烦我们来扛"。

谁用、谁决定、谁付钱

角色做什么对 MongoDB 意味着什么
应用开发者 (后端 / 全栈)决定用什么数据库写代码。通常从免费版开始，自己刷信用卡入口。MongoDB 过去 15 年靠"开发者先爱上它"增长。现在一部分开发者变成了 AI coding agent，而 agent 默认选 Postgres
平台工程 / DBA (数据库管理员)负责数据库稳定、安全、成本：选规格、设备份、看慢查询、控账单决定用量。他们会优化、会压成本，也会推动"公司内新应用统一用 MongoDB"
CTO / CIO / 采购签年度承诺合同 (常常从已经承诺给 AWS/Azure 的云预算里扣)，决定要不要把老系统迁出 Oracle决定大单。2024 年起 MongoDB 的销售"上移大企业"，主要打这一层。$100 万以上年付客户 434 家，5 年复合增长 34%
系统集成商 (Accenture 等)帮大企业做迁移和新应用开发渠道。我们引用的渠道调研大多来自这些人

一个大客户通常是这样长大的：某个团队用免费版做了一个新功能 → 上线后换成付费集群 → 好用，公司里其他团队的新应用也用 → 平台团队把它设成"新应用默认数据库" → CIO 签多年承诺，再把一部分老系统从 Oracle、大型机迁过来。CEO 举过一个例子：一家北美财富 100 强公司把 MongoDB 定为新应用的默认标准，除非证明不适用。

一个 App 从试用到上线，每一步收多少钱

一个新 App 用 MongoDB 的典型路径。注意每一步 MongoDB 收多少钱：原型阶段几乎为零，真正的收入来自上线后长大的应用。

阶段发生了什么MongoDB 收多少钱
1. 试用开发者在 Atlas 网站注册，选 AWS/Azure/Google 和地区，几分钟拿到一个免费数据库的连接地址$0 (Free，512MB)
2. 写代码在 Python/Node/Java 代码里装官方驱动，把代码里的对象直接存成文档；或者让 Claude Code 通过 MongoDB 的 MCP 插件帮你建库、查数据$0 或 Flex 档，封顶 $30/月
3. 上线换成 Dedicated 集群：默认 3 台机器互为备份，一台挂了自动切换；打开自动扩容从 M10 约 $57/月起；M50 约 $2.35/小时，最大 M700 约 $40/小时；按节点数相乘
4. 长大用户多了升级规格；单个集群装不下就"分片"，把数据切到多组机器上，应用代码基本不改账单按 规格 × 节点数 × 分片数 成倍增长。这是 Atlas 收入增长的主要来源
5. 加功能加站内搜索 (不用再单独搭 Elasticsearch)、向量搜索做 AI 问答、实时数据流处理另买搜索节点、流处理器，按小时收费
6. 迁老系统大企业把 Oracle/SQL Server 上的老应用迁过来：免费工具 Relational Migrator 搬数据，难的是改代码，MongoDB 推出 AMP (AI 帮忙改代码 + 自家工程师交付)工具免费，钱从迁过来以后跑的负载里赚

和投资判断的关系：Atlas 按"开了多大的机器、开了多久"收费，而不是按"跑了多少次查询"收费。CPO 的原话是"周末多跑 10 万次 agent 查询也不额外收费"，只有把集群撑满、客户升级规格，才会多收钱。所以 AI 带来的查询量变成收入会比较慢、会打折。

AI 应用怎么用它

AI 应用为什么需要 MongoDB 这类数据库？三个最常见的用法：

  • AI 问答 (RAG)：把公司文档切成小段、转成向量，用户提问时先按"意思相近"找出相关段落，再交给大模型回答。MongoDB 的卖点是向量和原来的业务数据放在同一张卡片里，不用另外维护一个向量数据库并来回同步。
  • Agent 的记忆：一个 AI agent 做一件事要走很多步，每一步的状态、和用户的对话历史、用户偏好都要存起来，下次接着用。这些数据结构经常变、格式就是 JSON，正好是文档数据库的长处。LangChain/LangGraph 有官方的 MongoDB 插件。
  • 让 coding agent 直接操作数据库：开发者在 Claude Code、Cursor 里接上 MongoDB 的 MCP 服务，用自然语言让 agent 建库、看结构、查数据、建索引。

问题在入口：同样这些事，Postgres 加上 JSONB 和 pgvector 也能做，而且 AI 写代码时默认选它。Stack Overflow 2026 年开发者调查里 MongoDB 使用率 19% (2025 年 24%)，Postgres 58%；一项研究让 Claude Code 选 125 次数据库，MongoDB 一次也没有被首选；Supabase 超过 60% 的新数据库是 AI 工具建的。MongoDB 的反驳是：App 长大以后会撞到 Postgres 的瓶颈再迁过来，比如一家前沿 AI 实验室 4 周把聊天记忆从 Postgres 迁到 Atlas，读快约 10 倍。但管理层自己也说，从 MongoDB 起步的 AI 公司是少数。

回到投资判断

  • 好生意的部分：数据库是 App 的地基，客户很少换；Atlas 按用量收费，客户的 App 长大，MongoDB 自动跟着长大。所以它的增长稳定 (Atlas 连续 6 个季度约 29%)，大客户越来越大。
  • 增长从哪来：主要是大企业把更多老应用、新应用放到 Atlas 上，以及已有应用长大。这是"上云 + 换掉 Oracle"的老逻辑，不是 AI。
  • AI 时代的风险：过去的入口是"开发者喜欢它"，现在写代码的越来越多是 AI，而 AI 默认选 Postgres。AI 带来的查询量也因为按容量计价而传导得慢。
