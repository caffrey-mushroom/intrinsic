1. 行业科普

一句话：软件公司写代码像工厂造东西，GitLab 卖的是这条“软件流水线”：代码放在哪、谁改了什么、改完自动跑测试、扫安全漏洞、审批后发布上线。行业叫 DevOps，加上安全叫 DevSecOps。

以前这条流水线由很多小工具拼起来：存代码用 GitHub 或 Bitbucket，自动化用 Jenkins，安全扫描用 Snyk 或 Checkmarx，存安装包用 JFrog。GitLab 的卖点是一个产品全包，企业少管几家供应商，审计时只看一套记录。

空间多大。真正已经发生的收入比 TAM 小得多：

  • 实际数据 GitLab FY26 收入 $955M，管理层说年化收入已超过 $10 亿
  • 实际数据 GitHub (Microsoft) 2024 年 7 月披露整体年化收入 $20 亿。2026 年 1 月 Microsoft 披露 Copilot 付费订阅 470 万，同比约 +75%；之后 Copilot 改为按用量计费。Copilot 的绝对收入从未单独披露 (二手整理，未逐条对 Microsoft 原文)
  • 实际数据 JFrog TTM 收入 $6.0 亿；Atlassian TTM $65.7 亿，但大部分来自 Jira / Confluence，Bitbucket 只是一小块
  • 管理层口径 GitLab 过去给过约 $400 亿的 TAM (未核实最新口径)。这是“所有开发者、安全人员都按 GitLab 价格付费”的终端市场价值，不是它能收到的钱。几家主要平台今天加起来的实际收入约 $50 亿 (估算)

钱怎么分。开发者数量上 GitHub 远大于 GitLab，开源项目几乎都在 GitHub。GitLab 的地盘是受监管的大企业和政府，它们在意能装在自己机房 (self-managed)、权限和审计一体化。2024 年以后，新增的钱主要流向 AI 写代码工具 (Copilot、Cursor、Claude Code、OpenAI Codex)，这一层 GitLab 不占优。GitLab 在电话会上只说“我们仍然只有一个主要对手”，没有点名 GitHub。

竞争格局

阵营玩家模式对 GitLab 的威胁

上下游

  • 客户：大企业研发团队，金融和政府占比高。82% 收入来自美国 (Q1 FY27 10-Q)。年付费超 $10 万的客户 FY24 955 家、FY25 1,229 家、FY26 1,571 家。一半以上的收入来自首单不到 $5,000 的客户，说明“先小单进门、再扩张”这条路走得通
  • 供应商：GitLab.com 跑在 Google Cloud 上；AI 功能调用第三方大模型 (Anthropic、Google 等)，管理层说很多客户自己付推理费，不经过 GitLab
  • 渠道和伙伴：AWS、Google Cloud 云市场；中国由合资公司极狐 (JiHu) 经营，GitLab 并表，目标是将来出表

GitLab 拿的是“流水线”那一环的钱。最大那份 (开发者入口和 AI 写代码) 在 Microsoft 手里；GitLab 的赌注是 AI 写的代码越多，流水线这一环越值钱。

产品客户拿到什么怎么收钱状态

其他用量产品计算分钟、存储、Secrets Manager、专用 Runner、制品管理 (测试中)按用量新业务，今年上了 3 个

Flex (收费方式)一份年度承诺金额，每月在席位和 credits 之间自由分配年度预付现金，按实际使用确认收入2026 年 6 月推出，6 周 130 多家、超 $2,000 万

收入怎么拆

收入 = 付费席位数 × 平均席位单价 (由 Premium / Ultimate 比例决定) + 用量收入 (AI credits、计算、存储、Secrets、Runner) 增长 = 新客户 (Q2 首单约 1,700 笔，同比翻倍；首单 net ARR +近 40%) + 老客户净扩张 (NRR 117% = 加人头 + 升级 Ultimate + 涨价 + 用量) − 流失 (毛留存 >90%)

SaaS (GitLab.com 和 Dedicated) 同比 +36%，比整体快 15 个点，是毛利率下降的主要原因：自己机房装的版本几乎没有服务器成本，云版要付 Google Cloud 的钱。报表里的 license 收入是 self-managed 合同里一次性确认的部分，大单多的季度会把收入推高，Q2 就是这样。

Flex 的会计要单独看。Flex 合同现金仍是年初一次收，但收入按实际使用确认，所以 self-managed 续约转成 Flex 会把收入往后推：每 $5,000 万转换约后移 $500 万，FY27 最多 $1,300 万。Flex 承诺也不计入 cRPO (未来 12 个月的已签合同)，Q2 cRPO $744.7M (+20%) 因此少算了 3 个点，总 RPO $12 亿 (+16%) 里包含它。全年指引没有计入 Flex 的影响。

是不是不可或缺

  • 受监管的大企业和政府、装在自己机房：很难替代。迁移要搬仓库、重写流水线、重做合规流程；毛留存 >90%，FY26 末客户流失四年最低 (Guggenheim 转述管理层)
  • 中小企业、纯云用户：只是“最好的选择之一”，GitHub 随时可替代。4 月管理层承认中小和中端客户 (约 20% ARR) 加公共部门 (约 12% ARR) 承压；Q2 说这两块已企稳，公共部门明显反弹
  • AI 写代码助手：已经有更强的替代品。GitLab 把 Duo 定位成“管 agent 的平台”，不和它们比谁写得好

利润质量

  • 股票薪酬吃掉了全部利润。FY26 SBC $215M，占收入 22.5%；Q2 FY27 SBC $75.0M，占收入 26%。FY26 non-GAAP 营业利润 $163M，GAAP 亏 $71M
  • 自由现金流约等于 SBC。FY26 调整后 FCF $219.6M，减 SBC $215.0M 只剩约 $5M
  • Q2 现金流比看起来更弱。Q2 经营现金流 −$3.1M；加回 $14.0M 极狐成立相关的一次性税款结算、减去 $1.0M 税款退回，才得到调整后 FCF $9.8M。管理层把弱势归因于收款时点，上半年合计调整后 FCF $156.5M
  • 回购在抵消稀释。H1 FY27 回购约 584 万股，总股本从 1.701 亿降到 1.673 亿 (−1.6%)；但 non-GAAP 摊薄股数仍有 1.739 亿。$400M 授权还剩 $245M
  • 利息收入撑着 EPS。$12.6 亿现金按 4% 约 $50M / 年利息 (估算)，约等于 FY27 non-GAAP 净利润的三分之一

一句话：每多卖 $1，non-GAAP 口径留下约 $0.13–0.15 营业利润、约 $0.20 自由现金流；但其中约 $0.22 是用股票付给员工的，股东真正拿到的接近零，靠回购把稀释补回来。

往下多想一层

① 下半年指引隐含了什么 全年指引中值 $1,131M − 上半年实际 $550.4M = 下半年 $580.6M Q3 指引中值 $282M → 隐含 Q4 ≈ $298.6M，同比 Q4 FY26 $260.4M 只增 14.7% 若 Q3、Q4 像过去一样各超指引约 4%：FY27 ≈ 550.4 + 293 + 311 ≈ $1,154M，+20.8% 再扣 Flex 后移 (最多 $13M，不在指引里)：账面约 $1,141–1,154M ② 用量收入要做到多少，才能让 FY28 回到 20% (估算) FY27 用量收入 ≈ 各季平均 CRR ÷ 4 之和 ≈ 3 + 7 + 14 + 21 ≈ $45M (假设 CRR 按 15 → 40 → 70 → 100 走) 席位业务 FY27 ≈ 1,131 − 45 = $1,086M，按 12% 增长 → FY28 $1,216M 用量收入 FY28 若 CRR 从 $100M 走到 $160M，确认约 $130M FY28 ≈ 1,216 + 130 = $1,346M，同比 +19% vs 一致预期 $1,310M (+15.8%) 席位只长 10%、用量只到 $90M：FY28 ≈ $1,285M，+13.6%，低于一致预期

真实需求大约还是 20% 左右，一致预期的 15.8% 基本没算进用量收入。但报表上，下半年会因为保守指引和 Flex 后移显得只有十几。市场在 Q3 会不会因为“账面减速”卖出，是短期最大的变数；用量收入能不能过 $100M，是中期唯一重要的数。

市场在问什么

  1. AI 写代码对 GitLab 是需求放大器 (更多代码要管)，还是席位杀手 (更少开发者)?
  2. 按用量收费能不能把收入增速拉回 20% 以上，代价是不是毛利率?
  3. GitHub 会不会把安全和 agent 功能打包降价，削掉 Ultimate 的卖点?

预期差

  • 正向：一致预期 FY28 增速 15.8%，和指引隐含的下半年增速差不多，基本没给用量收入留位置。如果 Paid CRR 年底过 $100M，FY28 收入可能在 $1,340M 以上，比一致预期高约 3%。更大的变化是估值方法：按用量收费的 JFrog、Datadog 是下一年收入 15–17 倍，GitLab 是 5.8 倍
  • 负向：18 / 28 家卖方是持有，平均目标价约等于现价，股价已经不便宜。Q2 的超预期集中在大单和那家银行，如果不可重复，下半年账面增速掉到 15% 左右，在约 50 倍 FY28E P/E 下，股价承受不了“看起来在减速”

要做的判断

  1. 用量收入的单位经济：毛利率多少、推理成本谁出、是否集中在前 10 个客户
  2. 按客户类型 (受监管大客户 / 中小 / 公共部门)，席位数在 AI 时代是增是减
  3. 合理价值区间，以及被收购时的估值底在哪里

下一次财报最该盯的一个数：Paid CRR 从 $40M 走到多少。$65M 以上说明年底目标可信。

反推现价隐含了什么

隐含目标年 EPS = (股价 − 每股现金) × (1 + r)^n / 终值 P/E = (53.16 − 7.54) × 1.10^4 / 30 ≈ $2.23 (FY31，non-GAAP) FY27 指引 $0.86 → FY31 $2.23，EPS 年复合增长约 27% 对照一致预期：FY29E EPS ~$1.28 (估算) 按 30 倍、10% 回报折回今天 = 1.28 × 30 / 1.10^2 + 7.54 ≈ $39 现价 $53 相当于按 10% 折现后给 FY29E 约 43 倍

这个数算得通吗？拆开看 (估算)：收入年增 17% → FY31 约 $21 亿；non-GAAP 营业利润率从 13% 升到 22% → 约 $4.7 亿；加利息约 $5,000 万，扣 25% 税，除以 1.7 亿股 ≈ $2.3。也就是说，现价要求 GitLab 未来四年保持约 17% 增长，同时利润率提高约 9 个点。一致预期给的路径是 FY29 利润率只到 16%，比这条路慢。现价已经比卖方的利润预测乐观一档。

GAAP 视角：如果 SBC 届时仍占收入 20%，non-GAAP 22% 的利润率对应 GAAP 只有约 2%。管理层没有公布长期利润率目标，所以没法用“管理层目标兑现值多少”来反算。

Deepdive 要做什么

模型

  • 收入按 席位 (Premium / Ultimate × 席位数 × 单价) + 用量 (credits、计算、存储、Secrets、Runner) 两块拆；再按 self-managed / SaaS / Dedicated 拆
  • 单独建 Flex 的收入确认节奏：承诺金额、每月消耗率、后移收入、cRPO 与 RPO 的差
  • 毛利率按 SaaS 和 self-managed 分开；AI 推理成本由谁承担单列
  • SBC、回购、股本三者联动，算扣 SBC 后的每股 FCF

专家访谈

  • 大型银行 DevOps 平台负责人：AI credits 扩大 10 倍具体花在哪，会不会把一部分搬到 GitHub 或直接用 Claude Code / Cursor
  • 前 GitHub 企业销售或产品经理：GitHub 对 GitLab Ultimate 客户的打包报价怎么做，赢单率如何
  • Cursor / Claude Code 企业部署负责人：agent 写的代码进哪个仓库、走谁的 CI，安全和审计的钱付给谁
  • 美国联邦政府 IT 采购人员：公共部门预算恢复能不能持续，self-managed 在政府里的地位
