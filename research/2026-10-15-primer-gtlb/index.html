1. 行业科普

一句话：软件公司写代码像工厂造东西，GitLab 卖的是这条“软件流水线”：代码放在哪、谁改了什么、改完自动跑测试、扫安全漏洞、通过审批后发布上线。行业叫 DevOps，加上安全叫 DevSecOps。

以前这条流水线由很多小工具拼起来 (存代码用 GitHub 或 Bitbucket，自动化用 Jenkins，安全扫描用 Snyk 或 Checkmarx，制品管理用 JFrog)。GitLab 的卖点是一个产品全包，企业少管几家供应商，审计时也只看一套记录。Gartner 连续四年把它列为 DevSecOps 平台的 Leader。

空间多大。真正已经发生的收入比 TAM 小得多：

  • 实际数据 GitLab 2026 财年收入 $955M，FY26 内年化经常性收入 (ARR) 突破 $10 亿
  • 实际数据 GitHub (Microsoft) 2024 年 Nadella 披露 ARR 超过 $20 亿，Copilot 是主要增量。之后没有再单独披露 (未核实最新数)
  • 实际数据 JFrog TTM 收入约 $6 亿；Atlassian TTM $66 亿，但大部分来自 Jira / Confluence，代码托管 Bitbucket 只是一小块
  • 管理层口径 GitLab 过去在投资者日给过约 $400 亿的 TAM (未核实最新口径)。这是“所有开发者、安全人员都按 GitLab 价格付费”的终端市场价值，不是它能收到的钱。今天几家主要平台加起来的实际收入在 $50 亿左右 (估算)

钱怎么分。开发者数量上 GitHub 远大于 GitLab (GitHub 2023 年披露 1 亿开发者)，开源项目几乎都在 GitHub。GitLab 的位置是受监管的大企业和政府：它们更在意能装在自己机房 (self-managed)、权限和审计一体化。2024 年以后，新增的钱主要流向 AI 写代码工具 (Copilot、Cursor、Claude Code、OpenAI Codex)，这一层 GitLab 不占优。

竞争格局

阵营玩家模式对 GitLab 的威胁
一体化平台GitHub (Microsoft)代码托管 + Actions (自动化) + Advanced Security + Copilot，按席位，能和 Azure / M365 一起打包最大。分发和 AI 都领先，大企业谈判时常被拿来压价
一体化平台Atlassian (Bitbucket + Jira)项目管理强，代码托管弱中等。Jira 用户多，但 Bitbucket 份额在流失
AI 写代码Cursor、Claude Code、OpenAI Codex、GitHub Copilot按席位或按 token 收费，只管“写”，不存代码也不管上线对 GitLab 的 AI 附加产品 (Duo) 威胁大；对存代码和流水线反而是需求来源，因为写出的代码要放在某个仓库里过检查
单点工具JFrog、Snyk、Checkmarx、Harness、CircleCI、Jenkins (开源)各管一环，按用量或席位中等。在单项上常比 GitLab 强，大客户会混用

上下游

  • 客户：大企业研发团队，金融和政府占比高 (有一家美国前 20 大银行在 Q2 把 AI 额度一次扩大约 10 倍)。按收入 82% 来自美国 (Q1 FY27 10-Q)。超过 $10 万 ARR 的客户 1,571 家，超过 $100 万的 155 家 (FY26 末)
  • 供应商：GitLab.com 跑在 Google Cloud 上；AI 功能调用第三方大模型 (Anthropic、Google 等)，管理层说很多客户单独付推理费
  • 渠道和伙伴：AWS、Google Cloud 云市场；中国由合资公司极狐 (JiHu) 经营

GitLab 在这条链上拿的是“流水线”那一环的钱。最大那份 (开发者数量和 AI 写代码) 目前在 Microsoft 手里。

2. 商业模式

产品客户拿到什么怎么收钱状态
Free (开源版)基础代码托管和流水线不收钱，拉新成熟
Premium团队协作、审批、更强的流水线按人头年费，公开牌价 $29 / 人 / 月成熟
Ultimate在 Premium 上加安全扫描、合规审计、组合管理按人头年费，多为谈判价 (公开牌价约 $99，未核实现价)成熟，占 ARR 59%，增速约 35%
Duo Agent PlatformAI agent 帮忙写代码、审代码、修漏洞、跑流水线从按人头附加改为 GitLab Credits，按用量扣新业务
用量类产品计算分钟、存储、Secrets Manager、专用 Runner、制品管理 (beta)按用量新业务，今年上了 3 个
GitLab Dedicated单租户云版，给受监管客户按人头，有溢价增长中
Flex (收费方式)一份年度承诺金额，可以在席位和 credits 之间自由分配，超出部分按量补年度预付，按实际使用确认收入2026 年 6 月推出，6 周签下 133 家、超过 $2,000 万

收入怎么拆

收入 ≈ 付费席位数 × 平均席位单价 (由 Premium / Ultimate 比例决定) + 用量收入 (AI credits、计算、存储、Secrets 等) 增长 = 新客户 (Q2 首单约 1,700 笔，同比翻倍以上) + 老客户净扩张 (NRR 117% = 加人头 + 升级 Ultimate + 涨价 + 用量)

部署方式：自己机房装的 self-managed 占收入约 57%，GitLab.com 和 Dedicated 等云版约 34%，云版同比增长约 36%。报表里的 “license” 收入 ($27.9M) 是 self-managed 合同里需要一次性确认的部分，所以大单多的季度会把收入推高。

是不是不可或缺

  • 受监管的大企业和政府、装在自己机房：很难替代。迁移要搬仓库、重写流水线、重做合规流程；毛留存率 96–97%，FY26 末客户流失降到四年最低 (Guggenheim 转述管理层)
  • 中小企业、纯云用户：只是“最好的选择之一”，GitHub 随时可替代。管理层 4 月承认中小和中端客户 (约 20% ARR) 加公共部门 (约 12% ARR) 承压
  • AI 写代码助手：已经有更强的替代品 (Copilot、Cursor、Claude Code)。GitLab 现在把 Duo 定位成“管 agent 的平台”，而不是和它们比谁写得好

利润质量

  • 股票薪酬吃掉了全部利润。FY26 SBC $215M，占收入 22.5%；Q2 FY27 SBC $75M，占收入 26% (含 $3.9M 重组加速归属)。non-GAAP 营业利润 $163M，GAAP 是亏 $71M
  • 自由现金流约等于 SBC。FY26 调整后 FCF $219.6M，减去 SBC $215.0M，只剩约 $5M，不到收入的 1%
  • 回购在抵消稀释。H1 FY27 回购 $154.7M (约 584 万股，均价约 $26.5)，总股本从 1.701 亿降到 1.673 亿 (−1.6%)。$400M 授权还剩 $245M
  • FCF 有季节性和一次性。Q1 是收年费的旺季 (FCF $147M)，Q2 只有 $9.8M，其中含 $14.0M 与极狐 (JiHu) 相关的一次性付款
  • 利息收入撑着 non-GAAP EPS。$12.6 亿现金按 4% 算约 $50M / 年利息 (估算)，约占 non-GAAP 净利润的四分之一到三分之一

一句话：每多卖 $1，non-GAAP 口径留下约 $0.15–0.17 营业利润、约 $0.20 自由现金流；但其中约 $0.22 是用股票付给员工的，股东真正拿到的接近零，靠回购把稀释补回来。

往下多想一层

全年指引中值 $1,131M − 上半年实际 $550.4M = 下半年 $580.6M Q3 指引中值 $282M → 隐含 Q4 ≈ $298.6M，同比 Q4 FY26 $260.4M 只增 14.7% 若 Q3、Q4 像过去一样各超指引 4%： FY27 ≈ 550.4 + 293 + 311 ≈ $1,154M，同比 +20.8% 另外：管理层说每 $5,000 万 self-managed 续约转成 Flex，约 $500 万收入后移， 全年最多约 $1,300 万，而且没有放进指引 → 报表下半年可能比上面再少 1 个多点

所以真实需求大约还是 20% 左右增长，但报表数字因为 Flex 后移和保守指引，下半年可能看起来只有十几。市场会不会因为“账面减速”卖出，是 Q3 的关键。

市场在问什么

  1. AI 写代码对 GitLab 是需求放大器 (更多代码要管)，还是席位杀手 (更少开发者)?
  2. 按用量收费能不能把收入增速重新拉回 20% 以上，代价是不是毛利率?
  3. GitHub 会不会把安全和 agent 功能打包降价，削掉 Ultimate 的卖点?

预期差

  • 正向：市场还按“按人头收费的 SaaS”给 GitLab 估值 (约 7 倍 EV/Sales)，而按用量收费的 JFrog、Datadog 是 20 倍左右。如果用量收入在 FY28 做到 $150–200M (估算)，增速回到 20% 以上，估值方法本身可能变
  • 负向：Q2 的大单 (比如那家银行扩大 10 倍) 可能集中在少数客户，不可重复；下半年报表增速掉到十几，在 60 倍 non-GAAP P/E 下，股价承受不了“看起来在减速”

要做的判断

  1. 用量收入的单位经济：毛利率多少，客户是不是自带模型 (推理成本由谁出)
  2. 按客户类型 (受监管大客户 / 中小 / 公共部门)，席位数在 AI 时代是增是减
  3. 合理价值区间，和被收购时的估值底在哪里

下一次财报最该盯的一个数：Paid CRR (按用量的承诺收入) 从 $40M 走到多少。

反推现价隐含了什么

隐含目标年 EPS = (股价 − 每股现金) × (1 + r)^n / 终值 P/E = (53.16 − 7.54) × 1.10^4 / 30 = 45.62 × 1.464 / 30 ≈ $2.23 (FY31，non-GAAP) FY27 指引 $0.86 → FY31 $2.23，EPS 年复合增长约 27%

这个数算得通吗？拆开看 (估算)：收入年增 17% → FY31 约 $21 亿；non-GAAP 营业利润率从 13% 升到 22% → 约 $4.7 亿；加利息约 $4,500 万，扣 20% 税，除以 1.7 亿股 ≈ $2.4。也就是说，现价要求 GitLab 未来四年保持 17% 左右增长，同时利润率提高约 9 个点。两者都不是极端假设，但都要兑现。

GAAP 视角：如果 SBC 届时仍占收入 20%，non-GAAP 22% 的利润率对应 GAAP 只有约 2%。用 GAAP 或“FCF 扣 SBC”看，现价贵得多。管理层没有更新长期利润率目标 (未查到)，所以没法用“管理层目标兑现值多少”来反算。

是否值得 deepdive：值得。GitLab 是“AI 让代码变多，谁来管”这个问题最直接的上市标的，而且答案会在未来两三个季度的用量收入里看出来。

Deepdive 要做什么

模型

  • 收入按 席位 (Premium / Ultimate × 席位数 × 单价) + 用量 (credits、计算、存储、Secrets、Runner) 两块拆；再按 self-managed / SaaS / Dedicated 拆
  • 单独建 Flex 的收入确认节奏：承诺金额、实际消耗率、后移收入
  • 毛利率按 SaaS 和 self-managed 分开；AI 推理成本由谁承担单列
  • SBC、回购、股本三者联动，算 FCF 扣 SBC 后的每股价值

要核实的数据

  • Q2 FY27 10-Q：RPO 里 $40.4M Flex 预收 (已开票 $15.0M、未开票 $25.4M) 的拆分和条款
  • 10-Q / 10-K：极狐 (JiHu) 的持股比例、$14.0M 一次性付款的性质，是否涉及出表
  • FY24、FY25 NRR (目前转引自 Guggenheim) 和毛留存率的原始披露
  • Q2、Q3 FY26 的原始收入和 EPS 指引 (本文来自记忆)
  • Sid 转换 1,513 万股 B 股之后的 Form 4：是否减持、减持节奏
  • 管理层是否有新的长期利润率目标 (最近一次投资者日材料)
