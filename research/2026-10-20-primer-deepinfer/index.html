DeepInfer 是 DeepSeek 自己线上跑 V4.1 Flash 用的推理引擎，10 月 20 日以 Apache 2.0 开源，同时开源了对齐官方 API 的输入输出处理组件 deepseek-recipe。它让别人能在 NVIDIA Blackwell (SM100) 或华为昇腾 950 上，用和 DeepSeek 同一套"后厨"跑它的模型。让官方 API 又快又便宜的 KV 缓存管理和负载均衡，DeepSeek 原文说"因与内部基础设施耦合较深，目前尚未完整开源"，只在文章里公开了设计。

这次开源的是 DeepSeek 推理的"引擎"，不是整套"服务"。它会把"谁能把 DeepSeek 模型跑得更快"这件事拉平，但 DeepSeek 官方价格最关键的那块 (96% 的输入命中缓存、缓存留 72 小时) 靠的是没开源的缓存系统。

对 token 需求是加项：同一个模型在别家跑得更便宜，用的人会更多。对算力和电力，每个 token 要的更少，但总量大概率还是加项，这不是 2025 年 1 月那种"效率冲击"。

对内存和存储是明确的加项：DeepSeek 一个集群约 2,400 张卡，配了约 100 PiB 的 SSD 专门存 KV 缓存。按吞吐和保留天数自下而上算，每张卡实际要 13–30 TB，和 NVIDIA Vera Rubin 参考设计的每卡 16TB 同量级到 2 倍。便宜的推理靠的是大量、长时间保存 KV 缓存，谁想追上官方价格，就得自己建这一层。

受益最清楚的是昇腾 950 和超节点 (64–128 卡一组的机柜级系统)；被挤压的是靠"DeepSeek 模型跑得快"做差异化的推理服务商。

Follow-up (复查 2026.11.20)

第三方跑 V4.1 Flash 的首 token 延迟和价格，跟官方比。 这条直接检验"引擎被拉平、缓存没被拉平"的判断。现在的基线：第三方输出速度已经比官方快 (Fireworks 约 250、LithosAI 约 400 token/秒，官方约 210)，但首 token 延迟是 5–7 秒，官方约 1.2 秒 (DeepInfra 博客整理，厂商口径)。一个月后，如果第三方的速度继续涨、首 token 延迟还在 3 秒以上，说明差距在缓存层，判断成立；如果首 token 延迟也追到 2 秒以内、价格贴近官方，说明引擎才是主要差距，"服务商被挤压"要写得更重。

DeepSeek 会不会把缓存管理和负载均衡也开源。 原文的说法是"目前尚未完整开源"，理由是和内部基础设施耦合深，没有说不开；README 说预填充 / 解码分离的"大部分引擎功能已经实现"。存储底座 3FS 2025 年已经开源。一旦放出，第三方能复制官方的成本结构，推理服务商的利润会被进一步压，存储层的加项会从 DeepSeek 一家扩散到所有部署方。没有放出，官方 API 继续保有价格优势。

vLLM / SGLang 会不会吸收 DeepInfer 的东西。 DeepInfer 是从 vLLM 早期版本分出去的，2025 年 4 月 DeepSeek 还说不开源整个引擎、只往上游贡献。看接下来一个月 vLLM / SGLang 是否合入 DSpark 投机解码、SWA bounded replay，以及 DeepInfer 仓库外部贡献者和 issue 的数量 (发布当天 50 star)。上游吸收了，说明开源生态继续以 vLLM / SGLang 为中心；DeepInfer 自己长成社区，说明 DeepSeek 想自立一套标准。

昇腾 950 上的独立实测。 SemiAnalysis 说过要做华为对 H200 / B200 的对比。如果 DeepInfer 让昇腾 950 的每卡吞吐达到 B200 的七成以上，国内云厂在 DeepSeek 模型上用昇腾替代 NVIDIA 的理由就更硬；如果差一倍以上，"支持昇腾"主要是姿态。

1. 是什么

DeepInfer 是 DeepSeek 把自己线上推理服务用的那套引擎开源出来，让别人能用同样的方式跑 DeepSeek V4.1 Flash。

全篇用一个比喻：把大模型推理想成一家餐厅。模型是菜谱 (DeepSeek 早就公开了)，芯片是灶台 (NVIDIA、华为)，推理引擎是后厨流水线：谁切菜、谁掌勺、几个人同时炒一锅、怎么把灶台火力用满。KV 缓存系统是冷库：客人之前点过的半成品存着，回头客来了直接加热。调度和路由是前厅派单：哪桌的单派给哪组厨师。这次开源的是后厨流水线，冷库和前厅没开。

底层怎么工作

  • 大模型回答一个问题分两步。预填充 (prefill)：把用户输入的整段文字一次性读进去，算出一份"读后笔记" (KV 缓存)。解码 (decode)：一个字一个字往外写，每写一个字都要翻一遍这份笔记
  • 预填充吃算力 (像切一大堆菜)，解码吃内存带宽 (像厨师不停回头翻菜谱)。所以大厂常把两步拆到不同机器上，叫预填充 / 解码分离
  • 如果同一段输入之前处理过 (比如 agent 写代码，每一轮都会把整个对话和代码库重新发一遍)，读后笔记可以从缓存里直接取，不用重算。这就是"缓存命中"。命中的输入，DeepSeek 只收 $0.003 每百万 token，是没命中的 1/50

核心指标是什么意思

  • 吞吐 (token / 天、token / 秒 / 卡)：后厨一天出多少盘菜。决定每个 token 的成本
  • 首 token 延迟：客人点单到第一道菜上桌要等多久。主要取决于预填充，缓存命中时会快很多
  • 每用户速度 (token / 秒)：上菜的节奏。DeepSeek 自报 V4.1 Flash 平均 230，写代码时最高 300
  • 缓存命中率：有多少原料是冷库里现成的。命中率越高，同样的灶台能接待越多客人

和现成的开源引擎差在哪

市面上已经有 vLLM、SGLang (都是开源通用后厨，什么菜谱都能做) 和 NVIDIA 的 TensorRT-LLM (只能用 NVIDIA 灶台)。它们早就支持 DeepSeek 模型，而且 DeepSeek 2025 年已经把最关键的几个"刀具" (FlashMLA、DeepEP、DeepGEMM 等算子库) 开源过，这些引擎也在用。DeepInfer 的区别是：它是只为 DeepSeek 一道菜谱打磨的专用流水线，是 DeepSeek 自己每天在用的那条，新模型的推理代码以后也先在这里更新。

做成了什么

  • DeepInfer：引擎本体，Apache 2.0。README 写明"最初主要基于 vLLM 构建"，参考了 SGLang 和 TensorRT-LLM
  • deepseek-recipe：把用户请求转成模型输入、再把模型输出转回 API 格式的组件，MIT 协议，Rust 写的、有 Python 接口。作用是让第三方部署的"口味"和官方 API 一致 (思考模式、工具调用、结构化输出这些细节以前要靠社区反推)

拿来干什么 (一个例子)

一家国内云厂想卖 DeepSeek V4.1 Flash 的 API。今天：用 vLLM 或 SGLang，自己调参数、自己写适配，模型发布后要等社区几周把性能追上来 (SemiAnalysis 记录过 V4 发布后开源引擎 43 天里性能还在成倍提升)，输出格式和官方有细微差别。用 DeepInfer 之后：拿到和 DeepSeek 一样的引擎和同口径的输入输出处理，在昇腾 950 上也能跑；但缓存要存多久、怎么在几百台机器之间派单，仍要自己搭或用别家的方案。

现在到哪一步

  • DeepSeek 自己在生产上用 (官方说法)。开源版只支持离线推理，没有 HTTP 服务、鉴权、限流这些上线必需的外壳
  • 只支持一个模型 (V4.1 Flash) 和两种芯片 (NVIDIA SM100、昇腾 950)。H100 / H200 / H20、AMD 都不在列
  • README 有性能图但没给数字：预填充用 4 张 SM100、解码用 64 张，都在一个机柜级互联域里测

2. 机制：便宜从哪来，卡在哪

把"一个 token 的成本"拆成串联的几段，最弱的一段说了算。每段标出这次开没开源、由谁定义。

段比喻做什么这次开源了吗谁定义
1 算子刀具和火候把每张卡的算力和带宽用满开了 (大部分 2025 年已开)DeepSeek + 芯片厂 (CUDA / CANN)
2 并行几个厨师分工一个模型拆到几十张卡上，专家并行让每张卡只负责一部分"专家"开了DeepSeek 写法；能拆多大取决于机柜级互联 (NVL72、昇腾超节点)
3 投机解码提前猜下一道菜备好小模块一次猜 5 个 token，大模型一次验证，猜对就省时间开了 (DSpark)DeepSeek，和模型结构绑定
4 回头客少重算回头客只补做最后一道SWA bounded replay：缓存命中时只把最后 128 个 token 重跑一遍，解码侧的预填充计算量近乎减半开了DeepSeek，和模型结构绑定
5 缓存存多久、命中多少冷库多大、存几天约 100 PiB SSD (3FS 集群，10+2 纠删码)，agent 缓存留 3 天、聊天留 7 天，输入命中 96%只公开设计 (3FS 本身 2025 年已开源)DeepSeek 内部；外部替代：Mooncake、LMCache、NVIDIA Dynamo
6 分离和派单前厅派单预填充用 8 卡机器、解码用 64–128 卡超节点，两边卡数约 1:1，随流量自动扩缩；图片编码放最便宜的卡只公开设计DeepSeek 内部；外部替代：SGLang、NVIDIA Dynamo、llm-d

第 4 段值得多说一句。原文确认 V4.1 Flash 是"编码器 + 解码器"结构 (CED)，前 20 层只看最近 128 个 token (滑动窗口注意力，SWA)。长对话的大部分"读后笔记" (Block KV) 只需要算一次、存进 3FS；窗口那一小段 (SWA KV) 只放在机器内存里，约 3 分钟过期，命中率 98% 以上，丢了就重算最后 128 个 token。V4 的做法是把窗口那段也存盘，结果占掉持久缓存近一半容量，V4.1 改掉了。第 4 段和第 5 段是一对：模型结构让缓存命中后几乎不用重算，冷库让命中率到 96%。两者叠在一起，才有 $0.003 的命中价。这次开了前者的代码，后者只公开了设计。

按"能不能单独复制"排：第 1–4 段现在任何人拿到 SM100 或昇腾 950 都能复制；第 5–6 段要自己有大规模存储和调度系统，而且需要足够大的流量才能让缓存命中率高起来 (冷库只有在回头客多的时候才划算)。

一句话：DeepSeek 的便宜一半来自模型结构 + 引擎 (这次全开了)，一半来自"缓存存得多、存得久" (没开)；后者需要规模，规模本身就是壁垒。

4. 一句话规则

问一句：这家公司的优势能不能用"每张卡每秒出多少 token"衡量？能，这次开源把它拉平了；要用"缓存命中率、首 token 延迟、集群规模"衡量，这次没碰到它。

为什么是这两个指标：每卡吞吐是引擎层 (第 1–4 段) 的产出，这次全部公开；缓存命中率和首 token 延迟是冷库和派单 (第 5–6 段) 的产出，没公开，而且要流量规模才能做高。第三方现在的状态正好印证：输出速度已经超过官方，首 token 延迟还差 4–5 倍。

拿几个例子过一遍：

  • 一家靠"我们 DeepSeek 跑得比别人快 30%"拉客的推理服务商：用每卡吞吐衡量，被拉平
  • NVIDIA Dynamo、Mooncake 这类分布式调度 / 缓存方案：用缓存命中率衡量，没被碰到，反而多了一个"给 DeepInfer 配冷库"的需求
  • 做大容量 DRAM / SSD 的存储厂：用"能存多少 KV、存多久"衡量，受益
  • DeepSeek 官方 API：靠缓存命中率和规模，优势保留

一句话：被拉平的是"引擎跑多快"，没被拉平的是"冷库存多少、存多久"，判断谁受影响就看它靠哪一个。

  • "没适配"的三项 (缓存、分离、API 层) 里，后两项是工程活，很快会被社区或 DeepSeek 补上；缓存系统最可能是 DeepSeek 主动留着的
  • "天生"的一项 (只做 DeepSeek 模型) 决定了 DeepInfer 不会取代 vLLM / SGLang，最多是它们的"DeepSeek 专用分支"
  • 结论会因下一个版本翻的地方：如果缓存系统也开源，第 4 节的规则仍成立，但"没被拉平"的那一半也被拉平，服务商被挤压的程度要上调

一句话：DeepInfer 缺的东西里，只有"缓存系统"是决定成本的，而它恰好是 DeepSeek 最可能长期不开的那一块。

7. 落到核心议题：加项还是减项

议题方向机制BaseBull
token 需求加项同一模型在更多地方、以更低成本跑；deepseek-recipe 让第三方结果和官方一致，企业更敢用小幅加项：主要影响 DeepSeek 模型在第三方的份额，不改总盘子国内云普遍用昇腾 + DeepInfer 上量，DeepSeek 系模型的总 token 再上一个台阶
算力 (GPU / NPU)每 token 减项，总量加项每卡吞吐提升让每个 token 要的算力更少；但第 3 节计算器显示，真正要算的 token 一年多涨了约 17 倍，效率提升被用量吃掉中性偏加：这次没有新的效率台阶 (算子 2025 年已开)，只是把已有效率推广到更多部署推动 SM100 和昇腾 950 换代，加速旧卡退役
HBM每 token 减项"编码器 + 滑动窗口"结构让每个 token 的 KV 更小、更少重算中性：是模型结构的影响，不是这次开源带来的—
内存 / 存储容量层 (DRAM、SSD)加项每张推理卡背后 13–30 TB 的 SSD 专门存 KV (自下而上算；100 PiB 平均下来约 47 TB 是配置上限)；第三方想追官方价格必须自己建加项，量级见下DeepSeek 开源缓存系统后，所有部署方都照着做
电力每 token 减项，总量随算力SemiAnalysis：B200 跑 V4 每兆瓦 token 数 43 天里软件优化提升约 1.7 倍；DeepInfer 把官方水平直接给到第三方中性：每兆瓦产出提高，但用量上升抵消—

存储加项有多大：拿 DeepSeek 自己的集群算

原文给了 KV 缓存存储的规格：3FS 集群约 100 PiB SSD，峰值读 10 TiB/s、写 850 GiB/s，每次读一块约 112 KiB。配上第 3 节反推的约 2,400 张卡，可以算出每张推理卡背后要多少存储。

指标数值算式怎么读
每张卡配了多少 SSD (自上而下)约 47 TB100 PiB ÷ 2,400 卡配置上限：原文没说 100 PiB 只服务这一个集群，峰值写入也是平均写入的约 10 倍
每张卡每天新写多少 KV2.85 TB3.7 万 token/秒 × 86,400 × 890 字节3.7 万 = 预填充卡未命中 6 万、解码卡输出 1.4 万，1:1 平均；890 字节/token 来自 V4.1 技术报告，128 token 正好约 112 KiB 一块
每张卡要多少 SSD (自下而上)13–30 TB2.85 TB × 3 或 7 天 × 1.2 (纠删码) ÷ 0.8 (不写满)只存 3 天约 13 TB，和 Vera Rubin 每卡 16TB 相当；存 7 天约 30 TB，约 2 倍。每 72 张卡约 0.9–2.2 PB
峰值随机读次数约 9,600 万次/秒10 TiB/s ÷ 112 KiB每张卡约 4 万次/秒
每 TB 每秒被读几次约 850 次9,600 万 ÷ 11.3 万 TB这是容量盘 (TLC / QLC) 的活，用不上 SLC 级的高速盘，和 XL-Flash memo 的判断一致
每天写满几遍≤ 0.7 遍850 GiB/s × 86,400 秒 ÷ 100 PiB按峰值算的上限。TLC 够用，QLC 在边上

最敏感的参数是每 token KV 大小。V4.1 Flash 只有 890 字节，是 V4 Flash 的 1/4，约为 V3 一类 MLA 模型的 1/40–1/80。KV 这么小，才存得起 3–7 天；KV 大几十倍的模型只能存几分钟到几小时。所以每卡 SSD 量由"KV 压多小 × 定价逼你存多久"决定，和卡的型号关系不大。

这组数说明两件事。第一，KV 缓存要的是容量，不是速度：每张推理卡背后几十 TB 的普通企业级 SSD。第二，这是 DeepSeek 一家、一个集群的配置；任何想把 DeepSeek 模型卖到接近官方价格的部署方，都要按差不多的比例配存储。卡数是我反推的，原文说机器留了冗余，实际卡数可能更多，每卡存储会相应少一些。

为什么这不是 2025 年 1 月那种"效率冲击"

  • 2025 年 1 月市场的担心是"同样的能力只要十分之一的算力"。这次没有新的模型或新的效率台阶，DeepInfer 的核心算子 2025 年 2 月就开源了
  • DeepSeek 这次自己披露的数据反而在讲另一件事：推理很赚钱。每卡每小时理论收入 $38，即使按 B200 级 $3–6 的租价 (我的估计) 算，收入也是成本的 6–13 倍。推理赚钱，云厂就愿意继续买卡
  • 社区第一反应也是这个方向：Linux.do 上有人说"每卡 38 美元，怪不得计算卡涨上天了"

DeepSeek 为什么要开 (我的推断)

  • 它不卖卡，只卖模型和 API。别人越容易跑它的模型，它的模型用的人越多
  • 2025 年 4 月说过要做"多硬件首发支持"，引擎同时支持昇腾 950 是兑现这一点，也符合国产化方向
  • 冷库没开，官方 API 的价格优势保留。开源引擎不伤自己的生意

一句话：对 token 和存储容量是加项，对每 token 的算力、HBM、电力是减项，但总量上算力大概率还是加项；DeepSeek 自己的数字在说推理很赚钱，这比效率本身更重要。

9. 最容易被误读的几点

大家以为实际
DeepSeek 又一次效率冲击，算力需求要降没有新的效率台阶。核心算子 2025 年已开源，这次是把已有效率推广出去；同时披露的数字在说推理很赚钱
开源之后，谁都能做到 DeepSeek 的价格引擎能复制，96% 命中率和 72 小时缓存不能。小规模部署回头客少，冷库建了也命中不高
155 万亿 token 说明 DeepSeek 比 OpenAI 还大九成以上是命中缓存的输入，几乎不花算力。不能和别家的 token 数直接比，也不能直接换成收入
支持昇腾说明 DeepSeek 要脱离 NVIDIA两边都只支持最新一代 (SM100、昇腾 950)。这是"跟最新硬件走"，在中国是"能买到什么用什么"
$38 / 卡时是 DeepSeek 的利润是全部按最低价计费的理论收入，不扣成本，也不考虑免费用户
DeepInfer 会取代 vLLM / SGLang只支持一个模型、两种芯片，定位是 DeepSeek 专用分支

一句话：这次开源的是"后厨"，不是"冷库"；数字说的是"推理很赚钱"，不是"算力用不完"。

10. 2027E 全球 KV 缓存 SSD 需求 (按 3 天规则)

把 DeepSeek "存 3 天"的做法套到海外大模型上，结果几乎完全取决于每个 token 的 KV 有多大。 不压缩 KV 的话，算出来要 500–1,500 EB，接近或超过 2027 年全球 NAND 的全部产量 (约 1,400 EB)，这不会发生，只能缩短保存时间。只有海外模型也像 DeepSeek 一样把 KV 压到几 KB，3 天才存得起；那时需求约 80 EB，是全年 NAND 的 5–6%。

算式

2027E KV 缓存 SSD (EB) = 加速器出货 × 用于推理的比例 × 每卡每秒新写入 token × 86,400 × 每 token KV 字节 × 保存天数 × 1.2 (纠删码) ÷ 0.8 (不写满)

  • 出货 (默认 2,000 万颗 GPU + ASIC)：AI Economy model 里的 2027E 数字我在项目文件和麻薯站里都没找到，这里先用占位数 (我的估计)，拖滑块换成 model 里的数
  • 推理比例 (默认 50%)：只有推理卡要存 KV
  • 每卡每秒新写入 token (默认 4,000)：没命中缓存的输入 + 输出。DeepSeek V4.1 Flash 实测是 3.7 万，但它每次只激活 80–160 亿参数；海外旗舰模型大得多，每卡吞吐按约 1/10 取 (我的估计，最软的锚)
  • 每 token KV：海外闭源模型不披露，用开源模型的结构推。Llama 3 70B 约 160 KB (FP8)，Llama 3.1 405B 约 260 KB (FP8)，Qwen3-235B 约 100 KB (FP8)，DeepSeek V3 一类的 MLA 约 35–70 KB，DeepSeek V4 Flash 约 3.5 KB，V4.1 Flash 890 字节 (技术报告)。按结构推算，未逐一核实
  • 2027 年全球 NAND 位元供给 (约 1,400 EB)：SanDisk 说 2026 年闪存出货 1.2 ZB；行业位元增速 15–20% (SanDisk "mid- to high-teens"，TrendForce 说 2027 年明显快于 2026)，推得 1,380–1,440 EB。机构没直接给 2027 年绝对数。对照：SanDisk 投资者日估 2030 年持久化 KV 存储装机量超过 1 ZB

  • "3 天规则"是一个约束，不是预测。它真正说明的是：KV 每 token 压到几 KB 之后，存几天才变得划算。DeepSeek 先做到了，所以它敢把缓存命中价定到 $0.003
  • 对 SSD 最有用的观察项是海外模型的 KV 压缩程度和缓存保存时长。现在 Anthropic、OpenAI、Google 的商用缓存大多是 5 分钟到 1 小时，个别提供更长的选项 (训练知识，未在本次核实)。哪家把缓存时长拉到天级，就是这条线成立的信号
  • 保存时长和 KV 大小对需求的影响是线性相乘的：KV 压小 10 倍、保存时间拉长 10 倍，SSD 需求不变。所以 KV 压缩本身不是减项，它会把保存时间推长

买存储划不划算：平均回报很高，边际回报接近盈亏平衡

  • 平均 (有没有缓存)：100 PiB 按 $0.5/GB 约 $0.56 亿。不存缓存的话，96% 命中的输入都要重算，预填充卡要从约 1,200 张变成约 3 万张，多花约 $14 亿 (每卡 $5 万，我的估计)。存储的回报约 25 倍，是上限：只在内存里存一小时也能接住一部分命中
  • 边际 (聊天从存 3 天加到 7 天)：原文说只存 3 天左右，聊天命中率会掉 0.5–1%。多存 4 天要多约 34 TB/每对卡，约 $1.7 万；腾出的预填充算力按 $38/卡时去卖，扣掉命中后少收的钱，一年净增 $0.7–1.4 万，回本 1.25–2.5 年。NAND $1/GB 时要 2.5–5 年
  • 含义：DeepSeek 的 3 天 / 7 天大致停在"再多存就不划算"的位置，是它在当前价格下的最优点，不是行业标准。NAND 涨价砍掉的是最后几天的尾巴，不是主体

长程 agent 为什么利好 NAND：看停顿多久

  • KV 放哪取决于下次被用到前要等多久：等几秒留显存 (HBM)，等几分钟放内存 (DRAM)，等几小时到几天只能放 SSD (NAND)
  • loop 任务、跨天任务"跑一段、等一段"，上下文更长、回头读更多、停顿更长，三项都是 NAND 的加项。反向力量是上下文压缩 (定期总结历史) 和 KV 压缩
  • 要盯的是 agent 任务的平均停顿时长和厂商缓存的保存时长，比任务总长度更关键

一句话：照搬 3 天规则，海外大模型的 KV 太大，算出来的需求超过全球 NAND 产量；海外模型学 DeepSeek 把 KV 压到约 5 KB 才存得起 3 天，2027E 约 80 EB、占 NAND 5–6%，按 NVIDIA 参考设计每卡配满 16 TB 是约 160 EB、占 11%。
