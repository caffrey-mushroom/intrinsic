结论

一句话：SNOW 是企业放"全部业务数据、拿来分析"的云上大仓库，按客户跑了多少计算收钱。AI 是真的在帮它：agent 查数据比人勤得多，产品收入增速一年里从 26% 拉到 37%。但现价 $306 (10-30 收盘) 要求未来 5 年收入每年涨 ~26% (不扣 SBC) 到 ~42% (扣 SBC)，我们的基本情景只有 ~21%。结论：不买，放观察；买点 $205-235 (较现价低 ~23-33%)。

为什么加速是真的：FY27Q2 产品收入 $1.49B (+37%)，比 Street 高 5%；全年指引从 +27% 一路上调到 +36%；NRR 回到 126%，$1M+ 客户 828 家 (+27%)。FUNDA 10 月的渠道调研里 8 家 SNOW 客户全部说账单在涨，没有一家在砍。和 NOW 正好相反：NOW 按"处理工单的人"收钱，agent 替人干活账单可能变小；SNOW 按计算收钱，agent 每回答一个问题要跑几十条 SQL，账单变大。

为什么还不买：(1) 加速的质量要打折：管理层说"约一半加速来自 AI 产品"，其中一块是转售 Anthropic、OpenAI 的 token，毛利低，产品毛利率指引已从 75% 降到 74%；另一块是 AI 工具把迁移从 ~2 年压到 1-2 个季度，同一笔收入被提前确认。领先指标在放缓：部署的 use case 增速 114% → 89%，RPO 增速 42% → 30%。(2) 竞争在新增预算上：DBX run-rate +80%，2026 年收入第一次超过 SNOW；新平台预算 DBX:SNOW ≈ 60:40。(3) 股东经济学：SBC 占收入 ~30%，高于 FCF (22%)，扣掉 SBC 后 FCF 收益率是 -0.4%。EV/Sales 17.9x FY27E、13.9x FY28E。

和 10-21 SNOW - 101 比：结论不变 (不买，买点当时 $210-240)，股价从 $320 跌到 $306，还没到买点。这次更明确的是 Caffrey 说的"SNOW 还要考虑毛利率"：毛利率 (≈ FCF Margin) 每 1pt 值 ~$8-10/股，和收入 CAGR 多 1pt 一样重要 (见 6.1)。

1. 产品：它是什么、怎么运转、凭什么赢

1.1 一句话 + 一个例子

SNOW 是企业放"全部业务数据、拿来分析"的云上大仓库。一家公司的订单、库存、客户、财务、App 日志散在几十个系统里 (SAP、Salesforce、自家数据库)，要回答"上季度哪个区域哪个产品卖得最好、为什么"，就得先把数据集中到一个地方，清洗好，再让分析师写 SQL 或用 BI 看板去查。SNOW 就是这个地方。

一个好记的比喻 (来自 DBX vs SNOW 研究)：DBX 像中央厨房，原料、刀具、灶台都给你，厨师想做什么都行，但得有厨师；SNOW 像出餐很快的餐厅前台，菜单是定好的，按按钮就出餐，谁能点什么有规矩，不需要懂厨艺。下面这张图把一份数据从进来到被用掉拆成 6 站，标出每站怎么收钱、谁最强。

它的技术核心是"存储和计算分开"：数据放在 AWS、Azure 或 GCP 的对象存储里 (很便宜)；要查的时候，SNOW 临时起一组计算机器 (叫"虚拟仓库")，查完就关，按秒计费。不同团队可以各起各的仓库、互不抢资源。2014 年这是革命性的设计 (老一代的 Teradata、Oracle 要买一整台机器)。再拿一个具体问题走一遍，看 agent 怎么改变账单：

1.2 行业背景：为什么需要它

数据库分两类：操作型 (App 的"收银台"，每笔下单实时写进去，Oracle、Postgres、MongoDB) 和分析型 (公司的"财务部"，把所有收银台、App、日志的数据汇到一起，一次扫几十亿行算总数)。几乎每家公司两套都有。分析型过去 30 年走了三代：一体机 (Teradata、Oracle Exadata，软硬件绑在一起卖) → 云数仓 (SNOW、BigQuery，存算分离、按用量付费) → 开放湖仓 (数据以 Iceberg 等开放格式放在客户自己的云存储上，多个引擎都能读)。SNOW 是第二代的赢家，现在要在第三代里守住位置。AI 让这件事更重要：模型要用企业自己的数据，数据从"存起来备查"变成"每天被 agent 读"。行业全貌见 数据平台行业入门。

1.3 怎么收费

收费单位是 credit。1 个 credit = 一台最小号 (XS) 虚拟仓库跑 1 小时，按秒计 (60 秒起)；仓库每大一号，每小时的 credit 翻倍 (S = 2、M = 4……)。谁算一个单位：不看人数、不看座位，只看"计算跑了多久、开了多大"。所以分析师多、看板多、agent 查得多，都会变成更多 credit。AI 功能另有一种货币叫 AI credit，按模型 token 计。存储按 TB/月 另收。约 95% 收入是这种用量制，其余是专业服务。

一句话：收入 = 客户数 × 每个客户跑的计算量 × 每 credit 价格 + AI token。和人头无关，所以不受"agent 替代人"的冲击；但直接暴露在"客户优化" (2023 年客户集体优化，增速一年从 70% 掉到 38%) 和"计算单价下降"之下。底层机器是向云厂商租的，所以毛利率 (产品 74.7%) 比纯软件低。

1.5 核心竞争力

先说它不是最强的地方。接入和存储是云厂商的 (S3 本来就是它们的)；加工这一站 (夜间批量 ETL、流处理、训练模型) DBX 比它强，工程师能调每一个旋钮，大数据量更便宜；AI 这一站 DBX 起步早 (2025 年 AI run-rate ~$10 亿 vs SNOW ~$1 亿，二手数据)，模型厂商自己也在做。它强在"查询和 BI"和"共享"两站：

为什么只有它把这两站做成了：出身。SNOW 2012 年从一开始就是"云上的 SQL 数仓"，用户是写 SQL 的分析师和业务人员，产品原则是"像个黑盒、不用调参数"：自动扩缩、自动优化、一套权限。对手的出身不同：DBX 起家于开源 Spark，产品是 notebook + 代码 + 集群，强在灵活但要养工程师；云厂商的数仓 (Redshift、Synapse) 是各自云的配套，跨云和共享都弱。一位前 DBX 现场工程师的说法："如果你是做 BI 的，要报表和数仓，显然 SNOW 从零开始用更容易……很多不懂技术的初创也更喜欢 SNOW，因为不想养昂贵的数据工程师" (GuidePoint 09-09)。

为什么它记下的东西最"可信"：财务、销售看的数字 (口径)、谁能看哪一行 (权限)、几百张看板都建在 SNOW 的表上；专家估计核心传统数仓 (SQL、BI、ELT) 仍占 SNOW 消费 60-65%。数字上：前 25 大客户平均每年花 $3,400 万 (两年前 $2,200 万)，G2000 客户平均只有 ~$240 万 (Investor Day 06-02)，同一客户在越用越深。

巨头为什么不能自己做：云厂商不是早就有数仓了吗？

先核对前提：巨头不但做过，而且一直在做。AWS Redshift 2012 年上线 (比 SNOW 产品还早)，Google BigQuery 2011 年，微软 Synapse 之后又推出 Fabric (2023)，Oracle 有 Autonomous Data Warehouse。Gartner DBMS 市场前五一直是 AWS > 微软 > Oracle > 谷歌 > IBM，大厂合计 ~86%。结果是：SNOW 在它们的地盘上长成了 $60 亿的生意，而且主要跑在 AWS 上。巨头做出来了但没赢下这一块，原因不是写代码：

  1. 跨云中立。大企业的数据在 AWS、Azure、GCP 上都有；Redshift 只在 AWS、BigQuery 只在 GCP、Fabric 绑 Azure 和 Office。SNOW 在三朵云上体验一样，还能跨云共享数据。
  2. 简单。Redshift 早期要自己管集群大小、调分布键；BigQuery 按扫描量收费，账单难预测。SNOW 把"不用调"做成了产品原则。
  3. 数据共享网络。A 公司把表直接共享给 B 公司，不复制文件；前提是两家都在 SNOW 上。云厂商的共享基本只在自己云内。
  4. 激励不同。对云厂商，数仓是"卖算力的配套"，客户在 SNOW 上跑也一样买它的机器 (SNOW 是 AWS 最大的客户之一)；所以 AWS 一边做 Redshift，一边和 SNOW 联合销售、给 SNOW 计入客户的 AWS 承诺额。这一条是我们的判断。

所以巨头真正的威胁不是"做出一样的产品"，而是捆绑和补贴：微软把 Fabric 和 Office、Power BI 打包；三家云厂商都在用数百万美元补贴把客户从 SNOW、DBX 迁出，补贴额度从 $10-20 万涨到包揽整个迁移 (Thoughtworks 05-08)；但客户大多没接受，Thoughtworks 只看到 1 个因已有大量 AWS 工作流而迁走的客户。反方向也有：Dairy Farm 从 DBX 迁回 SNOW，原因之一是 AWS 给了含 26% 折扣的一揽子协议 (Acecamp 10-22)。

用了 DBX 的企业还会买 SNOW 吗？会，并存是常态

  • 并存是常态。"历史上 DBX 常被用来在 SNOW 里产生的受治理数据上跑 AI 和机器学习" (FUNDA 渠道 09-01)。大企业典型分工：DBX 负责加工和建模，SNOW 负责存放整理好的表、给分析师和看板用。渠道商 (Merit 08-19)："没有看到 SNOW 客户整体迁往 DBX，大企业两者并存"。
  • 正面交锋发生在新预算和大数据量客户上。Thoughtworks 美洲数据与 AI 负责人 (GuidePoint 08-20)：新增平台预算 DBX:SNOW 约 60:40、且缓慢扩大，但他承认样本偏工程、全市场按 50:50 建模。DBX 现任员工 (Acecamp 10-13)：数据量超过 2PB、慢查询 ~15% 的 SNOW 客户成本急剧上升，是转向 DBX 的核心原因，DBX 专门去接触这类客户。
  • 双向的真实案例：向 SNOW：Dairy Farm 从 DBX 迁回 (集团要求统一 Iceberg + AWS 折扣 + 易用)；大型药企把 DBX 降为遗留平台，SNOW 支出 +10-15% (Merit 08-10)；OpenAI 从 BigQuery 转到 SNOW 做日志和 AB 测试 (Acecamp 01-28，GCP 视角)。向 DBX：DBX 现场工程专家称去年近 200 家客户从 SNOW 迁到 DBX，包括 SNOW 前 6 大客户的部分负载 (Merit 08-13，DBX 立场)；10 人 AI 初创 CTO 选 DBX (AI/ML 深度)；Tavant 代客户选型选了 AWS + DBX (价格)。

5. Invert：Bear case

把多头逻辑倒过来，问"什么情况下 SNOW 3 年后让人后悔"。最大的那条先画成传导链，再逐条展开：

  1. 加速是迁移提前，不是需求变大。AI 编程工具把 2 年的迁移压到 1-2 个季度，同一笔收入在 FY26-27 集中确认；FY28 起迁移数增速放慢，核心数仓回到 20% 以下。早期信号：use case 增速从 114% → 89% 继续往 50% 以下走；RPO 增速持续低于收入增速；FY28 首次指引 ≤24%。
  2. AI 收入越大，毛利越低。AI 产品占产品收入从 ~10% 升到 30%，按 AI 毛利 ~55%、核心 ~78% 算，产品毛利率从 ~75.7% 掉到 ~71% (见 6.1 的表)；token 价格还在降，转售收入通缩。早期信号：毛利率指引再下调；管理层继续不披露 AI 毛利。
  3. Iceberg 让大客户把加工层分流。数据留在客户自己的 S3 上，批处理交给 DBX、Spark、ClickHouse，SNOW 只留交互查询；SNOW 收入的 ~25% 在加工层。早期信号：NRR 从 126% 回落到 120% 以下；渠道报告大客户续约时承诺额下调。
  4. agent 绕开 SNOW 的界面，甚至绕开数仓。OpenAI、Anthropic 的 agent 成为"问数据"的入口，SNOW 被降级成"存数据、跑 SQL 的地方"，失去定价权；或 FDE 直接用组织度低的数据绕开数仓 (微软 FDE 专家)。早期信号：CoWork 账户增速继续慢 (环比 +11%)；外部 agent 调用占比上升但 SNOW 不单独收费。
  5. SBC 降不下来。SBC 停在收入 20% 以上，GAAP 盈利目标推迟；稀释股数继续上升 (可转债价内)。早期信号：FY28Q4 GAAP 盈利目标被改口。
