2. AI服务器部署与硬件配置策略

  1. 针对不同规模的客户，华为提供哪些部署方案？
  • 中小企业/初创公司：
  • 模式：公有云的MaaS（模型即服务）平台。
  • 特点：按token计费，平台聚合了几十上百款模型供选择，可通过API key调用，并能接入自有知识库。平台是多租户模式，会进行TPM和RPM限流。
  • 头部/大型客户（用户量上万，或对时延、性能要求高）：
  • 模式：私有化集群部署。
  • 特点：不再按token计费，客户只需支付算力、存储等基础资源成本。部署方案优先选择云端，交付速度更快。
  • 配置建议：对于1万用户以上的客户，通常建议部署一个由4台8卡910C服务器组成的集群。
  1. 不同AI应用（如聊天机器人 vs Agent）在硬件配置（HBM:DDR:SSD）上有何差异？
  • 标准配置基准：通用的配置比例是1:4:16，也会根据需求动态调整为1:3:16、1:4:12或1:3:12。
  • 聊天机器人（Chatbot）：
  • 配置比例：大致为1:4:16。
  • 考量因素：模型参数量、并发客户端数量、延迟要求。
  • 具体配置：DDR通常配置3T到4T，SSD配置15T到20T。
  • 智能体（Agent）平台：
  • 配置比例：对HBM配比要求略高，倾向于采用1:3的比例（HBM:DDR）。
  • 考量因素：并发任务数、训练规模、延迟要求以及后端配合的基础模型。
  • 具体配置：SSD配置不固定，通常在12T到20T之间。
  1. Agent任务对CPU资源的需求有何特点，是否需要额外配置CPU？
  • 需求特点：Agent任务除了GPU的矩阵运算，还涉及逻辑计算、网页处理、tool calls、读取RAG等操作，需要CPU频繁与DDR进行交互，因此对CPU资源有较高要求。
  • 配置方式：会额外配置CPU，与GPU分开部署。
  • 配置案例：在一个基于DeepSpeed（专家解读为Deepsteak）的案例中，GPU配置了8颗920，同时额外配置了4颗鲲鹏920 CPU（每颗48核），形成了2:1的GPU:CPU机柜比例（非固定）。
  • 成本占比：CPU在总成本结构中占比不高，通常在10%左右，80%以上的成本投入在GPU上。
  1. 在处理Agent任务时，HBM、DDR和SSD各自存储什么数据，如何协同工作？
  • HBM (高带宽内存)：存放“热数据”，即模型当前运算所必需的关键参数和正在进行推理任务的KV cache。
  • DDR (内存)：存放“温数据”，即调用频率较高但优先级低于HBM中数据的缓存数据。例如，刚完成推理、等待下一次调用，或因任务被CPU接管而暂时从GPU卸载的KV cache。
  • SSD (固态硬盘)：存放“落盘数据”或“冷数据”。
  • 模型训练数据：训练完成后持久化存储的数据。
  • 向量数据库：用于本地知识库，将文件向量化后供模型使用。
  • 其他：如日志文件、本地数据库等。
  • 任务卸载（Offload）：在预算有限时，将部分KV cache卸载到SSD中执行，以满足高并发需求，但这会牺牲时延。

3. 供应链、采购策略与市场展望

  1. 面对存储产品价格上涨，华为的核心采购标准和应对策略是什么？
  • 价格影响：价格上涨的感知已比较明显，成本压力已显现，预计供应紧张情况可能持续到2027或2028年。
  • 短期应对（内部消化）：
  • 库存消化：利用存货和备品，按原有长期协议价格供应客户。
  • 技术优化：在云端业务通过算力调度、内存池等技术分摊成本。
  • 价格策略：不直接调整产品目录价，而是通过调整大客户的折扣来实现，避免客户流失。
  • 长期解决方案：
  • 国产替代：在继续从国外采购的同时，积极与国内供应商（如长鑫存储）合作，根据自身需求定制产品，这是当下最主要的解决路径。
  • 签订长协：积极争取与供应商签订长期订单，保障供应。
  1. 华为在HBM自研和与国内厂商（如长鑫）合作方面进展如何？
  • 自研技术：已实现HBM自研，推出了H-Cube 1.0和2.0技术。受外部限制，目前最多能使用HBM2，自研技术正努力对标HBM3。
  • 下一代产品：下一代3.0版本预计将与昇腾950DT同步推出，性能至少对标HBM3。
  • 生产合作：目前与长鑫存储进行合作，解决量产问题。
  1. 存储涨价是否会传导至下游的解决方案，云服务商为何难以提价？
  • 传导困难：理论上可以提价，但实际上云服务商不能轻易提价。
  • 主要原因：
  • 市场竞争：单独提价可能导致客户流失到未涨价的竞争对手处。
  • 备货差异：部分厂商（如腾讯）可能有较高的备货量，受上游价格波动影响较小，不会选择涨价。
  • 行业协同：除非全行业普遍性涨价，否则单方面提价风险很高。近两年内价格基本未上涨。
  1. Agent市场的成熟度和未来爆发的时间点预判是怎样的？
  • 当前阶段：Agent市场仍处于产业化和商业化起步阶段，热度虽高，但大规模商业落地场景尚未成熟。
  • 驱动因素：当前DDR等资源的紧张主要是由AI大模型和数据中心（ADC）部署驱动的，Agent的出现只是加速了供应链紧张，其影响深度不及大模型本身。
  • 未来预判：预计Agent市场到2028年才会真正迎来爆发。

单任务价值量和token消耗最高的场景或客户是哪些？

目前用量最高的场景是多轮对话，例如用于查询。如果限定在大语言模型的范畴，不考虑文生视频等跨模态应用，那么用量最多的场景主要有几个：首先是多轮对话，应用最广；其次是AI翻译，占比也较高；此外还有文案生成和报告生成等场景。

这些高token消耗量的应用场景主要集中在哪些行业？例如科技公司或制造业公司？

每个行业的应用场景不同。例如，媒体类公司主要用于文案生成；电商行业会应用在图片处理和客服问答方面；金融行业则用于客服和报表生成。

当媒体、电商或政府等不同行业的客户前来洽谈合作时，他们的需求各不相同。我们是否会根据其特定需求来配置相应的集群？

这里有几种不同的服务方式。一种是公有云的MaaS（模型即服务）模式，另一种是私有化部署，即为客户配置专门的集群。

中小企业、互联网企业及初创公司通常直接使用MaaS平台，按token进行计费。我们的MaaS是一个聚合平台，对接了现有几十上百款各类模型供客户自行选择和调用。客户可以通过API key进行调用，并能接入自己的知识库，将本地文件向量化后进行知识库搜索。

而对于头部的公司，例如一天调用量达到几十上百亿的客户，其需求和部署方式则不同。

对于用户量上万的客户，我们建议采用部署模式，而不是使用 Mass 平台。Mass 平台是多租户模式，我们会对其进行限流，包括限制 TPM（每分钟生成的 Token 数量）和 RPM（每分钟请求数）。如果用户量过高，超出限制，很多请求将无法执行或执行缓慢。因此，对于并发高、负载高、用户数多，或对时延和性能有较高要求的头部客户，我们会推荐集群部署方案。

集群的规模需要根据客户需求来计算，主要考虑用户数、并发高度以及每日的 Token 调用量，以此反推所需的机器数量。例如，对于 10000 用户以上的客户，我们通常建议部署一个由 4 台 8 卡 910C 服务器组成的集群。具体的服务器配置需要根据客户需求来推荐。

部署方案优先选择云端，因为云端交付、实施和开通速度更快。采用集群部署后，客户只需支付算力、存储等基础资源成本，不再按 Token 计费。对于有特殊需求的金融、政务类客户，我们会提供 HCS 方案。

用户需求差异很大，有些是偏向长上下文的 Agent 任务，有些是简单的聊天机器人。在为这些不同类型的用户进行配置时，存储方面会有什么差异？具体来说，除了 GPU 自带无法调整的 HBM 外，后续的 DRAM 和外挂 SSD 的配置比例是如何根据不同需求决定的？

我们有一个标准的配置比例，即 1:4:16。这是一个基准，会根据不同需求进行动态调整。在推荐配置中，也常用到 1:3:16、1:4:12 或 1:3:12 这些比例。

您提到的 HBM 是跟 GPU 卡绑定的，无法单独调整。高端卡通常有 100 多个 GB，低端卡则为几十个 GB。一台 8 卡服务器的 HBM 总量是固定的。如果需要增加 HBM，就必须在集群中增加更多的 GPU 卡。

能否介绍一下在AI服务器配置中，HBM、DDR和SSD的配置逻辑以及不同应用场景下的差异？

一般情况下，我们不会随意增加HBM，因为这会导致成本急剧上升，需要综合考虑性价比，所以HBM的配置通常是一个固定值。在其之下，我们会配置DDR内存，目前的标准配置为3T到4T，最低也有2T。

DDR的具体配置量主要依据应用场景。以对话式聊天机器人（chatbot）为例，我们会根据其模型的参数量、并发客户端数量以及对延迟的要求来决定。如果要求越高、并发量越大，DDR的配置也会相应提高。此外，还会外挂用于数据落盘的SSD，目前通常配置15T到20T。对于聊天机器人这类应用，HBM、DDR和SSD的配置比例大致为1:4:16。

那么对于智能体（Agent）平台这类应用，硬件配置有何不同？

智能体平台的配置有所不同。其配置主要取决于并发任务数、训练的规模（scale）以及延迟要求。此外，智能体后端所配合的底层基础模型也是一个重要的考量因素。

从我们目前的部署情况来看，智能体平台对HBM的配比要求会略高于对话式应用。我们一般倾向于采用1:3的比例，即HBM为1，DDR为3。SSD的配置则不固定，通常在12T到20T之间，最低为12T。

另外还有一个比较关键的问题，是关于之前你们提供的TQ……

这可以理解为是用存储换算力，即以延迟换算力吗？

是的，可以这么理解。任务转移（offload）通常应用于客户预算有限的场景。在这种情况下，我们不会配置高容量的 HBM 卡，而是通过将部分任务转移到 SSD 中执行，来满足其大模型等并发任务的时延要求。相对地，对于预算充足的客户，我们会直接增加硬件，例如将 2 台 8 卡的服务器增加到 3 台，用额外的一台处理突发性的并发访问负载。

针对这类需求，业内将在 25 年推出 AI SSD 产品，专门用于解决内存墙问题。

这款 AI SSD 产品有什么特点？

与传统的 SSD 相比，它的吞吐量和 IO 性能要高得多。

所以它主要是提升了 IO 和吞吐，而存储介质本身没有改变，优化在于控制器和软件层面，是吗？

是的，存储介质没有变。提升主要体现在 IO 和吞吐上，同时底层的算法和阵列的软件控制层面也进行了修改。

这种 AI SSD 能够部分解决任务 offload 的问题，但需要明确，并非 100% 的任务都适合转移到 SSD 执行。一旦任务进入 SSD，时延必然会受影响。虽然能解决高并发和高负载问题，但速度肯定不如直接在 HBM 中进行数据交换。因此，这涉及到性能与成本的平衡，要节省成本，就必须在性能上做出牺牲。

我们先从DDR开始讨论。目前我们观察到普遍的HBM与DDR配比是1:3或1:4。我的问题是，在多轮对话场景中，DDR主要存储KV cache，对CPU的依赖较小。而在Agent场景中，除了GPU计算，还涉及到tool calls、读取RAG等操作，需要CPU频繁与DDR进行交互。既然Agent对CPU和DRAM的消耗更强，为什么HBM与DDR的配比没有发生变化，通常还是1:3？

这个配比一般维持在1:3或1:4。之所以如此配置，是因为无论是对话场景还是Agent场景，1:4的配置在一般情况下是够用的。系统资源并未完全用满，最高使用率可能在70%到80%，因此足以应对需求。

对于1:3的配置，通常是考虑到客户在进行POC（概念验证）时，不希望资源配置过高导致利用率过低，例如低于50%，从而造成浪费。

我们通常所说的1:3或1:4是取整后的大概比例，实际配比可能会有小数点，例如1:2.9或1:3.x。

举一个具体的例子，一张H200显卡拥有140GB的HBM。一个包含8张H200的服务器，其HBM总量约为1TB。在这种情况下，我们通常会配置4TB到5TB的DDR内存，例如4.5TB，这就构成了接近1:4的比例。同时，存储方面可能会配置17TB的SSD。当然，具体的配置会根据客户的实际需求进行调整。

您提到的多轮对话场景，其内存使用和数据交换相对简单。而Agent场景更为复杂，因为它不单单是根据需求进行调用。

与常规的大模型任务相比，Agent任务在处理时有何不同，对硬件资源的需求有何特点？

大模型在执行Agent任务时有所不同，需要处理网页、执行内部文件、处理邮件等多种任务。这类任务对内存容量的要求很高，具体来说就是对KV cache的容量要求会高一点。但由于任务较长，它对延迟反而没有那么敏感。

在部署Agent时，考虑到其需要大量CPU资源，我们是否会像海外一些方案（例如NVL中1个CPU配2块GPU，每块GPU配8块HBM）那样，额外配置一个专门用于tools calling的CPU机柜？还是说机柜内自带的CPU就足够了？

我们会额外配置CPU。

那么额外配置的这部分CPU所消耗的DDR，是否独立于我们之前提到的1比3的比例之外？

对，这个不包含在里面。

请问这部分额外CPU的采购量大吗？在全年的总采购量中大约占多少？

CPU的用量不高。配置CPU的原因在于，GPU主要负责矩阵运算和深度学习，而大模型中会涉及到逻辑计算。此外，模型本身的部署可以理解为一套系统，也需要由CPU来执行。从总成本结构来看，80%以上都投入在GPU上，CPU的成本占比为10%不到，或者10%多一点。

那么具体到Agent任务，CPU的配置是怎样的？

这需要看具体的任务。以我们之前做过的一个案例来看，其中是包含CPU的，我需要回忆一下具体配置。

请问这个配置方案是供给Deepsteak的吗？

是的，我们之前有一个案例，其底座采用了Deepsteak。这是我们新推出的版本，具体配置如下：CPU配置了4颗鲲鹏920，每颗为48核；GPU配置了8颗920；CPU内存的配置是32乘以32GB。

GPU内存是8颗GPU共计4TB吗？

不是。GPU内存采用的是大内存模块，具体配置为16颗256GB的模块，即16乘以256GB。数据盘配置了NVMe SSD。

关于部署方式，这4颗鲲鹏920 CPU是与GPU集成在一起，还是部署在独立的服务器机柜中？如果是独立部署，是否意味着每部署8颗GPU，就对应部署一个含4颗CPU的机柜，形成2:1的比例？

CPU和GPU是分开部署的。在我们这个案例中，可以理解为是2:1的比例，但这个比例并非固定不变。

我们观察到Agent技术在GPT-4.5等模型推出后，从今年才开始真正兴起。在此背景下，从1月到7月，您观察到客户在采购HBM、DRAM和SSD的配比及供需方面出现了哪些明显变化？是DDR、SSD还是HBM的需求更为突出，或者说所有产品的需求都很强劲？

目前各类产品的需求都很好，但主要是DDR内存，包括DDR4和DDR5。持久化存储的情况相对好一些。HBM的需求也同样受到AI大模型方面的影响。

至于智能体（Agent），其影响目前还不是特别明显。Agent的产业化和商业化仍处于起步阶段。尽管有过一波热度，但许多公司仍处于尝试和评估效果的阶段，并未投入大量预算。这主要是因为企业需要考量实际的投资回报率（ROI），并解决数据合规等潜在问题，因此有些还在研究阶段。

实际上，在Agent概念兴起之前，DDR等资源就已经处于紧张状态。这主要是由AI模型和数据中心（ADC）的部署所驱动的，当时市场已经出现缺货。由大模型带动的上游资源供应紧张从25年开始就已出现，而Agent的出现只是加速了这一供应链的紧张状况。因此，Agent带来的影响深度不及大模型本身。

我们预计，Agent市场到28年才会真正迎来爆发。目前，其商业落地场景和产业化进程尚未完全成熟。

您好，我想了解一下采购端的情况。目前存储产品价格上涨了很多，我们在制定采购决策时，如何考虑价格上限或核心采购标准？价格高到什么程度会影响我们的采购意愿？

我并非直接负责采购，但因项目需要会与采购部门对接，因此有一定了解。每家公司的采购政策不同，以华为为例，针对HBM和DDR等产品有不同的策略。

对于HBM，华为现在已实现自研，推出了H-Cube 1.0和2.0技术。该自研技术对标的是主流HBM产品。由于受到封锁，我们无法使用最新的技术，例如HBM3以上的产品，最多只能使用到HBM2。目前华为只能用HBM2，国内其他厂商最多能用到HBM3已经很不错了，因为最新的技术会优先供应给英伟达等厂商的最新产品。

华为正沿着自研路线发展，目前是第二代技术。下一代3.0版本也即将推出，预计在昇腾950DT发布时会同步推出3.0技术，其性能预计至少能对标HBM3。

我们有了自研技术后，量产问题如何解决？是由长鑫存储代工吗？

是的，在供应方面，目前是与长鑫存储进行合作。

我理解HBM偏向于设计层面，我想主要了解DDR DRAM和SSD这类产品的采购情况。内存价格大幅上涨，是否已经影响到我们的采购决策，例如减少采购量或进行价格谈判？或者说，这部分成本在整体采购中占比不大，价格变动的感知不明显？

价格变动的感知现在已经比较明显了。在涨价初期的前3到6个月，成本上升的感受不是特别明显。

我们也可以通过一些内部方法进行消化，但长期来看，成本压力不可能一直不显现。

短期内，由于我们有存货和备品，并且与部分客户签订了长期协议，可以按照原有价格供应，所以影响不明显。其次，我们内部也会进行调整，尤其是在云端业务，通过算力调度和内存池等内存优化技术来分摊成本。但对于私有化部署，因为是一次性买断的模式，无法进行成本分摊，只能由一方承担亏损。

这种成本压力，我们在前半年已经感受到了，但由于有备品库存，我们没有立即将成本转嫁给客户。我们的调价策略是渐进式的，并非原厂价格调整多少，我们就直接转嫁给客户多少。具体而言，我们没有调整产品的目录价格，而是通过调整大客户的折扣来实现。这种方式客户更容易接受，可以避免因直接上调产品价格而导致客户流向竞争对手。我们通过这些内部消化的方法，避免了客户流失。

目前，这种压力已经明显化。我们预测，HBM包括内存的供应问题在短期内无法解决，无论是产业链问题还是真实的需求拉动所致。我们预计这种情况可能要到 2027 年或 2028 年才能缓解。

长期来看，我们内部也在寻求解决方案。一种主要的解决路径是，在继续从国外采购的同时，积极寻找国内供应商进行替代，例如长鑫存储的产品。这可以说是当下最主要的一条解决路径。

价格方面，我理解公司会寻找多家供应商并调整大客户价格。另外，存储已成为一种战略性资源，大家都在通过长期订单来保障供应链安全。请问公司在这方面是如何做的，会去签订长期订单吗？

我们也会签订长期订单，只要有机会争取到就一定会争取。因为目前保障供应的方式之一就是签订长期协议。

您提到的高价采购模式，是指与海外原厂（例如海力士）直接进行拍卖，还是通过中间贸易商进行？对于DRAM和SSD这类产品，我们目前的采购渠道是怎样的？

对于一些关键产品，例如最新的HBM，是无法直接从原厂拿到的，需要通过中间商。但DRAM和SSD，我们现在是直接对接的。采购模式确实类似于拍卖，如果您愿意出高价，就可以获得更优先的交付顺序；否则就需要排期，等待时间可能从半年到一年不等。即使通过中间商采购HBM，目前监管也非常严格，想要绕开限制非常困难，除非最终商业化应用时更换其他身份进行采购。

目前和国内厂商（如长鑫）的合作情况是怎样的？

我们与国内厂商的合作，并非直接采用他们的现有产品。作为重要的采购方，我们会向他们提出自己的特定需求，由他们根据这些需求进行针对性的设计、流片和出样。

从您的角度看，目前存储市场的紧缺程度如何？与当前的价格上涨幅度相比，是保障货源更重要，还是价格已经上涨到难以接受的水平？

目前，各头部厂商对于此轮价格上涨仍然在可承受范围之内，可以通过不同方法来稀释成本压力。价格虽然上涨，但还未到特别夸张的程度，也未到迫使我们必须向上游买家调整产品售价的地步。

我们观察到 token 和算力的需求非常强劲，这会向上游传导至对存储和 GPU 的采购，当存储成为瓶颈并因此涨价时，我们是否也能相应地为下游的机架解决方案提价？

理论上可以。但实际上，云服务商不能轻易提价，因为对于海量存储（mass storage），无论是私有云、公有云租赁，还是与华为等厂商合作的产品形态，都存在一定的标准。任何一方单独提价都可能对市场产生较大影响，并导致客户流失。

所以这其实需要行业实现普遍性涨价，如果大家都因成本压力而一同提价，问题就不大了，是这样吗？

是的，如果全行业一同涨价就没有问题。但情况并非如此，例如腾讯这类公司可能有较高的备货量，尤其是在存储方面，他们受上游价格波动的影响较小，因此不会选择涨价。所以，除非出现非常极端的情况，价格通常不会上涨，近两年内也确实没有涨过。

我想请教一个技术问题。在处理 agent 任务时，我的理解是：HBM 存储的是正在进行推理任务的 KV cache，而 DDR 则用于存放刚完成推理、等待下一次调用，或是因任务被 CPU 接管而暂时从 GPU 卸载的 KV cache。这个理解是否准确？

可以这样理解。简单来说，HBM 存放的是“热数据”，即刚处理完、即将处理或正在使用的关键数据。具体而言，HBM 中存放的是模型当前运算所必需的关键参数，而非全部参数。

DDR 则用于存放“温数据”，也就是调用频率较高但优先级低于 HBM 中数据的缓存数据。它的访问优先级高于存储在 SSD 上的“落盘数据”，因为 SSD 的读取速度较慢，容易形成瓶颈。

那么，在什么情况下会决定将 KV cache 卸载到 SSD 中（即“落盘”）？或者换个角度问，当我们为企业部署一个 agent 服务集群时，集群内每台机器的 SSD 存储空间通常是如何分配的？能否大致拆解一下模型参数、RAG 数据库以及为 KV cache 预留空间这几部分的大致比例？

以 100% 的 SSD 容量为例，如果其中 20% 用于存放模型参数，40% 用于其他数据，那么配置大容量 SSD 的主要用途是什么？

配置 SSD 主要用于存储“落盘数据”。这类数据是经过 CPU、HBM、DDR5 等多轮内存处理后执行完毕的持久化数据。例如，在模型训练的不同阶段完成后，训练好的数据就会被写入 SSD 进行存储。这个过程涉及到 CPU 内的进程处理代码及相关数据，数据从 HBM 或 DDR 中获取，处理完成后再落盘。

除了模型训练数据，SSD 中还存储其他类型的数据，例如日志文件、本地数据库以及向量数据库。向量数据库尤其关键，它用于本地知识库，将知识库中的各类文件进行向量化处理，处理后的向量数据可供模型使用。向量数据库本身也存储在 SSD 中。
