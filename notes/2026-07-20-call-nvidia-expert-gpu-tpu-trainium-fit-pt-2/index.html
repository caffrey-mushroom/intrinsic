AI算力平台与智能体基础设施专家访谈纪要

1. GPU、TPU与Trainium的工作负载适配

a) 哪些场景更适合NVIDIA GPU？

  • NVIDIA GPU更适合以下工作负载：
  1. 模型架构、提示词或数据格式频繁变化；
  2. 同时训练、测试或部署多个模型；
  3. 需要快速迭代、A/B测试和快速发布；
  4. 需要兼容广泛的AI框架；
  5. 工程时间有限，不希望投入大量适配和优化工作；
  6. 前沿模型训练、混合研究及开放式智能体工作负载。
  • 大多数企业通常从NVIDIA开始部署，主要原因不是单纯的芯片性能，而是其软件栈成熟，开发、调试、扩展和生产部署更加容易。
  • GPU无需针对单一工作负载进行大量定制优化，即可覆盖较广泛的模型和任务，因此是更稳妥的通用选择。

b) 哪些场景更适合TPU？

  • TPU更适合规模大、运行稳定、重复性高，并且已经完成深度优化的工作负载。
  • 典型场景包括：
  1. 使用JAX或TensorFlow；
  2. 长期重复训练相同的大型Transformer架构；
  3. 使用同一生产模型服务数百万用户；
  4. 模型、输入模式和服务管线较为稳定；
  5. 团队可以承担前期优化投入，并通过后续规模化运行摊薄成本。
  • 例如，团队每月重新训练一次基础语言模型，可以集中完成一次TPU适配和优化，之后通过大规模重复运行获得更低成本。
  • 对于固定模型、流量规模较大且推理模式相似的聊天机器人，TPU同样可以具备较强竞争力。

c) 哪些场景更适合Trainium？

  • Trainium更适合已经确定采用AWS生态，并希望降低充分优化模型训练成本的客户。
  • Trainium的核心吸引力在于：
  1. 与AWS基础设施深度整合；
  2. AWS持续投入硬件、编译器、运行时和框架支持；
  3. 对稳定且规模化的训练工作负载具有成本效率潜力。
  • 如果工作负载频繁变化、需要广泛框架支持或需要快速测试新模型，NVIDIA目前仍更具优势。

d) 企业是否会只选择一种计算平台？

  • 实际部署中，混合使用多种平台非常普遍，并非GPU与ASIC二选一。
  • 常见组合方式包括：
  1. 在GPU上进行研究、模型测试、A/B实验和快速发布；
  2. 将成熟、稳定的大规模训练或推理迁移至TPU、Trainium等优化加速器；
  3. 不同模型根据可用性、软件栈、经济性和时间要求选择不同平台。
  • 某个模型采用TPU或Trainium训练，并不代表该实验室正在永久放弃NVIDIA。

2. 工作负载稳定性的定义与判断标准

a) 流量大幅波动是否意味着工作负载不稳定？

  • 不意味着。
  • 从基础设施角度看，稳定性主要取决于模型计算图和服务管线是否保持不变，而不是用户数量或流量是否波动。
  • 即使用户数量大幅增加或减少，只要运行的是同一个模型、采用相似的推理模式，仍可被视为稳定工作负载。
  • 因此，同一聊天机器人模型面向大量用户服务，即使流量存在峰谷，也仍然适合采用经过优化的推理平台。

b) 哪些变化会导致工作负载由稳定转为不稳定？

  • 主要可归纳为四类：
  1. 模型变化：频繁部署新版本、更换架构或改变计算图；
  2. 输入变化：上下文窗口显著扩大，或加入视觉、音频等新模态；
  3. 性能要求变化：批量大小、延迟目标、吞吐量目标发生变化；
  4. 软件栈变化：推理框架、服务代码、运行时或调度方式发生变化。
  • 任何一类变化都可能削弱高度优化ASIC平台的收益。

c) 为什么上下文窗口变化也会影响硬件选择？

  • 即使模型本身不变，上下文长度大幅增加也会改变：
  1. 计算量；
  2. 内存容量需求；
  3. 内存带宽压力；
  4. KV Cache规模；
  5. 多卡互连与调度需求。
  • 如果引入视觉、音频等新模态，模型的性能下降曲线和资源消耗特征也会发生明显变化。
  • 因此，判断稳定性不能只看模型名称，还要观察上下文、模态、批量大小、延迟目标和软件栈是否稳定。

3. GPU短缺、平台迁移与多平台策略

a) AI团队是否会因为GPU短缺而转向ASIC？

  • 会开展评估，但并非简单地“有什么卡就用什么卡”。
  • 在此前GPU供应紧张期间，部分团队确实评估过TPU、Trainium或其他加速器。
  • 但切换平台还需要考虑：
  1. 软件迁移成本；
  2. 编译器与框架适配；
  3. 工程团队学习成本；
  4. 性能调优时间；
  5. 后续维护和扩展成本。
  • 硬件供应不足可以触发平台评估，但长期选择仍取决于性能、成本和工程投入的综合权衡。

b) 某个新模型采用TPU训练，是否意味着大模型行业正在放弃GPU？

  • 不能得出这一结论。
  • 采用TPU可能是出于以下原因：
  1. 当时GPU供应不足；
  2. TPU资源更容易获得；
  3. 特定训练任务在TPU上成本更低；
  4. 存在明确的交付时间限制；
  5. 团队已经具备相关软件栈和优化能力。
  • 大型AI实验室通常会使用不止一种计算平台，单个模型的平台选择不代表公司永久转向或放弃NVIDIA。

c) 硬件供应之外，决定平台选择的核心因素是什么？

  • 主要包括：
  1. 硬件和集群可用性；
  2. 软件生态成熟度；
  3. 模型与平台的匹配程度；
  4. 单位成本与功耗；
  5. 工程迁移和优化工作量；
  6. 训练或上线时间要求；
  7. 长期维护与扩展能力。

4. GB300、Hopper与TPU的训练效率比较

a) 最新NVIDIA GPU是否正在扩大与ASIC的训练效率差距？

  • 不能仅根据模型发布速度得出这一结论。
  • 模型训练周期不仅取决于加速器，还取决于：
  1. 核心系统设计；
  2. 软件优化；
  3. 网络与互连；
  4. 数据流水线；
  5. 集群规模；
  6. 工程质量；
  7. 模型与训练方法本身。
  • 如果首要目标是尽快完成新模型训练，并尽量减少工程投入，NVIDIA通常是更稳妥的选择。
  • 对于适配度较高且经过充分优化的工作负载，TPU同样可以具备较强竞争力。

b) GB300、Hopper和TPU V7应如何进行公平对比？

  • GB300作为更新一代产品，预计会明显快于Hopper。
  • GB300与TPU V7不能脱离具体模型直接比较，应在以下条件一致时进行系统级测试：
  1. 相同模型；
  2. 相同精度；
  3. 相同批量大小；
  4. 相同集群规模；
  5. 相同目标准确率；
  6. 相同训练数据和软件优化水平。
  • 更合理的指标是系统层面的完整训练时间，而非单颗芯片的理论性能。
  • GB300的明显优势主要体现在灵活性和软件成熟度；经过高度优化的TPU配置仍具有竞争力。
  • 受访者判断，TPU V7更偏向推理优化；对于纯训练，特别是混合且快速变化的任务，GB300通常更值得优先考虑。

c) 每美元Token数能否形成跨平台统一结论？

  • 目前没有通用基准能够证明某个平台在所有企业和工作负载中全面胜出。
  • 即使将资本开支、运营成本和电力成本全部纳入，每美元Token数仍高度依赖：
  1. 模型利用率；
  2. 软件优化程度；
  3. 集群调度效率；
  4. 模型和硬件匹配程度；
  5. 团队工程能力。
  • 即使使用相同硬件，不同团队实现的单位美元性能也可能存在较大差异。
  • 因此，应谨慎看待由供应商主导的跨平台基准测试。

d) NVIDIA在不同工作负载中的“胜率”大致如何？

  • 对通用AI和快速变化的模型，NVIDIA在现实项目中的方向性胜率约为60%—75%。
  • 对前沿模型训练和混合研究型任务，NVIDIA的胜率可能达到70%—80%。
  • 对固定模型、重复运行且大规模的推理任务，NVIDIA的胜率可能下降至40%—50%。
  • 对稳定且经过高度优化的工作负载，NVIDIA的胜率大致可能处于40%—55%，TPU或Trainium可能凭借成本效率胜出。
  • 以上比例仅为方向性判断，实际结果高度取决于利用率和优化质量。

5. Trainium与TPU的竞争格局

a) Trainium是否正在快速缩小与TPU的差距？

  • 是。Trainium近几代的改进速度较快，AWS同时在硬件和软件栈方面进行大量投入。
  • 其进步主要体现在：
  1. 编译器能力增强；
  2. 运行时持续改善；
  3. 与常用框架的结合更加便利；
  4. 硬件与软件协同设计更紧密；
  5. AWS对AI基础设施的战略投入增加。
  • 与几年前相比，Trainium正在更快地缩小差距，但整体上尚未超越TPU。
  • Trainium相对较新，生态积累和成熟度仍是重要限制。

b) Trainium进步是否主要来自与Anthropic等模型公司的合作？

  • 更核心的原因是硬件、编译器、运行时和软件团队之间的协同更加紧密。
  • 不能简单归因于模仿TPU设计，也不能只归因于某一家模型公司的合作。
  • 对AI加速器而言，编译器、运行时和框架支持所带来的整体体验，与芯片本身同样重要。

c) GPU生态优势是否仍然存在？

  • 仍然存在。
  • 即使Trainium和TPU持续增强，GPU在庞大生态系统、框架兼容、新模型优先支持和工程人才储备方面仍占优势。
  • 当前竞争格局不是某一方已全面拉开差距，而是各平台在不同工作负载中持续增强。

6. 智能体工作负载对算力平台选择的影响

a) 智能体与传统聊天机器人的工作负载有何不同？

  • 智能体不仅生成Token，还需要：
  1. 调用工具；
  2. 检索数据；
  3. 运行代码；
  4. 在多个模型之间切换；
  5. 多次调用模型；
  6. 动态规划下一步行动。
  • 因此，智能体计算更加动态、不规则和难以预测。
  • 智能体系统中，GPU不再是唯一瓶颈，CPU、内存、存储、网络、编排系统和任务调度的重要性都会提升。

b) 智能体是否整体上更适合GPU？

  • 从当前情况看，总体上更适合GPU，特别是开放式、多步骤智能体。
  • 主要原因包括：
  1. 执行路径经常变化；
  2. 工具调用和模型路由较多；
  3. 上下文长度不断变化；
  4. 模型更新更加频繁；
  5. 很难针对固定ASIC进行长期优化。
  • 但如果核心模型推理稳定，仍可以将该部分放在ASIC上高效运行。
  • 更合理的架构可能是：稳定的基础推理由ASIC承载，动态的编排、实验和变化部分由GPU承载。

c) 不同类型智能体的动态性如何划分？

  • 动态性较弱的智能体：
  1. 客户支持智能体；
  2. 文档摘要智能体；
  3. 知识辅助智能体；
  4. 理赔处理及其他规则明确的运营工作流。
  • 这类智能体通常遵循预先定义、相对一致的工作流，更容易针对GPU或ASIC进行优化。
  • 动态性较强的智能体：
  1. 编程智能体；
  2. 研究智能体；
  3. 数据分析智能体；
  4. 网络安全调查智能体；
  5. 科学发现智能体；
  6. 自主工作流智能体。
  • 这类智能体需要自主选择工具、检索信息并决定下一步行动，其执行路径会随任务变化。

d) 投资报告撰写智能体属于哪一类？

  • 如果智能体需要读取数据库、在线搜索、比较多来源数据、判断是否继续检索、执行计算并最终撰写报告，则属于高动态工作流。
  • 如果始终使用相同数据源、固定模板和明确步骤，则动态性会明显降低。
  • 开放式投资研究智能体是动态智能体的典型场景，因为每次任务的检索范围、工具选择和执行路径都可能不同。

e) 在动态智能体场景中，GPU相对TPU的优势有多大？

  • 不太可能达到10倍，更可能处于20%—50%范围，具体取决于工作负载。
  • GPU优势不只体现在原始吞吐量，还包括：
  1. 更强的灵活性；
  2. 更低的重新适配成本；
  3. 更快的模型和功能上线速度；
  4. 对多模型路由和变化上下文的支持；
  5. 较低的工程开销。
  • 对极高动态性、频繁更新且涉及大量路由的智能体，GPU的实际综合优势可能更大，但不存在适用于所有场景的固定比例。

f) 智能体发展是否会进一步强化GPU需求？

  • 总体判断是会。
  • 随着智能体任务持续时间变长、工具调用增加、模型更新加快，灵活性的价值将进一步提升。
  • 增长较快的智能体场景主要集中在编程、研究、数据分析和科学发现等开放式任务，这些领域更有利于GPU。
  • 即使部分工作负载逐渐标准化并转向ASIC，智能体系统中快速变化的部分预计仍会默认使用GPU。

7. NVIDIA在动态工作负载中的核心优势

a) GPU在动态任务中表现更好的主要原因是什么？

  • 主要原因是生态系统，而不仅是芯片性能。
  • 可归纳为三个方面：
  1. 成熟的软件体系：CUDA、编译器、运行时、性能分析和调试工具成熟；
  2. 广泛的框架支持：主流框架和新模型通常优先支持GPU；
  3. 平台灵活性：能够更快部署新模型、内核和优化方案。
  • 在动态工作负载中，快速迭代往往比挖掘最后一点硬件效率更有价值。

b) AI编程智能体是否会削弱CUDA生态壁垒？

  • AI编码工具能够加快编码和调试，并降低所有平台的工程投入。
  • 但其暂时无法完全替代以下环节：
  1. 编译器适配；
  2. 运行时优化；
  3. 性能分析；
  4. 生产测试；
  5. 集群级调优；
  6. 长期维护和故障排查。
  • 因此，AI编码工具可能缩小不同平台的工程差距，但不会彻底消除NVIDIA的生态优势。
  • 新模型通常仍优先获得NVIDIA支持，短期内CUDA优势不会消失。

c) NVIDIA将预填充与解码解耦，是否会削弱ASIC优势？

  • 会缩小差距，但无法完全消除ASIC优势。
  • 将预填充和解码阶段分离，并分别优化，可以：
  1. 提高不同计算阶段的资源利用率；
  2. 在保持GPU通用性的同时增强专业化能力；
  3. 改善固定推理工作负载中的成本效率；
  4. 降低GPU与定制ASIC之间的效率差距。
  • 但如果只有一种非常稳定、规模极大的工作负载，ASIC仍可能凭借成本和功耗效率胜出。

8. HBM、NVLink与系统级效率比较

a) HBM利用率是否是选择GPU或ASIC的决定性指标？

  • HBM利用率很重要，但通常不会被单独用于平台决策。
  • 团队更关注端到端指标，包括：
  1. 每秒Token数；
  2. 每美元Token数；
  3. 推理延迟；
  4. 系统利用率；
  5. 调度效率；
  6. 工程成本。
  • 即使某个平台HBM利用率略低，只要整体吞吐量更高、调度更优或工程成本更低，仍可能是更优选择。

b) NVIDIA平台的HBM利用率是否一定高于TPU和Trainium？

  • 目前没有明确证据支持这一结论。
  • HBM利用率高度依赖：
  1. 模型结构；
  2. 内存访问模式；
  3. 并行策略；
  4. 编译器和运行时；
  5. 软件栈优化程度。
  • 更高的HBM利用率也不一定直接转化为更高吞吐量或更好的成本效率，因此跨平台比较需要谨慎。

c) NVLink跨GPU访问HBM是否构成NVIDIA的架构优势？

  • 这确实是一项架构优势，可以减少数据移动，并简化部分分布式工作负载。
  • 相较之下，现阶段TPU和Trainium在使用其他芯片HBM方面仍存在一定限制，可能需要未来几代产品进一步改善。
  • 但NVLink和跨GPU HBM访问不是决定系统性能的唯一因素。
  • 实际效果仍取决于互连、内存系统、模型并行策略、编译器和运行时如何协同工作。

d) 超大稠密模型和长上下文更适合GPU还是ASIC？

  • 对超大稠密模型和长上下文，NVIDIA通常在以下方面更具优势：
  1. 内存扩展；
  2. 高速互连；
  3. 多机分布式软件；
  4. 系统灵活性；
  5. 复杂KV Cache管理。
  • 长上下文会显著增加内存带宽、缓存容量和互连压力，NVIDIA能够在系统层面较好处理。
  • 如果模型固定、序列长度可预测且经过深度优化，TPU或Trainium仍可能在成本和功耗效率上胜出。
  • 总体而言，NVIDIA是运营层面更稳妥的选择，ASIC则可能在特定稳定场景中实现更高效率。

e) 自研ASIC是否具有HBM采购成本优势？

  • 因此，自有ASIC的超大规模云厂商可能具备结构性成本优势，尤其在大规模部署时更加明显。
  • 但具体供应合同和加价水平并未公开，云客户也不是自行向HBM厂商采购内存。

9. CSP、新云厂商与自建基础设施的选择

a) 新云厂商相较大型CSP有哪些优势？

  • 新云厂商通常更加中立，主要优势包括：
  1. 专注提供GPU算力；
  2. 部署速度可能更快；
  3. 平台限制更少；
  4. 不强制客户使用自有ASIC；
  5. 对希望避免深度绑定超大规模云技术栈的AI实验室更有吸引力。
  • 对集中式训练集群，如果新云厂商能够提供更好的经济性或更快的上线速度，可能更受模型公司青睐。

b) 大型CSP仍具备哪些优势？

  • AWS等大型CSP能够提供：
  1. 全球区域覆盖；
  2. 成熟的网络和存储体系；
  3. 安全与合规能力；
  4. 企业级集成；
  5. 完整生产环境；
  6. 更成熟的运营和服务保障。
  • 因此，即使新云厂商能够提供同等规模GPU算力，客户也不会只根据GPU数量作出选择。

c) 如果AWS和新云厂商都能提供1吉瓦算力，模型公司会优先选择谁？

  • 不存在必然答案。
  • 对专用训练集群，如果新云厂商部署更快、价格更低，可能更具吸引力。
  • 对长期生产环境，AWS更广泛的平台能力、网络、存储、安全和运营成熟度仍然重要。
  • 实际选择通常不是非此即彼，而是根据训练与生产需求进行组合。

d) 领先模型公司未来是否会全面转向自建基础设施？

  • 更可能采用混合模式，而不是完全自建或完全租赁。
  • 当核心算力利用率长期保持高位时，自建基础设施具备经济性，可以作为稳定的固定资源。
  • 云服务仍能提供：
  1. 弹性扩容；
  2. 临时峰值容量；
  3. 全球部署；
  4. 快速获取新硬件；
  5. 降低区域性运营风险。
  • 建设和运营大型数据中心是一项复杂工程，因此领先实验室预计会同时使用自有基础设施、传统CSP和新云厂商。

10. 未来模型训练的重点方向

a) 未来最重要的两类训练方向是什么？

  • 第一是推理能力：
  1. 更可靠地解决复杂问题；
  2. 提升长链条推理能力；
  3. 减少错误和不稳定输出；
  4. 重点不是单纯增加参数，而是提高答案可靠性。
  • 第二是智能体能力：
  1. 规划多步骤任务；
  2. 使用外部工具；
  3. 与软件和真实系统交互；
  4. 根据反馈动态调整行动；
  5. 完成端到端任务而不仅是生成文本。

b) 未来训练方法会发生哪些变化？

  • 训练将更加侧重：
  1. 长上下文推理；
  2. 基于真实世界任务的强化学习；
  3. 工具使用与软件交互；
  4. 规划与行动决策；
  5. 面向智能体行为的训练。
  • 模型仍可能继续增大，但扩大参数规模本身不是最终目标。
  • 更重要的目标是提高模型解决问题、采取行动和完成任务的可靠性。

c) 缩放定律是否仍会继续有效？

  • 模型规模预计仍将继续扩大，缩放仍然具有价值。
  • 但行业重点正在从“单纯增加参数量”转向“规模扩张与推理、智能体能力提升并行”。
  • 即使未来出现更大规模模型，评价标准也将更多转向答案可靠性、真实任务完成率和智能体执行能力，而非单纯参数数量。
