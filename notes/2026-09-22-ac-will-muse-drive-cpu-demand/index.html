原标题：Meta Muse 会带火 CPU 吗？算一笔消费 Agent 的算力账

#semis #agents

AceCamp · 2026-09-22 · article 70567355

摘要

  • AMD 对 2030 年服务器 CPU 市场的预期，已从约 600 亿美元上调至约 2,200 亿美元。三类需求中，agentic 被视为最大的增长来源。
  • 按 1 亿执行日活测算，轻、中、重三档对应约 1.36 万、10.9 万、86.8 万颗 128 核 CPU；每颗 5,000 美元假设下，芯片价值约 0.68 亿、5.43 亿、43.4 亿美元。以上是装机价值，不是年度销售额。
  • Muse 的任务执行落在云端，但购物、比价、报名等案例尚不足以证明普通用户会长期保持编码 agent 的计算强度。装机弹性取决于每天运行多久，以及实际占用多少核心。

一、服务器 CPU 的三部分需求

服务器 CPU 的需求，可以拆成传统通用计算、AI 主机节点（Head-node）和 agentic 执行三部分。

这也是 AMD 对 CPU 市场的划分。Lisa Su 在一季度电话会上指出，传统计算继续增长，AI Head-node 是较小的一部分，最大的增长来自 agentic AI。

AMD 对 2030 年服务器 CPU 市场的预测也在快速上调。

图 2 AMD 对 2030 年服务器 CPU 市场的预测上修

Head-node 的增长，可以通过 GPU 部署规模和配套比例估算。Agentic 的需求则更有弹性：一次用户委托，可以延伸出多次网页浏览、搜索、脚本执行和后台检查，独立执行层的 CPU 消耗未必与 GPU 数量保持固定比例。

Muse 提供了一个观察窗口：当这类工作从开发者和企业扩展到普通消费者，究竟能形成多大的 CPU 增量？

二、用户数之外还要看核数与时间

Cloudflare 曾估算，在其美国知识工作者规模及约 15% 并发率的假设下，需要约 2,400 万个同时运行的会话。如果一颗 CPU 承载 25—50 个并发会话，就需要约 50 万—100 万颗服务器 CPU。

这个模型已经考虑了并发，但“每颗 CPU 承载多少会话”仍是一个较粗的系数。一个会话可能只调用几次 API，也可能连续浏览网页、处理文件和运行代码，资源消耗差异很大。

对具体产品，更容易理解和验证的口径是：每个 DAU 每天占用 agent 运行环境的分钟数，乘以运行期间平均实际占用的 CPU 核数。

例如，一个环境运行 60 分钟，平均消耗一个物理核心，就是 60 核分钟；平均消耗两个核心，就是 120 核分钟。这里的核数是实际计算消耗，不是虚拟机标注的配置。环境即使分配了多个虚拟核心，也未必一直用满。

完整公式为：

先用用户数、时间和核数，算出每天消耗多少核分钟；除以每天 1,440 分钟，得到平均同时需要多少核心；再考虑高峰和容量余量，换算成 CPU 颗数。

“执行 DAU”包括当天产生后台任务的用户，不要求用户打开 App。运行时间统计所有执行环境的累计运行分钟数，休眠期间不计，多个独立环境并行运行则累计计算。

三、Muse 的 CPU 装机与芯片价值

上一篇Muse不是新Agent已经讨论过 Muse 的云端执行方式：用户通过手机交办任务，浏览网页、运行工具和处理事务等执行工作发生在 Meta 的云端环境。关闭手机上的 App 后，任务仍可以继续，因此这部分执行负载会落到数据中心。因此，Muse的这种计算方式天然的增加了大量在云端的CPU消耗。

我们以 1 亿执行 DAU 为统一规模，设置三种使用情景。共同假设为：每颗 CPU 为 128 个物理核心，峰值计算需求为全天平均的 2 倍，峰值时目标利用率为 60%。

CPU 平均采购单价假设为 5,000 美元/颗，仅用于芯片价值换算，不代表 Meta 实际采购价格。

图 3 1 亿执行日活对应的 CPU 装机及芯片价值

来源：笔者测算。运行时间、核占用和价格均为情景假设，非 Muse 生产数据；芯片价值不含服务器其他部件及基础设施。

以中间情景为例：1 亿用户，每天每人运行 60 分钟、平均占用一核，合计消耗 60 亿核分钟。除以 1,440，平均需要约 417 万个核心同时工作；考虑两倍峰值和 60% 目标利用率，需要约 1,389 万个装机核心，对应约 10.9 万颗 128 核 CPU。按每颗 5,000 美元计算，芯片价值约 5.43 亿美元。

用户规模可以线性调整。中间情景下，1,000 万执行 DAU 对应约 1.09 万颗 CPU、5,430 万美元芯片价值；5 亿执行 DAU 则对应约 54.3 万颗 CPU、27.1 亿美元芯片价值。

三个情景的用户规模相同，装机结果相差 64 倍。重度情景意味着每个用户每天平均消耗 8 个 CPU 核小时，已经是相当强的使用假设，需要持续、多任务的执行行为支撑。

表中是承载相应用户规模的装机价值，不是年度收入。转成 CPU 厂商某一年的销售额，还需要考虑建设节奏、现有产能利用和设备更新周期。

四、消费场景究竟消耗多少核分钟

FUNDA 整理了 654 个公开使用案例，覆盖省钱、购物、旅行、行政事务和工作等场景。这些案例能帮助理解任务结构，但没有披露 CPU 实际占用。下面在案例后附上简单的量级假设，用来解释核数与时间的关系，不是对案例的实测还原。

购物筛选 一次任务可能只有十几个核分钟

一名用户希望购买符合预算、重量和电脑尺寸要求的工作包。Muse 浏览品牌及零售网站，约 15 分钟给出三个选项。

如果这 15 分钟内，平均实际占用 0.5—1 核：

15 分钟 × 0.5—1 核 = 7.5—15 核分钟

这样的任务对用户有用，但单次 CPU 消耗未必很大。要形成较大的日均负载，需要用户每天交办多项任务。

保险比价 经济价值很高而计算量可能有限

另一名用户自述，Muse 约五分钟找到更便宜的汽车保险方案，预计每年节省约 3,500 美元，随后帮助办理切换。

仅对前面的五分钟搜索环节，假设平均占用 0.5—1 核，对应约 2.5—5 核分钟；后续办理另计。用户省下多少钱，与 CPU 消耗多少并不成比例。高价值服务也可能只需要短时间执行。

复杂旅行规划 搜索范围扩大增加累计消耗

FUNDA 收录的一次欧洲旅行规划，覆盖多个出入境城市、日期及现金和积分方案，用户称进行了 146 次搜索。

报告没有给出完整运行时间。作为示意，如果这些搜索及整理工作累计需要 60—120 分钟环境运行时间，平均占用 1 核，就是 60—120 核分钟。

这已经明显高于一次简单购物筛选。但 146 次搜索也不应直接算成 146 个完整任务，更不能默认全部同时运行。

后台监控 两天可能只消耗几十个核分钟

一名用户让 Muse 持续检查两个孩子的游泳课名额，两天后找到空位并完成报名。假设每小时检查一次，每次环境运行一分钟、平均占用 0.5 核，检查之间休眠：

48 次 × 1 分钟 × 0.5 核 = 24 核分钟

即两天累计约 24 核分钟，平均每天 12 核分钟，报名操作另计。这组检查频率和执行时间均为示意假设，但它说明了为什么不能把“持续两天”直接换成 48 小时的连续计算。

编码任务的上限更高但仍要区分执行与等待

Claude Code 可以运行命令、执行测试并反复验证修改。编译和测试密集的工作，更容易形成较高 CPU 消耗。例如，假设一个三小时任务的云端执行环境平均消耗两核，就对应 360 核分钟；如果大量时间在等待模型回复，平均只消耗半核，则只有 90 核分钟。

这些案例支持消费 agent 存在广泛需求，但尚不能确定全体用户的平均强度。日常助手情景，需要购物、邮件、旅行、家庭事务等任务不断叠加；重度情景则需要更多并行、数据处理或代码执行，才能支撑每天数百核分钟的消耗。

五、用户基数扩大之后看使用深度

Muse 把云端执行环境带给了普通消费者，扩大了 agentic CPU 的潜在用户基数。随着用户把更多事务交给 agent，任务数量、后台检查频率和累计执行时间都有增加空间。

在本文假设下，1 亿执行日活、每人每天运行一小时、平均占用一核，对应约 10.9 万颗 128 核 CPU，以及约 5.43 亿美元芯片价值。如果使用深度达到每天四小时、平均占用两核，则上升到约 86.8 万颗、43.4 亿美元。

但从目前的消费案例看，购物、比价、报名等任务中，有相当一部分是短时间执行或间歇检查。Muse 已经展示了消费需求，尚未证明普通用户会长期保持编码 agent 那样的计算强度。

笔者对 CPU 行业的需求方向持积极判断，但单一消费产品能拉动多少装机，仍要看使用强度。AMD 对行业市场的大幅上修，需要消费助手、编码、企业自动化等多类工作负载共同增长，不能由一个产品的下载量直接推导。

后续应跟踪执行用户数、每人每天累计运行分钟数和平均实际核占用。任务增长会扩大需求，API 替代浏览器、休眠及执行效率改善则会降低单位任务成本，两者共同决定最终装机。

本文只计算独立 agent 执行层的 CPU 需求，不包含 DRAM 容量或带宽约束，也不包含 LLM 推理集群中的 GPU Host CPU 消耗。

免责声明：本文仅供研究交流，不构成投资建议。情景测算依赖用户规模、运行时间、核占用及价格等假设，实际结果可能存在较大差异。
