企业AI、智能体工作流与FDE专家访谈纪要

1. 专家背景与企业AI发展趋势

1. 受访专家具备怎样的行业与项目经验？

  • 受访者Vaibhav Kulkarni现任埃森哲高级经理，拥有26年工作经验，经历覆盖产品、咨询、架构设计、部署实施、项目管理及项目群管理。
  • 具备美国、加拿大及东南亚等地区的海外项目经验，服务过多个行业和不同类型客户。
  • 当前主要负责复杂AI项目，目标是帮助客户提升运营效率并创造可量化的业务价值。
  • 在技术选型上保持厂商中立，不主张所有场景都使用AI，而是根据业务问题合理组合AI、云、SaaS、机器学习、RPA及脚本等技术。

2. 过去6至12个月，企业AI需求发生了什么变化？

  • 企业AI需求正在从传统机器学习、深度学习及基础生成式AI，进一步转向智能体工作流。
  • 客户自身的技术和研发团队对AI的理解明显加深，开始主动评估哪些复杂流程可以通过生成式AI或智能体实现。
  • 企业关注点已不再局限于内容生成、简单采购等单点任务，而是希望自动化原本由多人协同、包含人工判断的复杂流程。
  • 智能体的目标正从“辅助单个员工”升级为“承接一个团队协同完成的部分工作”，但现阶段仍需保留人工审核和决策机制。

3. 智能体项目从演示进入生产的比例有多高？

  • 过去约12个月，受访者所在团队为约4至5家重点客户开展了约40至48个解决方案演示。
  • 真正进入生产环境的项目约为5个，生产转化率约为10%左右，整体仍然较低。
  • 受访者另提到，上述5个生产解决方案涉及约7至8个客户，相关客户与项目统计口径存在一定交叉。
  • 智能体方案在演示阶段通常表现良好，但进入真实生产环境后，准确率容易下降，导致试点向生产转化具有较大挑战。

4. 为什么智能体项目从试点进入生产较难？

  • 演示阶段通常使用范围有限、经过筛选或假名化的数据，数据质量较高，因此准确率和商业价值较容易体现。
  • 生产环境会出现试点阶段未覆盖的数据类型、异常情况和复杂业务规则，导致智能体准确率下降。
  • 企业无法直接在生产环境中随意训练模型，同时还要满足安全、治理、数据隐私和系统集成要求。
  • 生产化不仅涉及模型本身，还包括RAG建设、数据准备、业务规则配置、系统连接、可观测性、评估体系及人工审核机制。
  • 一线员工对AI生成结果的接受程度也会影响实际效果，部分员工认为修改AI输出比从零完成任务更复杂。

2. 智能体工作流的部署路径与渗透策略

1. 已上线的智能体工作流在企业整体业务中的占比如何？

  • 当前智能体工作流仍处于初步渗透阶段，在客户整体工作负载中的占比较小，未来仍有较大增长空间。
  • 客户不会在初期将完整供应链、全部营销流程或核心业务全面交由智能体处理，而是先选择业务量较小、数据暴露程度较低的范围上线。
  • 典型部署范围包括：
  1. 单一渠道；
  2. 单一市场；
  3. 较小的业务单元；
  4. 非核心或低风险流程。
  • 客户通常会保留最大规模和最关键的业务流程不变，待试点区域获得验证后，再逐步向其他业务单元、渠道和市场扩展。

2. 企业为什么更倾向于“小范围上线、逐步扩展”？

  • 客户对智能体参与业务决策仍然谨慎，不愿一次性投入全部资金，也不愿完全依赖AI作出的判断。
  • 小范围上线能够降低数据、合规及运营风险，并为客户建立对解决方案的信任。
  • 生产环境中准确率下降后，FDE可在有限范围内及时优化提示词、补充训练数据并调整智能体。
  • 方案只有在实际生产中证明准确率、ROI和运营效率达到约定目标后，客户才会批准进一步扩展。

3. 统一营销平台的部署方式说明了什么？

  • 埃森哲开发了统一营销平台，覆盖需求简报、营销内容创作及营销活动上线等端到端流程，并尝试实现智能体化。
  • 某全球大型制药企业共有约25个市场，但客户最初只允许在特定业务单元和3个市场中上线，而非全面推广。
  • 生产部署后，方案准确率出现下降，因此需要安排前向部署工程师进入客户现场进行问题处理和模型训练。
  • 在客户认可生产效果后，方案才会逐步扩展至更多业务单元和市场。
  • 埃森哲、德勤、BCG等服务商普遍采用类似的渐进式推广策略。

4. 一个典型智能体项目从试点到生产需要多长时间？

  • 发现阶段：约2至3周
  1. 识别客户用例和数据复杂度；
  2. 梳理CRM、Salesforce、ServiceNow等系统；
  3. 判断不同环节应使用智能体、机器学习、RPA还是基础脚本；
  4. 选择适合的模型。
  • 实验性试点：约3至4周
  1. 使用有限的数据范围；
  2. 通常仅覆盖一个渠道、市场或小型业务单元；
  3. 主要用于展示商业价值；
  4. 一般不建设完整的可观测性和生产级评估体系。
  • 内部审批：约1至2周
  1. 通常需要首席信息官等管理层批准；
  2. 实际经验中审批周期约2周。
  • 试点转生产：约12至14周
  1. 搭建RAG；
  2. 配置品牌、渠道及标准文档；
  3. 完成数据准备和系统集成；
  4. 构建智能体、安全治理及评估体系；
  5. 配置FDE支持。
  • 生产监控：约2至3周
  1. 持续观察准确率；
  2. 评估平均处理时长；
  3. 验证生产环境ROI；
  4. 决定是否向其他市场和业务单元扩展。

5. 试点阶段通常使用哪些模型？

  • 项目会根据用例采用不同的现有模型，而不是固定使用单一供应商。
  • 受访者提到的模型包括Anthropic Claude系列、OpenAI GPT-4o mini及Microsoft Copilot相关模型。
  • 模型选择由AI架构师根据任务复杂度、准确率、成本和系统集成需求决定。
  • 埃森哲等系统集成商没有必要自行训练基础大模型，更合理的模式是采购并组合市场上已有模型。

3. 企业AI的ROI评估与落地难点

1. 客户主要通过哪些指标衡量AI项目ROI？

  • 全职员工数量缩减或避免增员
  1. FT/FTE缩减是最直接的财务回报指标之一；
  2. 部分项目并非立即裁减人员，而是通过AI避免新增人员；
  3. 对于承担外包交付的咨询公司，人员成本节省会直接影响客户费用。
  • 平均处理时长（AHT）
  1. 衡量流程从发起到完成所需时间；
  2. 例如原流程需要12至15小时，客户希望AI将其缩短至3至4小时；
  3. AHT、问题解决时间及工单关闭时间都是关键运营指标。
  • 周期时长与吞吐率
  1. 衡量同一时间能够处理的请求数量；
  2. 关注流程是否能够更快完成并支持更大业务量。
  • 质量与缺陷率
  1. 评估AI输出质量；
  2. 控制幻觉和错误；
  3. 衡量返工及人工修订比例。
  • 客户满意度
  1. 取决于AI输出本身；
  2. 也取决于一线人员处理、调整AI输出的能力和意愿。

2. AI是否真正显著缩短了平均处理时长？

  • 当前项目的财务ROI通常可以得到改善，但平均处理时长未必能达到客户预期的60%至70%降幅。
  • 以营销内容创作为例，AI可以生成内容，但网页开发人员、设计师、创意总监等仍需审核和修改。
  • 实际项目中，相关人员可能仍需投入原工作量约50%至60%的时间处理AI生成内容，因此AHT下降并不显著。
  • 一线团队可能认为修改AI生成的代码或内容不如自己重新制作高效，形成采用阻力。
  • 项目团队需要通过培训和变革管理，让员工认识到AI已经减少了从零开始的工作量。

3. 影响AI项目质量和客户满意度的主要因素是什么？

  • AI模型或智能体生成结果的准确率与稳定性。
  • 生产环境数据是否完整，是否覆盖试点阶段未见过的异常数据。
  • 人工审核流程是否设计合理。
  • 一线员工是否具备处理AI输出的能力。
  • 员工是否愿意接受新的工作方式，而不是抵触AI生成内容。
  • 项目是否能够持续监控、调整提示词和重新训练智能体。

4. 生产级AI的主要应用场景与技术架构

1. 哪些智能体用例已经较容易进入生产环境？

  • 营销内容创作
  1. 覆盖需求简报、内容生成、审核及营销活动上线；
  2. 已服务多家制药和能源行业客户；
  3. 受访者提到的客户包括Astellas、Merck、Organon、Shell及British Petroleum等。
  • 供应链与采购
  1. 监测供应链中断；
  2. 重新规划订单；
  3. 供应商准入和黑名单识别；
  4. 合同与报价比较；
  5. 订单到现金流程中的异常处理。
  • 客户服务
  1. 端到端工单处理；
  2. 自动识别问题并生成解决方案；
  3. 在关键环节保留人工审核。
  • 财务流程
  1. 发票处理；
  2. 三方匹配；
  3. 对账；
  4. 催收跟进；
  5. 应付账款、应收账款、订单到现金和订单管理。
  • 财务领域仍处于扩展阶段，营销、供应链/采购和客户服务已形成相对成熟的客户基础。

2. 哪些领域的智能体需求正在增加？

  • 销售领域开始出现潜在客户研究等需求。
  • 人力资源领域正在增加招聘、候选人筛选和员工入职等用例。
  • 这些领域尚处于需求收集和早期扩展阶段，成熟度低于营销、供应链及客户服务。

3. 企业是否应当在所有流程中部署智能体？

  • 不应在所有环节使用智能体，单纯追求“全AI化”很可能导致项目失败。
  • 智能体更适合需要复杂执行、规划、编排和多步骤判断的流程。
  • 不需要人工判断的基础任务，可以使用更便宜的小模型、机器学习、RPA、SaaS或脚本完成。
  • 实际有效的技术架构通常是智能体、机器学习、RPA和传统系统的混合方案。
  • AI架构师需要先分析业务流程，再决定各环节最合适的技术，而不是先确定使用AI再寻找场景。

5. FDE的作用、参与者差异与收费模式

1. 为什么FDE会随着企业AI部署快速增长？

  • 传统SaaS部署完成后，供应商往往将后续采用和运营工作交给客户；但AI上线并不代表项目结束。
  • 智能体进入生产后可能因真实数据、异常情况及业务变化导致准确率下降，需要持续优化。
  • FDE的主要职责包括：
  1. 监控生产运行效果；
  2. 跟踪准确率和ROI；
  3. 处理试点阶段未覆盖的数据；
  4. 优化和微调提示词；
  5. 重新训练或调整智能体；
  6. 推动方案在更多业务单元落地。
  • 只要AI仍具有非确定性，并需要持续适配生产数据，FDE就会成为长期、不可或缺的能力。

2. AI实验室、云厂商、系统集成商及Palantir的FDE有何不同？

AI实验室：OpenAI、Anthropic等

  • 主要目标是推动自有模型的采用和使用。
  • 优势是拥有最深入的模型专业能力，并能提前接触尚在测试阶段的新功能。
  • 团队规模通常较小，人员精英化、成本较高，主要服务少量精选客户。
  • 业务范围较窄，通常聚焦于自有模型可以支持的高价值用例。
  • 中立性较弱，会倾向于推荐和销售自有模型。

超大规模云服务商：Microsoft、AWS、Google等

  • 主要目标是推动云基础设施和AI服务消费。
  • 优势包括基础设施、安全能力、企业客户关系及价格折扣。
  • 对已有云客户具备较强的交叉销售和整合能力。
  • FDE团队规模通常处于中等水平。
  • 更关注工作负载迁移、云资源使用和平台消费。

系统集成商：Accenture、Deloitte、BCG、Infosys等

  • 主要目标是交付完整项目并通过咨询、实施和长期服务获得收入。
  • 优势包括厂商中立、多供应商集成、规模化交付和变革管理。
  • 能够从整体项目视角组合AI、云、安全、SaaS和传统系统。
  • FDE团队规模较大，通常采用少量高成本驻场人员加大量离岸团队的模式。
  • 业务范围最广，关注方案采用、组织变革、长期扩展和实际业务价值。

Palantir

  • 主要目标是推动自身平台落地，并在平台基础上扩展更多应用。
  • 可能采用低成本或补贴式训练营模式促进客户快速采用。
  • 相较系统集成商，其业务范围更偏向自身平台，长期跨技术服务范围相对有限。

3. 哪类FDE提供商最可能从企业AI预算增长中受益？

  • 受访者认为，系统集成商可能比AI实验室、云厂商及单一平台公司获得更多长期收益。
  • 原因包括：
  1. 系统集成商不仅实施AI，还覆盖网络安全、云迁移、SaaS改造、缺陷修复和功能增强；
  2. 复杂项目通常无法在3至6个月内完成，需要更长服务周期；
  3. 系统集成商可以长期配置FDE并建立持续客户关系；
  4. 驻场FDE费率较高，同时可通过离岸团队提升项目规模和利润。
  • AI实验室和云厂商在模型、平台或云消费上具有优势，但业务范围相对集中，FDE长期配置空间可能不如系统集成商。

4. FDE和AI项目通常采用哪些收费模式？

  • T&M模式
  1. 按投入人员数量和工作时间收费；
  2. 对系统集成商收入和盈利最有利；
  3. 目前仍是咨询行业偏好的模式。
  • 固定价格模式
  1. 根据明确项目范围约定总价；
  2. 系统集成商需要承担交付成本超支风险。
  • 托管服务模式
  1. 通过长期服务合同持续收费；
  2. 适用于生产监控、模型维护及持续优化。
  • 成果挂钩模式
  1. 根据FTE缩减、AHT下降或其他业务指标收费；
  2. 客户越来越倾向于采用该模式；
  3. 对系统集成商而言，收入和利润的不确定性更高。

5. 系统集成商的典型AI项目费率是多少？

  • 在岸AI资源费率约为每小时150至350美元。
  • 离岸AI资源费率约为每小时30至70美元。
  • 系统集成商通常采用驻场人员与离岸团队结合的模式，以控制整体交付成本。
  • 从系统集成商角度看，T&M模式通常优于固定价格或成果付费模式。

6. 成果付费会对系统集成商收入产生什么影响？

  • 对客户而言，成果付费能够降低无效投入风险，更符合实际价值导向。
  • 对系统集成商而言，智能体项目的结果具有不确定性，单纯依赖成果付费可能难以获得理想收益。
  • 尽管T&M模式更有利于系统集成商，但客户对项目成果越来越敏感，行业不得不逐步向成果挂钩转变。
  • 为适应这一变化，系统集成商需要引进更强的工程人才、提高产品化程度并提升项目交付效率。

6. 模型成本、企业支出与预算展望

1. 模型价格下降会减少企业AI总支出吗？

  • 更便宜的模型通常会释放更多使用需求，因此单次调用成本下降不一定带来总支出下降。
  • 企业可能将更多任务迁移到AI，最终推动模型和云服务总使用量增加。
  • 支出结构会向更便宜、更高效的模型转移，但企业总体AI预算仍可能继续增长。
  • 客户通常先确定AI总预算，而不会直接干预每一个用例使用哪一种模型。

2. 企业如何在便宜模型与高质量模型之间选择？

  • 模型选择主要由AI架构师和客户技术团队负责，而不是由业务客户直接决定。
  • 对不需要复杂判断、编排器、规划器或多智能体协作的基础任务，可以采用价格较低的模型。
  • 对中等及以上复杂度的任务，不能只考虑Token成本，还要关注准确率、质量和稳定性。
  • 受访者以Anthropic Haiku为例，指出其价格较低，但准确率可能无法满足部分中等复杂度任务。
  • 模型降价后，架构师仍需要重新评估质量，不能为了降低成本而过度牺牲准确率。

3. 模型路由和成本优化应在哪个阶段完成？

  • 在正式试点前，应开展2至3周的发现阶段。
  • 业务领域专家和AI架构师共同完成：
  1. 用例分类；
  2. 数据复杂度分析；
  3. 系统依赖梳理；
  4. 模型成本测算；
  5. 准确率与质量评估；
  6. 不同模型与传统技术的任务分配。
  • ROI计算需要同时纳入模型、云服务、集成、FDE、人工审核及后续运维成本。
