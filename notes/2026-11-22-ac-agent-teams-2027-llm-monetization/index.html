\\*专家观点\\*

在金融和法律等长尾领域，大模型能力提升的关键驱动因素是什么，以及当前面临的主要瓶颈在何处？

在金融和法律等专业领域，模型能力提升的关键不仅在于模型本身，更重要的是其在进行实时推理时能否接入最新的、非公开搜索引擎可得的专业信息。例如，在金融分析中，获取关于英伟达高管的最新动态，并区分传闻与事实至关重要。同样，在法律领域，能够实时查询Westlaw等数据库中的案例和全球法律动态信息也极为关键。因此，与Bloomberg、Moody's等专业数据提供商的合作，获取高质量、实时的专有数据源，是提升模型在这些领域能力的核心。此外，近两个月出现了一个新的趋势，即数据提供商（如Scale AI）开始提供所谓的“反向工程数据”（办公场景数据），这对模型能力的提升也很有帮助。

请问什么是反向工程数据，以及它如何提升大语言模型在处理复杂问题时的能力？

反向工程数据是指通过分析最终产出物来逆向推导出其生成过程的数据。以撰写研究报告为例，输入的是一份完整的研究报告，输出的则是生成该报告的具体流程，包括查询了哪些信息、验证了哪些内容、绘制了何种图表以及具体的操作步骤。这类数据不仅限于金融领域，也涵盖其他行业，并且其数量正在不断增长。这类反向工程数据对于大模型至关重要，因为它能帮助模型在规划和处理如金融、法律等领域的复杂问题时，更精准地拆解任务和制定计划，使其表现更接近专业人士的水平。

Anthropic相较于Google的领先优势体现在哪些方面？其模型在效率与实际能力之间是如何权衡的？

Anthropic的模型在效率方面正在持续优化。例如，Argon和Carbon的评价速度相对较慢，但后续即将发布的新模型以及通过蒸馏技术得到的Hydrogen等模型，在效率上将有显著提升。模型的优先级在不同版本中有所不同。尽管单纯的效率提升可能不会直接反映在如Arena等排行榜的评分上，但在LMSYS Chatbot Arena这类基于用户体感和相互评分的平台上，效率是能够被感知的。因此，为了在排行榜上获得更高的分数，公司需要在模型的实际能力和运行效率之间进行兼顾。

业界有观点认为Anthropic的模型在实际使用体验上优于其他模型，其优势在于通过不断增大基础模型来提升长上下文任务的进步空间，并已形成一个自我迭代的闭环。请问这一闭环是如何运作的？

目前，主流模型开发基本都已实现闭环。当内部员工使用模型时，他们的反馈，无论是正面还是负面，都会被一个自动化的Agent进行分析。如果Agent识别出问题，例如在上下文压缩（context compression）等特定步骤中出现错误，系统会自动生成相关的训练数据，并将其添加到预训练数据库中。这种高度自动化的流程极大地加速了长上下文任务的调试和改进。以往，分析一个包含数百甚至数千步骤的长任务，找出其中具体错误点是一项非常繁琐的工作，因为错误往往是多个小问题的累积。现在，通过自动化分析，能够更快地定位并修复这些错误。

实现长上下文任务能力的持续提升，是否必然要求基础模型不断增大？

用于调试长上下文任务的模型本身不一定需要特别大，像Carbon这样数个T（trillion-parameter）级别的模型基本足够。然而，从发展通用基础模型的趋势来看，模型的规模确实在不断增大。即使最终发布的是通过蒸馏技术得到的小模型，也需要先训练一个能力更强的超大模型作为基础，以确保整体能力的上限。

从当前的技术发展来看，大语言模型的参数规模增长是否存在上限？目前模型规模达到了什么水平，未来的瓶颈又在哪里？

目前来看，模型参数规模在10T到20T级别内尚未观察到能力增长的尽头。从Next Token Prediction准确率等内部指标来看，至少在达到100T级别之前，模型的性能仍在持续提升，未出现明显的瓶颈。虽然理论上瓶颈必然存在，但其上限远高于当前10T左右的级别。目前所知，已训练的最大模型接近百T级别，但即便是这个规模，也尚未触及性能天花板。

随着模型性能的不断提升，除了在编码领域，其未来的主要应用场景将在哪些方面？

随着模型能力的增强，其应用将扩展到更多领域。在办公场景中，例如金融或白领工作，未来可能会出现Agent Team的形式，即由一个大型Agent自动管理整个部门的工作流程，这种应用场景对模型能力有极高的要求。此外，另一个重要的应用方向是与3D相关的垂直领域，包括CAD（计算机辅助设计）、Robotics（机器人学）和CAE（计算机辅助工程）等。

在实现由一个Agent管理整个部门的Agent Team产品形态时，是否需要一个非常大的核心模型来统筹，再将任务分发给较小的模型执行？

是的，从目前观察到的情况来看，用于扮演统筹者角色的模型确实是越大越好。除了模型本身的智能水平，另一个至关重要的能力是其对整个上下文的管理能力。

在一个部门的工作任务中，一个大型的Orchestrator模型所消耗的Token量大概会占到多大比例？

如果未来一个部门配置一个大型Orchestrator模型来管理多个小型模型或替代部分员工，那么该Orchestrator模型消耗的Token量将远超当前人均消耗水平，可能会高出一个数量级甚至更多。这是因为它承担了原本由多名员工完成的工作。虽然单个任务的Token成本可能相对更低，因为可以分派给更小的模型（例如，仅有几B参数的light模型）执行，但总体消耗的Token数量会显著增加。关键在于，负责统筹组织的模型必须具备高智能水平，例如像Carbon这样的模型。尽管总Token成本会上升，但由于节省了大量的人力成本，公司的整体支出实际上是下降的。

Agent Teams主要适用于哪些具体应用场景？

Agent Teams的适用范围非常广泛，几乎可以应用于企业的各个模块，其核心前提在于企业是否愿意接受用Agent Teams替代大部分员工。应用的关键区别在于，需要赋予Agent Teams更高级别、更宏观的任务，让其内部自行进行任务分解。一个具体的例子是，目前已有一个团队完全使用Agent Teams通过一个prompt来开发新的中等复杂度的feature。该功能允许用户在电脑网页端通过Gemini控制安卓手机上的应用程序，例如读取和发送WhatsApp消息，或通过OpenTable预订座位。若不采用Agent Teams，这项工作可能需要两到三名工程师分工协作，分别负责客户端、服务器端的开发与测试，效率相对较低。Agent Teams能够接手一个更庞大的工作任务，并自主地将其分解为更细化的子任务来执行。

Agent Teams的能力边界和未来发展潜力是怎样的，例如从管理少量Agent到管理成千上万个Agent，其任务复杂性会如何演进？

Agent Teams的能力正处在快速演进中。当前，一些大型模型已经能够管理大约十几到几十个Agent，这使其可以胜任普通软件工程师级别的工作。未来，随着模型能力的发展，它们将能够管理数千个Agent，从而处理复杂度更高的任务，相当于承担起VP级别的职责。例如，一个能够指挥数千个Agent的系统，将有能力独立开发一个金融相关的交易应用程序。

在Agent Teams被广泛应用的背景下，哪些人类角色是短期和长期内难以被替代的，其核心瓶颈在哪里？

尽管Agent Teams能力强大，但始终需要人类来处理涉及特定权限和关键决策的事务。即便在当前没有Agent Teams的工作流程中，一些核心的、突破性的操作也需要人工确认。未来，需要人类介入的场景会减少，但对介入者的专业能力要求会更高。人类的角色将转变为帮助Agent在关键节点做出决策，例如在选项A和选项B之间进行选择。

是否有考虑开发一种产品，让用户在分配任务后，Agent能自动生成一系列需要审批的问题，用户只需通过选择“是/否”或提供方向性指引即可推动工作进展？

目前内部已有类似的实践和产品雏形。在一些内部试点中，一个用于帮助管理者分析员工工作进展和潜在问题的Agent Team获得了非常积极的反馈。在传统管理模式下，一位管理者可能管理十几到二十几名员工，每个人任务不同，遇到的困难也各异，但员工未必会主动上报所有问题。例如，员工可能因未被邀请参加某个关键会议，而不知道自己正在进行的工作已被否定，导致时间浪费。现在，Agent Team可以实时追踪员工的工作内容，并与部门的整体目标进行比对。当发现员工的工作与最新的会议决议不符，或可能存在跨团队沟通障碍时，系统能主动提醒管理者。这样，管理者就能在员工开口求助前，预先识别问题并及时介入，指导员工停止当前工作或调整方向，从而实现了对整个团队更高效的管理。

为什么企业级AI Agent产品尚未推出，是算力不足的原因吗？预计何时可以推出？

目前尚未推出的主要原因在于上下文管理方面仍存在一些问题，而非算力不足。随着迭代速度的加快，预计各家公司将在3到6个月内推出相关产品。当前的核心挑战并非数据问题，而是在于随着管理的Agent数量增多，处理部门级（department level）任务的上下文变得日益复杂。关键在于要找出并修复模型在各种上下文管理中存在的bug，并实现自动化debug，从而确保模型在处理例如上下文冲突或与历史文档冲突等情况时，能有正确的行为。

模型在上下文管理中出现的bug是如何被发现并修复的？这个过程是否已经自动化？

目前bug的发现与修复流程已相对完善且高度自动化。当员工对模型的输出提供负面反馈（例如“点踩”）时，模型能够自动进行分析，其分析结果通常优于人工分析且速度更快。模型能识别出工作或分析出错的原因，多数情况下是上下文管理或内存管理的bug。修复这些bug后，模型能力会得到迅速提升。整个过程中，人的角色主要是数据评估团队（data evaluation team）进行抽查，以验证模型分析结果的准确性。基本上，只要有bug报告，调查和分析都是自动完成的。

修复bug的具体机制是什么，例如是通过修改prompt还是模型参数？这个过程的难度如何？

修复bug通常是通过创造相关的训练数据来完成，目前这个过程并不特别困难。例如，Gemini模型能力的提升也主要依赖于此种bug修复机制。只要员工能够报告错误的案例，机器就能自行分析，甚至不需要多人反馈，单个案例就足以让模型进行泛化处理。有些非常奇特的bug，如果不是员工报告，常规情况下很难被发现。例如，近期发现一个bug：模型在执行某个循环步骤（step loop n）时，自我触发了上下文压缩（context compression），压缩后的信息本身没有问题，但模型却在压缩后丢失了该信息，并错误地调用了三步之前的一个旧上下文，遗忘了最后两步的关键信息，导致后续步骤连续出错。这类在数千步的复杂任务中才会出现的奇怪行为，只有通过自动化分析才能有效发现。一旦发现这类行为，就可以针对性地创造数据，训练模型以避免再次发生。

在bug修复高度自动化的背景下，当前模型训练团队的主要工作方向是什么？

训练团队的工作主要分为预训练和后训练两个方向。负责预训练的人员仍在进行各种模型结构（model structure）的迭代，研究不同数据的配比，并试验来自不同数据提供商的数据质量。同时，他们也致力于解决许多工程上的问题，例如如何提升预训练的效率。Google的模型训练基本只采用预训练方式，直接修改参数，这与梯度下降不同，因此在推理上会带来新的瓶颈。负责后训练的人员则专注于开发各种评估器和奖励模型（reward model），以帮助模型筛选出更优质的预训练数据。

模型规模越来越大为何能带来性能提升？能否更具体地解释其内在机理？

从机理上解释，如果一个问题的复杂度很高，例如存在一万种可能的解法或探索路径（exploration method），那么理论上就需要足够多的神经元来表征这一万种可能性，才能一次性地完整表达。如果神经元数量不足，就相当于对解空间进行了有损压缩，所建立的符号系统对于解决该问题而言可能是不完备的。因此，更大的模型规模提供了更多的神经元，使其能够更充分地表征和处理复杂问题。

据悉OpenAI内部的研发优先级已调整为端侧设备、AI for Science和具身智能，这是否会影响其大模型的训练节奏？

端侧设备的发展目前并非很快，具体影响要看其策略是纯端侧模型还是端云结合。纯端侧模型目前能力有限，通常只能做到30到40亿（3-4B）参数级别。AI for Science的定义非常广泛，有人将利用AI优化模型训练也归为此类。如果指的是CAD 3D或CAE（各种模拟场景），这些是目前行业非常重视的方向。但如果特指生物医药领域，其发展速度相对较慢。目前了解到的情况是，包括OpenAI及其他二线公司在内，都没有放慢模型训练的速度。

预计明年（2027年）下半年各厂商将推出Agent Teams形态的产品，这是否意味着届时AI公司的收入将开始加速增长？

Agent Teams的推出预计将极大地推动收入增长。采用Agent Teams的公司可能会大规模削减人力员工，并将相应的投入更多地转向token消耗。

关于算力分配，目前行业内训练与推理的算力需求比例大致是怎样的？推理需求的规模是否远小于训练需求？

目前算力分配中训练所占比例较高，但并未达到8:2的极端情况，更接近于6:4的水平。当前推理算力资源较为紧张，在工作日期间难以获得稳定的扩容。造成这种情况的原因之一是大量算力被用于模型训练。此外，各大模型厂商正在普遍减少对C端用户的配额，因为C端用户数据对于模型训练的价值已经变得非常有限，厂商不再需要通过补贴来获取此类数据。

B端客户的数据是否仍具有训练价值？

根据目前了解的情况，主流的大型AI实验室出于合规和安全考虑，通常不敢直接使用B端客户的数据进行模型训练。

在B端客户中，当新模型（如5.2版本）发布后，预计会有多大比例的用户选择升级？

预计升级的比例可能相对有限。金融和法律行业的客户通常会在新模型推出后立即升级。但对于大多数从事编程工作的用户而言，升级决策更多取决于公司。如果公司不采购新方案，员工个人可能不会主动要求升级。公司在决定升级前需要进行充分测试，以确保新模型在不显著增加成本的前提下能带来明确的收益。

Anthropic在10月份的ARR环比加速增长，这是否主要是由于抢占了OpenAI的市场份额？尤其是在C端市场，具体原因是什么？

Anthropic在C端市场份额的增长，很大程度上得益于OpenAI调整了其用户配额策略。OpenAI近期大幅削减了其订阅套餐（如200美元套餐）的用户配额，使得其性价比远低于竞争对手。根据内部团队测试，同为200美元的套餐，Anthrop ic提供的价值大约是OpenAI的4倍多。此前，OpenAI为了抢占市场份额，曾提供非常慷慨的用户补贴，但现在这一策略已改变。在中断200美元用户注册后重新开放时，其套餐内容已大幅缩水。因此，许多对价格敏感、追求更高性价比的C端用户，尤其是那些同时购买多个平台账户的用户，正在从OpenAI转向Anthropic。这些用户大多进行外部编程等任务，对不同模型间的细微体验差异感知不强，其选择更倾向于能提供更多使用量的服务商。

近期Anthropic是否也开始收紧账户管理，例如大规模封禁200美元套餐的账户？其背后的原因和具体策略是什么？

是的，Anthropic确实在进行大规模的账户封禁，主要目标是清理“薅羊毛”的用户，而非进行蒸馏的用户。此举主要是为了节省算力。封禁策略主要针对特定的用户行为模式，例如，如果一个用户连续多次在配额即将用尽时才停止使用，系统会将其判定为“薅羊毛”行为。这种行为在用户中很常见，他们为了完成一个较大的任务，会等待账户配额重置后立即投入使用。

谷歌在2027年的算力规划是怎样的，其中训练和推理的算力分配如何？

谷歌计划在2027年将GPU数量从目前的70万张增加到100万张。更重要的是硬件配置的代际升级，将从目前的v5、v6和v7混合配置，全面转向v7和v8t的组合。综合考量数量和配置的提升，预计2027年总的训练算力配置将是2026年的三到四倍。这一战略调整的背后逻辑是，行业普遍认识到，通过训练一个超大模型再进行蒸馏，其效果优于直接训练小模型，例如“海之针”的发布也印证了这一趋势。

如果未来禁止向中国租赁算力，导致全球约20%的算力需求被释放，北美市场是否有能力消化这部分空余算力？

北美市场消化这部分算力不存在问题。目前存在算力未被充分利用的情况，例如，许多用户仅使用Opus和Carbon模型完成日常工作，并未使用Flash等其他模型。如果这部分空余的算力配额释放出来，市场完全有能力吸收。

在头部公司持续投入大模型训练的背景下，二三线的小模型公司是否还有存在的必要？以及，企业拥有的独特数据未来是否还能构成护城河？

二三线公司如果能训练出足够小且性价比极高的模型，仍然具有市场价值，但通过这种路径实现高收入并非易事。关于数据护城河，其稳固性正在减弱。一方面，特殊数据集的来源日益增多，例如CAD、工业模拟以及金融和法律领域的案例反向工程数据，获取数据的关键更多在于企业是否愿意投入资金。另一方面，企业当前拥有的独特数据，未来未必能继续保持其独特性。

既然3D、CAE、CAD等行业的市场规模并不大，为何各大公司仍在这些领域投入大量资源进行模型训练？这种训练是为了优化特定行业能力，还是提升通用能力？

在这些特定领域进行训练，主要目的并非直接追求其有限的商业变现潜力，而是基于两方面考虑。第一，这些复杂场景是衡量模型能力差距的有效基准。例如，3D和CAD设计涉及复杂的长程任务和反向工程（根据成品生成设计代码），对模型的上下文管理（context management）和迭代能力提出了极高要求。在训练过程中，模型能自我发现并修复在长上下文处理等方面的bug，从而促进其通用能力的提升。第二，这为模型评估提供了重要手段。当前，在常规的编码任务中，不同模型生成结果的差异已不明显。但在设计3D游戏这类复杂任务中，不同模型在思考的全面性、边缘案例（corner case）的考虑周全度等方面表现出显著差异，这有助于有效评估模型的核心思考能力。

一方面，在单人编码任务中，模型版本迭代（如从5.2到5.5）带来的能力提升体感不明显；另一方面，Agent Teams的实现又需要一个更聪明的Orchestrator模型。这两者之间是否存在矛盾？

这两个观点并不矛盾，它们描述的是两种不同的应用场景。在单人执行的、相对独立的开发任务（small feature）中，不同顶尖模型的能力差异确实难以察觉。然而，Agent Teams处理的是部门级别（department level）的大型项目，需要模型管理更大范围的复杂工作流，这对于模型的规划、协调和管理能力要求极高。在这种更复杂的场景下，模型之间的能力差距会非常显著，因此确实需要一个更强大的核心模型来扮演Orchestrator的角色。

从行业发展来看，具身智能（Embodied Intelligence）的落地节奏预期是怎样的？

具身智能领域包含多个不同的模型和技术难点。以Embodiment Reasoning为例，其核心能力（例如通过模拟器进行训练）相较于自身过去已有显著提高，模型评分远高于从前。不过，这种进步是纵向比较的结果，该领域的发展仍面临诸多挑战。

目前机器人领域，特别是具身智能（Embodiment Reasoning）的发展现状如何？相较于编程领域，其技术成熟度和未来发展空间是怎样的？

当前，机器人领域在具身智能方面取得了进展，但相较于编程领域仍有较大差距。如果将先前水平视为10分，现在大概能达到50分的水平。在编程领域，各类基准测试如Dortmund bench已变得非常复杂，需要通过偏题、难题才能区分模型优劣，榜单更新频繁。相比之下，机器人领域的任务仍相对简单，主要集中在实验室场景中的纯粹任务，例如“抓取与放置”（pick and place）、工具使用（tool usage）、轨迹规划（trajectory planning）和验证，尚未扩展到日常生活中复杂的应用场景。因此，具身智能的提升空间依然非常巨大。预计机器人领域可能需要大约一年的时间，才会发展到像编程领域那样需要不断更新榜单来衡量模型差距的阶段。此外，机器人领域还涉及VOA（Vision-Oriented Attention）模型和硬件等环节，其中硬件，如机械手的设计，也是一个瓶颈，市面上存在从几百美金到几万美金不等的各类开源和闭源方案，整个产业链条较长。

企业客户在选择Gemini、Anthropic和OpenAI等不同的大模型时，主要的考量因素是什么？是否存在客户在这些模型之间频繁切换的情况？

目前绝大多数企业用户在模型选择上存在困惑，不确定哪款模型最适合。针对这一痛点，市场上出现了类似Gemini Enterprise的解决方案，即用户支付固定的月费（例如每月五六十美金），便可以自由使用Anthropic、OpenAI和Gemini等多种模型，将选择权交还给用户。用户的选择偏好各不相同：有些人偏爱Anthropic，有些人则有自己的一套判断逻辑，会根据不同任务类型选择不同的模型，例如某些任务分配给OpenAI，另一些则分配给Gemini或Anthropic。这种能够在一个套餐内选择所有主流模型的能力很重要，因为如果单独购买某个厂商的套餐，例如微软的套餐，就无法选用Gemini的模型。

从B端市场的角度看，不同模型在功能定位和用户偏好上是否存在差异？例如，企业是更需要一个能精确执行指令的模型，还是一个能主动提出下一步建议的模型？

在训练通用模型时，会考虑到不同的用户需求，并通过设置特定的执行模式（execution mode）来触发模型展现不同的行为。对于编程用户而言，他们对模型是否主动并不十分在意，核心需求是完成任务。而对于B端用户，需求则更加多样化。部分客户不喜欢模型过于主动，他们更希望模型能严格按照既定流程实现自动化。因此，不同模型会根据其定位进行优化。例如，Kimi 3.1版本在训练时更侧重于执行的准确性，将“主动性”的优先级排在后面，以满足特定用户的需求。

在Gemini Enterprise、Claude Enterprise和OpenAI Enterprise等企业级模型的功能差距逐渐缩小的情况下，客户选择的关键决策因素是什么？

当模型在核心功能上的差距不明显时，客户的选择主要基于以下两点：

第一，推理时可接入的数据源。这一点至关重要。例如，Gemini Enterprise集成了大量实时的金融和法律数据源，用户无需额外付费即可使用。这相比于通过常规搜索引擎（如Google Search）获取的信息更为可靠，因为网络搜索结果（例如来自Reddit的内容）的准确性无法保证。

第二，价格。许多企业的预算标准是每人每月50美金左右。在此预算下，基于TPU运行的模型能够提供比其他公司更多的Token数量，这构成了显著的成本优势。

考虑到明年（2027年）可能会推出Agent Teams等新产品，您认为大模型市场未来会爆发价格战吗？当前的算力增长能否满足需求的扩张？

价格战的爆发取决于算力是否达到严重过剩的程度，而目前远未达到这个节点。算力需求正在急剧增长，不太可能在短期内出现过剩。以内部员工（仅限coding相关）的Token消耗量为例，2026年1月时，人均每日消耗量约为三四千万Token，而现在（2026年11月）已增长至1.5亿到1.6亿Token，在不到一年的时间里增长了近五倍。算力的增长速度显然跟不上这样量级的需求扩张。随着Agent Teams等新应用的推出，用户会希望利用AI完成更多任务，这将进一步推高算力需求。尽管算力可能每年翻倍，但面对需求的指数级增长，未来几年算力可能仍然处于紧张状态。
