核心摘要

  1. 传统CDN与基础云防火墙架构同质化率高达90%已进入成熟期，而AI Agent成为拥有独立权限与操作行为的实体后，为人类设计的零信任与SASE身份管理迎来“第二春”，跨国大企高客单价身份安全订单可撬动全量流量迁入。
  2. AI配套产品（AI Gateway与Guardrails）因技术栈从RAG向vLLM、MCP快速迭代，厂商普遍采用“资金池/小钱包”预付按量扣费模式，帮助企业实现多模型招标比价（如ChatGPT七折、Claude八五折）、敏感信息脱敏（Zero Data Retention）及智能路由。
  3. 通过AI Gateway将轻量任务切向自部署的DeepSeek、GLM、Kimi等开源模型、仅复杂任务调用SOTA API，企业可在无感状态下削减70%至90%的AI调用成本。
  4. 尽管AI Agent流量远超人类，但90%以上常规流量可由基础设施既有冗余吸收且伴随用量付费增长，仅语义识别提示词等需GPU升级的AI安全功能会直接推升算力硬件成本。
  5. 轻量后台Agent与毫秒级决策模型高度契合边缘计算网络，但企业从社区认可到商业化落地仍普遍需要约6个月的ROI与安全评估观察期。

正文

以下为专家观点：

Yue：公司业务中哪些板块已趋于成熟，未来一到三年内，哪些领域将成为主要的增长动力或公司的重点布局方向？

专家：业内已有共识，传统的CDN和基础安全网络防护（可理解为云防火墙）市场已非常成熟，产品形态几乎没有变化。无论是云厂商（如阿里云、腾讯云、AWS）还是以CDN为主的SaaS厂商（如Akamai、网宿科技），其CDN及基础防火墙产品的技术架构和设计理念相似度高达90%。同样，Anti-DDoS这类防御海量流量攻击的技术架构也几乎完全一致，已形成非常稳定的产品形态。 然而，零信任和身份安全领域则展现出显著的不同和巨大的增长潜力。这一安全概念在疫情期间因替代传统VPN而兴起，旨在解决远程办公场景下网络不通、VPN端点可用性差以及传统安全策略将风险暴露在入口等问题。零信任通过在边缘设置安全节点来处理身份或可疑行为，从而有效保护公司内部系统。最初，它主要应用于保障远程办公和追溯员工行为。进入AI时代后，随着AI Agent开始融入工作流程，成为拥有独立操作行为和权限的个体，原先为人类设计的零信任系统迎来了“第二春”。该系统可以被用来控制AI Agent的身份行为，判断其对特定资源的访问权限，从而实现对AI Agent的身份管理。这也会影响到Okta等传统的IAM公司，它们需要与零信任身份管理平台配合，才能在AI Agent时代发挥最大价值。这一发展使得零信任的逻辑突然闭环，成为一个极具潜力的方向。目前，绝大多数企业仍在使用传统的VPN，其升级迭代非常缓慢，而安全事件的频发正不断推高企业对边缘安全专业服务的需求。 另一个重要的方向是基础设施层。无论AI模型如何发展，自动化流量如何增长，最终都会回归到对电力、计算能力等基础设施的需求上。这意味着传统的CDN公司需要从单纯关注带宽转向提供更全面的基础设施服务，包括增强计算能力和扩大网络覆盖。随着AI应用带来的流量呈倍数级增长，对底层基础设施的要求也将越来越高。

Yue：从客户企业安全预算的角度来看，未来资金主要会流向哪些方面？例如零信任、AI安全、WAF或SASE等领域，哪个方向的需求增长预计最快？

专家：企业安全预算的流向和增长速度可以从三个主要方面来看。 首先，增长最快的领域，从市场敏锐度和用户数量来看，将是传统安全产品在AI时代的升级版。以往，企业部署的防火墙多为静态设备或服务，设置后便很少管理。然而，当前层出不穷的新型安全事件要求企业必须采取动态防护措施。这促使企业淘汰现有的硬件或静态安全产品，转向由具备成熟技术团队的SaaS厂商提供的托管式防火墙服务。例如，Akamai、Fastly、腾讯、阿里、Google、AWS等云厂商提供的云上防火墙均属于此类，它们能自动更新策略以拦截最新威胁。这种转变是紧迫的，因为传统产品的暴露风险极高，甚至厂商自身的管理面板都可能成为攻击点。预计在2026年，未使用或使用传统防火墙的企业用户数量可能会实现翻倍增长，转向采用这类网络安全产品。尽管这类基础防火墙产品更像必需品，单价和市场体量可能不是最大，但其用户基数的巨大增长将是主要特征。 其次，从收入贡献最大的来源看，身份安全领域，即零信任和SASE相关产品，将占据主导地位。这类产品的目标客户通常是已经发展成熟、业务全球化的成功企业。这些企业有管理全球员工访问内部系统（如客户管理系统、Salesforce）和网店的需求。根据二八定律，20%的顶级客户贡献了80%的收入。这类大型企业客户的订单金额通常更高，一个身份安全产品的采购能撬动其全量业务的接入。例如，一个拥有一万名员工的跨国公司采购身份安全服务，就需要为每一位员工付费。一旦采用某个平台进行身份管理，企业大概率会将其基础的CDN、WAF，乃至未来的内部AI工作流和边缘计算等服务，都逐步迁移到该平台。这是因为身份管理系统需要尽可能多的流量入口和业务视野来做出精准判断。因此，SASE产品不仅自身客单价高，还能带动更大规模的订单，其原生设计就是面向大型企业用户。同时，这类产品对AI Agent时代的适应性也更好，能够涵盖并管理Agent的运行状态和行为。 最后，第三个可能产生巨大收入的方向是与AI相关的配套产品。这个领域的产品形态尚不稳定，迭代速度极快。例如，2026年初业界还在讨论RAG（检索增强生成），随后出现了vLLM等技术，再之后AI Search又成为新的焦点。由于技术迭代迅速，很难确定哪种具体产品会长久存在。目前来看，业内较为有效的产品包括AI Gateway和Guardrails（安全围栏），几乎所有涉足AI的厂商都在提供。这些产品主要用于控制AI行为、管理Token消耗、API Key安全以及实现智能路由（如根据任务难度选择不同模型）。由于产品形态多变，多数主流厂商采用一种“资金池”或“小钱包”的商业模式。企业预存一笔资金（例如数百万美元），便可按用量使用厂商推出的所有AI新工具。当某个工具过时，企业可以无缝切换到新工具，费用从资金池中按次、按量扣除。这种灵活的计费模式本身也构成了一个巨大的、快速增长的市场。

Yue：随着AI Agent逐渐替代员工访问公司系统，当前的安全产品（尤其是零信任）能否满足由此产生的新需求？未来的产品形态将如何演进？

专家：目前现有的产品形态，如零信任安全产品，已经能够满足企业在生产环境中应用AI Agent的基础需求。企业可以利用现有工具对AI Agent进行权限限制，例如将其划归特殊用户组，确保其仅能访问特定资源。以代码审查（code review）的Agent为例，可以通过零信任策略限制其只能访问和判断相关代码，而无法触及客户信息或其他内部敏感数据。当前，通过MCP协议调用各类服务（如Salesforce、GitHub的API），并利用零信任验证Agent的访问权限（如可读或读写），已是一种成熟的应用形态。 然而，这种成熟形态是建立在现有工作模式为最终形态的假设之上，但未来的工作或沟通方式可能会发生变化，甚至可能淘汰MCP这类协议。如果出现新的协议或交互方式，基础产品形态也必须随之演进。像公司这类快速变化的公司，通常会从社区出发，推出实验性新功能供用户免费试用，以验证其是否能成为未来的生产力工具，随后再逐步将其整合为正式产品。 尽管当前产品足够企业系统化应用，但这种由AI Agent带来的需求是凭空产生的。社区（即开发者和广大用户）对这种工作方式和安全产品的使用逻辑普遍认可，但这并不意味着所有企业都会立即采纳并改变其现有工作流程。企业是否进行商业化部署，通常需要一个观察周期，例如6个月，来评估新的Agent工作模式能否在公司内部稳定运行并产生商业价值。考虑到当前技术迭代速度极快，这6个月内可能又会出现新的变化，形成一种相对悖论的状态。

Yue：AI Agent产生的网络流量远超人类用户，这对提供基础服务的公司而言，是转化为收入和利润，还是主要增加了带宽与服务器成本？

专家：AI Agent带来的流量增长对成本和收入的影响需要分情况讨论。对于涉及GPU等算力资源的新兴功能，例如使用AI强化传统网络安全产品（如通过语义识别提示词而非简单文字匹配），这确实会直接导致成本增加。企业若不进行此类升级，其安全能力在AI攻击泛滥的背景下可能会下降。 然而，超过九成的流量增长并不会直接导致成本显著上升。从CPU角度看，硬件成本相对不高。尽管内存、硬盘等采购成本在上涨，但流量增长带来的收入也在增加，因为用户通常根据使用量付费，基础付款额会随之变多。对于提供基础服务的公司而言，成本上升通常具有延迟性。多数公司会保有远超一倍的冗余资源，因此即使传统请求和流量翻倍，也往往可以复用原有资源，不会立即导致系统崩溃。 成本的传导性也存在。虽然像AWS、Akamai这样的大客户向运营商（如中国联通）采购带宽时，因用量巨大能获得相当的议价能力和底价，但如果终端ISP本身提价，这个成本最终还是会辐射到上游用户。不过，这预计不会造成巨大的成本压力传导。总的来说，对于传统流量部分，成本不会急剧上升，收入增长也相对有限；而对于涉及GPU等新算力需求的部分，则确实会因采购硬件或租用云服务而推高成本。

Yue：企业为何不直接使用OpenAI、Anthropic或Google等模型供应商的原生平台，而是选择通过第三方AI Gateway来统一管理模型调用？AI Gateway未来是否会成为一个重要的收入来源？

专家：企业选择第三方AI Gateway而非直接使用模型供应商的原生平台，其逻辑与多云战略相似。除非企业与特定模型供应商（如OpenAI）建立了深度战略合作关系，否则多数企业在商业化应用场景中不会完全依赖单一的SOTA模型。主要原因涵盖成本、管理、安全与合规等多个层面。 首先，在成本控制方面，企业为避免高昂的开销，通常会融合多个模型渠道，通过公开招标等方式采购不同折扣率的Token，例如以七折采购ChatGPT，以八五折采购Claude。AI Gateway提供了一个统一的接口，便于企业根据价格进行流量分配，避免被单一供应商锁定，并可通过设置多家供应商来规避单一供应商倒闭或无法持续供应所带来的服务中断风险。 其次，在内部管理方面，AI Gateway为员工提供了统一的调用入口。员工只需指定使用某个模型版本，而后台的供应商选择、流量比例分配、故障切换等复杂逻辑均由AI Gateway根据预设策略自动完成。此外，它还能通过缓存和日志功能优化上下文调用，节省Token消耗，并统一接入企业内部的百科、代码仓库等工具，确保员工在安全可控的范围内使用AI，防止调用恶意工具。 再者，在安全与合规方面，AI Gateway扮演着关键的脱敏层角色。企业为实现零数据保留（Zero Data Retention），不希望敏感数据被模型供应商用于训练，需要在数据传输前进行脱敏处理。AI Gateway能够在中间层识别并遮蔽手机号等敏感信息，确保供应商无法获取个人数据，这既是企业的内部需求，也符合部分地区的数据合规要求。 最后，AI Gateway能够融合自部署的开源模型。企业可将自行部署的DeepSeek、GLM、Kimi等模型整合进Gateway。通过设置策略，让这些成本较低的模型处理大部分轻量级任务，仅在需要SOTA模型能力时才调用供应商的API。这种混合使用策略能显著降低成本，在用户无感的情况下，成本节约幅度可达70%至90%。 尽管AI Gateway的技术门槛不高，许多初创公司也能开发出功能完善的产品，但其商业化的关键在于安全背书。由于Gateway处理企业所有AI流量，其性质类似于零信任安全产品，需要极高的品牌信誉。因此，拥有深厚积累的传统安全厂商在该领域更具优势，更容易获得大型企业的信任。

Yue：与AWS、Anthropic、OpenAI等云服务或模型供应商相比，在边缘网络上部署AI应用的优势体现在哪些方面？哪些应用场景更适合部署在边缘网络上？

专家：边缘网络的核心优势在于其广泛的覆盖和低延迟特性。尽管在一年前，大模型动辄数分钟的响应时间使得边缘网络几百毫秒的性能提升显得无足轻重，但随着Agent和小型专用模型等新概念的出现，边缘计算的价值正变得日益凸显。 首先，Agent类应用非常适合部署在边缘环境。Agent通常需要在后台7x24小时运行，并根据外部信息随时被唤醒。其自身运行相对轻量，核心消耗在于调用后端的大模型进行思考和操作。将Agent部署在边缘容器中，可以实现即时调用和唤醒，任务完成后即进入休眠，无需像传统服务器那样维持一个持续运行的核心实例，从而大幅降低了维持成本。例如，用于代码审核的Agent平时处于静默状态，仅在有新代码提交时被唤醒，它将代码分析任务交由后端大模型处理，自身仅需设定好工作流程和安全边界。这种轻量、分散、精调的应用模式与边缘场景高度匹配。 其次，决策类模型，如前几个月出现的Jev类型模型，也适合在边缘运行。这类模型经过精调，专注于在毫秒级别内做出快速判断（如Yes/No决策）。虽然模型本身比通用大模型小得多，但直接嵌入App或网页仍有一定负担。边缘网络为此提供了理想的中间件环境：既能提供足够的算力，又具备最低的网络延迟。若将此类模型部署在核心数据中心，仅网络通信就可能耗费数百毫秒；而部署在边缘，通信和模型运行的总耗时可控制在100毫秒以内，体感速度显著提升。这种实时性使其在智慧城市、无人驾驶、物联网等场景中具备巨大潜力，开发者可以将其无缝集成到各类应用中，实现快速响应。 总结而言，边缘网络并非要与大型云厂商在核心大模型算力上竞争，而是专注于发挥其低延迟和轻量化部署的优势。对于需要快速唤醒、分布式运行的Agent组件，以及要求毫秒级响应的专用精调模型，边缘是其理想的战场。
