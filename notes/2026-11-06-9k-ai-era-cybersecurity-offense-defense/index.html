专家访谈纪要

1. AI时代的网络安全攻防态势

a) AI目前是否让进攻方比防守方更加受益？

  • 从整体能力看，攻防双方仍处于相对均衡状态，但现阶段进攻方更具主动性和灵活性。
  • 进攻方可以借助AI探索不同于传统攻击的新手段，这些新手段对防守方并不透明；相比之下，防守方的基础防护机制、产品架构和响应流程对进攻方相对透明。
  • 近期多起造成重大市场影响和经济损失的安全事件，反映出AI技术爆发后网络安全风险正在上升。
  • 当前进攻方更愿意快速采用开源模型、商业模型和AI智能体，而防守方对新风险的认知、预算投入和产品部署相对滞后，因此短期内进攻方更占优势。

b) AI带来了哪些新的攻击方式，未来攻防范式会如何变化？

  • AI正在推动网络攻击从“人工组织、长周期筹备”转向“自动发现、自动生成、自动执行”：
  1. 主动扫描和发现潜在漏洞。
  2. 自动生成漏洞验证代码和攻击脚本。
  3. 自动构造Exploit并形成完整攻击流程。
  4. 借助智能体将模型的分析结果直接转化为攻击行动。
  • 传统攻击通常需要黑客发现漏洞、编写脚本、设计攻击路径，再通过钓鱼邮件、恶意链接或员工误操作完成入侵，整体筹备周期较长。
  • AI智能体可以大幅缩短漏洞发现到攻击执行之间的时间，形成自动化、敏捷化攻击，留给防守方分析、修复和响应的窗口显著缩短。
  • 未来防守方不能再依赖安全事件发生后的被动修补，而需要转向持续监测、主动扫描、自动响应和事前加固。

c) 企业部署大模型和AI智能体时存在哪些主要认知误区？

  • 很多企业误以为，只要采用OpenAI、Anthropic等主流厂商的大模型或智能体，相关产品天然就具备安全属性。
  • 实际上，当前大模型和AI智能体仍存在技术成熟度、安全成熟度和稳定性不足的问题，包括幻觉、偏差、错误调用及不安全输出。
  • 模型生成的代码、业务结果和工作流同样可能存在功能缺陷与安全漏洞，不能直接视为可信产出。
  • 企业还需要针对以下环节建立额外防护：
  1. AI智能体API网关。
  2. Agent工作流及工具调用权限。
  3. 提示词注入和越权调用。
  4. 模型输出与机器生成代码检测。
  5. AI治理、审计和Human in the Loop机制。
  • 目前市场尚未出现能够全面商业化、产品特性高度稳定，并系统防御大模型和智能体新型风险的成熟产品。

2. Cyber安全模型的能力、价值与边界

a) OpenAI Cyber类模型主要解决哪些问题？

  • 根据受访者对相关产品信息的理解，Cyber类模型主要聚焦软件研发周期内的安全检测与修复，包括：
  1. 代码漏洞检测。
  2. 修复方案生成。
  3. 自动生成补丁或自动修复。
  4. 在研发、测试、上线前等阶段提前发现软件缺陷。
  • 其核心价值是将安全能力前移至软件生产环节，提高软件上线后的鲁棒性、安全性和稳定性。
  • 传统企业的软件研发、测试及运行时防护往往相互割裂，Cyber类模型有望推动安全能力贯穿软件开发全生命周期。

b) Cyber类模型能否解决企业全部IT安全问题？

  • 不能。企业安全覆盖的不只是软件代码，还包括：
  1. 基础设施与网络。
  2. 计算与存储。
  3. 应用和API。
  4. 数据资产。
  5. 身份权限。
  6. 业务流程和员工行为。
  • Cyber类模型更擅长发现和修复软件生产过程中的技术缺陷，但对社会工程学、人员安全意识不足和业务流程漏洞的解决能力有限。
  • 例如，攻击者以招聘、面试或任务测试为名，诱导企业员工将恶意代码下载到公司设备，这类风险并非单纯依靠代码扫描和补丁生成就能消除。
  • 对动态验证码、模拟人类行为、业务流程利用和内部人员误操作等场景，仍需要身份管理、行为分析、终端安全和流程管控等其他安全能力。

c) Cyber类模型是否会让防守方重新取得优势？

  • Cyber类模型能够提高漏洞发现和修复效率，但不会立即逆转攻防态势。
  • 攻击成功的前提仍是企业的IT系统、应用、代码、数据或网络中存在可利用缺陷，因此提升代码质量和补丁效率确实有利于防守方。
  • 但企业生产环境中的漏洞修复还受到以下因素限制：
  1. 修复可能影响现有业务稳定性。
  2. 补丁需要完成测试、审批和上线流程。
  3. 老旧系统和复杂依赖关系增加修复难度。
  4. 生产系统通常无法随意停机。
  • 当前攻击方正利用防守方AI成熟度不足和风险认知滞后的窗口期主动出击，而防守方仍主要使用传统思路和传统工具，转型需要时间。
  • 因此，中短期进攻方仍然较为激进；长期随着自动检测、自动修复和主动防护成熟，防守方能力有望明显增强。

3. AI生成代码对漏洞数量和安全需求的影响

a) 未来AI编写代码是否会显著减少漏洞？

  • 如果AI智能体和大语言模型能力持续提升，未来大量前端、移动端和后端代码由AI生成，整体代码质量理论上会高于纯人工编写。
  • Coding Assistant厂商会持续提高代码正确性、稳定性和安全性，长期有望减少低级错误和常见漏洞。
  • 但这一过程不会立即完成，原因包括：
  1. 企业不可能一次性将全部遗留代码改为AI生成。
  2. 当前模型本身仍存在幻觉、偏差和推理错误。
  3. AI厂商为推动商业化，可能在产品尚未完全成熟时提前投放市场。
  4. 机器生成代码也可能形成区别于人工代码的新型缺陷。
  • 因此，人工代码与AI生成代码将在较长时间内共存，形成安全风险的“灰度阶段”。

b) AI代码质量提高后，企业安全防护需求是否会下降？

  • 短期内不会下降，反而可能增加。
  • 即使AI生成代码的平均质量提高，企业仍需要新的代码检测和安全治理工具，对人工代码及机器生成代码进行深度检查。
  • 随着企业部署更多AI智能体，还会产生新的安全需求：
  1. API网关和接口调用安全。
  2. 智能体工作流安全。
  3. 身份、权限及工具调用控制。
  4. 提示词注入防护。
  5. 模型和数据访问审计。
  6. AI输出内容检测。
  • 长期来看，传统代码漏洞可能减少，但安全需求会从单纯的代码漏洞检测，扩展至模型、智能体、数据、身份、业务流程及运行时安全，整体市场未必收缩。

c) 为什么防守端会为安全厂商带来新的市场机会？

  • 企业需要在传统安全产品之外，增加AI治理和智能体安全能力。
  • 目前防守端产品仍处于逐步成熟阶段，厂商需要与用户共同定义场景、产品和实施标准。
  • 潜在增长方向包括：
  1. AI生成代码安全检测。
  2. Agent运行时防护。
  3. 提示词注入检测。
  4. 模型调用和API安全。
  5. AI治理、审计和合规。
  6. 智能体身份与权限管理。
  • 防守方的劣势在于企业采购和产品建设周期较长，而攻击方只需由少数专业人员利用开源或商业模型，即可快速构造私有攻击工具。

4. AI在安全产品中的主要应用方向

a) 除代码扫描外，AI目前已在哪些安全场景落地？

  • 安全运营中心自动化
  1. 将智能体嵌入Security Operations Center。
  2. 支持Incident Management、告警、升级、跨部门协同和事件处置。
  3. 提高安全事故管理及响应流程的自动化水平。
  • 主动红队与安全巡检
  1. 利用AI智能体构建红队机器人。
  2. 定期扫描基础设施、网络、存储、计算、应用和API。
  3. 检查第三方SaaS、PaaS及外部集成是否存在漏洞。
  4. 降低人工设计安全基线检测的成本。
  • 企业安全知识库
  1. 将企业内部、行业及IT领域安全策略整合为知识库。
  2. 通过聊天机器人向员工提供安全规范和操作指导。
  3. 提高安全知识的可访问性和员工安全意识。
  • 上述场景已经出现一定规模化应用，其中安全运营自动化和知识库场景的成熟度相对较高。

b) 传统安全厂商如何将AI融入现有产品？

  • 传统厂商主要选择在既有产品中嵌入大语言模型能力，而不是彻底推翻原产品体系。
  • 典型产品包括：
  1. WAF。
  2. 防火墙和安全网关。
  3. 渗透测试工具。
  4. 告警分析和安全运营平台。
  5. 终端及网络安全产品。
  • 华为、新华三、Palo Alto等软硬件厂商正在将AI能力加入防火墙和网关，并加强对AI智能体请求、模型调用及相关流量的安全检测。
  • 现阶段传统厂商的策略仍较谨慎，更多是增强原有流程，而非全面研发全新的AI原生安全产品。

c) 模型厂商未来能否进入身份权限、终端、网关和运行时安全？

  • 从技术能力上看，模型厂商可以进入代码安全以外的身份权限、应用安全、智能体运行时、终端及网关安全等领域。
  • 但实际投入取决于两个核心问题：
  1. 新功能能否立即提升客户安全能力。
  2. 客户是否愿意为该功能采购和付费。
  • 如果相关需求不是客户中短期的关键任务，厂商可能暂缓投入，将资源集中于代码安全、安全运营自动化及Agent防护等更紧迫场景。
  • 因此，未来模型厂商和传统安全厂商的能力边界可能逐步重叠，但渗透速度会受到商业回报、需求优先级和客户采购意愿制约。

5. 安全预算与企业采购趋势

a) 企业是否正在全面增加AI安全预算？

  • 并非所有企业都在全面增加安全预算。
  • 从全球市场观察，安全投资增长主要集中在云安全领域，企业全面开展安全加固并大幅增加预算的情况尚不普遍。
  • 预算投入存在明显分化：
  1. 云化程度较高的企业更积极采购云安全能力。
  2. 金融、政府和公共事业等高合规行业投入更稳定。
  3. 安全事件可能造成重大业务损失的企业更容易追加预算。
  4. 普通企业对AI中长期风险的认知仍不充分。
  • 近期重大安全事件可能促使高合规、高风险企业更主动地升级安全能力，但尚未形成全行业同步扩张。

b) 为什么企业和安全厂商对AI安全投入仍较谨慎？

  • 企业需要判断新产品是否能够立即解决关键问题，而不是仅关注长期技术趋势。
  • 安全厂商需要确认客户是否愿意购买，否则不会激进投入研发。
  • 当前限制因素包括：
  1. 客户对AI风险的认知不足。
  2. 产品成熟度和稳定性不高。
  3. 投入回报难以快速量化。
  4. 安全系统涉及业务连续性，替换和升级较为谨慎。
  5. 企业已有大量传统安全资产，无法一次性重构。
  • 随着攻击损失扩大和监管要求加强，企业的投入意愿可能逐步提高。

6. AI智能体与安全平台化趋势

a) Agent能否串联独立安全软件，从而降低平台化的必要性？

  • Agent可以连接问题发现、风险判断、阻断执行和漏洞修复等环节，提升跨系统响应效率。
  • 但Agent并不会完全取代平台化，企业仍需要在平台、自建系统和第三方工具之间进行选择。
  • 企业是否采用平台化方案主要取决于3个因素：
  1. 合规要求：金融、政府等行业可能被要求进行私有化部署。
  2. 数据敏感性：企业可能不愿将业务、数据和内部安全信息上传至云端。
  3. 成本：自建需要投入软硬件、人员及长期运维成本，平台化方案可能更经济。
  • 因此，Agent更可能成为跨平台、跨产品的连接和自动化层，而不是彻底消除平台化需求。

b) 有了Agent后，企业是否可以完全自动化处置安全事件？

  • 目前不能，Human in the Loop仍是最佳实践。
  • 现阶段任何厂商的Agent和大语言模型都存在能力边界，尚未达到可以完全自主、可信执行的AGI水平。
  • 企业需要根据风险级别设计不同流程：
  1. 低风险事件可由系统静默自动处置。
  2. 中高风险事件需要安全团队审核。
  3. 涉及核心业务、敏感数据或跨边界操作时，需要业务与安全部门共同确认。
  • 企业会基于合规、敏感数据和成本因素，选择平台化、自建或混合部署路线，而不会仅因为Agent出现就彻底改变基础架构。

7. 云厂商与第三方安全厂商的竞争格局

a) 云厂商在安全领域具备哪些优势？

  • 云厂商同时拥有基础设施、网络、计算、存储、AI和安全能力，可以提供高度融合、开箱即用的解决方案。
  • 对已上云的应用，受访者观察到超过90%的企业会采购云厂商的平台化安全能力，如云盾、网盾等。
  • 云厂商的主要优势包括：
  1. 与云计算资源天然集成。
  2. 部署配置简单，部分功能仅需开启选项即可使用。
  3. 无需启动复杂的第三方集成项目。
  4. 总体运营复杂度和实施成本较低。
  5. AI开发平台、模型服务和安全产品可以形成一体化销售。
  • 对全新客户而言，云厂商的集成便利性、价格和部署效率形成明显优势。

b) AI和智能体发展是否会进一步增强云厂商优势？

  • 会。企业建设AI能力时，通常优先以云平台作为基础。
  • 企业采用AWS SageMaker、Bedrock等AI平台后，可以直接配置同一云厂商的安全能力，无需再与第三方开展复杂集成。
  • 云上的托管模式可以降低企业在基础设施、网络、AI工程和人员建设方面的投入。
  • MNC和非强合规企业部署AI及智能体时，云服务商的AI与安全一体化方案具有较大放量潜力。
  • 因此，AI智能体的普及可能强化云厂商在新增云原生客户中的竞争优势。

c) 第三方安全厂商仍有哪些竞争优势？

  • 混合云已经成为企业主流架构，本地数据中心、私有云和传统IT基础设施仍需要专业安全软件与硬件。
  • 第三方厂商的机会主要包括：
  1. 私有云和本地部署安全。
  2. 混合云跨边界安全。
  3. 高合规行业的专用安全能力。
  4. 身份权限、终端、WAF、DDoS等垂直领域的深度产品。
  5. 云厂商底层安全能力的供应和合作。
  • 云厂商前端虽然以自有品牌提供产品，但底层渗透测试、DDoS、WAF及AI软硬件能力未必全部自研，仍可能采购第三方产品并进行集成。
  • 因此，云厂商拥有销售界面和平台入口，并不意味着传统安全厂商失去市场。

d) 大型企业和中小企业通常如何采购云安全与第三方安全产品？

  • 大部分跨国公司和大型企业会同时采购云服务商的安全产品与第三方安全机制。
  • 中小企业更倾向于采购第三方平台化安全工具，以降低自建成本，但金融等强监管行业除外。
  • 强监管行业即使规模较小，也可能被要求建设自有安全防护能力。
  • 混合云环境下，企业通常采用以下组合：
  1. 云端使用云服务商原生安全产品。
  2. 本地使用自建系统或第三方安全平台。
  3. 云端与本地之间建立联合处置和跨边界协作机制。

8. 身份安全市场与客户分层

a) 为什么企业采用微软等云厂商产品后，仍会继续采购Okta等第三方产品？

  • 云厂商在身份认证等领域具备较强基础能力，但Okta等专业厂商在垂直领域拥有长期积累和更深入的客户痛点理解。
  • 已经使用Okta多年的企业，其内部应用、业务流程和数据均可能围绕Okta完成集成，全面替换会带来较高的重构成本和业务风险。
  • 即使企业增加微软、AWS等云产品，也更可能将原有Okta产品无缝集成，而不是完全取消。
  • 客户采购决策不仅取决于技术先进性，还取决于：
  1. 现有IT资产。
  2. 迁移和重构成本。
  3. 用户体验。
  4. 业务连续性。
  5. 历史集成关系。

b) 云厂商和第三方安全厂商谁在新增客户市场更占优势？

  • 对新增客户而言，云服务商更具天然优势。
  • 企业采购AWS等云基础设施后，其身份认证、数据平台和安全产品已经高度融合。
  • 使用云厂商安全产品往往只需简单配置，而引入第三方产品可能需要启动独立项目，进行身份认证、接口对接和系统集成。
  • 在功能满足基本需求的情况下，新客户通常优先选择操作更简单、成本更低、集成更顺畅的云原生安全产品。
  • 第三方厂商在存量客户中具备较强粘性，但在云原生新增客户市场将面临更大竞争压力。

9. 混合云环境下的安全运营模式

a) 为什么混合云成为企业安全架构的主流？

  • 企业上云已持续多年，但部分全球及中国企业的上云体验并不理想。
  • 企业既希望利用公有云开箱即用的产品和技术，又希望控制成本、满足合规并保留敏感数据，因此逐渐转向混合云。
  • 混合云通常包含两类运营模式：
  1. 自有数据中心由企业自行建设和管理。
  2. 云端基础设施由云服务商托管。
  • 混合架构既保留了云平台的效率，也为传统安全厂商提供了本地软件和硬件部署空间。

b) 混合云环境下如何处理跨边界安全事件？

  • 云端和本地通常采用不同的安全工具，跨边界事件需要云服务商、第三方厂商及企业内部团队协同处置。
  • 企业需要提前明确：
  1. 哪些事件可以由平台自动处置。
  2. 哪些事件需要企业安全团队审核。
  3. 哪些事件需要业务团队共同确认。
  4. 云端与本地之间的数据和责任边界。
  5. 服务等级协议及事故升级机制。
  • 如果攻击从云端穿透至本地，或从本地扩散至云端，仅依靠单一产品难以完成处置，必须建立联合运营机制。

10. AI监管对安全行业的影响

a) 更严格的AI监管会给安全厂商带来哪些机遇？

  • 如果监管机构加强对AI能力、应用范围和安全边界的约束，开发和使用AI的企业将面临更高的合规要求。
  • 安全通常是合规体系中的核心环节，相关政策可能推动企业增加以下投入：
  1. AI模型和应用安全检测。
  2. 数据安全和隐私保护。
  3. 模型治理与审计。
  4. 智能体身份、权限和运行时防护。
  5. 合规评估、认证和报告服务。
  • 对安全厂商和安全服务行业而言，更严格的AI合规制度总体构成潜在利好。

b) AI监管为什么也可能对安全行业形成挑战？

  • 如果政策限制模型参数、应用场景或AI能力上限，整个AI市场的应用范围和市场容量可能受到约束。
  • AI应用减少后，相应的AI安全防护产品需求也可能下降。
  • 如果AI能力充分发展，进攻方能力提升会迫使防守方购买更先进产品，并推动安全厂商持续研发；如果AI发展受到严格限制，这一增量需求也可能放缓。
  • 因此，AI监管对安全行业具有双重影响：
  1. 合规要求提升，带来新增安全投入。
  2. AI应用规模受限，压缩部分安全产品的潜在市场。

11. 国内“等保”制度及市场机会

a) “等保”是什么，哪些企业需要满足相关要求？

  • “等保”即网络安全等级保护制度，是国内针对信息系统、网络、服务器、存储、软件、硬件及研发流程提出的分级安全要求。
  • 适用范围不仅包括国企和政府机构，也包括涉及国家安全、公共安全和公共利益的民营企业及业务系统。
  • 例如，民营企业如果运营地铁、公共交通等涉及公共利益的系统，也需要满足相应等保要求。
  • 不同业务的重要性对应不同等级：
  1. 一般公共事业和公共安全系统可能需要达到三级。
  2. 政府相关系统可能需要达到四级。
  3. 军事等高敏感系统可能需要达到五级。
  • 不同等级对硬件、软件、代码、网络和合规流程有明确要求。

b) 等保认证如何实施，对安全行业有何影响？

  • 企业完成系统建设后，需要向政府授权的测试机构提出申请并支付相关费用。
  • 测试机构会依据目标等级制定测试计划，对软硬件、网络、代码和流程进行评估。
  • 测试通过后，企业获得相应等级的认证或证明；部分系统如果没有相关报告，可能无法正式上线。
  • 等保制度会直接拉动安全检测、咨询、软件、硬件、整改和认证服务需求。
  • 海外金融等领域也存在类似的强制安全检测及可靠性报告制度，因此合规驱动是全球安全市场的重要增长来源。
