专家观点

Q&A

请介绍一下Mimo大模型近期的主要进展和策略？

近期的主要进展集中在mimo 2.6的PRO和FLASH版本，目前已进入国产模型的第一梯队。特别是mimo 2.6 FLASH版本，在经济性、缓存机制及多模态识别等开发能力上，深度对标DeepSeek V4.1 Flash版本，这是一个比较大的突破。当前的工作重点更多地聚焦于Nemo大模型的推理集群加速框架，以及对DeepSeek最新开源工作的复现、参照和生产环境适配。在Agent层面，正在将类似Super Agent和对标OpenAI Agent Teams的能力整合到的Cloud体系中，包括与超级小爱、澎湃OS在手机端和PC端的生态整合。

在进行教师蒸馏时，主要参考哪些国产模型，以及这种方法是否存在无法超越教师模型的局限性？

教师蒸馏参考的国产模型包括智谱、Kimi和DeepSeek等。理论上，这种方法不一定会导致无法超越教师模型。首先，人类专家可以在专项的场景数据或自有数据上介入，从而建立起新的衍生优势。其次，该过程是参考、反思和分析教师模型的任务执行表现，而非模仿其权重分布或大规模抄袭其输出，因此不一定会被教师模型完全限制。不过，在线教师的配比会产生影响，例如，若过于单一地依赖某个教师模型，可能会导致输出风格与其非常接近，在后续的第三方交叉熵分析或文风判断中，容易被判定为过度蒸馏或抄袭。

为什么现阶段不选择对海外顶尖模型进行教师蒸馏？

主要有两方面原因。首先是成本问题。其次，海外模型的交付产物越来越折叠化，其过程思维链被大量简化，中间产物难以获取。例如，在交付一个代码项目时，可能只能得到最终封装好的程序包，而中间所有的规划文件、建构文档、技术分析报告、接口文档等均不提供。此外，其各级Agent的分配细节，如一个副代理分配了几个子代理、每个子代理的任务进程等信息也无法获得。在这种思维链和中间过程信息缺失的情况下，进行蒸馏学习会非常吃力，相当于只拿到了残缺的解题思路和答案，容易被引入误区，导致整体项目交付出现偏差。

海外模型是如何在技术上实现隐藏其核心思考过程的，国内的开源模型是否也能采取类似策略？

海外模型主要通过几种技术手段隐藏其思考过程。一种方法是在模型输出中插入特定的隐藏标记，这些标记在特定的客户端（如CodeX或Claude Code的自有终端）处理时会被拦截，从而不对外显示。另一种方法是针对API形态的输出进行混淆和掺杂处理，例如，将不同子代理的思维链进行对调，或者打乱模型思考步骤的顺序，这些都可以作为防范蒸馏的手段。

相比之下，国内的开源模型很难做到这一点。因为其模型权重已经公开，即便在API层面做混淆或隐藏处理，使用者只需平行部署一个开源权重版本，通过工程化理解，就能很快对比出两个版本的差异，从而识别出所做的特征工程、混淆或隐写策略。因此，对开源模型采取反蒸馏措施的实际意义非常有限，因为开源的初衷本就是希望用户直接基于其权重进行增量训练、微调或直接部署使用。

从模型训练的角度看，未来训练效率是否会持续提升？

是的，模型训练的速度正在加快。普遍来看，基于B200、B300甚至Rubin等新一代计算卡，通常在三个月内就能获得较好的训练结果。这种效率的提升已经导致海外计算卡的租用价格开始回调。尽管市场供应仍处于满足状态，但这种满足是通过降价实现的，因为许多持有大量计算卡的长协协议方在完成自身任务后，需要通过对外租赁来盘活资产。

模型训练效率提升背后的主要原因是什么，这与开源社区的突破有何关联？

效率提升主要源于英伟达最新计算卡的进步，包括其工程架构、算力调度能力、精度支持以及日益成熟的算子设计，这些都为推理和训练提供了强有力的支持。硬件的迭代与模型产业界的理论突破基本保持同步，使得新的模型训练工程策略和架构方法能迅速在硬件上得到体现，从而显著加强了3T以内模型的训练能力。此外，中国开源阵营的突破也起到了推动作用。例如，DeepSeek在开源推理和训练框架方面的工作以及包含的技术思路和开源成果，为整个产业界提供了可借鉴的经验。这些工程思路，包括SD-WAN等通用框架层面的开源以及对异构算力的标准化接入，都为各类项目提供了支持，间接促进了效率的提升。

为什么说未来模型训练领域的参与者数量会进一步收敛？

市场参与者收敛的原因有两方面。首先，当模型参数规模达到2T至3T级别时，许多厂商已无力承担高昂的训练成本，无法继续参与这场“军备竞赛”，例如MINI MAX、阶跃星辰等已逐步退出超大模型的竞争。其次，市场已形成普遍认知，即Flash级别的模型性能已经足够强大，能够满足市面上85%至90%普通用户的绝大多数AI需求，包括网页开发、应用制作、数据处理和办公等场景。因此，继续投入巨资研发3T以上模型的边际效益有限。这种头部玩家有意放缓前沿模型训练节奏，而中腰部玩家则转向Flash模型或端侧模型的双重效应，共同导致了市场参与者的收敛，并已反映在B系列计算卡租金的回调上。

既然可以选择在2T至3T的开源模型上进行微调，为什么Minimax、阶跃星辰等公司不采取同样的策略？

理论上他们可以这样做，但实际操作面临挑战。关键在于，这些公司并未掌握独家的、场景化的数据。在一个已经相当完善的开源模型基础上进行微调，如果没有独特的数据优势，很可能导致模型性能下降或无法获得显著增益，这与品牌定位和应用场景的匹配度密切相关。

手机厂商基于开源模型进行微调的独特优势是什么？相较于其他同样使用开源模型的第三方，它们如何避免陷入纯粹的价格竞争？

手机厂商的优势在于其拥有庞大的用户基础和明确的推理需求基本盘，覆盖车机、手机端、智能助理（如超级小爱）以及即将发布的整合云能力的下一代澎湃OS和办公场景。这部分自有体系内的用户更关注实际问题的解决和合理的性价比，而非模型是否基于开源微调。因此，手机厂商不必在模型发布初期就过度担忧开发者调用量不足的问题，因为其C端用户本身就构成了稳定的需求基础。这种场景和数据的优势，使得厂商可以针对特定场景进行有效优化和收敛，从而规避了与其他第三方开发者在同一赛道上单纯进行价格竞争的风险。

在模型策略上，公司是如何规划云端大模型与端侧模型的？是优先发展Flash这类轻量化模型，还是Pro这样的大参数模型？

公司的策略是加速端侧模型的发展，同时在云端维持一个技术不掉队的大模型。端侧模型的需求正在显著增长，尤其是在桌面级AI计算设备（如AI Cube）上部署几百T算力的模型。未来，消费者将倾向于在本地设备上运行200B至300B参数的模型，以实现全天候持续运行、保护数据隐私，并处理各种模态信息。这不仅满足了用户对隐私和无限制使用的需求，也有助于带动更高性能、更高价值的硬件设备销售，从而分担纯云端推理集群的成本压力。在云端，策略并非追求超大参数模型。例如，公司发布的1T以上模型参数量为1.02T，远小于业界其他模型（如Kimi的2.8T）。后续推出的Pro Speed Ultra版本也更强调性能、加速和性价比。云端大模型（Large模型）的核心目标是作为技术基座，确保技术不落后，并以此为基础拆解出Flash模型和端侧模型。

Pro模型的主要应用场景是什么？其在公司内部和对外生态中分别扮演何种角色？

Pro模型主要面向生态链企业内的开发者。对内，它作为一个大型基座模型，用于验证公司的技术水平，并作为训练Flash模型的“教师模型”环节之一，同时也能为内部的RSI或编程辅助等应用提供一个性能领先的版本。对外，该模型主要赋能给生态链中为数众多的应用开发者，为他们提供开发工具和技术支持。

公司为何要坚持自研AI大模型，而不是完全依赖第三方开源模型？

坚持自研模型的关键原因在于公司业务版图极为宽广，涵盖手机、智能汽车（包括车载系统和自动驾驶）、巨犀智能以及PC等众多品类。如果完全依赖第三方开源模型，将难以实现跨设备、跨品类的协调适配，也无法积累长期的自主技术和成本优势。不同业务线（如手机、汽车、智能家居）对AI模型的需求和成本核算方式各不相同，若分别采购或基于不同模型开发，会导致重复建设和较高的成本。自研一个统一的AI基座，则可以实现技术共享，避免这种高昂的代价。

关于在端侧部署200B到300B参数模型的规划，当前端侧设备的承载能力是否支持？具体的技术路线图是怎样的？

目前的端侧设备尚无法部署如此大规模的模型，当前主流端侧模型最多在7B至14B参数之间。200B至300B模型的端侧部署是为下一代消费级电子平台进行的技术储备。技术路线图分为几个阶段：首先，将Flash级别的量化模型部署到家用的AI主机或AIGC微型超算（如AI Cube）中；该步骤成功后，意味着拥有多芯片和相似功耗架构的汽车平台也能适配并部署这类模型；最后，在解决了前两个终端场景后，才会着手攻克手机这类单芯片、低功耗环境，研究如何部署一个经过极致量化的70B至100B（或略高）参数的端侧版本来执行相应任务。

Agent Team主要应用于哪些场景？其部署在云中与超级小爱整合，具体是如何运作的？

Agent Team目前被封装在云中，后续将与超级小爱进行整合。其主要应用场景有两个方面。第一，针对自营及生态链中的大量智能家居设备。过去用户需要通过米家APP或小程序手动控制每一个设备，当设备数量增多时（例如近百个），操作和协同变得极为困难。Agent Team能为云端的每个设备分配一个Agent，根据用户的自然语言指令和AI协同控制逻辑，实现对大量设备的智能化管理和高效协同，解决了以往基于规则的整合模式效果不佳的问题。第二，面向重度生产力用户，应用于泛办公、复杂项目开发、数据调研及研究报告撰写等场景。Agent Team架构能够比以往的方案更有效地执行复杂任务，它如同一个内部角色无固定分工的团队，各Agent可以根据需要灵活转化、相互补位，协同完成特定目标。这种模式类似于在一个统一框架（如HarmonyOS框架）内实现多个Agent的高效协作，而非简单地将多个独立模型进行硬性组合。

Agent Team的实现是更侧重于模型层面的突破，还是产品设计层面的创新？另外，将Agent Team作为高优先级项目，是因为它更适配的特定场景，还是当前行业各家都在推进的普遍趋势？

Agent Team的实现首先是产品层面的，与框架机制（如HarmonyOS框架）相关，但同时也需要模型层面做出相应的突破来支持。将其作为高优先级项目，主要是因为它非常适配的业务场景。

未来是否多数AI应用都会采用Agent模式，其主要价值体现在哪些方面？

大概率会推进。例如，Work-Body、豆包、千问等应用一定会基于各自的生态或场景改良Agent Team方案，以实现AI之间的协作。这种模式最大的作用是解放用户的注意力，用户无需持续监控项目进展、检查每个中间产物或进行大量的Prompt批准，而是让AI自主决策和判断。其核心是从接收需求转变为预测、推进并推荐需求。例如，AI可以分析群聊中人类的一句吐槽或需求，自动在后台进行预探索和信息搜集，在确认需求价值后，完成技术方案、初步验证甚至小型Demo，然后向人类汇报已完成的工作，并提出后续P0、P1级别的开发建议，询问是否进入下一步。

Agent Team与单个Agent在产品设计或用户体验上有何本质区别？

主要区别在于设计架构。目前主流的交付方案，如Codex或Claude Code，仍以单个Agent为核心，该Agent最多指挥5到6个仅负责信息搜集等辅助任务的子代理。在这种模式下，通常是一个Agent从头到尾线性执行任务，在不同任务节点间切换。其优点是上下文记忆可以持续累积和共享，任务交付路径单线性，每个节点可追溯，且Token消耗量相对可控。

相比之下，Agent Team模式是将原先由单个Agent串行完成的工作，合理地分配给多个Agent并行处理，如同团队协作。这种模式的挑战在于需要解决多Agent间的信息对齐、产物标准统一、进度约定等问题，存在沟通成本和摩擦，可能导致重复工作和冗余操作。因此，其Token消耗量会大幅增加，可能是单Agent模式的10倍甚至100倍。尽管这对于销售Token的模型厂商有利，但用户侧初期可能难以接受，只有那些注意力高度稀缺、无法长时间监控AI交付过程的重度开发者或生产者才会采用。

Agent Team模式主要面向哪些用户群体，其核心价值是什么？

Agent Team模式最大的潜力在于企业端，能够极大地释放效能。在这种模式下，一个人类员工可以管理成百上千个能够有序协作并产出正向交付成果的Agent，而不会出现互相掣肘或拉低整体产出的情况。对于个人生产者而言，由于其Token消耗速度快，且模型厂商通常不愿意让个人用户无限制地消耗额度，因此并非主要目标用户。此外，用户自行开启多个窗口让不同Agent同时运行，仍需人类作为项目经理进行信息的复制、粘贴和搬运，而Agent Team则无需人类介入，可实现后台的自主协同。

从技术角度看，采用Agent Team（多Agent并行）而非单个Agent处理多任务，是否能解决上下文记忆丢失和模型注意力分散的问题？

是的。当单个Agent处理多个混合任务时，其上下文记忆窗口（如百万级别）被打满后必须进行压缩，这不可避免地会导致信息丢失。同时，模型难以分清不同任务的执行重点和焦点，其注意力会天然地向最近几轮的交互倾斜，从而忽略早期的项目原则、约定或其他已完成的交付成果中的重要信息。Agent Team通过让不同的Agent负责不同的任务，可以基于共性的项目背景和记忆实现更有效的管理。这正是在短期内模型上下文窗口长度或其注意力精选能力遇到瓶颈后，业界选择在并行或横向路径上进行扩展的原因。

DeepSeek开源其推理框架对行业及自身业务有何具体影响？

该开源项目最大的贡献在于为国产模型提供了参考和借鉴，使得在部署DeepSeek模型时，能够将NVIDIA GPU上的大量算子、推理引擎及工程化产物，几乎无性能损失地迁移到华为升腾的算力阵营上。同时，这对其他国产算力或异构算力平台也具有借鉴意义，能够加快其生态的适配和迁移速度。对于自身而言，即便不采购华为芯片而选择其他国产算力，该开源框架同样有很大的帮助。公司会充分解析和借鉴其设计，并结合自身模型的特征进行相应调整，同时看到了许多新的思路和范式转移策略，例如，如何在将算子从NVIDIA阵营切换到其他阵营时避免性能损失，相关的工程策略和项目设计都非常有价值。

DeepSpeed的开源框架对模型厂商的价值体现在何处？为何其对不同厂商的帮助程度存在差异？

DeepSpeed的开源框架对于模型结构与其相似的厂商具有较高的参考价值。由于自身模型结构与DS存在相似性，且对NVIDIA的依赖程度相对较低，因此DS的开源框架，特别是其推理框架以及面向国产算力进行设计迁移的工具，能够提供显著帮助。这与一些深度依赖NV卡进行训练和推理的大型模型厂商不同，后者由于存在较强的路径依赖和内部阻力，向异构算力或国产算力迁移的动力不足，因此DS的相关框架和工具对它们的实际效用有限。

在参考DeepSpeed的开源推理框架后，模型和硬件层面需要进行哪些相应的调整？目前的推理成本与DeepSpeed相比处于何种水平？

在参考DeepSpeed的开源推理框架后，模型本身以及软件框架都需要进行调整，其中模型和软件框架的调整是优先事项。芯片层面的调整周期更长，需要进行更多的论证和规划，其受到的影响相对更为间接。目前，经过调整后的推理成本基本可以与DS相媲美，可能略高出15%至20%。

“超级小爱”这一场景的核心功能是什么？它如何在国内相对封闭的生态系统中实现服务整合？

“超级小爱”的核心功能是作为个人助理，主要覆盖智能家居管理、个人日程与生活管理以及工作辅助等场景，类似于Muse与work party的结合体。在国内生态环境下，虽然不像海外开放生态那样可以直接接入各类服务，但可以通过“agent to agent”的方式与应用服务商进行逐一谈判，以实现APP端或应用端能力的接入。目前，除了智能家居管理，它也能为用户的本地生活，如出行、外卖、餐饮、旅游等提供帮助，并管理部分工作事务。行业当前的重点是优先发展智能办公领域（如Office三件套及泛办公应用），未来将逐步对标Muse，发展为全能型生活助理。然而，要解决国内APP厂商间信息孤岛的严重问题，实现更深度的服务整合，可能需要国家层面出台相应的行业规范或指引来推动“agent to agent”的互联互通。

手机厂商是否有机会推出OS Agent，其面临的主要挑战是什么？与Super APP Agent相比有何区别？

手机厂商在推出OS Agent方面持相互观望的态度，例如会参考华为，华为会参考苹果，而苹果则会关注其他大模型厂商的进展。主要挑战在于，端侧AI的用户付费意愿存在瓶颈，增加的设备溢价需要厂商与用户进行新的博弈。同时，AI涉及个人隐私和伦理问题，厂商还需应对监管层面的博弈。以苹果为例，其主要担忧反垄断指控以及欧盟在数据合规方面的严格制裁。在国内，华为的鸿蒙体系最接近苹果的闭环生态，但为了持续吸引开发者，难以采取强硬的介入方式，以免损害其生态拓展。对于、OPPO、vivo等基于安卓的厂商而言，由于安卓生态的开放性，它们无法强制要求应用厂商在其平台上进行开发并开放Agent调用权限。这些厂商在推进类似OS Agent的策略时会更加审慎，倾向于走一步看一步。

在中国市场，由于安卓生态的开放性，手机厂商是否难以强制要求大型应用厂商为其系统进行深度开发，从而导致类似OSA（Operating System Agent）的整合模式难以实现？

是的，这种模式在中国市场推行的客观难度很大。一方面，手机厂商担心若强制推行，会遭遇大型应用厂商大范围的联合抵制。国内市场存在多家手机品牌并存的格局，如果某一家厂商的做法过于激进，其他厂商可能会联合抵制。另一方面，生态系统中存在像微信这样体量巨大的超级应用，它本身就具备向AI化改造和发展为OSA形态的潜力，构成了手机厂商主导整合的一大障碍。目前整个局面尚不明朗，仍需一段时间发展才能看得更清晰。此外，个人端Agent的需求本身也需要市场验证，存在付费意愿不明、语音交互习惯渗透率低、交互复杂性等问题。目前来看，使用AI交互在效率上是否能超越用户直接在App内操作尚未得到证实。同时，AI对手机算力侧的负担也给厂商带来较大压力，尤其是在存储、推理、算力等成本上涨，而手机换机周期拉长、消费者支付意愿不高的背景下，问题更为突出。

从手机厂商的角度来看，AI时代的到来对其业务模式，特别是应用商店和浏览器等互联网服务收入，会产生怎样的影响？

AI时代的到来对手机厂商而言并非完全有利。尽管中国的移动互联网基础设施较新，用户体验基础好，但存在信息孤岛和碎片化问题，这在AI时代对提供更优的C端体验是不利的。手机厂商天然希望与用户体验站在一起，保持中立，不愿被单一的超级App绑架。然而，AI时代的一个趋势是，各大互联网巨头都希望将自身打造为新一代的超级App，甚至是一个全能型的AI OS，实现一站式解决用户所有需求。例如，若腾讯将其所有小程序完成AI化改造，理论上独立App的存在必要性将大大降低。这种趋势对手机厂商原有的商业模式构成了挑战，特别是对于像这样依赖“硬件低毛利+互联网附加服务高毛利”模式的厂商，其应用商店等收入会受到很大影响。

面对AI可能带来的商业模式冲击，手机厂商正在采取哪些应对策略，并从中发掘了哪些新的机遇？

手机厂商主要从两方面进行应对。一方面是硬件层面的高端化转型，例如和其他等厂商都在持续向更高价位段发展，通过推出旗舰影像机型、AI旗舰手机、折叠屏手机等产品来提升硬件本身的毛利，但这一策略的效果因存储芯片等元器件涨价而受到一定影响。另一方面，AI也带来了新的商业机会，尤其是在个人AI云服务领域。与个人Agent相关的云存储、云电脑、云端环境、数据保护、跨端云生态整合等需求正在加强。厂商可以围绕这些新需求设计联合权益产品，或通过云服务收取更多费用。在这方面，苹果被认为是理想的范例，但其面临合规和反垄断等压力。因此，国内厂商可能会在这一路线上更加积极地投入和布局，例如加强在PC、个人工作云以及跨端云服务整合方面的投入。腾讯等互联网公司也开始重新重视这一生态，例如其推出的AI套餐就整合了多种服务。
