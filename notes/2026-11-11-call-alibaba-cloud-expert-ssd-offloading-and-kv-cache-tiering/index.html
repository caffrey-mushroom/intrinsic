1. 推理集群存储架构与配置比例

a) 2026—2027年推理集群中，单GPU的HBM、DRAM和SSD如何配置？

  • 推理集群主要考虑HBM、DRAM和SSD三层资源的配比。
  • 典型配置比例约为：
  1. HBM∶DRAM∶SSD约为1∶2∶8
  2. 部分场景可提升至1∶4∶20
  3. 极端情况下，SSD比例甚至可能扩展至50
  • DRAM配置主要取决于节点类型：
  1. Prefill节点通常采用HBM∶DRAM约为1∶2
  2. Decode节点通常采用约1∶4，配置更大的DRAM池
  • SSD配置更加灵活，不需要全部部署在单台GPU服务器内，可以通过远端共享存储、高密度闪存服务器及CXL扩展形成共享SSD池。
  • 在PD分离架构下，一个Decode节点可能挂载4—5台高密度SSD服务器，形成集群级SSD共享池。

b) 为什么阿里不会采用DeepSeek式的单GPU超大SSD配置？

  • 阿里云面向的是多模型、多租户和异构算力的大型公有云平台，需求与DeepSeek针对特定模型深度优化的模式不同。
  • 阿里云已形成四类池化能力：
  1. 计算池化
  2. 内存池化
  3. 存储池化
  4. 网络池化
  • 阿里认为没有必要在每台服务器或每张卡上配置特别大的SSD，可以通过高性能网络和共享存储池实现更灵活的资源调度。
  • 整体SSD容量会快速增长，但不会均匀分配到每张卡或每台服务器上，不同卡型、8卡/16卡服务器及超级节点会采用不同规格。

c) 哪些业务场景需要更高的DRAM和SSD配置？

  • AIGC向量检索场景
  1. 类似Lindorm的检索服务需要实现秒级召回
  2. 大量数据需要驻留内存，因此DRAM配置较高
  3. 大规模向量数据还需要本地大容量SSD，DRAM与SSD会同步放大
  • 模型权重热备场景
  1. 阿里的E-gin模型权重热切系统需要将大量非激活模型权重常驻共享内存
  2. 因此需要大容量DRAM和CXL内存扩展
  • Agent长程任务场景
  1. 长上下文、长记忆和历史KV数据会持续占用SSD
  2. SSD将逐步承接原本放在HBM或DRAM中的部分数据

2. Prefix/KV Cache命中率与行业对比

a) 阿里百炼不同场景的缓存命中率分别是多少？

  • 不同模型、任务和部署方式之间差异较大：
  1. 百炼自有千问模型的长程任务、在线编码及文档审阅场景：约78%—85%
  2. 百炼平台整体平均水平：约60%—68%
  3. DeepSeek等外部托管模型或多Agent场景：约40%—50%
  4. 客户在裸机上自行搭建、尚未优化的Agent：约20%—35%
  • 百炼自有模型命中率更高，主要原因是模型、平台、自研DPU、编译器和底层存储之间进行了白盒协同，部分优化已经达到微码级。
  • 外部开源模型只能进行平台适配和编译器优化，除非由阿里长期托管并持续调优，否则命中率很难达到自有模型水平。
  • 从阿里云全平台口径看，平均缓存命中率接近70%，平台追求的是大规模、多场景下的综合表现，而非单一模型的极致指标。

b) 国内其他厂商的最佳缓存命中率处于什么水平？

  • DeepSeek
  1. 针对特定模型、经过多轮运行后，缓存命中率可以超过90%
  2. 前几轮命中率可能不高，但几十轮之后可稳定在较高水平
  3. 主要受益于模型与存储的深度协同，以及低秩KV压缩
  • 月之暗面
  1. 在特定超长上下文场景中，有效命中率可能达到90%以上，甚至约92%
  2. 但在Agent长程任务和多模态任务中的表现未必同样突出
  • 阿里与上述厂商的差异在于，阿里云更像综合型平台，需要兼顾多模型、多客户和多应用，不能仅针对单一场景优化。

c) DeepSeek为什么能够实现较高的缓存命中率？

  • DeepSeek采用低秩压缩，将每层、每个Token的KV压缩为较小的潜变量。
  • 在相同SSD容量下：
  1. 常规方案可能只能加载数万个Token的上下文
  2. 压缩后可加载数十万甚至100万以上Token的上下文
  • 本质上是显著降低单Token KV占用的物理字节数，从而提高可缓存上下文规模和后续轮次命中率。

d) 如果不继续增加SSD，还有哪些方式可以提升命中率？

  • 全局KV Cache调度
  1. 阿里自研tier KVCM缓存调度系统
  2. 统一管理多级缓存、全局KV Cache Store和PD分离资源
  3. 新实例可以从G3.5层以毫秒级速度拉回历史KV块
  • 模型与框架协同
  1. 针对千问及Agent产品进行专门的底层框架优化
  2. 通过动态加载缓存技术提升特定产品的缓存利用率
  • 软硬件协同
  1. 仅依靠软件优化不足以解决容量、时延和成本问题
  2. 还需要定制主控器、NAND颗粒和企业级SSD
  3. 相比采购标准SSD模组，定制方案成本可能降低30%—40%

3. 多级缓存体系与KV Cache保存周期

a) 阿里的KV Cache分层存储体系如何划分？

  • 阿里已经实现存储与内存融合的多级缓存架构，主要包括：
  1. G1：HBM层，缓存时间约为分钟级，约1分钟
  2. G2：本机DRAM
  3. G2.5：本机挂载的CXL内存池，缓存时间约1.5小时
  4. G3/G3.5：SSD/NAND池，通常按24小时配置
  5. 更低成本的层级可用于更长期的数据留存或归档
  • 不同层级的时间配置并非完全固定，部分SSD数据可能保存1小时，也可能保存24小时甚至更长。
  • 24小时并非绝对上限，系统会通过热度和访问策略进行滚动，部分企业级及Agent数据需要更长期保存。

b) 24小时KV Cache落盘是否会成为行业标准？

  • 随着Agent和企业级应用发展，历史上下文、长记忆和任务状态不能轻易丢失，24小时落盘预计会逐步成为基础能力。
  • 如果厂商不建设分层缓存和落盘体系，将面临更多重算成本，Token成本和毛利率可能缺乏竞争力。
  • OpenAI已开始提供最长约24小时的缓存策略；英伟达推出KVBM、Dynamo等技术，本质上同样是将部分KV卸载至闪存池。
  • 专家判断，KV Cache落盘和“以存代算”最终可能成为全球通用技术路线。

4. SSD采购规模与KV Cache Offloading需求

a) 2026年和2027年的SSD采购量分别是多少？

  • 2026年SSD采购容量约为16—17EB
  • 2027年规划采购约为27—30EB
  • 按上述口径计算，2027年同比增速至少在55%以上，按照中高位规划测算可能接近80%。
  • SSD采购容量的增速将明显快于HBM和DRAM。
  • 2027年虽然SSD容量大幅增长，但由于将更多采购60TB、64TB、120TB等高密度产品，SSD盘数增幅可能不到20%。

b) 2026年和2027年的DRAM采购量分别是多少？

  • 2026年DRAM采购量约为0.8EB
  • 2027年约为1.1—1.2EB
  • 同比增速约为45%—50%，低于SSD的容量增速。

c) KV Cache Offloading占SSD采购容量的比例是多少？

  • 2026年专门用于KV Cache Offloading的SSD容量占比不到10%。
  • 2027年该比例预计提升至接近18%。
  • 该口径主要指专门服务于KV Cache的独立高密度NAND/SSD资源，不包括GPU服务器中同时承载多类任务、难以拆分的混用SSD。
  • 2027年KV Cache Offloading相关容量相比2026年可能增长1倍以上，是新增SSD需求的重要驱动力。

d) 其余大部分SSD主要用于哪些场景？

  • 传统通用计算和公有云存储。
  • 2026年新增约55万台CPU服务器，其中部分承担Agent执行任务所需的CPU计算。
  • GPU服务器及8卡、16卡或超级节点中的本地SSD。
  • 推理集群中的高密度SSD服务器及共享存储池。
  • 向量数据库、检索、模型权重、企业应用和其他云服务数据。

e) 为什么2027年SSD采购量增长如此明显？

  • Agent任务从2026年开始发展，2027年需要提前建立底层IT和存储基本盘。
  • 主要驱动因素包括：
  1. KV Cache落盘比例提升
  2. Prefix缓存保存时间延长
  3. 长上下文和长记忆需求增加
  4. PD分离后Decode节点挂载更多高密度闪存服务器
  5. 向量数据、模型权重及企业级Agent数据持续增长
  • 上层应用对底层基础设施需求存在滞后，因此必须提前建设，不能等Agent应用全面爆发后再补充存储。

5. “以存代算”的TCO与技术争议

a) SSD延迟较高，为什么不直接让GPU重新计算Prefix？

  • 专家测算显示，在超大规模推理平台中，重新计算的综合成本约为存储成本的2—3倍。
  • 以100万Token为例：
  1. 压缩后的KV Cache仅占几GB，通常不超过10GB
  2. 在SSD中保存24小时的折旧和电费成本较低
  3. 删除后重新执行100万Token的Prefill，需要消耗GPU卡时和电费，成本约为0.3—0.5元
  4. 存储一天的成本可能比重新计算一次低数十倍
  • 因此，对于1万卡至10万卡级别的大型云端推理平台，“以存代算”具备明显TCO优势。

b) 什么情况下重新计算可能更合理？

  • 小模型或单机运行场景。
  • 对时延极度敏感、SSD读取速度无法满足需求的场景。
  • 车载、端侧等对实时性和硬件资源约束更强的场景。
  • 如果GPU利用率较低、任务规模较小，重新计算的性价比可能更高。

c) 哪些任务最适合KV Cache Offloading？

  • 长程Agent任务。
  • 在线编码、文档审阅和多任务协同。
  • Harness类任务及多Agent协作。
  • 这些任务的核心要求是降低长期Token成本，时延通常不是第一优先级，因此更适合采用SSD落盘和Prefix复用。

6. SSD产品需求、采购模式与供应链策略

a) 阿里未来重点需要什么类型的SSD？

  • 更倾向于236层以上的NAND产品。
  • 单盘容量至少需要达到60TB、64TB，进一步向120TB以上发展。
  • TLC和QLC均存在增长空间：
  1. QLC更适合追求大容量和低成本的场景
  2. TLC适合对寿命和性能要求更高的场景
  • 阿里无法自研NAND颗粒，但可以自研主控器，并将主控器与采购颗粒结合，定制企业级SSD。

b) 2027年SSD采购将采用什么模式？

  • 采购结构大致分为：
  1. 约40%完全白牌化：平头哥开发主控器，阿里向三星、长存采购颗粒，再交由代工厂生产
  2. 约30%半白牌化：使用阿里主控器，但颗粒由板卡或代工厂采购并按阿里要求定制
  3. 约20%多采购三星、海力士的标准SSD模组
  4. 约5%采购长存标准SSD模组
  • 整体方向是提高自研主控和白牌化比例，降低对标准SSD模组的依赖。
  • 通过定制主控器和颗粒，可以在寿命、容量、延迟和成本之间进行针对性优化。

c) 采购订单是否已经全部锁定？

  • 2026年的主要需求已基本锁定。
  • 当前锁定的重点是NAND颗粒，而不是大量标准SSD模组。
  • 阿里已与三星、长存等供应商签订NAND颗粒长期协议，即LTA。
  • 2027年约27—30EB的需求尚未全部以标准SSD订单形式覆盖，较大比例将通过自研和白牌化方式完成。

d) 是否会导入铠侠、闪迪推广的SLC类产品？

  • 目前没有明确的大规模导入或测试计划。
  • 2026—2027年的重点更偏向自研主控、定制TLC/QLC和白牌企业级SSD。
  • SLC类产品预计不会形成较大采购量。

e) 2027年SSD和DRAM的采购金额约为多少？

  • SSD采购金额预计约为100亿—120亿元人民币
  • DRAM采购金额预计约为95亿—110亿元人民币
  • 该金额不包含HBM和HDD。
  • HBM支出可能高于普通DRAM和SSD支出的总和。

7. 国内外KV Cache Offloading技术路线差异

a) 为什么国内KV Cache Offloading进展相对更快？

  • 国内模型较多采用稀疏模型、MoE和多模型架构，海外则较多采用稠密模型，模型架构不同导致KV卸载方式不同。
  • 国内高端Prefill算力相对不足，更需要通过缓存复用和减少重算降低计算压力。
  • 国内Token价格竞争激烈，厂商有较强动力降低单位Token成本。
  • 国产模型从架构设计初期就更重视缩小KV：
  1. DeepSeek采用MLA，将单Token KV从数百KB压缩至几KB
  2. 阿里研发GDN线性注意力，目标是减少约一半的KV层
  • 海外算力更充足、Token定价和毛利率更高，过去缺少通过存储节省算力的紧迫性。

b) 海外是否会跟进KV Cache落盘？

  • 2026年下半年开始，海外厂商已经加大相关投入。
  • OpenAI已采用最长约24小时的缓存策略。
  • 英伟达推出KVBM和Dynamo软件栈，将部分KV卸载至闪存池。
  • 专家判断，随着Agent长任务增加和推理成本竞争加剧，海外KV Cache Offloading占比也会结构性提升。

8. 2027年CAPEX、算力卡与基础设施规划

a) 2027年阿里云CAPEX预计是多少？

  • 专家预计阿里云2027年CAPEX约为2300亿—2500亿元人民币。
  • 相比2026年仍有增长，但增速可能略有放缓。
  • 存储采购金额占总CAPEX比例看似不高，主要是因为：
  1. 尚未计入HBM
  2. 算力卡和服务器仍占较大比例
  3. HBM金额可能高于普通DRAM和SSD总和

b) 2027年CAPEX大致对应多少张算力卡？

  • 规划口径接近200万张。
  • 考虑自研芯片产能约束，实际采购或部署量可能为180万—200万张。
  • 自研卡占比预计超过一半。

c) 国内和海外分别部署多少张卡？

  • 海外约为40万—45万张，接近45万张。
  • 海外最多可能投放约10万张自研TPU用于推理，其余主要为英伟达GPU。
  • 国内部署100多万张卡，主要使用平头哥自研卡。
  • 海外CAPEX占总CAPEX比例预计约40%，低于一半。

d) 30EB SSD平均到每张卡是多少？

  • 如果按200万张卡和30EB容量简单计算，平均约为每张卡15TB。
  • 但该数字不能视为实际单卡配置：
  1. 部分卡可能配置8TB
  2. 部分节点会通过共享池挂载更大容量
  3. 大量SSD还用于传统云、CPU服务器、向量检索和其他公有云业务
  • 阿里更强调集群级池化，而非统一的单卡SSD配置。

9. Agent发展对长期存储需求的影响

a) 2027年之后SSD需求是否会趋于平缓？

  • 从单集群、单卡配置角度看，2027年完成基础配置后，单位算力对应SSD的增长可能有所放缓。
  • 从整体数据量和应用规模看，SSD需求未必会平缓，增长曲线仍可能保持陡峭。
  • 主要原因包括：
  1. 2025年以对话推理、网页推理为主
  2. 2026年Agent应用开始发展，但渗透率仍不高
  3. 2028—2029年Agent可能替代大量传统应用
  4. 传统应用也可能被迫转向Agent化
  5. 数据形态将从结构化数据转向向量、KV和长记忆数据
  • 存储性能要求也会提高，部分传统PCIe 4.0 SSD可能逐步升级至PCIe 5.0或PCIe 6.0。

b) 2027年在整个发展周期中处于什么位置？

  • 2027年可能是SSD导入斜率最快的年份之一。
  • 这一阶段的核心任务是建立KV Cache、长记忆和Agent数据存储的基础盘。
  • 上层Agent应用真正大规模发展可能滞后于底层IT建设，因此2027年的投入具有提前预置性质。

10. 推理业务毛利率与Token商业模式

a) 阿里百炼推理业务的毛利率是多少？

  • 通义自有模型的平均毛利率约为25%。
  • 百炼托管的第三方开源模型毛利率可能略高。
  • 上述毛利率为Blended整体口径，包含KV Cache、Prefix等因素。
  • 阿里Token业务毛利率明显高于字节，专家估计字节推理业务毛利率约为10%多。

b) 阿里Token成本优势来自哪里？
