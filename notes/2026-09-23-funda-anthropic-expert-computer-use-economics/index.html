核心摘要

  • Astra性能提升的三项驱动因素 — 该行业专家将Astra在计算机操作基准测试中的优势归因于面向工具使用的强化学习和后训练增加、据称可减少上下文窗口限制及外部推理Token反复输出的循环式变换器架构，以及提升推理服务算力效率的算法工作。
  • 计算机操作属于过渡性架构 — 该行业专家认为，当前形态只是临时方案，因为模型需要反复处理视觉渲染结果、将图像转换为文本、推理操作并控制虚拟鼠标。其预计，应用程序编程接口、代理间通信协议和模型上下文协议最终将取代其中大部分流程。
  • 浏览器流程的高Token成本 — 据该行业专家估计，一次浏览器操作可能消耗2万多个Token，包含10次点击的流程可能达到20万个Token；按每100万个Token约25美元的典型价格计算，后者成本约为5美元。复杂的推理或研究流程可能消耗100万个甚至更多Token。
  • Anthropic面向企业的差异化定位 — 该行业专家将Anthropic在计算机操作方面相对同业较弱的表现归因于战略选择，而非基础能力差距。其称，Anthropic优先关注软件工程、金融、法律、生命科学和安全，并且比大众消费者浏览器自动化更重视企业接口、应用程序编程接口和模型上下文协议。
  • 企业身份与访问控制障碍 — 据该行业专家判断，代理通过网站点击并冒充人类，会带来安全、隐私、数据主权及数据驻留问题。其提到Amazon已阻止Muse浏览其网站，并认为更广泛的企业采用需要独立的代理身份、基于角色的访问控制及授权委托。
  • 当前节省时间的能力有限 — 该行业专家表示，现有系统仍处于早期阶段，需要大量人工参与，对于用户熟悉的流程，速度可能慢于人工操作。其认为，代理在跨陌生网站开展开放式研究时可能表现更好，并可能通过强化学习逐步改进。
  • JEV的潜在贡献较为有限 — 该行业专家认为，JEV属于二元或概率型决策模型，可能承担一小部分底层选择，但任务拆解和调度仍需依赖LLM。其估计，这一细粒度环节在整个计算机操作流程中的占比远低于5%，对应的LLM工作时间少于5秒，因此只能带来非常有限的算力效率改善。
  • 蒸馏风险存在但总体有限 — 可见的计算机操作状态机具有较强的结构性和确定性，因此点击行为可能被复制；但该行业专家表示，隐藏的推理轨迹、任务拆解、用户界面定位和安全判断使完整能力蒸馏较为困难。其更看好同策略蒸馏，并称OpenAI和Anthropic限制展示思考Token及思维链后，异策略蒸馏的可行性进一步下降。
  • 高端模型的推理经济性 — 该行业专家称，GPT-6、Fable 5或Fable 5.1等高价模型的定价约为每100万个输出Token50美元，而Haiku约为5美元。其判断，低价模型的利润率最低，中型模型更高，最昂贵模型的利润率极高，但后者的Token用量仍然有限。
  • 处于早期阶段的定制芯片计划 — 据该行业专家称，Anthropic曾公开表示正在组建内部团队并与合作伙伴开展工作，但相关计划仍处于非常早期的阶段，首款芯片通常需要2年以上才能成熟。其认为，获取更多算力、降低对下游架构的依赖以及推进软硬件协同设计是主要动因，并判断公司很可能寻求外部后端合作伙伴。
  • 未提供精确比例的云端算力排序 — 据该行业专家估计，Anthropic的算力通常分布在Google、Amazon和Microsoft，其中Google占比最大，Amazon次之，Microsoft再次之。其未给出具体百分比。
  • 单芯片吞吐量差异较大 — 在模型规模、上下文窗口、批处理和配置等条件约束下，该行业专家估计，Kimi K3等超大模型约为每秒20-40个Token，700亿参数模型约为每秒2千个Token，80亿参数模型约为每秒1万-2万个Token。若运算完全位于高带宽内存内且不将键值缓存卸载至外部，其估计低价模型可达到每秒1.5万-2万个Token，而最大型模型约为每秒10-50个Token。

关键要点

  • 基于协议的自动化更可能成为企业路径 — 该行业专家的核心观点是，企业自动化将从视觉点击转向应用程序编程接口、代理间通信和模型上下文协议，因为仅一次点击就可能消耗2万多个Token。
  • 计算机操作差异主要源自战略选择 — Anthropic的相对定位与其专注五大企业垂直领域及端到端工具集成有关，而面向消费者的模型提供商在浏览器自动化方面投入更多。
  • 大众消费者规模化的经济性面临挑战 — 包含10次点击的浏览器流程可能消耗20万个Token，并按所述价格产生约5美元成本；该行业专家同时认为消费者业务的利润率有限。这一组合构成其质疑当前计算机操作方式能否广泛扩展的主要依据。
  • 隐藏推理构成更可防御的能力层 — 尽管可见的点击、输入和滚动操作形成了确定性状态机，但该行业专家认为，未公开的任务拆解、推理及安全判断使完整蒸馏较为困难。
  • 高端定价与有限用量并存 — 所述高端模型输出Token价格约为Haiku的10倍，而参数量并未相应增加10倍，这支持了该行业专家关于高端模型利润率更高的判断；但其同时提醒，这些模型的实际用量有限。
  • 定制芯片属于长期战略项目 — 该行业专家认为，该计划有助于保障算力并推进软硬件协同设计，但其估计首款芯片通常也需要2年以上才能成熟，且Anthropic的相关工作仍处于非常早期的阶段。
  • 推理经济性无法由参数量简单推导 — 在所述内存条件下，最大型模型与低价模型的吞吐量估计分别为每秒10-50个Token和1.5万-2万个Token；但该行业专家强调，批处理、延迟目标、上下文窗口和应用场景使吞吐量与参数量之间不存在固定比例关系。

以目前的发展方式来看，“电脑使用”是非常暂时的。首先，它在 Token 效率上非常低下。想想看：当你访问一个网站时（比如 economictimes.com），浏览器接收代码并将其渲染成网页；如果让大语言模型或 AI 去到处点击，它就必须截取画面、将图像转化为文本、进行决策，然后再用鼠标去模拟点击。这种方式在 Token 消耗和时间效率上都极其低下。这对普通消费者来说或许行得通，但对企业来说并不太适用。企业真正需要的依然是 API，因此“电脑使用”只是一种短期过渡方案。 这正是 OpenClaw 原本想做的事。而像 GPT-6、Muse 或 Rockbot 这些厂商所做的，只是把类似 OpenClaw 的环境搬到了云端提供给所有人，让你无需在本地手动运行或部署。更重要的是，他们借此留存了你的数据——你在买什么、你的支付网关、你的个人偏好等。 Anthropic 对这种模式不感兴趣。我认为“电脑使用”只是暂时的。随着网站越来越先进并普及 API、智能体间（A2A）通信协议或 MCP 协议，最终会逐渐不再采用这种模式。面对算力短缺以及大众用户的大规模普及，“电脑使用”这种方式根本无法扩展。

EX

Expert · Executive

并不总是成正比，因为这很大程度上取决于你所服务的企业业务类型。在推理方面，从芯片中挖掘算力潜力的方式有很多，但关键在于根据目标进行调优。推理的核心目标是优化首个 Token 延迟（TTFT）和 Token 之间的延迟（TBT）等指标。实现这一点本身并不算难，关键在于要付出多大的成本来实现。因此，这本质上是一场推理单元经济效益（unit economics）的博弈。通过调整批处理大小（batch size）——增加或减少——你可以服务更多的用户，但满足延迟指标就会变得非常具有挑战性。 我的观点是，如果你使用的是 Haiku 这一类模型，通常用于语音代理（voice agent）等场景，要求延迟极低，因此需要分配更多的算力来保证其实用性。而对于极其复杂或更大的模型，比如 Fable 等，并没有那种任务关键型的实时延迟要求，因为使用它们是为了获得高智能水平，而不是为了快速生成 token 或超高速推理。在这种情况下，重点在于模型能力，应用场景更多是长跨度上下文窗口等非时间敏感型任务。因此，你可以专注于提高计算效率和经济效益，而不是单纯去压低延迟。总而言之，这里有非常多的可调参数和变量，而不是一个简单固定的对应关系。
