AIDC与Neocloud高频数据追踪功能会议纪要

1. AIDC与Neocloud页面定位及数据覆盖

a) 论坛页面新增了哪些数据追踪功能，二者是什么关系？

  • 论坛新增两个高频数据追踪页面：
  1. AIDC项目页面：追踪AI数据中心项目的规划、建设、并网、交付及延期情况。
  2. Neocloud页面：追踪GPU算力租赁价格、园区交付、合同、融资风险、估值及收入预测。
  • 两个页面需要结合使用：
  1. AIDC页面主要判断数据中心供给何时上线、是否延期。
  2. Neocloud页面进一步分析供给变化如何影响算力租赁价格、合同价格、融资成本及公司收入。
  • 页面以展示内部自行追踪的高频数据为主，并在底层数据基础上进行驱动因素拆解和预测分析。

b) AIDC项目数据覆盖哪些范围？

  • 数据完全由内部团队采集，主要覆盖近两年新增的AIDC项目。
  • 地域上以北美项目为主，同时包括部分其他海外项目及海外大型科技公司的项目。
  • 重点采集近两年的原因包括：
  1. 美国缺乏全国统一的数据中心申报机制，历史项目难以完整统计。
  2. 许多历史数据中心较为老旧，难以兼容新一代AIDC架构和新一代GPU。
  3. 新一代AIDC项目通常需要先确定土地，并向地方政府提交土地用途、规划栋数、占地面积、规划功率及并网节奏等信息，因此可追踪性更强。

c) 什么阶段的项目可以纳入AIDC统计？

  • 项目仅有投资意向或新闻报道，但尚未取得土地、未提交土地相关申报的，不纳入有效统计。
  • 纳入统计的项目至少需要进入取得土地或提交土地规划申报的阶段。
  • 当前全美抓取到的项目超过1,000个，其中约700—800个项目能够提供有效数据并进入统计。
  • 对仍处于意向阶段的项目，可以根据其申报计划进行初步测算，但会采用相应的估算口径，并在项目页面中披露具体信息。

2. AIDC数据来源、采集内容与处理方法

a) 数据中心项目信息主要来自哪些渠道？

  • 主要数据来源包括：
  1. 地方政府及县级政府的土地、建设、空气许可、柴油机许可和并网申报文件。
  2. 大型媒体及地方媒体对项目申报和建设进度的报道。
  3. 数据中心行业垂直媒体及专门追踪AIDC项目的网站。
  4. 数据中心企业官方网站和公告。
  • 企业信息来源主要覆盖三类主体：
  1. CSP云服务商，如Meta等大型科技企业。
  2. Vantage等专业数据中心开发商和连锁数据中心运营商。
  3. Neocloud算力基础设施企业。
  • 不同企业的信息披露完整度差异较大，部分企业会公布项目列表和建设进度，部分企业则基本不披露，因此需要结合政府文件及媒体信息进行补充。

b) 具体采集哪些项目信息？

  • 采集内容主要包括：
  1. 项目投资方、立项方和开发商。
  2. 建设地点、土地规模、建筑面积及规划栋数。
  3. 数据中心规划功率和预计上线规模。
  4. 预计开工、完工及上线时间。
  5. 租户、合作方及潜在客户。
  6. 土建投资金额。
  7. 并网方式、接入变电站及相关电网协议。
  8. 是否计划采购设备建设自有微电网。
  9. 设备进场、项目封顶、延期或取消等建设进度。
  • 项目金额主要指土建相关金额，通常不包括GPU、内存等IT设备支出。

c) 获得原始信息后如何处理？

  • 第一步是进行项目去重和归一化：
  1. 同一项目可能被多家媒体重复报道。
  2. 政府申报文件可能多次修改。
  3. 项目可能因原址无法推进而更换建设地点，但本质上仍是同一个项目。
  4. 部分项目属于已有园区的扩建，需要避免重复计算。
  • 第二步是统一功率统计口径：
  1. 区分IT侧功率和中压侧功率。
  2. 将不同项目统一换算为兆瓦或吉瓦口径。
  3. 按年度或季度拆分项目可能的上线节奏。

d) 对未披露年度上线计划的项目如何测算？

  • 约三分之二以上的项目未明确披露每年的上线规模，需要内部进行拆分测算。
  • 主要测算依据包括：
  1. 申报建筑面积。
  2. 规划建设栋数。
  3. 预计开工、上线和完工时间。
  4. 项目类型及开发主体。
  5. 并网申报节奏。
  • 新一代AI数据中心的建筑面积与可容纳机柜数量之间通常存在较稳定的比例。
  • 单个标准建设单元的规模通常约为20—30MW，大型郊区园区可能将多个建设单元连接在一起。
  • 不同项目主体的建设节奏存在差异：
  1. CSP自建项目的建设节奏通常相对稳定，会按照既定规划逐栋上线。
  2. 第三方开发商在租户尚未完全确定时，通常先建设两栋，后续根据租户情况建设第三栋、第四栋。
  3. 需要并网的项目还受到当地电网扩容、设备升级和采购节奏的制约。
  • 对仅披露预计上线及完工时间的项目，会结合建筑面积、规划栋数和建设周期，测算每年或每季度可能上线的功率。

e) 如何验证项目测算结果？

  • 主要采用两类交叉验证方式：
  1. 新闻及项目方进度跟踪：持续追踪设备进场、主体封顶、延期、暂停或取消等信息。
  2. 卫星图像验证：观察项目现场是否已开始土建，以及实际进度是否明显落后于计划。
  • 虽然卫星图像通常存在数月滞后，但数据中心从土建到变压器等设备采购本身需要较长周期。如果项目临近计划上线时间，卫星图像仍显示为荒地，基本可以判断项目已经延期。

3. AIDC项目延期监测及美国市场判断

a) 当前AIDC页面重点关注哪些问题？

  • 当前分析重点是项目延期和交付，而不是按州或政策进行静态分类。
  • 页面重点展示：
  1. 每个项目的建设主体和所在地区。
  2. 项目规划规模及测算方式。
  3. 原始申报材料和相关新闻。
  4. 预计上线窗口及实际建设进度。
  5. 延期原因及其可能影响的设备采购需求。
  • 页面当前以美国市场为重点，后续将继续补充其他海外市场。

b) 2026年美国AIDC项目的延期情况如何？

  • 根据当前测算，原计划于2026年上线的美国项目规模为13GW以上。
  • 其中：
  1. 约3GW可能延期。
  2. 约4GW基本确定能够上线。
  3. 约6GW仍处于等待确认状态。
  • 若按季度平均计算，整体规模约为每季度3GW，但实际交付会因项目建设和并网节奏而不均匀分布。
  • 对可能延期的约3GW项目，页面会逐一列出：
  1. 项目名称。
  2. 原计划上线窗口。
  3. 当前实际进度。
  4. 延期判断依据。
  5. 具体延期原因。
  6. 可能受影响的设备及采购需求。

c) 延期分析采用什么统计口径？

  • 延期主要包括两种情形：
  1. 已有明确新闻或项目方公告说明项目延期。
  2. 项目当前实际进度与原计划上线时间存在明显差距。
  • 实际进度的判断依据包括：
  1. 土地及建设申报进度。
  2. 设备进场和土建进度。
  3. 卫星图像显示的现场情况。
  4. 项目方、地方政府和媒体披露的信息。
  • 已彻底暂停或取消的项目不计入“延期”统计，而会从延期口径中剔除并单独处理。
  • 每个项目的原始资料、延期原因和判断依据均可在页面中点击查看。

4. Neocloud算力租赁价格监测体系

a) Neocloud页面的数据主要来自哪里？

  • 页面主要采集GPU算力租赁的公开报价，并结合第三方数据源进行对照。
  • 主流第三方数据来源包括：
  1. Silicon Data。
  2. SemiAnalysis。
  • 按需租赁价格当前主要展示Silicon Data数据，原因是其覆盖面和更新频率相对更高。
  • 内部还会自行爬取按需、合同和可抢占报价，与第三方数据进行综合比较，用户可在页面中切换不同数据来源和价格类型。

b) 算力租赁报价分为哪些类型？

  • 公开GPU报价主要可归纳为三大类、四种形式：
  1. 按需报价（On-demand）：无需签订长期合同，可直接租用空闲算力。
  2. 合同报价：进一步分为短期合同和长期合同。
  3. 可抢占报价（Spot Price）：利用短期空闲资源，可能被中断，价格通常最低。
  • 不同报价反映的市场信息不同：
  1. 按需报价最能反映短期供需变化。
  2. 短约价格反映阶段性供需紧张程度。
  3. 长约价格当前更多反映数据中心建设、融资和运营成本。
  4. Spot价格主要反映可被临时调用的闲置资源情况。

c) 页面如何形成不同GPU型号的价格指数？

  • 内部会按照不同GPU型号持续收集报价。
  • 基于大规模报价样本，分别计算：
  1. 按需报价指数。
  2. 短期合同报价指数。
  3. 长期合同报价指数。
  4. Spot报价指数。
  • 页面支持按GPU型号、报价类型和合同期限进行切换。
  • 重点监测短期价格上涨是否开始向长期合约价格传导；目前尚未观察到明确传导证据。

5. ABCD监测、归因与预测框架

a) ABCD框架的主要功能是什么？

  • ABCD框架主要承担四类功能：
  1. 监测GPU租赁价格的实时走势。
  2. 拆解价格变化的可能来源。
  3. 判断短期价格变化是否向长期合同传导。
  4. 基于供需、价格和市场叙事预测未来变化。
  • 高频数据每日刷新，短期波动较大，因此相关结论也会动态调整。

b) 如何拆解近期价格波动的驱动因素？

  • 系统会识别近期具体由哪些供应商调价，例如RunPod等。
  • 同时进一步分析调价背后的客户需求，判断是否与OpenAI、Cursor或其他客户有关。
  • 重点拆解的驱动因素包括：
  1. 供应商主动调价。
  2. 短期数据中心供给变化。
  3. 总体算力需求变化。
  4. 新一代GPU迁移和型号切换。
  5. 数据中心项目延期。
  6. 不同区域和供应商之间的资源错配。
  • 除价格数据外，还会收集研报、社交媒体及新闻观点，对不同驱动因素进行评分，从而判断最近数日或一周价格变化的主要来源。

c) 页面如何判断价格变化能否持续？

  • 完成驱动因素拆解后，会对相关因素进行线性外推。
  • 分析会结合市场叙事进行动态调整。
  • 当前主要判断是：
  1. 短期价格主要由供需关系决定。
  2. 数据中心上线延期会减少短期供给，从而推动短约或按需价格上涨。
  3. 短期供给不足并不意味着长约价格一定同步上涨。
  4. 长约价格更多取决于建设成本、利率、通胀及融资成本。

6. Neocloud园区交付、合同与融资风险分析

a) 园区交付页面主要展示哪些内容？

  • 页面按Neocloud公司拆解其各个数据中心园区，包括：
  1. 各园区未来季度可能交付的项目。
  2. 项目交付规模。
  3. 预计上线功率。
  4. 已被协议或客户锁定的资源。
  5. 可能释放至按需市场的资源。
  6. 可能延期的项目及原因。
  • 底层逻辑与AIDC项目页面一致，均采用项目级自下而上的跟踪方法。

b) 如何从自上而下角度验证供需规模？

  • 除项目级拆解外，还会根据全球GPU整体出货量，测算每个年度所需的数据中心功率。
  • 由于部分GPU出货数据只能按年度拆分，因此会先按年度测算，再平均或结合交付节奏分配至各季度。
  • 随后将GPU出货所需功率与实际可上线的数据中心功率进行比较，从而判断：
  1. 算力供给是否充足。
  2. 哪些季度可能出现供给缺口。
  3. 短约价格是否存在上涨压力。
  4. 部分园区资源是否可能从长约转向按需市场。

c) CDS数据如何用于分析Neocloud融资风险？

  • 页面采集金融市场CDS及信用利差数据，并以大型CSP的信用水平作为基准。
  • 若市场认为企业违约风险较低，信用利差通常约为40—50bp。
  • Oracle、CoreWeave等部分公司的信用利差可达到400bp以上，明显高于低风险主体。
  • 信用利差每增加100bp，大致对应融资利率上升1个百分点，可能显著提高大型数据中心项目的融资成本。
  • 当前Neocloud融资的核心逻辑是：
  1. 若企业依靠自身信用融资，融资成本可能较高。
  2. 若企业能够与Microsoft、Meta等高信用主体签订长期合同，则合同可形成信用支持。
  3. 金融机构会结合合同对手方信用，决定是否提供融资以及融资定价。
  • 页面会持续更新CDS和信用利差，并分析其对融资成本、项目交付及公司估值的影响。

d) 估值分析采用什么方法？

  • 估值分析主要观察信用利差、GPU租金、园区交付及合同变化的历史走势。
  • 在底层因素持续存在的假设下，对未来几个季度的估值变化进行线性推演。
  • 分析以公司间横向比较为主，判断哪些公司在以下方面表现相对更好：
  1. 融资成本。
  2. 园区交付能力。
  3. 长期合同质量。
  4. 短期资源变现能力。
  5. 信用风险和违约风险。

7. 短约、长约价格及季度收入预测

a) 短约价格如何预测？

  • 首先测算美国及全球GPU出货量对应的数据中心功率需求。
  • 当前假设约75%的相关芯片运往美国，再将美国芯片出货所需功率与各季度预计能够上线的功率进行比较。
  • 如果所需功率超过实际可上线功率，意味着短期算力供给偏紧，短约价格可能上涨。
  • 当前对延期项目的处理方式是：
  1. 根据实际进度将项目向后顺延一个或两个季度。
  2. 如果项目持续延期，则继续动态调整。
  3. 如果项目被直接取消，则不再简单向后顺延，而是从供给中剔除。
  • 在此基础上，以当前短约价格为基准，根据季度供需缺口推算未来价格涨跌幅。

b) 长约价格如何预测？

  • 目前尚未看到短约价格上涨向长约价格传导的明确证据。
  • 因此长约价格仍以成本端为主要定价依据，重点考虑：
  1. 数据中心建筑成本。
  2. 利率成本。
  3. 通货膨胀。
  4. Neocloud公司的融资成本。
  5. 长期合同对融资信用的支持作用。
  • 当前判断是，数据中心延期导致的短期价格上涨不能直接推导出长期合约价格同步上涨。
  • 长约价格暂按建设成本、利率和融资成本的线性变化趋势进行推算。

c) 各公司季度收入如何计算？

  • 收入预测基于自下而上的园区交付数据，主要步骤包括：
  1. 拆分每家公司每季度能够上线的功率，即可出租供给。
  2. 根据历史合同结构，估算可用于长约和短约的资源比例。
  3. 分别预测短约价格和长约价格。
  4. 结合可出租时长，计算各类资源的租赁收入。
  5. 汇总得到每家公司每季度收入。
  • 核心公式可概括为：

提问者：请介绍论坛页面新增的AIDC和Neocloud数据追踪功能，以及相关数据的统计口径和采集方法。

回　答　者：论坛页面新增了2个数据追踪功能，分别是AIDC和Neocloud，主要用于展示我们自行追踪的高频数据，并进行基础分析。这2个页面需要结合查看。这2个页面中，1个是AIDC项目页面，1个是Neocloud页面，二者存在关联。

AIDC项目数据完全由我们内部采集，覆盖近2年新增的AIDC项目，以北美项目为主，也包括部分海外项目及海外大厂的项目。

从统计口径和方法来看，新建AIDC项目从立项开始，首先需要申请建设许可。历史AIDC项目难以统计，因为美国全国没有统一的申报机制，只有弗吉尼亚州北兰登县和德克萨斯州建立了AIDC，即大规模数据中心的申报机制。其他历史数据中心则需要依靠空气许可、柴油机许可等数据进行推算。

许多历史数据中心已经较为老旧，与新一代AIDC不太兼容，也无法安装新一代GPU。因此，我们采集的新闻时间范围主要集中在过去2年。之所以从过去2年开始，是因为新一代AIDC项目在土建前首先需要确定土地，并向当地政府申报土地用途和规划。规划中需要写明大概要建设几栋楼、占地面积多大，更详细的内容还包括大概要上线多少兆瓦。如果需要申请并网，还要申报上线兆瓦数及相应节奏。

我们的做法是采集所有此类信息。1类来源是地方政府每个县的申报文件。当出现新的申报文件或原有文件发生修改时，地方媒体通常会进行报道，部分数据中心垂直网站也会转载相关报道。另1类来源是知名数据中心企业的官方信息。

知名数据中心企业主要分为3类：1类是CSP；1类是Vantage等专门从事数据中心及连锁数据中心业务的企业；还有Neocloud企业。这些企业会在官网发布部分信息。例如，在CSP企业中，Meta会发布部分数据中心列表及项目进展，但不同企业的发布情况并不一致，有些会发布，有些不会发布。

数据来源基本包括上述几类，其中1类是企业官网自行公布的信息，另1类是地方政府申报文件及相关媒体报道。

提问者：数据中心项目信息主要来自哪些渠道，具体包含哪些内容？获得这些信息后，如何进行处理和测算？

回　答　者：信息来源主要包括大型媒体报道、地方政府申报文件、地方垂直媒体报道，以及专门追踪AIDC的垂直类媒体报道。我们的做法是汇集这些信息，并提取其中与数据中心相关的内容。

这些内容主要包括项目投资方、立项投资方、开发商、建设地点、规划用地规模，以及计划建设的数据中心规模。部分信息还会涉及采购情况，例如数据中心准备采用并网方式，还是采购设备建设自有微电网，或者与本地哪些变电站签订了协议。

综合来看，这些信息包括开发商，部分项目还包括租户、合作方、土建相关金额、项目规划、预计上线时间、预计开工时间、预计完工时间，以及本地可能采用的并网方式。相关金额主要为土建金额，基本不包括IT设备，即GPU和内存等设备的金额。

获得这些信息后，我们主要进行2步处理。第1步是去重，因为其中存在大量重复信息，而且申报文件经常发生变化。如果项目在当前地点无法推进，可能会更换建设地点，但仍属于同1个数据中心项目。此外，还有部分项目属于原来172737的扩建，因此需要进行去重处理。

另1步是统一吉瓦数的统计口径，包括IT功率数和中压侧吉瓦数，并按年度拆分项目的上线节奏。部分项目会明确说明目标规模是1吉瓦还是500兆瓦，以及具体的上线节奏；但超过约2/3的项目没有说明，需要由我们自行拆分测算。

测算方式主要基于新时代面向AI的数据中心特征，可以统计其建筑面积和栋数。1个cube的规模差不多是2、20兆瓦到30兆瓦。如果位于荒郊野外，大型数据中心可能会将多个cube连接在一起。每个cube内采用英伟达机器的占地面积是固定的。

像城市里的这种2、1栋2、20、20兆瓦、30兆瓦的数据中心，以前都属于超大规模数据中心，现在已经成为标配，基本上都采用类似的构成方式。因此，我们可以统计建筑面积和栋数，因为建筑面积与可容纳的机柜数量之间基本保持稳定比例。

在栋数方面，如果是CSP项目，建设节奏通常较为平稳。例如，1个园区规划了10几栋，就会按照既定节奏逐步上线。如果是第3方开发的项目，由于初期租户没有那么确定，一般会先上。

回　答　者：项目通常先建设2栋，后续根据租户情况再建设第3栋、第4栋。如果需要并网，项目节奏还需向当地电网申报。当地电网会根据项目每年预计规划上线的吉瓦数，制定电网设备升级、投资和采购规划。

我们的第2步处理方式是，对于未提供每年上线计划、仅披露预计上线时间和预计完工时间的项目，根据其申报的建筑面积、规划栋数及申报的建设节奏，拆分测算每年可能上线的吉瓦数。

我们还会通过2种方式进行交叉验证。1种是持续追踪新闻，因为部分新闻或项目方会披露数据中心的建设进度，例如设备是否进场、项目是否封顶等；部分数据中心也会披露项目延期或取消的情况。另1种是利用卫星图像判断建设进度是否明显落后。

虽然卫星图像存在几个月的滞后，但从土建到采购变压器等各类设备，本身也需要较长时间。如果项目方公布了计划时间，即使考虑卫星图像的滞后，当前仍显示项目所在地为荒地，基本可以判断项目已经延期。

这基本上就是我们研究数据中心建设数据的方法。整个页面采用平铺方式展示数据，我们会根据每次研究重点调整核心结论。此前也会按照州、电力设备等维度进行划分，但州层面的情况涉及不同政策。目前特朗普和共和党主要支持在共和党执政、支持天然气等能源的州建设项目，下一届政府的情况可能有所不同，但这并不是当前重点。现阶段的重点仍是项目延期和交付问题。

当前页面虽然采用平铺方式展示，但核心需要关注2个方面。1个方面是每个具体项目，包括项目主体、所在地区、测算方式，以及相关原始材料和资料。
