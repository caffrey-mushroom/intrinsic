1. GSK现有生成式AI工具与应用场景

a) GSK内部主要使用哪些大语言模型工具？

  • GSK内部主要有两类大语言模型工具：
  1. JGG：主要用于非研发场景中的简单业务文档分析及翻译。由于公司内部不允许使用外部翻译软件，JGG承担了部分内部翻译需求。
  2. Jules：主要面向研发员工开放，保密性较高，并预设了大分子生物、小分子化学等不同研发领域的提示词。
  • Jules目前没有连接公司内部业务文档、实验数据或既有知识库，因此更接近面向研发人员的通用交互式AI工具，尚未形成与内部研发体系深度融合的知识平台。
  • 受访者作为使用者了解相关工具，但不清楚其后台使用的具体模型、硬件及推理基础设施。

b) 编程与数据科学工作中如何使用AI？

  • 数据科学团队主要使用以下平台和工具：
  1. Databricks：用于编写SQL、提取数据、进行基础分析并制作仪表板。
  2. VS Code及Copilot：主要用于Python、R代码开发，Copilot可在模型构建过程中辅助编写和修改代码。
  3. GitHub及Copilot：用于代码和模型的版本控制及同步。由于部分员工不熟悉Git相关语法，会使用Copilot辅助完成代码提交与同步。
  • 现阶段AI在编程中的主要作用仍是解决相对具体的代码或语法问题，尚未普遍参与整个机器学习项目的思路设计和模型决策。

c) Teams中的AI应用有哪些？

  • Teams内集成了Copilot，主要功能包括：
  1. 查询和回顾Teams中讨论过的工作内容。
  2. 对会议转录文本进行信息提取和分析。
  3. 在会议结束后自动生成会议摘要。
  • 当前流程仍存在延迟：
  1. 会议结束后通常需等待约3—5分钟才能获得Transcript。
  2. 将Transcript交给Copilot总结，还需额外约2分钟。
  • 当员工全天连续参会、会议之间没有空档时，往往只能等当天会议全部结束后再统一处理会议内容，实时性不足。

d) 实验报告自动生成工具如何应用？

  • 实验人员完成实验后，会将实验数据上传至数据库。
  • 过去需要人工提取既有实验报告模板，再将新数据逐项填入。
  • 部门后来开发了较为简单的AI应用，新实验数据产生后可自动生成实验报告。
  • 该场景能够显著减少重复性人工工作，但由于报告格式相对固定，主要是模板化数据填充，对复杂推理和大规模算力的需求较低，因此并不是快速推理价值最大的方向。

e) GSK是否使用Cerebras开展表观基因组学、蛋白质结构预测和小分子生成等工作？

  • 受访者看到的相关管线包含表观基因组学模型、蛋白质结构预测、小分子生成与优化等应用。
  • 前两个方向更偏基础研究，第三个属于小分子开发，而受访者此前主要从事大分子开发，与相关部门没有直接联系。
  • 因此，受访者无法确认GSK是否实际使用Cerebras服务开展上述项目，也没有在此前工作中直接接触相关应用。
  • 对于公司内部AI工具，受访者仅能从最终用户角度评价使用体验，无法确认其底层是否使用Cerebras或其他快速推理服务。

2. 快速推理在医药研发中的潜在应用

a) 快速推理可应用于哪些核心研发场景？

  • 受访者基于现有AI应用，归纳出以下潜在方向：
  1. 大分子药物发现。
  2. 常规实验设计及资源、人员分配。
  3. AI辅助实验仪器监测和实验室自动化。
  4. DOE（Design of Experiment，实验设计）。
  5. Design Space建模与最优工艺参数搜索。
  6. 机器学习模型开发和迭代。
  7. 内部历史实验报告、知识与数据的检索和交互。
  8. 大规模文件提取与翻译。
  9. Teams会议实时转录与总结。
  • 在上述场景中，快速推理的价值主要来自三类需求：
  1. 高实时性：如会议转录、实时摘要和交互式问答。
  2. 高交互频率：如机器学习模型开发、假设迭代和项目反馈。
  3. 大数据量或大运算量：如Design Space搜索、历史知识库查询和药物发现。

b) 快速推理对大分子药物发现有什么潜在价值？

  • 大分子药物发现主要是寻找合适的分子、生成指定抗体并完成初步筛选，再将候选分子交给后续开发部门。
  • 该方向涉及较大的运算量和较多初步实验，理论上适合使用快速推理提升候选分子生成、筛选和优化速度。
  • 受访者并非药物发现部门人员，因此仅能确认该方向具有潜力，无法量化具体效率提升或商业价值。
  • 从行业趋势看，英伟达、OpenAI等公司对AI制药的重点设想主要集中在Drug Discovery，因为相较于后端研发和生产环节，该方向更可能较快展现阶段性成果。

c) 快速推理如何支持DOE和Design Space？

  • DOE用于设计日常实验。实验并非完全按照固定流程执行，需要根据变量、目标和约束进行实验组合设计。
  • Design Space则是对工艺中的多维参数进行建模和优化，参数可能包括：
  1. 温度。
  2. 湿度。
  3. 液体加入量。
  4. 固体加入量。
  5. 其他工艺变量。
  • 例如，在一个四维空间中，已有约20个实验数据点，但整个候选空间中可能存在100—500个待推理点。模型需要从中找到产量和产品质量综合最优的参数组合。
  • 快速推理的价值包括：
  1. 协助构建和完善Design Space模型。
  2. 加速对大量候选参数组合的预测和筛选。
  3. 当模型应用于不同大分子或小分子对象时，加快重新训练和重新预测。
  • 该场景的核心特征是计算量较大，并且模型需要在不同对象和实验条件下重复训练、推理。

d) AI辅助实验仪器监测与实验室自动化的价值是什么？

  • 截至受访者离职时，GSK在Development阶段开展的实验仍以传统人工方式为主，实验人员需要进入实验室并操作仪器。
  • 行业内较先进的实验室已开始采用机械臂和机器人执行完整实验流程，减少人员直接进入实验室的需求。
  • AI可用于：
  1. 监控实验仪器状态。
  2. 控制机械臂和机器人。
  3. 识别实验异常并及时调整。
  4. 协调实验步骤和资源。
  5. 支持Lab Automation体系建设。
  • 这一场景对实时响应和推理速度要求较高，快速推理有望提升自动化实验的执行效率，同时节省大量实验人员成本。
  • 受访者认为，中国部分CRO公司，如药明生物，可能已在实验室自动化方面取得较大进展，但无法确认其是否使用快速推理服务。

e) 将AI连接历史实验数据和知识库有什么价值？

  • 当前面向研发的AI工具尚未连接内部Lab Report、历史实验数据和既有知识。
  • 若将AI与历史数据连接，并结合RAG等技术，可形成面向Lab Scientist的交互式知识平台，使研究人员能够：
  1. 一边提问，一边迭代实验假设。
  2. 调取历史实验结果和报告。
  3. 比较不同项目和实验条件。
  4. 自动整合不同来源、格式的数据。
  • 该场景可缓解药企人员流动造成的知识断层：
  1. 员工离职时，个人知识通常无法完整传递给继任者。
  2. 新员工可能只接收到部分经验，其余知识沉睡在数据库中。
  3. AI可以持续提取、组织并复用历史知识，提高知识连续性。
  • 不同实验仪器产生的数据在格式和来源上存在差异，过去依赖人力难以完成全面整合；AI可以构建更完整的知识管理体系。
  • 这一场景的数据量可能比单一建模场景大多个数量级，因为模型开发可能只使用海量数据中的约1%，而企业知识平台需要覆盖尽可能完整的历史数据。
  • 受访者认为，现有AI的处理速度可能难以满足该需求，快速推理有望显著提升检索和交互效率，并降低不同部门间的信息壁垒。

3. 快速推理的效率提升与降本增效价值

a) 用户是否能感受到当前模型推理速度的差异？

  • 从普通用户角度看，GSK内部交互式AI与公司外常用的AI产品体验没有特别明显的区别。
  • 如果与专门的快速推理服务相比，内部工具的速度可能明显偏慢。
  • 在代码开发场景中，员工通常只是基于已有Script或大型模型询问部分代码问题，任务复杂度不高，因此速度暂时不是主要瓶颈。
  • 推理速度的价值更明显地体现在交互式AI、实时会议处理、复杂建模和大规模知识检索等场景。

b) 快速推理如何改善大规模文件提取与翻译？

  • GSK部分部门曾与中国CRO公司合作，相关材料来源复杂，包括：
  1. PDF文件。
  2. 纸质手写报告的扫描件。
  3. 其他非结构化业务文档。
  • 处理流程通常需要先进行OCR或文字提取，再完成翻译，有时还需要中文人员协助校对。
  • 即使已经使用AI，整个过程仍然耗时、耗力。
  • 如果快速推理可带来5—10倍的性能提升，其价值包括：
  1. 加快大批量文件的文字提取和翻译。
  2. 减少中文人员提供辅助的需求。
  3. 降低跨国合作中的非技术性沟通成本。
  4. 缩短文件处理和信息传递周期。
  • 受访者保守估计，快速推理至少可以将此类工作的处理时间缩短一半。

c) 快速推理如何改善Teams会议转录和总结？

  • Teams场景的核心诉求不是单次任务运算量特别大，而是要求结果能够快速、及时生成。
  • 理想状态下，快速推理可以实现：
  1. 会议进行到一半时，自动总结前半段内容。
  2. 会议接近结束时，会议纪要基本生成完毕。
  3. 会后立即向参会人员或管理层分发摘要。
  4. 减少员工在全天会议结束后集中整理内容的负担。
  • 该场景的核心特点是强实时性和持续输出，而不是会后批量处理。

d) 快速推理如何改善机器学习模型开发？

  • 过去使用Copilot时，数据科学家通常需要先自行形成模型开发思路，再让AI解决代码或编程语言层面的具体问题。
  • 快速推理服务可以推动AI从“代码助手”升级为“项目和模型助手”，帮助团队：
  1. 讨论和梳理模型开发思路。
  2. 分析应从哪些方向切入问题。
  3. 选择合适的机器学习模型。
  4. 对整体项目和模型结构提出建议。
  5. 根据反馈进行连续迭代。
  • 模型开发中，形成解决思路通常比编写代码耗费更多时间。传统迭代周期可能以月为单位，快速推理有望将其缩短至以周为单位。
  • 受访者以光谱、质谱峰值识别模型为例估算：
  1. 完全不使用生成式AI：形成初级模型版本可能需要1个月以上。
  2. 使用普通生成式AI：所需时间约为2周。
  3. 使用快速推理：有望缩短至1周以内。
  • 这一提升不仅来自代码生成提速，更来自思路形成、模型选择、反馈和交互式迭代效率的提高。

e) 快速推理对实验报告生成的价值有多大？

  • 实验报告主要根据固定模板自动填入实验数据，流程相对标准化。
  • 该场景不需要复杂逻辑推理或大量算力，普通自动化工具已经可以实现较好的效果。
  • 因此，快速推理对Lab Report生成的边际价值相对有限，是所讨论场景中应用空间最小的方向之一。

f) 快速推理能否直接带来收入增长？

  • 快速推理可以通过减少人工、缩短研发周期和提高工作效率实现降本。
  • 研发阶段距离最终商业化收入较远，增效很难直接等同于增加收入。
  • 对受访者此前所在部门而言，研发成果到收入体现之间可能至少存在以年为单位的时间差。
  • 因此，快速推理的早期价值应优先通过以下指标衡量：
  1. 节省的FTE或人工时间。
  2. 项目周期缩短幅度。
  3. 模型迭代次数和效率。
  4. 实验成功率或资源利用率。
  5. 知识检索和信息传递效率。
  • 药物发现等前端领域可能更早体现业务价值，但受访者无法提供具体量化判断。

4. GSK部署快速推理面临的挑战

a) 最大的开发挑战是什么？

  • GSK全球员工可能达到8万—9万人，业务横跨大分子、小分子和疫苗等多个方向。
  • 各研发方向及其细分领域之间通用性较弱，难以通过少量标准化AI工具覆盖全部需求。
  • 很多潜在场景需要同时理解AI技术和具体研发业务，但内部AI工程师未必具备足够深入的医药研发知识。
  • 一些小众业务方向可能因为尚未提出明确需求，或AI/ML团队资源尚未覆盖，而长期处于空白状态。
  • 受访者此前所在的大分子开发部门即未被公开提及的部分AI应用方向覆盖。

b) GSK内部AI人才规模和结构如何？

  • 受访者估计，GSK内部AI/ML相关部门整体约有100多人，但并非所有员工都从事生成式AI。
  • 从事生成式AI工作的人员可能为几十人，但该数字仅为受访者推测，无法确认。
  • 研发业务员工与生成式AI人员之间的比例可能达到几十比一，导致AI团队难以深入覆盖全部业务。
  • 招聘背景主要包括：
  1. 软件工程师。
  2. AI Engineer。
  3. Machine Learning Engineer。
  4. AI应用于Finance等职能方向的人才。
  5. 少量AI Ethics人才。
  • 招聘时会优先考虑有医药行业或特定研发方向经验的候选人，但更核心的要求仍是AI和机器学习能力。

c) 员工接受度和工具普及面临哪些问题？

  • 欧洲科技应用和数字化普及程度相较于中国、美国可能相对落后。
  • 医药研发领域存在较多长期从事同一工作的资深员工，更习惯沿用传统实验和工作方式。
  • 部分员工甚至难以熟练使用电脑，因此生成式AI工具的推广效果有限。
  • GSK的数据科学团队曾协助AI/ML部门开展推广，包括：
  1. 介绍内部AI工具及其使用方法。
  2. 开发小型Use Case。
  3. 在部门月度会议上演示AI如何处理真实数据。
  4. 展示不同提问方式可以得到的结果。
  • 尽管部分Use Case能够明显提升效率，员工整体普及率仍有较大提升空间。

d) 公司内部是否可以选择不同模型？

  • 受访者印象中，内部平台应该支持选择模型，但本人没有特别关注具体选择流程。
  • 其离职前平台中可能包含：
  1. GPT及GPT-4系列的不同版本。
  2. DeepSeek。
  3. Gemini的不同版本。
  • 受访者无法确认每个模型对应的具体使用范围及底层部署模式。

5. 生成式AI在GSK内部的推广和价值评估机制

a) GSK从何时开始系统推广生成式AI？

  • 公司大约从2024年下半年开始推出多个内部AI工具，相关产品由AI/ML部门开发。
  • 推广过程主要包括：
  1. 举办线上宣讲会。
  2. 面向全公司发送培训邮件。
  3. 安排统一时段，培训员工使用内部AI工具。
  4. 由各业务部门的技术团队进行二次推广和本地化演示。
  • 在受访者此前所在部门，Data Science团队因技术能力较强，被部门领导安排协助推广。

b) 业务部门如何判断AI工具是否有用？

  • 部门领导会通过以下渠道了解工具价值：
  1. 与AI/ML部门管理层沟通。
  2. 参加公司高层会议或全员会议。
  3. 观看AI/ML部门展示的Use Case。
  4. 参考部门内部Data Science团队每月提供的案例。
  • 工具价值通常通过可量化的人工节省进行衡量。
  • 例如，实验报告过去需要一定数量的FTE完成，应用AI后可能减少至原来的约20%，即节省约80%的相关人工投入。
  • 对于研发AI项目，除FTE外，还可以用模型开发周期、实验时间和迭代速度评估效果。

c) 除实验报告外，还有哪些典型Use Case？

  • 光谱、质谱分析是一个较典型的案例：
  1. 光谱或质谱数据通常以时间为横轴、谱强度为纵轴。
  2. 需要识别数据中的峰值。
  3. 虽然人眼可以看到峰值，但仍需通过严谨模型实现自动检测。
  4. 团队使用AI辅助选择机器学习模型、编写代码并整理整体模型结构。
  5. 最终形成可用于后续实验的自动化分析模型。

6. 医药行业生成式AI的发展趋势

a) 不同药企的AI应用场景是否相近？

  • 药企之间最大的差异来自具体研究方向，而不是公司本身。
  • 如果不同公司的研究方向相同，行业交流通常较多，技术和应用进展也较为同步。
  • 因此，从公司整体层面看，不同头部药企的AI应用方向大体相近，主要集中在：
  1. Drug Discovery。
  2. 分子生成与优化。
  3. 实验设计和工艺建模。
  4. 数据分析与机器学习。
  5. 实验室自动化。
  6. 企业知识管理。
  7. 文档处理、翻译和会议总结。

b) 为什么头部科技公司更关注Drug Discovery？

  • OpenAI、英伟达等公司提出的AI制药设想主要集中于Drug Discovery。
  • 主要原因包括：
  1. 药物发现需要处理大量候选分子和实验组合，计算负荷较高。
  2. AI可以较直接地参与生成、筛选和优化。
  3. 相较于开发、生产和商业化等后端环节，Drug Discovery更可能较快形成阶段性成果。
  4. 后端医药研发周期较长，科技公司难以在短期内验证最终商业收益。
  • Drug Discovery仍需开展较多实体实验，AI主要用于提高早期筛选和决策效率，无法完全替代实验。

c) 快速推理在医药行业最适合哪些类型的任务？

  • 根据受访者判断，快速推理最适合以下三类任务：
  1. 高实时性任务：会议实时转录、实时总结、仪器监测和机器人控制。
  2. 高计算量任务：药物发现、Design Space搜索、模型训练和重新预测。
  3. 大规模知识处理任务：企业历史实验数据整合、RAG检索、大批量文件提取和翻译。
  • 对固定模板填充、简单报告生成等低复杂度任务，快速推理带来的增量价值相对有限。
