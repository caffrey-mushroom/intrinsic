摘要

1、客户降低模型支出后，调用量变化与2027年收入增长的关系。2、算力承诺提前锁定后，复杂代理可靠性与利用率兑现的条件。3、Opus与Astra在高难任务中的成本比较，以及人工复核对升级的影响。

本报告基于笔者 2026 年 9 月 18 日至 10 月 22日完成的四场专家访谈。主线是三个问题：需求是否真实，算力承诺能否兑现，模型竞争力能维持多久。文中数字均为访谈口径，未做外部核验。以下先给笔者的总体判断和推理链，再按主题展开证据。

#

一、核心结论

笔者的总体判断：Anthropic 2027 年的核心命题不是「需求有没有」，而是「可靠性门槛什么时候跨过去」。这个门槛同时决定收入增速、算力利用率和价格战的终结时间。

以下五步推理基于四场访谈的事实，是笔者的推断，不是任何受访者的原话。基于事实的分项结论见各章开头。

  1. 收入端是「以量补价」。价格在通缩，旗舰降价 20%，客户把 60–70% 的请求路由到便宜模型。但用量在三个维度同时扩张：客户数、每客户工作流数、任务复杂度。复杂任务的单任务 Token 量随模型升级上升 1.3–2

倍，简单任务可能持平或下降。总量增长的主驱动是任务结构向代理工作流迁移。笔者的判断是，总量增速仍然跑赢降价。

  1. 成本端的最大赌注是算力承诺。承诺跑在需求前面是常态，兑现取决于代理工作流能否在 12–24 个月内跨过可靠性门槛。跨过去，容量爬坡到 80–90% 的利用率。跨不过去，用量增长会失去最大的引擎，利用率爬坡变慢，价格通缩的压力持续更久。
  2. 竞争端的护城河和裂缝都很清楚。护城河在长上下文编程、多文件代码库和合规工具链。裂缝在最高难度任务的推理效率，单价便宜 60% 也可能输掉总账。
  3. 增量市场里金融和医疗最确定，但合规要求和部署成本会拖慢落地速度。
  4. 验证这个框架最直接的指标，是 Anthropic 的实际 Token 调用量增速。Token 调用量增速也是下一步最该补的数据。

二、需求与收入：需求真实增长，但客户在收紧花钱方式

根据笔者的调研，Anthropic 的企业基本盘在增厚。

2027 年预算的方向是增加，但花法更谨慎。客户在引入季度固定预算和月度限额，防止代理 24 小时运行失控。

行业结构上，科技、软件和编程仍是最大板块。笔者的判断是，金融和医疗的占比还会继续上行。

三、算力承诺：采购跑在需求前面是正常规划，兑现看代理爬坡

算力承诺与需求之间存在时间差，但这是行业惯例，不等于过剩。容量通常先于需求锁定。所以新容量上线的初期利用率可能只有 60–75%，工作负载成熟后升至 80–90%。需要注意，这组利用率是规划情景，不是实际运营数据。

承诺的逻辑是代理工作流放大推理量。单次用户请求可触发数十次后台模型调用。如果员工每天几十次提示变成代理每天数百次调用，算力需求可能放大一个数量级。这个放大情景是示例，不是已实现的结果。

供给侧还有一个值得记录的信号。谷歌的算力正在变紧，原因之一是把 GPU 转到谷歌云（GCP），以更高价格租给 Anthropic 等公司。

#

四、模型竞争力与定价：Opus 5.5 是标杆，但领先方式已经变了

根据笔者的调研，Opus 5.5 目前是业界公认的 SOTA 模型，但领先不靠绝对能力。它的 Elo 分数比第二名 Fable 5.1 Max 高十几分，胜在可读性和响应速度，速度快约 2–3 倍。它的参数量约 5T，明显小于 Fable 5.1 Max 的 9.7T，推理效率更高。分工上，Claude 强在长上下文编程、多文件代码库修改和复杂文档分析。OpenAI 在严格 Schema 和固定 API 顺序的工具流中更可预测。

价格战已经开始。Opus 5.5 比上一代低 20%、快 30%，典型工作负载的任务成本约降 40%。Opus 5.5 Max 的定价低于 Fable 5.1 Max。Opus 5.5 Medium 的性能追平上一代 Opus 5 High，但价格只有三分之一。

但单价不等于总账。按 API 单价 Opus 5.5 比 Astra 便宜约 60%，Sonnet 5.5 便宜约 80%。但部分高难任务用 Astra 反而更便宜，例如 3.50 美元对 Opus 5.5 的约 6.00美元。原因是弱模型在复杂任务上会烧掉更多思考 Token。

企业用量结构反映了这种分层。

下一代模型的信息有两条。Anthropic 手中最强的模型是 Mythos 2，A 榜约 60 分，只比 Opus 5.5 高一两分，不构成断代领先，参数量接近 10T。同时 Anthropic正在开发新的旗舰模型，目标是在任务完成成本上对标 Astra。

高价订阅方面，Google 和 Anthropic 原计划推出 300 美元套餐，可能跟随 OpenAI 调至 500 美元。但即便如此这项服务仍然亏损。

其他收入线索有三条。Anthropic 为礼来等大型药企用专有数据从头训练垂直模型，收取服务费。科学研究负载占商业推理需求的 1–5%，2027 年不会成为主要收入来源。内部研发方面，AI 生成 40–70% 的常规研究代码，20–40%的实验分析可以自动化。但实验设计仍由人主导。

笔者的结论是，Token 增长由模型升级和任务变长双驱动。新代模型做复杂任务的 Token 用量按 1.3–2 倍规划，增量的拆解如下。Opus 5.5 做同一任务的 Token 消耗是 Opus 5 的 2 倍。

升级有稳定节奏。迁移慢的原因是客户要重跑评估和回归测试。

升级有三个触发因素：成功率可测量的提升、更低的总成本、旧模型做不到的新能力。升级的经济门槛也很明确。如果新模型把人工复核比例从 15% 降到 2–3%，两倍 Token 价格也更便宜。笔者判断，还需 2–3个模型世代，才能跨过很多复杂流程的门槛。

迁移按工作负载发生，不是整家公司更换供应商。编程迁移最快，金融、医疗和法律因合规和系统集成慢得多。OpenAI 客户向 Anthropic 的迁移同样在发生，驱动是可测量的任务表现提升。AWS Bedrock等渠道只起简化采购和部署的作用。

#

六、落地瓶颈：卡在可靠性和组织，不在模型够不够聪明

笔者的结论是，瓶颈按任务复杂度分化。

可靠性方面，20–30 步的工作流里一致性是大问题。受控环境的编程任务成功率可达 70–90%。根据笔者的调研，复杂编程和企业流程在 12–24 个月内有明显改善。但不可预测环境的全自动执行要 3–5年以上。复杂任务执行慢的主因是串行执行，不是算力或模型大小。解法包括用小模型处理简单步骤、并行执行和减少推理循环。

金融和医疗的瓶颈是隐私合规、遗留数据库、数据孤岛和推理错误的责任归属。应对方案是私有云隔离、MCP 连接器、引用追踪和审计链。但部署成本不低。

人机协同的验收标准是 90% 的案例自动处理、10% 路由给人工。如果 30% 的案例都要人工复核，商业价值就有限。未来 6–12 个月，金融知识工作和客户运营的采用速度最快。因为这两个领域从第一天起就不需要完全自主。工程上，系统架构约70–80% 可以复用，例如评估框架、重试逻辑和审计日志。其余由现场工程师（FDE）按客户适配。

收拢成一句话：需求是真的，悬念在执行。接下来几个季度，笔者会持续跟踪需求、可靠性和价格三个方向的变化。如果关键信号走弱，本报告的框架就需要重检。
