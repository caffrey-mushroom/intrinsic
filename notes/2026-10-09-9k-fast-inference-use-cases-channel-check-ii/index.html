1. AI推理需求与云计算市场趋势

a) 当前AI需求侧呈现哪些总体趋势？市场是否需要更高速度和吞吐量？

  • 推理即服务成为云计算市场最显著的增长方向
  1. 当前最主要的需求趋势来自开源模型及推理即服务（Inference as a Service）。
  2. Nebius、Together AI、Fireworks、Baseten、Modal等新云厂商均在加速布局推理服务，年度经常性收入（ARR）快速增长。
  3. Fireworks和Together AI去年的ARR约为1亿至2亿美元；Together AI今年ARR预计接近15亿美元，增速显著。
  4. Nebius和CoreWeave原本以裸金属及GPU即服务为主，目前也在大规模发展模型即服务。
  5. Nebius模型即服务ARR由去年的约2,500万美元增至今年预计6亿至8亿美元，并可能接近8亿美元。
  6. CoreWeave相关业务当前ARR约为6亿美元，并可能向8亿美元增长。
  • 闭源模型成本过高，推动企业需求转向开源模型
  1. OpenAI、Anthropic及Google等闭源模型成本较高，许多企业难以长期承担。
  2. 原本可能流向头部闭源模型厂商的收入和算力需求，正在向开源模型及其推理服务迁移。
  3. 这一趋势对Nebius、Together AI、Fireworks等新云厂商较为有利。
  4. 受访者援引的OpenAI收入预测口径为700亿美元、实际完成约500亿美元，但该组数据的统计周期和定义未进一步说明。

b) 前沿模型实验室的云计算需求是否正在减弱？

  • 大型前沿实验室的云合同增速可能放缓
  1. 受访者判断，前沿模型实验室对外部云计算的新增需求正在减弱。
  2. 微软已经出现相关合同增速放缓的迹象。
  3. OpenAI的大部分云合同实际由微软吸收，部分项目未能按照最初预期落地。
  4. Anthropic仍在与合作伙伴推进云部署，但行业整体投资意愿正在下降，相关部署的融资难度也在上升。
  • 裸金属及GPU服务需求仍然较强
  1. 即使前沿实验室需求有所减弱，裸金属服务和整体GPU算力需求仍在延续。
  2. 因此，云计算市场并非整体转弱，而是需求结构从大型长期合同逐步转向灵活、高价值的推理服务和中短期合同。

c) GPU供需和租赁价格呈现怎样的变化？

  • HBM短缺限制最新一代GPU供给
  1. Nvidia最新旗舰GPU Vera原计划具备约40万至60万块的生产能力。
  2. 由于HBM4存在供应及技术问题，受访者估计实际产能可能下降至约10万至20万块。
  3. 旧型号GPU仍可继续部署，但其推理效率低于Vera。
  4. ASIC现阶段产量有限，市场上尚未出现能够全面替代Nvidia的方案。
  • 供给紧张推动GPU租赁价格上涨
  1. GPU持续处于供应紧张状态，10月租赁价格再次上涨约20%。
  2. 这对Nebius等新云厂商有利，因为其通常可以将新增硬件成本转嫁给客户。
  3. 但同时，新云厂商的资本开支和运营成本也在显著上升。

d) Nebius等新云厂商将如何调整合同策略？

  • 从追求长期规模转向利润率和资本效率
  1. Nebius希望避免重演CoreWeave债务杠杆过高的问题。
  2. 公司不再像过去一样大量签署规模庞大、期限较长的裸金属合同。
  3. 当前更倾向选择期限为1至3年、定价较高的大型合同，而非期限长达5年的低回报裸金属合同。
  4. 战略重点正在从单纯扩张收入和算力规模，转向提高盈利能力、利润率及资本周转效率。

2. Nvidia部署LPU的战略逻辑

a) Nvidia为什么要将Groq LPU/LPX纳入自身体系？

  • 核心目标是实现推理解耦
  1. Nvidia GPU在Token效率、智能体响应速度和Token输出延迟方面仍存在不足。
  2. LPU被纳入Nvidia整体推理战略，主要用于拆分和加速推理过程中的特定工作负载。
  3. 相关方案可能与D-Matrix等推理加速芯片共同部署，并与Vera GPU形成完整系统。
  • 缓解HBM带宽瓶颈
  1. D-Matrix和LPU均可以更多依赖SRAM，从而降低对HBM的访问压力。
  2. D-Matrix与Vera组合后，预计可使Token输出能力提升至少20%。
  3. LPU进一步参与后，可继续提高Token吞吐量并降低响应延迟。
  4. 该组合旨在同时解决智能体AI响应、Token输出效率及HBM过载问题。

b) Vera、D-Matrix和LPU组合后的Token输出能力如何？

  • 不同方案的性能对比
  1. Etched Sohu ASIC针对单一模型优化，每颗芯片理论上每秒可处理约6万个Token。
  2. Vera预计每秒可处理约4.5万个Token。
  3. Vera引入D-Matrix后，按20%的提升幅度计算，可达到至少每秒5.4万个Token。
  4. 如果进一步由LPU辅助，Vera、D-Matrix与LPU组合方案预计可接近每秒7万个Token。
  • 经济性与规模化能力
  1. Nvidia组合方案的成本预计高于Etched。
  2. 但Nvidia具备更成熟的软件生态和更大的部署规模，可通过规模效应提高综合竞争力。
  3. 因此，LPU并非独立替代GPU，而是作为Nvidia推理系统中的加速组件。

3. Etched纯推理ASIC的性能与商业化

a) Etched为什么能达到每秒约6万个Token？

  • 从设计之初即专门面向推理
  1. Etched采用ASIC架构，而非传统通用GPU。
  2. 芯片从一开始就针对智能体AI、规模化推理及低延迟计算进行优化。
  3. Etched移除了面向通用计算的部分，不设置传统的可编程层或复杂软件编译器。
  4. 其架构专注于单一类型工作负载，因此可以获得更高的硬件利用率。
  • 软硬件架构更加简化
  1. Etched采用144GB HBM3e，而非依赖HBM4。
  2. 系统采用液冷方案，并配有自主软件管理系统。
  3. 通过简化软件层和数据路径，Etched基本绕过部分内存带宽瓶颈。
  4. 其Transformer相关计算利用率可达到约90%的FLOPS利用率，显著高于通用产品。
  • 单位系统输出能力较高
  1. 一套约8U的Etched系统，其推理输出能力约相当于20至40块GB200。
  2. 与Google TPU、Amazon Trainium、Cerebras、Maia等产品相比，Etched更加专注于纯推理场景。
  3. 其他产品虽然也具备较高推理效率，但通常仍保留训练或通用计算能力。

b) Etched当前融资及客户情况如何？

  • 融资规模较大
  1. Etched近期完成约10亿美元融资。
  2. 另有约10亿美元资金预计即将到位。
  3. 主要投资方以金融机构为主。
  • 当前客户集中在金融服务领域
  1. Etched已在摩根大通部署，并向Jane Street直接交付产品。
  2. 华尔街金融机构是其主要目标客户。
  3. 由于制造能力有限，目前主要面向金融服务这一利基市场，尚无法进入大规模通用市场。
  4. 产品可直接部署在客户办公场所，无需额外建设微型数据中心。

c) Etched当前主要运行哪些工作负载？

  • 目前重点并非通用大语言模型
  1. Etched当前实际运行的主要是高频交易算法，而非面向消费者的大语言模型。
  2. 相关工作负载通常具有内存密集、低延迟和实时计算等特征。
  3. 由于需要实现亚毫秒级延迟，设备必须部署在办公楼或交易场所内部，不能依赖远程数据中心。
  • 主要应用包括高频交易与预测智能体
  1. 系统需要自主生成交易信号，并立即执行智能体操作。
  2. 高频预测智能体可直接预测证券短期走势。
  3. Sohu能够在极低批量条件下保持实时处理能力，并结合完整上下文预测未来10秒至1分钟的情况。
  4. 相较标准Nvidia GPU等通用硬件，Etched在延迟套利场景中具有明显优势。
  • 关于架构定义的口径
  1. 会议中受访者将此处的“Transformer”解释为硬件架构，而非公开披露的具体大语言模型。
  2. Jane Street等客户的模型及算法属于机密，未披露具体名称和参数规模。

4. 快速推理的定义、性能标准与应用场景

a) 当前应如何定义快速推理？

  • 快速推理必须结合具体工作负载判断
  1. 不同场景对Token吞吐量、首Token延迟和端到端响应时间的要求不同。
  2. Groq目前侧重实时智能体AI及即时响应。
  3. Cerebras同样布局智能体AI，但更偏向高吞吐推理输出。
  4. Etched在性能上高于Cerebras和Groq，但由于仅服务少数金融客户，暂不能视为开放市场的通用基准。
  • 首Token延迟是重要指标
  1. Cerebras的首Token生成时间已低于80毫秒。
  2. 受访者将80毫秒视为现阶段开放市场中最快推理的重要参考线。
  3. 实时代码生成等场景未来希望将延迟由当前约200至300毫秒降至10至40毫秒。
  4. 快速推理并不存在统一Token速度门槛，核心标准是端到端响应是否能够快于实际交互需求。

b) 为什么机器人和物理AI需要更快推理？

  • 不仅需要响应，还需要预测
  1. 机器人和物理AI必须实时判断当前环境及下一步行动。
  2. 系统还需要预测未来事件及不同操作可能产生的后果。
  3. 未来最快推理的目标，不只是更快输出Token，而是预测未来1至2分钟内可能发生的情况。
  4. 系统应在事件发生前完成决策并立即行动。
  • 未来发展方向
  1. 当前预测准确率据称约为99%，长期目标是接近100%。
  2. 推理价值将由“回答更快”逐步转向“提前预测并执行”。

c) 当前最需要快速推理的应用有哪些？

  • 金融算法与预测分析
  1. 高频交易是当前最成熟、最重要的应用之一。
  2. 其他场景包括低延迟算法、实时计算和预测分析。
  3. 这些场景已经接近或进入实际部署阶段，并非远期概念。
  • 智能体AI工作流
  1. 智能体AI需要真实、自然且实时的交互。
  2. 当前OpenAI或Anthropic等服务往往存在5至10秒响应延迟，难以实现即时交互。
  3. 快速推理可以支持智能体实时完成任务、预测下一步操作，并在与用户交互时减少停顿。
  • 语音、通信与代码生成
  1. 语音到语音交互和实时电话通信对响应延迟高度敏感。
  2. AI编程需要从“建议代码”升级为实时预测和生成代码。
  3. UI生成、实时软件操作和智能体编程也将成为重要场景。
  • 推测解码
  1. 推测解码通过预测模型提前生成候选Token，再由主模型进行验证。
  2. 该技术可以直接提升大语言模型的生成速度和资源利用率。
  3. 随着预测能力提升，推测解码预计将成为快速推理的重要软件层应用。

d) 快速推理能为现有AI应用带来多大价值？

  • 端到端体验将显著改善
  1. 当前GPU生成Token及软件处理会带来明显等待感，部分场景整体延迟可达10至20秒。
  2. 快速推理的目标是让输入、计算、输出和智能体操作尽可能即时完成。
  3. 实时交互类应用将率先体现价值，通用模型和非实时应用随后跟进。

5. 快速推理市场规模与渗透率

a) 快速推理目前占整体推理市场多少？

  • 当前仍处于早期阶段
  1. 专业快速推理目前约占整体推理市场的5%至10%。
  2. 占比较低的主要原因并非需求不足，而是ASIC产能有限、技术尚未形成大规模交付能力。
  3. 云厂商的生态合作关系也会影响专业芯片选择。
  • 未来渗透率将持续提升
  1. 预计下一年度专业快速推理占比可能提升至10%至15%。
  2. 此后随着智能体AI、编程、算法交易、机器人及预测算法增长，渗透率有望继续显著提高。
  3. 受访者预计相关市场未来可能以约40%的幅度扩张，但未提供2027年和2030年的最终占比数据。

b) 智能体AI是否比聊天机器人带来更多快速推理需求？

  • 智能体AI的需求强度更高
  1. 聊天机器人主要关注生成内容，而智能体AI还需实时判断、规划和执行。
  2. 智能体需要与用户、软件和现实环境持续交互，因此对首Token延迟和实时响应要求更高。
  3. 编程、算法交易、机器人和预测算法均属于延迟敏感型专业工作负载。
  • 推理市场将出现分层
  1. 对延迟不敏感的工作负载继续采用通用GPU推理。
  2. 对延迟高度敏感的专业工作负载将转向Groq LPU、Cerebras或Etched等专业推理方案。
  3. 专业推理不会完全替代通用推理，而是形成差异化市场。

6. Groq LPU/LPX的产能、部署与生态

a) Groq LPU当前最大的瓶颈是什么？

  • 核心瓶颈是制造能力，而非架构兼容性
  1. 理论上，大部分开源和闭源大语言模型都可以部署在LPU上。
  2. 小规模模型部署通常不存在明显容量问题。
  3. 超大模型需要更多LPU协同，单个LPU的输出速度也会随模型规模增加而下降。
  4. 当前限制大模型部署的主要因素是芯片和机架产能，而非架构本身。

b) LPU/LPX产能的最新判断是什么？

  • 会议中出现多次口径调整
  1. 早期口径称2026年LPU产量约为4万，但受访者随后明确表示应删除该数字。
  2. Groq依赖Samsung 4纳米制程，实际产量和产能爬坡均低于原先预期。
  3. 受访者后续给出的保守预测是，下一年度LPX机架产量约为2万至2.5万台。
  4. 会议另有“约400万至500万个组件、折合约2万个完整机架”的表述，但组件与机架的换算定义未详细说明。
  • Nebius预计获得的数量
  1. Nebius预计到今年年底获得约5,000至10,000个LPU/LPX机架，但原始表述在“芯片”和“机架”单位上存在混用。
  2. 剩余产能主要交付Groq自有客户，包括Saudi Aramco等。
  3. 大部分合同预计仍由Groq直接签署，而非全部通过Nebius分销。

c) 为什么Nebius更可能采用LPU，而非Cerebras或Etched？

  • LPU能够融入Nvidia生态
  1. LPU可以配合Nvidia软件栈和GPU系统部署。
  2. 对已经使用Nvidia基础设施的云厂商而言，LPU的迁移成本相对较低。
  3. 因此，LPU具备未来规模化采用的潜力。
  • 其他方案的限制
  1. Nebius目前不太可能采用Cerebras。
  2. Cerebras更多局限于自有生态及大型定制合同，尚未实现全生态部署。
  3. Nebius曾考虑采用Etched，但Etched当前产能过于有限，无法满足通用云服务部署需求。

d) 还有哪些公司可能采购LPU？

  • 目前公开客户有限
  1. 除Nebius外，其余主要采购方包括Groq自己的直接客户。
  2. Saudi Aramco被提及为潜在或已有直接客户之一。
  3. 其他客户暂未公开。
  4. Amazon可能将Groq与Trainium结合部署，Anthropic可能通过Amazon体系使用相关能力，但会议未给出已正式落地的确认信息。

7. LPU支持的模型、性能及定价

a) 哪些模型可以部署在Groq LPU上？

  • 架构上兼容开源和闭源模型
  1. 理论上，各类开源和闭源模型均可部署在LPU或Cerebras上。
  2. 当前公开信息较多的是Gemma约31B参数模型。
  3. Llama等模型已进行少量测试。
  4. Anthropic、OpenAI及其他前沿实验室模型理论上也可以使用LPU，实际限制主要来自容量和产能。
  • Cerebras现有部署情况
  1. Cerebras与OpenAI签有合同。
  2. Cerebras可能正在为Meta部署Llama、Muse等模型。
  3. Cerebras还与阿联酋G42、Core42及Mohamed University合作部署主权AI模型。
  4. 部分模型尚未公开。

b) 模型越大，LPU输出速度如何变化？

  • 输出速度随参数规模上升而下降
  1. 较小模型在LPU上可以达到较高Token输出速度。
  2. 超大模型需要多个LPU协同，并调用更多内存资源。
  3. 受访者给出的单用户输出速度宽泛估算约为每秒50至200个Token，但该数据尚未公开验证。
  • Kimi系列参考数据
  1. Kimi 1.5在LPU上预计可达到约每秒1,000个Token。
  2. Kimi K2预计约为每秒400至450个Token。
  3. Kimi 3无法直接在单个LPU上运行，需要至少2个LPU共同调用内存。
  4. Kimi 3的估算速度约为每秒250个Token。

提问者：从您的角度来看，目前需求侧呈现出哪些总体趋势？市场是否需要更高的速度、更高的吞吐量？未来的大语言模型是否会进一步扩大？

回　答　者：目前，闭源模型成本高昂，许多企业难以承受，因此开始直接转向开源模型。原本可能流向 OpenAI、Anthropic 或 Google 的收入和需求，也开始直接转向开源领域。这一趋势对新云厂商显然有利，但其长期影响仍需关注。

目前市场上尚未出现真正能够替代 Nvidia 的方案，ASIC 的产量仍然有限。因此，GPU 供应持续紧张，租赁价格在 10 月又上涨了 20%。这对包括 Nebius 在内的新云厂商有利，因为它们会将成本直接转嫁给客户，而不会自行承担相关成本。

主要问题在于资本支出正在大幅增加，新云厂商的运营成本也随之上升。Nebius 等新云厂商正在调整策略。为避免像 CoreWeave 一样出现债务杠杆过高的情况，同时提高盈利能力和利润率，Nebius 不再像过去那样签订多份规模庞大的裸金属服务合同，而是优先选择期限为 1 至 3 年、定价最高的大型合同，而非期限为 5 年的裸金属服务合同。

提问者：英伟达为什么要部署 Nvidia Groq 3 LPX？快速推理的潜在市场规模如何？

回　答　者：英伟达部署 Groq LPU，首先是为了实现推理解耦。目前，英伟达 GPU 在令牌效率、智能体响应以及令牌输出延迟等方面存在效率问题。LPU 已被纳入英伟达的整体战略，例如在 GPU 层面与 D-Matrix 部署相结合。这一方案尤其适用于从10月起部署的英伟达 Vera GPU。不过，目前 D-Matrix Vera 的产量尚未匹配，涉及40,000颗芯片。

LPU 与英伟达 GPU 构成了一套完整系统。在这套系统中，D-Matrix 芯片利用 SRAM 来避免 HBM 过载，使英伟达 Vera GPU 的输出能力显著高于此前的型号，因为数据批处理过程中的 HBM 瓶颈得到缓解。这意味着令牌输出至少可以提升20%。

结合 LPU 后，令牌数量还会进一步大幅增加，因为 LPU 同样能够解决这一问题：它可以完全绕过 HBM，主要依赖 SRAM。以目前市场上竞争力最强的推理芯片 Etched 为例，每颗 Sohu ASIC 针对1个模型，每秒可处理约60,000个令牌。Vera 目前每秒可处理约45,000个令牌，两者之间存在较大差距。引入 D-Matrix 后，令牌输出可提升20%，至少达到每秒54,000个。如果进一步使用 LPU 辅助 Vera，Vera、D-Matrix与LPU组合方案的输出将接近每秒70,000个令牌。

从 GPU 的经济性来看，该方案的成本高于 Etched，但英伟达可以依靠更大的部署规模。因此，部署 LPU 并不是一项孤立的策略，而是为了同时解决智能体 AI 响应、令牌输出效率以及此前较为突出的 HBM 内存瓶颈问题。

快速推理的市场需求非常庞大，尤其体现在边缘推理计算和本地化推理领域，也包括物理 AI、智能体 AI 等需要实时响应、无法容忍延迟的特定应用。

提问者：您提到一家名为 Etched 的公司，其推理速度约为每秒60,000个 Token，对吗？

提问者：为什么其速度如此之高？这一水平远高于 Cerebras、Groq 等市场参与者，主要原因是什么？

回　答　者：首先，Etched 从一开始就是专门针对推理进行优化设计的，因此不同于传统 GPU，而是采用 ASIC 架构。

Etched 能够以较小规模进行部署。目前，一套约为8U的 Etched 系统，其推理输出能力大约相当于20至40块 GB200。此外，它从设计之初就专门针对智能体 AI 和规模化推理进行了优化。

在软件和架构层面，主要区别在于 Etched 没有可编程层或软件编译器。它不依赖 HBM4，而是采用容量为144GB的 HBM3e。Etched 还拥有自己的生态系统，目前采用液冷方案，并具备自主的软件管理系统。同时，它基本绕过了内存带宽瓶颈，软件层也更加简化，且仅针对推理进行优化。

Nvidia GPU 属于通用计算产品，Cerebras 的 ASIC 也具有通用属性，并非仅针对推理进行优化。目前市场上真正可以被视为纯推理芯片的产品并不多。Google TPU、Amazon Trainium、Cerebras 和 Maia 通常都属于通用型产品。它们在推理方面非常高效，但并非仅为推理而设计。

Etched 实际上移除了架构中面向通用计算的部分，简化了 GPU 本身。通过这种方式，它能够提高 Transformer 的利用率，实现约90%的 FLOPS 利用率，而其他产品的 FLOPS 利用率和 Token 输出通常低得多。这也体现了 Etched 针对纯推理场景的优化程度。

此外，Etched 目前的规模也相当大，刚刚完成了一轮10亿美元融资，另有10亿美元即将到位，主要投资者以金融类为主。

回　答　者：华尔街的公司都属于目标客户。例如，Etched 已在摩根大通部署，也直接向 Jane Street 交付产品。该产品旨在成为市场上最高效的推理集群，同时无需配套微型数据中心即可部署。目前，Etched 面向的更多是利基市场，而非大众市场。由于制造能力非常有限，现阶段只能在金融服务领域进行部署。

提问者：Etched 的硬件目前运行哪些类型的大语言模型？

回　答　者：目前，Etched 的硬件并未运行大语言模型，实际运行的是高频交易算法。与其讨论大语言模型，不如从当前最重要的应用场景，以及摩根大通和 Jane Street 实际运行的工作负载入手，这样可以提供更清晰的概览。

Etched 最初并非为大语言模型而设计，更多是为规模化推理而设计。这也是它的不同之处：通过去除无关处理并专注于特定应用场景，而不是面向整体的智能体 AI 部署或开源模型，Etched 主要针对需要在最短时间内完成最高强度计算的任务。

目前公开披露的信息有限，尤其是 Jane Street 运行的大多数模型都属于机密，但相关应用场景可以说明。这些工作负载通常是内存密集型、低延迟的 Transformer 推理。出于延迟要求，设备必须部署在办公楼内部，不能放置在其他外部数据中心。

其应用包括高频交易。所使用的特定大语言模型并未公开，需要实现亚毫秒级延迟，不仅服务于高频交易，还要以比现有高频交易算法更高效的方式，自主生成交易信号并立即执行独立的智能体操作。此外，还包括高频预测智能体，不仅能够直接预测证券的下一步走势。

回　答　者：Sohu 能够在批大小为 0 时实现无性能衰减的处理，基本上属于实时处理。它可以结合全部上下文，直接预测未来10秒或1分钟内可能发生的情况。因此，与标准的英伟达 GPU 或其他硬件相比，它在直接延迟套利方面具有显著优势。

提问者：我想确认一点：该模型仍然是 Transformer 模型吗？您提到它主要用于低延迟 Transformer 推理，那么在 Etched 上运行的是某种 Transformer 模型吗？

回　答　者：不是，Transformer 指的是硬件架构。

提问者：目前应如何定义快速推理？Cerebras 的输出速度可以超过每秒4,000个 Token，Groq 同样可以超过每秒3,000个 Token。在当前市场中，所谓的快速推理究竟需要达到怎样的速度？

回　答　者：首先，我们需要对工作负载进行分类。稍等1秒，我们需要先明确快速推理将用于哪类工作负载，因为这是最重要的因素。

例如，Groq 目前用于实时智能体 AI，以实现智能体 AI 的即时响应。Cerebras 目前也在部署智能体 AI，但主要侧重于推理输出。正如我之前提到的，目前性能领先的是 Etched，其表现优于 Cerebras 和 Groq，速度最快，输出能力也最强。不过，由于它目前不会向金融客户以外的客户开放，因此暂时只能将其视为市场之外的更高层级。

就市场本身而言，Cerebras 的表现优于 Groq，尤其是在首个 Token 生成时间方面，已经低于80毫秒。

至于快速推理为何重要，以及应如何界定，其基准就是速度越快越好，因为系统需要实现实时输入和输出。例如，在机器人和智能体 AI 场景中，系统的响应速度必须快于现实中的实时交互。

其中首先需要考虑的是预测能力。如果讨论的是物理 AI 和机器人，它们不仅需要实时计算正在发生的情况以及需要采取的行动，同时还要预测未来将会发生什么。

回　答　者：系统需要了解将会发生什么，以及相关行为可能带来的后果。因此，我们需要非常高的响应速度，同时也要缩短首个Token生成时间。这是利用层面的第1个重点。

目前，最快推理的基准是80毫秒，未来还会进一步降低。在80毫秒的情况下，这已经是当前能够实现的最快速度。以Etched为例，其仍被视为快速推理方案，但未来最快的推理将是对至少未来1至2分钟内可能发生的情况进行预测。这样一来，机器人或算法不仅能够以接近100%的最高准确率进行预测，目前准确率约为99%，还能够在事件发生前立即作出反应。这将是最快推理的发展方向。

提问者：能否进一步介绍目前的应用场景？机器人或物理AI可能距离实际应用还比较远，而当前已经出现了智能体AI、AI编程等应用。现阶段哪些应用场景最需要快速推理？快速推理能够为这些应用场景带来多大价值？

回　答　者：不同场景确实存在差异。正如之前提到的，快速推理最适合应用于算法，而且相关应用并不遥远，目前已经非常接近实际落地。

高频交易是当前最重要的应用之一。此外，快速推理也广泛应用于各类算法、计算和预测分析，这些是目前应用程度最高的场景。

因此，其应用不仅包括通用模型的输入与输出，还包括与智能体AI相关的各类场景，例如智能体AI的实时编程、语音到语音交互以及实时电话通信。智能体不仅能够以预测性方式实时执行被分配的任务，在开始与用户直接交互时也不会出现延迟。目前，消费者已经能够从实际体验的各类交互中感受到这种延迟。
