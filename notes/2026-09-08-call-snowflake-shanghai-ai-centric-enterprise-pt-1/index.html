1. AI中心型企业与AI应用趋势

a) 什么是“AI中心型企业”，企业为什么需要向这一方向转型？

  • “AI中心型企业”是指充分理解数据与AI的价值，并利用AI提升组织内各项职能效率、生产力和决策质量的企业。
  • AI的应用已经从3—4年前以问答为主，发展到深入企业经营流程、重塑组织运作方式的新阶段。
  • 企业应用AI的最终目的不是单纯部署新技术，而是取得更好的业务成果，包括：
  1. 提高员工生产效率。
  2. 优化经营分析与决策。
  3. 提升客户服务质量。
  4. 更高效地利用企业数据。
  5. 在安全可控的前提下实现业务自动化。
  • 智能体企业并非未来3—5年的概念，相关能力已经能够在当前企业环境中部署和使用。

b) 企业部署AI智能体后，数据问题是否会自然得到解决？

  • 行业内曾存在一个普遍误区，即只要部署AI智能体，企业的数据问题就会自动解决。
  • AI虽然能力强大，但并不是“魔法”。AI要输出正确、可靠的结果，必须具备：
  1. 坚实的数据基础。
  2. 正确且完整的数据。
  3. 与业务相关的上下文。
  4. 清晰的数据架构与治理体系。
  • 企业不能期待AI自行完善数据战略，而需要主动投入资源建设数据连接、治理、安全和统一语义能力。
  • 卓越的AI能力建立在卓越的数据能力之上。如果企业的数据基础不完整，AI能够创造的价值也会受到限制。

c) 当前企业在数据层面主要面临哪些问题？

  • 大多数企业存在明显的数据碎片化问题，数据分散在多个业务系统和技术平台中。
  • 常见情况包括：
  1. 销售数据存在于独立报表中。
  2. 分析数据位于Power BI等可视化系统中。
  3. ERP数据位于另一套系统中。
  4. 实时数据分布在流式处理平台或应用系统中。
  5. 线下采集数据、成本数据和经营数据无法直接关联。
  6. 部分历史数据因存储空间不足而被删除。
  • 数据孤岛会导致企业难以统一计算收入、成本、利润率等核心经营指标，也会使AI缺少完整的业务上下文。
  • 当各部门对同一指标采用不同定义时，AI即使能够访问数据，也可能输出相互冲突或不准确的结果。

2. 智能体企业的四项核心能力

a) 企业要充分释放AI价值，需要具备哪些关键要素？

  • Snowflake将智能体企业所需的能力总结为四个关键要素：
  1. AI模型：提供先进的大语言模型、中型模型及多样化模型选择，用于处理不同规模和类型的数据。
  2. 企业数据与上下文：让AI在企业自身业务环境中运行，理解企业特有的数据、流程、指标和知识。
  3. 软件与应用集成：使AI能够与企业整体架构、业务系统和应用程序交互。
  4. 智能体控制平面：统一管理智能体的访问、运行、安全、治理和协作。
  • 这四项能力并不是单一软件功能，而是企业证明自身具备成熟AI能力所需的基础条件。
  • Snowflake希望通过AI数据云，将模型、数据、应用和智能体控制能力整合在统一平台中。

b) 为什么企业数据和业务上下文是智能体能力的核心？

  • 通用模型具备基础推理和生成能力，但不了解企业内部的指标定义、业务流程、权限边界和经营目标。
  • AI只有接入企业自身的数据与上下文，才能回答与经营相关的问题，例如：
  1. 哪些城市利润率更高。
  2. 哪些场馆成本异常。
  3. VIP客户增长为什么放缓。
  4. 哪些区域存在经营风险。
  5. 哪些成功经验可以复制到其他城市。
  • 企业上下文还包括指标来源、计算逻辑、责任部门和历史业务资料，这些内容决定了AI回答是否准确、可追溯。
  • 因此，AI不仅需要“能找到数据”，还需要“理解数据代表什么”。

c) 企业级AI如何兼顾生产效率与数据安全？

  • 企业级AI需要在提高效率的同时，确保敏感数据得到最高级别的保护。
  • Snowflake强调数据与模型应采用统一治理方式，避免只管理原始数据、却忽略模型调用和AI输出环节。
  • Thomson Reuters、Sanofi、Under Armour、Canva和Samsung等企业已在不同场景中使用AI。
  • 典型实践包括：
  1. Thomson Reuters使用AI处理高度敏感的数据。
  2. Under Armour利用AI智能体推动呼叫中心现代化，并承担完整层级的客户支持工作。
  3. 其他企业通过AI提高生产效率和成果质量。
  • 这些案例表明，AI可以在当下投入企业实际运营，但前提是具备可靠的数据治理和安全能力。

3. 统一数据平台与经营分析演示

a) 数据分散时，企业为什么难以形成有效经营分析？

  • 演示案例中的企业需要同时管理活动体验、场馆经营和审计等业务，其主要成本包括场馆租赁和人员费用。
  • 企业内部不同管理者关注的指标不同：
  1. CEO更关注收入增长、城市扩张和业务表现。
  2. CFO更关注成本、利润和经营效率。
  • 由于销售、ERP、成本及分析数据分散在不同系统和报表中，企业难以快速形成统一的利润分析。
  • 报表数量不断增加后，IT和数据工程师需要反复响应业务部门的数据需求，导致分析周期较长、重复工作较多。

b) Snowflake如何帮助企业建立统一、互联的数据平台？

  • 数据工程师可以将销售、成本、ERP、实时应用数据及线下采集数据连接到统一平台。
  • 在统一数据基础上，企业可以快速生成同时覆盖收入、成本和利润的经营报表。
  • 报表不仅展示高层指标，还能够进一步下钻到：
  1. 各城市的收入和利润率。
  2. 各城市的成本差异。
  3. 单个场馆的活动和经营情况。
  4. 不同区域的人流和用户分布。
  5. 正面、负面反馈及其他经营信息。
  • 销售数据与成本数据连接后，企业才能准确计算利润，并为CEO和CFO提供一致的经营视图。
  • 统一平台使不同用户能够共用、共创同一套数据，减少跨系统取数和重复建设。

c) 数据工程师最重要的工作是制作报表吗？

  • 制作可视化报表只是最终呈现，数据工程师更重要的工作是管理报表背后的数据体系。
  • 底层数据管理工作包括：
  1. 接入应用系统的实时数据。
  2. 处理实时数据加载。
  3. 接入线下场景采集的数据。
  4. 连接销售与成本信息。
  5. 建立统一的数据口径。
  6. 持续维护数据安全和治理策略。
  • 只有底层数据连接和管理稳定，经营报表与AI分析结果才能保持及时、准确和可信。

4. Horizon Catalog数据治理与统一语义

a) 企业如何管理医疗、糖尿病等场景中的敏感数据？

  • 医疗及糖尿病相关数据可能包含电话号码、个人身份信息及其他敏感信息，员工访问和使用这些数据时存在较高合规风险。
  • Snowflake可以通过Horizon Catalog连接和汇集相关数据，并在统一平台内开展数据治理。
  • 开发人员可以通过自然语言描述治理需求，由开发工具协助完成相关处理。
  • 典型操作包括：
  1. 扫描每个schema、table和column。
  2. 自动识别PI等个人敏感信息。
  3. 识别电话号码和用户相关数据。
  4. 为敏感字段配置masking policy。
  5. 根据员工或数据人员的身份应用不同访问策略。
  • 这种方式可以降低治理工作的技术门槛，减少开发人员额外学习和手工配置的成本。

b) 为什么数据和模型需要统一治理？

  • 企业AI的风险不仅存在于原始数据访问环节，也存在于模型调用、模型输入和结果输出环节。
  • 如果数据受到权限保护，但模型可以绕过策略访问或暴露敏感信息，治理体系仍然是不完整的。
  • Snowflake将masking policy等治理能力同时应用于数据和模型，使AI应用沿用企业现有的安全与权限体系。
  • 统一治理有助于确保：
  1. 不同角色只能访问其有权限的数据。
  2. 模型无法绕过敏感数据保护策略。
  3. 数据使用过程能够被管理和审计。
  4. AI输出与企业安全要求保持一致。

c) 同一指标在不同部门定义不一致的问题如何解决？

  • 同一个企业中，不同部门可能对收入、互动、访问、转化等指标采用不同定义。
  • Snowflake通过统一语义层建立企业核心指标，并明确：
  1. 指标的标准定义。
  2. 指标的数据来源。
  3. 指标的计算逻辑。
  4. 指标之间的关联关系。
  • 企业人员查找指标时，可以通过同一个入口获取统一口径，减少部门间数据争议。
  • 统一语义不仅让员工获得一致答案，也为AI提供准确的业务含义，防止模型因口径不一致产生错误结论。

d) 企业实现规模化数据治理需要完成哪些工作？

  • 企业需要依次建立四项基础能力：
  1. 数据连接：将分散在多个系统中的数据统一连接。
  2. 数据治理：识别敏感信息并配置访问、脱敏和管理策略。
  3. 统一安全：实现从数据端到模型端的统一安全治理。
  4. 统一语义：统一企业核心指标、数据来源和计算逻辑。
  • 只有完成以上工作，企业才能在大规模使用数据和AI时保持一致性、安全性和可追溯性。

5. Observer每日简报与AI深度分析

a) 老板工作繁忙时，Observer如何帮助其快速掌握经营情况？

  • Observer可以根据老板的身份、职责和关注重点，判断其每天需要查看的信息。
  • 系统能够自动生成每日业务简报，帮助管理者了解：
  1. 当天发生了什么。
  2. 哪些事项需要重点关注。
  3. 哪些区域或指标出现异常。
  4. 当前存在什么经营风险。
  5. 哪些问题需要进一步分析。
  • 管理者可以配置定时推送，例如每天早上6点将简报推送至个人仪表盘。
  • 整个过程可以通过订阅自动完成，无须管理者主动进入多个系统查询数据。

b) Observer如何根据管理者角色实现个性化信息推送？

  • 系统会结合管理者的身份和角色，筛选与其职责相关的信息，而不是向所有人推送相同内容。
  • 管理者可以重点订阅特定区域、业务、客户或经营指标。
  • 对于需要进一步解释的问题，Observer会将相关内容转入分析环节，并生成更深入的结论。
  • 这种方式可以减少信息过载，让管理者优先关注对业务最重要的事项。

c) 如果简报发现风险，AI如何进一步分析原因并提出建议？

  • 当管理者发现风险但不知道应由谁处理、也不了解问题原因时，可以通过Search检索企业现有内容。
  • 过去可能需要逐一访谈多个相关人员、反复询问同类问题；AI Search能够调用已有数据和企业内容，自动完成检索、汇总和校验。
  • 系统可以进一步分析：
  1. VIP增长放缓的原因。
  2. 订单结构发生了哪些变化。
  3. 各区域、城市或组织当前的经营状态。
  4. 哪些部门或人员负责相关事项。
  5. 哪些成功经验可以复制。
  6. 哪些城市适合下一步推广。
  • 对于内容量较大的问题，系统会进行深度分析和校验，最长可能需要约20分钟。
  • 最终结果可以采用长文、详细回答、总结或预案等形式输出。

d) AI分析结果如何转化为可执行内容？

  • 系统不仅回答“发生了什么”，还会进一步说明“应该怎么做”。
  • AI可以基于搜索和分析结果形成：
  1. 风险判断。
  2. 原因分析。
  3. 改进建议。
  4. 业务预案。
  5. 可复制的最佳实践。
  6. 针对VIP业务的标准化操作手册。
  • 对已有成功案例，其他区域或团队可以直接复制相关做法，并根据本地数据进行调整。
  • 如果需要更具体的影响因素，还可以继续追问，让系统迭代并完善最终输出。

6. 分析结果交付与企业协同

a) AI生成的内容如何交付给老板或CEO？

  • 分析结果可以先下载，再接入企业现有IM系统。
  • 用户也可以直接将相关内容拖拽至IM或协作工具中，完成发布与分享。
  • 管理者能够在仪表盘、IM系统或手机端接收每日简报和分析结果。
  • 这一方式减少了人工整理报告、发送文件及跨系统传递数据的工作量。

b) 为什么统一平台可以缩短从数据到决策的链路？

  • 演示中的数据连接、治理、分析、搜索、内容生成和交付都在同一体系内完成。
  • 中间不需要等待其他团队发送数据，也无须反复进入不同的数据结果系统。
  • 所有工作基于：
  1. 同一套企业数据。
  2. 同一套安全体系。
  3. 同一套企业语义。
  4. 同一企业业务领域和上下文。
  • 统一平台可以降低数据搬运、口径转换和权限重新配置带来的效率损失。

c) 云端架构对企业AI能力有何价值？

  • 本次演示中的流程主要基于云端完成，并可在手机端操作。
  • 云端承载的数据、模型和应用越完整，AI能够调用的企业能力也越强。
  • 企业可以将自身业务体系与Snowflake的数据和AI工具结合，形成从日常经营监控到深度分析、再到管理层交付的闭环。
  • 该模式有助于企业更快进入以数据和AI驱动经营的下一阶段。

新版prompt提炼之后的转译

我们正处于一生中最激动人心的时代之一。技术正在快速变化和演进，重新定义每个组织能够实现的目标。3、4年前，AI或许主要用于提出问题并获取答案，但如今已发生根本变化。AI正在改变企业的经营方式。借助AI，组织内的每一项职能都可以变得更具生产力、更高效、更全面。我们希望展示Snowflake如何帮助各组织在这一过程中释放AI的价值。

归根结底，所有人都希望自己的组织取得更好的业务成果。我们将这种以AI为核心的企业称为“AI中心型企业”，即充分理解数据和AI的价值，并让所有人更加高效、更具生产力的企业。这正是本次讨论的背景。

行业中存在一个很大的误区。虽然情况正在改善，但在1年前，这种看法仍非常普遍：只要部署一个AI智能体，所有数据问题就会自行解决。由于AI似乎无所不能，这种设想听起来很简单，但现实并非如此。

AI是一项极其强大的技术，但并不是魔法。要使AI正确运行，需要坚实的基础、恰当的上下文和正确的数据。期待组织的数据战略自行完善并不是一种成功的方法。组织需要投入精力并构建相应架构，确保具备卓越的数据能力，进而形成卓越的AI能力。
