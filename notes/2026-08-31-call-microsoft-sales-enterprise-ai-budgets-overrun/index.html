专家访谈会议纪要

1. 企业AI预算与需求增长趋势

a) 2026年企业AI预算及使用量增长情况如何？

  • 本次访谈未披露客户AI预算的绝对金额，但从预算执行情况看，企业AI投入明显超出原计划
  • 客户主要覆盖零售、汽车、互联网及传统制造业，应用场景贯穿供应链、生产制造、研发、销售、客服及运营等环节
  • 对于采用预算制的传统企业：
  1. 2025年多家企业已多次追加AI预算，但仍出现预算不足
  2. 部分企业暂停其他项目，将预算转移至AI项目
  3. 截至2026年第二季度，多数客户已用完上一年度预算，并启动新一轮预算提升
  4. 整体AI用量基本实现翻倍；部分将传统研发转向AI研发的企业，用量增长超过10倍
  • 传统企业已经从“AI只能聊天、画图”的认知，转向“AI可以完成实际工作”，管理层的调研、试用和项目部署意愿显著增强
  • 从平均水平看，2026年AI Agent带来的收入预计增长3—4倍，个别企业增幅可能更高

b) 已较早部署AI的成熟企业增长情况如何？

  • 部分非预算制企业早在2022—2024年就已部署AI，主要用于智能客服、退货处理和线上问答机器人
  • 由于过去3年已经基本覆盖全部用户，这类企业当前业务量增幅相对有限，部分出海欧美项目增长约10%
  • 其工作重点已从“扩大用户覆盖”转向：
  1. 提高AI回答准确率
  2. 降低模型调用成本
  3. 提升企业毛利率
  4. 优化整体TCO，即总体拥有成本
  • 对成熟企业而言，AI投入可以增加，但单一业务场景的TCO不能上升，因此通常要求同步削减人员或其他运营开支

c) 2027年企业AI需求预计增长多少？

  • 预计2027年企业AI业务量及Token使用量仍可增长3—4倍，增速大概率不会明显放缓
  • 从过去数月表现看，整体月均环比增长约10%—20%，部分客户单月Token量环比增长可达10倍
  • 个别客户的Token量大幅增长后，转换为收入的增幅约为3—4倍
  • 企业级AI项目一旦上线，在当前财年内通常只会继续扩张，不会中途突然停止，因此增长具备较强持续性
  • 微软销售团队的2027财年目标也支持这一判断：
  1. AI Token相关收入目标整体较高
  2. 传统业务预计增长约1倍
  3. 互联网业务预计增长3—4倍
  4. 销售团队相关KPI要求增长约3倍
  • 专家认为上述目标相对保守，2027财年完成KPI的概率较高

d) 企业AI增长何时可能开始放缓？

  • 预计2026年和2027年仍处于强劲增长阶段，2028年以后增速可能开始放缓
  • 放缓主要来自两个因素：
  1. 单位Token价格下降，Token绝对使用量增长未必能完全转化为收入增长
  2. 场景成熟后，企业会重新评估哪些功能必须使用AI、哪些功能可以用传统技术完成
  • 当人员已基本完成优化后，企业无法再持续通过裁员抵消AI开支，只能进一步优化模型、工作流和调用方式
  • 因此，2028年以后企业关注点可能从“部署更多AI”转向“降低AI自身成本”

2. AI需求增速、季度表现与市场阶段

a) 当前企业AI需求是加速还是放缓？

  • 自然年第三季度仍保持增长，暑假对企业级市场影响较小
  • 从6月至9月的情况看，环比增长曲线基本未发生变化，未观察到明显降速
  • 节假日只会对零售、物流等特定行业产生阶段性影响，例如双11、黑五和圣诞促销季
  • 对大多数企业级场景而言，全年业务量相对稳定，增长主要由项目扩张和新场景上线驱动

b) 中国市场第二、第三季度同比增速如何？

  • 中国市场自然年第二季度AI相关开支同比增长超过20倍
  • 全球同比增速预计低于中国，但美国和中国仍是AI发展最快、市场规模最大的两个区域
  • 第三季度同比增速可能较第二季度有所回落，主要原因是去年同期基数已开始快速上升
  • 环比层面没有明显放缓，说明需求增长仍在持续，只是同比增速受到基数变化影响

c) 为什么AI市场会呈现阶段性爆发？

  • 市场通常由重大技术事件或产品突破触发新一轮增长
  • 相关事件使企业重新认识AI能力，并开始尝试此前无法落地的场景
  • OpenCloud（按原记录口径）的意义不在于客户直接使用其框架，而在于证明AI可以围绕目标自行拆解并执行任务
  • 企业由此认识到，AI不仅能对话，还能完成市场调研、报告撰写、PPT制作和任务执行
  • 每次技术事件引发一轮集中投入后，市场会进入相对稳定期，直至下一项技术突破再次推动增长

3. 模型选择、采购结构与价格变化

a) 国内出海企业主要使用哪些模型？

  • 对在美国、欧洲运营的国内企业而言，闭源模型仍占主导地位
  • 对未受到额外审查的美国分支机构，Azure渠道与OpenAI等模型的使用结构约为7:3，Azure占比较高
  • 在受到审查的情况下，相关云上收入结构可能转向约9:1，主要集中于GPT类模型
  • 微软和AWS也提供DeepSeek、Kimi、GLM等开源模型，但企业调用量相对较低

b) 为什么企业云客户仍更愿意使用闭源模型？

  • 企业认为灵活性、稳定性、可用性和服务保障比开源属性本身更重要
  • 如果确实要使用开源模型，企业更倾向于自行购买服务器和GPU部署，而不是通过第三方云平台调用
  • 通过云平台采购开源模型时，海外定价显著高于国内直接采购价，削弱了开源模型的价格优势
  • 闭源模型当前在效果上仍领先开源模型约6—8个月
  • 当实际价格差距缩小至数倍后，企业更愿意为更好的效果和稳定性支付溢价

c) 开源和闭源模型的价格差距发生了什么变化？

  • 此前按每百万Token计算，开源与闭源模型的价格差距约为10—30倍
  • 由于欧美闭源模型大幅降价，目前差距已缩小至约2—5倍
  • 企业通过微软等云服务商还可获得6折、7折等统一企业折扣，实际价差可能进一步缩小至约3倍
  • 对企业客户而言，较小的绝对价格差异通常不是主要决策因素，模型效果和企业级服务能力更重要

d) OpenAI和Claude等闭源模型的降价情况如何？

  • 从2026年6月起，欧美闭源模型已开始大幅降价：
  1. GPT系列平均降价约80%
  2. Claude系列平均降价约30%—40%
  3. 低端模型降幅较大，部分可达80%
  4. 高端模型降幅相对较小，约20%—30%
  • 预计自9月1日起还将有新一轮降价，价格竞争尚未结束
  • 此次降价为全球范围调整，通过不同采购渠道购买均会同步受到影响

e) Claude的渠道折扣策略发生了什么变化？

  • Claude官方标价未必全面下调，主要变化是将更多定价权授权给微软、AWS等渠道
  • 企业可直接与云服务商协商折扣，当前通常可获得10%—20%的优惠
  • 折扣水平与采购量承诺相关
  • 大型云服务商还可提供30—60天账期，进一步降低企业资金占用成本
  • 该模式正在冲击传统“号池”采购方式，未来大客户采购可能进一步向Oracle、Google、AWS和Azure等大型平台集中

f) 模型降价是否明显刺激了Token使用量？

  • 降价后Token使用量有所增加，但未观察到调用量立即跃升
  • 专家判断，即使不降价，当前Token使用量仍会沿原有趋势增长
  • 闭源模型降价更可能是为了应对开源模型在消费级市场的竞争，而非直接刺激企业客户使用
  • 企业级客户对价格敏感度相对较低，更关注模型稳定性、效果和工作流适配
  • 降价的影响可能体现为半年以上的长尾效应，而不是短期爆发

g) 为什么新模型降价后企业没有立即迁移？

  • 企业工作流一旦基于某一成熟模型完成调试，只要不出现问题，通常不会主动切换
  • 大量客户仍停留在GPT-4o等成熟模型阶段
  • 即使新模型价格下降，企业仍需重新测试准确性、稳定性和系统兼容性
  • 当前中国客户中，能够将2%—3%的用量从现有模型迁移至新模型，已属于较明显的迁移
  • 因此，企业级模型切换速度显著慢于消费级用户

4. Agent应用场景与ROI评估

a) 2027年AI Token开支增长的核心驱动力是什么？

  • 主要驱动力不是简单增加聊天机器人，而是AI开始进入过去难以应用的复杂任务
  • 新增场景包括：
  1. 制作标书和报告
  2. 调整机器设备参数
  3. 编写机器人或生产程序
  4. 开发求解器
  5. 市场调研和数据分析
  6. 运维监控和异常处理
  • AI在部分场景中已经能够达到人工效果的60%—80%，足以支持客户试点和逐步替代外包或内部重复劳动
  • 即使AI投入增长1倍，只要能减少1名员工或削减外包成本，整体TCO仍可能下降

b) 企业如何衡量办公类AI工具的ROI？

  • 对通用办公效率工具，企业通常不会逐项计算ROI
  • 这类工具更接近Office、PowerPoint等基础IT工具，被视为员工应当具备的标准配置
  • 企业主要关注其能否提升员工生产力、缩短工作时间及提高输出质量
  • 对具体业务项目，则必须设置明确目标，并量化收入增长、成本下降或人员替代效果

c) 面向消费者的AI功能如何计算ROI？

  • 智能摄像头是典型案例：
  1. 过去人脸识别和场景识别依赖本地模型
  2. 当前部分企业转向大模型，并将AI功能包装为订阅服务
  3. 欧美市场订阅价格通常约为9.99、15.99或16.99美元
  4. 假设AI成本约为5美元，只要订阅价格高于成本即可形成利润
  • AI功能还能提升硬件销量和订阅渗透率，因此企业会综合考虑订阅收入、硬件销售和前期研发投入

d) 智能客服项目的ROI如何计算？

  • 客服场景通常由运营或支持团队主导，而非消费者部门主导
  • 一个典型测算逻辑是：
  1. 将80%的客服流量导入AI
  2. AI解决其中80%的问题
  3. 相当于约64%—65%的整体任务无需人工处理
  4. 企业可先削减约50%的客服人员，再观察服务质量和运营稳定性
  • 只要AI成本低于被削减人员的工资、管理和区域运营成本，项目即可成立
  • 部分企业提出的目标包括：
  1. AI上线后单个客服处理量提升至原来的3倍以上
  2. 客服人员削减50%
  3. 激进企业计划削减80%的客服人员

e) 企业如何看待运维场景中的AI替代？

  • 运维场景推进速度慢于客服，因为AI无法承担责任，且部分运维人员具备不可替代的专业技能
  • 企业通常不会将完整技术架构和核心运维职责全部交给AI
  • 但AI已经广泛用于：
  1. 自动读取和分析报表
  2. 监测异常并触发通知
  3. 解释问题原因
  4. 提供解决方法
  5. 给出避免问题再次发生的建议
  • 重复性较强、需要一定经验、需接入多个数据源的运维工作，正在加速由Agent承担

f) 当前企业AI项目的ROI整体是否较高？

  • 当前能够获得预算并快速推进的项目，整体ROI相对明确
  • 从2025年开始，无法讲清ROI的项目审批和推进速度明显较慢
  • 销售团队也会优先投入能够清晰证明ROI、较快扩大使用量的项目
  • 企业级Agent市场目前仍属于蓝海，成熟场景有限，垂直行业仍存在较多机会
  • 预计未来1—3年，客服、RAG、运维等场景会逐步标准化，形成能够解决约80%问题的通用Agent
  • 场景成熟后利润空间会下降，行业资源将转向新的复杂场景

5. AI对数据库、存储及传统云服务的拉动

a) 为什么整体AI相关云收入增速可能高于Token收入增速？

  • 企业部署Agent后，除模型Token外，还会增加知识库、数据库、存储、API和计算资源的调用
  • 一个Agent执行任务时，通常需要：
  1. 查询数据库或知识库
  2. 对查询结果进行验证
  3. 发现错误后再次修正和查询
  4. 输出最终结果
  • 相比传统固定查询，AI工作流可能使查询量增加2倍甚至更多
  • 为避免AI查询冲击核心生产数据库，企业通常需要：
  1. 新建专门服务于AI的数据库
  2. 或对原数据库进行扩容
  • 扩容并非只增加CPU，还需同步增加内存、磁盘和IO资源，因此成本可能提高至原来的1.5—2倍

b) Harness和结果验证会带来哪些新增需求？

  • 企业级AI必须确保输出准确，不能只依赖第一次结果
  • Harness机制要求系统对输出进行复核、验证和修正
  • 该过程会显著增加：
  1. 数据库查询次数
  2. API调用量
  3. 输入输出量
  4. 后端计算和存储压力
  • 因此，AI带来的整体基础设施需求增长可能高于纯Token收入增长

c) 微软Fabric的发展情况如何？

  • Fabric被微软定位为战略级数据产品，对标Databricks
  • 目前尚不能简单定义为全面爆发，但其增速预计高于普通数据库产品
  • 微软通过销售激励推动Fabric增长：
  1. 销售Fabric可能获得约20%的价格或利润补贴
  2. 销售普通PostgreSQL等产品，补贴可能只有5%—10%
  • 当客户对底层产品没有明显偏好时，销售激励和价格优势会推动其选择Fabric
  • 随着AI对数据平台需求增加，Fabric有望成为AI相关收入的重要增长点

6. GPU供需、云上租卡与基础设施约束

a) 当前GPU需求是否旺盛？

  • 客户需求量并非无限增长，但市场确实面临严重的GPU无法交付问题
  • 训练类需求尤其明显，2026年春节前后，大量客户提出数千张GPU的集群需求
  • 主要需求方包括国内互联网科技公司、汽车企业和大模型研发企业
  • 小米等大型客户即使已自行进口大量高端GPU，仍存在明显算力缺口，并继续向微软寻求采购

b) 当前全球GPU供需缺口有多大？

  • 专家观察到的Azure云GPU供需缺口可能超过10倍
  • 典型情况是客户申请1,000张GPU，总部可能只批准10张
  • 但客户的最小可用集群可能需要64张，因此即使获得少量资源也无法实际使用
  • 中国区域的缺口可能达到10倍以上，部分大型客户的缺口更高
  • 微软财报中的待执行订单反映了部分未满足需求，其中GPU相关需求可能占约20%

c) 为什么微软有GPU库存却无法部署？

  • 当前瓶颈不仅是芯片数量，更包括电力、数据中心空间和地缘政治因素
  • 欧洲主要受到电力供应不足限制，部分数据中心有卡但无法上架
  • 中东原本是重要扩产区域，但受到战争和地缘风险影响
  • 亚洲电力条件较好的地区主要是中国，但受限制无法充分部署相关GPU
  • 新加坡等数据中心市场已接近容量上限，难以继续扩容
  • 因此，核心约束正在从“有没有GPU”转向“有没有电力和可部署的数据中心”

d) 缺少新一代GPU时，微软如何满足客户需求？

  • 微软有时会使用旧代GPU提供等效算力方案
  • 例如客户需要H200但无法提供时，可考虑用约2,000张A10替代
  • 旧代GPU数量更多，理论总算力可以接近，但会面临：
  1. 集群规模更大
  2. 调度复杂度更高
  3. 通信和调度损耗增加
  4. 实际性能低于理论等效水平
  • 对模型参数量较小的汽车和自动驾驶客户，此类替代方案有时可以满足约一半需求

e) 微软云上租用GPU的模式是什么？

  • 客户需先向微软销售提交GPU数量、用途和区域申请
  • 微软内部由销售与数据中心规划团队评估资源可用性
  • 审批通过后，通常签订3—5年使用合同
  • 合同采用订阅计费，签订后无论实际利用率高低均开始收费
  • 从单卡成本看，在微软云上使用约2年或略多于2年的费用，可能接近直接购买一张GPU的成本

  1. GDPR等海外数据保护要求
  2. 美国数据隔离和审查要求

  • 微软的价值不只在于服务稳定，还在于提供可信背书，减少审查、沟通和认证成本
  • 对欧美业务而言，这种合规和品牌背书往往比单纯价格更重要
