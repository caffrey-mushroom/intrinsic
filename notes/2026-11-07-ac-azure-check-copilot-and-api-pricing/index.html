核心摘要

  1. 专家拆分了Azure MaaS收入结构：OpenAI占比超过60%（此前约70%），Claude约9%（此前7–8%），开源模型约14–15%。

  4. 国内与海外云的定价策略不同，海外更看重用量绑定。

摘要

核心战略为“云+AI”捆绑销售，以低毛利 AI 产品带动高毛利传统云服务，复刻 Teams 增长逻辑。SaaS 商业模式演进：将从单一按席位收费转向“席位+API Token”复合模式，通过自研 Maia 芯片与高阶推理收费提升客单价。竞争壁垒由单一模型转向全堆栈能力：涵盖自研芯片、Agent 平台治理（权限/安全/审计）及存量 SaaS 数据生态，迁移成本极高。风险点：美国国会酝酿针对中国开源模型的全面限制政策。

Q&A

在MaaS（API Token）业务中，不同模型提供方的收入占比是怎样的？开源模型的增长趋势和客户采用情况如何？

在2027财年第一季度MaaS（API Token）业务近收入中，基于OAI GPT模型的调用收入占比超过60%。与2026财年全年OAI GPT模型占比70%的情况相比，本季度占比有所下降。基于Anthropic Claude模型的调用收入占比从2026财年的7%-8%上升至本季度的9%。剩余约20%至30%的收入来自第一方模型（如Mind-Think）及其他第三方模型（如Llama、Mistral等）。

从开源模型的角度看，其在一季度的收入占MaaS业务总收入的14%至15%，相较于2026财年全年10%的占比，增速较快，但从绝对值来看，基数仍然不高。目前，北美的大型企业客户高层（C-level）对开源模型普遍持谨慎态度，倾向于在涉及公司核心IP及机密敏感数据时使用闭源模型。

美国监管层面对于中国开源模型（如Kimi）的态度和潜在政策走向是怎样的？

目前美国国会内部正在酝酿一项针对中国开源模型（如Kimi）的潜在限制政策，但这只“靴子”尚未落地。该政策可能对美国本土的政府、企业及商业客户全面禁止使用此类模型。近期美国中期选举后，民主党在国会两院占据主导，可能会积极推动此类“一刀切”的政策。尽管现任总统尚有两年任期可能形成一定的制衡，但政策推进的趋势已经显现。此前，美国联邦政府及相关机构已发文，禁止联邦政府和部分机构接入包括Kimi在内的特定中国开源模型清单。预计这一态势将逐步推进，但最终是否会扩展至所有美国政府及企业级客户，尚无定论，相关消息可能在2027日历年出现。

公司当前的核心增长逻辑是什么，尤其是在云和AI业务的竞争壁垒方面是如何体现的？

公司的核心增长来源于将云服务与AI产品进行捆绑的打包销售逻辑。目前公司处于高业绩增长的承压阶段，而非利润承压阶段。公司的核心战略思想是“AI is just part of cloud”，即AI只是云业务的一部分。鉴于传统SaaS业务的毛利率可达70%-80%以上，PaaS为60%-70%，IaaS为50%-60%，而Azure AI和各类Copilot产品的毛利率仅为40%至接近50%，利润率相对较低。因此，公司采取的策略是以AI产品作为吸引客户的切入点，从而带动IaaS、PaaS、SaaS等高利润产品的整体销售，这与2020年利用Teams带动整体云服务销售的策略相似。

具体操作上，当客户表达对AI产品（如调用GPT-6或Claude模型进行二次开发）的需求时，销售团队（包括AE、STU、CSU及FDE）提供的第一版方案绝不会仅限于Azure AI或Copilot产品。方案中会包含Azure底层的IaaS、PaaS（如高阶云安全、数据池、数据湖）以及SaaS本体等高利润服务。如果客户接受这种打包方案，公司会提供一个基础折扣。在此之上，再根据客户的实际采购量、承诺用量以及与公司的战略合作关系（如签署MOU或研发路线一致性协议等），提供从5%到25%以上的阶梯式二次折扣，确保最终价格相比竞争对手具有优势。

这种打包逻辑旨在拉动整体业务的高速增长。对于公司这类云服务提供商，投资市场主要关注三个核心指标：一是收入增长是否达到或超过预期；二是成本控制，包括资本支出和利润表现；三是自由现金流能否保持正向。公司的这一策略正是为了在这些关键指标上表现出色，从而获得市场认可，正如财报发布后股价上涨所反映的那样。

公司AI业务的增长驱动力主要体现在哪些方面？其不同业务板块的收入构成和未来增长潜力如何？

公司AI业务的增长逻辑主要建立在“云加AI”的打包销售模式之上，这种模式是公司整体收入增长、利润平衡以及自由现金流持续增长的基础。

其次，展望未来，最大的增长点将来源于两个层面：

第一，SaaS订阅业务。公司的核心优势在于其SaaS产品组合，涵盖办公、会议、协同、视频、安全合规、ERP、CRM等多个领域，且均拥有较高的市场占有率。SaaS业务的增量将主要依赖于两方面：一是通过自研的Maia 300芯片实现成本降低；二是在下一个财年，最晚从下个财年开始，SaaS的收费模式将从单一的按坐席收费，转变为“坐席+API Token”的复合型消费方式。例如，目前E5版本若配置30美元的Copilot，总费用约八九十美元；E7版本（以M365为例）为99美元，已包含30美元的M365 Copilot，且API Token使用不受限制。未来，针对重工作负载、高分析或AGI场景的API Token使用将采用类似手机话费的模式进行额外收费，这将显著提升客单价和整体收入，构成一个高增长部分。

第二，平台服务。公司对自身的AI战略定位是成为AI时代的操作系统，类似于构筑AI时代的Windows。其底层平台能够接入并管理包括自研和第三方、闭源和开源在内的各类模型。平台之上的各个SaaS Copilot如同Windows上的应用软件，而Agent则可以在这些软件中贯穿运行。无论是现有的多模型编排、Copilot Fusion还是向量检索等技术，都是为了构建这一平台架构的软件部分。未来的核心增长与护城河将来源于这种平台架构，通过将模型的API Token、平台和SaaS进行深度集成，为客户提供一个统一界面来选择和使用不同的服务。

再次，算力租赁业务。如果OAI承诺的2000多亿RPO能够兑现，算力租赁无疑将是一个高增长领域。因此，算力租赁的增长前景在很大程度上取决于OAI和Anthropic等主要客户的履约情况。

最后，关于API Token业务，需要分为两个层面来看。对于标准化的、泛行业通用的API Token（如类GPT的通用模型），无论是OAI、Anthropic还是其他模型提供商，未来的趋势都是降价。

在MaaS（Model as a Service）时代，API token的定价逻辑和价格走势将如何演变，其增长驱动力是什么？

API token的定价可类比于云时代的IaaS（网络、计算、存储）。如同AWS、GCP及国内云厂商在IaaS层面技术能力趋同、主要进行价格与折扣竞争一样，MaaS中基础型或通用型泛行业模型的API token未来也将趋向IaaS化的发展路径，单价会下降，市场竞争激烈。相比之下，类似FDE这种需要驻场进行二次开发和二次训练的模型，以及针对医疗、政府、金融等领域的行业专用训练模型，其客单价则会上升。从整体逻辑看，MaaS API token的整体价格水平最多保持持平，甚至可能呈下降趋势，其增长将受到整体价格和市场趋势的影响。

在2011年至2022年的传统公有云时代，主要云服务提供商的竞争格局与定价策略有何不同？

在传统公有云时代，各主要CSP的竞争策略各有侧重。公司的核心优势在于打包竞争，将IaaS、PaaS与SaaS产品捆绑销售，定位为一家to-B公司，而非纯粹的互联网公司。AWS和GCP则更接近互联网公司的模式。

在公开标价的结构性降价方面，各家策略如下：

AWS的经典模式是，当硬件迭代、利用率提升导致单位成本摊薄后，会主动分批次、分区域下调EC2、S3、EBS等标准基础产品的价格，降价幅度通常在10%至20%区间，极少进行全产品线一次性大幅降价。

GCP基本跟随AWS的降价节奏，且跟进得更为紧密。

Azure则不盲目追随所有EC2的降价，其降价优先在拉美、亚洲等价格竞争激烈的区域进行，以调整算力标价。而在成熟的北美和西欧市场，其标价相对稳定，价格空间更多地体现在捆绑销售中，而非下调单价（unit price）。价格调整通常不是通过大范围调整价格列表，而是通过控制价格折扣的深浅来实现。

GCP则一直采用自动持续折扣（automatic sustained use discounts），客户使用时间越长，自动享受折扣，无需提前承诺。

公开标价的降价主要是向市场传递规模红利，是价格上限，而最终成交价则取决于各企业的具体协议。

在针对长期承诺合约（如与B级客户签订的三年期EA）的折扣体系方面：

AWS主要通过Savings Plans和预留实例（Reserved Instances），客户承诺一至三年的保底消费，可获得最高60%至70%的有效折扣。对于面向容错和离线批处理负载的竞价实例，折扣可低至两三折，但SLA不作保证。

Azure的价格折扣主要与客户年度承诺用量挂钩，客户通常签订三年合约，可分期支付。用量高则次年可调整价格，用量未达标则可能提升价格，通过价格折扣而非直接降价或定价来进行杠杆调节。

GCP主要采用承诺使用折扣，对一年、三年、五年的使用承诺提供最高70%的折扣，并可与自动折扣叠加，无需强制承诺。

总而言之，前三大CSP均通过深度折扣来锁定多年期的收入和现金流，稳定机房利用率。B级客户则通过锁定使用量来换取成本的确定性。折扣的深度与承诺周期及保底金额强相关，并非简单地价低者得。

为何在传统公有云时代，北美市场的云服务价格相对稳定？

北美市场云服务价格相对稳定的原因主要有三点。首先，北美地区的数据中心规划和建设速度较快，在2011年至2017年间已基本完成布局。2017年后，三大CSP的IaaS、PaaS、SaaS产品线趋于稳定，无需快速扩容DC，从而减轻了成本摊薄的压力，为价格稳定甚至持续降价提供了空间。相比之下，国内云厂商目前仍处于云时代的中前期阶段。

其次，北美和欧洲市场的B级客户养成了良好的订阅付费和续约习惯。这使得公司的Office M365和Azure等产品能够维持较高的定价、付费率和续费率。

最后，北美的CSP厂商倾向于将云产品与AI产品集成为一整套矩阵化方案进行销售，以适应B级客户的采购模式。与此形成对比的是，国内的云厂商和应用厂商受过去十几年互联网发展逻辑的影响，倾向于将B端产品拆分成单个C端应用的形式进行售卖。这种“格列去卖”的模式，即将底层的云、GPU算力、模型、SaaS本体、Copilot及Agent等各层级产品拆分单独销售，虽然突出了核心优势产品，但也导致B端客户对价格极为敏感，削弱了客户粘性。这种销售模式的差异，结合数据中心规模和成本压力，共同影响了不同市场的价格稳定性。

与国内云厂商相比，公司的毛利率水平和定价策略有何不同？

公司的SaaS毛利率可达70%-80%，PaaS为60%-70%，IaaS为50%-60%。相比之下，国内BAT等云厂商的IaaS毛利率能达到20%已属不易，PaaS稍高。这种毛利率上的差异制约了国内厂商的价格与成本之间的作用力，也解释了为何公司能够在价格保持相对稳定甚至可以降价的同时，利润仍能保持甚至有所提升。

国内外大型企业客户在采购云与AI服务时的关注点有何显著差异？这种差异是否源于国内劳动力成本较低？

国内外客户的关注点存在显著差异。多数国内大型企业客户C-level高管主要关注两点：第一，产品相较于其他厂商能提供多大的折扣；第二，使用AI产品后能具体节省多少人力与资金成本。他们倾向于将云和AI视为一种生产力工具或应用。相比之下，北美、西欧及亚太地区亲美发达国家的C-level高管更关注战略价值，他们将价格和折扣问题交由CFO或采购部门处理，而自身则聚焦于云平台（IaaS, PaaS, SaaS）如何贯穿整合，解决企业前、中、后台的数据孤岛问题。他们关心AI（无论是Copilot还是基于标准模型的二次开发模型）在云基础之上能为公司的发展方向、核心KPI预测以及业务模态预测带来多大的增速，以及云与AI在端到端解决数据孤岛问题上的整体性和矩阵化能力。这些客户将云和AI视为公司级的平台载体，而不仅仅是单个工具或应用。这种差异并非源于劳动力成本，其根源在于国内软件和云服务市场早期的发展模式。国内市场起初普遍采用项目制，针对某个部门（如IT或财务）的特定升级需求进行单点切入。这种模式导致客户形成了碎片化的采购思维，习惯于就单个项目进行询价和压价，例如利用腾讯云或百度云的价格来压低阿里云的报价。在这种环境下，云厂商缺乏足够的议价能力去阐述其产品在技术、整体解决方案（如整合高阶云安全、数据分析及SaaS应用）以及综合性能提升方面的价值，导致市场在一定程度上偏离了整体化、平台化的发展路径。

海外大型企业（如世界500强）普遍采用混合云和多云架构，其选择不同云服务商背后的决策逻辑是什么？是基于不同云厂商适用于不同应用场景的考量吗？

首先需要明确混合云（Hybrid Cloud）与多云（Multi-cloud）是两个不同的概念。混合云指的是公有云与私有云的结合。对于有数据隐私、高敏感信息、核心IP或专利保护需求的B端或G端客户，其部分数据不允许接入公网，必须通过私有云或混合云的私有化部署部分来保障安全，例如使用Azure Stack、HCI等产品。云服务的本质在于将客户数据上传、下载并进行托管，从而减少其在本地自建大型服务器所需的大量IT支出。然而，基于信息安全与合规的敏感度，混合云架构应运而生，它既能利用云服务商的公有云服务器进行数据托管，又能通过本地的微型或迷你机柜等方式保留部分数据。

多云则通常发生在IaaS层面，部分也涉及PaaS。由于当前IaaS市场的同质化现象较为严重，各主要云厂商（如Azure、AWS、GCP）在功能上大同小异，竞争核心在于价格折扣。因此，客户倾向于同时采购多家云服务，例如一部分Azure、一部分AWS和一部分Google Cloud。由于各平台功能相似，整合难度不大。这种策略使得客户在与任何一家云厂商进行续约谈判时，都能以其他厂商提供的更优惠折扣作为议价筹码，从而获得更有利的合同条款。这构成了云时代客户采购的一个基础逻辑。

在IaaS层面趋于同质化的背景下，各云服务商在PaaS和SaaS层面存在哪些差异化优势？

各家云服务商在PaaS和SaaS层面确实具备各自的优势领域。以微软为例，在SaaS办公协同领域，尽管Google拥有Workplace，但微软的Office套件仍具有强大的市场优势，而其他竞争对手在该领域的影响力相对有限。在CRM领域（如D 365），虽然Salesforce等厂商实力更强，但微软的产品也具备相当的竞争力。

微软在云安全与合规产品方面优势显著，拥有全球覆盖范围最广、产品序列最全的产品矩阵。其单点产品，如防火墙、杀毒软件、全时管理及分布式管理等，与赛门铁克这类专业的网络信息安全厂商相比也毫不逊色。更重要的是，微软的安全合规产品体系完全构建于Azu re之上，能够为自身的IaaS、PaaS和SaaS服务提供内置化、内嵌式的合规保障。

总结而言，虽然各家厂商各有所长，但微软的核心优势在于其产品线的全面性——几乎覆盖所有领域，且在每个领域都保持了不俗的竞争力。通过将这些产品打包，以一个整体平台和矩阵化的逻辑提供给客户，构成了其最核心的竞争优势。

在传统云时代，行业的核心壁垒是什么？进入AI时代后，这些壁垒又发生了怎样的演变？

在传统云时代，行业的核心壁垒主要体现在以下几个方面：

首先，最核心的壁垒源于B端客户存量软件资产所带来的高昂切换成本。以Azure为例，其早期最持久的护城河在于，大量客户在软件时代已经深度使用微软的Win Server、SQL Server、Active Directory、Office等产品。当这些客户向云迁移时，将其部署在原有微软软件体系上的海量数据迁移至Azure，可以实现后台的无缝衔接。相比之下，若将这些数据迁移至AWS或GCP，其总拥有成本将比迁移至Azure高出至少2.5倍。这种低迁移成本和无缝衔接构成了最初的核心优势。

其次，随着市场发展，壁垒逐渐演变为规模化的基础设施和资本投入所形成的成本优势。

最后，企业级渠道、合作伙伴生态以及完善的安全合规治理产品矩阵也构成了各家厂商的重要壁垒。

进入AI时代后，这些壁垒正在发生转变。首先，独家模型本身已不再构成壁垒，因为对于B端客户而言，模型的选择变得更加多样化。

在AI时代，传统云厂商的竞争壁垒正在发生哪些变化？哪些原有壁垒在减弱，而哪些又在被放大和巩固？

在AI时代，传统云厂商的竞争壁垒正在经历结构性变化。部分原有壁垒的权重在下降，而另一些壁垒的价值则在提升。

壁垒权重下降的方面主要体现在：

首先，模型的选择多样化削弱了单一模型的锁定效应。企业级和政府客户现在可以自由选择一方或三方模型，例如Anthropic的模型，这打破了类似过去Windows时代单一操作系统的垄断模式。

其次，底层算力的供给渠道分流。传统云时代，CSP的核心竞争力之一是自建数据中心的规模和覆盖范围。而现在，除了自建，还可以向CoreWeave、Lambda等第三方“New Cloud”租赁算力，这意味着不必完全依赖自建海量数据中心或单一供应商采购GPU。例如，公司在一季度将资本支出预期从500亿美元下调了50亿，部分原因就是由于从CoreWeave和Lambda等第三方获取的算力供应延迟到了第二、三季度。

最后，IaaS层的权重在降低。AI的许多负载，如无状态的训练和推理集群，对传统IaaS功能的锁定效应较弱。如果企业客户只采购GPU运行模型，而不绑定其他存量服务，其成本会低于传统的企业级业务。在某些简单的AI任务中，CPU甚至可以替代GPU，这意味着传统以IaaS为基础的业务推进模式受到了挑战。

壁垒价值被放大的方面主要体现在：

首先，SaaS业务中的存量席位、企业数据及身份权限链路的价值显著提升。AI的核心是数据，拥有海量数据的厂商能训练出更强的细分模型。SaaS席位为未来的推理侧应用提供了广泛的部署基础，而身份验证与权限安全则是保障体系。

其次，混合云与多云模式的壁垒进一步加高。以Azure Arc为代表的混合云能力，能够在包含GCP、AWS等多个云服务商的复杂客户环境中，实现无缝衔接与数据迁移。在AI时代，支持公有云与私有云混合部署，并能在开源与闭源模型间灵活切换变得至关重要。将数据保留在隔离边界内、支持完全离线运行的模式，已成为一项硬性准入门槛，这是中小型算力厂商和应用商难以做到的。

最后，长期消费承诺的价值在提升。随着SaaS本体及其AI服务的价格预计将上涨，无论是按席位还是按API Token计费，客户越早锁定长期合同就越有优势。2026年第一季度M365及M365 Copilot的增长，主要驱动力就来自财富500强和EC中的大客户，这些客户将采购量从几千席位扩大到数万甚至一二十万席位，其核心动机之一就是锁定当前价格，以应对未来可能的价格上涨。

在当前AI驱动的竞争格局下，头部CSP厂商的核心壁垒具体体现在哪些方面？

头部CSP厂商在AI时代的核心壁垒主要体现在三个层面：全堆栈的软硬一体化能力、面向企业级Agent的平台治理能力，以及端到端的商业模式。

第一，构建了全堆栈、软硬一体的AI矩阵，可概括为“1+1+1 > 3”的模式。第一个“1”指硬件层面，涵盖自研GPU（如Maya）、自研CPU（如Cobalt），以及以Copilot+ PC为代表的端侧载体（包括Surface和OEM厂商如戴尔、HPE的产品）。第二个“1”指模型层面，不仅提供自研的第一方模型，还集成了最先进的第三方模型，并正在针对医疗、金融、政府等关键行业，循序渐进地训练垂直领域模型。第三个“1”指应用层面，即全面覆盖各类场景的Copilot应用。这三者结合旨在形成一个AIOS平台，底层可调用所有模型，上层可使用所有应用工具，并同步构建Agent。这种端到端的把控能力覆盖了从训练/推理芯片、机房架构到成本控制、算力调度和交付效率的全流程。在GPU供给受限的周期内，这意味着在同等的电力、机柜和芯片配额下，能够产出更多的Token，实现更高的GPU利用率和资本效率。目前，只有AWS、GCP和微软具备构建这种完整体系的能力。

第二，具备强大的Agent平台治理能力。这套体系以Foundry、Fabric、Copilot Studio和Preview等产品为核心，构建了AI时代的操作系统。客户的核心痛点已从简单地运行大模型，转变为如何在标准化大模型基础上，灌注自身核心数据进行二次开发和训练，并在此之上构建和管理多个企业内安全运行的智能体。这要求平台必须能确保Agent不越过数据访问权限，所有操作留痕以满足监管，防止数据泄露，并平衡成本。这套复杂的工作流平台，包括模型评估、数据集管理、权限约束、审计规则和数据管道等，难以被复制或迁移，目前只有少数几家头部CSP能够提供。

第三，形成了“席位+ API Token消耗”的复合商业模式。与AWS相比，微软和Google（因其Workplace）在SaaS层面具备优势。这种模式下，客户为标准化的SaaS功能支付席位费，而高阶的推理应用则通过类似手机话费模式的API Token消耗来付费。这种将SaaS的存量优势与AI服务的增量消耗相结合的商业模式，是NVIDIA、OpenAI、Anthropic等其他维度的厂商难以复制的。
