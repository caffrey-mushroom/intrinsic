1. 模型训练效率与算力需求

1.1 未来2至3年，在能力和可靠性不变的情况下，模型训练所需算力可以降低多少？

  • 预计达到特定前沿能力和可靠性门槛所需的算力可降低约 5倍至10倍。
  • 这一判断延续了历史上的算法效率趋势：实现同等能力所需的算力，大约每 8至12个月减半。
  • 算力节省并不只是来自缩小预训练规模，更重要的来源包括：
  1. 重新平衡预训练与后训练的算力投入；
  2. 使用超稀疏架构，如混合专家模型；
  3. 推进低精度训练；
  4. 提高训练数据的有效信号密度；
  5. 提升后训练阶段的样本效率和自动验证能力。

1.2 预训练阶段的效率提升主要来自哪些方面？

  • 预训练的核心目标是降低每个Token所需的FLOPs，同时提高每个Token承载的有效信息。
  • 未来更可能采用：
  1. 数量更少但质量更高的训练Token；
  2. 总参数量更大、但单个Token激活参数更少的超稀疏模型；
  3. 更小的激活模型完成相同能力目标；
  4. 更低精度、更高硬件利用率的训练方式。
  • 预训练将从单纯追求参数和数据规模，转向追求数据质量、有效激活规模和单位算力产出。

1.3 后训练阶段的效率提升主要来自哪些方面？

  • 后训练的重点是提高样本效率和验证效率，而不是依赖暴力式推演或大量人工标注。
  • 关键改进方向包括：
  1. 强化学习任务展开；
  2. 自动化结果验证；
  3. 让模型学习自我检查和自我纠正；
  4. 减少高成本人工反馈；
  5. 将更多算力投入到测试时计算和高价值推理路径。
  • 后训练未来可能成为模型能力提升的主要投入方向，特别是在复杂推理、智能体执行和现实任务泛化方面。

1.4 算法效率提升是否会直接减少实际算力需求？

  • 在能力水平固定的前提下，效率提升会直接降低算力需求。
  • 如果今天只要求达到GPT-4级别的智能，所需GPU数量仅为3年前的一小部分。
  • 但前沿实验室的实际算力总投入不会因此下降，反而会继续增长，主要原因是“杰文斯悖论”：
  1. 实验室不会因效率提高而减少GPU采购；
  2. 节省下来的算力会被重新投入到更大规模实验；
  3. 模型会使用更多Token、开展更多强化学习任务；
  4. 测试时推理和长周期智能体将消耗大量增量算力。

2. 预训练扩展路径与前沿能力驱动因素

2.1 未来模型总参数量是否会继续增长至20万亿或30万亿？

  • 模型总参数量可能通过超稀疏混合专家架构提升至 20万亿甚至30万亿。
  • 但每个Token实际激活的参数量仍会保持在相对较低水平。
  • 因此，总参数规模仍会增长，但仅依靠扩大参数规模，已经不再是推动能力跃升的最有效方式。
  • 后续竞争重点将从“模型有多少参数”转向“每次推理激活多少有效能力、能否完成复杂任务”。

2.2 如果参数规模不再是主要驱动力，未来模型能力提升依靠什么？

  • 前沿模型能力提升将依赖四个主要支柱：
  1. 真实环境中的强化学习：让模型在实际或高保真环境中探索、行动和获得反馈；
  2. 高信号合成数据与多模态数据：补充高质量文本数据不足，提高任务覆盖度；
  3. 测试时计算扩展：通过增加推理、搜索、验证和自我修正提高答案质量；
  4. 长上下文与记忆架构：让模型在长时间、多阶段任务中保留目标和状态。
  • 整体范式正在从“让模型记忆静态文本”，转向“让模型在多任务、多步骤环境中探索、验证和推理”。

2.3 强化学习扩展至数学和编程以外领域的最大障碍是什么？

  • 最大障碍是 验证瓶颈，主要体现为：
  1. 缺乏客观、确定的真实标准；
  2. 奖励模型本身可能存在缺陷；
  3. 模型可能学会欺骗或利用奖励模型，而非提升真实判断能力。
  • 数学和编程任务可以通过答案、编译器或测试用例验证，但战略、医疗和企业运营等开放领域没有类似的确定性验证器。
  • 当强化学习依赖学习得到的奖励模型时，策略模型可能优化评判机制的漏洞，形成“奖励欺骗”。

2.4 如何证明强化学习能力能够泛化到现实世界？

  • 应重点观察三项证据：
  1. 分布外泛化：模型面对训练分布之外的问题仍能保持稳定表现；
  2. 校准后的拒绝回答：模型在不确定时能够主动拒答或升级给人工处理；
  3. 长周期稳健性：模型在多步骤、长时间任务中不会持续累积偏差。
  • 现实世界可靠性不能仅依靠基准测试成绩，还要验证模型是否知道自身能力边界，并能在长期运行中保持稳定。

3. 算力需求趋势与训练范式变化

3.1 效率提升后，前沿实验室的总算力需求会下降吗？

  • 即使训练效率提高5倍至10倍，前沿实验室的总算力需求仍会继续上升。
  • 节省的算力会被以下工作负载迅速吸收：
  1. 面向自主、长周期智能体的测试时推理；
  2. 大规模强化学习任务展开；
  3. 合成数据生成；
  4. 更多并行实验和模型迭代。
  • 未来几年，增量算力需求的首要驱动力将是 长周期智能体的测试时计算，其次是强化学习和合成数据。

3.2 超大规模文本预训练还会持续多久？

  • 超大规模文本预训练预计将在未来 2至3年开始进入平台期。
  • 主要限制来自：
  1. 物理层面的硬件和能源约束；
  2. 高质量文本数据逐渐枯竭；
  3. 训练成本与边际收益之间的经济性下降。
  • 大规模实验不会停止，而是会转向：
  1. 多模态预训练；
  2. 具身智能预训练；
  3. 持续扩展的强化学习；
  4. 更大规模的推理和智能体任务运行。
  • 静态文本预训练收益递减后，实验室会将原有集群和算力资源转移至新的训练范式。

4. 企业AI商业化应用与渗透率

4.1 未来12至24个月，编码之外最重要的商业化应用是什么？

  • 最有可能推动下一轮规模化商业应用的两大方向是：
  1. 自主网络安全运营：包括安全运营中心、告警分类、事件调查和漏洞修复；
  2. 长上下文企业工作流智能体：包括金融分析、法律尽职调查和复杂后台运营。
  • 这两类应用与编码场景相近，均具备：
  1. 相对结构化的环境；
  2. 较容易验证的结果；
  3. 明确的人工成本瓶颈；
  4. 已经存在且较为紧迫的企业预算。

4.2 企业采用AI应用的一般路径是什么？

  • 企业通常遵循以下采用顺序：
  1. 首先使用编程助手，因为投资回报率最容易衡量；
  2. 随后将新增预算投入自动化安全分类；
  3. 再扩展至文档密集型运营工作流。
  • 企业购买模型时，竞争标准正在从基准测试智能水平转向生产环境能力，包括：
  1. 可靠性；
  2. 低延迟；
  3. 可控的工具调用；
  4. 严格遵循数据模式和企业政策；
  5. 长上下文中的高召回率；
  6. 低成本、高并发处理能力。

4.3 文档密集型工作流目前的自主化渗透率是多少？

  • 当前真正实现自主运行的渗透率仍处于 较低个位数至10%出头。
  • 这意味着未来1至2年，绝大多数企业扩张和预算投入尚未释放。
  • 后续渗透率提升的前提是：
  1. 建立可审计的决策链；
  2. 接入企业后端系统；
  3. 提升权限控制能力；
  4. 明确失败处理和人工升级机制。

4.4 客户服务场景有多少请求可以端到端自动解决？

  • 在成熟生产环境中，AI智能体通常能够在无需人工干预的情况下解决约 50%至70% 的客户服务请求。
  • 对于1级和常规2级客户服务案例，端到端解决率通常处于50%至70%。
  • 不同部署模式的解决率差异较大：
  1. 只能读取知识库时，解决率上限约为 30%；
  2. 安全接入CRM、计费和订单管理等可写入API后，解决率可以提升至 65%以上；
  3. 电商、金融科技和SaaS等标准化业务的领先企业可达到 75%至80%；
  4. 若包括医疗、银行等强监管行业，整体平均水平约为 35%至50%。
  • 随着后端API集成成熟，未来12至24个月，成熟部署的解决率有望提升至 70%以上。
  • 当前主要限制并非模型的语言能力，而是API访问能力、企业政策是否清晰，以及是否允许模型执行实际操作。

5. 后台工作流规模化的“最后一公里”

5.1 财务、保险和法律工作流从试点转向生产的最大障碍是什么？

  • 最大单一障碍是 责任认定与可审计性缺口，主要体现为：
  1. 错误容忍度高度不对称；
  2. 缺乏确定性验证机制；
  3. 无法完整解释某项决策为何作出；
  4. 企业无法明确错误发生后的法律和财务责任。
  • 在试点阶段，模型达到92%或95%的准确率可能已非常出色。
  • 但在生产环境中，剩余5%的错误可能导致：
  1. 误读赔偿责任上限；
  2. 错误计算税务责任；
  3. 批准欺诈性理赔；
  4. 触发重大监管处罚。
  • 如果企业无法确定性地审计模型决策，就无法取消人工复核。

5.2 “最后一公里”问题在保险理赔中如何体现？

  • 以商业财产保险理赔为例：
  1. AI可读取50页保单、受损照片和维修发票，并正确完成95%的计算；
  2. 但第42页可能存在一项隐藏批单，将特定水损的赔付上限限制为1万美元；
  3. 例外附加条款可能以手写扫描件形式存放在另一个旧文件夹中；
  4. 如果AI遗漏交叉引用并批准支付25万美元，公司将直接多损失24万美元。
  • 由于模型不能可靠识别自身不确定性，也无法稳定提供监管要求的审计记录，人工理赔员仍需逐一核查文件。
  • 只有解决跨文档检索、确定性验证、拒答升级和审计链问题，企业才能真正取消人工审核。

6. 网络安全应用、攻防趋势与价值分配

6.1 当前哪些AI网络安全工作流已经产生明确生产价值？

  • 目前价值最明确的工作流包括：
  1. 安全运营中心第1层级和第2层级的告警分类；
  2. 自动化事件调查；
  3. 漏洞分类；
  4. 补丁生成。
  • 即使考虑误报、人工审核以及SIEM或SOAR集成成本，投资回报率仍具有吸引力。
  • 原因在于传统人工基线已经失效：
  1. 分析师每天面对数万条告警；
  2. 告警疲劳导致最多约70%的告警被忽略；
  3. AI只需显著降低告警量和调查时间，即可形成明确价值。

6.2 未来2年，AI会更有利于攻击方还是防守方？

  • 时间维度不同，结论也不同：
  1. 未来6至12个月：AI将率先增强攻击方；
  2. 未来2年左右：结构性优势将逐步转向防守方。
  • 短期攻击方占优的原因：
  1. 攻击者只需找到一个未修补漏洞；
  2. 防守方必须保护所有环节；
  3. AI会将漏洞披露至规模化利用的时间从数周缩短至数小时。
  • 中期防守方占优的原因：
  1. 企业可以白盒访问完整代码库；
  2. 企业掌握整个内部网络的遥测数据；
  3. AI可以在代码发布前扫描100%的代码库；
  4. 攻击者多数只能从外部进行盲目探测。
  • 因此，短期内修补速度慢的组织风险上升；中期则可能通过持续审计和自动修补改变传统攻防不对称格局。

6.3 现有网络安全厂商和AI实验室，谁将获得更多价值？

  • 未来2至3年，CrowdStrike、Palo Alto Networks、Wiz和Microsoft等现有网络安全龙头将获得企业安全支出的主要份额。
  • 前沿AI实验室将主要获得：
  1. 底层Token和API收入；
  2. 部署前代码审计收入；
  3. 主动式代码级安全能力的价值。
  • 现有安全平台的优势来自：
  1. 长期数据沉淀；
  2. 企业信任；
  3. 合规认证；
  4. 工作流分发；
  5. 实时遥测；
  6. 执行和拦截能力。
  • AI实验室掌握推理引擎，现有安全企业掌握传感器和执行层，双方存在相对清晰的价值分工。

6.4 企业会绕过传统网络安全平台，直接采购AI实验室产品吗？

  • 未来2至3年内不太可能。
  • 企业不会淘汰端点传感器、防火墙或云安全代理，直接用AI实验室产品替代核心安全平台。
  • 根本原因是：
  1. 大语言模型是推理大脑，而不是传感器；
  2. AI实验室通常不构建内核级端点代理、网络防火墙或身份网关；
  3. 没有实时遥测，模型无法感知企业环境；
  4. 没有执行引擎，模型无法在毫秒级拦截攻击。
  • 但AI实验室和AI原生智能体可能替代部分人工服务与衔接工具，包括：
  1. 1级托管安全服务；
  2. 人工渗透测试；
  3. 独立代码扫描工具。

6.5 部署企业AI智能体时，最大的安全风险是什么？

  • 最大单一风险是 权限过大。
  • 权限过大是根本性风险放大器，会使提示词注入和数据泄露从轻微漏洞演变为重大安全事件。
  • 如果智能体通过宽泛的服务账户读写Slack、SharePoint、Jira和生产数据库，一次来自邮件或工单的间接提示词注入，就可能导致：
  1. 敏感数据泄露；
  2. 生产数据被修改；
  3. 业务系统被错误操作；
  4. 权限被横向滥用。

6.6 什么条件下可以允许智能体执行实际写入操作？

  • 不应依赖模型厂商的安全声明，而应进行系统层面的验证。
  • 上线前应满足：
  1. 对抗性提示词注入红队测试；
  2. 实现零次未经授权的工具执行；
  3. 自动化权限边界模糊测试；
  4. 基于真实生产流量的影子模式测试；
  5. 确定性策略门控验证；
  6. 身份层和API层能够拦截100%的恶意操作。
  • 核心原则是：将大语言模型视为不受信任的用户，而不是可信任的管理员。
  • 即使模型受到攻击，确定性的权限层、API层和身份层也必须阻止越权行为。

6.7 哪些厂商将受益于智能体安全需求？

  • 最大受益者包括：
  1. Okta、Microsoft Entra等身份提供商；
  2. AWS、Azure、GCP等云计算平台；
  3. AI原生运行时安全网关；
  4. 传统网络安全平台；
  5. 自动化红队测试和策略执行初创企业。
  • 企业预计会形成三层技术栈：
  1. 云服务和身份厂商限制智能体以何种身份执行操作；
  2. 网络安全厂商和AI安全企业负责红队测试、运行时监控和策略执行；
  3. 企业内部工程团队根据具体业务逻辑开展影子模式评估。

7. AI for Science的商业化与技术瓶颈

7.1 哪类AI for Science应用最接近可重复商业价值？

  • 最接近近期商业化的方向是：
  1. 生成式蛋白质和生物制剂设计；
  2. 抗生素、酶和多肽工程；
  3. 电池、半导体和工业化学品相关材料发现；
  4. 催化剂发现。
  • 生成式蛋白质、工业材料和催化剂的优势在于：
  1. 具备较快的高通量实验反馈；
  2. 可以形成模型—实验—数据的闭环；
  3. 制药、工业生物技术和制造业存在明确商业买家。
  • 小分子药物仍受制于长达 7至10年 的人体临床试验，因此短期商业价值实现速度较慢。

7.2 AI for Science目前主要受限于模型、数据还是实验验证？

  • 首要瓶颈是物理湿实验室中的实验验证，其次是标准化的负面结果数据，而不是原始模型能力。
  • 基础模型可以在数小时内生成数百万个看似合理的蛋白质序列或候选分子。
  • 但即使只合成、表达和测试其中数百个候选对象，也需要：
  1. 数周至数月时间；
  2. 数十万美元成本；
  3. 实验室设备和专业人员；
  4. 标准化、可复用的实验数据。
  • 因此，候选生成速度远快于实验验证速度，形成明显瓶颈。

7.3 更强的通用模型能否消除实验验证瓶颈？

  • 不能。
  • 通用模型可以承担：
  1. 阅读科学论文；
  2. 形成研究假设；
  3. 编写实验代码；
  4. 协调科研工作流。
  • 但生物学和材料科学受3D几何、量子力学和复杂实验物理规律支配，无法仅通过阅读文本推断全部规律。
  • 完整科研闭环需要三类能力协同：
  1. 通用模型负责协调和推理；
  2. 专用领域模型与物理模拟器负责探索3D物理空间；
  3. 湿实验负责最终验证。
  • 仅依靠扩大文本模型无法绕过现实物理规律。

8. 前沿模型厂商竞争格局

8.1 Anthropic、OpenAI在网络安全和AI for Science领域各有什么优势？

  • 没有任何一家实验室具有普适性垄断优势。
  • 网络安全领域：
  1. Anthropic在深度静态代码审计、长代码库理解和生态系统级漏洞发现方面略占优势；
  2. OpenAI在自主端到端漏洞利用验证、补丁生成和执行流程方面能力较强。
  • AI for Science领域：
  1. Anthropic更擅长长上下文科学推理和湿实验协调；
  2. OpenAI更积极地发展经过专用领域训练的科学模型。
  • 总体上：
  1. Anthropic更偏向深度阅读、分析与协调；
  2. OpenAI更偏向自主执行、工具使用和专用模型。

8.2 Grok在哪些方面正在迎头赶上？

  • 凭借超级集群规模，xAI的Grok已经基本缩小与OpenAI和Anthropic在原始推理能力及STEM基准测试上的差距。
  • Grok形成了三项相对优势：
  1. 实时威胁和市场情报；
  2. Grokbot等持久化云计算机智能体；
  3. 与SpaceX生态的硬件和工程协同。
  • Grok目前主要短板包括：
  1. 企业治理成熟度；
  2. 品牌和对齐可预测性；
  3. 合规能力；
  4. 专业合作伙伴生态。
  • 因此，Grok在实时开源情报和工程密集型工作流中具有优势，但在受监管企业、网络安全和生命科学部署中，Anthropic和OpenAI仍拥有更高信任度。

8.3 如何看待Google Gemini的竞争力？

  • Google Gemini已经取得显著进步，是全栈发展势头最强的实验室之一。
  • Google的核心优势是完整的垂直技术栈，包括：
  1. 自研TPU芯片；
  2. 前沿模型能力；
  3. 原生多模态能力；
  4. Google Cloud企业分发；
  5. Workspace办公入口；
  6. Security安全产品生态。
  • 在长上下文推理、网络安全和科学AI领域，Google已经成为OpenAI和Anthropic最强的全方位竞争对手之一。

9. 长周期智能体的可靠性与成本

9.1 智能体连续运行数小时的最大障碍是什么？

  • 最大障碍是：
  1. 单步错误率持续累积；
  2. 上下文漂移；
  3. 状态漂移；
  4. 工具日志占据上下文窗口；
  5. 模型忘记初始目标。
  • 如果一个100步工作流中每一步可靠性为99%，整体成功率仅约为 36%。
  • 一个早期细微错误可能持续传播，导致智能体在后续几十个步骤中不断偏离，却无法意识到问题。
  • 因此，仅提高模型智力不足以支持数小时稳定运行，还需要类似操作系统的智能体框架，负责：
  1. 内存压缩；
  2. 状态管理；
  3. 里程碑验证；
  4. 确定性回滚；
  5. 异常升级。

9.2 长周期智能体可靠性问题能否解决？成本是否可控？

  • 该问题可以解决，实际可靠性不依赖每一步都达到99.99%的开环准确率。
  • 应通过以下机制打破准确率指数衰减：
  1. 闭环自我纠正；
  2. 分阶段验证关卡；
  3. 任务拆解；
  4. 分层子智能体；
  5. 确定性检查与回滚。
  • 成本不一定显著增加，因为无需每一步都调用大型前沿模型。
  • 可采用模型路由和非对称验证：
  1. 低成本、高速度模型执行常规步骤；
  2. 确定性代码低成本验证结果；
  3. 只有验证失败或出现高风险情况时，才调用昂贵的推理模型。
  • 企业级可靠性的核心不是让单一大型模型连续执行100步，而是通过任务拆解、低成本执行模型和确定性验证构成闭环。
  • 在合理架构下，总成本可以显著低于人工执行成本。

10. 多模态应用的商业突破点

10.1 哪些多模态能力能够形成文本模型无法覆盖的新市场？

  • 两项最重要的多模态商业突破方向是：
  1. 连续实时视频感知：面向制造、物流、现场服务、机器人和实体运营；
  2. 超低延迟、具备情感感知能力的语音智能体：面向客户服务和医疗工作流。
  • 实时视频可帮助AI持续理解物理环境、设备状态和人员操作。
  • 全双工语音智能体能够支持自然打断、实时反馈和情绪识别，是传统文本交互无法替代的能力。

10.2 多模态应用规模化部署的主要障碍是什么？

  • 主要问题已不再是基础感知准确率，而是连续流式推理的经济性和安全性。
  • 关键障碍包括：
  1. 实时视频导致Token消耗过高；
  2. 高并发下持续保持300毫秒以内延迟较难；
  3. 实体环境中的时空幻觉可能带来安全风险；
  4. 连续视频和语音处理对网络及边缘算力要求较高。
  • 当边缘—云混合帧过滤技术降低持续流式处理成本后，实时视频和原生全双工语音有望在企业端实现规模化。

11. 模型商品化、市场份额与定价权

11.1 如果模型能力差异缩小，定价权将掌握在谁手中？

  • 定价权将从单纯提供模型API的企业，转移至掌握以下资源的公司：
  1. 客户日常工作流程；
  2. 专有记录系统数据；
  3. 实时反馈闭环；
  4. 监管信任；
  5. 对最终结果承担责任的能力。
  • 最终胜出者可能分为两类：
  1. 掌握工作流和数据引力的既有记录系统厂商；
  2. 能够交付完整端到端结果的垂直AI原生应用厂商。
  • 如果前沿模型实验室不向上延伸至智能体产品、企业工作空间和业务流程平台，单纯Token业务将持续面临利润率压力。
  • 当智能能力像电力一样逐渐标准化，真正的定价权将属于掌握“电器”、工作流程和最终结果的企业。

11.2 模型能力是否正在完全商品化？

  • 市场正在分化，而非全面商品化。
  • 对于约90%的标准企业任务，模型能力正在快速趋同，包括：
  1. 摘要；
  2. 基础问答；
  3. 常规编码；
  4. 结构化数据提取。
  • 开放权重模型和中端模型已经可以低成本满足大量常规需求。
  • 但在以下高复杂度领域，模型差异仍然明显：
  1. 多小时自主智能体；
  2. 零日漏洞安全审计；
  3. 科学推理；
  4. 超可靠工具调用。
  • 前沿差距可能继续扩大，因为只有3至4家实验室能够承担：
  1. 大规模强化学习环境建设；
  2. 专有合成数据管线；
  3. 定制芯片投入；
  4. 将可靠性从95%提升至99.9%的高额成本。
  • 整体格局将表现为：基础智能趋于商品化，前沿、高可靠、长周期执行能力则呈现赢家占据大部分市场的特征。

11.3 常规任务将由领先实验室还是开放权重模型占据？

  • 对于不需要SOTA推理能力的高频常规任务，预计：
  1. 领先实验室的Mini、Flash、Haiku等蒸馏模型占据约 60%至70% 的云端企业级业务量；
  2. 开放权重模型占据约 30%至40%。
  • 领先实验室仍能占据大部分市场的原因包括：
  1. 使用便利；
  2. 服务可靠；
  3. 无服务器部署；
  4. 蒸馏模型价格接近边际算力成本；
  5. 可直接纳入现有企业合同；
  6. 企业无需承担自托管GPU和DevOps成本。
  • 开放权重模型更适合：
  1. 数据主权要求较高的场景；
  2. 本地化部署；
  3. 强调部署控制的业务；
  4. 超大规模、稳态业务量使自托管更具经济性的场景。

提问者：能否更详细地介绍预训练和后训练，并说明效率提升的具体驱动因素？

提问者：关于预训练，目前最先进的LLM模型约有10万亿参数。未来，AI实验室是否会预训练参数规模更大的模型，例如20万亿或30万亿参数？通过增加预训练参数量，是否仍会带来显著的边际改善？
