FY27 Q1云与AI业务专家访谈纪要

注：本次访谈属于FY27 Q1业绩预览，相关数据尚处于公司财务部门最终确认阶段，可能因统计口径或会计调整而变化，最终应以10月28日正式财报披露为准。

1. FY27 Q1核心判断与Azure增长情况

a) 公司当前对AI与云业务的核心战略判断是什么？

  • AI仍被定义为云业务的一部分
  1. 公司管理层继续强调“AI is just part of cloud”，AI不是独立于云之外的业务，而是Azure及整体云平台增长的重要组成部分。
  2. FY28规划仍将延续这一战略定位，不会对AI与云的整体关系进行根本性调整。
  • 当前仍处于高增长、重投入、ROI尚未充分兑现的阶段
  1. AI及云业务保持较高收入增长，但资本开支、算力及研发投入压力仍然较大。
  2. 自研芯片、模型优化和客户迁移需要时间，显著的利润率及投资回报改善预计不会在FY27立即体现。
  3. AI业务短期重点仍是扩大规模、保证供给及深化大型客户部署，而非立即实现利润最大化。

b) FY27 Q1 Azure整体收入和增速大致如何？

  • Azure整体规模
  1. 按新的财报口径，FY27 Q1 Azure整体收入预计为320多亿美元。
  2. FY26 Q1同口径收入约为222亿至223亿美元。
  3. 据此测算，FY27 Q1 Azure同比增速约为44%至45%，实际结果可能为45%或略高，但仍需以最终财报为准。
  • FY27全年目标
  1. FY26全年Azure新口径收入基数约为1,020亿美元。
  2. FY27全年内部底线增长目标约为41%至42%。
  3. 更积极的争取目标为44%至45%。
  • 新财报口径的主要变化
  1. 公司由原来的三大业务板块调整为两大板块。
  2. 新口径主要剔除了部分GitHub云服务、开发者云服务、安全SaaS以及部分医疗行业传统云服务。
  3. Azure AI本身的统计范围基本没有变化，预计该口径至少会持续使用两至三年。

c) FY27 Q1 Azure整体收入由哪些业务构成？

  • 在320多亿美元的Azure整体收入中：
  1. 传统IaaS、计算、存储及网络等业务占比约为48%至49%。
  2. Azure AI占比约为21%至22%。
  3. 其余为传统PaaS，包括数据池、数据湖、高级云安全、数据分析及混合多云等业务。
  • 传统云业务盈利水平
  1. 传统云业务的毛利率仍约为50%至60%。
  2. 传统云业务的利润率明显高于当前AI业务，仍是整体云业务利润的重要支撑。

2. Azure AI收入结构、增长目标与毛利率

a) FY27 Q1 Azure AI的收入规模和占比如何？

  • FY27 Q1 Azure AI收入约为70多亿美元，占Azure整体收入约22%。
  • FY27全年Azure AI占Azure整体收入的内部目标分为两个层次：
  1. 底线目标约为22%。
  2. 积极目标为24%至25%。

b) Azure AI内部各类业务的收入构成如何？

  • 在70多亿美元Azure AI收入中，主要包括：
  1. MaaS/API Token：约27亿至28亿美元。
  2. Machine Learning：10多亿美元。
  3. Other AI：约7亿多美元，包括视觉、大数据及其他认知类服务。
  4. GPU Rental：约20多亿美元。
  • 结构变化
  1. MaaS/API Token是当前Azure AI最主要的增长来源。
  2. GPU租赁占比相对平稳，主要原因是现有A卡、H卡持有量较稳定，而Maia 300尚未正式放量。
  3. 随着新模型、自研模型、Agent及企业客户场景增加，API Token收入预计仍将继续提升。

c) Azure AI的毛利率处于什么水平？

  • 内部目前存在两种计算口径：
  1. 一种口径下，Azure AI整体毛利率为30%多、不到40%。
  2. 另一种财务口径下，毛利率可以达到40%多。
  • 受访者倾向认为：
  1. 接近30%高位、不到40%的口径更合理。
  2. Azure AI毛利率明显低于传统云业务，主要受到GPU、数据中心、模型训练及推理成本影响。

3. MaaS模型结构、开源模型占比与定价策略

a) MaaS/API Token中各模型的收入占比如何变化？

  • OpenAI模型
  1. FY26全年，OpenAI/ChatGPT约占MaaS API Token收入的70%。
  2. FY27 Q1下降至60%多，但仍是绝对主体。
  • Anthropic模型
  1. FY26全年占比约为7%至8%。
  2. FY27 Q1提升至约9%或略高。
  • 开源模型
  1. FY26全年约占MaaS收入的10%。
  2. FY27 Q1提升至约14%。
  3. 这里的14%是按收入计算，而不是按Token用量计算。
  • 其他模型
  1. 剩余收入来自微软自研模型及其他一方、三方开源或闭源模型。
  2. GPT新版本、自研模型推广及Agent场景增加均对MaaS增长形成支撑。

b) API Token价格是否出现明显下降？

  • 官方基础价格暂未明显下调
  1. 尽管OpenAI、Anthropic及其他模型厂商存在降价趋势，但微软MaaS及API Token的基础单位价格尚未出现显著下降。
  2. Copilot、Core AI及其他AI产品同样没有明显的直接降价趋势。
  • 实际成交价格通过综合折扣调整
  1. 微软通常将AI产品与传统云、高毛利云服务及总部级框架协议打包销售。
  2. 根据客户采购规模、长期承诺及产品组合，可给予约5%至25%以上的不同折扣。
  3. 因此，虽然基础SKU价格没有明显下调，折扣后的综合价格未必高于模型厂商直接面向企业客户的报价。
  • 维持价格的主要原因
  1. AI算力及模型成本仍然较高。
  2. 若基础价格率先大幅下降，大客户仍会进一步要求折扣，将显著压缩利润空间。
  3. 公司现阶段仍需兼顾高收入增长与成本回收。

c) 大型企业为什么会使用开源模型？

  • 企业采用开源模型的主要目的包括：
  1. 降低部分模型使用成本。
  2. 提高采购谈判能力，避免被单一闭源模型厂商锁定。
  3. 通过蒸馏、后训练等方式满足部分非核心场景需求。
  4. 向内部管理层证明企业正在兼顾ROI及成本效益。
  • 但在HR、财务、研发核心IP等关键场景中：
  1. 北美大型企业仍以闭源模型为主。
  2. 企业更加重视安全、治理、可追责性及平台整合能力。
  3. 开源模型更多用于非核心、成本敏感或可控风险场景。

4. OpenAI合作关系与多云分配

a) OpenAI对Azure历史收入的贡献如何理解？

  • FY26与OpenAI相关的收入或经济贡献约为241亿美元，其中：
  1. 40多亿美元来自OpenAI向微软支付的利润分成。
  2. 约200亿美元与Azure向OpenAI提供的整体云服务及相关资源使用有关。
  • 这部分收入主要归入传统IaaS和PaaS：
  1. 微软向OpenAI提供的不只是GPU算力，而是完整的云服务。
  2. 为避免重复确认收入或利润，Azure AI与传统云收入之间会进行清晰切分。

b) 微软与OpenAI新协议后，合作关系发生了哪些变化？

  • 在4月26日至27日相关协议调整后：
  1. 微软与OpenAI之间的交易和结算关系进一步简化。
  2. 过去根据微软获得20%利润分成倒推OpenAI收入的方法已不再适用。
  3. 只有当Azure继续作为底层云服务支柱时，OpenAI才会按照约定向微软支付利润分成，累计上限约为380亿至390亿美元。

c) OpenAI的云服务如何在微软与AWS之间分配？

  • OpenAI已经采用多云策略，除微软外，最主要的供应商为AWS。
  • 在协议调整初期的设想中：
  1. 微软可能继续承接约70%至80%的OpenAI云服务需求。
  2. AWS约占20%至30%。
  3. 其他云厂商或通过投资关系引入的算力供应不一定计入上述比例。
  • 截至FY27 Q1：
  1. 微软在OpenAI训练及部分推理需求中的份额仍明显高于AWS。
  2. OpenAI多云化会削弱微软的独家地位，但微软仍是其最重要的云服务提供方。

5. M365 Copilot收入、席位与长期目标

a) FY27 Q1 M365 Copilot收入规模如何？

  • FY27 Q1 M365 Copilot收入约为30亿美元。
  • FY27全年收入目标约为130亿美元，目前未发生明显调整。
  • FY28收入目标约为220亿至230亿美元。

b) M365 Copilot当前席位数量是多少？

  • 内部存在两种主流统计口径：
  1. 较宽口径约为4,000万席。
  2. 相对保守口径约为3,700万至3,800万席。
  • 口径差异主要来自：
  1. 是否包含一个月免费试用用户。
  2. 是否只要付费并激活就算活跃用户。
  3. 是否进一步要求用户产生实际使用行为。
  • 季节性影响
  1. 公司财年第一季度通常是全年相对较弱的季度。
  2. 不宜简单根据Q1席位增量推演全年表现。

c) M365 Copilot的ARPU和实际折扣如何？

  • 标准价格：
  1. B端企业用户约为每月每用户30美元。
  2. C端用户约为每月每用户20美元。
  • 实际企业客户成交价：
  1. 可按标准价格的七成多进行粗略测算。
  2. 大客户实际折扣可能更深，具体根据采购规模和长期承诺逐案审批。

d) FY28 M365 Copilot收入目标如何测算？

  • B端市场
  1. 全球B端云化付费用户约为4亿至4亿多人。
  2. 标准版、高级版、E3、E5及E7等可购买Copilot的eligible用户占比约为67%至68%。
  3. FY28末预计Copilot渗透率约为17%至18%。
  4. 按每月30美元、12个月及平均折扣测算，B端收入约为150多亿美元。
  • C端市场
  1. 全球C端Office用户约为6.2亿。
  2. 其中云化用户占57%至58%。
  3. FY28末预计Copilot渗透率约为7%至8%。
  4. 按每月20美元、无折扣测算，C端收入约为70亿美元。
  • B端与C端合计收入可能超过200亿美元，与FY28目标基本匹配。

e) 新版Microsoft Copilot会不会影响M365 Copilot？

  • 新版Microsoft Copilot包括Auto、Coding和Home三大板块，代表公司向“AI OS”平台方向推进：
  1. 底层可以接入一方、三方、开源及闭源模型。
  2. 上层可以运行标准化或客户定制化的Agent和应用。
  3. 其定位类似AI时代的Windows平台。
  • 对M365 Copilot的影响：
  1. B端产品定位会与M Copilot清晰区分，短期不会产生直接冲击。
  2. C端M365 Copilot可能受到影响，部分用户可能直接购买M Copilot并按API Token付费。
  3. 多数新功能预计于11月左右正式GA，具体商业模式仍处于讨论阶段。

6. 各类Copilot收入与毛利率

a) FY27 Q1各类Copilot收入分别是多少？

  • M365 Copilot：约30亿美元。
  • D365 Copilot：接近3亿美元。
  • GitHub Copilot：约6亿美元。
  • Security Copilot：3亿多美元，接近4亿美元。
  • C端Copilot及其他AI业务：约16亿至17亿美元，其中包括Agent相关收入。
  • 若加上70多亿美元Azure AI收入：
  1. FY27 Q1 AI相关收入合计约为130多亿美元。
  2. Azure AI和M365 Copilot是当前两项最主要的收入来源。

b) SaaS本体和SaaS Copilot的毛利率分别是多少？

  • SaaS本体
  1. M365、D365及GitHub等SaaS本体毛利率约为70%至80%。
  2. 部分业务毛利率可能更高。
  3. 内部编程工具、自动化及人员优化对毛利率形成支撑。
  • SaaS Copilot
  1. 各类SaaS Copilot毛利率约为40%至40%多。
  2. AI推理及模型调用成本使其毛利率显著低于传统SaaS本体。

c) 未来Copilot收费模式会如何变化？

  • SaaS AI产品将逐步采用“席位费+API Token”的复合收费模式。
  • M365 Copilot未来也可能从单纯席位订阅转向：
  1. 基础席位费。
  2. 根据实际Agent、模型及Token消耗额外收费。
  • 这一模式有望提升收入及投资回报，但也可能增加客户预算管理难度。

7. FDE团队建设、客户覆盖与业务贡献

a) FDE团队目前有多大规模？

  • 当前FDE团队人数约为5,500多人，尚未达到6,000人。
  • 人员结构大致为：
  1. 行业专家占19%至20%。
  2. AI工程、云架构及AI编程人员占60%多。
  3. 安全合规人员约占9%。
  4. 其余为项目管理及支持岗位。
  • FDE于7月至8月完成独立组织调整，严格意义上独立运营时间只有约一个月，仍处于整合初期。

b) FDE目前覆盖哪些客户和地区？

  • FDE已介入全球约20个国家的客户项目，但不代表每个国家均配置了本地人员。
  • 当前主要聚焦S500大型客户：
  1. S500客户占FDE覆盖客户的70%至80%。
  2. 介入客户约为200至300家。
  3. 约200家客户已有FDE参与的项目进入生产环境。
  4. 其余客户仍处于POC测试阶段。
  • 重点行业包括：
  1. 政府。
  2. 金融。
  3. 制造。
  4. 医疗。
  5. 零售。
  • 每个客户通常配置4至9名FDE人员，具体取决于客户规模和承诺年度价值CAV。

c) FDE参与的项目主要有哪些类型？

  • 已上线项目结构大致为：
  1. Agent智能体项目占40%多。
  2. M365 Copilot规模化及定制化项目约占30%。
  3. Fabric、Foundry及生成式AI平台项目约占20%。
  4. 其余为AI安全、治理及数据隐私项目，占个位数比例。

d) FDE对客户项目落地效率有何提升？

  • POC转生产率
  1. 有FDE支持的项目约为60%。
  2. 没有FDE支持的项目仅为30%多。
  3. FDE支持下的转化率接近翻倍。
  • 项目上线周期
  1. 无FDE支持时，AI项目从POC到生产平均需要约20周。
  2. 有FDE支持后缩短至约10周，周期缩短约一半。
  • 系统可用率
  1. FDE支持的Agent及生成式AI项目可用率约为96%多。
  2. 客户自行上线的项目可用率仅为80%多。
  • 用户采纳率
  1. 无FDE支持时，客户内部活跃用户比例约为40%。
  2. FDE入场一个季度后可提升至接近60%。
  • 业务场景扩展
  1. FDE覆盖客户平均每季度新增2个或2个以上AI业务场景。
  2. 无FDE支持的客户平均仅新增约1个场景。

e) FDE对收入和Copilot席位的贡献有多大？

  • FY27 Q1，FDE覆盖客户对Azure整体收入的拉动约为20亿至30亿美元，更接近20多亿美元。
  • 其中40%多来自：
  1. 算力扩容。
  2. Agent持续运行。
  3. 模型微调及相关消耗。
  • FDE带来的M365 Copilot新增席位约为数十万，但其中既包含FDE直接推动，也包含接手客户既有项目，难以完全拆分。

8. 客户需求、增长来源与算力供给

a) 当前Azure及Copilot增长主要来自哪类客户？

  • 增长仍主要来自大型企业客户：
  1. GA全球大客户。
  2. EC企业客户。
  3. S500头部客户。
  • 主要增长方式不是新增客户数量大幅增加，而是：
  1. 原有大客户扩大Azure使用量。
  2. 增加Copilot席位。
  3. 扩展至更多部门和业务场景。
  4. 从POC转入生产部署。
  5. 增加Agent、模型微调及API Token消耗。
  • 中型企业有一定增长，但小微企业采纳表现仍不突出。

b) 为什么中小客户AI产品采纳率不高？

  • 核心原因包括：
  1. 产品价格仍然较高。
  2. 算力及模型成本尚未明显下降。
  3. 高阶套装中的部分功能并非中小企业刚需。
  4. 中小客户更关注短期ROI，对长期平台、安全及治理价值的支付意愿有限。
  • 例如E7打包价约为每月每用户99美元，虽然低于各单项累计110至120美元的价格，但中小企业可能无法充分使用其中的高阶功能。

c) 大客户为什么愿意作出长期使用承诺？

  • Azure本身采用Pay-as-you-go模式，未来M365 Copilot也会向席位加Token收费靠拢。
  • 大客户如希望获得更深折扣，需要通过CAV作出长期使用承诺：
  1. 承诺Azure整体消耗规模。
  2. 承诺Azure AI或MaaS消耗。
  3. 承诺Copilot席位及未来Token使用量。
  • 这种“承诺量换折扣”的方式是推动大型客户扩展使用的重要手段。

d) 当前的主要矛盾是容量不足还是客户部署不够快？

  • 两种情况同时存在，但需要按客户层级区分：
  1. 对S500和EC大型客户，公司会优先保障云和AI算力供给。
  2. 大客户的核心问题更多是场景扩展、内部部署和组织采纳。
  3. 对中小客户而言，需求不足及价格敏感比容量不足更加突出。
  • 整体增长的核心仍是大型客户内部扩张，而不是中小客户全面爆发。

9. 资本开支规划与AI算力采购

a) FY27资本开支规模预计是多少？

  • 当前FY27资本开支计划仍为2,300亿至2,400亿美元。

  1. 公司可能将100亿至200亿美元预算缓冲转为资本开支。
  2. 全年资本开支上限可能提高至2,500亿至2,600亿美元。
  • 即使进行上调，预计也要到圣诞节和新年之后，即1月中下旬才会明确。

b) 资本开支中有多少用于AI芯片？

  • 约35%至37%的资本开支用于采购AI芯片，包括外购芯片与自研芯片。
  • 此外资本开支还覆盖：
  1. 数据中心建设。
  2. 网络及存储设施。
  3. 电力和冷却系统。
  4. 云及AI基础设施扩容。

c) AI芯片供应商结构如何变化？

  • 上一阶段的采购结构约为：
  1. 英伟达约占90%。
  2. 自研Maia约占6%至7%。
  3. AMD及其他供应商约占3%至4%。
  • FY27可能发生的变化：
  1. 若Maia 300顺利量产，自研芯片占比将进一步提升。
  2. 英伟达占比可能从90%下降至80%多。
  3. AMD预计继续维持3%至4%，主要受年度框架协议及AI PC业务绑定影响。
  • 英伟达Rubin目前仍存在一定供给及产能紧张，可能进一步提高自研芯片的重要性。

10. Maia自研芯片进展与利润率影响

a) Maia 200和Maia 300目前进展如何？

  • Maia 200
  1. 量产时间不足10个月。
  2. 当前规模约为10万颗或略高。
  3. 主要用于公司内部部署。
  • Maia 300
  1. 正在与台积电沟通排产，市场所传20万至30万颗并非完全没有依据。
  2. 当前仍处于局部参数调优阶段。
  3. 相对完善的Beta版本预计于11月中旬Ignite大会前后推出。
  4. 主要优势在推理侧，能够与Azure及M365后台推理体系进行更直接的软硬件协同。

b) Maia 300未来主要应用于哪些场景？

  • 若性能、排产和量产均达到预期，Maia 300可用于：
  1. 中端和中高端推理。
  2. 中低端推理。
  3. 低端训练。
  4. 部分GPU Rental场景。
  5. Azure及M365 Copilot内部推理。
  • 公司不排除在FY28向部分外部客户销售Maia芯片或相关算力服务。
  • 目前正与Anthropic商谈Maia 300合作，但谈判进展并不明确。

c) 自研芯片何时能够改善毛利率？

  • FY27预计难以显著体现。
  • 从芯片开片、流片、量产，到集群测试、部署及客户迁移，至少需要6至9个月。
  • 即使Maia 300在FY27下半年正式放量：
  1. 客户迁移也可能持续到年中或更晚。
  2. 对云业务毛利率及净利率的明显改善大概率要到FY28才会体现。

11. AI降本路径与ROI改善

a) 公司实现20%降本目标主要依靠哪些措施？

  • 自研芯片
  1. 是最核心的降本方向。
  2. 通过降低对高价外部GPU的依赖，改善单位推理成本。
  • 自研模型
  1. 在细分垂直场景训练更小、更专业的模型。
  2. 对不需要顶级通用模型能力的客户场景使用自研模型。
  • 模型蒸馏
  1. 使用蒸馏模型降低推理成本。
  2. 在模型效果与成本之间进行平衡。
  • FDE场景切片
  1. 根据客户具体场景选择适配模型。
  2. 避免所有业务均调用最高成本的大模型。
  • 运营费用优化
  1. 继续通过人员调整和组织优化降低OPEX。
  2. 据受访者判断，本年度剩余时间内可能仍有进一步人员优化。
  • 收费模式调整
  1. SaaS产品逐步采用“席位费+API Token”。
  2. 在成本无法快速下降时，通过使用量收费提升收入与ROI。

b) 开源模型能带来多大降本效果？

  • 根据不同客户规模、模型版本及使用深度：
  1. 一般可降低30%左右成本。
  2. 部分场景可实现40%以上降本。
  • 但北美大型企业不会只根据模型成本做决策，还会重点评估：
  1. 数据安全。
  2. 合规与治理。
  3. 知识产权保护。
  4. 事故后的追责和赔偿能力。
  5. 与既有平台的整合程度。

12. 开源模型政策风险与替代方案

a) 美国是否可能限制中国开源模型？

  • 美国众议院已出现针对中国开源模型的限制性提案讨论，但目前尚未真正落地。
  • 潜在风险在于：
  1. 政策可能在中期选举期间被政治化。
  2. 若实施“一刀切”，北美企业使用中国开源模型将面临明显合规障碍。
  • 目前该事项仍属于政策风险，而非已经生效的事实。

b) 如果中国开源模型受到限制，企业有哪些替代方案？

  • 采用欧美开源模型
  1. 可选择Mistral、Llama等模型。
  2. 但受访者认为，其性能可能不及部分中国开源模型。
  • 开源与闭源结合
  1. 将不同模型用于不同业务路径。
  2. 核心数据使用闭源模型，非核心场景采用开源模型。
  • 企业自建模型
  1. 基于开源或闭源模型进行Post-training。
  2. 虽然基础数据规模有限，但能够更贴近企业自身业务。

c) 为什么北美大型企业对闭源模型接受度更高？

  • 闭源模型虽然也存在数据托管和潜在后门风险，但相较开源模型：
  1. 服务商主体明确。
  2. 出现泄露时可以追责、诉讼和索赔。
  3. 安全治理和合规体系更加完整。
  4. 更容易与企业现有云、安全及数据平台整合。
  • 开源模型一旦发生问题，责任主体和数据传播路径往往更难追溯。

13. GenAI对安全、数据与PaaS投入的带动

a) GenAI是否带动企业增加安全和数据基础设施投入？

  • 从FDE覆盖客户来看，GenAI正在带动相关投入增长。
  • FDE入场后，客户对以下业务的综合投入承诺较此前增长10%多、接近20%：
  1. Azure云安全。
  2. 数据池与数据湖。
  3. 高级数据分析。
  4. 混合云。
  5. AI治理与数据隐私。
  6. 其他Azure PaaS能力。
  • 这一增长是综合口径，不能单独归因于安全或数据业务。

b) 大型企业当前安全体系是否能够支撑Agent部署？

  • 北美大型客户普遍已部署较完整的传统云安全体系。
  • 当前新的问题是：
  1. 原有安全能力能否覆盖Agent及生成式AI工作流。
  2. 是否需要增加Security Copilot、AI治理和模型围栏。
  • 客户态度大致分为两类：
  1. 一半认为现有安全能力不足，需要追加投入。
  2. 另一半认为可以先推进项目，同时继续观察。
