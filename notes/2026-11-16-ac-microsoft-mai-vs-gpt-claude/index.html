【以下为专家观点汇总，具体细节仅供参考。】

目前MAI的模型矩阵情况？

MAI的体系中既有 Base，也有 Think 等一系列模型。无论是之前的 Base 1，还是现在的 Base 2，包括即将在全球技术大会Ignite上可能会介绍的 Base 3，Base层面其实都是预训练的基座，并不是对外可以直接调用的成品化模型。如果从自研模型的层面来看，2023年开始有 PHI 一代 1.5，包括Orca、PHI 2，这些基本都是2023年研发的，2024年主要是 PHI 3。这些 PHI系列主要对应的是中小模型，尤其是小模型化。2025年开始，自研模型成为MAI的主线，比如基准大模型MAI的第一代，以及MAI里的 voice 一。在 PHI 的层面上，2025年左右还有 PHI 4。这两者的区分在于，MAI的角度是MAI，第一个端到端训练的基础 MoE模型，主要用途是降低对 OpenAI的依赖，包括内部模型评估、早期测试和开发者生态的捆绑。

在MAI这个底座完成后，2026年开始出现了 transcript，包括 MAI THINK 和 TRANSCRIBE，主要用于高精度语音转写，服务于会议、文档语音工作流，对标 OpenAI 的 WHISPER。MAI IMAGE一代和二代主要是文生图或图生图，嵌入 Office One Drive，对标GPT的图形生成和 Claude 的图形理解，多模态生成。同步推出的 MAI think 1层面是在今年（2026年）6月左右发布，主要用于自研专用推理模型，即稀疏的 MoE，面向多步骤复杂任务，如长下文推理、代码工作、金融或工程类智能体任务。这是从零开始，没有第三方模型蒸馏，主打性价比，对标 OpenAI 的 o系列、opus、sonnet 等复杂推理模型。

同期配套的还有 MAI Image 2.5 flash、MAI Code、MAI Voice、MAI Transcribe 的更新版本，分别覆盖图像创新、代码生成、语音链路，旨在实现智能体端到端全堆栈的各组件补完。从2023年开始，PHI一直到 MAI一代 preview，2025年，再到2026年的 MAI，无论是 think、transcript 还是 imagine、code，这些都是自研 AGI 相关的、对外可调用销售变成 MaaS API token 的自研 ep模型。这部分与MAI的 Base 系列（Base 1、Base 2、Base 3）形成逻辑上的区分。Base 3 预计将在明年（2027年）上半年正式发布。这两者形成了底座式预演，A公司自有模型，而商业化层面，无论是GPT、Claude，还是其他开闭源的 3p 模型，都能形成有效补足。

MAI Think 是否目标为模型的第一梯队的能力？

从 CORP 的模型战略来看，已经从单独压住 GPT 旗舰版模型，转向多模型编排，按任务匹配最优模型，即 RIGHT SIZE MODEL。操作层面，SIF 是统一控制平台，Foundry贡献 Azure增速，多模型调用层面，copilot fusion 路由引擎负责子任务自动分配，fabric 承载企业私有上下文。这套体系可以理解为自研的 ep、3p 以 OpenAI 和 Anthropic 为主，再配合 mistral、lama 等开源模型的总体框架。

MAI 的 Base 和 MAI think 都是A公司自研的第一梯队，均由 MAI团队研发，但并不是公司全产品线唯一的模型。A公司有多个模型，它们处于成本到产出的前沿梯队。之前A公司有 ai frontier团队，专注于前瞻性预演，原本在 research lab，后来调到 MAI，后又有所变动。公司现在的模型战略是多元化，无论是 1p 还是 3p。平台基础之上，无论是自研 ep 基础模型、应用模型还是第三方模型，自研应用模型底座需要 Base支撑，这种预演模型在平台底层可以灵活选择合适模型。

对于模型本身，尤其是自研模型，A公司现在更关注规模化效应。一旦形成规模，比如 GPU、DC测集群化效应，就像当年云时代一样。对于没有商业化验证或转化的前瞻性算法模型，现在逐步缩小。在目前这个层面，无论是基础模型还是商业化模型，OpenAI和Anthropic这两家的旗舰模型能力上限持续提升。A公司自身拥有B级客户，并且需要区分GA、SMB或EC的大客户，包括FDE的方式，这些客户目前主要使用NV家的高阶卡，以及OpenAI或Anthropic在当期最先进的模型。因此，这两条路径是并行的，定位、算力分配和负载场景是分开的，不存在所谓的替代关系。Base 2是整个MAI家族的唯一主干底座。未来会有Base 3、Base 4，后续的MAI Think、Code Flash、Cyber、Transcribe、Decision One等EP自研商业化模型，全部基于该底座进行微调和衍生。基本上不会再出现独立预训练的新大基础底座模型。

MAI与头部前沿模型的能力和效率的对比？

MAI团队的核心设计目标是在头部前沿模型发布后的3到6个月内，自研模型要达到接近的能力区间。例如，OpenAI或Anthropic Claude的新一代模型发布后，A公司要在3到6个月内接近其能力区间，并且训练算力效率要达到开放权重模型的4到10倍，同时能够深度嵌入并匹配自研的MAI芯片，比如MAI 300。MAI系列模型的战略定位主要是压低单位推理成本，服务于非GA或EC重点大客户之后的腰部、SMB甚至C端用户。在自研内部层面，MAI Base加MAI Think在算力、配额、人才和上线优先级上都是最高的，是自研路线上的主力前沿模型。PHI已经变成轻量化或端侧模型，不再承担云端前沿推理底座任务，PHI这类中小模型已成为第二梯队。

从公司整体产品堆栈角度看，面向全部Copilot或高价值客户，OpenAI和Anthropic的旗舰模型仍是复杂性、多步骤Agent、前沿科学、深度二开、深度定制和高难度多模态创新的首选模型。A公司不会把MAI系列定位为同一时期全面达到SO TA，也不是要全面超越GPT或Claude的最新旗舰版。MAI的使命是承接大批量中等或轻度复杂度、对成本敏感的B级客户负载，分流OpenAI和Claude的Token，降低M365等Copilot的成本，并不是抢最高能力上限的旗舰版。在算力调度层面，内部算力池基本上是独立优先级。

MAI是否会合并自身不同分支的模型？

A公司自身不会做权重的大一统，不会将全部模型合并成一个单一基础大模型。A公司遵循的逻辑是底座逐步收敛，这类似于Copilot数量的减少。前两年，无论是B级客户还是内部，Copilot最大的问题不是能力一般或内容产出虚，而是数量过多。由于这些问题，A公司制定了整体AI战略，要做平台，无论是模型平台还是应用平台。今年Copilot已从七八十个减少到三4十个，未来还会继续减少，最终形成单一模块挂在Copilot上，形成不同功能模块。

回到模型角度，A公司会做的是底座收敛。之前有达芬奇、图灵等模型，现在底座要收敛到MAI作为唯一基础底座。MAI主要针对腰部或中小客户，Fine现在定位为端侧，即Copilot Plus PC。今年在PC层面，AI PC的战略较前几年总部AI战略是下调的。A公司自身有五十多年历史，主要是To B，C端不会做，硬件也做得不够好。因此，在底座收敛的同时，接口和评测标准要统一，并进一步淘汰老旧冗余的模型，这是一个roadmap。垂直方向则是一些特制、特化或特别的模型，比如基于MAI和内部数据的模型。

MAI在垂类模型上的策略？基本放弃最前沿模型的目标？

A公司目前正在进行的工作包括行业垂类模型的训练，例如 healthcare、金融、政府等领域。这些模型仍在持续训练，但在底座层面会统一到MAI作为底座。如果外部认为底座统一意味着只保留一个模型，这其实是不准确的。从MAI的角度来看，主线包括Base 2，以及 think code cyber、transcribe decision 1 等微调分支，主要面向云端企业推理、copilot 的云端测负载，以及 Azure AI Fabric 上对外 B 级客户可调用 API token 的售卖。PHI 主要是轻量化的端侧模型，运行在 copilot plus PC 上，约束为低能耗、低功耗和低显存，数据不出设备。这是两条路径。

此外，AI Frontier 之前是并行的第三条路径，属于前沿性模型，包括机器人和安全专项模型。随着 AI Frontier 团队的解散，这部分正在逐步缩减。合并或收敛的层面主要包括：首先，MAI的全系列会收敛到以 Base 2 或未来的Base 3 作为单一主干底座，所有商用特化模型都会基于MAI的 Base进行微调，不再各自独立训练底座。这样做的直接目的是减少多底座带来的算力重复或浪费，评测体系的不一致也会大幅改善，软硬件适配成本降低，运维复杂度下降。但这并不等于权重的合并，例如 think code cyber是独立的微调分支，其目标和评测集不同，权重独立，面向不同任务。

第二个不会合并的是MAI的云端主线和 PHI，PHI 仍是端侧模型，低功耗、低显存、离线延迟等约束，目前不会基于 Base，而是基于 PHI 的底座。第三个不会合并的是自研的MAI和 OpenAI 的GPT，尤其是0426、0427分家协议后更不会合并，只会做接口对齐、评测对齐、路由打通等动作。老的旧分支会进一步梳理、清理、合并，这一过程会逐步完成，不会一刀切，因为部分老分支的 B级客户还有剩余周期，需要允许继续使用老版本。这是目前的情况。

27年Azure平台的模型策略？自研和三方模型的搭配？

对于下一个阶段，比如从2027年开始，主线仍是1P加3P混合模型的多元化策略，这不会改变。Copilot 依旧是核心操作系统，Foundry是多模型编排的控制平台。模型本身不再是核心卖点，模型路由、企业私有定制上下文、agent编排、安全治理、算力成本才是未来的护城河。基于 AIOS 平台，底层模型可自由选择，上层架设类似于 Windows 操作系统的软件，即各种 copilot功能，再基于 copilot形成二开的定制 copilot，以及 agent 加flow。

这意味着一方面要强化自研MAI，作为降低成本的基础模型主导方式，另一方面要维持头部第三方3P模型的供给，满足不同类型客户的需求，包括 GA、EC、SMB、C端等。不同客户选择单一模型供应商会有依赖风险。对于OpenAI，主要是合约供给，不再独家绑定，转为优先供给、非排他、负载隔离、分层定价等竞合关系。OpenAI 的 GPT 仍是体系内复杂高难度推理和前沿多模态任务的首选模型，如 M365 Copilot的高端场景、世界500强复杂智能体基本都是 OpenAI，但不能将所有 Copilot 都压在 OpenAI，需要通过MAI分流批量化、标准化负载，控制 token 采购成本，保护 Azure 的毛利和 M365 Copilot 的毛利。

在产品和路由策略上，Copilot Fusion 自动路由引擎会内置默认规则：高复杂、高价值、高客单价任务归到 OpenAI 或 Anthropic，标准化、高吞吐、成品、成本敏感任务归到MAI，客户可选择开源模型，也可强制锁定OpenAI 或 Anthropic。Azure OpenAI Services 会继续做增值打包销售，如安全、数据隔离、私有微调、审计、RBAC、SLA兜底，赚取的是平台治理溢价，而非单独转售 token。

怎么看基础API token调用的同质化趋势？在这个领域的竞争前景？

将来通用 API token 在某种层面上极为类似于现在的 IaaS，即网络、计算、存储，同质化趋势明显，价格必然走低。举例来说，无论 AWS、GCP，还是国内 BAT，谁都不敢保证自己的IaaS比别人功能更强，大家拼的是价格折扣。未来所有基础化、标准化模型都会趋同于这一路径。为此，自研MAI模型必须持续推进。从商业化和算力约束角度来看，无论 OpenAI 还是 Anthropic，都可以直接向 B级客户销售模型，A公司与他们存在天然的竞合关系。A公司为 OpenAI 提供算力配额，但配额边界清晰，OpenAI不能进一步挤占MAI的客户算力。算力紧张时，优先保障付费用户高负载，其次是 M365 Copilot，再分配内部训练资源。
