Snowflake CoCo 企业级AI应用与黑客松会议纪要

1. 制造业AI落地方法论

a) 如何将AI能力真正落实到制造业主管及业务实战中？

  • AI应用建设不能从模型或技术出发，而应首先明确需要提升的业务能力，例如销售、财务、运营或具体流程效率。
  • 从AI想法走向实际应用，需要同时推动三个关键要素：
  1. 价值：明确要解决的业务问题、预期收益及衡量标准。
  2. 人员：让数据团队、技术团队、业务用户和管理人员共同参与。
  3. 流程：将AI嵌入现有业务系统和日常工作流程，而不是停留在独立演示阶段。
  • 企业需要在安全合规的基础上，统筹数据、技术、业务流程和人员权限，最终形成可持续运行的生产级应用。
  • 对制造业主管而言，AI的核心价值不是单纯生成内容，而是帮助其调用业务数据、分析问题、提出建议，并进一步执行相关操作。

b) 企业构建AI应用时首先应考虑什么？

  • 首先应明确AI应用具体提升哪一项业务能力，以及为什么该问题值得解决。
  • 其次需要判断AI是否能够与企业现有应用、数据平台和业务系统快速结合。
  • 最后需要从一开始就考虑安全、权限、合规、数据治理及后续生产化运维，避免仅形成无法规模化的小型应用。

c) 企业数据治理在AI时代发生了哪些变化？

  • 企业数据建设经历了以下几个阶段：
  1. 传统数仓和集中式架构阶段，重点关注指标体系和数据集成。
  2. 营销、风控等场景发展后，开始建设用户标签及其他业务标签。
  3. 近两年进入生成式AI阶段，需要进一步管理Memory、Context及相关治理策略。
  4. 最终需要将传统结构化数据、非结构化数据、上下文和AI交互记录纳入统一的企业级数据治理体系。
  • Memory Governance和Context Governance将成为企业级智能体应用的重要基础能力。

2. 企业数据架构现代化

a) 传统数据平台在AI应用建设中面临哪些问题？

  • 企业内部系统较为分散，通常需要在多个系统、不同组件和不同版本之间完成数据处理。
  • 传统集中式架构成本较高，企业长期在原有架构上叠加新技术，逐渐形成技术债务和技术惯性。
  • 复杂组件需要长期维护，并处理版本、兼容性和运维问题，导致：
  1. 运维压力持续上升。
  2. 数据任务链条过长。
  3. 系统整体效率下降。
  4. 数据治理长期依赖大量人工投入。
  • 许多企业已经完成了数据接入，但在应用构建、跨平台整合和生产化阶段仍存在较多困难。

b) 现代数据架构应如何解决上述问题？

  • 企业应尽可能采用统一、开放且具备较高性价比的数据架构，减少多套组件重复建设。
  • 同一平台或引擎应支持多种任务类型，包括：
  1. 离线数据处理。
  2. 实时数据处理。
  3. 数据分析与探索。
  4. 应用开发。
  5. AI和机器学习任务。
  • 如果企业希望将数据保留在Amazon S3上以控制成本，可以使用相应表格式、目录和计算引擎完成处理。
  • 企业也可以根据性能、成本和业务特性选择不同引擎，而不需要将所有数据和工作负载完全迁移到单一平台。

c) 企业是否必须“All in”单一数据平台？

  • 企业现实中通常不可能全部采用单一平台，也会同时使用其他数据厂商、数据平台和计算引擎。
  • Snowflake可以通过Federation、Catalog等技术与其他平台结合。
  • 企业可以根据实际需求选择Snowflake Catalog、其他Catalog或外部数据方案，实现跨平台数据发现、访问和计算。
  • 即使未来涉及系统迁移或更换计算引擎，也可以在不推翻原有体系的情况下完成整合。

d) 如何减少数据复制并提升分析效率？

  • Snowflake相关能力可以在逻辑上快速形成数据表，但物理层面无需实际复制数据。
  • 该能力适用于：
  1. 数据处理。
  2. 临时分析。
  3. 数据探索。
  4. 新业务场景验证。
  • 通过减少数据搬运和重复存储，可以降低成本，并提升分析和应用构建效率。

3. AWS与Snowflake的合作及企业级AI架构

a) AWS与Snowflake之间是什么合作关系？

  • Snowflake既是AWS的合作伙伴，也是AWS的客户，双方形成了双向合作关系。
  • 双方在以下方面保持紧密联系：
  1. 数据库。
  2. 现代化应用设计。
  3. 数据分析。
  4. 数据安全。
  5. AI及机器学习。
  • Snowflake长期位于AWS Marketplace数据分析领域的领先位置。
  • 分享数据显示，Snowflake客户群中与AWS相关的客户占比较高，整体约为70%，亚太区约为75%。

b) Snowflake和AWS如何支持不同的大模型需求？

  • 企业可以根据具体用例选择不同模型，不必绑定单一模型。
  • 系统支持自动模式，可根据当前应用场景选择更适合的模型。
  • 如果企业需要微调模型，可以结合Amazon SageMaker相关能力。
  • 如果企业希望自建模型，也可以使用相应的云资源和基础设施。
  • 企业在选择模型时应综合考虑准确率、响应速度、成本、安全及具体场景，而不是单纯追求模型规模。

c) 企业级生成式AI应用需要具备哪些基础能力？

  • 企业级应用不仅需要模型，还需要整合：
  1. Memory。
  2. Context。
  3. Policy。
  4. 权限体系。
  5. 企业数据。
  6. 原有业务系统。
  • AI用户、开发人员、业务用户和管理员具有不同需求，应按照身份和权限开放相应数据及操作能力。
  • AI应用不仅要读取平台内的数据，还应在授权范围内调用原有业务系统数据并执行相关操作。

d) Snowflake如何帮助企业快速接入AI能力？

  • Snowflake提供默认连接能力，企业无需从头完成大量连接配置。
  • 用户可以在现有聊天工具或分析页面中直接调用数据。
  • 将企业本地资料、业务数据和专业分析工具结合后，可以帮助一线分析师处理客户定制化问题。
  • 其目标是让AI从简单问答工具转变为能够访问受治理数据、开展专业分析和执行任务的业务助手。

4. CoCo的核心定位与使用方式

a) 即使此前没有使用过CoCo，能否直接开始操作？

  • 可以。用户可以直接使用自然语言向CoCo提出要求，无需先学习复杂的编程语法。
  • 例如，用户可以直接提出“构建一个数据管道”“创建一个应用”或“显示市场中的可用数据集”等请求。
  • CoCo会根据用户有权访问的数据和资源开展工作，并进一步询问用户希望构建哪类应用或管道。

b) CoCo如何避免基于错误假设执行任务？

  • 智能体不应在信息不足时自行假设。
  • 当需求、数据或执行条件不明确时，CoCo会主动向用户提问，确认目标和约束后再执行。
  • 对复杂应用，可以先使用计划模式生成实施方案，由用户审核后再开始开发，降低错误修改或破坏原有应用的风险。

c) CoCo提供哪些操作界面？

  • CoCo支持多种使用方式：
  1. CoCo CLI：通过命令行构建应用和数据管道。
  2. CoCo Desktop：通过桌面图形界面完成与CLI类似的工作。
  3. Visual Studio Code：直接融入开发者熟悉的IDE。
  4. Snowsight/Web UI：在Snowflake网页界面中直接使用，无需安装外部软件。
  • 核心理念是让开发者继续使用熟悉的工作环境，而不是被迫学习新的开发工具。
  • 如果企业IT政策不允许安装第三方软件，可以直接通过Snowflake Web UI使用CoCo。

d) CoCo在Snowsight中如何使用？

  • Snowsight是工程师和管理员日常使用的Snowflake默认界面。
  • 用户可以在界面右侧直接调用CoCo，通过自然语言构建应用、分析数据和创建数据工程任务。
  • 现场展示的应用主要使用Snowflake Marketplace中的数据，并通过Snowsight右侧的CoCo完成构建。
  • 用户只需登录Snowflake账户即可使用，无需额外安装外部依赖。

e) CoCo是否支持技能复用和第三方服务连接？

  • CoCo支持创建和上传Skills。
  • 如果团队经常开发同一类应用，可以将标准步骤和规则封装成可复用技能。
  • 技能复用可以带来以下价值：
  1. 保证不同团队成员获得更一致的响应。
  2. 提高同类应用的开发效率。
  3. 以结构化方式向语言模型提供指令。
  • CoCo还支持：
  1. 导入Git仓库和项目。
  2. 同时运行多个会话。
  3. 连接Gmail、Slack等第三方服务。
  4. 上传图像及其他类型文件。
  5. 调用用户已有权限的数据和服务。

5. CoCo应用演示与可构建场景

a) CoCo能否构建交互式仪表板？

  • 可以。现场第一个应用包含多个标签页、图表及交互组件。
  • 用户可以移除或重新添加特定数值，相关图表会自动更新。
  • CoCo还可以构建热力图及其他可视化内容。
  • 即使用户编程经验有限，也可以通过自然语言完成基础应用和仪表板建设。
  • 对专业开发人员而言，CoCo也可以提高开发和交互效率。

b) CoCo如何分析视频内容？

  • 用户可以上传视频，并通过按钮或自然语言触发分析。
  • CoCo能够基于视频内容及分析结果回答相关问题。
  • 整个过程不需要用户编写代码，只需提供提示词。
  • 该能力表明CoCo不仅能够处理结构化数据，也能够处理视频等非结构化内容。

c) CoCo是否能够处理地理空间数据？

  • 可以。现场应用展示了地理空间数据处理能力。
  • 用户点击地图中的某个区域后，可以显示来自不同社交媒体平台的实时信息流。
  • 现场部分实时加载和刷新受到网络连接影响，但不影响其整体场景设计。

d) CoCo能否构建流数据应用？

  • 可以。现场展示了订单数量持续增加的流数据应用。
  • 该应用结合了Spark Streaming等实时数据处理能力。
  • 在开展流数据分析前，需要先确认真实数据流已经接入，避免在没有数据的情况下直接进行可视化。
  • 平台可以对数据流基础设施、计算集群和相关技术细节进行管理，降低开发门槛。

e) CoCo如何结合Cortex AI分析支持工单？

  • 应用可以实时查看持续接入的支持工单。
  • 通过Cortex中的AI函数，可以：
  1. 将工单自动划分到不同类别。
  2. 生成分类统计图表。
  3. 识别特定缺陷或集中问题。
  4. 使用AI Complete等函数生成处置建议。
  • 整个流程基于实时数据，可用于客服运营、质量管理和问题预警。

f) CoCo的能力是否仅限于图表和仪表板？

  • 不限于图表和仪表板。
  • 现场演示主要用于展示CoCo可以快速构建的不同内容，其能力还包括：
  1. 数据管道建设。
  2. 数据分析。
  3. 实时数据处理。
  4. 非结构化数据分析。
  5. 机器学习模型构建。
  6. 智能体应用开发。
  7. 第三方系统连接。
  8. 业务操作执行。

6. 机器学习模型构建与业务应用

a) CoCo如何帮助用户构建机器学习模型？

  • CoCo可以通过机器学习工程能力帮助用户构建模型。
  • 即使用户不了解模型开发过程，也可以通过自然语言描述需求，由CoCo完成相关工作。
  • 当数据发生变化或模型需要定期更新时，可以进一步建立自动化执行机制。
  • 构建完成的模型可以部署到不同智能体中，供业务用户调用。

b) CoCo创建的模型如何提供给业务用户使用？

  • 使用CoCo创建模型后，可以通过存储过程将其接入面向业务用户的Core界面。
  • 即使用户不了解如何编写存储过程，CoCo也可以代为完成。
  • 业务用户可以通过自然语言提问，调用模型并获得洞察，无需直接操作底层代码。

c) 姚明历史数据预测案例展示了什么？

  • 现场使用Snowflake中训练的机器学习模型，基于姚明的历史比赛数据进行预测。
  • 模型用于分析当每场比赛上场时间增加时，场均得分可能发生的变化。
  • 训练数据来自市场中可获得的真实数据。
  • 该案例用于说明，用户可以直接结合Marketplace数据完成模型训练和预测应用。

d) 如果项目暂时没有数据，应如何开展开发？

  • Snowflake Marketplace提供大量不同类型的数据集，其中包括免费数据集。
  • 用户可以直接要求CoCo显示市场中可用的数据集，并选择适合当前项目的数据。
  • 使用Marketplace数据可以减少外部导入工作，帮助团队快速完成原型开发和场景验证。

7. 从AI原型走向生产级应用

a) AI小应用如何升级为生产级应用？

  • 企业需要从产品和数据两个方面同步推进。
  • 产品层面需要明确：
  1. 用户是谁。
  2. 用户需要解决什么问题。
  3. AI结果如何进入实际业务流程。
  4. 应用能否持续产生业务价值。
  • 数据层面需要明确：
  1. 数据来源。
  2. 数据质量。
  3. 权限和安全。
  4. 数据更新方式。
  5. 模型和应用如何持续运行。
  • 例如，企业可以从分析客户购买和使用产品的情况入手，再逐步将分析结果用于销售、营销、服务及产品改进流程。

b) 企业级AI应用与普通演示型应用的主要区别是什么？

  • 企业级应用需要运行在受治理的数据平台上。
  • 必须具备权限控制、安全策略、数据治理、业务系统连接和持续运维能力。
  • AI不能只输出分析结果，还应在授权范围内处理企业数据并协助完成业务操作。
  • 企业最终目标是将AI嵌入业务，而不是停留在孤立的聊天工具或一次性Demo阶段。

8. CoCo黑客松规则与操作流程

a) 本次活动设置了多少个奖项？

  • 本次CoCo黑客松共设置3个获奖名额。
  • 最终3名获胜者将获得Snowflake相关奖品。
  • 参赛者需围绕分组主题构建应用，并在活动结束时展示成果。

b) 黑客松项目应重点关注哪些内容？

  • 构建应用前，应重点思考：
  1. 要解决什么问题。
  2. 为什么该问题重要。
  3. 目标用户是谁。
  4. 应用如何利用数据和AI解决问题。
  5. 最终成果如何进行现场展示。
  • 各颜色分组对应不同主题，团队应围绕本组主题进行构建。

c) 如何领取并登录CoCo测试账号？

  • 尚未领取账号的参会者需要扫描现场二维码。
  • 二维码对应网址建议使用电脑打开，手机端操作可能出现错误。
  • 基本流程如下：
  1. 在Register页面输入邮箱并注册Snowflake Web账号。
  2. 查收邮箱中的验证密码并完成登录。
  3. 在页面中获取最终测试账号信息。
  4. 使用页面下方显示的Username和Password登录Demo环境。
  • 需要注意：邮箱收到的密码主要用于完成注册，并不是最终制作Demo时使用的账号密码。
  • 不同参会者的账号地址可能不同，应以个人页面显示的信息为准。
  • 如果电脑弹出多重认证窗口，需要按照提示通过相应应用完成认证。

d) 登录后如何开始使用CoCo？

  • 登录后，可以在Snowflake主页进入Cortex/CoCo相关区域。
  • 用户可以通过自然语言创建Application，并围绕本组主题提出构建需求。
  • 网页版和Desktop客户端具备基本一致的功能。
  • 现场建议优先使用网页版，主要原因包括：
  1. Desktop安装需要一定时间。
  2. 现场网络带宽有限。
  3. 网页版无需安装，可直接开始使用。

e) 参赛过程中遇到问题如何获得支持？

  • 每张桌子附近均安排了Snowflake专家和导师。
  • 不同颜色分组的大屏幕旁也有现场老师提供支持。
  • 参赛者可以就以下问题随时咨询：
  1. 应用开发。
  2. 数据集选择。
  3. CoCo使用方法。
  4. 数据管道建设。
  5. 用例设计。
  6. 项目展示思路。
  • Snowflake首席开发者倡导者Dash Desai也将在现场为开发者提供咨询和支持。
