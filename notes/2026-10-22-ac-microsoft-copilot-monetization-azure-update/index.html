摘要

增长质量在改善：约两百万的增量里近一半来自"大客户 Pilot 转 Rollout"（0→1 的规模化转化），而非促销拉新，说明产品正从试点走向规模部署。Azure 增速呈稳健爬坡而非爆发：约四成→四成三→四成半→接近五成。每季新增约 1GW 算力的 KPI 按计划推进，但在高位基数上只贡献边际增量，且"新建→可售"存在时间差，Q4 才会更多兑现。AI 约占 Azure 三成、GPU 租赁约占两成（两者是重叠维度非互斥桶）。某头部 AI 实验室直接贡献约占 Azure 总收入一成半，是最大单一客户。

专家观点：

Q：Q3Copilot付费坐席实际做到了多少？相比计划是超还是欠？

Q3末（截止9月底）Copilot付费坐席实际约为三千六百万量级，超出计划。

Q：超出计划的增量从哪里来？结构怎么拆？

大客户Pilot转Rollout：——原本处于小范围试用（Pilot，可能一两个人或一个部门在试）的大企业，验证后推广到整个部门乃至全公司；

已有客户自然扩席：——已购买license的老客户追加席位；

Q3促销与Commitment：——季度内的促销活动和企业承诺合同带来的拉新。

第一块贡献最大，说明Copilot正从"试点"走向"规模部署"，这是比单纯促销更健康的增长来源。

Q："Pilot转Rollout"和"已有客户自然扩席"有什么本质区别？

特意区分了这两个概念：

已有客户自然扩席：指已经稳定购买Copilotlicense的客户，在原有部署基础上直接追加license，属于成熟客户的扩容；

Pilot转Rollout：客户此前仍处于"试用阶段"（Pilot），尚未形成稳定的全公司部署，可能只是一两个人或一个部门在体验。当他们用了之后觉得有效，从一个部门扩展到一个公司，这一步跨越虽然也带有"扩席"色彩，但商业实质上更接近新客户从0到1的规模化转化，而非老客户的边际追加。

Q：ARPU从Q2到Q3的提升，怎么拆解原因？

四个相互作用的因素，方向有正有负，净效应为正：

正向——存量Enterprise席位占比高：早期客户很多是按约三十美元刊例价付的，折扣少，拉高了存量mix；

负向——大客户Rollout的volumediscount：大单新增席位量大，Enterprisedeal有批量折扣，实际成交单价被摊低；

负向缓冲——Q3促销力度弱于Q2：Q2是冲财年末，促销更猛，拉低了Q2ARPU；Q3促销力度收窄，相对抬升了Q3均价；

正向——高价值EnterpriseMIX一期Bundle：一期打包Bundle总价近百美元，其中分摊给Copilot的部分约三十美元（会随比例浮动），高于Basic套餐的均价。

综合下来，老客户高价mix和弱促销的正面效应，盖过了大单折扣的负面效应，ARPU净小幅上升。

Q：什么是CopilotCoWorker？它是一个更贵的席位SKU吗？

CoWorker已经GA（正式商用），但它不是一个独立的、更贵的席位SKU，而是一个管理员可选择性开启的用量附加能力。开启逻辑是：

1.用户首先必须拥有Microsoft365Copilot的资格（即已经买了约三十美元/坐席的Copilot）；

2.然后由管理员通过spendingpolicy（支出策略）给特定用户单独开放CoWork权限，并同时启用usagebasedbilling（按量计费）；

3.如果管理员不配，普通用户即使在界面上看到入口也用不了。

CoWorker执行任务时会额外消耗CopilotCredits，因此真正的成本是在约三十美元坐席费之上再加一笔按量费用。但观察到：大部分管理员并不开启这个功能，因为担心用量失控，所以它目前对ARPU的实际拉动还很有限。

Q：CopilotCredits体系到底包含哪几类按量计费的能力？

列出CopilotCredits覆盖五个计费项：

CoWork（即CoWorker，agent自主执行任务）；

WorkIQAPI——把组织上下文图谱通过API提供给agent调用；

GitHubCopilot的Harness（agentic编码能力）；

StudioAgents（即CopilotStudioAgents，企业自建agent）；

AgentWorkflow——工具调用、MCP（ModelContextProtocol）类的工作流执行。

这五项共同构成了该巨头"席位+用量"混合计费模式的用量侧收入基础。

Q：WorkIQ具体是什么？基于什么技术？解决什么问题？

WorkIQ建立在MicrosoftGraph（组织图谱）之上。它的作用是把企业的组织上下文——包括人员关系、邮件、日历、权限、文档、会议记录、历史沟通——通过API开放给agent使用。

普通搜索只能回答"有没有这个东西"（信息检索）；

WorkIQ能回答"这个任务涉及哪些人、哪些文件、哪些会议、哪些历史沟通记录"，让agent的输出更贴合该企业的真实业务上下文。

WorkIQ的调用量目前普遍很小，支出增量有限，所以虽然理论上它会让企业支出超过约三十美元坐席费，但实际增量很小。

Q：用户在Copilot里可以选择不同的底层模型（如GPT6.1、Sora），选更贵的模型公司会额外付费吗？

不会。在Copilot界面中选择某美国头部AI实验室的不同模型都包含在现有套餐内，不额外向企业收费。模型选择本身不是计费维度，目前的计费维度仍然是"席位"加"那五类Credits用量"。这一点对理解其商业化口径很关键——模型升级不会立刻转化为单价提升。

Q：什么是Blended Revenue per Paid Seat？

由于传统ARPU只算席位费，不包含CoWork、WorkIQ等Credits消耗收入，另用一个口径叫混合每付费坐席收入，即把所有usage based收入摊到全部付费坐席上。强调：目前真正启用Credits的企业"不算特别多"，所以这个usage侧收入还处于早期。

Q：算力（GW）落地节奏如何？为什么增速没有跳升？

在规划口径下，该巨头每个季度新增约1GW的算力KPI，目前落地是按计划在推进的。但为什么新增1GW后增速只从约四成出头到约四成出头（略高）？因为：

这已经是"起量之后"的增速——前面几个季度已经在持续上量，1GW是在高位基数上的边际增量；

新增capacity从建成到真正转化为可售算力收入有时间差，Q4会有更多capacity完成这一转化；

同时强调：客户需求仍然超过capacity供给，不是需求不足，而是供给爬坡节奏决定了收入释放节奏。

Q：Azure收入结构里，AI和非AI各占多少？某AI实验室直接贡献占多少？

NonAIAzure收入占大头；AI相关收入：约三成；

在AI这三成里面，某美国头部AI实验室直接贡献的Azure消费约占Azure总收入的一成半；

剩下的AI部分包括：其他前沿模型（如某美国头部AI基础模型公司）、AI基础设施、企业AzureAI、其搜索产品、其他该实验室服务等。

也就是说，该实验室一家约贡献Azure总收入的一成半，是AzureAI故事里最大的单一客户。

Q：GPU租赁占Azure收入多少？和AI收入是什么口径关系？

GPU租赁约占Azure总收入的两成；

它包括三部分：该AI实验室租用的GPU、其他前沿模型厂商购买的GPUcapacity、以及企业客户购买的GPUVM实例。

Q：Fabric、OneLake、Foundry这些数据/AI产品增速和客户进展如何？

Fabric增速：约六成，显著高于Azure整体约四成三的增速；Q4预计进一步上行；

One Lake数据量：同比增长数倍，增速非常快；

Foundry+Fabric合计客户数：约一万六千家，客户增量快；

Fabric财务归属：在Cloud层，属于Azure数据服务，记在Azure口径内（不是记在Dynamics里，专门核对了财务归属）；

Azure绝对收入从内部变化报告看，AI正快速成为增长主力；

传统Azure并没有掉队，新增主要来自AI，但传统业务也在稳健增长；

数据层整体明显走强，客户需求仍然超过capacity。

Q：各块Copilot用量收入在财务上到底记在哪个部门？

很多人以为CoWork/WorkIQ的用量收入都记在Azure，实际上不是：

CoWork、WorkIQ：记在Microsoft 365 Copilot商业化收入里；

Studio Agents（Copilot Studio）：记在Power Platform；

Share Point Agents：记在M365；

GitHub Copilot（含Harness）：记在GitHub；

底层AzureOpenAI、Foundry、GPU：才记在Azure。

这意味着前面说的usage ARPU，并不计入Azure收入增速——它主要落在M365Copilot、PowerPlatform、GitHub等产品线。分析其分部收入时，不能把Copilot用量增长简单归因到Azure。

Q：本财年CAPEX计划有变化吗？还有什么值得关注的收尾判断？

明确：本财年CAPEX目前没有变化，没有上修也没有下修。

1.Copilot从试点走向规模部署：Q3超预期、年底目标上调到约四千六百万，未来一年还要冲到六千万以上，但路径是"席位单价微降、用量收入快速补位"；

2.Azure增速稳健爬坡但不是爆发式：Q3约四成三、Q4约四成半、明年H1接近五成，瓶颈在capacity供给而非需求，毛利率因GPUmix微降但正在通过Fabric/Foundry向高价值企业数据业务转型来修复；

3.该AI实验室已是干净的商业大客户：自CY26Q1起按Commitment全额付费，约占Azure收入一成半，不再有投资Credit对冲的成分。
