Q&A

当前大语言模型 (LLM) 发展的进展如何？主要瓶颈是什么？

大语言模型 (LLM) 的发展依然迅速，特别是在推理、代码编写、工具使用和多模态能力方面。主要瓶颈在于长周期任务的可靠性。虽然模型在涉及 10 到 20 个步骤的任务中表现令人瞩目，但当要求它们自主运行较长时间（如几个小时）时，错误往往会不断累积。为应对这一挑战，需要改进的关键领域包括提高训练数据质量、加强后训练评估、改善内存管理以及实现更高效的推理。

Anthropic 和 OpenAI 等公司正如何试图克服长周期任务的挑战？这种进展是渐进的还是以突发性突破为特征？

解决长周期任务的进展从根本上说是渐进的，尽管从外部看来可能像是一次突然的飞跃。在训练、后训练、工具使用、上下文管理以及将智能体整合到研发循环本身等方面，都在进行增量式改进。例如，Anthropic 公开报告称，AI 协助完成了超过 90% 的受测研发任务，形成了一个可以加速进度的反馈循环。然而，预计并非所有实验室都会以相同的速度前进。例如，模型可靠完成一项编码任务的能力可能会从 20 分钟逐渐延长到一小时，然后再延长到几个小时。对于用户来说，当模型的可靠性跨越某个阈值，使他们能够委托整个工作流而不仅仅是单个步骤时，就会体验到一次突破。OpenAI 注意到，用户越来越多地向智能体分配相当于数小时人类工作量的任务。虽然各实验室可能享有相似的扩展趋势，但在数据质量、后训练以及有效利用 AI 进行研发等方面的执行力可能会有所不同，这使得某个实验室能够暂时领先，直到其他实验室赶上。

您能否详细说明为什么训练数据和内存被认为是长周期任务的主要瓶颈，以及 Anthropic 正在使用哪些具体方法（例如基于 harness 的方法）来解决这些问题？

在数据质量方面，挑战不再是数据量，而是拥有多步骤工作的高质量轨迹，这包括规划、工具使用、从错误中恢复以及验证。在记忆方面，长任务可能会超出模型的有效上下文窗口，导致其丢失决策记录或重复工作。Anthropic 公开的应对方法是基于 harness（测试框架/支架）的，包含四个关键方法。首先是任务分解，将大型工作分解为更小、易于管理的步骤。其次是使用外部内存，在模型直接上下文之外存储计划、跟踪进度并记录重要决策。第三是上下文管理，当上下文变得太大时，对其进行总结或重置。最后一种方法是验证，即在继续下一步之前，使用测试或另一个智能体来检查工作。例如，对于一项耗时数小时的编码任务，与其让一个模型实例在上下文中保留所有内容，不如让 harness 维护一个进度文件，使用 Git 历史记录，并将工作分解为不同的功能，为每个部分向全新的上下文提供一个干净的状态。Anthropic 已经公开描述了为此类工作使用初始化和编码智能体模式，以及规划器-生成器-评估器架构。

除了长周期任务之外，LLM 下一步的主要能力提升领域有哪些？具体针对哪些应用？

未来 LLM 的发展有三个关键领域值得关注。首先是计算机使用和智能体，这涉及超越简单的回答问题，通过点击、输入、导航和完成工作流来主动操作软件。当连接到公司系统和权限时，这种能力就会演变为企业级智能体。第二个领域是科学研究，模型将从总结论文过渡到生成假设、运行分析和协助实验。第三个领域是物理世界的交互，包括机器人技术、实验室设备，最终扩展到工业系统。Anthropic 已公开表示正在这三个方向上积极推进。

您能否提供更多细节，说明 Anthropic 是如何在计算机使用、科学研究和物理世界交互方面追求进展的？

在计算机使用方面，目标是让模型能够看懂屏幕并操作软件以完成整个工作流，而无需人类逐步干预。当集成到公司系统中时，这将成为企业级智能体。在科学领域，目标不仅限于回答具体问题，还包括协助文献综述、假设生成、数据分析和模拟。Anthropic 正在通过云科学计划、科学工具和研究合作伙伴关系推进这一目标。对于物理世界交互，其范围比仅仅 3D 和空间理解更广；它包括感知、物理定律、规划、反馈和控制硬件。据公开消息，Anthropic 正在尝试用于实验室和制造设备的机器人及接口。

LLM 应用在计算机使用、科学研究和物理世界的市场成熟及采用预期时间表是怎样的？

预计这三个领域的采用速度将有显著差异。计算机使用智能体已经在进行商业化扩展，预计在未来五年内将获得更广泛的采用。科学 AI 也预计在五年内成为一种有意义的工具，主要作为研究助手和工作流自动化层，而不是进行完全自主的科学研究。由于硬件、安全性和可靠性施加了更为严格的限制，物理世界智能体的进展将较为缓慢。Anthropic 当前的产品供应已经反映了这一进程。

除了 Claude Code 之外，Anthropic 还在规划哪些其他主要产品或战略方向？

最清晰的战略方向是将编码中展示的智能体能力扩展到一般性的脑力工作。Co-Work 产品正是为此设计的，并且 Claude 可以集成到 Slack 等团队工作流中，在其中保持上下文并执行委托任务。除此之外，还有用于研究应用的 Claude Science。公司还在开发托管智能体以及针对金融等行业的特定垂直智能体。这反映了从聊天机器人功能向主动执行工作的智能体的更广泛战略转变。

Anthropic 年度经常性营收 (ARR) 的主要来源是什么？其未来增长的关键驱动因素和制约因素是什么？

年度经常性营收 (ARR) 的主要引擎是企业使用，而不是消费者订阅。企业通常从 API、Claude Code 或 Claude for Work 开始，然后在整个组织内扩展使用。未来的增长预计将来自更深的企业渗透率、智能体工作负载的增加以及对 Co-Work 等更广泛产品的采用。增长的主要制约因素是算力可用性与成本、模型竞争、定价压力，以及智能体在生产工作流中达到足够可靠性的需求。例如，一个客户可能会先让 100 名开发人员使用 Claude Code，随后扩展到数千名工程师，同时增加基于 API 的智能体用于支持和内部运营。作为其大型企业客户的一个衡量标准，Anthropic 公开表示，截至 2026 年 2 月，已有 500 多家客户在该公司每年的支出超过 10 亿美元。

Anthropic 近期 ARR 增长率放缓的核心原因是什么？未来几年的增长前景如何？

百分比增长率的放缓主要不是由于市场饱和，因为绝对增长仍然非常庞大。公开报告显示，到 2026 年 7 月底，年化营收约为 650 亿美元，而 2025 年底约为 20 亿美元。影响增长率的关键因素包括大得多的营收基数、来自 OpenAI 的更激烈竞争、更便宜的开源权重模型的可用性，以及企业客户对价格变得更加敏感。展望未来，绝对增长预计将保持强劲，但百分比增长率应继续回归常态。未来几年年度增长的合理估计在 50% 到 100% 之间，而不是以前看到的百分之几百的增长。上行空间将由 Claude Code、企业扩张、API 消耗和智能体驱动。最大的下行风险是竞争和持续的价格压缩。

在 Claude Code 和 Co-Work 之间，目前哪个产品对 Anthropic 的营收贡献更大？

Claude Code 目前是明显更大的营收贡献者。Anthropic 公开披露，早在 2026 年 2 月，Claude Code 的年化运转率就超过了 25 亿美元，其中一半以上来自企业使用。Co-Work 主要用于非工程任务，尽管增长迅速，但它是今年 (2026 年) 才推出的。因此，它目前的营收贡献在实质上要大大小于 Claude Code。

Co-Work 的产品形态预计将如何从当前状态演变？

该产品预计将从基于委托的模型演变为持久且主动的模型。目前，Co-Work 的运作主要是接收用户的目标，然后执行必要的步骤。未来的方向是让智能体理解项目的上下文，监控连接的系统，并主动运行计划任务，无需等待新的提示就能自动呈现工作。这种演变的开端已经通过涉及记忆、连接器、计划任务和浏览器操作的功能显现出来。

您能否澄清一下 AI 智能体背景下的“记忆 (memory)”和“连接器 (connectors)”概念？

这些是软件功能，而非硬件。“记忆 (Memory)”是指智能体跨会话保留有用上下文的能力，例如用户偏好、项目详细信息或先前的决策，这避免了每次都从头开始。“连接器 (Connectors)”是允许智能体访问 Google Drive、Slack、GitHub 或企业数据库等外部系统并与之交互的集成。本质上，记忆为智能体提供了连续性，而连接器则授予它访问执行实际工作的系统权限。

对于像 Co-work 这样的 AI 智能体，关键的差异化因素是什么？是什么驱动了用户黏性？主要是关于理解上下文和持续学习吗？

虽然基础的智能体能力正在迅速趋同，但更强大的差异化在于智能体能积累多少有用的上下文，以及它与用户工作流连接的深度。记忆、连接器、权限和历史项目上下文等因素可以产生转换阻力（转换成本），尽管它还不是一条显著的护城河。例如，Anthropic 正在围绕记忆、连接器和可复用的组织工作流构建其差异化优势。

鉴于生态系统集成的重要性，像谷歌这样的公司，由于其原生拥有访问 Google Drive 和 Google Docs 等产品的权限，是否相对于 Anthropic 和 OpenAI 等竞争对手具有显著优势？

是的，谷歌拥有真正的优势。其 Gemini 智能体原生于 Workspace 生态系统，能够以较低的集成摩擦跨 Gmail、Drive、Docs 和 Calendar 访问上下文。然而，这并不是一条不可逾越的护城河。Anthropic 可以将其 Claude 智能体连接到 Google Workspace，但谷歌更深层的原生集成、权限处理、更低的延迟和用户分布仍然是关键优势。虽然谷歌可以在原生集成上获胜，但其他提供商仍然可以通过卓越的模型或智能体性能、执行质量以及跨更广泛供应商的合作来有效竞争。

AI 智能体和模型的进步对硬件有何影响，特别是关于计算需求、芯片、内存和互连方面？

高级 AI 智能体的崛起显著增加了推理需求，而不仅仅是训练需求。单个用户任务可能需要智能体调用模型数十次，每一步都将上下文向前传递。这将硬件需求从单纯的最大化 FLOPS 转移到了在计算与 HBM 容量、内存带宽和互连带宽之间取得平衡。具体来说，更长的上下文要求增加了 KV 缓存 (KV cache) 的压力。更复杂的推理任务增加了需要生成的 token 数量。多智能体系统（多个模型实例并行工作）推高了对并行通信的需求。

您能否详细说明生成的 token 增加以及并行智能体的使用具体如何影响硬件需求？

生成的 token 增加主要推高了 GPU 计算时间和内存带宽需求。在解码过程中，GPU 会重复读取模型权重和 KV 缓存以生成每个 token。并行智能体通过同时运行许多推理流增加了一个新维度。这需要更大的聚合加速器容量、HBM 和网络带宽。在实践中，这推动了系统设计向更高带宽的内存、更快的互连以及更高效的推理调度方向发展。
