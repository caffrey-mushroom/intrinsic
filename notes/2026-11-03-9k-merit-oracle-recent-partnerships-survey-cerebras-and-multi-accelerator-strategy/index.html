1. Oracle与Cerebras合作概况

a) Oracle与Cerebras合作的核心内容是什么？

  • 双方近期在Oracle AI World大会上宣布建立合作伙伴关系，计划通过Oracle云基础设施（OCI）向客户提供基于Cerebras晶圆级引擎的高速AI推理服务。
  • Cerebras晶圆级引擎将计算与内存集成并协同部署于单个晶圆级处理器上，主要优势包括：
  1. 减少数据移动及芯片间通信需求。
  2. 提升长推理序列的Token生成速度。
  3. 支持需要多步骤连续推理的智能体AI工作流。
  4. 提供更低、更可预测的推理延迟。
  • 双方合作的核心目标是满足企业客户对高速、稳定AI推理的需求，尤其是智能体AI场景。

b) 双方合作目前处于什么阶段，预计何时上线？

  • 双方目前主要完成了合作伙伴关系及产品方向的宣布，实质性部署工作尚处于早期阶段。
  • 基于OCI的Cerebras推理服务计划于2027年推出，但尚未公布：
  1. 具体上线日期。
  2. 首批上线区域。
  3. 支持的模型及实例类型。
  4. 定价方式及容量规模。
  • 专家判断，该合作更接近“先宣布合作、后开展测试与部署”的模式，而不是已经完成充分验证的成熟项目。
  • 后续双方预计将开展硬件评估、模型适配、基准测试、基础设施部署及商业模式设计，再决定最终部署规模。

c) Oracle是否已经测试过Cerebras硬件？

  • 截至目前，Oracle和Cerebras均未公开OCI环境下的测试结果，包括：
  1. 特定模型的每秒Token生成速度。
  2. 推理成本及每Token价格。
  3. 试点客户情况。
  4. OCI环境下的性能与稳定性表现。
  • Oracle尚未披露已在Cerebras硬件上部署或运行具体大语言模型，也未发布相关基准测试。
  • Cerebras独立宣称，其在大型开源模型上的单用户推理速度约为GPU云的2至7倍，但该性能能否在OCI环境中复现仍待验证。
  • 预计相关公开基准测试可能于2027年出现，Artificial Analysis等第三方平台的数据将成为重要观察指标。

2. 合作商业模式与信息披露时间

a) Oracle将采购Cerebras硬件，还是采购Cerebras云服务？

  • 目前双方尚未正式确定或公布具体运营模式，潜在模式主要有三种：
  1. Oracle采购模式：Oracle购买Cerebras CS-3完整系统，自行拥有算力并通过OCI销售推理服务。
  2. Cerebras托管模式：Cerebras拥有硬件，Oracle提供数据中心、电力、网络及托管服务，双方按客户使用量进行结算。
  3. BYOH模式：第三方客户拥有Cerebras硬件配额，Oracle提供部署硬件所需的基础设施及配套服务。
  • Cerebras主要销售CS-3完整系统，每套系统以一颗晶圆级芯片为核心。
  • 最终商业模式的关键在于硬件资产由谁持有，以及Oracle和Cerebras分别承担资本投入、销售、托管及客户服务中的哪些职责。

b) 当前尚有哪些商业信息未披露？

  • 尚未披露的信息包括：
  1. Oracle计划采购或部署多少套Cerebras系统。
  2. 双方的容量分配方式。
  3. 硬件所有权及折旧承担方。
  4. OCI面向客户的定价模式。
  5. 是否按Token、实例时长或预留容量收费。
  6. 服务是否通过OCI Marketplace销售。
  7. Oracle和Cerebras之间的收入分成及结算方式。
  • 这些信息可能要到服务接近正式上线时才能完全明确。

c) 未来应关注哪些信息披露节点？

  • 专家预计未来数月可能出现更多信息，重点关注：
  1. 11月12日：Cerebras发布第三季度财报，可能披露OCI合作是否形成硬件销售或订单。

  5. 2027年服务上线前后：预计将明确具体定价、硬件所有权、服务入口及支持模型。

3. Oracle选择Cerebras的战略原因

a) Oracle为什么选择Cerebras作为ASIC合作伙伴？

  • Oracle的核心战略不是押注单一芯片，而是针对不同客户工作负载提供更多基础设施选择。
  • Cerebras与Oracle重点推进的智能体AI工作负载高度契合：
  1. 智能体在执行任务的每个步骤中都需要推理。
  2. 推理速度越快，智能体能够完成的连续任务越多。
  3. 更低且可预测的延迟能够减少终端用户等待。
  4. 企业应用不仅关注速度，也关注稳定性和响应时间的一致性。
  • Oracle正在围绕Fusion、NetSuite、数据库、AI Workspace和App Composer构建智能体AI产品体系，Cerebras的高速推理能力可为这些产品提供基础设施支持。
  • Cerebras已通过OpenAI等客户初步证明规模化服务能力，而OpenAI同时也是Oracle的重要基础设施客户，这可能构成双方合作的潜在驱动因素。

b) Cerebras在快速推理市场中的稀缺性如何？

  • 专注超低延迟、高速推理的独立厂商数量有限。
  • Groq曾是该领域的代表性厂商，但在Nvidia取得其相关许可后，Cerebras被视为少数仍保持独立、专注高速推理的供应商。
  • Oracle同时引入Cerebras、SambaNova等ASIC合作伙伴，有助于：
  1. 避免过度依赖Nvidia。
  2. 对冲Groq技术被Nvidia整合后的供应风险。
  3. 为客户提供针对不同模型和工作负载的选择。
  4. 增强Oracle在AI基础设施定价和供应链中的议价能力。

c) OpenAI与Cerebras的关系是否会推动OCI合作？

  • 据专家援引公开信息，OpenAI已同意采购Cerebras约750兆瓦的推理容量。
  • OpenAI也是Oracle的重要基础设施客户，OCI可能成为部署相关Cerebras基础设施的可信平台之一。
  • 但该判断主要基于外部信息推测，尚无公开资料证明Oracle与Cerebras合作专门服务于OpenAI。
  • Cerebras可能优先满足OpenAI的大规模需求，这也可能影响OCI面向其他客户的容量分配及商业模式设计。

4. 企业AI中的“确定性”价值

a) 企业AI中的“确定性”具体指什么？

  • 确定性主要分为两个方面：
  1. 确定性行为：同一任务按照清晰、可重复、可审计的流程执行。
  2. 确定性性能：相同类型的请求具有相对稳定、可预测的处理时间和延迟。
  • 大语言模型本质上具有概率性，同一个问题多次输入可能得到相似但不完全一致的答案，不具备计算器式的绝对可重复性。

b) 企业如何提高智能体AI的行为确定性？

  • 企业需要在模型之外增加管理和控制机制，包括：
  1. 管控智能体可以读取的数据和上下文。
  2. 设置防护机制及企业政策。
  3. 将业务规则代码化。
  4. 验证大语言模型输出。
  5. 管理身份、权限及数据访问边界。
  6. 对关键操作引入人工审批。
  7. 建立评估和反馈闭环。
  8. 保留可审计的操作及输出记录。
  • Oracle通过Fusion智能体应用等产品，将概率性模型推理与确定性企业操作相结合，以企业事实和业务上下文为基础提升用户信任。

c) Cerebras与确定性性能有什么关系？

  • Cerebras强调超高速、低延迟和延迟可预测性。
  • 对企业智能体而言，响应时间稳定与平均速度同样重要，因为多步骤智能体会连续触发多次推理，单次延迟波动可能被整个工作流放大。
  • 因此，Cerebras的价值不仅在于每秒Token数，也在于能否提供稳定、可预测的服务水平。

5. Oracle多元AI加速器与基础设施布局

a) OCI Acceleron是否是Oracle自研ASIC芯片？

  • OCI Acceleron并不是AI ASIC芯片，而是Oracle的高性能云网络解决方案。
  • 其主要功能包括：
  1. 提供专用数据平面和优化的数据包路由。
  2. 将数据包处理从主机CPU卸载至专用硬件。
  3. 降低分布式训练和实时推理的网络开销。
  4. 提供高吞吐量及超低延迟的数据传输。
  5. 减少大规模AI集群中的通信瓶颈。
  • Acceleron本质上是硬件与网络算法的结合，战略作用类似于Nvidia围绕NVLink构建的高速互联能力。
  • 对Oracle而言，自有网络技术可以提高系统级性能，并改善承载第三方训练和推理芯片业务的利润率。

b) Oracle为什么同时合作多种ASIC？

  • 不同芯片适合不同工作负载：
  1. Google TPU侧重规模化训练及高性价比推理。
  2. Cerebras侧重超高速、低延迟推理。
  3. SambaNova侧重多模型切换及智能体工作流。
  4. OpenAI Jalapeno主要服务OpenAI定制推理需求。
  5. Positron Atlas侧重低功耗、小型开源模型及现有数据中心部署。
  • Oracle提供的核心价值不仅是芯片，还包括电力、冷却、网络、机房及云服务管理。
  • 多元化芯片策略有助于OCI扩大客户覆盖面，并降低对单一GPU供应商的依赖。

6. Google TPU与OCI合作分析

a) Google TPU的主要优势是什么？

  • Google TPU已通过大规模训练和推理工作负载证明其矩阵计算能力，是目前经过验证程度较高的Nvidia替代方案。
  • 主要优势包括：
  1. 训练性价比较高。
  2. Google具备芯片、模型、软件及应用的完整全栈能力。
  3. 可利用自有TPU测试Gemini模型及开展多模态训练和推理。
  4. 已在Google Photos、Google Maps等大规模数据和应用场景中得到验证。
  5. 同时提供训练芯片和推理芯片，满足不同工作负载需求。
  • Oracle计划通过多年扩张将TPU部署提升至吉瓦级规模，Anthropic和OpenAI等客户均存在显著需求。

b) Google TPU的主要风险是什么？

  • 最大风险是软件迁移成本：
  1. 大量客户当前基于Nvidia CUDA生态构建。
  2. TPU软件体系仍以JAX为优先。
  3. 原生PyTorch支持仍处于预览阶段。
  4. 客户可能需要重新移植和优化模型。
  • 系统层面还存在以下待验证事项：
  1. OCI Acceleron网络与TPU组合后的系统性能。
  2. 机架规模直接液冷的部署要求。
  3. 区域、实例类型及定价尚未公布。
  4. 系统级性能能否达到客户目标仍有待观察。
  • 双方目标时间为2027年，距离正式落地较近，但仍需等待更多部署信息。

7. OpenAI Jalapeno与Oracle的角色

a) Jalapeno是什么，Oracle在其中承担什么角色？

  • Jalapeno是OpenAI委托Broadcom开发的首款定制推理加速器。
  • Oracle与OpenAI拥有大规模基础设施合作及积压订单，因此OpenAI如需部署Jalapeno，Oracle预计会提供配套的数据中心和云基础设施支持。
  • Jalapeno有望：
  1. 提升OpenAI的推理效率。
  2. 降低OpenAI对通用GPU的依赖。
  3. 深化Oracle作为OpenAI基础设施提供商的角色。
  • OpenAI称Jalapeno运行部分开源模型的速度可达到竞争芯片的约1.5倍，但公开数据仍然有限。

b) Jalapeno是否会向OCI普通客户开放？

  • 现阶段Jalapeno主要服务于OpenAI自身，并非OCI客户可以直接租用的公开产品。
  • 尚不确定OpenAI未来是否会像Google通过OCI销售TPU服务一样，将Jalapeno商业化。
  • 目前主要不确定性包括：
  1. 没有明确推出日期。
  2. 没有公开定价。
  3. 没有公开部署规模。
  4. 尚不确定是否面向第三方客户开放。
  • Jalapeno属于第一代产品，正式披露时间较短，技术成熟度和商业化路径仍待观察。

8. Cerebras技术优势与结构性局限

a) Cerebras的核心技术优势是什么？

  • Cerebras采用晶圆级计算架构，主要优势包括：
  1. 单用户推理速度较高。
  2. 芯片内计算和内存距离更近，减少数据搬运。
  3. 可提供较稳定、可预测的推理延迟。
  4. 适合需要实时响应和多步骤推理的智能体任务。
  • Cerebras宣称其速度可达到部分GPU云服务的6至7倍，尤其适用于愿意为速度和确定性支付溢价的客户。

b) Cerebras的主要技术局限是什么？

  • 每块晶圆级芯片仅有约44GB片上内存，导致大型模型需要跨多套系统运行。
  • 跨系统扩展会带来：
  1. 更多晶圆级系统需求。
  2. 更高机房空间占用。
  3. 更高资本支出。
  4. 晶圆之间的通信瓶颈。
  5. 每Token成本可能高于其他方案。
  • 因此，Cerebras可以提供极高速度，但未必能提供最低的每Token价格。
  • 模型参数和上下文窗口越大，片上内存限制越突出，需要连接更多晶圆，可能抵消部分片上集成优势。

c) Cerebras的商业风险有哪些？

  • Cerebras对OpenAI的客户依赖程度较高，存在客户集中度风险。
  • 如果其有限产能优先用于满足OpenAI需求，可能影响其他OCI客户可获得的容量。
  • Cerebras作为规模较小的供应商，在产能、融资、持续研发和售后支持方面无法与Nvidia直接相比。
  • Oracle与Cerebras最终能否形成规模化业务，仍取决于性能、成本、容量和可靠性验证结果。

9. SambaNova产品定位与风险

a) SambaNova的主要产品优势是什么？

  • SambaNova采用三层内存架构：
  1. 432MB片上SRAM。
  2. 64GB高带宽内存。
  3. 256GB至2TB DDR5内存。
  • 该架构支持模型在毫秒级完成切换，适合需要频繁调用不同模型的智能体和多智能体工作流。
  • 随着智能体根据任务复杂度选择不同模型，快速模型切换有助于优化每Token成本。
  • SambaNova机架平均功耗约20千瓦，可采用风冷，无需液冷，能够部署在更多现有数据中心。
  • 公司宣称其系统可支持：
  1. 10万亿参数模型。
  2. 约1,000万Token的超长上下文。
  3. 相比GPU低约3倍的总体拥有成本。

b) SambaNova的主要风险是什么？

  • 相关性能和成本数据主要由公司自行披露，缺乏充分、独立的公开基准验证。
  • SambaNova使用较早一代的HBM2E，而非更新的HBM3，其架构能否完全弥补内存代际差距仍待观察。
  • SambaNova仍属于小型供应商，存在：
  1. 持续经营风险。
  2. 产能和交付能力风险。
  3. 售后与生态支持风险。
  4. 被大型厂商收购后战略改变的风险。
  • 市场存在Intel可能收购SambaNova的传闻，但尚不能作为确定事实。

10. Positron Atlas在OCI上的定位

a) Positron Atlas是什么，目前是否已在OCI商用？

  • Positron Atlas是一套基于FPGA的AI推理系统，目前已经在OCI上正式商用。
  • 其下一代Titan产品计划于2027年推出。
  • Atlas的主要优势包括：
  1. 功耗较低。
  2. 部署相对简单。
  3. 支持兼容OpenAI的API。
  4. 可运行开源Hugging Face模型。
  5. 适合现有数据中心及部分边缘计算场景。

b) Positron适合哪些企业AI场景？

  • Positron公开展示的数据主要围绕Llama 3.1 8B等较小模型，因此更适合：
  1. 部门级AI项目。
  2. 解决特定问题的小型模型。
  3. 成本敏感型企业工作负载。

  1. Cerebras现有产能已被其他工作负载占满。
  2. GPU生态成熟，可帮助新模型更快上线。
  3. Cerebras部署进度可能尚未跟上新模型发布时间。
  4. 新模型上下文窗口扩大，对内存容量提出更高要求。
  5. Nvidia GPU可借助片外HBM扩展内存，灵活性更高。

c) 该变化反映了Cerebras架构的什么权衡？

  • Cerebras通过片上集成减少计算与内存之间的数据搬运，可以获得高速和低延迟。
  • 但单块晶圆无法容纳持续增长的大模型及超长上下文所需的全部内存。
  • 其核心权衡是：
  1. 片上内存带来更高速度和确定性。
  2. 片上容量有限，限制超大模型和长上下文扩展。
  3. 跨晶圆扩展可增加容量，但会提高系统成本和通信复杂度。
  • 因此，Cerebras更适合高度重视单用户速度和低延迟的场景，但未必适合所有超大模型及最低成本推理场景。
