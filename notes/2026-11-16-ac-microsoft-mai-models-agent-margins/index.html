核心摘要

  1. 专家称微软自研MAI模型在外部调用中的使用场景正显著扩张，主要聚焦标准化、高吞吐、中低复杂度任务，复杂强推理和前沿场景仍以OpenAI为主。
  2. 在M365 Copilot总体token池中MAI占比约10%，较2025年的4%~5%提升5到6个百分点，同等质量下单位推理成本较OpenAI旗舰降低50%、延时降低约20%；GitHub Copilot首选仍是Claude，MAI占比仅个位数。
  3. 内部自用场景MAI占比约24%~25%，计划财年底承接内部约1/3的模型能力；开源模型在Azure MaaS API token收入中的占比从2025财年约10%升至2026年一季度的14-15%。
  4. 微软稳步降低OpenAI在模型底座中的占比以防范断供、涨价或合规风险，与Anthropic是定向投资加算力承诺的伙伴关系，Claude主攻长上下文、法律、编码和政企合规场景，但不做独家绑定。
  5. Foundry作为统一调度平台、Copilot Fusion按质量、时延和成本动态路由多模型，被视为区别于AWS和GCP的核心护城河，专家认为Token同质化未来或类似IaaS现状。
  6. 毛利测算以每1000美元agent收入为基准：以GPT为底座全成本毛利率约22%、边际约30%以上；Claude全成本约30%、边际接近40%；开源模型边际约60%、全成本约40%但合约单价约低20%。
  7. 自研MAI在MAIA 200集群上运行，同等吞吐算力成本下降30%~40%，每1000美元收入总成本约210美元，是毛利最高的选项，但能力边界限制其难以承接复杂推理和超长agent任务。

摘要

/ Token同质化未来或如同IaaS现状。/ MAI与大客户模型的竞合关系，智能路由等。

【以下为专家观点汇总，具体细节仅供参考。】

在A公司外部客户调用中对MAI的使用场景是否在显著扩大？

首先需要说明，短期内外部自研和MAI的模型使用场景正在显著扩张，主要聚焦于标准化、高吞吐、中低复杂度和评价指标统一化。复杂强推理、超长任务及前沿场景仍以OpenAI为主。流量环比增速较高，主要因为此前MAI的模型在MaaS API token中的占比很低，并非要全部替代前沿闭源模型。在M365 Copilot的标准化办公负载场景，如邮件摘要、归类、短邮件草稿、Excel基础公式生成、Teams会议纪要转录、PPT简单改写、常规配图生成等，逐步转向MAI的模型。在M365 Copilot总体token池中，MAI的模型目前占比约10%，较去年（2025年）增长5到6个百分点，去年仅4到5%。在同等质量下，单位推理成本较OpenAI旗舰版降低50%，延时降低约20%。这是目前的量化表现。

在GitHub Copilot产品层面，首选仍是Anthropic Claude，OpenAI Codex作为补充，MAI的模型目前仅有轻微放量，占比仍为个位数。希望未来MAI的模型能更多用于编码场景。目前MAI的模型在安全风险层面，包括安全扫描、日志结构、解析、漏洞初筛等初步应用，表现尚可。复杂性方面，如安全合规预测、骇客攻击预测、等级预测、溯源以及高级危机解决方案推荐，OpenAI和Anthropic的Claude基本都能覆盖。如果偏向本地化、高合规性的场景，Anthropic的Claude使用会更多。因此，在高阶安全和风险层面，MAI的模型占比依旧是小个位数。

在语音转录和搜索摘要场景，MAI的模型如transcribe等占比相较前述场景更高。目前在病的一些搜索摘要或SPEECH语音生成与稳定性方面，MAI的模型占比已达到10%几，不到20%左右。对于多模态或定制化的语音视频转录，高端场景仍以GP T为主。

在A公司内部场景中对MAI的使用场景是否同样在显著扩大？

内部自用场景中，MAI的模型占比基本接近24%~25%。这也是内部高阶占比进一步压低成本的可行性所在，需要用MAI的模型，无论是底座二开还是MAI的think、transcribe等，来实现自有agent。目前表现较好。今年（2026年）财年底计划，MAI的模型要承接内部约1/3的模型能力，主要用于自用场景。对于外部层面，Foundry托管MAI系列对外API token的占比很小。今年（2026年）希望MAI的模型在原有friendly调用模型收入基础上有所提升。基于MAI的B级客户、底座私有私调的微调，目前占比约1%，计划扩充到3%~4%。在一方、三方推理总值中，MAI的模型占比非常小，希望整体能提升4~5个百分点。

怎么平衡和Anthropic/OpenAI的商业关系？

展望2027年，MAI会进一步紧跟 OpenAI 或 Anthropic当期新旗舰模型的迭代，同步接入 OpenAI 或 Anthropic新一代旗舰模型到Foundry的同时，加快MAI的追赶速度。刚才提到，4到6个月就要进行一次追踪，基本上各项工作都已完成。稳步降低OpenAI在整体模型底座的占比，主要是为了防范OpenAI在供给端出现中断、涨价或合规风险等问题，对A公司自身造成巨大冲击。

从Anthropic的角度来看，A公司与Anthropic更多是定向投资加算力承诺的绑定伙伴关系。Anthropic承诺购买A公司的算力，A公司将Claude接入Foundry，包括Copilot Fusion等引擎，作为长上下文、法律文档、编码、合同审核等场景的主力选择。这与OpenAI形成了差异化补充，Claude和GPT并不是简单的替代关系，而是针对客户分层场景进行选择。对于大客户，如金融律所、跨国合规企业、重AI研发的技术企业，Claude凭借长上下文、稳健对齐、高能力AI编码能力，成为他们的首选。A公司会将Claude作为独立方案推荐给这类客户。

在边界方面，A公司不会做独家绑定。Anthropic同样直接向其B级客户销售，坦白讲，Anthropic在B级客户销售能力上比OpenAI强一个档次。因此，A公司不会盲目扩大Claude在通用推理场景的占比。Claude在通用场景不会盲目扩张，避免与自有模型及其他模型产生恶性竞争。基于上述逻辑，未来一年将持续上线Claude新旗舰版，并接入Foundry进行微调评估，包括安全套件补充。重点推荐给欧盟及美国政企客户，作为数据主权和合规维度的差异化选项，这是Claude的另一优势。

开源模型在Azure API调用中的比重趋势？在大厂模型矩阵中的角色？

开源模型如Llama、Mistral及国内开源模型。这些并非自研或头部闭源模型的替代品，而是底座补充，主打主权型、低成本、区域合规性。去年（2025年）F26一年，API token在Azure最小圈中，开源模型占比10%。今年（2026年）一季度，Azure的MaaS API token收入占比已提升至14-15%。不过，开源模型在北美、西欧或亚太亲美发达国家的C-level决策者眼中并不关键，担心政策风险。对于开源模型，A公司不投入其训练研发，核心价值定位仍是托管层面，提供IaaS基础设施、安全加固、企业级SLA、微调评估工具、RDBC、Fabric数据打通等服务。收入主要来自算力租赁，如为开源模型商提供IaaS云服务、托管服务分成及配套服务，并非模型授权费用。

总体来看，Foundry作为统一的模型调度平台，负责模型控制与调度。这也是为什么管理层在季度披露会上反复强调Foundry的重要性。所有模型，包括自有、OpenAI、Anthropic及开源模型，都共用一套评估体系，内部会评估模型优劣及适用场景。安全网关、数据链路、计费体系将进一步整合统一，Fabric统一沉淀内部KB、记忆及Agent状态。Copilot Fusion可将复杂任务拆解为子任务，自动分配给不同模型，在质量、时延和成本之间动态调整与权衡。最终形成AIOS平台，并进一步推进Copilot平台化。这套逻辑是A公司最核心的护城河，也是区别于AWS、GCP的重要差异化点。

公司在对比不同模型毛利率时的测算基准是什么样的？

毛利率等于营收减直接成本。对比毛利规则时，需统一基准假设，确保a和b对比时基础量一致，否则自研与其他家的毛利无法比较。以agent workflow为例，平均一轮智能体交互包含两到三次模型调用、RAG检索、一到两次工具调用、状态记忆复写、错误重试（重试率10~15%）。输入输出token比例锁定在8:1，是算力报告核算基础线。算力利用率统一按75%机架利用率计算，部署区域以美东主区域为准，统一规定电价、机房PUE、折旧年限等。收入按实际book revenue核算。

成本方面，模型采购成本主要存在于OpenAI和Anthropic等3p，MAI和开源模型采购成本为0。MAI的模型研发属于长期R&D，不计入直接毛利口径，需看全周期R&D摊销。开源模型也无外部采购成本。算力成本包括加速器折旧、电力、机房、制冷、机架运维等，MAI的模型在Base 2优先跑200卡，算力成本显著低于NV GPU和GPT Claude。GPT和开源模型主要跑NV GPU，成本节省明显。

AGENTS编排层固定开销（如FUSION路由、记忆向量库、RAG检索、工具调用调度、状态持续化维护）在同一agent方案下，几类模型编排层开销基本一致。内部核算时，编排层成本按agents会话数分摊，不按token API分摊，这是agent场景与普通API场景的最大区别。第4层为安全审计与租户隔离，统一进行安全网关、内容过滤、合规日志等，成本按会话分摊，同租户下模型成本一致。

毛利口径分为边际毛利和全成本毛利。边际毛利不含历史性模型研发资本摊销，仅用于fusion自由路由、负载调度、增量资源分配、伙伴比价等。边际毛利不含研发成本，因此毛利高于GPT，但因未计入研发资本，相对更高。全成本毛利需叠加自研模型资本化、摊销、总部内部投放等，毛利低于边际毛利，但仍高于OpenAI。整体来看，在agent场景下，基准场景大客户企业agents、75%算力利用率标准下，所有模型毛利率都会下降，分开来看GPT、OpenAI模型在成本角度下，模型成本按4类分。

怎么对比A公司的agentic方案中MAI、Claude、GPT、和开源模型的毛利率？

每1000美元客户收入，成本包括GPU推理折旧、电力和运营费用约180美元，AGENTS编排、记忆、RAG工具回调约70美元，合规约30美元，总计约280美元，占比约70%。如果以OpenAI的GPT为基础，按全毛利计算，毛利率约22%；按边际毛利计算，约30%至30%以上。这是以GPT为基础的大致逻辑。

如果采用Anthropic Claude模型，模型算力成本包括token采购、合约分成、折旧等，GPU推理算力（自有或租用）、电力和运营费用约170美元，调度层面约70美元，安全约30美元，总计约600美元，比OpenAI略低。以Claude为底座，按全毛利计算毛利率约30%；边际毛利约30%多，接近但不到40%。

Claude的agent适用于agent场景时，毛利高于GPT，主要原因是采购成本较低。长上下文场景下，agent轮次更少，重试开销也更低。但该赛道相比GPT仍较窄。例如文档密集型合规、长上下文、coding等复杂推理agent，Anthropic Claude能力略弱于GPT。Fusion路由会优先将长文档合规性agent导向Claude，这既能能力匹配，也有毛利优势，因为Claude agent毛利高于GPT。

第三个层面是自研MAI。自研MAIA 200集群，标准化agent如邮件处理、表格agent、客服agent、简单代码agent、批量单据agent等。从成本角度看，模型采购成本基本为零。算力侧，MAIA200集群加折旧、电力、运营，同等token吞吐量成本下降30%至40%。在1000美元B级客户收入中，算力成本约110至120美元，调度层70美元，安全合规保障30美元，总计约210美元，明显低于Anthropic的600美元和OpenAI的700美元。自研MAI是毛利最高的，也是Fusion路由降本提升agent毛利的核心抓手。约束因素不是毛利，而是能力边界，这是目前MAI的主要瓶颈。对于复杂推理、超长深度agent，MAI生成的agent质量尚未达标，不能强行主动路由。主要需将标准化高吞吐agent负载迁移至MAI，前提是客户体验和SLA不降低，针对SMB和C端用户提升agent整体毛利池。

针对开源模型毛利，客户支付agent方案加算力费，无外部采购成本，但算力需分成。开源模型客户会选择量化蒸馏，进一步降低token成本，但客户端幻觉风险和体验可能下降。以开源模型为基础，1000美元B级客户收入，模型采购成本为零，GPU算力（含折旧、电力、运营）约180至200美元，具体取决于底座模型如Llama或Mistral的GPU消耗。调度层70美元，安全合规30美元，总计约280至300美元。按边际毛利计算，约60%；按全毛利计算，约40%。开源毛利仅次于MAI，高于G PT和Claude，但存在两大约束：一是客户价格敏感度高，开源agent合约单价普遍低于GPT、Claude、OpenAI甚至MAI，约低20%，毛利率虽高但绝对值低于MAI；二是合规、知识产权和许可风险带来额外审计成本和潜在费用。开源定位主要是主权合规、低成本、客户底层生态布局，并非提升高毛利的核心打法。

站在公司层面，A公司是一家B端公司，历史上属于标准云时代公司，没有经历互联网时代，相对传统。对开源态度较AWS、GCP、Meta更弱，更倾向于1P或3P闭源模型，服务高阶B端客户，提供更优质服务。总结来看，无论选用GPT、Claude、自研MAI还是开源模型，做agent时毛利水平各有差异。核心目标不是单一追求最高毛利，而是能力与合作伙伴平衡，包括与OpenAI、Anthropic、开源模型伙伴的平衡，以及算力供给约束，如卡延迟、高低阶、自研MAI进展等，需动态调整agent和模型能力的毛利，并通过多模型分层调度反复优化。MAI是不可或缺的拼图，但目前中短期内，公司仍处于高业绩增长承压阶段，主要业绩来源于B级大客户。OpenAI、Anthropic GPT或Claude模型、开源模型仍是B级客户主要调用模型来源，MAI更多嵌入并支撑M365 Copilot底层应用，面向B端、C端的应用层token或API token消耗，也包括自用逻辑。整体模型切层及毛利情况如上。
