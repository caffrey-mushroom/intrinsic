专家访谈纪要

1. 中国开源模型的企业采用与竞争格局

a) 中国开源模型是否正在分流OpenAI和Anthropic的收入？

  • 分流现象已经发生，但目前主要影响收入增长轨迹，而非导致OpenAI或Anthropic的绝对收入下降。
  • 当前企业关注度较高的中国模型依次为：
  1. Kimi
  2. GLM
  3. Qwen
  4. DeepSeek
  • 在较小规模、云原生和AI原生客户中，约有15%的模型支出开始转向中国开源模型；未来3个月可能进一步升至20%，但短期内不太可能达到50%。
  • 即使Claude的支出占比由100%下降至85%，由于客户整体AI预算仍在增长，Anthropic的绝对支出仍可能继续上升。
  • 因此，中国开源模型当前带来的主要影响是：
  1. Anthropic和OpenAI的份额被逐步稀释。
  2. 两家公司的收入仍增长，但增速可能放缓。
  3. 企业开始重新评估不同任务是否有必要使用最昂贵的前沿模型。

b) 不同规模客户对中国开源模型的采用有何差异？

  • 小型客户采用速度明显更快：
  1. 典型客户的AWS年度经常性支出约为500万至1,000万美元。
  2. 这类客户预算敏感度更高、组织更灵活、决策链条更短。
  3. 当前转向中国开源模型的支出占比约为10%至15%，且仍在上升。
  • 大型客户采用相对谨慎：
  1. AWS支出达到5,000万至1亿美元的客户，通常对应营收20亿美元以上的大型企业。
  2. 这类企业具有完整的法务、合规和风险控制体系，组织惯性更强。
  3. 大型客户预算更充足，也更有能力承担OpenAI和Anthropic的高价格。
  4. 目前大型客户尚未积极采用中国开源模型。
  • 大型企业的主要顾虑并非单纯的模型能力，而是模型与中国的关联可能带来的数据安全、合规和地缘政治风险。
  • 通过Amazon Bedrock托管后，企业对中国模型的信任度会明显提高，因为AWS承担了模型审核、托管和安全隔离的角色。

c) 企业会对某一开源模型形成长期忠诚度吗？

  • 当前中国开源模型之间并不存在明显的客户护城河，企业对具体模型的忠诚度较低。
  • 如果Kimi优于GLM，或DeepSeek、Qwen推出更强模型，客户可能迅速切换。
  • Bedrock降低了不同模型之间的接入和切换成本，进一步推动企业进行多模型比较。
  • 开源模型的核心优势不仅是价格，还包括：
  1. 用户对模型拥有更强的掌控感。
  2. 可以根据企业自身需求进行调整和定制。
  3. 更容易构建多模型架构，降低对单一前沿实验室的依赖。
  • 当前企业对Kimi、Qwen的接受度似乎高于DeepSeek，后者仍面临更明显的安全和地缘政治顾虑。

d) Kimi等模型会优先冲击Anthropic的哪些产品？

  • Anthropic最强的Opus模型相对安全，因为在追求极致能力的场景下，OpenAI和Anthropic仍被认为处于领先位置。
  • 压力更可能首先落在Haiku、Sonnet等中低档模型：
  1. 如果最强的Kimi模型能力优于较弱的Anthropic模型，同时价格更低，企业缺乏继续使用后者的理由。
  2. Bedrock允许客户更方便地在Opus、Kimi、OpenAI等模型间切换。
  3. 长期来看，企业可能重新审视Haiku等模型的定位和必要性。
  • Anthropic实际使用量并非均匀分布在Haiku、Sonnet和Opus之间，而是明显集中于Opus。
  • 只要Anthropic能够保护Opus这一核心收入来源，其短期收入受到的冲击仍相对可控。

e) 当前全球模型竞争格局如何？

  • 企业市场目前主要围绕3类模型竞争：
  1. Anthropic
  2. OpenAI
  3. 中国开源模型
  • Llama目前在企业讨论中的存在感较低，受访者几乎没有听到客户主动讨论Meta的开源模型。
  • Gemini的讨论热度也有所下降，尚未形成与OpenAI、Anthropic和中国模型相当的企业关注度。
  • 从企业市场视角看，“开源模型”正在越来越多地与“中国模型”形成关联。

2. 企业AI成本压力与治理需求

a) 为什么AI成本突然成为企业的首要议题？

  • 成本治理是近期才快速出现的新趋势，受访者约从5月下旬开始频繁听到相关讨论。
  • 5月以前，企业很少讨论成本、成本治理和成本可观测性；目前这些问题已经成为客户最关注的第1、第2大事项。
  • 成本快速增长主要有3个原因：
  1. 开发人员的AI使用量持续上升。
  2. 过去接近无限使用的补贴模式正在结束。
  3. 企业此前严重低估了Token消耗速度。
  • 企业内部的激励机制仍鼓励工程师增加AI使用量，FinOps和财务团队则开始追问成本增长原因，两者之间形成明显矛盾。
  • Meta被视为极端案例，其内部强制员工使用AI工具，Token消耗较少的工程师甚至可能被认为缺乏竞争力。

b) 客户最希望Bedrock提供哪些功能？

  • Bedrock当前最受期待的3项功能分别是：
  1. 原生成本治理工具。
  2. 智能提示词路由与模型选择。
  3. 更快接入最新中国开源模型。
  • 前2项需求同时来自大型和小型客户，第3项需求主要来自较小规模客户。
  • 原生成本治理工具需要支持：
  1. 为不同开发者设置Token限额。
  2. 为高价值、可信任开发者开放更高额度。
  3. 限制普通员工使用高成本模型。
  4. 对超额使用设置审批机制。
  5. 提供更完善的成本可观测性。
  • 智能路由功能的目标是根据任务难度自动选择模型：
  1. 简单问题，如查询天气，应调用成本最低的模型。
  2. 复杂编码或推理任务，才调用Opus等高端模型。
  3. 企业希望减少员工无差别调用最高成本模型的行为。
  • 客户对新模型上线时间的容忍度约为1个月，不要求发布当天即可使用，但不希望Bedrock的接入延迟过长。

c) 企业当前如何控制AI支出？

  • 最常见的方式不是禁止使用AI，而是优化模型结构：
  1. 减少Opus使用。
  2. 增加Haiku、Amazon Nova等低成本模型使用。
  3. 对提示词进行智能路由。
  4. 将部分任务迁移至中国开源模型。
  • 更严格的企业会在Token额度用完后停止服务，要求员工提交额外额度申请，并可能拒绝申请。
  • 开源模型迁移是一种更复杂、更激进的成本控制方式，尚未成为大型企业的主流选择。
  • 企业目标不是将月度支出从5万美元降到4万美元，而是避免支出从1万美元迅速增长至50万美元。
  • 企业更希望将支出增速稳定在合理范围内，例如从1.5万美元增长至6万美元，而不是完全冻结AI预算。

d) 为什么企业不会主动选择低成本模型？

  • 当员工不需要直接承担Token费用时，缺乏主动节约成本的动力。
  • 即使Haiku的成本仅为Opus的50%，并可实现99%的任务效果，员工仍倾向于使用Opus。
  • 工程师甚至可能用Opus查询天气、修改简单邮件或完成小型代码调整。
  • 因此，未来模型结构变化不会主要依赖员工自觉，而会由企业通过系统规则强制推动。

e) 现有成本管理工具能否满足需求？

  • Claude Apps Gateway for Amazon Bedrock能够提供配额、权限和模型使用限制，是Anthropic在企业采用中的一项优势。
  • OpenAI目前缺少完全同等的成本治理功能，成为其在Bedrock上扩大企业采用的障碍。
  • Light LLM作为开源工具，可以跨模型进行成本控制，但存在以下问题：
  1. 维护成本较高。
  2. 无法像原生功能一样即插即用。
  3. 企业部署阻力较大。
  • 客户强烈希望AWS直接在Bedrock内提供原生成本治理能力，预计可能在re:Invent或其他大型会议上发布相关功能。

3. OpenAI与Anthropic的应对策略及收入前景

a) Anthropic和OpenAI是否可以通过大幅降价应对开源模型？

  • 两家公司很难对旗舰模型进行全面大幅降价，原因包括：
  1. 仍在签署大量数据中心扩建协议。
  2. 算力和基础设施投入极高。
  3. 公司整体仍处于大额亏损状态。
  4. 在争取上市的背景下，无法继续扩大补贴和亏损。
  • 即使单Token毛利率较高，也不代表公司层面已经盈利。
  • OpenAI尤其面临高额算力和数据中心建设成本，因此价格下降空间有限。
  • 当前竞争局面类似“囚徒困境”：
  1. 两家公司无法停止前沿模型研发。
  2. 也难以大幅降低价格。
  3. 如果放缓投入，可能失去技术领先地位。
  4. 如果继续投入，则现金消耗和亏损压力会进一步上升。

b) 前沿模型公司将如何回应中国开源模型竞争？

  • 主要方式是推出更多低成本、中小型模型，而非直接降低最强模型价格。
  • OpenAI和Anthropic预计会更加重视Haiku、Luna、Tara等较低成本产品。
  • OpenAI近期已对除最佳模型之外的多款模型降价，这被认为与中国开源模型竞争有关。
  • 未来可能出现比Haiku更便宜的模型，以覆盖简单任务和成本敏感场景。
  • 该策略既可以保留旗舰模型的高端定位，也可降低客户迁移至中国模型的必要性。

c) Anthropic未来几个月的绝对支出会下降吗？

  • 受访者明确认为不会出现绝对支出下降。
  • 更可能出现的变化是：
  1. 环比增速放缓。
  2. 支出逐渐趋于稳定。
  3. 市场份额被开源模型小幅分流。
  4. 绝对收入继续增长。
  • AI业务不适合进行传统同比比较，因为一年前的数据参考价值较低，更适合关注月度环比变化。
  • 企业现阶段并不是减少AI支出，而是防止支出继续呈指数式增长。
  • 成本治理讨论仅出现约2至3个月，可能尚未充分反映在Anthropic的收入数据中。
  • 未来几个月新增收入可能有所放缓，但不会出现显著萎缩。

d) 为什么成本控制不会阻止Anthropic继续增长？

  • 企业竞争压力形成了另一个“囚徒困境”：
  1. 如果竞争对手大规模使用AI，企业很难主动削减投入。
  2. 企业担忧节省AI预算会导致长期竞争力下降。
  3. 即使部分投入可能浪费，也无法判断具体哪部分会浪费。
  • 新客户签约、客户渗透率提高和整体Token使用增长，仍将支撑Anthropic收入。
  • 企业会优化支出结构，但不会全面禁止AI使用。

e) OpenAI在Bedrock上的企业竞争力如何？

  • 随着新一代模型推出，OpenAI在Bedrock上的竞争力和客户兴趣均有所提高。
  • Claude在企业市场的绝对主导地位已经减弱。
  • OpenAI当前的主要障碍不是模型能力，而是成本治理工具不足。
  • 企业即使愿意使用OpenAI，如果无法对开发团队设置配额、权限和成本限制，也可能推迟采用。
  • 预计OpenAI正在将成本治理功能列为高优先级开发事项。

4. 企业合同、Token定价与商业模式

a) 企业AI合同通常如何构成？

  • 企业合同一般包含2部分：
  1. 固定席位许可费用。
  2. 年度最低Token消费额。
  • 例如：
  1. 500个席位，每席位每月50美元。
  2. 即使用量为0，也需支付50×500×12的年度席位费。
  3. 此外，还可能承诺100万至150万美元的年度Token最低消费额。
  • 企业必须在12个月内完成最低消费，即使实际使用量为0，也需要支付合同金额。

b) 为什么企业经常提前耗尽年度Token额度？

  • 很多客户在合同第2个月或第3个月就用完全年最低Token消费额。
  • 这说明：
  1. 企业严重低估实际使用量。
  2. Anthropic自身也未准确估算客户需求。
  3. 开发者使用量的增长速度远高于合同签订时的预测。
  • 客户在合同年度仅过去约20%时便耗尽额度，随后需要额外采购Token，使实际成本显著超出预算。

c) 企业客户能够获得多大折扣？

  • 企业能够获得批量折扣，但幅度并不特别大。
  • 普通企业协议的平均折扣约为20%至30%，而非50%。
  • 如果客户能够在非高峰时段进行批处理，折扣可能达到50%左右。
  • Anthropic和OpenAI正在减少高额补贴，原因是：
  1. 无限制使用模式不可持续。
  2. 两家公司仍在亏损。
  3. 上市准备要求其改善财务表现。
  • 个人高价订阅过去接近无限使用，现在超出限额后会立即被限流，标志着用户补贴阶段基本结束。

d) Fable为什么尚未得到广泛采用？

  • Fable此前在美国受到禁用限制，影响了其早期普及。
  • 即使解除限制，仍存在3个主要障碍：
  1. 价格高于Opus。
  2. 企业普遍认为Opus能力已经足够，没有迁移动力。
  3. 企业数据是否会被用于模型训练存在明显顾虑。
  • 在企业已经面临Opus成本压力的情况下，价格更高的模型难以获得采用。

5. 生成式AI应用结构与发展趋势

a) 企业当前最主要的AI应用是什么？

  • 编码仍是生成式AI最核心的企业应用。
  • 当前约90%的使用场景与编程相关。
  • 编码相关用途包括：
  1. 代码生成。
  2. 代码库分析。
  3. 代码修改与调试。
  4. Claude Code等编程工具。
  • 某大型客户的AI月度运行率较3个月前增长约20%至25%，主要增量仍来自编码。
  • AI并未像1年前预期的那样迅速影响所有岗位，但对程序员的影响高于预期，代码生成量出现爆发式增长。

b) 大量生成代码是否已经创造业务价值？

  • 部分统计和实际案例显示，80%至90%的生成代码可能没有形成可衡量成果。
  • 企业正在更严格地评估：
  1. 代码是否真正进入生产环境。
  2. 是否带来收入、效率或客户增长。
  3. 是否只是增加了无效代码量。
  • 对多数客户和团队而言，目前大量AI生成代码尚未形成明确业务回报。
  • 下一阶段企业将从“鼓励使用”转向“评估产出和投资回报”。

c) 非编码应用的发展情况如何？

  • 非编码应用主要包括：
  1. Claude Enterprise和企业聊天工具。
  2. Databricks Genie。
  3. Amazon Quick。
  4. Copilot类办公工具。
  • 这些应用仍在增长，但整体规模较小、增速相对稳定，因此市场讨论度较低。
  • 非技术员工的采用速度明显慢于开发人员，主要原因包括：
  1. 自然使用习惯尚未形成。
  2. 企业难以强制营销、财务等人员持续使用。
  3. 非技术用户中的滞后采用者更多。
  • 即使1年后更多普通员工开始使用聊天机器人，其使用强度可能仍明显低于开发人员。

d) 未来1年企业AI支出结构会如何变化？

  • 当前约90%的使用与编程相关，其中约80%使用Opus。
  • 未来最先发生的变化不是编程占比下降，而是高价旗舰模型占比下降。
  • 预计1年后：
  1. Opus等旗舰模型在总体支出中的占比可能由80%至90%降至40%至50%。
  2. 编程相关支出占比可能由85%至90%降至约70%。
  3. 简单任务将更多转向Haiku、Nova或开源模型。
  4. 非技术员工的AI采用会逐步提升，但增长相对缓慢。
  • 企业将通过强制模型路由，而非依靠员工主动选择，实现支出结构优化。

6. 编程工具竞争与Anthropic的产品护城河

a) 当前开发者主要使用哪些编程工具？

  • 目前真正具有明显竞争力的第一方编程工具主要是：
  1. Claude Code
  2. CodeX
  • AWS拥有Amazon Q，但企业开发者通常不会优先选择Amazon Q替代Claude Code。
  • 聊天场景下，企业可以较容易地在Opus、OpenAI、Gemini或Nova之间切换。
  • IDE和CLI编程场景的切换成本明显更高，因为开发者已经适应特定工具的：
  1. 操作格式。
  2. 代码输出方式。
  3. 工作流。
  4. 上下文管理能力。

b) Claude Code为何构成Anthropic的重要护城河？

  • Claude Code用户黏性较强，企业很难强制开发者更换工具，否则容易引发明显抵触。
  • 在Claude Code内部，用户主要在Anthropic自身模型之间切换，不能自由使用其他厂商模型。
  • 因此，即使聊天和API层面的模型切换成本较低，Claude Code仍能将高价值编程需求留在Anthropic生态内。
  • 相比Claude Enterprise或通用聊天机器人，CLI和IDE才是Anthropic更重要的防御能力。
  • 专家认为，IDE是Anthropic最关键的产品护城河之一。

c) 企业如何从Claude Code切换至GLM等模型？

  • 如果企业希望开发人员使用GLM，通常需要改用GLM对应的产品或重新搭建编程工作流。
  • Claude Code作为闭源产品，不会主动鼓励客户接入竞争模型。
  • 小型公司和初创企业更愿意尝试新的开发工具，大型企业则因已有成熟流程和合同体系而更加谨慎。
  • 因此，开源模型在API层面的份额迁移会快于IDE和编程工具层面的迁移。

7. Bedrock的商业模式与AWS战略

a) AWS更希望客户使用闭源模型还是开源模型？

  • 对企业销售团队而言，最重要的是客户业务继续运行在Bedrock上。
  • 客户从Anthropic转向OpenAI通常不会构成问题，只要支出仍留在Bedrock。
  • 如果客户转向低成本开源模型，导致Bedrock年支出从500万美元下降至200万美元，理论上并非理想情况。
  • 但目前AWS尚未观察到如此极端的支出下降。

b) 为什么AWS不担心客户转向低成本模型？

  • AWS当前的判断是，模型价格下降会刺激使用量增长，即“杰文斯悖论”。
  • 例如：
  1. 模型价格下降50%。
  2. 使用量可能增长约1.7倍，而非完整增长2倍。
  3. 最终总体支出可能大致保持稳定。
  • 至少在2026年，AWS更关注扩大Bedrock使用量和客户覆盖，而非维护单一高价模型的收入。
  • 到2027年，若低成本模型对总体收入产生更明显影响，AWS的态度可能发生变化。

c) Bedrock对中国模型采用有何战略价值？

  • Bedrock能够提供：
  1. 模型审核。
  2. 安全托管。
  3. 权限隔离。
  4. 统一计费与治理。
  5. 多模型切换能力。
  • 相比直接从DeepSeek等模型厂商采购，企业对AWS托管模式的信任度更高。
  • Bedrock可能成为中国模型进入美国企业市场的重要安全屏障和信任中介。
  • 即使较为保守的客户，也开始表现出对Kimi、Qwen等模型的接受意愿。

8. AWS芯片、GPU成本与基础设施策略

a) AWS使用哪些芯片部署开源模型？

  • AWS向客户提供多种算力选择，包括：
  1. Nvidia GPU
  2. AMD GPU
  3. Trainium
  4. Graviton
  • AWS会尽可能引导客户使用自研芯片：
  1. AI模型部署优先推动Trainium。
  2. ECS和通用计算工作负载优先推动Graviton。
  • 对企业客户而言，模型在哪里训练并不重要，核心是模型最终部署在哪类算力上。
  • 即使模型在英伟达芯片或阿里云上完成训练，也可以在AWS的Trainium上进行部署。

b) GPU和内存涨价是否会推动AWS提价？

  • 目前尚未听到AWS近期提高GPU实例价格的明确计划。
  • AWS短期内受到以下因素保护：
  1. 与英伟达、美光等供应商签订长期采购协议。
  2. 大规模批量采购带来的议价能力。
  3. 部分资本开支在价格上涨前已经锁定。
  4. 约2,000亿美元资本开支承诺具有较强前瞻性。
  • AWS目前收入增长强劲，最新财报增速约37%，没有明显动力通过提价干扰增长。
  • 中长期不排除英伟达实例价格上涨，但这可能进一步推动客户迁移至Trainium和Graviton等AWS自研芯片。
  • 自研芯片是AWS控制基础设施成本、降低对英伟达依赖的重要手段。

9. AI支出对AWS整体增长的影响

a) AI是否正在推动AWS整体收入增长？

  • AI支出正在明显推动AWS增长。
  • 即使在成熟客户群体中，AI支出增速也可达到30%至50%。
  • 受访者负责的零售和CPG客户通常整体增速仅为8%至10%，而初创企业、安全公司等客户增速可能达到70%。
  • AWS整体约37%的增速高于部分成熟客户团队此前预期，说明AI支出的绝对规模已经足够大，开始对整体收入形成实质推动。
  • 1年前AI支出规模较小，即使增速很高，对AWS总体收入影响也有限；当前这一情况已经发生变化。

b) AI支出增长是否会直接带动计算、存储和数据库支出？

  • AI支出与核心计算、数据库支出并不存在固定的直接比例关系。
  • 理想情况下，AI支出从10万美元增长至20万美元，可能带动核心计算支出从100万美元增长至110万或120万美元。
  • 这种增长属于二阶效应：
  1. AI功能提升用户体验。
  2. 用户参与度和停留时间增加。
  3. 应用使用量增长。
  4. 最终带动计算、存储和数据库需求。
  • 如果AI功能未获得用户采用，即使已经进入生产环境，也可能无法带来任何核心云支出增长。
  • 因此，Bedrock支出增长本身与数据库支出基本相对独立，关键取决于AI应用是否创造实际业务价值。

c) AI应用落地效果为何呈现明显分化？

  • Amazon Rufus是较成功的案例，用户使用率较高，能够带动更多AI及相关计算支出。
  • Tapestry旗下Coach网站的AWS聊天机器人也是较具代表性的企业案例。
  • 但如果聊天机器人设计不佳、缺乏推广或战略定位不清，用户使用率可能低于1%。
  • 在低使用率情况下，即使模型已经部署，带来的非AI云支出也几乎可以忽略。
  • 企业AI应用正在呈现明显的两极分化：高使用率产品形成正向云消费循环，低使用率产品则成为无法产生业务回报的“黑箱”。
