Q:在追踪的 28 天基础上，最新的四周 ARR 是什么样的？Anthropic 在 8 月底、9 月底和 10 月底的 ARR 分别是多少？

A:有些信息仍然被严格控制，但我可以提供基准区间。10 月是非常强劲的一个月，尤其是横跨 9 月和 10 月的那段 28 天。有部分在 10 月收到的款项因为超出滚动截止日期而被排除，但增长仍在继续。10 月的 ARR 估计大约为 840亿美元到 860 亿美元。在追踪的 28 天基础上，收入大约为 64 亿美元到 66 亿美元。

这些更新后的计算与放缓论调相矛盾：增长仍在以指数级速度继续。公开披露的 7 月 ARR 为 650 亿美元。由于假期周期、竞争和 token 价格战，8 月相对平静，ARR 接近 700 亿美元。9 月 ARR 约为 760 亿到 770亿美元，10 月 ARR 在 840 亿到 860 亿美元之间。尽管面临中国开重量模型、OpenAI 的定价和其他竞争对手的挑战，公司仍回到其增长轨迹。模型现在以大约低 40% 的价格发布，同时保持更高的利润率。

公司目标是在 2026 年接近 1,100 亿美元，到 12 月底可能达到 1,100 亿到 1,200 亿美元之间。该增长由大型企业项目支持，特别是在医疗、制药和生物技术领域；8 月完成的项目现在正在跨工作流消耗 token；以及与Blackstone、Goldman Sachs 和 [HNF] 相关的合资活动，中端市场的试点正在进入生产阶段。自治代理全天候持续消耗 token，导致经常性工作负载快速扩张，尽管价格更低、存在免费额度或最低消费安排。

Q:新闻报道将 Anthropic 的第三季度收入估计为大约 168 亿美元。将其乘以四约为 672 亿美元。这与所述用于 9 月底和 10 月底的增长和 ARR 数据一致吗？

A:是的。第三季度收入约为 168 亿美元，这与 10 月 ARR 基准 840 亿到 860 亿美元是一致的。这些数字在财务上并不矛盾；它们反映了陡峭的向上增长轨迹。168 亿美元的季度总额平均到 7、8、9 三个月大约是每月 55 亿到56 亿美元，但月度收入是在快速增长，而不是保持平稳。

一个现实的分解大约是 7 月 51 亿美元、8 月 54 亿美元、9 月 63 亿美元，总计 168 亿美元。9 月的月度退出率为 63 亿美元则年化约为进入 10 月时的 750 亿到 760 亿美元。从 760 亿的 9 月退出率增长到10 月 ARR 的 840 亿到 860 亿，意味着 10 月收入大约为 70 亿美元，这看起来是可实现的，因为 9 月到 10 月是一个高增长期。10 月尤其繁忙，收入持续上升，轨迹支持约 1,100 亿美元的目标。

Q:鉴于预计的第四季度增长，到年底前新增收入中有多少来自新客户，多少来自现有客户的增加支出？你能否进一步说明那些新的大型财富 500 强项目？

A:假设 ARR 维持在大约 840 亿到 860 亿美元，超级增长在很大程度上更多集中于现有企业客户的支出增加，而非净新增客户获取。基于使用量的按需付费智能模型具有超过 900% 的 NRR，是最强大的财务指标。随着 token消耗上升并且项目深入嵌入组织工作流，现有客户会不断扩张。

净新增客户对规模很重要，但其即时收入贡献有限。一个新账户可能开始时仅为测试和评估分配每月 2 万或 3 万美元的开发者 API预算。真正的加速通常发生在三到六个月后，当账户将生产工作负载迁移到公司的模型时。因此，现有客户大约贡献每月新增账单的 75% 到 80%，而新客户大约贡献 20% 到 25%。

运行率由自动化和程序化消耗驱动，而非面向用户的软件。基于消耗的 API 占收入的超过 80%，尤其是通过高频开发者 API 调用。大型企业将 Claude模型系列集成到自动化工作流、后端数据库、消费类应用和编码工作流中。许多大型账户也通过云服务商（如 Amazon Bedrock 和 Google Claude Vertex AI）进入。Claude 市场允许现有企业使用 Claude积分，从而避免可能需要三到四个月来完成 NDA、合同和谈判的采购周期。

Q:ARR 的年化计算具体是怎样的：是将一周的收入乘以 52，还是将追踪的 28 天收入乘以 12？

A:公式使用总运行率收入。追踪的 28 天的消耗费用乘以 13，代表 364 天。按月订阅，包括 Pro 和 Max 等等级或按席位收费，则乘以 12。

Q:因为业务是基于消耗的，一些观察者认为向前预测一年后的 ARR 很困难。未来一年的增长如何预测？预测是非常困难，还是可以基于现有项目和合同？

A:虽然过程看起来简单，但预测并不单纯依赖像传统软件公司那样的管道投影。它结合了不可预测的产品高峰、12 周的企业前瞻以及有机扩张。企业客户通常会提前规划预算，但实际消耗取决于他们通过 API推送了多少数据。客户成功和客户管理职能随后对客户进行教育并将模型集成到更多工作流中，从而将 API token 的消耗乘数化。

很多增长并非始于销售人员在管道中录入交易。开发者会悄然将代码嵌入内部应用和代码库。因此，预测包括净美元留存模型并跟踪现有分组的扩张力度。约 900% 的 NDR 或 NRR 意味着去年花费 100 万美元的分组今年可能花费 900万美元。历史上的分组扩张曲线为未来提供了基线，尽管在多年内维持 900% 的年化曲线在统计上会高度波动。

预测还考虑风险因素、跨行业扩张、工作流转换率以及从聊天机器人向代理、自治代理和机器对机器工作负载的转变。消耗不再仅依赖人类提示聊天机器人；自治系统持续不断地消耗 token。因此，转换速度和现有客户基础的 token消耗是重要的预测变量。年初时预测 ARR 将超过 1,000 亿美元，当时看起来令人惊讶，但预计的轨迹已在实现。

Q:在最近的降价（包括对 Sonnet 的降价）之后，客户实际支付的混合价格在折扣和其他优惠后是多少？更低的价格是否导致现有客户消耗更多 token 从而增加 ARR？

A:是的，这是策略的一部分。截至 10 月 9 日，一些模型已发布，降价约为 40%，在某些情况下为 50%。在 8 月，Sonnet 的引入基线也从 3 美元和 15 美元下调为 2 美元和 10 美元。即便基础 token价格保持不变，缓存比率的大幅下降也改变了混合价格——每百万 token 的有效总成本——尤其对重度用户影响显著。

由于代理循环（agentic looping），混合价格也在发生变化。企业正在从简单的问答式聊天机器人转向持续运行的软件代理，这些代理会反复检查大型代码库和数据库。因为代理会反复传递几乎相同的大量 prompt上下文，仅做细微变动，企业客户的输入 token 中可能有 80% 到 90% 从缓存读取。在每百万 token 缓存成本约为 $0.10 的情况下，一个实现 90% 缓存命中率的工作流，其有效混合输入价格可能会从每百万输入 token $2 降至约 $0.30。

定制的企业折扣通常为 10%、20%，有时可达 25%。一旦客户用尽其预付的年经常性收入（ARR）承诺，折扣就会终止，边际使用将按标准 API 费率计费，除非重新谈判合同。尽管价格在某些情况下可能下降 40%、50% 或甚至 60%，但ARR 仍会继续上升，因为使用量增长速度远快于价格下跌。企业不会简单地把节省下来的钱存着不动；它们会改变使用 AI 的方式并部署后台代理，运行成千上万次隐藏迭代来调试代码、审计财务文件、管理物流和执行其他任务。一个人每天可能使用成千上万个token，而一个代理每小时可能使用数百万个 token。

Q:当 token 价格或成本下降时，使用量会立即上升，还是会因为大公司需要预算审批而滞后？消费激增通常会延迟一个或两个月吗？

A:近期经验表明，价格下降会促使客户购买更多。对于公司而言，较低的 token价格使得额外的工作流、更大的折扣和更高的承诺支出成为可能。增长是否立即发生完全取决于客户细分。对于自助式开发者或科技初创企业，几乎是即时的。对于大型企业，可能需要数周时间，因为要经历预算周期、管理层授权、采购订单以及证明为何较低的单价应当支持更大的整体预算。

企业客户对 AI 的了解在不断加深，并且仍然关注投资回报率（ROI）。即使审批需要数周、预算必须在各部门间传递，批准后支出仍会增加，因为客户会将模型更深度地嵌入其工作流。举例来说，一个在一月份消耗 1,000 个 token的组织，现在可能消耗超过 20,000 个，代表了 20 倍的增长。目前有超过 1,700 名客户的年付金额超过 $1,000,000，其中大多数客户的支出超过 $10,000,000 并持续扩张。

Q:大型企业客户的合同通常如何运作？客户是对下一年或若干年做出承诺，按年签订合同，还是设立预算上限？

A:有几种结构。一种是基于使用量的承诺并设定最低月度支出：如果客户承诺每月支出指定金额，就能获得约定的折扣。另一种是在三年或五年合同框架内做出为期六个月或一年的使用量承诺。例如，一个平均月度支出为 $100 的客户可能承诺达到 $120 或$130，并在证明该使用水平后获得折扣。

对战略性的重要客户（如财富十强）可能会提供定制化套餐。每席位收费可能对 1,000 或 5,000 名员工免除，客户改为按使用量付费。主要结构包括：固定席位费基线、固定基线加折扣 token使用、免除席位费以及完全定制的合同。在少数情况下，财富十强客户可能在最初三个月免费使用服务，之后才开始付费，但需满足最低支出要求。

许多客户最初是通过超大云服务商（hyperscalers）接入，随后寻求直接签约，通常带有最低支出或 ROI 要求。合同条款可以有很大差异，除了上述四种主要结构外，还可能采用客户特定的定制协议。

Q:随着 token 成本下降，是否有足够的新增企业工作负载能够经济地使用 AI，还是机会受限？你如何看待企业 AI 的渗透率，哪些用例最受欢迎，渗透率是否持续增长？

A:渗透率在提高。随着 token 成本下降，企业通常不会减少总体预算；相反，它们会问用同样的钱还能做更多什么。如果一项任务之前花费 $1，现在可以以 $0.50 完成，它们倾向于把剩下的 $0.50用于额外工作，而不是简单地减少开支。从基础聊天机器人向自主后台代理的转变需要巨量的 token，并解锁了此前不经济的用例。

以代理为中心的软件工程是增长最快的细分市场，由 Claude Code 等产品引领。代理不再只是帮助开发者写一行代码，而是可以检索整个代码库、识别 bug、运行测试并自动合并代码。另一个重要用例是持续的财务和法律审计。过去公司可能只抽样5% 的发票，而较低的 token 成本可以支持后台代理实时读取 50% 的财务交易、供应商合同和法律文件。有些项目从 20% 或 25% 的自动化起步，已经在某些情况下朝着完全自动化推进。

第三个趋势是大规模上下文注入。企业现在会在每次自动化查询时将完整的产品目录、数十年的客户服务历史和大量合规模板输入到长上下文窗口中。表面上的采用——员工在免费工具上做实验——与将其深度集成到核心业务基础设施之间存在实质性的差别。表层组织采用率大约为85% 到 90%，这里的定义是至少有一个部门或员工每天至少使用一小时 AI。

Q:扩大企业用例规模的最大障碍是什么：容量、安保审批、客户项目还是其他因素？是否有客户因为总 token 账单过高而设限或减少支出？

A:最大障碍往往不是绝对的预算规模，而是成本管理摩擦、支出上限和结构性市场竞争的综合作用。自年初以来，企业已积极对 token 支出进行上限管理，因为自主代理比人工触发的聊天机器人消耗额度更快。它们对 AI保持热情，提供方也以折扣响应，因此这些上限不应被解读为整体放缓。

一个重大进展是混合架构，即企业同时使用多个 LLM 提供商。在超大云服务商保证数据保持在相关国家领土内时，中国的开放权重模型现在可以在美国、英国和欧洲使用。这些模型能力很强且价格仅为一小部分，因此企业可能将其用于基础任务，同时把Anthropic 的模型保留用于高推理负载。到目前为止尚未观察到放缓，因为推理任务仍然消耗大量 token，但未来这可能成为一个威胁。

另一个障碍是公司购买基础设施的方式与企业采购 AI 的方式之间的合同错配。公司已承诺在可识别于 S-1 的提供商上投入约 $6180 亿的固定算力负债，而客户在合同到期时可以减少消费或转向竞争对手。因此，公司越来越要求 12 到 18个月的最低承诺，特别是来自财富 500 强的客户。早期协议可能涉及三个月或六个月的试用，但在向提供商承诺约 $6180 亿算力后保持这种灵活性变得困难。客户仍保留替代方案，且成熟的 IT部门正在采用混合架构。到目前为止尚未观察到客户流失或使用量负增长，但未来可能会发生。

Q:Anthropic 在《财富》500 强公司的渗透率是多少？考虑到微软在 Copilot 的积极部署、其既有的企业软件堆栈以及企业安全要求，你如何评估 Anthropic 在大型企业中的渗透情况？

A:企业覆盖是按每年化收入至少为 100,000 美元的客户来衡量，而不是按免费使用或小规模试用来计算。基于这一标准，超过 50% 的《财富》500 强公司是付费或高用量的 Anthropic 客户。所有《财富》10强公司均为客户，年支出从至少 100,000 美元到 500,000 美元或 1,000 万美元不等。按行业划分，全球 10 大银行全部为客户，10 大制药公司中有 9 家为客户，10 大互联网公司全部为客户，10 大医疗企业中有 8家为客户。

这些公司也可能使用微软的 Copilot；成为 Anthropic 客户并不意味着独占。Copilot 构成了一个复杂的、多层次的威胁，因为它与 Microsoft 365 和 Windows的无缝集成。在某些情况下，微软还可以将其捆绑免费提供，并通过相关的 token 消耗进行变现。同时，微软作为云服务提供商（CSP）通过其 Claude 市场分发 Claude，从而形成既合作又竞争的关系。

第三方数据显示，Copilot 的付费运行时市场份额已从大约 18% 或 19% 下降到 11%。那些在核心架构中进行深度集成并依赖大量后台 agent 的企业，越来越倾向于选择 Anthropic 的推理和长上下文能力而不是标准的Copilot 基线。Anthropic 在受监管行业尤其受欢迎，金融服务、医疗保健、编码和软件工程是其最强的垂直领域之一。

Q:处于受监管行业的客户是否担心他们的数据可能会被回传给 Anthropic？他们如何评估这一问题？

A:相关政策已明确表述，并且合同可以规定客户数据不会被用于训练当前或未来的模型。受监管公司主要担心的是专有数据未来可能通过模型训练进入公共领域。合同边界具有法律约束力：通过付费企业层级、Claude API、Claude Enterprise 工作区或 Claude 市场环境提交的数据不会被用于训练 Anthropic 的模型。

客户可以选择保留期，例如 28 天或 30 天，或自定义的零保留并立即删除。通过 Claude 市场部署或 VPC 发送的数据可以由客户自己的 IT 团队进行控制。安全团队还会评估认证和合规性，包括 SOC 2 Type II、HIPAA、GDPR 以及跨境合规。企业数据不会用于下一代模型训练，并且客户会被告知此项政策。

Q:在公司编制 2027 年预算时，典型客户的 AI 预算是否在大幅增加？这一趋势是持平、略有上升，还是显著上升？

A:市场正在从聊天机器人向 agents 转变，从 agents 向自主 agents 发展，现在又朝向机器对机器系统演进。大多数组织已经在其路线图中纳入了这一转变。关于 2027年预算的早期讨论显示，预算是在增加而非下降，尤其是在英国和欧洲市场。等效的美国数据尚不可用，而亚太地区的预算总体上持续上升。

财务部门现在要求价值证明和投资回报率（ROI）。作为基准，预算在上半年大约增长了 5 至 10 倍，然后在下半年将这一速度翻倍，达到大约 10 至 20 倍。这些水平目前已与大多数企业达成一致。

Q:目前可用的计算能力是多少，目前训练与推理的比例如何，预计到 2027 年将新增多少能力，以及未来训练与推理的比例将如何变化？

A:针对预训练、后训练和其他工作负载，公司目标是在今年年底前通过与 AWS、[X1]、AMD、Meta、Google 和 Broadcom 的承诺将规模接近 5 吉瓦。明年的目标基于签署的协议大约为 12 到 14吉瓦。还在考虑来自新型云提供商（neocloud）的较小机会，包括 50、100 或 300 兆瓦，其中一些可能在三年内扩展到 300 兆瓦。提供商的名称尚未公开。

这些容量将按合同阶段逐步交付，而不是一次性全部到位。预计从现在到明年，Google 和 Broadcom 将贡献大约 5 到 6 吉瓦，AWS 预计在 2028 年 2 月前贡献大约 5 吉瓦，另外还会有来自Nscale、AMD、Microsoft、SpaceX、[Colby] 以及其他 neocloud 提供商的容量。交付日期可能会推迟几周或一个月，且容量配额可能发生变化。

目前大约 65% 的计算资源分配给训练和研发，包括预训练和后训练，而 35% 分配给推理。到年末，计划的比例约为 60% 训练和 40% 推理。到 2027 年中期，预计约为各占 50%。到 2027 年底，预计推理将占约 55% 到60%，训练占约 40% 到 45%。推理毛利率超过 80%，因此增加推理比重有助于扩大利润率和履约支付。训练仍然至关重要，因为 Anthropic追求的是最优模型而非最便宜的模型，尽管未来的模型可能会辅助训练下一代模型并减少预训练所需的计算量。

Q:如果年末的计算能力为 5 吉瓦且 40% 分配给推理，那么这部分推理能力在 AWS、Azure、Google Claude 平台和其它芯片平台之间如何分布？

A:答案取决于芯片是用于训练还是用于推理，以及硬件是 AWS 的加速器、TPU、NVIDIA GPU 还是 AMD GPU。将 40% 的推理分配视为基线，指示性分布为：40% 为 NVIDIA GPU，用于高度 agent化的多步推理和实时音频或语音管道；40% 为 TPU；15% 为通过 Amazon Bedrock 的 AWS Trainium 2 或 Trainium 3；5% 为 AMD GPU。这是一个规划估算，最终分配与该估算匹配的精确程度仍不确定。

Q:Anthropic 向超大规模云提供商做出了大额固定承诺。如果经常性收入（ARR）未按计划增长，公司可能需要额外的债务或股本资金。在签署这些承诺时，公司对 ARR 增长的信心有多大？

A:公司有信心，因为这些承诺是基于详尽的预测。二月份的预测显示 ARR 将达到 1,000 亿美元，起初这看起来是一个不切实际的销售目标。然而，该预测被逐月拆分，公司随后遵循了这一轨迹。

对 2027 年的预测意味着四到五倍的增长。公开的预期在经历了 1,000 亿美元的一年之后可能更接近 2,500 亿美元，而公司的规划假设约为四倍增长。2025 年的 ARR 为 90 亿美元；如果 2026 年以 1,100亿美元收官，这将意味着超过 12 倍的增长。2027 年的四倍增长速度会放缓，因为市场逐渐趋于饱和，但这仍将是一个大幅增长。

对计算承诺的评估会考虑容量未能到位、电力或制冷短缺、市场崩溃或安全漏洞等风险。分析会衡量可以产生多少收入以及如何覆盖责任。计划中季度性地向推理转移有助于提高毛利和现金生成。增长也通过合作伙伴网络、合资企业、医疗和生物技术湿实验室、1亿美元收购 Coefficient Bio、增加市场拓展（GTM）人员和地理扩张来实现多元化。风险仍然存在，但预计 ARR 明年将继续增长。

Q:当前用于训练的芯片组合是什么？大多数训练工作负载运行在 Trainium 上，还是分布有所不同？

A:AWS 是 Claude 训练的主要合作伙伴并获得了最大的分配。据回忆，约有 50% 到 55% 的训练运行在 AWS Trainium 2 或 Trainium 3 上。其余份额分配在 TPU 和 NVIDIA GPU 之间：TPU约占 30% 到 35%，包括多模态对齐训练，而 NVIDIA 约占 10%。这些百分比为近似值。

Q:客户越来越多地针对不同工作负载使用不同模型：复杂推理使用高端模型，较简单任务使用二线或开源模型。这是真实趋势吗？Anthropic 将如何在保护推理利润的同时应对？会使用 Haiku 或其他更具成本效益的模型来留住客户吗？

A:推理利润率超过 80%，混合架构和多模型路由是真实的趋势。该策略假设客户可能会在基本任务上使用开源模型，而 Anthropic 的产品套件则作为智能层来编排这些低成本模型。低复杂度、高量且低利润的工作可以路由到诸如Llama、Haiku 或其他开源模型。高推理需求的工作则可以路由到 Sonnet、Opus 或 [Fable]。

开源模型运行成本低，但将其适配到专有企业数据上可能需要大型工程团队和大量内部基础设施。Anthropic 的应对措施包括更低成本的微调、上下文优化、提示缓存折扣以及为企业定制的适配器，以安全地将专有数据叠加到 Claude上。公司可能在通用客户服务上使用开源模型，同时为管理其知识产权的定制调优 Claude 模型支付溢价。

对抗开源和模型商品化的最终防线是从销售原始 API-token 基础设施转向销售成品的 Anthropic 应用和软件。在自治的机器对机器工作流中，哪怕 1% 的成功率下降也可能导致任务失败和 token浪费，因此可靠性很重要。客户在某些基础任务上使用 DeepSeek、Kimi K 或 GLM 5.2，同时在更高要求的工作负载上继续使用 Sonnet、Opus 和[Fable]。尚未观察到使用量或推理利润率的下降，旗舰模型的消耗仍在增长。目标不是在最低价上取胜，而是构建最好的模型。

Q:当 Anthropic 通过 AWS Bedrock 分发 API 时，它是否识别客户支付的金额、先支付渠道或平台费用，然后另行承担推理计算成本？收入和成本如何计算？

A:如果客户通过 AWS Bedrock 使用 Anthropic API 产生了 100 美元账单，Anthropic 首先支付平台费用。剩余收入然后与 AWS 按 50:50 分成，因为 AWS是主要合作伙伴并分发了大量流量。作为基准示例，如果在 100 美元账单上平台费用为 20 美元，则剩余的 80 美元将平分：Anthropic 会得到 40 美元，而 AWS 会得到 40 美元，外加那 20 美元的平台费，总计 60美元。

Anthropic 上个月尝试与 AWS 重新谈判，寻求降低平台成本或调整分成比例，但明年的安排保持不变。Google 使用不同的分成：在支付平台费之后，Anthropic 得到 70%，Google 得到 30%。Microsoft的安排各不相同；在一些协议中 Microsoft 得到 20%、Anthropic 得到 80%，而在另一些协议中 Microsoft 得到 30%、Anthropic 得到 70%。没有发现 Microsoft 在任何协议中获得超过30% 的情况。所有这些收入分成均发生在支付平台费之后。

Q:Microsoft 和 Google Claude Platform 的平台费率是多少？

A:Microsoft 和 Google Claude Platform 的确切平台费率记忆中不可得。可能存在 18% 这一数字，但无法确认。AWS 的平台费百分比在合同上是保密的，尽管它低于 Google Claude Platform和 Microsoft 的费用。在扣除平台费后，AWS 的分成固定为 50:50，而 Anthropic 在 Google Claude Platform 和 Microsoft 的安排中最多可获得 70%。

Q:Anthropic 试图与 AWS Bedrock 重新谈判其收入分成。预计何时会有新条款生效？

A:上个月尝试的分成比例重新谈判没有成功。AWS 在一周后审阅了提议并回应，提出了额外的承诺并可能在其他领域带来更多客户，但它不同意在来年更改分成比例，因为其认为市场不可预测。

现有的 AWS 经济条款将维持到 2027 年 12 月。预计将在 2027 年 10 月左右进行另一次讨论，以审查市场表现并决定是否可以在那时从可能更有利的立场重新谈判条款。与 Google 和 Microsoft 的合同讨论可能会在 3月或 4 月左右进行，尽管确切时间表仍不确定。

Q:未来，Anthropic 的产品和服务中将有多少百分比是直接交付的，多少通过超大云供应商交付？是否有更多客户转向 Claude 交付或直接采购？这种选择是由计算可用性还是安全性驱动？

A:与超大云供应商的协议有价值，因为它们消除了采购摩擦。客户可以立即入职并使用现有的 Claude 积分，而直接关系则需要合同、保密协议、演示和其他采购程序。今年年初，超大云供应商产生了大约 55% 的业务，Anthropic直接渠道产生了 45%。当前的组合约为 52% 直接和 48% 通过超大云供应商。

预测是在 2028 年 5 月左右达到约 75% 的直接或本地交付和 25% 通过超大云供应商交付。这并不意味着超大云供应商的绝对收入会下降；它们的贡献可能会继续增加，同时 Anthropic的直接收入增长更快。这是一个预测，而非保证的结果。
