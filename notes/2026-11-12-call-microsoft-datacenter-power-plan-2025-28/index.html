核心摘要

  1. 微软10月版规划显示数据中心电力交付总量将从2025年底10.6吉瓦增至2026年14.3吉瓦、2027年19.6吉瓦、2028年25.6吉瓦，年度增量分别为3.7、5.3和6.0吉瓦。

  3. 上述数据为电力交付口径，从电力交付到算力上线微软通常还需3—6个月，更接近6个月，2028年底交付的部分算力要到2029年才能使用。

  6. 专家推断OpenAI和Anthropic合计占AI推理需求70%以上、两者约3比1，微软内部及初创等其他客户约占25%—30%；2028年部分客户合同尚未签完，存在规划下修风险但需求仍强。
  7. GPU供应中NVIDIA约占80%—85%，其余为AMD、OpenAI自研芯片和微软Maia；风冷加sidecar方案最多延续到2027年的Rubin，2028年Rubin Ultra必须进入原生液冷数据中心，2027—2028年液冷供应主要依赖租赁。
  8. 按微软财务口径每兆瓦成本约为自建风冷1,350万美元、自建液冷1,650万美元、租赁1,790万美元、Partner Cloud 2,250万美元，因此微软正减少Partner Cloud，并让Oracle早期4年期合同到期后不再续租。

专家访谈纪要

1. 微软数据中心电力规划与部署节奏

a) 微软数据中心规划部门的职责和规划频率是什么？

  • 该部门负责微软全球数据中心的电力容量规划，核心内容包括：
  1. 何时建设数据中心；
  2. 在何地建设；
  3. 建设何种类型的数据中心；
  4. 配置多少吉瓦或兆瓦的电力容量。
  • 实际项目以兆瓦级为主，吉瓦级项目仍属于少数。
  • 该部门主要负责供应规划并发出规划信号，后续由交付团队执行建设和上线。
  • 规划通常每月更新一次：
  1. 当前分享的数据来自10月份完成的规划；
  2. 11月份规划尚未完成；
  3. 12月份不做规划；
  4. 下一次较有参考价值的更新预计在1月底形成。

b) 2025—2028年微软数据中心电力交付规划是多少？

  • 2025年年底：
  1. AI推理：2.0吉瓦；
  2. AI训练：1.5吉瓦；
  3. 通用云计算：7.1吉瓦；
  4. 合计：10.6吉瓦。
  • 2026年年底：
  1. AI推理：2.9吉瓦；
  2. AI训练：1.8吉瓦；
  3. 通用云计算：9.6吉瓦；
  4. 合计：14.3吉瓦。
  • 2027年年底：
  1. AI推理：5.1吉瓦；
  2. AI训练：2.0吉瓦；
  3. 通用云计算：12.5吉瓦；
  4. 合计：19.6吉瓦。
  • 2028年年底：
  1. AI推理：9.1吉瓦；
  2. AI训练：2.0吉瓦；
  3. 通用云计算：14.5吉瓦；
  4. 合计：25.6吉瓦。
  • 从年度增量看：
  1. 2026年较2025年增加3.7吉瓦；
  2. 2027年较2026年增加5.3吉瓦；
  3. 2028年较2027年增加6.0吉瓦；
  4. AI推理是后期增长最快的部分，2028年同比增加4.0吉瓦。

c) 这些吉瓦数据代表电力交付还是算力正式上线？

  • 以上数据全部采用“电力交付”口径，而不是“算力交付”口径。
  • 电力交付指：
  1. 数据中心机房已经建成；
  2. 电力已经接入；
  3. 之后项目移交给其他部门。
  • 电力交付后，还需完成：
  1. 网络设备和交换机部署；
  2. 服务器安装；
  3. 线缆连接；
  4. 设备启动；
  5. Hypervisor部署；
  6. 最终接入云端。
  • 从电力交付到算力正式上线，微软通常还需要3—6个月，更可能接近6个月。
  • 其他公司可能只需要3—4个月，微软内部流程相对较慢。
  • 因此，2028年年底完成电力交付的项目，部分实际算力可能要到2029年才能投入使用。

2. 美国大选后的政策影响与许可风险

a) 美国大选是否已经改变微软各年度的吉瓦规划？

  • 截至目前，各日历年度的总体吉瓦数规划尚未因大选发生变化。
  • 原因包括：
  1. 大选结束时间较短；
  2. 11月份规划尚未完成；
  3. 新政府班子要到次年年初才正式上任；
  4. 具体政策能否落地仍存在较大不确定性。
  • 预计2027年整体较为稳定，真正可能受到明显影响的是2028年。

b) 为什么2027年的项目受影响较小？

  • 计划在2027年实现电力交付的项目，主要许可基本已经取得，包括：
  1. 建设许可或立项许可；
  2. 土地建设用途许可；
  3. 并网及电力相关安排；
  4. 空气质量及其他环保许可。
  • 内部判断，新政府无法从法律层面追溯撤销此前已完成审批的项目。
  • 因此，2027年已进入执行阶段的项目确定性较高。

c) 新政府可能通过哪些方式影响数据中心项目？

  • 主要风险不是撤销已取得的建设许可，而是在验收阶段增加要求。
  • 可能受到影响的环节包括：
  1. 消防验收；
  2. 环境污染检查；
  3. 环保验收；
  4. 地方政府其他验收程序。
  • 例如，原本消防验收只需检查20个项目点，新规则可能增加到35个项目点，从而拉长交付周期。
  • 新规则通常还需经过州层面立法，再传导至执行部门，因此不会立即产生影响。
  • 大规模延误更可能在2027年年底至2028年年初开始体现。

d) 2028年项目受到政策影响的比例有多大？

  • 2028年AI推理新增算力大部分来自租赁项目。
  • 微软要求出租方在项目洽谈的前期阶段，就证明已经取得关键项目许可证，因此多数项目的基础许可风险相对可控。
  • 若进行情景测算，可按约20%的项目受到影响。
  • 考虑当前数字仍较软，也可以采用20%—30%的压力测试区间。
  • 影响形式主要是：
  1. 许可办理时间延长；
  2. 验收流程变慢；
  3. 电力交付延期；
  4. 少数项目调整地点。
  • 已立项项目最终被完全取消的情况仍然较少。

3. 德州项目风险与区域分散策略

a) 德州为什么成为当前政策风险最明显的地区？

  • 德州此前具备两项主要优势：
  1. 电力资源相对充足；
  2. 政策环境对数据中心较友好。
  • 因此，大量吉瓦级AI推理园区最初计划落地德州。
  • 新州长当选后，政策方向存在较大变数，部分政治表态也具有较强针对性。
  • 微软已取得许可的现有德州项目预计不会受到太大影响，但部分仍在洽谈的项目可能暂缓推进。

b) 微软为什么暂缓推进部分德州项目？

  • 当前主要目的是观察新州长上任后的实际政策，而不是因为算力需求下降。
  • 如果项目现阶段继续推进，但最终无法取得许可，将浪费大量时间和资源。
  • 微软内部已意识到，不能把AI算力资源过度集中于德州。
  • 后续更可能将项目分散到其他州，以降低单一地区的政策与交付风险。

c) 德州项目会被取消，还是延期、转移或采用其他供应方式？

  • 目前尚未看到已经签约的项目被直接取消。
  • 更常见的处理方式包括：
  1. 延期交付；
  2. 转移到其他项目；
  3. 调整到其他州或海外；
  4. 通过其他出租方补充算力。
  • 取消合同属于重大事项，微软仍然需要相关算力，因此更倾向于推迟或替换，而不是直接取消需求。

4. Crusoe与Nscale项目调整

a) Crusoe德州0.7吉瓦项目为什么从2027年推迟到2028年？

  • 微软与Crusoe在德州星际门项目附近规划了一个0.7吉瓦的大型AI园区。
  • 该项目原计划于2027年交付，交付时间在双方前期签约时已经确定。
  • 但Crusoe在近期向微软表示缺少继续建设所需的资金，希望微软提前提供借款。
  • 原合同模式是项目交付后，微软再按照租约支付费用。
  • 当前相当于要求微软提前出资支持建设，微软财务部门仍在评估是否提供资金。
  • 受融资问题及前期延误影响，微软已将该项目0.7吉瓦的AI推理供应从2027年推迟到2028年。
  • 该项目并未取消，核心原因是微软仍然需要这部分算力。

b) 微软为什么放弃Nscale德州项目？

  • 微软购买的并不是确定租赁合同，而是ROFO优先租用权。
  • 其含义是：
  1. 项目建成并对外出租时，微软拥有优先选择权；
  2. 微软也可以选择不租；
  3. 放弃优先权不等于取消合同。
  • 微软决定不行使该选项，主要考虑：
  1. 德州项目可能出现交付延期；
  2. 新州长上任带来政策风险；
  3. 不希望AI资源过度集中在德州；
  4. 需要将项目分散到不同州。
  • Nscale项目原本没有计入微软2027年或2028年的正式吉瓦规划，因此放弃该选项不会直接下调已披露的规划数字。

5. AI推理需求结构与客户构成

a) 2027—2028年AI推理增量主要来自哪些客户？

  • 专家负责供应端，无法直接看到完整的客户合同结构，以下比例主要是基于与需求团队沟通后的推断。
  • 预计两大头部客户OpenAI和Anthropic合计占AI推理需求的70%或以上。
  • 微软内部需求、初创企业及其他中小客户合计约占25%—30%。
  • 在两大头部客户内部，可以大致按照：
  1. OpenAI占3份；
  2. Anthropic占1份。
  • 因此，OpenAI仍是微软AI推理新增需求的绝对主力。
  • 微软近两年一直希望通过客户多元化争取Anthropic订单，目前Anthropic占比仍低于OpenAI，但已形成一定规模。

b) 微软内部需求和其他客户需求如何分配？

  • 微软内部需求与初创企业等其他客户需求的占比差距不大。
  • 微软内部算力需求长期被降低优先级：
  1. 外部第三方客户能够直接付费；
  2. 只要微软自有或租赁机房中存在可用算力，通常优先出售给外部客户；
  3. Microsoft AI内部需求有时只能通过Partner Cloud方式满足。
  • 微软内部和其他小客户合计约占25%，两者可以近似理解为各占一半。

c) 2028年规划为什么仍存在需求侧下修风险？

  • 2028年部分客户合同尚未完全签订。
  • OpenAI和Anthropic可能只签订了部分地区、部分比例的需求，并未一次性签完全年全部容量。
  • 微软与数据中心出租方签订租赁合同的节奏，会跟随客户端签约进度。
  • 微软采取较保守的匹配原则：
  1. 先确认客户端合同；
  2. 再执行供应商端租约；
  3. 避免提前锁定过多机房并自行承担需求风险。
  • 因此，2028年可能出现部分项目未最终落地，但这不代表市场需求疲软。
  • 当前需求仍然强劲，实际交付量持续低于需求量。

6. AI训练业务规划

a) 微软AI训练算力主要提供给谁？

  • 微软训练算力主要提供给OpenAI。
  • 当前只有一个Fairwater训练园区，按照OpenAI需求建设。
  • Fairwater园区的电力容量上限约为2吉瓦。

b) 为什么2027—2028年训练算力维持在2吉瓦？

  • 规划数据显示：
  1. 2025年训练算力为1.5吉瓦；
  2. 2026年为1.8吉瓦；
  3. 2027年达到2.0吉瓦；
  4. 2028年仍维持2.0吉瓦。
  • 训练算力暂时不再增长，并不代表OpenAI不再需要训练资源。
  • 核心原因是微软当前尚未看到Fairwater园区上限之外的明确训练需求和新增项目可见性。
  • 微软已批准部分内部训练相关项目，但预计要到2029年才能交付。

7. 通用云计算增长与CPU需求

a) 通用云计算具体指什么？

  • 通用云计算是指在GPU和生成式AI兴起之前，微软已经持续提供的传统云服务。
  • 该类业务主要使用CPU服务器，不属于GPU训练或GPU推理业务。
  • 2025—2028年通用云计算电力需求分别为：
  1. 7.1吉瓦；
  2. 9.6吉瓦；
  3. 12.5吉瓦；
  4. 14.5吉瓦。

b) 为什么AI推理增长也会带动通用云计算增长？

  • 一个AI推理集群无法做到100%全部由GPU服务器构成。
  • 例如部署1吉瓦的AI推理工作负载时：
  1. GPU服务器可能最多占约0.8吉瓦；
  2. 其余约20%需要计算、存储和其他辅助资源；
  3. 这些资源主要由CPU服务器承担。
  • CPU服务器用于支持GPU集群上线并接入云服务，包括存储、网络及通用计算等配套功能。
  • 因此，GPU推理业务增长会按一定比例带动CPU需求增长。
  • 此外，传统云业务本身仍有较大存量并持续扩张，预计未来CPU增长表现仍然较好。

c) CPU和GPU服务器能否通用？

  • CPU与GPU服务器不能直接通用。
  • 不同工作负载对应的数据中心供电、散热和服务器架构存在明显差异。
  • GPU代际升级后，对液冷设施的要求会进一步提高，传统风冷数据中心的兼容性将逐步下降。

8. GPU供应结构与芯片规划

a) 微软硬件部门如何根据吉瓦规划制定采购计划？

  • 数据中心部门和硬件部门采用平行组织架构，因此专家无法直接看到GPU、存储等硬件采购订单。
  • 但数据中心建设周期最长，硬件部门会将吉瓦规划作为采购预测的重要上限。
  • 例如，AI推理业务达到5.1吉瓦、年度新增约2.2吉瓦时，硬件部门会据此与NVIDIA等供应商制定未来一年的供货计划。
  • 很多硬件采购事项均以可交付吉瓦数为上限进行规划。

b) NVIDIA、AMD及自研芯片的份额如何？

  • 当前GPU供应中，NVIDIA预计占80%—85%。
  • 其余主要包括：
  1. AMD GPU；
  2. OpenAI自研芯片；
  3. 微软自研Maia芯片。
  • AMD当前硬件参数更适合相对低端的推理场景。
  • 未来1—2年，主流GPU仍将以NVIDIA为主，暂未看到AMD出现特别大规模的需求。
  • OpenAI正在Broadcom协助下设计自研芯片，微软预计于2027年协助部署并进行实际验证。

9. 风冷、液冷与下一代GPU适配

a) 训练、推理业务目前分别部署在哪类数据中心？

  • 训练工作负载主要直接部署在Fairwater液冷数据中心。
  • 当前大多数推理工作负载仍部署在风冷数据中心。
  • 在风冷数据中心部署GPU时，需要搭配sidecar设备，作为散热与运行上的过渡方案。

b) 风冷数据中心还可以支持多久的GPU部署？

  • 风冷加sidecar的方式预计最多延续到2027年。
  • Rubin仍可通过这种方式部署，虽然不是理想方案，但具备可行性。
  • 到2028年的Rubin Ultra一代，该方式将不可行，GPU服务器必须进入原生液冷数据中心。
  • 因此，2028年较大一部分数据中心增长，是为了匹配下一代GPU的液冷要求。

c) 微软自研芯片和AMD GPU对液冷有什么要求？

  • 微软Maia 300可以部署在风冷数据中心。
  • Maia 400需要部署在液冷数据中心。
  • 按微软内部估算，AMD在2028年前后推出的新一代GPU也基本需要液冷支持。
  • 到2028年，绝大多数GPU相关硬件预计都将切换至液冷数据中心。

d) 微软液冷数据中心的供应节奏如何？

  • 微软从2027年开始通过租赁方式上线液冷数据中心，2028年还会继续。
  • 微软也在自建液冷数据中心，但自建项目从许可到电力交付通常需要约3年。
  • 因此，自建液冷数据中心要到2029年才能实现大规模、吉瓦级交付。
  • 2027—2028年的液冷需求将较大程度依赖外部租赁项目。

10. 数据中心建设成本与Partner Cloud策略

a) 不同数据中心模式的单位建设成本是多少？

  • 按微软财务部门提供的规划口径，每兆瓦对应成本约为：
  1. 自建风冷数据中心：1,350万美元；
  2. 自建液冷数据中心：1,650万美元；
  3. 租赁第三方机房：1,790万美元；
  4. Partner Cloud模式：2,250万美元。
  • Partner Cloud指机房和其中的算力卡均由第三方提供，微软整体租用。
  • 从成本上看，Partner Cloud是微软利润最低、成本最高的模式。

b) 微软为什么计划减少Partner Cloud？

  • 微软内部战略是尽量减少Partner Cloud合作。
  • 2022年底至2023年，AI需求快速增长，市场上A100和其他算力资源紧缺，微软只能被动向Oracle等合作伙伴租用算力。
  • 这些算力主要转售给OpenAI，微软只能赚取较少的经手费。
  • 随着自有和长期租赁算力逐步上线，微软不再希望继续依赖高成本的Partner Cloud。
  • 近期微软不再续租Oracle部分项目，主要原因就是这些项目采用Partner Cloud模式。

c) Oracle相关合同为什么逐步到期退出？

  • Oracle早期Partner Cloud合同期限主要为4年，近两年合同期限延长至5年。
  • 最早签订的4年期合同已接近到期。
  • 合同到期后：
  1. 微软不再继续租用相关算力；
  2. Oracle也缺少对应的后续客户；
  3. 市场对A100的需求已明显下降。
  • 因此，微软减少Oracle项目属于合同自然到期后的结构调整，而非临时取消有效合同。

11. xAI/SpaceX算力与微软合作可能性

a) 微软是否有意租用xAI或SpaceX的算力？

  • 微软自身没有如此大规模的内部AI工作负载需求，也没有明确租用xAI算力的意愿。
  • 微软Copilot主要通过API调用不同公司的模型，包括：
  1. OpenAI模型；
  2. Anthropic Claude；
  3. xAI Grok。
  • 通过API调用模型即可满足部分产品需求，微软没有必要额外租用xAI算力。
  • Anthropic可能需要采购短期算力，但微软本身没有同等需求。

b) xAI数据中心建设速度和竞争力如何？

  • xAI在德州已有数据中心，但更大规模项目位于田纳西州。
  • xAI目前在当地的规模约为2吉瓦，后续还将继续增加。
  • 其数据中心建设速度快、执行方式激进，明显快于微软。
  • 微软自建数据中心从取得许可、开工到电力交付通常需要约3年。
  • 部分激进项目可以在不到20个月内完成，但会采用大量燃气轮机现场发电等方式。
  • 微软不会轻易采用类似方案，原因是环境和社区影响较大。
  • 田纳西州当地社区已对大规模使用燃气轮机发电提出抗议。

c) xAI是否会对微软构成重大威胁？

  • 目前微软并不认为xAI构成特别大的直接威胁。
  • 除非xAI真正跑通太空数据中心的完整产业链，否则短期内其竞争影响仍然有限。
  • 微软是否使用xAI算力，最终取决于是否存在真实需求和经济回报，而不是单纯因为对方有闲置资源。
