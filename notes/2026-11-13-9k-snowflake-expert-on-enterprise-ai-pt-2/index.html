1. Snowflake三季度经营情况与企业AI发展趋势

a) Snowflake三季度业绩、签单及RPO表现如何？

  • 受访者明确表示，三季度业绩完成情况、部门KPI、签单及RPO均属于企业内部信息，不在本次访谈范围内，无法披露或评价
  • 对于三季度客户消耗增速、新老客户消费占比及具体产品使用量变化，受访者同样未提供数据
  • 本次访谈可交流的范围主要是美国企业AI落地趋势、Agent应用及行业竞争格局，不能据此判断Snowflake三季度实际业绩是否达到指引

b) 北美企业AI部署是否正在加速？

  • 北美企业仍在加速探索AI，当前重点已经从简单问答、数据查询和文档总结，转向将AI Agent部署到生产环境
  • 去年大量企业仍停留在POC阶段，目前企业不再满足于AI“回答问题”，而是希望Agent能够执行下单、操作系统、分析客户及推进业务流程等实际任务
  • ServiceNow、Salesforce已披露Agent实际使用情况，被视为企业Agent进入真实应用的积极信号

c) 企业AI落地最快的场景有哪些？

  • 客服场景
  1. 当前成熟度较高、普适性较强，也是较容易验证ROI的场景
  2. AI可以承接客户问答、服务流程及部分业务操作，不再局限于传统Chatbot
  • 企业内部销售分析
  1. 过去CEO、CFO或销售团队需要依赖BI团队制作报表，并逐一查询客户使用量及经营情况
  2. 现在Agent可以连接Salesforce等系统，直接回答季度销售增长或下降原因、主要增量客户、主要流失客户等深层问题
  3. 分析结果可以进一步指导销售团队针对具体客户制定策略
  • 供应链场景
  1. 覆盖采购、流程、仓库、供给等环节，是复杂度较高但价值较明确的方向
  2. 各企业供应链体系不同，通常需要大量定制化工作
  3. 企业可以自行构建，也可以采购专注供应链的垂直AI产品
  • 垂直行业应用
  1. 如果已有成熟产品能够处理客服、供应链等特定任务，企业更倾向于直接采购，而非从零搭建
  2. 垂直Agent初创公司因此成为企业AI应用的重要供给方

2. 企业AI落地流程与数据消费增长逻辑

a) 企业部署AI前需要完成哪些基础工作？

  • 企业首先需要将数据存放在Databricks、Snowflake、AWS等平台或云基础设施中
  • 数据进入平台后不能直接交给模型，还需要完成以下步骤：
  1. ETL及数据迁移
  2. Data Cleaning数据清洗
  3. 数据治理及权限管理
  4. 从Data Lake向Data Warehouse或可用数据层转化
  5. 按Medallion架构完成Bronze、Silver、Gold分层
  • 原始数据在Bronze阶段通常不能直接供AI使用，一般需要到Gold阶段，才能形成适合模型和Agent调用的数据
  • 无论企业使用Snowflake、Databricks，还是自行建设数据平台，上述数据准备过程都无法绕开

b) AI应用为什么会带动数据平台消费？

  • 企业AI并不是简单将S3或Data Lake接入OpenAI模型，而是需要持续进行数据整理、治理、查询和调用
  • Agent进入生产环境后，需要长期连接企业数据、上下文和业务系统，因此会形成持续的数据处理和计算需求
  • 即使企业不迁移数据，而是通过MCP或其他接口进行跨平台查询，数据仍然需要存储、治理和被调用
  • AI最终进入企业应用层，必须依赖可信、可治理的企业数据，因此数据湖、数据仓库和System of Record整体上仍是AI的受益环节

c) 企业AI从POC走向生产的核心门槛是什么？

  • 企业应用通常经历“尝试—POC—生产部署”三个阶段
  • 当前行业关注重点已经从“能否做出Agent”转向“Agent能否进入生产并持续创造价值”
  • 进入生产环境后，企业会重点评估：
  1. Agent能够解决多少实际问题
  2. 是否能够参与或执行真实业务流程
  3. Token及基础设施成本是否可控
  4. 业务收益能否覆盖投入
  5. 安全、治理和权限控制是否完善
  • 构建一个Agent本身并不困难，难点在于让Agent理解企业上下文、接入复杂系统并稳定执行任务

3. Salesforce与数据平台的竞争关系

a) Salesforce开放数据接口是否会削弱Snowflake、Databricks和Palantir？

  • Salesforce是CRM领域的System of Record，企业已经积累的大量客户数据具有很强黏性
  • Salesforce一方面开发自己的Agent，另一方面通过MCP等接口向OpenAI、Anthropic及其他平台开放数据
  • 企业不一定需要将Salesforce数据迁移到其他平台，也可以在需要时通过Agent直接查询
  • 这种模式会加剧Agent入口和企业应用层的竞争，但并不意味着数据平台失去价值
  • Snowflake、Databricks、Palantir等更接近数据平台或数据处理层，其价值仍包括跨系统数据整合、治理、计算和上下文构建

b) Salesforce能否被Vibe Coding或模型公司重新构建？

  • 实际上很难通过Claude、Claude Code、Vibe Coding等方式自行重建一个完整的Salesforce
  • 原因包括：
  1. 企业已有数据和业务流程已经长期沉淀在Salesforce中
  2. CRM系统规模庞大，涉及权限、流程、数据模型及大量系统集成
  3. System of Record的迁移成本和业务风险很高
  • 同理，企业也很难依靠Vibe Coding自行构建能够全面替代Snowflake或Databricks的数据仓库
  • 因此，底层数据平台和核心记录系统更可能受益于AI，而不是被AI直接替代

c) 数据不再迁移、改为跨平台调用，会影响数据平台长期空间吗？

  • 数据不迁移会改变部分传统的数据集中方式，但不会消除企业对数据存储、治理和计算的需求
  • 企业最核心的资产仍是自身数据，模型能力再强，也必须获得准确、受控的企业数据才能产生价值
  • 数据平台未来的竞争重点将从单纯“吸引数据迁移”，扩展到：
  1. 支持跨平台数据访问
  2. 提供统一治理和权限
  3. 构建企业上下文
  4. 为Agent提供稳定运行环境
  5. 承接持续的数据计算和消费

4. Token经济性、AI产品增速与企业ROI

a) Token Maxing退潮是否影响AI产品使用量？

  • 企业早期使用AI时对Token消耗限制较少，随着账单上升，开始关注每一单位Token产生的业务价值
  • Token成本控制已成为数据公司、模型公司及AWS、Microsoft等云平台共同面对的问题
  • 企业通常会选择价格更低、性价比更高的模型，但不会因为优化成本而停止使用已经进入生产的Agent
  • 如果销售Agent等应用已经成为真实业务流程的一部分，其使用量具有客观需求，不会在构建后轻易弃用
  • 受访者目前没有观察到三季度数据服务公司AI产品用量或账单增速明显下降，但未提供定量数据支持

b) Token价格下降会不会压制数据平台收入？

  • 理论上存在“价格下降、用量上升”的对冲关系
  • 如果Token单价下降速度快于调用量增长，可能对部分按消耗计费的AI产品收入形成压力
  • 但从受访者观察来看，现有客户仍在使用，新客户也开始使用，尚未看到整体用量下降
  • 不同公司的收入影响取决于其计费结构：
  1. 是否直接按Token收费
  2. 是否同时收取计算、存储和平台费用
  3. AI产品是否已进入生产环境
  4. 客户是否扩大Agent数量及使用场景
  • 关于Databricks三季度可能因Token降价而增速放缓的市场消息，受访者无法验证

c) 为什么AI前景明确，但上市软件公司的增速未普遍大幅提升？

  • 核心卡点仍是ROI，而不是Agent供给不足
  • 去年大量企业受FOMO推动开展POC和试用，今年开始更加重视投入产出
  • SaaS公司虽然推出大量AI产品和Agent，但企业会追问：
  1. Token和开发费用投入了多少
  2. Agent实际替代了哪些工作
  3. 是否带来收入增长或成本下降
  4. 是否值得持续扩大部署
  • 企业AI整体趋势仍在加速，但“技术可用”不等于“预算立即转化为大规模收入”
  • 从POC到生产的转化速度、生产后的使用深度以及ROI验证周期，决定了软件公司收入兑现节奏

d) 企业需求是否在下半年出现降温？

  • 受访者认可市场从早期FOMO逐渐转向理性评估的总体趋势
  • 但并未观察到项目数量突然减少，或新签客户出现普遍性明显下滑
  • 如果只是单季度新签或RPO增速由较高水平小幅回落，尚不足以判断行业趋势反转
  • Palantir、Snowflake、Datadog等公司的具体变化，可能同时受到客户结构、Token价格、行业暴露及公司自身因素影响
  • 年底签约是否会加速仍难判断，还会受到宏观经济、行业政策、AI产业不确定性及企业预算周期影响

5. Palantir的定位、护城河与竞争压力

a) Palantir为什么更适合复杂跨系统场景？

  • Palantir最初并非从AI或Agent起家，而是从数据整合和Digital Twin业务发展而来
  • 其核心优势是将ERP、供应链、制造、能源和国防等复杂系统整合在一起
  • Foundry、Ontology和AIP为其提供了系统集成、业务建模和AI应用基础
  • AI出现后，Palantir可以在已有复杂系统之上增加推理和Agent能力，而不需要从零构建业务底座
  • 在制造、供应链、能源及军工等运营密集型行业中，Palantir仍具有明显优势

b) Palantir真正的护城河是数据还是行业know-how？

  • Palantir更重要的优势不是专有数据，而是长期积累的行业know-how
  • 其FDE长期嵌入客户现场，能够理解：
  1. 工厂如何实际运行
  2. 供应链各环节如何协同
  3. 不同系统之间如何连接
  4. 业务异常如何处理
  5. 企业内部决策流程如何运作
  • 这些经验无法仅通过获得数据或调用一个大模型快速复制
  • OpenAI、Anthropic和一般数据公司即使具备较强模型能力，也难以在短期内补齐Palantir多年积累的复杂行业经验

c) 哪些场景不一定需要Palantir？

  • 如果企业只需要简单Chatbot、知识问答或局部工作流，可能无需购买Palantir这样复杂的平台
  • 法律、金融、医药及部分普通商业客户的系统复杂度可能低于制造、能源和军工行业
  • 对于简单Agent，企业可以选择OpenAI、Anthropic、AWS、Snowflake、Databricks或自行搭建
  • Palantir也在向下拓展，通过Agent和FDE服务覆盖业务相对简单的企业，但其复杂平台和高强度服务未必适用于所有客户

d) Palantir新签表现承压是否与模型公司竞争有关？

  • OpenAI和Anthropic正从API和模型提供商向Enterprise市场拓展，开始与Palantir、Snowflake、Databricks及云厂商竞争企业预算
  • 企业Agent需求总量有限，当多个平台同时争夺同一批Agent项目时，竞争会明显加剧
  • 部分原本可能采用Palantir复杂系统的客户，可能转向模型公司搭建更简单的Agent
  • 但这种竞争更多影响简单或局部场景，尚不足以完全替代Palantir在复杂系统集成中的价值
  • Palantir新签客户增速变化可能受到竞争影响，但不能仅用模型公司竞争解释，还与其目标市场较窄、项目复杂及销售周期较长有关

e) Palantir与OpenAI、Anthropic如何分工共生？

  • OpenAI和Anthropic主要提供模型、API、Coding工具、知识工作工具及部分Agent定制服务
  • Palantir主要负责：
  1. 企业复杂系统集成
  2. Ontology及业务上下文构建
  3. 跨系统数据连接
  4. 生产环境中的复杂流程编排
  5. 行业know-how落地
  • 当Palantir系统需要模型推理能力时，可以调用Claude、OpenAI或其他模型
  • Palantir具有模型可插拔特征，更换底层模型通常不会改变其系统集成价值
  • 最复杂的企业场景中，模型公司与Palantir更可能形成分工合作，而不是由一方完全取代另一方

6. FDE模式的价值与商业化逻辑

a) Palantir与其他公司的FDE有何区别？

  • 各家公司FDE均围绕自身平台开展：
  1. Databricks FDE基于Databricks平台
  2. Snowflake FDE基于Snowflake平台
  3. AWS FDE基于AWS基础设施
  4. OpenAI、Anthropic FDE基于各自模型和Agent能力
  • Palantir FDE的差异在于，更深度嵌入复杂企业场景，长期积累制造、能源、供应链及军工等行业经验
  • 其他平台的FDE更多聚焦于客户定制、平台连接、Agent搭建及自身平台调用
  • 每个Agent需要连接的系统、Harness、Runtime及业务流程不同，因此即使平台提供标准化产品，仍需要FDE完成定制化落地

b) 为什么模型交付给客户后，仍然需要FDE？

  • 企业仅获得模型API，并不等于可以直接构建生产级Agent
  • FDE需要解决：
  1. 连接哪些企业系统
  2. 如何获得上下文和权限
  3. 如何设计Harness和Runtime
  4. 如何进行评估与监控
  5. 如何处理异常和业务规则
  6. 如何将Agent嵌入实际工作流
  • 企业场景差异很大，标准产品只能满足部分需求，生产级部署仍需要大量工程和业务定制

c) FDE通常是否收费？

  • 各家公司和项目模式不同，既有收费项目，也有免费项目
  • AWS等大型公司可能免费搭建或免费提供POC，在客户进入生产环境后再通过平台使用量收费
  • 资金实力较弱的小公司可能在早期象征性收费，以覆盖服务成本
  • Snowflake的FDE也同时存在收费和免费模式，取决于：
  1. 项目规模
  2. 客户战略价值
  3. 预期业务量
  4. 后续平台收入潜力
  • FDE的核心目的不是依靠服务本身盈利，而是推动客户长期在平台上运行Agent并形成持续消费

7. 企业AI预算的主要流向

a) 企业目前最愿意在哪些领域投入？

  • 推理与Token
  1. 推理是企业AI预算的首要投入方向
  2. Agent持续运行必然产生模型调用和Token成本
  • Agent Infrastructure
  1. 包括Runtime、MCP、Harness、Evaluation和Observability
  2. 企业需要决定自行构建、采购SaaS，还是使用云厂商及平台现成服务
  • 数据与企业上下文
  1. Agent要理解企业数据、流程和业务语义
  2. Palantir Ontology等产品体现了企业上下文的重要性
  3. 数据治理、知识组织和业务流程建模是Agent落地的关键投入
  • 安全与治理
  1. 企业需要明确Agent可以调用哪些资源、拥有哪些权限
  2. Agent数量越多，网络安全、身份权限和治理需求越高
  3. CrowdStrike、Palo Alto等安全厂商的重要性将进一步提升
  • 垂直领域Agent
  1. 客服、供应链等场景若存在成熟产品，企业更愿意直接采购
  2. 垂直产品可以减少企业自行开发和维护的成本

b) Agent基础设施领域有哪些代表性产品和公司？

  • Observability和Logging方面包括Elastic、Datadog等
  • Snowflake收购的Observe也属于Observability方向
  • Harness及Coding Agent相关公司包括Firework、Cognition、Conductor等
  • 企业实际使用较多的其他产品还包括：
  1. Glean：企业搜索及知识服务
  2. Sigma：Dashboard和数据分析
  3. Cursor：AI Coding
  4. Perplexity：通用AI搜索与知识获取
  • 受访者认为，当前增长较快、企业更愿意尝试的产品中，AI Native公司占比较高

c) 为什么AI Native公司更容易获得预算？

  • AI Native产品通常直接围绕Agent、推理、开发、上下文和评估设计，产品形态更贴近当前需求
  • 传统SaaS推出AI功能后，仍需要证明其产品不能被企业自行开发或由Agent替代
  • 企业增量预算更可能流向：
  1. 无法替代的底层平台
  2. 数据和System of Record
  3. AI基础设施
  4. 网络安全
  5. ROI明确的垂直Agent
  • 虽然AI Native公司数量较多，但单家公司收入规模仍相对有限，因此整个企业AI预算尚未完全体现为上市软件公司的高增长

8. 传统SaaS、云厂商与AI时代的价值迁移

a) 哪类软件最容易被削减预算？

  • 主要是缺乏底层数据、客户黏性较弱的纯应用类软件
  • 如果应用功能可以通过外包Code、Vibe Coding或企业自行开发实现，其替代风险较高
  • 传统Seat Based模式也可能受到Agent冲击：
  1. 过去企业需要为每位员工购买软件席位
  2. Agent出现后，部分工作可能由少量Agent统一完成
  3. 企业未必继续为所有员工配置相同数量的Seat
  • 判断软件公司是否具备防御力，关键是看其是否拥有不可替代的数据、平台、工作流及System of Record地位

b) 是否大多数传统SaaS公司都无法获得本轮AI增量预算？

  • 受访者基本认可，大量传统SaaS公司与本轮AI预算增长的直接关系有限
  • 企业不会仅因为软件公司增加AI功能，就必然增加预算
  • 传统SaaS需要证明：
  1. AI功能能够带来明确ROI
  2. 平台具有不可替代性
  3. 产品无法由企业自行编码完成
  4. Agent可以形成持续调用和收入
  • 能够保留数据、业务流程和客户记录的平台，相对更具防御力

c) SaaS公司支付给云厂商的费用会如何变化？

  • 具体增长区间无法量化，但整体趋势是云账单持续上升
  • SaaS公司原有基础设施仍需运行，同时还要增加：
  1. Bedrock等模型平台调用
  2. GPU和推理资源
  3. Agent Runtime
  4. 数据处理和存储
  5. Agent基础设施及监控
  • 因此，AI投入通常不是替代原有云成本，而是在原有成本之上增加新的模型和Agent支出
  • AWS、Azure等云厂商将直接受益，其中较大部分增量来自GPU及AI基础设施收入

9. 客户结构、行业差异与签约趋势

a) 哪类客户最容易签约数据和AI平台？

  • AI Native和Digital Native公司最容易接受相关平台
  • 这类企业天然依赖数据和AI，通常优先选择云厂商及Cloud Native方案
  • 高科技、媒体、电信等行业对AI和云的接受速度通常快于传统行业
  • 传统企业若仍运行自有数据中心，需要同时考虑云迁移、数字化和AI改造，推进速度相对较慢

b) 传统行业的AI投入受哪些因素影响？

  • 能源行业会受到油价、地缘政治和资本开支周期影响
  • 制造业会受到宏观经济、订单及美国整体经济环境影响
  • 当行业盈利较好时，企业更愿意全面投入AI；行业景气度下降时，相关预算可能放缓
  • 因此，企业AI长期趋势向上，但不同行业和客户的签约节奏不会完全同步

c) 四季度及明年签约是否会明显加速？

  • 受访者无法给出数量判断，也无法确认今年四季度是否会比去年同期更快
  • 年底通常是企业作出采购决策的重要阶段，但仍会受宏观环境、AI行业不确定性、预算周期及产业事件影响
  • 当前没有观察到新签客户突然减少，但也不足以确认签约正在全面加速
  • 具体趋势仍需等待各家公司财报、RPO及新签合同数据验证

提问者：2C电商暂不讨论，我们只讨论企业生产和Enterprise场景。您提到的客服场景，我理解AI客服目前比较成熟，也比较容易跑通。第2个场景是企业内部销售团队，我理解其关联的软件主要包括Salesforce、ServiceNow和数据服务层，因为需要分析大量报表，主要涉及这些产品，对吗？

提问者：这个问题很有意思。如果一家企业需要使用相关服务，我们看到Salesforce正在将底层的数据收集端嵌入各种类型的Agent端口，例如OpenAI和Anthropic。它基本嵌入了所有调用场景，使企业无论使用哪个端口，可能都无法绕过Salesforce，这会提升其调用量和活跃率。但这种分析能力是否也会对Snowflake、Palantir、Databricks等公司的类似Agent分析产品产生竞争影响？

同时，Salesforce 也有自己的 Agent。这些 SaaS 公司一方面在开发自己的 Agent，另一方面也需要通过大模型或其他平台的接口开放数据。如果不向其他平台开放，只允许用户使用自己的 Agent，那么用户使用 OpenAI、Anthropic 或其他平台时，就无法接入相应数据。

因此，Salesforce 在开发自身 Agent 的同时，也将其 System of Record 通过 MCP 或其他方式向顶级 AI 或模型提供接口，使其能够查询平台上的数据。

提问者：明白。对于数据湖这一层，我们原本希望调用其他平台的数据，让用户将数据存放在这里。现在用户不再迁移数据，而是将数据保留在自己的云上，并允许其他平台通过 Agent 调用。这是否会影响我们长期的增长空间？

回　答　者：无论是 AI 还是 Agent，数据都至关重要。即使 Anthropic 拥有很好的模型，对于企业而言，最核心的仍然是自身的数据。

提问者：今天接着请教一下Salesforce。它目前采取了较为积极的模式，将底层数据嵌入所有公开的头部实验室的Agent中，使企业无须迁移数据。您认为这会对数据层或哪些公司产生竞争影响？

因此，Salesforce作为System of Record，具有很强的不可替代性。即使使用Vibe Coding、Claude或Databricks，也很难重新构建一个Salesforce。企业数据具有很强的黏性。Snowflake也是如此，一家公司很难不使用Databricks或Snowflake，而是通过Vibe Coding自行构建一个数据仓库。

从目前来看，数据湖和数据仓库很难被AI、Vibe Coding或Claude Code替代。对这些公司而言，从4月份至今，其股票反而一直上涨，因为它们是最受益的公司。AI最终要进入应用层并在企业中落地，仅有模型是不够的，还必须具备数据。

提问者：也就是说，这实际上不会明显影响存储领域，因为企业始终需要一个能够跨平台存储数据的地方，对吗？

回　答　者：对，而且这些公司应该是受益的。

提问者：大家都开始发展自己的AI产品，增长情况不错，应该是26年以来增长的主要贡献。我看到1季度和2季度的增速都明显加快，Databricks也是如此。但其中AI产品的很多贡献，是否都来自过去2个季度的存量客户？这些客户原本就是数据公司的大客户，在AI实践上也比较领先，因此使用了相关AI产品。但到5月、6月以后，北美出现Token Maxing退潮，这是否会影响AI产品的消耗？此外，Token价格下降是否会对AI产品的收入增长产生影响？您认为这些因素会对3季度形成压制吗？

回　答　者：这个趋势确实存在。最开始大家使用AI时没有限制用量，后来逐渐发现Token是有成本的。现在不只是数据公司，也包括AI公司以及Amazon、Microsoft等云平台。企业开始使用后，会关注消耗大量Token究竟产生了什么价值。如果这些价值能够反映在业务上，就可以接受；如果只是大量消耗Token，就需要判断究竟产生了什么价值。

提问者：我理解所有人都在关注ROI。具体来看，Token Maxing原本体现在模型API的账单上，而在数据层面，各家公司都有按消耗收费的AI产品，是否也存在同样的趋势？也就是说，到7月、8月以后，增速是否会下降？

回　答　者：目前来看还没有。使用量是客观存在的。例如，我为客户构建了一个销售Agent，就需要实际使用，不会构建后弃用。只要使用，就会消耗Token。区别在于使用Claude还是OpenAI的模型，通常会选择价格更低的模型，但实际用量仍然存在。

提问者：我不是在问企业使用Anthropic模型和OpenAI模型的账单，而是企业使用数据服务公司的Agent产品，例如Text to Code，以及Databricks的相关产品。进入3季度后，这些产品的账单增速相比2季度是否有所放缓？存量客户第1波较为激进的使用有所放缓，新签客户可能尚未起量，同时Token价格也在下降。综合这些因素，您认为是否存在这种现象？

回　答　者：目前来看没有。

提问者：您认为3季度相比2季度，数据行业的增速会发生怎样的变化？

回　答　者：从整体趋势来看，我们没有看到具体数据，也没有看到用量下降。现有客户仍在使用，新客户也开始使用。随着大家逐渐认识到这一趋势，Token使用量只会越来越多。

提问者：所有AI Infra软件公司的CEO都会表示，企业AI正在加速发展，并将拉动公司收入。从数据层面看，企业部署AI之前需要完成哪些环节，才会明显拉动数据消费？结合您的项目经验，企业通常需要先完成哪些工作，之后数据消费才会出现明显增长？

回　答　者：企业要应用AI，首先需要将数据存放在某个平台，例如Databricks、Snowflake或AWS。第2步是准备数据，确保数据真正可供AI使用。并不是将数据放入S3或Data Lake，再接入OpenAI的模型就可以直接使用，还需要对数据进行整理和治理，也就是数据治理。
