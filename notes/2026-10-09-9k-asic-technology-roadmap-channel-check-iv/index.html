1. SRAM、PIM与CIM技术路线判断

a) SRAM是否是Decode环节最具确定性的技术路线？PIM、CIM有哪些局限？

  • SRAM在Decode阶段具备显著速度优势
  1. Decode通常以逐Token输出为主，性能瓶颈更多来自数据访问和I/O，而非单纯计算能力。
  2. SRAM访问速度较HBM具有数量级优势，因此在模型和KV Cache能够被片上SRAM容纳时，Decode延迟优势非常明显。
  3. 但SRAM的优势成立存在严格前提，即核心模型、KV Cache或待加速部分能够尽量留在单芯片内。
  • PIM、CIM难以满足云端大规模负载
  1. PIM、CIM已发展多年，国内外均有创业公司持续推进。
  2. 两类方案的主要限制是算力规模和配套SRAM容量难以扩大。
  3. 当前AI Workload仍主要集中于云端数据中心，PIM、CIM较难满足大模型的容量和系统扩展需求。
  4. PIM、CIM可能在边缘端、小算力场景中体现计算和功耗优势，但该类市场并非当前AI算力的主要市场。

b) Cerebras的晶圆级SRAM方案能否解决Decode问题？

  • 单芯片场景下具有明确优势
  1. Cerebras通过晶圆级芯片，在现有工艺下尽可能堆叠算力与SRAM。
  2. 如果中小模型能够完整部署在单芯片内，其SRAM访问速度和Decode延迟会明显优于GPU多卡方案。
  3. 在该前提下，NVIDIA、AMD或TPU通过增加卡数也较难追上Cerebras单片速度，因为多卡方案会引入集合通信和跨卡传输开销。
  • 长上下文和大模型场景下受容量限制
  1. Cerebras单芯片最大约有44GB SRAM，而当前Agentic Workload的上下文通常达到数万甚至十万Token以上，KV Cache容量会快速增长。
  2. 单芯片难以同时容纳大模型及其全部KV Cache，必须使用多芯片或外部存储系统。
  3. 即使扩展至大量芯片，数据跨芯片传输后，系统性能仍会受到RDMA网络带宽限制，SRAM的片内速度优势会被削弱。
  4. 当KV Cache无法完全放入SRAM时，仍需要使用传统CPU加DDR系统承载，并在计算时将数据复制至SRAM，由此产生出芯片、进芯片的I/O开销。
  • 系统级瓶颈与GPGPU方案趋同
  1. 完整推理系统不仅需要计算芯片，还涉及CPU调度、KV Cache存储和模型权重存储。
  2. Cerebras的KV Cache及权重存储子系统仍主要依赖x86 CPU、DDR和Flash，与GPU系统采用的大规模缓存池并无本质区别。
  3. Scale-out之后，系统整体性能取决于最弱带宽环节，因此Cerebras与大型GPGPU Rack最终面临相似的I/O和互联瓶颈。
  4. Cerebras在短上下文、中小模型场景中更容易发挥优势，但在长上下文、大模型场景中的通用性有限。

c) Groq是否面临与Cerebras相同的容量问题？

  • Groq面临的SRAM容量限制更明显：
  1. Groq单芯片可用SRAM容量更小，单芯片能够承载的模型规模也更小。
  2. 运行大模型时需要更多芯片组成阵列，跨芯片或跨Rack互联将削弱SRAM的速度优势。
  3. 与Groq相比，Cerebras通过晶圆级方案实现了更大的单芯片规模，部署中小模型所需芯片数量更少，延迟表现理论上更好。
  4. Groq的跨芯片系统方案成熟度可能也弱于Cerebras。

2. PD分离、AF分离与异构解耦架构

a) 当前AI推理异构解耦的主流方式是什么？

  • PD分离是当前主流方向
  1. Prefill和Decode具有不同的计算属性，分离后可分别选择更适合的芯片与系统配置。
  2. Prefill阶段可以继续由GPU承担，Decode阶段则可引入低延迟ASIC、LPU或SRAM型芯片。
  3. PD分离的目标是通过针对性扩展提升吞吐，同时降低Decode延迟。
  • 增加芯片数量可以提升性能，但不会带来质变
  1. GPU扩容能够提高吞吐，并在部分情况下改善延迟。
  2. 但芯片数量增加后，All Reduce等多芯片集合通信会产生额外开销。
  3. 实际提升幅度需要根据模型、互联、并行策略和负载逐案分析，难以简单实现线性扩展。

b) Decode环节是否还可以进一步拆分？

  • 可进一步进行Attention与FFN分离，即AF分离
  1. 不必将整个MoE或Decoder全部放入Groq等系统，可以只拆分Decode中的Attention或FFN部分。
  2. 将待加速部分缩小后，可以更充分利用有限的片上SRAM。
  3. NVIDIA被认为正在探索类似方案，在物理PD分离基础上再进行局部分离。
  4. 与纯GPU系统相比，这类异构组合有望在高延迟敏感场景中取得优势。
  • Cerebras同样可以参与AF分离
  1. Cerebras可以负责加载KV Cache和执行Attention，将Experts或FFN部分部署在其他硬件上。
  2. Cerebras不一定独立承担完整模型，而可能与AMD、NVIDIA等芯片组成异构系统。
  3. 具体由哪类芯片加速模型的哪一部分，应由模型部署方根据Workload特点统一设计，Cerebras主要负责配合系统实施。

c) 异构解耦未来是否会继续无限细分？

  • 理论上可以继续拆分，但实际价值有限
  1. 当前完整系统已经包括KV Cache子系统、模型权重存储子系统和Cerebras CS-3计算子系统。
  2. KV Cache和权重存储通常由x86、DDR和Flash系统承担，CS-3负责计算并配合x86机头完成调度。
  3. 子系统之间还需要FPGA接口板完成PCIe延伸、总线转换、跨机器连接与数据传输。
  4. 当前架构已经涉及多级计算、调度、存储、互联与接口转换，系统复杂度较高。
  5. 计算环节理论上仍可继续拆分，但拆分越细，I/O、调度、软件适配和工程复杂度越高，是否值得需谨慎评估。
  6. 系统不能无限拆分，未来更可能围绕PD分离和AF分离进行优化，而不是持续增加大量独立子系统。

3. AMD收购Talas的动机与整合前景

a) AMD为什么收购Talas？

  • 市场与资本层面的补位需求
  1. NVIDIA已形成面向低延迟Decode的探索方案，Cerebras等公司也在推进特定环节加速。
  2. 单纯依靠GPU架构，可能无法充分解决Decode和低延迟问题，AMD在这一领域的短板比NVIDIA更加明显。
  3. NVIDIA此前还提出过以消费级GPU承担Decode、数据中心GPU承担其他阶段的CPX异构方案。
  4. AMD虽然拥有Radeon消费级GPU，但在高端算力和带宽方面与NVIDIA高端消费级GPU仍存在差距，难以直接复制类似路线。
  5. 收购Talas可以帮助AMD快速向市场表明其正在补齐低延迟推理能力。
  • 技术上具备潜在可行性
  1. Talas已在小模型、单芯片场景下证明了较好的加速能力。
  2. 其方案有望用于Decode、FFN或其他局部环节的专用加速。
  3. Talas与AMD具有一定人员渊源，其方案成熟度可能高于AMD从头基于FPGA开发。
  4. AMD此前收购的赛灵思也拥有FPGA能力，理论上可利用片上SRAM和高度定制的计算流实现类似加速，但研发和产品化周期可能更长。

b) 收购完成后，AMD产品是否已经获得效率提升？

  • 目前尚未形成实质性产品成果
  1. Talas此前主要验证了小模型能够完整放入单芯片时的加速效果。
  2. 在大型模型中，芯片需要与AMD MI Instinct等GPU系统交互，必须补充高速互联、接口及相关硬件设计。
  3. 如果GPU负责Prefill、Talas芯片负责Decode或FFN，就需要形成完整的异构互联和调度方案。
  4. 当前vLLM、SGLang虽已支持PD分离，但尚需针对该芯片进行软件适配。
  5. 软件层还需解决芯片接入、调度、PD分离、FFN加速和运行时管理等问题。
  6. 从单芯片技术到大型系统集成仍有较长路径，因此现阶段无法判断实际效率提升。
  • 短期价值可能来自设计思想吸收
  1. AMD可以较快吸收Talas的底层设计方式和架构理念。
  2. 相关技术未必最终以独立子系统形式落地，也可能被融入未来Instinct系列GPU或加速器设计。
  3. 该路径可能推动AMD后续架构演进，但目前仍属于推测。

c) 为什么AMD可能与Cerebras合作，而不是完全依靠自研？

  • AMD当前缺乏成熟的低延迟Decode专用方案，与第三方合作可以：
  1. 补足自身系统在部分Workload上的延迟短板。
  2. 更深入了解第三方方案的能力边界，为自身产品改进提供参考。
  3. 通过GPU与专用芯片组合，形成可与NVIDIA竞争的异构系统。
  4. 在系统集成尚未完全成熟前，以合作方式降低探索成本和时间成本。

4. AMD与Cerebras合作及系统主导权

a) AMD与Cerebras合作中，为什么可能由Cerebras主导？

  • 开放性和IP边界可能是重要原因
  1. AMD Helios方案较为开放，具备较强的可定制能力，其他厂商可以基于其公开接口开展系统工作。
  2. Cerebras的软件栈并未完全开源，若由AMD主导，可能涉及Cerebras核心软件和IP开放问题。
  3. 由Cerebras推进，可以更多利用AMD开放的硬件与系统能力，同时减少Cerebras自身IP暴露。
  4. Cerebras此前已经积累了x86存储子系统、计算子系统和接口连接方面的系统经验，由其推进技术整合具有一定合理性。

b) AMD Helios与Cerebras如何形成协同？

  • 可能的系统分工包括：
  1. AMD GPU负责Prefill或通用计算。
  2. Cerebras负责Decode、Attention或其他低延迟敏感环节。
  3. x86、DDR和Flash系统负责KV Cache及模型权重存储。
  4. 双方共同解决异构芯片互联、数据传输、软件调度和模型切分问题。
  • 合作的最终评价标准不是谁主导，而是混合系统能否在性能、延迟和TCO上优于纯GPU方案。

5. 异构系统互联瓶颈与光互联前景

a) GPU与Decode ASIC之间将如何互联？

  • 现阶段主要依赖RDMA等通用互联
  1. 异构系统间通常通过RDMA、以太网及相关通用接口传输数据。
  2. 主流互联方案可能来自博通、Marvell等厂商，AMD Helios也将使用Pensando相关能力。
  3. 系统中大量I/O调用都需经过通用接口或总线标准。
  4. RDMA网卡及相关网络设备能够提供的带宽，可能成为整个异构系统的最低带宽环节。

b) 互联为何会削弱SRAM方案的优势？

  • SRAM优势主要存在于片内访问：
  1. 模型或KV Cache一旦跨芯片、跨Rack传输，就需要经过网络互联。
  2. 整体性能由最慢环节决定，片内SRAM再快，也无法消除外部RDMA带宽和延迟限制。
  3. 大量芯片组成阵列后，其互联方式会逐渐接近GPU集群，SRAM方案的差异化优势随之下降。
  4. 除性能问题外，多芯片SRAM系统还可能存在成本劣势。

c) 光互联能否改善当前带宽问题？

  • 光互联具有较大潜力
  1. 光互联能够突破传统电互联的距离、带宽和功耗限制，传输速度有望实现成倍提升。
  2. 未来可通过光纤将GPU与远端HBM或大规模内存池连接，扩大可访问的高带宽存储容量。
  3. GPU和存储系统可以分别解决散热、供电和封装问题，不必全部堆叠在同一封装内。
  4. 该路线比持续增加片上SRAM容量更容易通过Scale实现上量。

d) 光互联是否会削弱Cerebras等SRAM路线的竞争力？

  • 二者解决的核心问题相近，均指向Decode阶段的I/O瓶颈
  1. SRAM通过缩短计算与存储距离降低I/O延迟。
  2. 光互联则通过扩大高速内存池和提高远端传输速度改善I/O。
  3. 一旦光互联能够支撑大容量HBM池，容量扩展难度将远低于扩大片上SRAM。
  4. 光互联更适合长上下文Agent Workload，因为能够支持更大的KV Cache。
  5. SRAM即使通过3D堆叠增加DRAM，仍受封装、散热、功耗和容量约束。
  6. 因此，长期看光互联路线可能更加稳妥，也可能削弱纯SRAM方案的相对优势。

e) Cerebras将DRAM混合键合至SRAM片上的方案是否可行？

  • 该方案类似3D堆叠，具备一定可行性：
  1. SRAM受工艺和面积限制，容量增长幅度有限。
  2. 通过混合键合增加DRAM，可以在容量和成本之间寻求平衡。
  3. 但该方案仍受封装密度、散热、功耗和总体容量上限约束。
  4. 它能够缓解容量问题，但难以从根本上解决长上下文、大规模KV Cache需求。

6. Cerebras、Groq与专用推理芯片的市场定位

a) Cerebras、Groq等厂商未来性能是否会出现飞跃？

  • 受访者不了解各家公司具体Roadmap，但判断：
  1. 下一代产品仍受到制程、带宽和芯片物理极限约束。
  2. 制程决定可集成算力、SRAM规模、功耗和互联能力。
  3. 在现有技术路径下，出现爆炸性、跨越式提升的概率不高。
  4. 更现实的提升来自工艺演进、系统优化和异构集成，而不是单一芯片能力突然跃迁。

b) NVIDIA与Groq合作意味着什么？

  • Groq芯片更可能成为NVIDIA系统的一部分
  1. NVIDIA大概率不会将Groq的LPU/RPU作为独立产品路线单独发展。
  2. 更可能将其用于PD分离、Attention或FFN等特定环节。
  3. 该策略能够发挥Groq在低延迟推理中的局部优势，但也会限制其独立架构演进空间。
  4. Cerebras作为独立公司，在产品路线和系统选择上相对不受类似约束。
  • 最终市场份额仍取决于TCO与系统效果
  1. NVIDIA尚未公开完整混合系统参数，说明方案可能仍在调试和验证。
  2. 如果性能优势足够明显，NVIDIA通常会进行更积极披露。
  3. 混合方案可能优先部署在对延迟要求极高的场景。
  4. 对于一般性、通用性负载，不一定需要异构方案，因为LPU未必具备绝对TCO优势。

c) Cerebras更适合怎样的市场定位？

  • 聚焦中小模型可能是更可行的路线
  1. 如果持续挑战超大模型，SRAM容量和系统互联将构成长期制约。
  2. 若聚焦可在单芯片或较小系统内部署的中小模型，则可以充分发挥低延迟优势。
  3. 随着训练、蒸馏和量化技术进步，中小模型在特定任务中的能力持续提升。
  4. 数据中心并非所有任务都需要最大模型，大任务可由大规模GPU系统承担，小任务可由中小模型专用系统承担。
  5. Cerebras若回归自身擅长的中小模型市场，仍可能形成差异化空间。

d) Cerebras与OpenAI相比，哪一方长期进步可能更快？

  • 受访者更看好OpenAI
  1. OpenAI对实际Workload、训练和推理部署的理解更深入。
  2. OpenAI已积累大量纯GPU系统工程经验，更清楚现有架构的瓶颈。
  3. 自研芯片时可以针对模型、算子、KV Cache和部署方式进行定制。
  4. OpenAI同时掌握模型、软件栈、数据和系统部署经验，能够开展端到端协同优化。
  5. Cerebras在硬件层面受到SRAM容量限制，在大型系统和软件部署经验方面也相对不足。
  6. 除非Cerebras转向中小模型等差异化市场，否则其长期前景仍存在较大不确定性。

7. 自研ASIC、通用GPU与外部专用芯片的路线选择

a) 未来推理芯片将以哪条路线为主？

  • 不同类型厂商将形成分层选择
  1. 具备大规模用量、资金、芯片设计和系统集成能力的头部厂商，更可能发展自研ASIC。
  2. 自研ASIC可以根据自身Workload定制计算、SRAM、HBM和互联架构，理论上比GPU外挂异构芯片更高效。
  3. OpenAI等厂商可能先推出能够同时完成Prefill和Decode的定制芯片，后续也可能将P、D分别衍生为独立子系统。
  4. 中小型厂商缺少芯片设计和系统集成能力，大概率仍将采购NVIDIA或AMD的通用GPU，并在软件层进行优化。
  • 自研芯片不仅是芯片设计问题
  1. 还需具备服务器、网络、存储、调度、编译器和软件栈的系统集成能力。
  2. 如果没有足够大的内部用量，自研芯片难以摊薄研发和流片成本。
  3. 因此，真正能够自研并规模部署推理ASIC的企业数量有限。

b) 专用ASIC增加SRAM或HBM是否更合理？

  • 对具备自研能力的大厂而言，这一方向较合理：
  1. ASIC可以围绕目标模型和Workload精确配置片上SRAM、HBM和计算单元。
  2. 相较通用GPU外挂第三方芯片，自研ASIC可减少接口转换和跨系统数据搬运。

回　答　者：多个大 Wafer 的芯片扩展以后，仍会受到总线互联带宽的限制。其片内 SRAM 的访问速度确实非常快，可能比 HBM 高数个数量级。但是，在进行 Scale-out 时，整个系统的瓶颈取决于带宽最弱的环节。互联仍采用现有的 RDMA 连接，因此会受制于 RDMA 现有的性能参数。从系统层面来看，虽然实现了扩展，但整体性能仍会受到互联带宽的拖累。
