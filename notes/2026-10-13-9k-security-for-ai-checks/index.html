AI安全行业专家访谈纪要

1. AI智能体带来的安全需求变化

a）从生成式AI转向生产环境中的AI智能体后，新增了哪些安全需求？

  • 传统生成式AI的安全重点主要包括：
  1. 数据泄露防护；
  2. 提示词注入防护；
  3. 生成内容过滤。
  • 当AI进入智能体阶段后，安全防护重点由“保护提示词和响应内容”扩展至“保障自主操作全过程安全”，新增需求主要包括：
  1. 机器身份与智能体身份管理；
  2. API访问安全；
  3. 凭证保护；
  4. 工具调用安全；
  5. 智能体执行过程保护；
  6. 智能体之间的通信安全；
  7. 授权管理与最小权限控制；
  8. 持续监控及可审计性。
  • 相比基础聊天机器人交互，复杂程度适中的智能体工作流可能使安全决策点增加约5至10倍。
  • 上述5至10倍为基于系统架构作出的估算，并非全市场范围的实测数据。
  • 新增支出将主要集中在运行时保护、智能体身份管理、授权和持续监控。企业只有具备这些安全能力后，才会允许智能体在生产环境中独立运行。

b）哪些AI安全能力最容易获得预算？

  • 更容易获得预算的功能包括：
  1. 敏感数据保护；
  2. 智能体身份管理；
  3. 访问控制与最小权限管理；
  4. 提示词注入防护；
  5. 运行时监控；
  6. 行为审计与可追溯性。
  • 最强劲的增量支出机会预计来自自主智能体保护，尤其是能够访问敏感系统、客户数据或自主执行操作的智能体。
  • 相比单纯的聊天机器人内容过滤，涉及交易、流程执行和系统权限的智能体更容易获得新增安全预算。

2. AI安全预算来源与支出增长

a）目前AI安全预算主要由安全部门还是业务部门承担？

  • 当前大部分AI安全支出仍来自CISO管理的安全预算，尤其是以下领域：
  1. 数据保护；
  2. 威胁防护；
  3. 合规；
  4. 运行时安全。
  • CIO、CTO以及实际部署AI应用的业务部门正在越来越多地参与共同出资。
  • 通常情况下，业务部门负责提出和建设AI用例，安全部门负责制定审批条件并决定是否允许上线。
  • 在银行、抵押贷款等金融服务场景中，如果AI智能体需要访问客户财务记录或执行交易，必须获得安全部门审批后才能投入生产。
  • 最终CISO通常拥有否决权。当安全成为AI应用上线前的最后一道障碍时，解决方案既可能由CISO预算支付，也可能由业务部门负责人出资。

b）AI安全支出更可能来自新增预算，还是现有预算重新分配？

  • 目前新增预算、预算重分配和供应商替换3种情况均存在。
  • 短期内，绝大部分AI安全支出仍来自现有网络安全和IT预算。
  • 企业初期通常会从传统应用安全、DLP和云安全等预算中重新分配资金。
  • 随着AI智能体进入生产环境、访问敏感数据并执行交易，新增安全要求将为追加预算提供依据，因此新增预算正逐渐增多。

c）为什么AI安全需求增长快于实际支出增长？

  • AI工作负载可能增长至原来的5倍，但企业不会按照相同比例增加安全预算。
  • 企业会通过以下方式控制净新增支出：
  1. 利用既有许可证；
  2. 协商批量折扣；
  3. 整合安全供应商；
  4. 将AI安全能力纳入现有云平台合同；
  5. 复用原有应用安全、DLP和云安全能力。
  • 因此，AI安全产品的采用率和使用范围增长较快，但安全净新增支出增长相对温和。
  • 新增预算最明确的机会集中在自主智能体保护、身份管理和云环境中的授权管理。

3. 云原生安全与第三方独立厂商的竞争格局

a）客户如何在云原生安全与独立安全厂商之间选择？

  • 当企业高度标准化地使用单一云平台时，云原生安全方案更具优势。
  • 例如，以Microsoft为核心并使用Azure OpenAI、Entra、Defender和Purview的企业，选择原生安全方案可获得：
  1. 更紧密的身份集成；
  2. 更便捷的部署；
  3. 集中式策略管理；
  4. 更低的增量采购成本。
  • 对于单一云环境中的基础提示词过滤和数据保护，原生安全能力通常已经足够。

b）哪些场景下第三方独立厂商更具优势？

  • 在同时使用Azure、AWS、Google Cloud、Anthropic和内部托管模型的多云、异构环境中，第三方厂商更具吸引力。
  • Palo Alto Networks等第三方平台能够在不同云、模型和应用环境中提供统一的安全策略和可见性。
  • 第三方厂商的差异化优势主要包括：
  1. 高级AI红队测试；
  2. 智能体运行时保护；
  3. 跨平台资产发现；
  4. 专门化威胁检测；
  5. 多云环境中的一致策略；
  6. 跨云权限与执行控制。
  • 核心区别在于：原生厂商具备集成和成本优势，独立厂商具备跨平台覆盖广度、一致性和专业检测能力优势。
  • 对于在多个环境中处理敏感数据和复杂权限的自主智能体，独立安全平台更容易证明其额外支出的合理性。

c）云平台与第三方厂商合作时，客户如何签约和采购？

  • 市场上主要存在2种商业模式：
  1. 客户直接与第三方安全厂商签约，由双方协商价格、容量和企业折扣；
  2. 客户通过Azure Marketplace或AWS Marketplace采购，由云服务商负责计费，第三方厂商仍可提供专属报价。
  • 云市场模式能够将交易计入客户现有的云支出承诺，从而简化采购流程、提高交易速度，并帮助第三方厂商触达大型企业客户。
  • 该模式也会对第三方厂商形成一定压力：
  1. 云服务商掌控市场和客户关系；
  2. 云服务商会收取交易费用；
  3. 云服务商也会通过自有原生安全产品参与竞争。
  • 云市场可以提高分销效率，但不一定提高第三方厂商的利润率或议价能力。
  • 只有能够提供原生云工具难以复制的差异化防护能力，第三方厂商才能保持较强定价权。

4. 新云厂商、AI安全初创公司与行业整合

a）除头部云厂商外，哪些新云厂商正在提供安全能力？

  • Microsoft、AWS和Google均已提供不同类型的AI安全产品。
  • Microsoft相关能力覆盖：
  1. Defender for Cloud；
  2. AI威胁检测；
  3. Purview数据保护和敏感信息管理；
  4. Entra身份与访问管理；
  5. Agent 365企业智能体管理与安全。
  • CoreWeave、Lambda和Nebius等AI原生云厂商主要聚焦GPU基础设施和AI工作负载，并提供部分基础设施安全能力，包括：
  1. 工作负载隔离；
  2. 加密；
  3. 身份管理；
  4. 跨平台管理。
  • Fireworks AI、Together AI和Bastion等AI平台提供：
  1. 安全模型托管；
  2. 私有化部署；
  3. API服务；
  4. 身份验证；
  5. 企业访问控制。
  • Lakera、Protect AI、HiddenLayer和Prompt Security等专业AI安全初创公司主要聚焦：
  1. 提示词注入防御；
  2. 模型保护；
  3. AI应用监控；
  4. 敏感数据泄露防护。
  • 小型AI云厂商通常提供基础设施层面的安全能力，专业AI安全供应商则在模型、应用和智能体运行时层面提供更深入的防护。

b）单点AI安全厂商的生存空间是否会被压缩？

  • 仅提供1至2项AI安全功能的小型独立厂商将面临越来越大的竞争压力，主要风险是功能同质化。
  • 如果厂商只提供提示词注入检测、基础智能体身份管理或API监控，大型平台可以将类似能力逐步整合进现有企业合同。
  • 主要大型平台的竞争优势包括：
  1. Okta在身份生命周期管理和访问治理方面具有优势；
  2. Palo Alto可以将AI运行时安全与网络安全、云安全和威胁情报结合；
  3. Microsoft可以将身份、数据、办公软件、云服务及安全能力一体化；
  4. CrowdStrike可基于终端和威胁情报能力向AI安全扩展。
  • 专业安全厂商不会完全消失，行业更可能出现持续整合。
  • 大型平台也可能与专业厂商合作，而非自行开发所有高级安全能力。
  • 在智能体授权、行为检测和自主威胁防御方面具有差异化技术的初创公司仍有发展机会，尤其是在复杂多环境场景中。
  • 专业厂商的长期竞争壁垒必须来自经过实践验证的能力，例如：
  1. 更高的检测效果；
  2. 更低的运行延迟；
  3. 更强的跨平台覆盖；
  4. 综合平台难以快速复制的专有能力。
  • 独立单点厂商将面临定价压力和市场份额挤压，领先专业厂商则可能成为收购标的，或扩展为覆盖更广的安全平台。

5. Agent 365的购买驱动、产品定位与客户使用情况

a）哪些需求最容易推动客户购买Agent 365？

  • 最明确的购买驱动因素是企业计划将AI智能体从试点环境投入生产环境。
  • 当智能体需要访问以下资源时，安全需求尤其强烈：
  1. 敏感企业数据；
  2. Microsoft 365应用；
  3. 内部数据库；
  4. 客户财务记录；
  5. 内部业务流程和交易系统。
  • 金融服务行业最关注的问题包括：
  1. 数据泄露；
  2. 未经授权的访问；
  3. 监管合规；
  4. 自主智能体行为的可见性与审计能力。
  • Agent 365通过智能体清单、身份管理、治理和安全控制满足相关需求。
  • Purview负责数据保护，Defender用于发现恶意活动或已经遭入侵的智能体。
  • 对已采用Microsoft 365、E3或E5，并希望扩大AI部署但不愿引入其他安全平台的客户，商业机会最为明确。
  • Agent 365与E5定位不同：
  1. Agent 365侧重智能体管理、治理和安全；
  2. E5覆盖更广泛的企业安全与合规能力；
  3. 两者可以同时采购，但并非简单替代关系。
  • 最强烈的购买触发因素是安全团队明确要求：若缺少身份管理、最小权限、监控和审计能力，智能体将无法获得生产上线审批。

b）购买AI安全产品的客户是否已经真正投入生产？

  • 当前客户主要分为2类：
  1. 已在生产环境部署AI应用的组织，正在积极启用安全控制；
  2. 仍处于智能体试验阶段的组织，会在全面部署前提前采购相关能力。
  • 金融服务客户通常将安全视为AI应用能否投入生产的决定性条件。
  • 当前实际使用最明显的能力包括：
  1. Purview敏感数据保护；
  2. Entra身份和访问管理；
  3. Defender威胁检测；
  4. 智能体活动监控和审计。
  • 采购许可证并不意味着客户已经使用全部功能。多数客户会先启用基础控制措施，再随AI工作负载进入生产环境逐步扩大使用范围。
  • 预计未来几个季度，生产环境中的实际使用量增速将超过初始许可证采购量，特别是在客户由有限的Copilot应用转向与业务流程深度集成的自主智能体后。

c）Agent 365整合原有功能后，能为客户带来哪些收益？

  • Agent 365整合的首要价值是形成一致的安全和治理体系，其次是加快部署、简化采购和减少运营复杂度。
  • 此前客户可能需要分别使用：
  1. Entra管理智能体身份；
  2. Purview进行数据保护；
  3. Defender进行威胁检测；
  4. 其他平台进行智能体开发和管理。
  • 整合后主要产生3方面收益：
  1. 基于现有微软合作关系简化采购；
  2. 为安全团队提供集中化可见性，在不同智能体之间实施一致策略；
  3. 减少管理、集成和监控多个工具所需的人工投入。
  • 随着企业内部智能体数量从数十个增长至数千个，碎片化安全策略将形成明显运营风险。
  • 整合平台的核心价值是帮助企业在不按比例增加人员的情况下扩大AI应用规模。
  • 但整合不一定直接减少人员成本，也不意味着企业不再需要专业安全团队。

d）Agent 365整合是否已经带来增量收入？

  • 整合能够带来增量收入，但短期最大机会是推动现有微软客户扩大安全产品采用范围，而非立即替换所有第三方厂商。
  • 统一管理身份、数据保护、威胁检测和治理后，客户采购阻力降低，更容易扩大部署。
  • 潜在收入来源包括：
  1. Agent 365订阅；
  2. 额外安全许可证；
  3. Azure使用量；
  4. 更多受保护智能体和安全工作负载。
  • 仅提供基础智能体监控、身份可见性或与微软现有产品高度重叠能力的独立厂商，可能被部分替换。
  • 在多云、自托管和异构环境中，微软整合优势会减弱，具体取决于第三方平台的集成深度和安全执行能力。
  • 微软正在将Agent 365扩展至AWS、GCP及其他第三方平台，因此其多云能力并非消失，而是表现为：
  1. 集中式可见性可以跨云扩展；
  2. 集成深度和安全执行能力因平台而异。
  • 微软预计将提高其在客户安全支出中的份额，但难以完全取代复杂环境中的专业安全厂商。
  • 应重点关注的指标不只是Microsoft 365许可证销量，还包括：
  1. 实际启用相关功能的客户数量；
  2. 每个客户受保护智能体的规模；
  3. 生产环境中的功能使用深度；
  4. 客户对现有合同的整合程度。

6. AI安全产品定价模式与议价权

a）订阅制和按使用量收费有什么区别？

  • 订阅制定价能够为客户提供更可预测的成本，适合企业预算管理。
  • 按使用量定价会随实际工作负载、智能体交互、令牌数量和安全决策次数变化。
  • 微软倾向于使用按用户订阅或按使用量收费，原因包括：
  1. 企业客户重视预算可预测性；
  2. 微软已通过Microsoft 365建立成熟许可关系；
  3. Azure AI和Copilot Studio天然适合按使用量变现。

b）智能体数量增长、人工席位不变时，微软如何获得增量收入？

  • 微软并非完全依赖人工席位收费，增量收入可来自：
  1. 为管理和治理智能体的员工提供Agent 365许可；
  2. Azure AI服务按使用量收费；
  3. Copilot Studio按智能体活动或使用量收费；
  4. 智能体交互和Azure基础设施使用增长；
  5. 附加安全功能和许可证扩容。
  • 即使员工人数保持不变，AI工作负载、智能体交互和安全检查量的增长仍可形成增量收入。

c）未来是否会转向混合收费模式？

  • 预计未来将逐步形成混合收费模式：
  1. 治理和管理能力按订阅收费；
  2. 智能体执行、安全检查和基础设施按使用量收费。
  • 转向混合模式的最大触发因素，是智能体活动增速显著高于员工人数增速。
  • 当人工席位数量无法反映客户获得的价值和供应商实际服务成本时，按席位收费的重要性将下降。
  • 短期内按席位模式不会消失，但未来几年，基于使用量、受保护工作负载和安全交易的收费占比将提升。

d）主动咨询需求增强后，AI安全产品是否具备提价能力？

  • 随着企业在智能体上线前主动寻求安全防护，专业AI安全厂商的议价能力将增强。
  • 需要区分单位价格和合同总价值：
  1. 随着智能体数量、受检交易和安全功能增加，合同总价值预计上升；
  2. 单位价格可能保持不变甚至下降，原因是平台捆绑、规模折扣和市场竞争。
  • 定价能力最强的差异化能力包括：
  1. 自主智能体保护；
  2. 智能体授权；
  3. 高级运行时保护；
  4. 跨云安全执行。
  • 单客户收入增长将主要由消费量增加和部署范围扩大推动，而不是持续提高单位价格。
  • 例如，Palo Alto的AI网关在更高产品层级或更大消费量下，每10亿个token的单位价格会下降，体现了“合同总价值增长、单位价格下降”的并存关系。

7. AI安全产品的成本结构与利润率

a）令牌检查和授权决策的成本有何差异？

  • 令牌检查成本通常随流量增长而增加，尤其是供应商使用AI模型执行以下任务时：
  1. 系统分析；
  2. 提示词注入检测；
  3. 数据泄露防护；
  4. 内容与行为风险识别。
  • 授权决策成本相对更低，因为多数授权判断可通过确定性策略引擎完成，无需每次调用大语言模型。
  • 在同等防护水平下，基础设施总成本大致会随检查量增长。
  • 随着规模扩大，供应商可以通过以下方式降低单位成本：
  1. 模型优化；
  2. 批处理；
  3. 缓存；
  4. 使用更小型的专业检测模型；
  5. 采用确定性策略处理部分决策。
  • 因此，每100万token或每次授权决策的成本预计会逐步下降。

b）AI安全产品稳态利润率可能达到什么水平？

  • 优化良好的AI安全平台，稳态毛利率预计约为70%至80%。
  • 主要依赖轻量级授权和策略执行的产品，毛利率可能更高。
  • 根据研发投入、销售效率和竞争性定价情况，长期营业利润率可能达到20%至30%。
  • 核心前提是收入增长速度必须快于推理和基础设施成本增长速度。
  • 以授权为主的安全产品，在结构上通常比需要使用昂贵模型检查每次交互的产品具有更高利润率。
  • 作为参考，访谈者记忆中Palo Alto FY2026订阅与支持业务整体毛利率约为69.2%，FY2025约为72%；该数据为公司整体口径，并非特定AI安全产品数据。
  • AI安全需求增长并不必然带来利润率提升，规模折扣、平台捆绑和推理成本都可能形成压力。

8. 中国市场的监管影响与竞争格局

a）微软Defender退出中国市场后，相关需求将由谁承接？

  • 中国本土安全厂商预计将承接大部分增量需求，尤其是在以下客户群体中：
  1. 政府机构；
  2. 金融机构；
  3. 受监管企业；
  4. 对数据本地化要求较高的企业。
  • 主要驱动因素包括：
  1. 数据主权要求；
  2. 网络安全法规；
  3. 本地托管要求；
  4. 跨境数据传输限制。
  • 潜在受益厂商包括华为、阿里云、腾讯云、奇安信和深信服等，它们能够提供符合本地要求的部署与安全服务。

b）Palo Alto等国际厂商是否仍有市场机会？

  • 国际厂商仍可参与竞争，主要机会来自：
  1. 在华经营的跨国企业；
  2. 混合云环境；
  3. 需要全球统一安全策略的客户。
  • 其市场空间将取决于：
  1. 监管合规能力；
  2. 本地交付能力；
  3. 客户数据能否留在中国境内；
  4. 是否能够满足本地托管和审计要求。
  • 外国服务提供商退出时，本土厂商将成为主要受益者；国际安全厂商仍会在部分跨国企业和混合云场景中发挥作用。

9. AI减少企业员工后，对按席位收费模式的影响

a）如果开发人员和安全分析师人数减少，按席位收费会受到多大影响？

  • 当员工人数保持稳定或下降，而智能体数量持续增加时，纯按席位定价将逐渐脱离AI安全的实际价值和工作负载。
  • 例如，一家企业可能只有500名开发人员和100名安全分析师，但这些人员未来可能管理1000个乃至数千个自主智能体。
  • 在纯席位收费模式下，即使智能体数量、安全事件和授权决策量大幅增加，供应商也难以获得对应的增量收入。
  • 未来更可能形成双轨收费体系：
  1. 对人类用户继续采用按席位订阅；
  2. 对智能体活动、受保护工作负载、安全交易和基础设施使用量按量收费。
  • 对Microsoft而言，可以通过Azure和Copilot Studio对额外AI使用量进行变现，同时保留Microsoft 365等产品的可预测订阅收入。
  • 基于席位的定价短期内不会消失，但随着智能体部署规模扩大，其重要性将逐渐低于按使用量变现模式。

新版prompt提炼之后的转译

提问者：从生成式AI转向生产环境中的AI智能体后，新增了哪些安全需求？这些需求推动了哪些原有需求的变化？能否进行量化说明？

回　答　者：从生成式AI转向生产环境中的AI智能体，显著增加了安全需求，因为安全防护的重点正从保护提示词和响应内容，转向保障自主操作的安全。

传统生成式AI的安全重点主要是数据泄露、提示词注入和内容过滤。进入智能体阶段后，还需要保障机器身份、API访问、凭证、工具调用、执行过程以及智能体间通信的安全。

与基础的聊天机器人交互相比，复杂程度适中的智能体工作流可能会使安全决策点增加5至10倍。这是我基于系统架构作出的估算，并非全市场范围内的实测数据。

从支出增长来看，新增需求主要来自运行时保护、智能体身份管理、授权和持续监控等方面。企业只有具备这些安全能力后，才会允许智能体在生产环境中独立运行。

提问者：在AI安全的支出预算方面，目前预算主要来自业务侧，还是原有的安全支出？换言之，相关预算仍由首席信息安全官拍板，还是越来越多地由业务侧负责人推动？此外，哪些场景或功能更容易获得AI安全预算？

回　答　者：目前，大部分AI安全支出仍来自CISO的安全预算，尤其是数据保护、威胁防护、合规和运行时安全方面。不过，我们正日益看到CIO、CTO以及部署AI应用的业务部门共同出资。

其中的区别在于，业务部门通常负责AI用例，而安全部门负责审批要求。以金融服务行业为例，在银行、抵押贷款等业务中，如果AI智能体需要访问客户财务记录或执行交易，通常必须获得安全审批后才能投入生产。

更容易获得预算的功能包括敏感数据保护、智能体身份管理、访问控制、提示词注入防护、运行时监控和可审计性。我预计，最强劲的增量支出将来自对智能体的保护，尤其是能够访问敏感系统或自主执行操作的智能体，而不仅仅是聊天机器人的内容过滤。

最终，CISO拥有否决权。当安全成为AI应用上线前的最后一道障碍时，相关解决方案可能由CISO或业务部门负责人出资。

提问者：此前您提到，AI安全相关需求正越来越多地依赖企业现有的安全预算和云预算，而不是单独设立全新的独立预算科目。在实际采购中，这意味着企业会追加投入，还是会重新分配现有预算？是否可能出现更换供应商的情况，例如从第三方安全企业转向现有云服务商提供的云原生安全方案？此外，是否存在需求明显增长，但安全支出并未相应增加的情况？

提问者：AI安全预算更可能来自新增预算，还是现有预算的重新分配？是否会出现供应商替换，例如从第3方厂商转向原生厂商？此外，您是否观察到AI安全需求不断增长，但相关预算支出仅小幅增长或没有增长的情况？

回　答　者：这3种情况都存在。但短期内，绝大多数AI安全支出仍来自现有的网络安全和IT预算。随着AI智能体逐步进入生产环境，新增预算正变得越来越普遍。

最初，企业会从传统应用安全、DLP和云安全等领域重新分配支出。当AI智能体开始访问敏感数据并执行交易时，就会产生新的安全要求，最终为追加资金提供依据。

我们也观察到供应商整合。Microsoft、AWS和Google正越来越多地将AI安全能力捆绑到现有平台中，这对独立厂商形成了压力，尤其是在基础防护方面。

需要特别区分的是，安全需求的增长速度仍快于实际支出的增长速度。企业可能将AI工作负载提高至5倍，但不会按相同比例增加安全预算，因为企业可以利用现有许可证、协商批量折扣并整合供应商。因此，AI安全的采用率在增长，但安全净新增支出的增长相对温和。新增预算的最大机会在于自主智能体保护、身份管理，以及云安全中的授权管理。

提问者：随着Microsoft等云平台不断增强原生安全能力，客户会如何在原生安全能力和独立厂商之间进行选择？在哪些场景或用例中，客户认为原生安全能力已经足够？又在哪些场景或用例中，第3方独立厂商仍然更具优势？

回　答　者：当企业高度标准化地使用单一云平台时，我会倾向于选择原生安全能力。

回　答　者：例如，在以 Microsoft 为核心、使用 Azure OpenAI、Microsoft Entra、Defender 和 Purview 的环境中，原生安全解决方案能够提供更紧密的身份集成、更简便的部署和集中式策略管理，并可能降低增量成本。

在复杂的多云环境中，第三方供应商更具吸引力。如果企业同时使用 Azure、AWS、Google Cloud、Anthropic 和内部托管模型，Palo Alto Networks 等供应商可以在这些环境中提供一致的安全策略和可见性。第三方供应商在高级 AI 红队测试、智能体运行时保护、成本、跨平台发现及专门检测方面具有差异化优势。

关键区别在于，原生供应商具备集成和成本优势，独立供应商则具备跨平台覆盖广度和一致性优势。对于单一云环境中的基础提示词过滤和数据保护，原生解决方案通常已经足够；但对于在多个环境中处理敏感数据和权限的自主智能体，独立安全平台更有机会证明其额外支出的合理性。

提问者：目前，我们看到越来越多的云平台与第三方供应商开展合作。在这种情况下，客户通常是与云厂商签约，还是单独与第三方供应商签约、议价和续费？从长期来看，这种合作模式主要会扩大第三方供应商的销售机会，还是可能削弱其独立定价能力？

回　答　者：通常有2种商业模式。第1种是直接与第三方安全供应商签订合同，由客户直接与其协商定价、容量和企业折扣。第2种是通过 Azure Marketplace 或 AWS Marketplace 等云市场进行采购，由云服务提供商负责计费，第三方供应商仍可与客户协商专属报价。

我认为，这种模式总体上有利于第三方供应商扩大销售机会，但也会对其定价能力形成一定压力。其中一项优势是，通过云市场完成的交易可以计入客户现有的云支出承诺，从而简化部分采购流程。

回　答　者：这类渠道能够触达大型企业客户，但其劣势在于，云服务提供商掌控着市场关系，会收取交易费用，并且越来越多地通过自有原生安全产品参与竞争。在我看来，云市场能够改善分销效率和交易速度，但不一定能提升供应商利润率或谈判能力。当实力较强的第三方供应商能够提供原生云工具难以复制的差异化防护时，仍将保有定价权。

提问者：目前有哪些新云厂商也在提供安全相关解决方案？它们的具体方案是什么，提供了哪些具体服务？这里所说的新云，是指小型公司或初创公司。

回　答　者：如果指主要云服务提供商，它们都在提供自有的AI安全产品，但能力各不相同。Microsoft提供Defender for Cloud、用于AI威胁检测的Defender、用于数据保护和敏感性管理的Microsoft Preview、用于身份和访问管理的Agents，以及用于管理企业安全智能体的Agent 365。AWS和Google Cloud也提供相关产品。

如果是指Microsoft、AWS和Google之外的新云厂商，目前也有一些AI原生云服务提供商和初创公司，正在将安全能力直接构建到自身平台中。例如，CoreWeave、Lambda和Nebius专注于GPU基础设施和AI工作负载，其中一些厂商提供基础设施层面的控制能力，包括隔离、加密、身份和跨平台管理。

此外，Fireworks AI、Together AI和Bastion等AI平台提供安全模型托管、私有化部署、API、身份验证和企业访问控制。

在专业AI安全领域，Lakera、Protect AI、HiddenLayer和Prompt Security等初创公司专注于提示词注入防御、模型保护、AI应用监控和敏感数据泄露防护。

其中的重要区别在于，小型AI云服务提供商通常具备或提供基础性基础设施安全能力，而专业AI安全供应商则能够在模型、应用和智能体运行时层面提供更深入的防护。随着这些小型云服务提供商向高端市场发展，我预计……

提问者：刚才您提到，智能体使身份与授权的重要性明显提升，这与 Okta 所从事的业务类似。目前，Palo Alto（PANW）也已通过收购补齐并强化了相关能力。在您看来，仅提供 1个或2个安全能力或安全功能的独立第三方企业，未来的市场份额和生存空间是否会受到明显挤压？

回　答　者：确实如此。仅提供 1个或2个 AI 安全能力的小型独立供应商将面临日益加剧的竞争压力，尤其是在 Palo Alto、Microsoft、Okta 和 CrowdStrike 持续扩展平台能力的背景下。最大的风险在于功能同质化。

例如，如果一家初创公司只提供提示词注入检测、基础智能体身份管理或 API 监控，大型平台可以逐步将类似功能和解决方案整合到现有的企业合同中。Okta 在身份生命周期管理和访问治理方面具有优势，而 Palo Alto 可以将 AI 运行时安全与网络保护、云安全及威胁情报相结合。

我预计，专业安全供应商不会消失，行业更可能出现整合。大型平台也将越来越多地与专业安全供应商合作，而不是完全自行构建所有高级安全能力。在智能体授权、行为检测和自主威胁防御方面拥有差异化技术的初创公司仍有机会取得成功，尤其是在复杂的多环境场景中。但其长期竞争优势必须来自长期实践中已经得到验证的能力，包括更出色的检测效果、更低的延迟，以及综合性平台难以轻易复制的能力。
