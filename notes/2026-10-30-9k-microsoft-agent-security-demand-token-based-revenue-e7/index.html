2026.10.30 | 9K | Software | Microsoft Agent Security Demand Token-Based Revenue E7

原标题：微软离职专家|企业AI前三大需求为数据管控、操作授权和事后审计，Agent从1,000个增至10,000个目前仍难带动按座席安全收入同比增长，增量主要来自Token消耗；E5升级E7因定价接近E5加购Copilot而形成趋势，未来2到3年AI对抗与Agent越权防护或打开按用量计费空间

#software #cloud

Meritco 久谦 · 2026-10-30

摘要

Agent正放大企业内网数据暴露、越权操作与合规风险，客户采购重点集中于权限、敏感数据和事后审计。当前多数微软安全产品仍按座席或套件收费，Agent数量增长难直接转化为收入，Token扫描和实际消耗成为主要增量，未来AI对抗及Agent运行管控可能打开新市场。

要点

  1. 企业部署Copilot和Agent的前三大安全需求是敏感数据与流转管控、Agent操作权限控制及全行为审计；多数客户仅开放“查”权限，增、删、改仍需人工确认，而事后定位原因、框定影响范围和找到事故断点是采购Agent

365的首要驱动力

  1. Agent扩大数据、系统和工具覆盖范围后，历史遗留的内网数据过度暴露问题被集中揭示，权限和敏感数据治理需求确定增长；基础薄弱或历史包袱较重的企业通常先划定沙盒，数据与权限梳理及Adoption过程可能持续一年甚至更久
  2. 安全合规通常只会延缓而非彻底叫停Agent项目，强合规行业可能通过数据分层隔离、冗余混合架构或完全本地化部署解决；一家中资金融机构的项目因内外部系统交互风险从去年年底持续延迟，直到最近才重新讨论上线
  3. Agent 365、Microsoft Entra ID和Microsoft Purview主要按套件或座席计费，Microsoft Security Copilot按Capacity计费，Defender for

AI等按扫描Token或用量计费；员工人数不变时Agent从1,000个增至10,000个，安全收入增长仍相对有限，增量主要来自Token消耗

  1. E3升级到E5主要由Endpoint Detection and

Response、DLP等传统安全需求驱动，但趋势并不明显；E5升级到E7则基本由AI驱动，因E7包含Copilot且全球定价接近E5加购Copilot，目前升级趋势更为突出

  1. 未来2到3年，确定性新增支出集中于权限授权、敏感数据保护和审计治理，更大的潜在增量来自基于Token的AI对抗能力及防止Agent越权、逃逸的内部管控；随着AI降低攻击成本并扩大经济可行的攻击范围，安全需求可能被极大扩张

Q:客户在使用Copilot或在Azure上部署Agent并实际落地项目时，最常提出的前三项安全要求是什么？对于不同类型的Agent，例如仅用于读取资料的助手，以及能够修改系统设置、发送邮件，甚至涉及敏感信息或正常业务流程的Agent，安全要求分别是什么？

A:目前的前三大需求与上述问题高度相关。第一项是数据安全，即向什么样的人展示什么样的数据，以及什么样的数据可以在此过程中以何种方式管理和流转。举一个真实案例:有客户基于Microsoft 365 Copilot搭建应用，过程中意外发现了此前系统建设中的安全漏洞。企业内部一部分面向管理层的经营数据，在权限和数据加密等级设置上过度开放给了很多员工。过去，这些数据存放在基于SharePoint建设的站点中，因为员工不知道地址或其他原因，无法在内部检索到，所以历史上没有发生太多严重的泄密事件。

Microsoft 365 Copilot接入并直接对齐权限后，这部分内容被员工偶然检索出来。一名澳洲员工发现后负责任地进行了上报。他可能并非第一个看到这些内容的人，但正是由于他的上报，集团才开展排查，并发现大量类似情况。过去，这些问题可能因员工没有发现自己能够搜索相关数据而被掩盖；随着一系列Agent的使用和建设，问题会被充分暴露，因此加强这部分管控是第一大需求。

第二项需求是控制Agent操作系统时的权限。当前多数客户会先开放“查”的权限，将增、删、改暂时保留在人工确认范围内。最常见的Agent应用是从现有数据平台、数据系统或CRM、ERP等业务系统调取数据，再进行后续处理，较少有客户愿意开放增改权限。这里首先涉及如何管控权限，避免误操作给整体系统带来持久的不利影响；其次，如果Agent增删内容或数据后出现问题，如何提供有效保障。

第三项是审计需求，既包括运营层面，也包括安全防护层面。从安全防护角度看，主要是记录所有Agent的历史行为，包括过去发生了什么、调用过哪些工具、读取过哪些数据，以及数据最终流向哪里。需要对这些内容开展事后审计和调查，确保Agent或AI应用引发问题后，后续调查能够有明确方向。主要就是这三个方面。

Q:整个架构是否可以理解为:门户和身份管理使用Microsoft Entra ID，检测使用Defender，分析使用Sentinel，员工查询或分析时使用Microsoft Security Copilot？

A:在此架构之外，还要加上Agent 365。Microsoft Entra ID不只是门户，还负责所有身份鉴权。Microsoft Entra ID除了对人进行鉴权，也会对Agent本身进行鉴权。在微软的架构体系中，Agent不能独立存在，必须代表某个实际的人，作为这个人的延伸，因此Agent执行时对应的是此人的一系列权限。Microsoft Entra ID的能力会延展到代表该用户的一系列Agent中。

Defender方面，Defender for AI会审计输入和输出中是否存在攻击性词汇，或涉及网络安全的其他情况。对于数据本身是否涉及敏感信息，也会进行管理。这些敏感信息既可以依据通用定义识别，例如个人隐私信息，也可以依据公司自行设定的规则识别，例如将某类文件或具有某些特征的文件设为高加密等级，这部分服务由Microsoft Purview提供。后续分析可以使用Microsoft Security Copilot，但目前针对Agent，更多可能使用Agent 365进行整体管控和审计。

Q:与三个月前或上半年相比，客户对AI安全需求的数量和紧迫程度发生了什么变化？是否所有项目都会部署相关安全功能？企业对更高等级安全能力的需求是否越来越多？

A:总体而言，客户对安全的重视程度肯定在提升，主要原因是Agent能够覆盖的数据范围、系统范围以及调用工具的能力都在扩大，这是行业发展被动带来的现象。但不同项目在实际交付中的差异很大。有一类企业的基础设施建设并不健全，很多安全产品无法被有效纳入，因此不得不采用一刀切的方法。例如，企业在建设整个AI系统时，会划出一块类似沙盒的范围，只将一部分数据和业务场景纳入其中，另一部分暂不纳入。

未纳入的部分通常存在传统数据和权限管控较为混乱的问题，需要经过有效梳理后才能迁移进来。尤其对于经营时间较长、历史包袱较重的企业，需要开展大量整理工作。这一实施或Adoption过程有时会持续一年甚至更久。随着Agent开始大规模铺开，很多企业逐渐重视并不得不开启这一进程，因此相关需求肯定会增加。

第二，AI应用增多后，企业对合规和实际使用的要求也在提高。传统企业推进速度相对较慢，现在才开始大量进入业务系统，因此对安全的要求会更高。Agent 365大约从上个财年结束，即年中五六月份开始，到现在实际订单逐渐增加，原因是企业在应用拓展过程中真正遇到了一系列问题，才开始引入这些安全产品。因此，市场确实在逐渐扩大，但不能将其直接等同于微软在这部分的销售增长。

安全产品的选择很大程度上取决于企业原有的数据分布、业务系统认证方式和安全体系。如果企业原本就在微软体系内，例如办公使用Microsoft 365套装，大量数据位于微软体系中，部署会相对顺利；如果数据和系统位于外部，企业可能考虑其他方案，因此相关需求不能直接计入微软营收。

最后，AI在跨国企业中面临的合规挑战越来越多。从微软的视角看，安全与合规高度相关。此前一些企业快速推进AI Agent；随着使用人员增多、使用范围扩大，合规问题开始出现。例如，大约上个月八九月份，一家中资出海公司在欧洲被发现其Agent将一部分属于欧洲的数据传递到内地，违反了General Data Protection Regulation（《通用数据保护条例》）。这类小样本违规可能因疏忽而难以完全避免，过去可能因为用量较少而未被发现；此次则因员工纠纷，由员工主动向新闻媒体上报。

为了平息此事，企业付出了很多成本，不得不使用大量安全产品加固合规通道和防火墙。随着AI应用拓展，合规挑战会不断增加，并推动此类安全产品持续扩张。这是目前呈现出的整体趋势。

Q:近期客户部署中，是否存在业务部门希望上线Agent项目，但因合规或其他原因被安全团队叫停的情况？这类项目具体缺少什么、最终如何解决？从处理现实卡点到上线通常需要多长时间？是否有项目最终因安全问题被取消？

A:从大方向看，目前绝大多数企业都将AI驱动视为重要方向，安全问题一般只会延缓上线，真正彻底叫停的情况基本只存在于强合规行业。一个类似案例来自金融行业，是一家向海外拓展的中资金融机构。该项目涉及外部信息系统与内部系统之间的数据和流程交互，整套系统因安全合规问题从去年年底一直延迟。应用本身并不复杂，实施周期也很短，但会带来一系列合规问题，因此直到最近才有机会重新讨论上线。

安全团队认为其中存在较大的数据外泄风险，项目方反复提交各种材料，并设计了一整套较为冗余的混合架构，对数据进行分层隔离，再逐层取用。但因安全问题而彻底取消项目的情况比较少。现在AI Agent在各企业CIO和IT部门中的优先级都很高，大方向已经确定，通常不会彻底停止，更多是调整架构，尤其是在数据架构上增加很多管理和规范。少数公司最终可能放弃云端方案，完全采用本地化部署来解决问题。

Q:不同安全环节分别采用什么付费模式？Microsoft Entra ID可能已包含在原有E3、E5、E7等套餐内，其他安全功能如何收费？哪些按席位收费，哪些按行为或用量收费？

A:Microsoft Entra ID、Agent 365等产品基本以席位付费为主。Defender for AI以及分析类产品基本按用量收费，其中Defender for AI比较新，也较为特殊，按照扫描过的Token收费。其他传统云端应用也偏向按用量收费。Microsoft Security Copilot按Capacity计费。多数身份类产品仍按席位收费，因为微软的逻辑是Agent是人的延伸。

但这会带来一个问题:当Agent越来越强、企业人员较少但拥有大量Agent时，微软的营收可能无法随实际用量同步增长。未来计费模式是否会变化，目前还无法确定。

Q:目前是否已经出现安全产品更多转向按用量计费的趋势？客户，尤其是CTO，对按消耗或用量计费持什么态度？

A:相对传统的企业不像Digital Native或AI原生公司那样拥有海量Agent。在仍有大量真人员工、Agent数量快速扩张的情况下，多数客户现阶段更愿意按用量付费，因为真正高频运行Agent的人可能不多，但按人头收费意味着即使某人的使用频次不高，企业也必须为其付费。

另一方面，很多企业的Agent仍处于快速扩张阶段，有些企业会举办黑客松活动，推动内部开发Agent。因此，企业一方面抱怨按人头收费带来的成本压力；另一方面又认为既然已经购买，就应充分利用现有能力，大量扩张Agent，以期减少真人员工并节约成本。客户的态度比较矛盾，通常都会基于对自身最有利的情况提出要求。

从整体趋势看，不排除未来在某个时间节点将此类安全产品的计费方式从按人转为按用量。当前定价很大程度上仍源于传统计费思维的惯性，以及对传统销售渠道和销售形式的依赖。随着用量不断扩张，计费方式大概率会转向按用量计费；一些对Token更敏感的产品和服务已经开始逐渐切换。

Q:安全预算通常由哪个部门承担？是从原有IT预算中支出，还是由希望上线业务Agent的业务部门承担？客户从去年到今年、再到明年的安全预算呈现什么变化趋势？安全预算通常如何制定？

A:不同企业的情况不同，没有统一模式。大部分仍放在原有安全预算中；有些企业会随着新Agent上线再申请一笔预算，因为产生了新需求，例如建设新的AI网关或其他安全能力。这笔预算会与AI应用项目立项绑定，但仍由原IT部门下负责安全的团队单独申请。少部分企业会在AI项目单独立项时将安全预算一并纳入，因为AI团队通常比较激进，可能会把相关成本全部纳入自身预算。

还有个别企业使用传统办公预算或传统安全预算。在Microsoft 365扩展较多的情况下，企业可能在Modern Work升级过程中追加一笔预算，以提升现有办公AI能力，并将安全部分纳入其中，但这种情况较少。

安全预算比较难制定，因为安全本身很难产生直接的正面收益。最常见的方式是参照此前预算或现有系统架构制定后续预算。少部分企业如果要对整个安全体系进行较大调整，会聘请第三方开展审计。例如，一家企业去年聘请PwC，对集团在南美、澳洲、内地、东南亚、欧洲和南非等地区开展整体安全审计，覆盖云端环境、桌面端环境、部分本地部署的混合架构、服务端和个人用户端等，由PwC出具完整报告，再根据报告中发现的安全隐患和问题制定预算。

对于资金充裕的公司，这类报告可能带来新的预算增量；对于资金紧张的企业，最多只能调整资金分配，甚至在重新分配过程中更换供应商、压降成本。例如，终端安全和零信任产品会不断被替换，微软作为安全厂商，这些年也存在产品被替换的场景；有些企业会切换到腾讯等价格较低的产品，从而腾出预算支持大规模AI Agent建设。总体来看，能够持续扩张安全预算的企业相对较少，除非近期遇到过较大的安全挑战。多数企业会在原有预算略微增长的情况下，在不同项目和供应商之间调整份额。

Q:企业安全预算是按照营业额的一定比例计算，还是采用其他逻辑？预算是否会拆分为安全团队人员成本，以及硬件、软件等成本？大致如何拆分？

A:总体而言，安全预算不是按照营业规模计算，而是按照企业实际使用IT资源的情况计算。例如，传统企业以工厂制造为主、IT化程度较低，即使营收规模不小，安全预算也会比较低。一家从事光纤相关业务的小巨人企业受服务器生产热潮影响，业绩增长很好，但整体IT化程度非常低。其安全预算基本只有本地物理网关和防火墙，好像采用的是华三的一套设备。

这家企业在云端基本没有实际应用场景，少量云端工作完全委托第三方，企业自己甚至不知道其中具体包含多少安全支出。相反，高度依赖IT的企业如果公有云使用量很大，或者维护较大的本地数据中心，即使营收与前者相近，也一定会有更高的IT和安全预算。因此无法给出具体比例，核心仍是IT资源的规模和形态。

具体拆分时，云端安全预算包括网关、防火墙等云端防护；桌面端则包括办公、邮件、个人终端设备管控和DLP等。服务端是一部分预算，桌面端是另一部分。桌面端预算有时会摊入实际业务部门的用人成本，与人头数正相关；服务端预算如果能够拆分到具体业务部门，也会由业务部门承担。有些企业按业务部门拆分，有些按区域拆分，具体取决于业务划分，最终会归入业务部门的IT使用预算。

Q:客户部署AI项目或进行选型时，会单独采购安全功能，还是将安全作为项目的一部分？客户通常为什么选择微软，或在Azure上部署AI项目？前面提到有客户从微软切换到腾讯，原因更多是成本，还是其他因素？

A:在一般企业的IT架构中，AI Agent位于较上层，底层一定有数据系统、数据平台、数仓等支持，而这些部分通常已经部署了现有IT产品。企业立项AI Agent时需要通过审核，成本可能包括应用是外采还是内部开发、开发人天，以及相应基础设施需要多少投入。此时，安全团队会提出项目带来的安全成本。

如果应用处于内网边界内，尤其是本地部署，可能不会带来太多新增安全成本，安全团队主要作为审核和参与方，将现有安全能力应用于项目即可。少部分项目因存在新增场景，会产生新的安全采购需求。通常企业在项目立项时就要考虑可能新增的安全产品，并将相关预算纳入项目；或者由项目团队与安全团队共同申请预算，作为整体项目打包提交审核。

客户选择微软整套产品，大概率是因为原有系统已经大量架设在微软体系中。最常见的是Modern Work使用较深，办公数据沉淀在微软体系内。企业使用微软相关安全产品后，开发Agent会较为顺利，身份认证等也已绑定在体系内，不需要很多额外采购成本就能将系统连接起来。如果企业的数据平台位于其他体系中，例如办公使用飞书、数仓架设在阿里平台，采用微软解决方案的概率就会较低。虽然微软也可以纳管第三方系统或数仓，但最终仍取决于企业最主要的平台位于何处。

客户从微软迁出的一个重要原因是成本。该客户内地员工人数近两年有较大增长，原合同到期后又大量采用飞书，文本和办公内容已经开始从微软办公体系迁移到飞书文档、多维表格等产品，因此有动力重新招标并评估整套新方案。腾讯与其股东之间还有一定关系，又以超低价进入，因此在内地完成了整体替换。

在发达国家等合规要求较高的市场，替换面临的挑战更大，客户可能暂时仍使用微软方案。腾讯产品在当地可能面临数据主权、合规审计等方面的挑战。但从集团目标看，如果腾讯的产品能力足以支撑需求，内部评估也有信心规避相应风险和隐患，未来仍可能切换，因为成本确实是重要考量，而且继续使用微软的必要性正在下降。

Q:是否可以理解为，微软基本盘中的大型全球企业较难从现有办公体系迁出，内地市场受到飞书等厂商竞争的挑战更多，但整体基本盘较为稳定？微软较强的安全能力是否会吸引更多客户在微软或Azure上部署Agent和Use Case，还是主要取决于企业历史上是否已使用微软全栈软件，以及数据是否已经位于微软平台上？

A:可以这样理解。因安全能力而迁移到微软的情况并非没有，但相对较少，而且案例并不集中在通常所说的Agent领域。微软有一类产品的销售机会相对较好，至少在全球范围内如此，Google目前也做得不错，即内容安全和防AI注入式攻击。

例如，品牌面向消费者提供大量应用，覆盖具有不同文化背景的地区和群体，就需要审核Agent生成和交互的内容。这类能力确实会吸引客户，尤其是中资出海客户在面对不熟悉的地区和市场时，态度会更加谨慎，可能选择微软较为成熟的体系，使用Azure AI Content Safety等服务保护内容交互。但与整个AI市场大盘相比，这类需求的规模仍然相对较小。

Q:假设企业员工人数不变，但生产环境中的Agent数量增加10倍，例如从1,000个增至10,000个，微软的安全收入会如何变化？哪些收费基本不变，哪些会随调用、扫描或日志量增加？增幅大致如何？

A:大量与Agent相关的产品目前仍按座席数计费，因此只有员工人数增加，或者购买、加购产品的员工座席数增加，才会带来相应的营收增长。单纯由Agent数量扩张带来的安全营收增长相对较少，因为更多Agent带来的消耗主要体现在Token层面。

目前微软的销售方法大致是:假设客户已经属于微软的基本盘，且原有IT系统已经就位，第一步是帮助客户建立Agent，例如使用Fabric IQ和Ontology等方法建设数据系统，再通过Microsoft IQ接入并使用办公等信息；第二步是在使用过程中产生相应消耗。目前核心盈利点仍在Token相关部分。此前Token也多按座席或包月计费，现在已经大量转向按点位或实际消耗计费。

安全审计等产品目前仍更多采用座席计费方式，形成固定投入。企业投资时对固定投入的心理安全感更强，更愿意确定一笔数额明确的预算；如果额外按量收费，客户会担心用量突然增加。尤其在客户已经感受到Token消耗波动的前提下，微软会先让其他部分保持可预测，再推动Token用量增长。

当前，微软会在基础体系上叠加安全管理和运营产品，通过座席方式将客户留在体系内，先促进Agent的Token用量整体增长。未来，一方面出于成本压力，另一方面在基本盘足够稳固后出于Margin等因素考虑，可能将其他按人计费的部分转为按用量计费。当前按人收费的目的是让客户放开使用，鼓励更多消耗。

现阶段，Agent 365、Microsoft Entra ID、Microsoft Purview等绝大部分产品仍以套件或座席计费为主。Microsoft Security Copilot更多按照支撑能力的Capacity，以固定档位或固定开支计费。只有少数扫描Token的服务与Token用量绑定，客户可能更容易接受为Token增加一定比例的安全成本。整体销售逻辑仍是先以较低价格帮助客户建立整套体系，未来可收费的环节还有很多。

Q:目前客户从E3升级到E5，或从E5升级到E7，主要动机是什么？是因为E5到E7折扣很深、只需增加几美元，还是安全或Copilot等功能吸引客户升级？

A:E3升级到E5多数由传统安全需求驱动，例如Endpoint Detection and Response体系，以及设备、服务端和桌面端的一系列安全管控。E3和E5在Office办公系列上的区别不大，主要区别在安全部分，安全仍是核心增长点。升级后，客户的安全覆盖会相对完整，例如DLP也包含在E5中。

E5升级到E7基本由AI驱动，因为E5本身不包含Copilot，而E7包含Copilot。如果确定要使用Copilot，E5加购Copilot的价格已经不低，在此基础上稍微增加一些费用就能升级到E7，并获得一整套完整的安全和管控体系。销售会通过这种方式更多地推动客户转向E7。目前E7无论折扣还是最终价格，都非常接近E5加购Copilot的价格，先将整套能力植入客户体系，这是当前的销售策略。

Q:E7价格非常接近E5加购Copilot的销售策略，是全球范围内都如此，还是仅限于中国区？

A:全球范围内基本都是如此。

Q:E5、E7套餐中是否包含Microsoft Security Copilot额度？客户实际能否消耗掉这些额度，还是更多只是获得使用权，但实际不一定用得完？

A:就目前看到的情况而言，Microsoft Security Copilot的销售和使用情况并不是特别好。它更像是问题发生后的响应工具，而不是事前防范工具。很多客户会质疑，它不能真正帮助客户预防或防护，只能在问题发生后帮助快速定位。因此，在没有出现问题时，客户很难单独购买这款产品，更多是将其打包到更大的项目中。

例如，企业上线大量应用、从E3升级到E5，或有定期输出安全报告的需求时，才会产生相应需求。另一种场景是安全团队能力较弱、人数很少。前面提到聘请PwC开展审计的企业，其全球全职安全人员不到10人，而且分布在几个大洲，南非只有1人。这种情况下，企业会使用Microsoft Security Copilot弥补人员和能力不足。

但很多时候，客户对这款产品必要性的评价并不高，因此目前看到的使用情况并不理想。不过，其整体使用状况尚未经过深入研究。

Q:未来2到3年，AI安全市场中最大的新增支出可能出现在哪些方面？在身份授权、敏感数据保护、Agent运行时防护、审计治理等类别中，哪些会形成较大的新增支出？哪些能力能够单独计费或按用量计费，从而打开收入天花板？

A:随着Agent逐渐扩展，权限管控和敏感数据管控的增长比较确定。很多公司过去没有发现内部存在如此多的敏感数据。相关数据对外网可能是安全的，没有暴露出去，但在内网中存在过度暴露问题。过去这些问题被掩盖，没有真正显现；Agent使问题暴露后，会带来较多变化和支出。这部分主要是现有安全框架下的增长。

从未来框架看，第一，目前整体安全软件基本仍按传统方式开发。至少微软已经上市、达到GA阶段的安全产品，多数还不是基于AI本身进行对抗。但近期在大模型加持下，AI攻击能力快速上升，可能带来很大的安全挑战，而当前安全产品显然有些没有跟上，至少微软在这方面有些落后。

微软大概率需要推出新产品，或彻底改变现有产品形态，在后端增加基于Token的AI对抗能力。这部分营收空间可能会被打开，但也可能需要某些外部事件触发客户消耗。计费方式可能是按用量计费，也可能是购买基础能力包，获得专门的Cyber Security模型或Agent进行对抗。未来的安全产品一定会具备比当前态势感知更强的AI能力。

第二个方向是内部Agent的管控。OpenAI此前发生过Agent从沙盒中逃逸等情况，但OpenAI基本已经完成了大部分必要工作。很多企业尚未发生类似问题，只是因为其Agent能力还没有Frontier Lab推进得那么靠前。目前企业用于防止Agent越权或逃逸的安全产品，仍是传统沙盒、最小权限等控制方式。这些手段是否足够、是否需要新的产品，目前仍需观察。

随着Agent大量走出沙盒并替代人类完成更复杂的工作，每一步能力提升都会进一步提高安全风险。目前实验中已经出现类似情况，大概率会出现新的安全产品来解决这些问题。但现在还没有看到成熟形态，市场似乎仍在传统方案上不断加高围墙。AI对抗能力和更强Agent的内部管控，这两个方向可能带来全新的产品变化。

Q:随着微软自身安全能力提升，它会挤压第三方安全企业的生存空间吗？哪些第三方安全企业提供的功能是微软无意涉足或无法替代的？

A:微软在一定程度上可能会挤压其他安全厂商。过去，第三方安全厂商与微软更多是平替关系；但AI使数据和应用系统之间的连接更加紧密，天然更有利于平台化产品进一步加强能力。因此，微软产品更容易叠加，对其他安全厂商可能产生一定冲击。虽然第三方产品也在持续迭代，尝试利用自身产品提供安全防护，但能够感受到平台型产品会对其基础市场产生影响。

另一方面，也可能有新的厂商崛起。传统大厂在AI安全方面可能行动太慢，或者能力跟不上快速变化，这种可能性很大。至少就微软而言，目前在AI相关安全工具方面有些落后。

Q:在客户实际采购决策中，哪些明确的AI安全需求会促使客户购买Agent 365，或者从E5升级到E7以获得Agent 365？

A:实际而言，无论是项目执行团队，还是发起立项、推动采购决策的团队，最大的诉求都是前面提到的第三项:如何进行事后追查和审计。Agent建设过程中必须有人管理，安全团队需要对Agent带来的问题负责。出现问题后，如何有效定位、查明原因、框定影响范围、找到事故断点等，都是现有安全团队较难处理的问题。

因此，客户更多是基于发现问题和事后处理的诉求采购产品。当然也存在运营层面的需求，例如建立大量Agent后如何计算ROI，但这是其他团队的诉求，最终取决于预算归属和负责团队。

Q:随着AI或Agent能力越来越强，会不会对原有按席位收费的基本盘产生影响？短期内是否已经受到影响？

A:前几年，程序员群体已经出现裁员。微软也裁减了很多产品开发团队和测试团队。今年主要裁减的是产品及产品开发团队，去年裁减的很多是提供工单支持服务的团队。

这一Roadmap与通常所说的AI应用路径很接近:第一步先影响知识型团队和客服型团队；第二步随着开发能力提升，再减少一部分开发团队和测试团队。大体上是这样的逻辑。

Q:微软CEO此前提到，他原以为模型能力增强后，安全或对齐问题会自动解决，但实际并非如此。随着AI模型能力越来越强，从逻辑上看，会对安全防护用量和安全需求本身产生什么影响？对安全市场空间的影响是线性的还是非线性的？

A:这会极大扩张安全需求。传统安全市场过去是相对稳态的市场，漏洞发现等大量依赖企业原有的网络、应用体系和历史积累。现在，无论是恶意攻击者利用漏洞，还是白帽发现漏洞，在AI加持下效率都提高了很多。这意味着传统安全需求会持续提升，攻击者的效率也会不断提高。

过去，攻击者需要锁定有价值的目标。例如，一个钱包里只有3块钱，可能不值得付出攻击成本；但如果AI将攻击成本降到1块钱，而攻击者能够获得3块钱，这项攻击就具有经济可行性。攻击范围因此会变得更加广泛，过去因价值不高而没有被攻击的场景也可能遭受新的攻击，由此会持续产生新的安全需求。

Q:确认一下，E3升级到E5更多是为了获得安全功能，对吗？

A:是的。E3和E5的产品区别主要体现在安全和Enterprise Mobility + Security套件中，Office办公能力相比之下只增加了一部分。虽然微软也会强调增加了其他功能，但升级的主要意义仍在安全上。

Q:目前是否看到更多席位从E3升级到E5？这一升级趋势如何？

A:整体上没有看到特别明显的趋势。原有E3升级到E5主要对应传统安全需求；目前更明显的是E5升级到E7，因为E7推出时间较短，正在形成一定趋势。E3和E5之间的安全能力差距，大概率已经被客户采购的其他安全产品填补，因此客户在此基础上继续升级的趋势可能不会特别明显。
