1. Snowflake消费增长与未来展望

a) Snowflake Q3客户消费增速是否达到此前预期，主要驱动因素是什么？

  • Q3消费表现
  1. Snowflake客户消费同比增速约为 34%，甚至可能达到 35%，略高于此前预期的33%。
  2. 核心SQL、分析、数据仓库及BI等计算业务仍是主要支出来源。
  3. 主要工作负载包括数据迁移、数据工程以及Iceberg开放格式相关应用。
  • AI带来的影响
  1. AI目前主要发挥增长加速作用，尚未形成大规模、直接的收入贡献。
  2. Cortex、Copilot等产品会生成更多查询，从而间接提升计算和数据使用量。
  3. 过去几个季度，AI首先提升了Snowflake平台的重要性；目前已开始出现AI推动Snowflake实际增长的迹象。

b) Snowflake Q4及明年初消费增速如何预测？

  • Q4客户消费同比增速预计约为 35%。
  • 下一季度，即Q1同比增速预计约为 35%至37%。
  • 增长预计将持续并略有加快，主要原因是企业AI应用不断深入，带来更多数据和计算需求。
  • 增长路径将是持续、稳步改善，而不是突然出现“曲棍球棒式”增长或集中追赶效应。
  • 上述判断基于地缘政治及宏观经济环境保持基本稳定的假设。

c) Snowflake的RPO增速是否较上季度加快？

  • 企业客户RPO同比增速仍在加快。
  • 与Q2相比，Q3延续了稳步提升趋势，但尚未出现显著拐点或趋势突变。
  • 整体表现与消费增速一致，属于持续改善而非突然跃升。

2. 企业迁移与AI规模化部署趋势

a) 美国企业向Snowflake迁移的节奏如何？

  • 当前Snowflake的大部分增长仍来自 现有客户渗透率和支出提升，而非大量全新客户一次性迁移。
  • Snowflake客户通常从小规模使用开始，之后逐步：
  1. 迁移更多计算负载；
  2. 使用更多平台模块；
  3. 提升整体支出。
  • 企业正减少平台数量并进行技术栈整合，采购策略由“同类最佳”逐渐转向“最佳套件”。
  • Snowflake等平台持续完善生态系统，有利于承接客户平台整合需求。

b) 企业AI部署何时会明显加速？

  • 企业已经逐渐摆脱POC和试点阶段，开始扩大AI部署规模。
  • 一年前或半年前，企业普遍存在大量分散试点，但缺乏规模化落地；目前已有更多项目进入生产和企业级推广阶段。
  • Snowflake能够提供底层数据基础设施和计算能力，因此会随着AI规模化部署持续受益。
  • AI部署不是从0到1的离散事件，而是逐个工作流、逐个业务流程推进的连续过程。
  • 实施项目正在变得更高效、更快速，企业级全面部署的比例也在提升。
  • 仍需管理预期：AI支出不会突然爆发，而会持续、逐步增长。

c) 企业实施AI面临哪些主要瓶颈？

  • 治理与法规
  1. 欧洲企业需要应对GDPR、欧盟《人工智能法案》等监管要求。
  2. 企业在进入生产环境前，需要完成大量治理、合规和审批工作。
  3. 美国企业同样需要处理数据防泄漏协议、访问规则、智能体身份及授权等问题。
  4. 更高层面的治理还包括Token支出管理和智能体编排。
  • 变革管理
  1. 很多企业错误地将AI视为纯IT项目或纯技术项目。
  2. AI会深入影响运行多年甚至数十年的业务流程，而这些流程中包含大量既有逻辑和隐性知识。
  3. AI项目需要项目管理、变革管理和业务分析师共同参与。
  4. 企业需要获得重新设计流程的授权；如果仅在旧流程上叠加AI，很难释放完整业务价值。
  5. 规模化部署需要高管支持，并以自上而下、覆盖全公司的方式推进。
  6. 许多早期试点缺少进一步推广的正式授权，这是项目无法规模化的重要原因。
  • 数据与IT基础
  1. 企业需要统一、可访问且适合AI使用的数据环境。
  2. 如果基础建设时间过长，会拖慢AI业务落地；如果基础尚未完备就快速实施，也可能因数据分散而停滞。
  3. 数据难度因用例而异：跨多个来源、格式复杂的用例问题更突出；仅依赖单一系统、且智能体已内置于该系统的用例，数据问题相对较小。
  4. 在企业级全面推广过程中，数据基础问题不可避免。

3. Cortex Code的渗透率与收入贡献

a) Cortex Code目前的采用和增长情况如何？

  • Cortex Code（CoCo）已成为Snowflake重要的增长驱动力，既能直接贡献AI产品收入，也能间接带动核心计算用量。
  • CoCo在Snowflake技术栈内部能够感知客户完整的平台环境和代码库，这是其相较Claude Code、GitHub Copilot等通用编程助手的重要优势。
  • 在Snowflake平台内部的核心场景中，CoCo已经证明具备与通用编程助手竞争的能力。
  • CoCo用量每季度增长约 30%至40%，且增速每季度约提升5个百分点。
  • 产品正在持续增加净新账户，并有望较快成为Snowflake客户的标准配置。

b) AI产品占Snowflake产品收入的比例是多少？

  • 核心SQL、分析、数据仓库及BI业务仍占产品收入的大多数。
  • Co-work、CoCo及其他Cortex功能等AI相关产品，预计占直接产品收入的 7%至8%。
  • 上一季度占比约为 6%，再前一季度约为 4%至5%，整体提升速度较快。

c) CoCo对Snowflake整体消费有多大带动作用？

  • 每1单位直接用于CoCo的支出，可能带来约 3至4倍 的相关平台用量增长。
  • CoCo能够提升Snowflake开发者生产效率，加快数据管道和相关功能建设，从而增加底层计算及数据消费。
  • 部分间接用量即使没有CoCo也可能发生，因此无法准确区分净新增贡献。
  • 总体而言，CoCo已经是Snowflake较为可观的收入和用量增长来源。

4. Cortex AI Gateway、模型路由与商业化

a) Cortex AI Gateway当前的客户采用情况如何？

  • Cortex AI Gateway目前尚未产生显著使用量影响，判断产品成效仍为时过早。
  • 产品定位不是单纯增加计算消费，而是将Snowflake打造为覆盖平台内外的 AI控制平面和智能体治理层。
  • 其核心能力包括：
  1. 治理Snowflake内部及外部的智能体；
  2. 路由和控制第三方智能体流量；
  3. 为企业提供智能体编排和治理能力。
  • 产品推出具有较强的战略和信号价值，补齐了Snowflake生态系统中的能力空缺。
  • 预计需要再观察3至6个月，才能判断其是否形成实际采用和使用量贡献。

b) AI Gateway对Snowflake的战略意义和商业模式是什么？

  • AI Gateway主要帮助第三方智能体访问Snowflake数据，提升平台数据的可访问性。
  • 主要商业价值不是直接收取网关费用，而是推动底层Snowflake数据和计算消费。
  • 产品可能产生少量直接收入，但预计规模有限。
  • 为争夺治理层控制权，Snowflake可能对AI Gateway提供较大折扣。
  • 随着更多第三方智能体通过Gateway访问Snowflake数据，平台消费有望间接受益。

c) 模型路由产品目前采用情况如何？

  • 模型路由功能在Q3较晚阶段才推出，目前几乎尚未正式投入生产，企业采用率较低。
  • 该功能可以根据模型成本及具体用例，动态选择合适的底层模型，提高Token使用效率。
  • 随着企业开始重视Token投入产出比，市场对Token监测和成本治理的需求明显提升。
  • 企业也开始更多考虑开源模型和较早代际模型，而非所有场景都使用前沿模型。

d) 模型路由会降低还是提升Snowflake消费？

  • 模型路由可能使Cortex和Co-work的单次Token成本及相关Token收入略有下降。
  • 但成本下降也会降低Snowflake自身成本，并支持更多AI用例落地。
  • 更高的Token效率有望推动更大范围的使用量，因此总体影响预计为正面。
  • 相关效果可能要到 2027年初 才会更加明显。

e) 未来哪类公司可能主导AI编排和治理市场？

  • 当前市场参与者非常多，主要包括：
  1. Salesforce、Workday、ServiceNow等企业软件平台；
  2. UiPath、Automation Anywhere等自动化平台；
  3. 微软、AWS、Google等超大规模云服务商；
  4. Snowflake、Databricks等数据平台；
  5. Palo Alto Networks等专业安全平台；
  6. 原生智能体平台及前沿模型实验室。
  • 目前尚未出现明确领先者。
  • 企业最终选择可能取决于其主要底层平台：
  1. 深度使用Salesforce的客户可能选择Agentforce；
  2. 深度使用微软生态的客户可能选择微软方案；
  3. 深度使用Snowflake的客户可能采用Cortex AI Gateway。
  • 当前编排产品发展略超前于客户实际需求，大部分企业的AI部署仍处于相对早期阶段。
  • 跨平台编排和第三方智能体治理将成为长期需求，但最终市场格局仍高度开放。

5. Snowflake与Databricks的竞争格局

a) Q3两家公司竞争是否进一步加剧？

  • Q3没有出现改变竞争格局的单一重大事件，双方仍处于持续性竞争状态。
  • 客户通常会在Snowflake和Databricks之间二选一，同时大规模使用两者的客户相对较少。
  • 数据和工作负载迁移成本较高，因此客户黏性较强。
  • 两家公司都在扩展生态系统，以：
  1. 增强客户黏性；
  2. 提高单客收入；
  3. 补齐产品功能；
  4. 向对方业务领域延伸。
  • 双方业务重叠度越来越高，但仍各自拥有稳定客户群。
  • 现有客户内部仍有大量数据和计算需求可以挖掘，因此当前竞争并非零和博弈，也不是以大规模争夺对方存量客户为主。

b) Iceberg能力完善是否明显促进Snowflake使用量？

  • Q3 Iceberg能力的变化未在数据中形成明显影响。
  • Iceberg并未成为本季度Snowflake增长的重大事件。
  • 现阶段尚难观察其对客户消费和平台使用量的实质性拉动。

6. MongoDB消费增长与未来预期

a) MongoDB Q3使用量增速是否达到此前22%的预期？

  • MongoDB Q3使用量同比增速约为 21%至22%，与此前22%的预期基本一致。
  • 若按实际数据观察，可能略低至21%，但主要是多年期大额交易确认节奏不均导致的数据波动，而非趋势转弱。
  • 整体增速稳定在20%左右。
  • Atlas增速快于MongoDB整体，是最值得关注的增长来源。

b) MongoDB Q4及明年初增速如何预测？

  • 若平滑大额交易及新旧日历年交界带来的波动：
  1. Q4同比增速预计约为 22%；
  2. Q1同比增速预计约为 23%。
  • 增速预计略有提升，主要由Atlas持续较快增长推动。
  • 上述数字为趋势参考，单季度数据仍可能受到大型合同分布不均影响。

c) MongoDB的RPO增速如何？

  • 专家没有MongoDB本季度RPO的确切数据。
  • 估计RPO同比增速与整体业务增速相近，约为 20%。
  • 暂无证据表明RPO出现明显加速或减速。

7. AI与智能体对MongoDB需求的影响

a) AI工作负载对Atlas贡献有多大？

  • 估计Atlas约有 25% 的业务来自AI工作负载。
  • 但AI工作负载定义较宽，任何具备AI功能的应用均可能被纳入统计。
  • 如果仅计算智能体直接产生的负载，占比可能明显低于25%。
  • AI已经对Atlas增长带来有意义的促进，但尚未出现智能体应用驱动大部分增长的情况。

b) 企业何时会大规模部署智能体应用？

  • 企业智能体采用不会像单一事件一样突然爆发，而是持续、逐步扩大的过程。
  • 从季度维度看，可能还需要 2至4个季度 才会观察到较为显著的阶跃式变化。
  • 即使届时变化更加明显，智能体普及仍会继续推进，不会在某个单一季度完成。
  • 对MongoDB的需求促进预计将逐步体现，而非短期倍增。

8. MongoDB 9.0与Voyage AI产品进展

a) MongoDB 9.0能否推动Q4及后续使用量增长？

  • MongoDB 9.0在Q3末期发布，企业客户升级周期较长，目前尚未反映在使用量数据中。
  • 主要更新包括：
  1. 提升吞吐量；
  2. 加快读取速度；
  3. 加快更新速度；
  4. 扩展加密能力。
  • 性能提升属于符合预期的渐进式优化，而非带来阶跃式变化的颠覆性升级。
  • 扩展后的加密能力可能对受监管行业更有吸引力，并带来新增业务机会。

b) Voyage AI商业化后的增长情况如何？

  • Voyage AI仍处于较早阶段，但产品方向正确。
  • MongoDB将其嵌入数据库和Atlas生态，而非作为独立产品销售，有利于向价值链上游延伸并增强智能体应用相关性。
  • Voyage AI当前基数较小，预计仅为较低的数千万美元规模。
  • 其环比增速可能达到 50%，未来两个季度较容易维持较快增长。
  • 当前增长主要通过Atlas实现，而非依靠独立产品销售。
  • 企业客户采用速度较慢，因此Q3尚未在MongoDB整体数据中形成明显贡献。
  • 中长期看，Voyage AI将促进Atlas增长，并填补MongoDB此前的产品空白。

9. Atlas Infinite与Agent Engine产品评价

a) Atlas Infinite会对MongoDB产生什么影响？

  • Atlas Infinite能够实现 计算与存储分离，是具有较大战略意义的产品更新。
  • 目前该产品可能仅支持AWS。
  • 核心价值包括：
  1. 缩短扩容时间；
  2. 快速提升计算能力和数据容量；
  3. 应对周期性负载峰值；
  4. 减少客户为覆盖峰值而进行的过度资源配置。
  • 短期内，产品可能降低客户闲置存储支出，因此对MongoDB消费并非完全利好。
  • 长期看，弹性能力有助于MongoDB赢得更多负载波动较大的工作负载，并与Postgres等平台竞争。
  • 总体预计产生净正面影响，但兑现需要时间，且取决于能否获取原本可能流向其他平台的工作负载。

b) Agent Engine的市场前景如何？

  • Agent Engine代表MongoDB向智能体基础设施和价值链上游拓展。
  • 产品尝试将状态、记忆、检索、权限及统一执行整合起来，本质上属于智能体编排与治理能力。
  • MongoDB靠近数据层，这是其优势之一，但并非独有优势。
  • Agent Engine需要与以下产品和平台竞争：
  1. Microsoft Foundry；
  2. AWS Bedrock AgentCore；
  3. Google相关平台；
  4. Databricks Agent Bricks；
  5. 其他AI平台及智能体框架。
  • 企业更可能优先选择主要云服务商或AI平台供应商提供的编排层，而非数据库厂商的方案。
  • MongoDB可能通过智能体记忆等功能获得一定收入，但智能体运行时和统一编排能力面临较大竞争压力。
  • Agent Engine大概率不会成为默认的企业智能体基础设施，可能最终是一款边缘性产品。

10. MongoDB管理层变化与竞争风险

a) CRO离职是否影响客户采购和公司运营？

  • CRO突然离职对MongoDB外部信誉和市场观感造成了一定负面影响。
  • 其转投Meta可能使外界认为MongoDB对高管人才的吸引力不足，且离职时点较为不利。
  • 从运营角度看，目前未发现明显影响，也没有迹象表明客户因此延迟或取消采购。
  • 该高管更偏向平台和销售职能，而非核心运营管理，因此单次离职不构成重大运营风险。
  • 后续需要观察管理团队或工程团队是否出现更多高级人员离职；若出现连续离职，才可能形成实质性风险信号。
  • 在没有更多高管离职的情况下，本次事件更接近短期噪声。

b) Snowflake、Databricks及Postgres是否会加大MongoDB竞争压力？

  • MongoDB面临两类主要竞争：
  1. Snowflake、Databricks、Lakehouse及Postgres等数据平台向运营数据库领域延伸；
  2. Google等超大规模云服务商进入MongoDB市场，例如Google通过Firestore提供MongoDB兼容能力。
  • 这些竞争对手拥有更广泛的平台能力，可以提供迁移方案、产品捆绑及统一采购优惠。
  • 当前数据尚未显示竞争对MongoDB造成特别显著的实际冲击。
  • 但从中长期看，平台型竞争者可能利用生态、捆绑和迁移能力持续压缩MongoDB空间，是MongoDB需要重点关注的风险。
