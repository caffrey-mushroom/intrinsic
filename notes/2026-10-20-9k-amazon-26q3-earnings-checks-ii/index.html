亚马逊AWS Q3业务与AI基础设施专家访谈纪要

1. AWS Q3支出趋势与增长驱动

a) AWS客户Q3支出相较Q2有何变化？

  • Q2客户支出已经明显加速，增长主要来自AI算力、推理以及传统云工作负载。
  • 受访者提到，AWS此前公布的收入约为420亿美元，同比增长接近35%；预计Q3增长势头将延续，增幅可能达到35%至40%。
  • Q3最大的结构性变化，是客户开始从小规模AI试点转向生产应用，支出范围也由单纯的计算资源扩展至存储、数据库和网络等配套服务。
  • 上述增速判断主要为受访者的方向性预期，并非AWS官方指引。

b) 哪些行业和AI用例正从试点转向生产？

  • 积极推进AI生产化的客户主要包括：
  1. 金融服务企业；
  2. 科技公司；
  3. 大型零售商。
  • 增长较快的生产用例包括：
  1. 客户服务自动化，如处理常规咨询的智能体；
  2. 编码辅助，如代码生成、问题排查和开发支持；
  3. 企业内部知识搜索，员工可基于内部文档进行问答；
  4. IT自动化，包括故障排查和事件管理。
  • 上述场景能够较清晰地衡量生产率提升，因此企业更容易论证扩大部署和支出的合理性。
  • 企业正从少数团队测试，逐步转向将AI工具整合进日常运营，从而形成更加稳定、持续的推理需求。

c) Q3增长来自少数大客户，还是企业客户的普遍采用？

  • 两类客户共同推动AWS AI业务增长：
  1. 少数超大型AI客户贡献了大量训练需求和长期容量承诺；
  2. 更广泛的企业客户推动推理和生产应用普及，带来多元化、经常性的云消费。
  • Anthropic是AWS最典型的大型训练客户，尤其在Trainium方面投入规模较大。
  • OpenAI未来也可能成为重要的容量需求来源。
  • Adobe、Salesforce等企业会贡献模型开发、定制和企业AI需求，但其训练容量规模无法与Anthropic相比。

d) Q3内部月度支出呈现怎样的趋势？

  • AI支出预计从7月至9月持续增长，月环比增幅可能处于低至中个位数区间。
  • 7月和8月整体相对稳定，AI算力和推理需求保持强劲。
  • 非AI传统云支出相对偏弱：
  1. 7月和8月可能基本平稳；
  2. 9月可能温和回升；
  3. 传统云并未呈现所有类别同步显著加速的趋势。
  • 如果9月增速出现明显提升，新增计算产能上线和现有客户利用率提高，可能是比企业AI采用更重要的短期驱动因素。
  • 企业AI采用也在增加，但其推进速度通常更加渐进。
  • 受访者没有经过核实的AWS月度支出数据，因此上述判断属于趋势性估计。

2. AI工作负载结构与增长趋势

a) AWS AI工作负载中，训练和推理分别占多少？

  • 受访者对AI计算资源消耗的粗略拆分为：
  1. 训练：约40%至50%；
  2. 企业推理：约30%至35%；
  3. 其他推理：约20%至25%。
  • 其他推理主要包括消费级AI应用和模型提供商服务。
  • Anthropic等大型客户使训练目前仍是重要需求来源，但推理占比预计将在2027年前持续提高。
  • 以上数据为受访者估算，并非AWS官方披露的工作负载结构。

b) 企业推理是否是增长最快的工作负载？

  • 推理整体增速预计快于训练，企业推理尤其突出。
  • 受访者粗略估计：
  1. 推理需求年增速约为60%至100%；
  2. 训练需求年增速约为30%至50%。
  • 训练仍占据较大的绝对计算需求，但推理正在向更多企业、行业和应用场景扩散。

c) 训练需求是否仍主要来自Anthropic？

  • Anthropic仍是AWS训练需求的最大驱动因素之一，尤其是在Trainium部署方面。
  • 增量需求也来自更广泛的模型开发生态，包括：
  1. Cohere；
  2. AI21 Labs；
  3. Stability AI；
  4. Hugging Face生态中的相关客户。
  • 企业侧还包括Salesforce、Adobe等针对特定商业场景开发和定制模型的公司。
  • 这些二线模型开发商和企业客户可以贡献增量需求，但短期内训练容量规模仍远低于Anthropic。

d) 未来训练需求将由哪些客户驱动？

  • 未来12至18个月，大部分新增容量需求预计仍由大型战略客户推动。
  • Anthropic在2027年前预计仍是Trainium需求的最大驱动因素。
  • OpenAI可能成为另一个重要贡献者，尤其是在相关容量承诺逐步扩大的情况下。
  • 长期来看，随着更多模型开发商采用Trainium，训练需求来源将逐渐多元化。

e) Anthropic是否会长期以AWS为主要基础设施合作伙伴？

  • 受访者不了解Anthropic具体的工作负载分配比例，但预计AWS和Trainium未来几年仍将是其基础设施战略的重要组成部分。
  • 主要原因包括：
  1. Anthropic已经作出大规模、长期的容量承诺；
  2. 已投入大量工程资源针对Trainium优化大型模型；
  3. 短期内快速迁移会产生较高技术和运营成本。
  • Anthropic仍可能继续使用其他计算服务商，以保持基础设施灵活性并降低单一供应商依赖。

3. Bedrock竞争力与模型采购方式

a) 企业为什么选择Bedrock，而不是Azure或Google Cloud？

  • 客户选择Bedrock的核心原因，是可以在不自行管理全部AI基础设施的情况下，直接利用现有AWS体系使用多种模型。
  • Bedrock的主要优势包括：
  1. 与既有AWS计算、数据、安全和计费体系自然整合；
  2. 可连接S3、Lambda及现有数据服务；
  3. 沿用客户熟悉的访问控制和安全机制；
  4. 支持不同模型之间灵活切换，降低单一模型供应商锁定风险；
  5. 便于统一治理、采购和成本管理。
  • 竞争对手的相对优势分别为：
  1. Microsoft依托Microsoft 365、Teams、GitHub和Copilot，更容易切入员工日常工作流；
  2. Google在数据分析和Gemini模型方面较强；
  3. AWS则在底层基础设施、企业系统集成和模型灵活性方面更具竞争力。
  • 整体来看，微软在AI分发和员工入口方面更有优势，AWS在企业基础设施和多模型平台方面更强。

b) Bedrock在Q3有哪些重要改进？

  • Q3的重点由模型试验进一步转向生产部署。
  • Agent Core等能力可帮助客户：
  1. 管理大规模智能体；
  2. 控制权限；
  3. 监控运行性能；
  4. 管理部署成本；
  5. 提高企业级AI应用的可靠性和可治理性。
  • 小规模AI试点相对容易，但如果企业需要安全运行数百个智能体，对权限、监控、成本和治理的要求会显著提高。
  • Bedrock的核心价值正在从“帮助客户测试模型”转向“帮助客户稳定运行生产级AI应用”。

c) 客户为什么通过Bedrock使用Claude，而不是直接采购Anthropic服务？

  • 标准按Token计费模式可能较为相似，定价并不是最主要的决策因素。
  • Bedrock的主要吸引力包括：
  1. 将Claude纳入现有AWS安全和权限体系；
  2. 使用统一账单；
  3. 相关支出可能计入客户现有AWS消费承诺；
  4. 与企业现有数据和应用深度集成；
  5. 使用AWS托管推理服务；
  6. 可在Claude与其他模型间灵活切换。
  • 对于已在AWS上支出数百万美元的大型企业，采购便利性、治理和系统整合通常比单纯的Token价格更重要。
  • 如果客户希望第一时间使用Claude最新功能，或更偏好Anthropic原生开发工具，则直接采购Anthropic服务可能更具吸引力。

d) 未来企业会通过云平台采购模型，还是直接向模型厂商采购？

  • 大型企业预计仍更倾向通过Bedrock等云平台采购，特别是在重视安全、合规、统一治理和现有系统集成的情况下。
  • 开发者和AI原生公司可能更倾向直接使用Anthropic或OpenAI，以更快获得新功能和更强的控制权。
  • 长期来看，云平台渠道与模型厂商直连渠道可能形成更均衡的分布，但大量支出仍可能留在AWS等云生态系统内。

4. 模型厂商的多云策略与算力分配

a) Anthropic和OpenAI如何分配基础设施支出？

  • Anthropic和OpenAI均在推动计算资源多元化，但策略存在差异。
  • Anthropic方面：
  1. AWS仍是主要训练合作伙伴，尤其是在Trainium领域；
  2. Google凭借TPU正成为重要的第二供应商；
  3. Anthropic还会通过其他合作伙伴使用NVIDIA基础设施；
  4. 到2027年，Google所占份额可能明显提升。
  • OpenAI方面：
  1. Microsoft仍是主要合作伙伴；
  2. 同时扩大与Oracle、AWS、CoreWeave和Google的合作；
  3. 核心策略是尽可能获得更多算力，并降低对单一供应商的依赖。
  • 决定支出分配的主要因素包括：
  1. 算力是否能够按时交付；
  2. 单位算力成本；
  3. 芯片性能；
  4. 部署速度；
  5. 可获得的总容量。
  • 对超大规模客户而言，算力的可获得性往往比单纯的价格优惠更重要。

b) AWS在产能有限时如何分配算力？

  • AWS会优先考虑作出大规模、长期承诺的客户。
  • 由于战略合作关系以及Anthropic对Trainium的工程投入，Anthropic自然拥有较高优先级。
  • 但Anthropic不会自动获得所有算力的绝对第一优先权，AWS还会综合考虑：
  1. 合同约定的容量；
  2. 工作负载要求；
  3. 预期利用率；
  4. 部署可产生的收入；
  5. 客户结构多元化需求。
  • AWS仍会为其他模型开发商和企业客户保留容量，避免过度依赖单一AI客户。

5. 数据中心容量与产能释放计划

a) AWS过去一年新增了多少电力容量？

  • 受访者估计，AWS在2025年新增约3.9至4吉瓦电力容量。
  • 其中Q4新增容量超过1.2吉瓦。
  • 这些数据为访谈中的估计值，并非正式季度容量指引。

b) 未来12个月预计新增多少容量？

  • 到2027年底，AWS的总体电力容量目标大致是实现翻倍。
  • 未来12个月可粗略按每季度新增1至1.5吉瓦进行规划假设，即全年约4至6吉瓦。
  • 实际新增容量不会均匀释放，主要受到以下因素影响：
  1. 公用事业通电进度；
  2. 数据中心调试；
  3. 服务器及设备交付；
  4. 大型园区建设节奏。
  • 某些季度新增量可能明显低于预期，而大型园区投产时可能出现容量集中跃升。

c) 哪些园区将贡献主要新增容量？

  • 最重要的项目之一是印第安纳州的Project Rainier，主要用于Anthropic的Trainium工作负载。
  • 印第安纳州北部还在进行更广泛的扩建，Amazon已宣布另有约2.4吉瓦容量。
  • 其他重点扩建区域包括：
  1. 北弗吉尼亚州；
  2. 密西西比州；
  3. 宾夕法尼亚州；
  4. 路易斯安那州。
  • 这些项目不会同时投产，实际容量释放取决于通电、调试和设备到位时间。

d) 2026年底前是否会有大规模容量交付？

  • 受访者预计2026年会有可观容量释放，尤其集中在Q4。
  • Project Rainier可能是最大的贡献项目，目标是在年底前部署接近1吉瓦的Trainium 2和Trainium 3容量。
  • 这一判断属于受访者预期，具体交付节奏仍存在工程和公用事业方面的不确定性。

e) 新产能投产后多久可以转化为收入？

  • 如果服务器已经安装、客户已经作出容量承诺，新产能投产后几乎可以立即开始产生收入。
  • 对Anthropic等大型已承诺AI工作负载：
  1. 最初几周即可产生可观收入；
  2. 利用率预计在1至3个月内逐步提升。
  • 对普通企业客户使用的容量：
  1. 更广泛的利用率提升可能需要3至6个月；
  2. 但这不等于完整收回资本投入所需的时间。
  • Q4新增的约1至1.2吉瓦容量，受访者确认指的是已经投产、可被模型客户用于训练的容量。

6. 开放模型、Nova与AWS模型经济性

a) 企业是否在增加开放权重模型的生产部署？

  • 数据保护、控制权和可移植性是企业采用开放权重模型的重要原因。
  • 多数开放模型工作负载预计仍会运行在云端，而不是本地部署。
  • AWS客户的主要部署方式包括：
  1. 通过Bedrock进行托管推理；
  2. 通过SageMaker和EC2获得更强的定制及部署控制。
  • 本地部署更适用于：
  1. 高度敏感的数据；
  2. 严格的数据驻留要求；
  3. 规模大且需求可预测、本地部署经济性更高的推理负载。
  • 开放模型并不是保护数据的唯一方式，Bedrock同样可以为Claude等闭源模型提供隐私和安全控制。
  • 开放模型的核心优势在于控制权、可移植性和定制能力；Bedrock的优势则是运营简便和系统集成。

b) 开放模型或AWS自有模型是否更有利可图？

  • AWS自有模型如Nova可能具备更高的潜在利润率，因为AWS同时掌控模型和基础设施，无须向第三方模型提供商支付费用。
  • 开放权重模型也具有吸引力，特别是可以在AWS自研硬件上高效运行时。
  • Claude等第三方模型虽然涉及授权费或收入分成，但可能创造更高收入，因为客户愿意为更强的模型能力付费。
  • 因此：
  1. AWS自有模型可能拥有更高利润率；
  2. Claude等领先模型可能带来更高总收入和总利润；
  3. 最终经济性取决于客户采用规模和资源利用率。
  • 亚马逊未披露不同模型的实际利润率，相关判断均为受访者估计。

c) Nova的战略定位是什么？

  • Nova既服务于亚马逊内部业务，也面向外部企业客户。
  • 内部应用包括Alexa、广告、零售和亚马逊自身运营。
  • 当前较有竞争力的外部场景包括：
  1. 客户支持；
  2. 日常大规模推理；
  3. 相对简单的智能体应用；
  4. 更强调速度和成本、而非最高推理能力的任务。
  • 亚马逊并未将Nova仅定位为低智能模型，还在通过Nova Pro、Premier和Nova Forge推动复杂推理及企业定制。
  • Nova的长期战略目标包括：
  1. 将更多模型经济利益保留在AWS内部；
  2. 提升推理业务利润率；
  3. 为客户提供同时使用AWS自有模型和Claude的理由。

7. Trainium采用、竞争优势与部署结构

a) Trainium目前主要用于训练还是推理？

  • Trainium在训练和推理领域的采用都在加速，但客户结构存在明显差异。
  • 训练方面：
  1. Anthropic仍是占主导地位的大规模客户；
  2. 据受访者所述，Anthropic使用超过100万颗Trainium 2芯片支持训练和推理；
  3. Poolside、Decart和Uber也在采用Trainium，但规模小得多；
  4. OpenAI预计从2027年开始成为重要贡献者。
  • 推理方面：
  1. 客户覆盖范围比训练更广；
  2. AWS表示Bedrock的大部分推理工作负载已运行在Trainium上。
  • 受访者估计，当前Trainium算力使用结构为：
  1. 训练约50%至60%；
  2. 推理约40%至50%。
  • 到2027年，推理增速预计更快，并可能成为规模更大的工作负载类别。
  • Trainium扩大应用的主要障碍仍是软件兼容性，新版PyTorch支持有望降低迁移难度。

b) 客户为什么选择Trainium？

  • 成本是客户选择Trainium的首要原因。
  • AWS宣称Trainium 2相较其他方案可实现30%至40%的性价比提升。
  • 对经过充分优化的工作负载，客户实际成本节省的合理目标约为20%至40%。
  • 第二个关键原因是容量：
  1. NVIDIA GPU价格较高且供应紧张；
  2. Trainium提供了另一条获取大规模AI算力的路径；
  3. 对年度AI算力支出达到亿美元级别的客户，成本和容量优势尤其重要。
  • 其他优势包括：
  1. 与现有AWS基础设施集成；
  2. 容量供应相对可靠；
  3. 新版PyTorch支持降低代码迁移和适配成本。
  • 客户最终是否切换，仍取决于Trainium针对具体模型的实际性能和优化效果。

c) Trainium与GPU的性能如何比较？

  • Trainium 2的算力约为第一代Trainium的4倍。
  • Trainium 3相较Trainium 2最高可达到约4.4倍性能提升。

  1. 客户获得更低的单位算力成本；
  2. AWS减少对高溢价NVIDIA硬件的依赖；
  3. 自研芯片有助于提升基础设施利润率。
  • 对客户而言，在工作负载充分优化的情况下，支出可能降低约20%至30%。

  • 相应的权衡是：
  1. AWS向客户收取的单位算力价格可能下降；
  2. 单位算力收入可能减少；
  3. 若降价推动使用量和利用率上升，总收入和总利润仍可增长。

  • 与Anthropic等模型提供商之间的授权费或收入分成，会分流部分经济利益。
  • 客户接入和技术支持会产生费用，但工作负载规模化后，其影响通常低于利用率和硬件成本。
