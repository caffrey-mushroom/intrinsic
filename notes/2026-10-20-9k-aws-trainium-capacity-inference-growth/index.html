摘要

AWS 第三季度增长预期为 35% 至 40%，原因是生产级 AI 采用在主要训练客户之外扩展；推理需求可能每年增长 60% 至 100%，并在 2027 年前获得更高份额；AWS 在未来 12 个月可能新增 4 至 6吉瓦容量，Project Rainier 支持年末近 1 吉瓦的 AWS Trainium2 与 AWS Trainium3 容量；AWS Trainium 性价比优于 NVIDIA GPU 约 30% 至 40%，可降低客户成本并将AWS 运营利润率提升约 3 至 4 个百分点

要点

  1. AWS 第三季度增长预计约为 35% 至 40%，此前第二季度同比增长近 35% 并实现约 420 亿美元收入，原因是企业将 AI 应用从试点推向生产并将支出从计算扩展到存储、数据库和网络
  2. 估计的 AI 计算构成为训练占 40% 至 50%、企业推理占 30% 至 35%、其他推理占 20% 至 25%，而推理需求预计每年增长 60% 至 100%，相比之下训练增长为 30% 至 50%，推理可能在 2027

年成为更大的一类工作负载

  1. 预计 AWS 在未来 12 个月将新增大约 4 至 6 吉瓦容量，Project Rainier 可能是最大的贡献者，目标是在年末实现近 1 吉瓦的 AWS Trainium2 与 AWS Trainium3 容量；已承诺的 AI

容量可以在数周内创造可观收入并在一至三个月内提升利用率

  1. Anthropic 仍然是大型 AWS Trainium 客户中的主导者，拥有超过一百万枚 AWS Trainium2 芯片支持 Claude 的训练与推理，而 OpenAI 可能从 2027

年开始成为另一个主要贡献者，并且大型战略客户预计将在未来 12 至 18 个月推动大部分新增容量

  1. AWS Trainium2 在性价比上大约优于 NVIDIA GPU 实例 30% 至 40%，对优化良好的工作负载估计可为客户节约 20% 至 40%，更广泛部署可能为 AWS 带来约 3 至 4

个百分点的运营利润率优势，尤其是在推理方面

  1. Amazon Bedrock 正通过 Amazon Bedrock AgentCore、企业治理、AWS 托管推理以及与 Amazon S3 和 AWS Lambda 的集成向生产部署转变，而 Amazon Nova

旨在将更多模型经济性保留在 AWS 内部并改善推理利润率；2027 年资本支出估计为 2,800 亿至 3,200 亿美元，而 2026 年计划大约为 2,200 亿美元

Q:与第二季度相比，客户在第三季度对 AWS 的总体支出如何？

A:据我所见，客户支出在第二季度明显加速，尤其是在 AI 计算、推理和传统工作负载方面。AWS 的收入同比增长近 35%，达到大约 420 亿美元，这是大约两个月前宣布的数据。对于第三季度，我预计这种势头将继续，增长可能在大约 35% 到40% 之间。

最大的变化可能是客户正在超越 AI 试点，进入生产阶段。因此，他们可能不仅在计算上花费更多，也会在存储、数据库和网络上增加投入。

Q:能否举例说明哪些类型的企业正在从试点转向生产，并指出哪些用例或领域增长最快？

A:金融服务公司、科技公司和大型零售商是更为积极的采用者。最明确的例子包括客户服务自动化、编码辅助和内部知识检索。公司正从用小团队测试这些应用转向将其集成到日常运营中，这推动了更稳定的计算消耗和更大的推理需求。

主要用例包括处理常规询问的客户支持代理和帮助开发者编写或排查代码的编码助手。我们也看到企业搜索，使员工可以在内部文档中提问，以及用于故障排查和事件管理的 IT自动化。公司能够在这些领域衡量生产力提升，这有助于证明将这些应用投入生产的合理性。

Q:增长是由若干大客户推动，还是有更广泛的企业客户正在进入生产环境的趋势？

A:两者兼而有之。相对少数非常大的 AI 客户尤其在训练方面推动了大量的计算需求。同时，更广泛的企业采用正在各行业展开，特别是在推理和生产级 AI 应用方面。大型客户推动最大的容量承诺，而更广泛的企业群体带来更分散的消费。

对于 AWS 而言，Anthropic 可能是最清晰的例子，特别是因为其对 AWS Trainium 的大规模承诺。OpenAI 也是另一个主要客户，特别是随着其在 AWS 的容量增长。Adobe 和 Salesforce 对企业级 AI需求也很重要，但在 AWS 训练容量方面，我不会把它们与 Anthropic 放在同一类别。

Q:在第三季度进展过程中，支出是加强了还是削弱了？九月与七月和八月相比如何，支出是否继续增长？

A:第三季度支出持续增长，尽管总体情况可能比第二季度更为参差。七月和八月看起来相对平稳，AI 计算和推理保持强劲，而传统的 Claude 支出则出现了一些较弱的信号。我不会说九月在各方面都有显著加速。

在最初将问题理解为指向十二月的前提下，我会预计 AI 支出保持强劲，并可能略高于七月或八月。传统企业支出可能更为不稳定，受年终预算周期影响。我没有经过核实的按月 AWS 支出数据，所以这更多是方向性预期，而不是测量得到的趋势。

Q:为澄清，问题是关于九月相对于七月和八月以及季度内的趋势。月度模式是典型的还是更不均匀？能否将 AI 支出与非 AI 支出分开——例如 AI 支出是否持续快速增长，而非 AI 工作负载更为波动？

A:我预计 AI 支出会持续增长，月环比可能在低到中单位数，因为随着更多容量可用。非 AI 的 Claude 支出在七月和八月稍显平缓，九月可能随着企业活动恢复出现小幅回升。总体而言，目前 AI 可能是更强的增长驱动因素。

Q:如果九月支出加速，主要驱动因素是新增容量的释放，还是企业只是单纯在 AI 上投入更多？

A:两者都有，但我会把更多归因于新增容量上线，尤其是针对大型 AI 工作负载。企业采用在推动方面有贡献，但它通常更渐进。如果九月出现明显加速，新上线的计算容量以及现有客户更高的利用率会解释更多的增长。

Q:能否提供 AI 工作负载的大致构成，包括训练、企业级 AI 推理和其他推理所占的百分比？

A:这只能是一个粗略划分，因为我无法看到确切百分比。我估计 AI 计算的构成大致为 40% 到 50% 的训练，30% 到 35% 的企业推理，以及 20% 到 25% 的其他推理，包括面向消费者的 AI 应用和模型提供方服务。

训练仍然是主要驱动因素，因为有像 Anthropic 这样的客户，但我预计推理将在 2027 年前获得更大份额。这些是基于观察到的计算消耗给出的方向性估计，而非 AWS 的官方工作负载拆分。

Q:推理的增长是否快于另外两个细分，特别是与训练相比？

A:推理增长更快，尤其是企业级推理。我大致估计推理需求的年增长在 60% 到 100% 之间，而训练约为 30% 到 50%。训练仍然占据可观的计算需求份额，但推理正在更多客户和更多应用中扩展。

Q:在训练工作负载方面，大多数仍来自 Anthropic，还是你看到来自其他、可能是二线模型实验室的额外需求？

A:Anthropic 仍然是 AWS 训练需求的最大推动者之一，尤其是通过其 AWS Trainium 的部署，但需求不再局限于 Anthropic。其他模型开发者以及为特定应用微调模型的公司也在贡献需求。Anthropic可能主导非常大的训练承诺，而较小的客户则提供更多增量需求。

例子包括 Cohere、AI21 Labs、Stability AI、Hugging Face 以及更广泛的模型开发生态系统。在企业方面，像 Salesforce 和 Adobe 这样的公司也在开发或定制用于特定业务应用的模型。在 AWS训练容量方面，我不会把它们与 Anthropic 相提并论。我无法看到它们各自的 AWS 支出情况，但它们仍然是重要的贡献者。

Q:展望未来，你预计大多数训练增长会继续来自 Anthropic，还是其他模型开发者会贡献更多？

A:我预计 Anthropic 在近期内仍将是 AWS Trainium 需求的最大驱动者，特别是在 2027 年之前。OpenAI 如果其承诺加速，也可能成为另一个主要贡献者。从更长期看，随着其他模型开发者采用 AWS Trainium，增长应会更为多元化。然而，在未来 12 到 18 个月内，我仍然预计大型战略客户会驱动大部分增量容量。

Q:你是否了解 Anthropic 如何分配其训练工作负载？它会继续依赖现有的 AWS 安排，还是在未来几年会在其他地方寻求计算容量？

A:这是推测性问题，我没有 Anthropic 具体工作负载分配的可见性。我预计在未来几年内，AWS 和 AWS Trainium 将继续是其基础设施策略的重要组成部分。Anthropic 已经做出重大长期承诺，并在针对 AWS Trainium 优化大型模型方面投入了大量工程努力。

我不认为 Anthropic 会很快离开，尽管它可能会继续使用其他计算提供商以保持灵活性。

Q:为什么有些客户选择 Amazon Bedrock，而另一些选择 Azure 或 Google Claude？与其他 AI 云相比，Amazon Bedrock 有哪些优势，第三季度有哪些改进或新增功能？

A:客户主要选择 Amazon Bedrock 是因为他们已经在使用 AWS，希望使用 AI 而无需自行管理所有基础设施。他们可以在现有的容量、安全、数据和计费安排下访问 Claude 及其他模型。微软通过 Microsoft 365、GitHub 和 Copilot 拥有强大的优势，而 Google 在数据分析和 Gemini 模型方面尤为强劲。对于希望在不同模型之间保持灵活而不被单一供应商绑定的客户来说，AWS 具有吸引力。

第三季度尤其重要，因为 Amazon Bedrock 更加聚焦于生产部署。例如，通过 Amazon Bedrock AgentCore，客户获得了更好的工具来管理 agents、控制权限、监控性能并管理成本。运行一个小型的 AI试点相对容易，但在企业范围内安全地运行数百个 agent 则复杂得多。关键的改进在于 AWS 正在帮助客户从模型实验转向将可靠的 AI 应用作为日常业务的一部分来运行。

Amazon Bedrock 最大的优势是它与 AWS 环境的自然契合。许多大型企业已经在 AWS 上运行应用、数据库和安全系统，因此采用 Amazon Bedrock 不需要完全重建新的环境。他们可以将其连接到 Amazon S3、AWS Lambda 和现有的数据服务，同时保留熟悉的安全和访问控制。

Q:按照这个逻辑，微软是否具有重大优势，因为许多大型企业已经使用 Microsoft 365、Office 和 Windows？

A:微软确实有显著优势，尤其是在企业用户中。Microsoft 365、Teams 和 GitHub 让它直接接触员工每天使用的工作流，从而更容易通过 Copilot 引入 AI。AWS 在已有基础设施和应用运行于 AWS的客户中可能处于更强的位置，但微软在员工层面具有更自然的切入点。我会说微软在 AI 的分发方面占优，而 AWS 在底层基础设施和模型灵活性方面仍然非常有竞争力。

Q:如果客户想使用 Claude，什么因素会促使它通过 Amazon Bedrock 而不是直接从 Anthropic 购买访问？在定价、与现有 AWS 承诺相关的好处，或其他影响该选择的因素方面有何差异？

A:定价很重要，但可能不是主要原因。无论客户是直接通过 Anthropic 还是通过 Amazon Bedrock 访问 Claude，标准每 token 的定价大致相似。更大的优势在于，已经在 AWS 上花费数百万美元的公司可以将Claude 纳入其现有的 Claude 环境，使用相同的安全控制、合并计费，并有可能将该支出计入其 AWS 承诺。这对大型企业尤其具有吸引力。

Amazon Bedrock 还提供 AWS 托管的推理、更强的与现有数据的集成，以及在 Claude 与其他模型之间切换的灵活性。当客户希望立即获得最新的 Claude 功能或更喜欢 Anthropic 的原生开发者工具时，直接通过Anthropic 访问可能更有吸引力。因此，相较于单纯的定价，Amazon Bedrock 在企业集成、治理和采购便利性方面具有更大优势。

Q:未来，客户会更倾向于直接从 Anthropic、OpenAI 等提供商获得模型服务和 API，还是通过像 Amazon Bedrock 和 Azure 这样的 Claude 平台获得？

A:大型企业在安全、合规性以及与现有 AWS 系统集成方面有要求时，会继续倾向于 Amazon Bedrock。开发者和以 AI 为原生的公司则可能更愿意直接访问 Anthropic，因为他们可以更快获得新功能并行使更多控制权。

一个有趣的发展是 Claude 在 AWS 上的平台，这可以在保留 AWS 计费和承诺的同时为客户提供 Anthropic 的原生功能。因此，我预计 Amazon Bedrock 与 Anthropic服务之间会出现更为均衡的分布，尽管大部分支出可能仍然留在 AWS 生态体系内。

Q:对于像 Anthropic 和 OpenAI 这样的模型提供商，它们在 AWS 与其他基础设施提供商之间如何分配支出？是什么驱动了这种分配，它们的策略有何不同？尤其是，能否解释下 OpenAI 的策略？

A:Anthropic 和 OpenAI 都在多个提供商之间分配计算支出，但它们的策略不同。对 Anthropic 来说，AWS 仍然是主要的训练合作方，特别是通过 AWS Trainium。Google 也正在成为重要的第二提供方，依靠其TPU 容量，而且 Anthropic 也通过其他合作方使用基于 NVIDIA 的基础设施。我不会声称精确的支出比例，但 AWS 和 Google 显然是两大主要关系，且到 2027 年 Google 的份额可能会显著增加。

OpenAI 的策略更加分散化。微软仍然是一个重要合作方，但 OpenAI 也在扩大与 Oracle、AWS、CoreWeave 和 Google 的合作。其策略似乎是尽可能多地 확보计算资源，而不依赖于单一供应商。

驱动分配的最大因素包括容量可用性、单位计算成本、芯片性能和部署时机。在这种规模下，即便某个提供商在价格上有优势，如果该提供商无法在客户需要时交付所需容量，那么该价格优势的价值也十分有限。

Q:AWS 如何在模型提供商之间分配有限的计算容量？鉴于与 Anthropic 的更深入合作，Anthropic 是否被优先考虑而 OpenAI 接收剩余容量，或是采用了不同的方法？

A:AWS 会优先考虑拥有大型或长期承诺的客户，Anthropic 自然会因为战略关系、AWS 的投资以及 Anthropic 在 AWS Trainium 上的承诺而位列靠前。然而，这并不意味着 Anthropic会对所有容量享有优先访问权。AWS 还会考虑已签约的容量、工作负载需求、预期利用率以及每个部署可以产生的收入。

AWS 还会寻求为其他企业客户保留容量，并避免对单一 AI 开发者产生过度依赖。

Q:AWS 在过去两个季度新增了多少容量，未来 12 个月又可能新增多少容量？如果可能，最好按季度给出估算。

A:AWS 在 2025 年大约新增了 3.9 到 4 吉瓦的电力容量，其中单是第四季度就超过 1.2 吉瓦。更广泛的目标是到 2027 年年底将总电力容量大约翻一番。对于未来 12 个月，我会将每季度大约 1 到 1.5吉瓦的新增容量作为粗略规划假设，并可能在更大规模的 AI 园区上线时加速。

这并非一份披露的季度预测。由于公用事业通电、设备投运、设备交付以及容量可用性的时序等瓶颈，实际新增将呈现不均衡。

Q:按每季度 1 到 1.5 吉瓦计算，年度总量将是 4 到 6 吉瓦。更有可能接近 4 还是 6 吉瓦？决定实际数字的因素有哪些？是否主要与某个大型园区有关？

A:位于印第安纳的 Project Rainier 将是最大的贡献者之一，特别是针对 Anthropic 的 AWS Trainium 工作负载。印第安纳北部也在更大范围内扩展，亚马逊已宣布另有 2.4吉瓦的计划容量。除印第安纳外，主要扩展区域还包括北弗吉尼亚、密西西比、宾夕法尼亚和路易斯安那。

并非所有这些项目都会立即交付算力。每季度1到1.5吉瓦的估算是一个公司层面的粗略规划假设，而不是已确认的季度新增值。一些季度可能明显更低，随后当一个大型园区投入运行或调试完成时会出现大幅增加。

Q:您预计在2026年底之前会有一次大规模的算力交付吗？

A:会的。我预计会有有意义的算力交付，尤其是在第四季度。Rainier 项目可能是最大的贡献者。目标是在年底前实现近一吉瓦的 AWS Trainium2 和 AWS Trainium3 容量。

Q:一旦 AWS 接收并调试了新的算力，该算力开始产生真实收入需要多长时间？

A:一旦算力完全调试、服务器安装完毕并且客户开始使用，收入几乎可以立即开始。对于像 Anthropic 这样有大规模承诺的 AI 工作负载，我预计在最初几周内就会出现显著收入，利用率可能在一到三个月内逐步提升。

对于一般企业算力，我会预留三到六个月让更广泛的利用率上升。这与收回投资所需的时间不同。

Q:之前提到的大约1到1.2吉瓦是指已调试并可供模型提供方立即用于训练的已投产算力，对吗？

A:正确。

Q:越来越多的企业客户是否将开源权重模型投入生产？如果是，他们是通过 Amazon Bedrock 在 AWS 环境中运行，还是在其它 Claude 上，或是在本地运行？

A:数据保护是企业考虑开源权重模型的最大原因之一。对于大多数企业，我预计这些工作负载的大部分会在 Claude 上运行，而不是本地部署。已有的 AWS 客户可以通过 Amazon Bedrock使用开源权重模型以获得托管推理，或者在需要更多自定义和部署控制时通过 Amazon SageMaker 和 Amazon EC2 使用。

对于高度敏感的工作负载、严格的数据驻留要求，或是那种拥有基础设施在经济上更划算的可预期高负载推理场景，本地部署会更有吸引力。然而，客户并不一定非得使用开源权重模型才能保护他们的数据，因为像 Claude 这样的专有模型在 Amazon Bedrock 上也能获得强有力的隐私和安全控制。

开源权重模型在控制性、可移植性和定制化方面具有优势，而 Amazon Bedrock 在运维简便性和集成方面具有优势。

Q:对于 AWS 来说，开源权重模型是否更有利可图，因为它不需要与模型提供方分成，尽管每百万 token 的收入可能更低？

A:AWS 可能从自有模型（例如 Amazon Nova）中获得更高的利润率，因为它既控制模型也控制基础设施，不需要支付第三方模型提供方。对于 Claude，AWS 仍然从基础设施和托管服务中获得收入，但部分经济利益会归属于Anthropic。

若 AWS 在自有硬件上高效运行开源权重模型，这类模型也具有吸引力。我预计亚马逊自有模型在潜在利润率上会更好，但不一定产生更高的总利润。Claude可能产生更多收入，因为客户愿意为其能力付费。亚马逊并未披露按模型划分的实际利润率，所以这反映的是我对经济性状况的看法，而非披露数据。

Q:AWS 对 Amazon Nova 的战略是什么？它主要用于内部，还是面向那些 AWS 可以推荐给客户的低到中等智能水平的使用场景？

A:Amazon Nova 两者兼顾，但长期战略超出内部使用范畴。亚马逊可以在 Alexa、广告、零售及自身运营中广泛使用它。目前我预计 Amazon Nova在高流量的日常工作负载（如客户支持或较简单的代理）中具有竞争力，在这些场景中速度和成本比最高推理能力更重要。

亚马逊并不把 Amazon Nova 单纯定位为低智能模型。通过 Amazon Nova Pro、Amazon Nova Premier 和 Amazon Nova Forge等产品，亚马逊也在向更复杂的推理和定制化企业模型延伸。最终战略是将更多模型经济留在 AWS 内部，提高推理利润率，并为客户提供在 Claude 之外使用亚马逊自有模型的理由。

Q:有多少客户在生产环境中运行 AWS Trainium，它们是用于训练、推理还是两者兼有？如果两者都有，训练与推理的大致比例是多少？

A:AWS Trainium 在训练和推理两方面的采用都在加速，但客户构成有所不同。在训练方面，Anthropic 仍然是主导的大型客户，拥有超过一百万片 AWS Trainium2 芯片支持 Claude的训练和推理。Poolside、Decart 和 Uber 等公司也在采用，但规模小得多。OpenAI 应该会从2027年开始成为另一个主要贡献者。

推理采用更为广泛。AWS 曾表示，大多数 Amazon Bedrock 的推理已经运行在 AWS Trainium 上，这一点很重要，因为 Amazon Bedrock 服务的是更广泛的企业客户群。如果我要估算当前 AWS Trainium的计算构成，我会假设大约50%到60%用于训练，40%到50%用于推理。这是我的假设，而非 AWS 披露的分解数据。

展望2027年，我预计推理增长会更快并可能成为更大的工作负载类别，因为 AI 应用的规模效应。更广泛采用的最大障碍仍然是软件兼容性。新的 PyTorch 支持应能让 AWS Trainium 更容易被采用，而无需大量代码改动。

Q:客户为何选择 AWS Trainium？决策是由更低的总成本、更好的可用性和性能、现有的 AWS 关系，还是整体商业包促成的？总成本大约比传统 GPU 低多少，训练性能与 GPU 相比如何？

A:主要原因是成本。与 NVIDIA GPU 实例相比，AWS 提供的 AWS Trainium2 价格性能大约高出30%到40%，在客户在 AI 计算上花费数亿美元时，这可以带来可观的节省。第二个原因是容量：NVIDIA GPU价格高且需求旺盛，因此 AWS Trainium 提供了另一种确保大规模算力的方式。

已经使用 AWS 的客户可以将 AWS Trainium 集成到现有基础设施中，新的 PyTorch 支持正在让工作负载迁移更容易。归根结底，这个主张是更低的成本、更容易的集成和可靠的容量。客户只有在 AWS Trainium对其特定模型表现良好时才会切换。对于经过良好优化的工作负载，我认为实际客户节省大约20%到40%是一个合理目标。

在性能方面，AWS Trainium2 的计算能力大约是第一代 AWS Trainium 的四倍，而 AWS Trainium3 的计算能力相对于 AWS Trainium2 可达最多4.4倍。这并不意味着 AWS Trainium3 比NVIDIA 硬件快4.4倍。

Q:在未来12个月预期的约4到6吉瓦算力中，大约多少比例会部署为 AWS Trainium 算力，多少比例为 NVIDIA GPU 算力？

A:粗略而言，我会估计 GPUs 占50%到60%，AWS Trainium 约占50%——基本接近50:50的分配。由于 Anthropic 和 OpenAI 的重大承诺，AWS Trainium 可能会比历史上占更大份额，但NVIDIA 对于更广泛的客户群仍然至关重要。

Q:如果更大规模部署 AWS Trainium 将如何影响 AWS 的利润率？客户会获得更低价格，而 AWS 的成本也会下降，那么 AWS Trainium 的部署大约能提高 AWS 的利润率多少？

A:我预计 AWS Trainium 将同时惠及 AWS 及其客户。客户可获得更好的定价，而 AWS 通过使用自有芯片而非支付 NVIDIA 硬件成本，可以改善利润率。对于客户来说，我估计在可比、良好优化的 AI 工作负载下，支出大约可降低20% 到 30%。AWS 宣传的是 30% 到 40% 更好的性价比，这并不等同于价格降低 30% 到 40%。

对 AWS 而言，AWS Trainium 可能为运营利润率带来数百个基点的优势，尤其是在推理方面。潜在改善大约为 3 到 4 个百分点，尽管这并非公司范围内的确认预测。

权衡在于每单位算力的收入可能更低，因为对客户的收费减少。然而，更低的价格可以驱动更高的使用量和更佳的利用率，从而在利润率改善的同时实现总收入增长。若不了解需求响应，我不会对收入提升的百分比做出精确估计。

Q:对于大型 AI 合约，哪些因素对盈利能力的挤压最大：客户折扣、模型费用、未使用的容量，还是让客户投入运行所需的支持？这些因素在第三季度是否有所改善？

A:所有这些因素都会影响盈利能力，但容量利用率是最大的驱动因素，其次是硬件成本和模型费用。客户支持很重要，但通常占比较小，尤其是在工作负载规模化运行之后。

我会将利用率放在第一位，因为这些资产非常昂贵。以 50% 而非 85% 的利用率运行，会对每个 token 的成本产生实质性差异。芯片和基础设施成本排在第二位，而 AWS Trainium 在这方面给 AWS带来优势。第三位是模型许可或收入分成费用，尤其是与 Anthropic 这类提供方相关的费用。客户上线是另一个因素，但相对较小。

A:我对 2027 年资本支出将增加多少没有清晰可见性，但我会估计资本支出约为 2800 亿美元到 3200 亿美元，而 2026 年计划约为 2200 亿美元。
