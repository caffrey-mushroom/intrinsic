摘要

【以下为专家观点汇总，具体细节仅供参考。】

是否看好Baseten和OpenAI的合作对OpenAI份额前景的推动？

Baseten的客户也有一些跑开源模型的需求，所以对双方来说都是一种妥协。对于Baseten那边，他们拿到的 deal 肯定也不会太好，OpenAI 肯定不会给他们太多分成，所以在整个合作中，OpenAI 拿大头。

像 OpenAI、Anthropic、Meta、Grok 这些也在找 Baseten或者 Firework 合作为了抢一些流量入口？

目前没有，确实好像只有 OpenAI 是第一家这么做试水。但这个流量入口对他们来说意义有多大，我其实也不觉得。比如现阶段如果有客户把 harness 放到 Claude Code 上跑，其实也不需要和 Anthropic合作，只要把模型底层的 URL 换过去就可以直接切流量。所以如果 OpenAI 或者 Anthropic来找 Fireworks合作，我觉得Fireworks也没有太大意愿合作，因为没有必要分流量的钱。现阶段 harness可以免费用，网关都是 API，OpenAI compatible，直接切过去就好了。这更像是一个Co-Marketing，算是有个官方合作，Baseten给点钱出去，换一个官方名声，大概就是这样。

怎么看Muse Spark Open、Nemotron V3.5和Beam在生产中的性能？对Kimi和GLM的份额影响？

会的。其他模型倒也没有特别强，尤其是Nemotron，一直表现一般。但 Muse Spark 其实还比较能打，大概能达到GLM 5.2的水平。所以在发物平台上，如果不是追求 SoTA的 coding 能力，multi agent架构下的模型都可以切成 Muse Spark Open。切完之后，以我对美国公司习惯的了解，他们一定会做一波爱国宣传，比如“Fireworks是第一家采用美国 open model”的这种说法。其实现阶段，除了做 SoTA coding agent 的那几个，大部分 use case 转过去都没什么太大问题。

在垂类模型的训练方面，客户会不会更倾向于用海外的开源模型？

其实没有什么倾向，更多是客户自己的选择。比如像 Atlassian这样的公司，本质上是很大的 SaaS 公司，但也做公共事业部分的业务，比如FBI，甚至软件开发和项目管理。这种情况下，没有美国模型就做不了这类业务。所以很多Fireworks现在在 engage 的客户，实际业务流都卡在今天测 Gemma 4，明天测Nemotron，后天测老的Llama，感觉都不太满意。第一波首先解锁的 use case 应该是直接上 Muse Spark Open，这样业务就能跑了。但已有客户的生产环境，比如可能在智谱5.3上跑着，如果没有看到显著的质量提升，我不觉得他们会马上把流量切过去。可能会有一部分客户觉得模型能力差不多，但切过去之后可以率先做一波marketing，比如以后可以说用美国模型了，原来用中国模型最多不吭声，现在用了美国模型就可以大声宣传。但从能力上来说，其实差别不大。

Fireworks 在7月底 GA 的 Nexus在生产环境对推理成本能有3-5成节省？会带动客户在 Fireworks上对开源模型的消耗？

Nexus 分成两套子产品，一个是 FireRouter，一个是 FireConnect。FireConnect就是可以一键把任务，比如用原来的 harness，OpenCode、Claude Code、Codex都可以，一键把底层调用的模型切成 Fireworks的模型。FireRouter是切到 Fireworks体系内后，可以自己配置，比如现在不是用 Opus 5吗？还可以继续用 Opus 5，简单一点的问题用 Kimi K3，再简单一点用智谱5.2。Fireworks自己做 performance 优化和模型训练，还是会用 Codex，甚至现在是 Opus 5.5。Fireworks进阶的 use case 比较多。如果下游 use case，比如数据库管理或网页开发，可以 fallback 到智谱的 case 会更多。它其实就是一个决策模型，只要 prompt 输出的阈值比Fireworks设定的低，就会直接用智谱5.2去解决。

把Jev融到决策流程里对frontier 模型的 token 消耗会有实质节约？

是的，大部分的用例来看很多场景需要用分类模型来解决问题。现阶段大家往往用很复杂的模型去解决很简单的问题，而 Jev这个方案反倒让大家回归了第一性原理。对于 token 的节省，肯定是能省的，尤其是模型体量很小时，单次生成决策消耗的能量比transformer 模型要少很多。有时候 transformer 生成的结果还不一定靠谱。Jev的用例非常广泛，比如客服公司检测客户情绪，数据分析时分析客户聊天记录，判断在哪个回合用户开始不满，这种不满可能是被动信号，需要分析前面 AI的回复哪里出了问题。

像 Atlassian等客户已经对上线的Muse Spark Open开始有很强的需求？

有，客户很早之前就开始来问了，至少上个月就有客户咨询。Fireworks的模型上线流程一般是，客户听说下个月有新模型上线，就会提前来询问。到上线当天，Fireworks会给所有问过的客户发推送，通知模型上线，请他们测试。比如规模较大的SaaS 公司，一般都有自己的 benchmark，基本上从上线当天到未来两周内，大量企业会先跑内部 benchmark，验证模型是否真的如宣传那样强，或者是否符合他们的用例。benchmark通过后，用户会提交下一阶段请求，比如模型差不多了，但某些 benchmark 能力稍微差一点，能不能做后训练？后训练完成后，用户会考虑签合同。整个过程基本上有两周左右的反应周期。

Inkling-Small 在7月在 Fireworks 上线后有没有吸引到很多流量？

没有，那个模型能力很一般，客户也没有动力去切换。

Fireworks 最近成立了 Fireworks Lab的情况？最近招了很多 FDE？

Fireworks开始尝试有没有一些模型能自己玩一玩就解决大部分用户痛点。比如 Kimi K3 这个模型非常大，但生成的 CoT明显有压缩空间。Fireworks做的 Amber 1模型，就是自己传数据后训练一把，基本上能把CoT长度压到原来一半左右。这个模型 researcher忙着试，试完后发现效果不错，甚至Fireworks很多内部开发流程都直接切到这个模型上了。大家觉得可以发布一下，试试反馈，结果社交媒体上的反响也很好。Fireworks认为类似的事情确实有需求，值得做。很多招进来的所谓的FDE就在做这类工作。当然更大一部分还是要为客户解决问题。

成立这个Lab是为了更贴近像Gemini Enterprise的模式？还是Fireworks自己摸索出来的方案？

完全是Fireworks自己摸索的。Fireworks没有把Google当作对手，Google现阶段Gemini Enterprise的体量应该没有Fireworks大。

Fireworks Lab成立之后，对获客和收入的提升明显吗？

现在刚成立，还看不出来明显效果。但在成立初期甚至还没成立时，Fireworks就已经意识到这个事情的必要性。过去Fireworks一直和用户做深度合作的客户都是非常专业的AI native公司，周边需要的配套门槛，客户公司都已经帮Fireworks解决了。但现在遇到的问题是，随着业务体量扩大，Fireworks不可避免地要接触到所谓的“行外人”，可能不是AI native公司，甚至可能是像安永、普华永道这样的公司，完全是不是行业内的玩家，因此Fireworks只能招一些人去应对。这其实是一个完全无法自动化的manual work，至少短期内无法自动化。

Amber这个模型后续包括做一系列垂类方案，会不会和Google和国内开原模型等直接竞争？

几个点。首先，Fireworks跑的Amber One模型其实也是Kimi K3，按照和Kimi的协议，Fireworks正常给他分成，所以没有任何矛盾。其次，如果Fireworks做一些模型改动，导致他要从Fireworks撤下去，我觉得Fireworks也还好，因为Fireworks服务的模型不止这一家。他撤下去其实是因为没有流量了，我甚至可以不给他分成，把分成给其他人。其实这个逻辑就像Fireworks现在是美国比较大的一个开源模型托管服务商，你可以把Fireworks理解为一个规模较大的超市。如果这个超市把你家的鸡买过来，做成白斩鸡，你说以后不卖鸡给我了，那你随意，鸡有的是，我可以从别家进货。

Fireworks觉得做垂类训练不赚钱，需求持续性也不是很高？

本身就没指望训练赚钱。如果之前聊过的话，训练的意义在于帮客户把模型的能力差距补上。客户现在签的是十几万的试水合同，而不是一千万元以上的真正大单，原因就是大部分模型能力还没达到那个水平。现在的问题是，如何基于客户的用户场景，把模型能力上的ga p补上，或者说把模型能力的拼图补齐，还是靠推理赚钱。

Kimi K3和Amber的分成是怎么分的？

Fireworks可以以任何方式定价，但会把自己在Kimi模型上的收入分一个固定比例。所以无论是Amber还是普通的K3，或者像Cursor用的Kimi k2.5，分成比例都是一样的。

Baseten 2025年第三季度组建了FDE团队，他们的进展如何？Fireworks的差异化在哪里？

其实Fireworks最早的训练业务是2024年初开始做SFT，2025年中就已经支持强化学习。今年（2026年）Fireworks把强化学习底层和Tinker兼容的API做了，今年只是把所有产品完善并重新发布公告，但实际上Fireworks最早在2023年底就开始支持训练了。FDE没有什么本质区别，核心区别在于训练的基础设施是否足够稳定。客户来这里，主要关注训练能不能更快，模型训练时GPU负载能不能更均衡，就是这些问题。FDE需要解决的是用户对整套训练基础设施的不同定制化需求。比如底层training API很多用户觉得太难看不懂，托管训练又觉得没空间自己定制。用户总是在这两个极端之间挣扎。最终的解决方案就是出人帮他改。

Nebius和Together AI在垂类模型训练方面的进展？也在招FDE？

现在他更多是搞一个裸机集群，然后租给OA两个大的frontier lab，相当于让他们去做训练。我只需要负责集群的稳定性就可以了。这就是Together会走的路线。Nebius现在是让Eigen AI在做训练。实际上和大家之前的想法不太一样，之前大家觉得是Eigen AI的人去做推理优化，但实际上是Clarify在做推理优化。逻辑上没有复杂，也没有什么区分度，就是看Fireworks和Baseten现在实现了什么，然后继续模仿。不过在效率和整体表现上，我觉得他可能还需要至少6个月才能赶上。

Fireworks最近发生的API key泄露事件进展如何？影响范围？

影响范围其实不大，但对Fireworks的整体声誉来说确实是一个很棘手的问题。随着AI能力提升，防御的成本变高。所有AI native公司可能都面临同样的问题，所以过去这两周Fireworks整体加强了所有安全措施，现在内部基础设施看不到任何hard code的key，所有API key都在动态轮换，同时内部很多权限审查也收紧了。

Fireworks主要和哪家网络安全厂商加强合作？现在的解决方案是什么？

现在主要是和CrowdStrike和OKTA等合作。
