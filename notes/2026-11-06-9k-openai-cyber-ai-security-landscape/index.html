网络安全与AI Agent行业专家访谈纪要

1. OpenAI Cyber的产品定位与行业影响

1. Cyber与此前的安全模型相比，核心差异是什么？

  • 从“安全模型”升级为“安全Agent”
  1. 此前的Mythos更接近单一模型，虽然展现出较强的安全能力，但受责任和授权限制，主要由特定厂商用于代码扫描，实际行业影响低于最初预期。
  2. Cyber并非单纯依赖模型能力，而是类似Codex、Claude Code的Coding Agent，具备预设的Harness、Agent Loop以及任务规划和执行机制。
  3. Cyber能够围绕任务目标规划执行路径，并完成验证、利用、修补、打补丁和再次验证的完整闭环。
  4. 相较于受限且难以规模化开放的安全模型，Cyber更接近成熟、可交付的安全产品，因此会直接影响现有安全市场。
  • 具备完整的红蓝队协作能力
  1. Cyber的Daybreak体系分为Red Team和Blue Team，红队负责发现和验证漏洞，蓝队负责修复和防御。
  2. 其能力已不局限于漏洞识别，而是可以完成从攻击验证到补丁生成、修复验证的全流程。
  3. 低端漏洞发现、报告编写及修补工作的成本，可能被Cyber大幅压缩。

2. Cyber首先会冲击哪些传统网络安全业务？

  • 受冲击较大的领域
  1. SAST及静态代码扫描。
  2. 相对低端的渗透测试。
  3. App Security咨询服务。
  4. 批量漏洞挖掘、报告生成和补丁修复。
  5. Bug Bounty平台及相关服务，例如HackerOne模式。
  6. 部分威胁情报业务。
  7. 依赖高级安全人员进行批量源码审查的服务。
  • 核心原因
  1. 上述工作的主要价值在于信息分析、代码理解和重复性操作，适合由高信息密度的AI Agent替代。
  2. Cyber可以稳定、批量执行漏洞发现和修复任务，边际成本显著低于人工团队。
  3. 传统安全咨询企业可能被迫转向合规、认证和责任承担等AI暂时无法取代的业务。

3. Cyber对攻击方和防守方分别有何影响？

  • 在合规使用条件下，更有利于防守方
  1. Cyber预计会进行较强的合规强化，难以在未授权情况下直接用于真实攻击。
  2. 闭源模型的操作需要经过模型厂商的大集群，并受到缓存识别、Guardrail及账户封禁机制约束。
  3. 因此，Cyber主要服务于拥有代码和授权的防守方，用于内部代码审查、红队测试、补丁生成及安全运营。
  4. 除非发生模型泄露或权限泄露，否则其直接流入匿名攻击者手中的概率较低。
  • 防守侧的需求不会因模型增强而消失
  1. Cyber主要替代低端渗透、代码扫描和补丁修复，并不能取代整个安全链条。
  2. 防火墙、身份认证、零信任、行为管理等产品不仅承担分析功能，还承担实际控制和部署功能。
  3. AI可以作为“安全大脑”，但仍需要防火墙、IAM、零信任等“手和脚”执行访问控制和阻断。
  4. 更多漏洞被快速发现后，企业会更直观地感受到安全风险，反而可能提升对防守产品的需求。

2. AI对不同安全市场的替代边界

1. AI能否替代高级合规及安全审计产品？

  • 能力层面可以覆盖，责任层面难以替代
  1. AI已经能够完成高级合规业务所需的大部分分析、检查和材料处理工作。
  2. 但AI无法代替企业承担法律责任，也无法独立出具License或认证结论。
  3. 很多地区要求具备资质的专家完成完整Audit，项目才可被认定为合规。
  4. 因此，合规企业仍有存在价值，但其底层执行工作已受到AI的严峻冲击。
  • 未来可能形成的分工
  1. AI负责审计资料整理、风险识别、规则检查和报告草拟。
  2. 持牌机构和专家负责复核、签字、认证及责任承担。
  3. 合规服务的人工工作量可能下降，但认证资质和责任承担的价值会上升。

2. 用户端点、服务器端点和中间件安全中，哪些最容易被替代？

  • 服务器端点安全最容易受到冲击
  1. 服务器端安全主要包括代码安全、SOC监测、恶意连接检测、敏感数据访问监测、文件篡改检查，以及EDR、XDR、IDS等产品。
  2. 这类能力主要依赖本地信息分析，不需要建设庞大的外部基础设施。
  3. AI公司能够利用更强的代码和推理能力，开发出技术水平不低于传统厂商的EDR、XDR及代码安全产品。
  4. 传统依靠安全人员7×24小时值守的工作，也可能由AI Agent完成。
  • 用户端点安全同样面临较强替代风险
  1. 电脑、手机上的传统杀毒软件具有较强的本地化特征。
  2. AI可以直接在终端识别恶意行为、分析代码并完成检测与处置闭环。
  3. 长期来看，赛门铁克等传统杀毒产品可能被本地AI安全能力逐步替代或重构。
  • 中间件和边缘安全壁垒最高
  1. 中间件安全包括WAF、身份安全、行为安全、零信任、SASE及基础云安全。
  2. 代表性企业包括Cloudflare、Akamai、Zscaler、Netskope、Palo Alto、Fortinet、Cisco和Check Point等。
  3. 这类业务的核心壁垒不仅是安全算法，还包括全球节点覆盖、网络性能、运营商骨干网接入、数据中心建设及当地合规能力。
  4. AI公司即使能够开发出一线水平的产品，也很难短期内复制全球基础设施、低时延网络和品牌信任。

3. AI将如何改变中间件安全产品？

  • 由规则匹配升级为上下文和语义判断
  1. 传统系统通常根据单一访问事件或固定规则判断行为是否可疑。
  2. 引入AI后，系统可以将用户连续访问页面A、B、C、D的行为串联起来，判断其是否正在逐步突破安全边界。
  3. 小模型可结合上下文识别异常行为，再由控制系统进行标记、阻断或权限收回。
  4. 中间件安全厂商会把AI推理能力嵌入原有产品，而非被AI公司立即整体替代。
  • AI公司短期难以直接进入边缘安全市场
  1. OpenAI、Anthropic等纯AI公司目前仍是Akamai、Cloudflare等中间件企业的客户。
  2. 建设全球边缘安全基础设施需要极高资本投入，将资源继续投入模型研发通常更具价值。
  3. 因此，AI对端点安全的渗透会快于对边缘和中间件安全的渗透。

3. AI对攻防能力和漏洞利用效率的影响

1. AI能力提升后，攻击方还是防守方会率先获益？

  • 第一阶段，攻击方能力提升更快
  1. 防守方在攻击发生前，往往并不知道攻击可能达到的程度。
  2. 企业无法仅为消除安全风险就立即全面修改代码，因为修改可能引发业务故障。
  3. 攻击方获得先进模型后，会立即进行黑盒测试、扫描、渗透和横向提权，优先寻找可以利用的资源。
  4. 因此，在没有模型限制的情况下，攻击方通常比防守方更积极、更充分地使用AI能力。
  • 真正可用于攻击的主要是可训练的开源权重模型
  1. 闭源前沿模型受到厂商Guardrail、账户管理和集群侧监控，难以长期执行未授权攻击。
  2. 成熟红队产品通常需要基于开源权重模型进行训练和调整，才能持续完成攻击任务。
  3. 专家接触的前沿攻击类产品主要建立在国内开源模型基础上。
  4. 如果开源模型没有进行安全能力分离，其合规流通可能面临较大压力。

2. 成熟的AI红队产品目前能达到什么水平？

  • 已具备长周期、多Agent协同攻击能力
  1. AI红队攻击并不是通过几轮对话完成，而是可能持续约1周进行不断试错。
  2. 系统通常设置总指挥Agent，并调度多个子Agent执行不同任务。
  3. 子任务包括搜索目标页面和App、扫描API、寻找变形域名、识别真实源IP、判断防火墙、建立网络资产图谱及寻找可利用漏洞。
  4. 后续还可进行横向提权、数据库获取、生产数据提取、管理员权限获取或Shell控制。
  5. 达成目标后，系统会进行结果评估并生成完整报告。
  • 效率已显著高于传统人工团队
  1. 专家观察到的产品，可以在约1周内完成一个5人高级安全专家团队约1个月的工作量。
  2. 在部分测试中，AI已能够取得目标网站后台数据库、资金流水及交易记录。
  3. 现有能力已经具有较强冲击力，而且使用的还并非最新一代模型。

3. 攻击方在没有源代码时，如何利用AI发现漏洞？

  • 先建立数字指纹和资产画像
  1. 攻击方可以识别目标使用的PHP、Node.js、WordPress等组件及其版本。
  2. 根据组件版本匹配已知漏洞，并验证目标是否已经升级到修复版本。
  3. 如果单一漏洞无法利用，则继续横向搜索其他问题，或将多个小漏洞组合起来。
  4. AI最擅长的是综合大量弱信号，将多个低风险漏洞串联为可利用的攻击路径。
  • 与防守方源码审计存在本质差异
  1. 防守方可以将完整源码交给模型，相当于已掌握答案，再寻找可能的利用路径。
  2. 攻击方只能进行黑盒测试，无法直接看到企业闭源代码。
  3. 因此，前沿闭源模型发现的企业内部漏洞，如果不公开，外部攻击者通常无法直接利用。

4. 为什么漏洞公开后的风险会急剧上升？

  • 许多高危漏洞可能早已被Google Project Zero或大型安全团队发现，但会先与厂商协作完成修复，而不会立即公开。
  • 一旦漏洞在补丁充分覆盖前被公开，攻击者可以在数分钟至数小时内编写利用程序，并通过Botnet对全网进行扫描。
  • AI将进一步缩短从漏洞公开到规模化利用的时间，使“分钟级响应”成为新的防守要求。
  • 未来安全竞争的关键不再只是能否发现漏洞，而是谁能更快发现、验证、修补和部署防护。

4. AI生成代码对长期安全需求的影响

1. AI编写代码是否会减少漏洞？

  • 企业级代码的漏洞数量长期有望下降
  1. 企业内部Coding Agent通常会配置自身的准则、RFC或“黄金标准”。
  2. Agent在处理不同业务时会严格遵守业务边界，犯错及越权概率可能低于人工开发。
  3. 从长期看，企业级代码中的低级漏洞和边界突破问题有望减少。
  • 开源社区的漏洞数量未必下降
  1. 非专业人士也可以使用Coding Agent大量生成代码。
  2. 默认大模型未必配置充分的安全围栏和企业级规则。
  3. 开源代码产出速度上升后，质量可能更加混乱，潜在漏洞反而可能增加。

2. 漏洞数量减少是否意味着安全需求下降？

  • 安全需求并不单纯由漏洞数量决定
  1. 安全工作的核心是漏洞发现、利用、修补和响应的完整过程。
  2. 即使漏洞从1000个下降至100个，甚至只剩1个关键漏洞，仍取决于攻击方和防守方谁先发现并采取行动。
  3. AI生成代码的迭代速度更快，新版本、新功能和新架构可能重新引入漏洞。
  4. 此前已经修复的问题，也可能因回归测试不足而再次暴露。
  • 真正变化的是安全响应速度
  1. 过去从漏洞暴露到被规模化利用可能有数月时间。
  2. AI时代如果不能在分钟级完成识别、规则下发和补丁响应，企业就可能面临较高暴露风险。
  3. 因此，静态安全产品会受到冲击，但动态检测、自动响应和持续防护的重要性会上升。
  4. AI不会简单消除安全需求，而会推动安全产品从静态规则转向动态闭环。

5. 网络安全产品的收费模式变化

1. 为什么传统按席位收费模式会受到冲击？

  • 过去CrowdStrike等厂商主要按License和受保护电脑数量收费，Zscaler等零信任产品则按照员工人数收费。
  • 企业裁员并使用AI Agent替代部分员工后，员工和终端席位数量可能下降。
  • 一个员工未来可能同时调度100个、1000个甚至更多Agent，无法继续按“一个人对应一个席位”的逻辑计费。
  • 新型安全产品变化快，企业难以在合同签订前准确确定将使用哪些产品及具体使用量。

2. 短期内最可行的收费模式是什么？

  • 资金池模式将成为主要方向
  1. 企业可能与安全厂商签订年度总额合同，例如向资金池充值100万美元。
  2. 合同不再严格绑定特定产品、员工、电脑或服务器数量。
  3. 企业可在日志审计、AI Guardrail、安全扫描、SOC观测、Agent Runtime和沙箱等多个产品间灵活调用额度。
  4. 计费指标可包括CPU、GPU调用量，模型调用次数，扫描时长，代码行数及Token消耗量。
  5. 本质上是从按席位收费转向按用量扣费。
  • 资金池模式更适合快速变化的产品形态
  1. AI安全产品几乎每月都会新增功能，传统合同无法及时覆盖。
  2. 企业在签约时无法确定未来一年会使用哪些安全能力。
  3. 资金池可以将预算先锁定，再根据实际使用动态扣费。
  4. 专家判断，至少在未来一年内，资金池模式较为合理。

3. 长期收费模式可能如何演变？

  • 产品形态稳定后，不排除重新采用席位收费。
  • 未来可能形成“AI per seat+Token用量”的混合模式。
  • 如果AI最终成为类似操作系统的基础能力，厂商可以按Agent或操作系统实例收费，同时按Token或算力消耗收取类似“电费”的用量费用。
  • 最终模式尚未确定，当前行业仍处于快速探索阶段。

6. 云厂商与第三方安全厂商的竞争格局

1. 云厂商发展安全业务具备哪些天然优势？

  • 基础设施和存量客户优势
  1. 云厂商已经提供CPU、GPU和底层算力，理论上可以覆盖安全厂商的大多数产品。
  2. 微软、AWS和GCP拥有大量企业客户，推出新型安全产品后，可以直接向现有客户追加销售。
  3. 企业通常会优先在现有技术架构上升级，而不会为了单一新需求重新寻找供应商并开展完整POC。
  4. 云厂商的平台化能力、产品整合能力和交付效率更强。
  • 数据和可观测性优势
  1. 云厂商承载大量业务数据、模型流量和基础设施日志，能够更早识别新型攻击。
  2. 谁先观测到新型恶意流量和攻击模式，谁就能更快设计应对方案。
  3. Cloudflare等边缘云厂商同样因承载大量流量和拥有丰富数据接口而受益。
  4. 动态安全时代，数据基座、响应速度和产品适应能力将成为关键竞争力。

2. 第三方安全厂商为何仍有长期生存空间？

  • 中立性是核心价值
  1. 大型企业通常采用混合云，不愿将全部业务绑定于单一云厂商。
  2. 第三方安全厂商可以将身份、终端、AWS、微软、谷歌等不同平台整合起来。
  3. 使用Zscaler等中立产品，通常更容易同时接入Okta、AWS和微软等多家平台。
  4. 单一云厂商则更倾向于将客户绑定在自身全家桶中，跨云兼容和配合程度可能下降。
  • 避免云厂商锁定和成本上涨
  1. 企业初次签约云厂商时可能获得较高折扣，但完成架构和流量迁移后，续约成本可能持续上升。
  2. 一旦被单一云平台锁定，企业将失去议价能力和快速迁移能力。
  3. 混合云架构能够在云厂商出现故障或进入续约谈判时保留切换能力。
  4. 第三方安全组件可以承担不同云平台之间的粘合和统一管理角色。
  • 可信度和知识产权保护
  1. 企业可能担心云厂商看到其模型训练数据、核心逻辑或知识产权。
  2. 即使平台声明“零数据保留”，也很难完全证明其中立性。
  3. 当云厂商本身与客户存在潜在竞争关系时，中立第三方基础设施和安全服务更具吸引力。
  4. 中立第三方托管SOC因此具有较大发展潜力。

3. 云厂商与第三方厂商各自更适合哪些场景？

  • 云厂商更有优势的场景
  1. 单一云环境。
  2. 原生云安全升级。
  3. 与算力、模型服务和日志平台深度结合的安全产品。
  4. 需要快速追加销售和统一采购的企业客户。
  • 第三方厂商更有优势的场景
  1. 混合云及多云环境。
  2. 跨身份、终端、网络和云平台的统一管理。
  3. 强调中立性、知识产权保护及跨平台兼容的场景。
  4. 需要第三方统一托管SOC和安全运营的成熟大型企业。

7. 安全平台、SOC与Cyber Agent的关系

1. Cyber能够串联安全功能后，平台化是否仍有必要？

  • Cyber不能完全替代安全平台
  1. 企业产生的日志、遥测和安全事件数量极其庞大，无法将所有信息全部输入大模型。
  2. 如果所有事项都由高性能模型处理，Token成本可能远超企业可承受范围。
  3. 安全平台的核心作用是以较低成本聚合数据、清洗日志、标注事件并统一调用各类安全工具。
  4. Cyber应作为智能大脑，用于处理最关键、最复杂的判断，而不是事无巨细地参与全部流程。

2. 未来SOC平台可能采用怎样的架构？

  • 底层数据平面
  1. 聚合WAF、身份认证、行为管理、端点安全等产品产生的遥测和观测数据。
  2. 通过规则、算法和小模型进行初步筛选、标注和异常识别。
  3. 形成统一、标准化的安全数据平面。
  • 上层智能调度
  1. 接入Cyber等高级安全Agent进行总体判断和任务调度。
  2. 通过平台调用任一安全组件并下发命令。
  3. 倒查安全事件触发原因、操作人员、访问内容及前后逻辑。
  4. 用户可以采用平台自带模型，也可以接入自行部署的DeepSeek、GLM等模型。
  • 平台与模型将双向融合
  1. 平台会增加更多AI推理和自动执行能力。
  2. 模型会不断向数据整合、工具调用和安全控制层延伸。
  3. 如果未来Token成本大幅下降，平台的部分功能可能被模型侵蚀。
  4. 更可能的最终形态是平台与模型共同走向统一安全平面，而非一方完全取代另一方。

8. AI发展对安全硬件和Agent安全的影响

1. 哪些安全硬件会因AI基础设施建设受益？

  • 数据中心安全硬件短期受益
  1. AI推动GPU集群、新节点和数据中心持续建设，带动光纤、光模块、内存及网络设备需求。
  2. 数据中心流量增长，需要更高性能的机架内分段、机架内防火墙和FortiGate等产品。
  3. Palo Alto、Fortinet、A10 Networks等厂商提供的防火墙、负载均衡、DDoS防护及CGNAT设备仍是基础设施刚需。
  4. 当前GPU数据中心建设与此前5G时代CPU机房建设类似，网络层所需设备基本相同。
  • 增长逻辑更接近传统基础设施
  1. 安全硬件与光模块、光纤和内存一样，需求真实但主要由数据中心扩张驱动。
  2. 若未来算力不再稀缺，或数据中心建设出现泡沫并产生大量闲置节点，安全硬件需求也会受到影响。
  3. 数据中心以外的安全硬件增长可能与过去相近，部分需求主要由设备更新周期带动。

2. 哪些安全硬件或产品可能受到冲击？

  • 偏静态、购买后依靠企业自行安排人员维护的安全产品，未来发展压力较大。
  • 单纯依赖固定规则、缺乏云化运营和动态响应能力的设备，更容易被软件定义和AI增强型产品替代。
  • AI不会立即消除底层硬件，但会降低传统静态功能的差异化和附加价值。

3. Agent规模化后，真正受益的安全方向是什么？

  • 身份识别和行为管理
  1. Agent to Agent、Agent to Web等东西向流量将显著增加。
  2. 大模型本身并不可信，需要外部框架限制其访问范围和行为边界。
  3. 系统必须明确Agent可以访问哪些资源、在什么条件下访问，以及是否存在越权行为。
  4. 出现异常时，需要实时阻断或收回权限。
  • AI Gateway和Agent Guardrail
  1. AI Gateway可以结合上下文判断Agent是否偏离业务目标。
  2. Guardrail可以检查提示词注入、越狱及敏感数据泄露风险。
  3. Zscaler、Netskope、Check Point和Palo Alto等拥有身份验证、零信任和行为管理能力的厂商有望受益。
  4. 这一方向属于软件和控制层机会，其长期价值可能高于传统静态安全硬件。

9. AI监管与安全合规产业机会

1. AI监管趋严将如何影响模型和安全行业？

  • 对模型厂商的影响
  1. 更严格的监管可能限制OpenAI、Gemini等模型厂商快速扩张。
  2. 部分AI估值和投入节奏可能受到压制。
  3. 模型在安全、数据和行为管理方面需要承担更高合规成本。
  • 对安全行业的影响
  1. AI已经进入实际应用，安全和合规需求不会因监管而消失。
  2. Agent行为安全、AI Guardrail和模型使用审计可能从可选项变为必需品。
  3. 使用模型可能需要报备、认证和满足特定安全标准。
  4. 监管产生的新增要求，大部分会转化为安全厂商的业务机会。

2. 欧洲及全球合规要求将带来哪些产业机会？

  • 欧洲数据法规要求数据本地化及更严格的安全管理，推动Akamai、Cloudflare等具备本地节点和合规能力的企业发展。
  • Anthropic租用Akamai在不同地区建设的GPU集群，可能主要出于数据不离境、区域部署和合规落地考虑。
  • 具备当地数据中心、网络节点和合规认证能力的第三方厂商，可以帮助AI公司快速进入不同市场。
  • AI基础设施与安全合规将逐步形成结合更紧密的产业链。

3. 第三方安全厂商将如何从监管中受益？

  • 安全厂商可通过FedRAMP、ISO及各地区安全认证，成为AI产品进入企业或政府市场的必要组件。
  • 企业接入模型时，要么自行完成安全与合规建设，要么通过第三方安全组件满足要求。
  • 未来第三方安全服务可能从AI公司的普通供应商，升级为模型接入、部署和运营中的强制性基础设施。
  • AI监管越严格，对具备认证、区域节点、数据隔离和合规交付能力的安全厂商越有利。
