1. AI 对工程效率与未来工作的影响

1.1 编程模型能力快速提升后，为什么开发者数量和工作需求反而持续增长？

  • 开发者从未像现在这样有能力完成更多工作，但行业和社会对开发者的要求也达到了前所未有的高度。
  • AI 提升生产力后，并未使需求趋于饱和，反而激发了更多产品、服务和创造性工作的需求。
  • 世界上存在庞大的潜在需求，人们对于技术产品的期望也在持续提高，因此开发者仍处于 AI 进步的核心位置。
  • 这一趋势在积极意义上超出预期：AI 没有简单取代人，而是在扩大人类能够完成的工作范围。

1.2 AI 对就业的影响是否存在边界，能否延伸到其他领域？

  • 部分不需要太多创造力、社会也不关心具体由谁完成的任务和岗位，未来确实会由 AI 承担。
  • 但人类需要的新事物仍然非常多，因此不会缺少值得投入的新工作。
  • AI 自动化的核心影响不是让工作整体消失，而是推动人们从低创造性任务转向新的需求和更高价值的工作。
  • 创造人们真正需要的产品这一基本原则不会改变，但个人和小团队能够完成的工作量将发生根本变化。

1.3 为什么 AI 的发展仍然以人为中心？

  • 人们并不真正关心机器本身做了什么，更关注作品背后的创作者、公司背后的人，以及理念或产品背后的主体。
  • 即使大量智能体协作完成重大科学问题，公众也更关心如何理解成果、哪些人参与其中，以及成果对人类意味着什么。
  • 例如，10,000 个智能体连续协作4天并解决重大问题后，外界讨论的重点仍可能是参与方式和成果解读，而不仅是机器完成了任务。
  • 这说明 AI 的价值最终仍要通过人类目标、人类参与和社会意义来体现。

2. AI 时代的愿景：从“工业革命”转向“新文艺复兴”

2.1 AI 未来更像工业革命，还是更像文艺复兴？

  • 工业革命从根本上以机器和规模化生产为中心，带来了经济增长和丰富的物质成果，但也让部分人成为高度专业化体系中的“齿轮”。
  • 文艺复兴则更强调人的主体性、创造力，以及对人类潜力的重新认识。
  • OpenAI 所期待的不是“AI 自动化一切、人类不再发挥作用”的未来，也不是人类像家猫一样由 AI 决定获得何种奖励和安排。
  • 更理想的方向是：
  1. 推动新一轮大规模科学发现；
  2. 促进艺术创作和新公司成立；
  3. 让更多人有能力开创新事物；
  4. 让人们在享受经济增长的同时重新掌控生活；
  5. 让个人可以按照自己的意愿安排时间和精力。

2.2 AI 是否正在改变人类对自身潜力的认识？

  • 文艺复兴的重要特征之一，是人们重新连接历史思想，同时结合未来主义、科学与工程发现，进而拓展对人类潜力的想象。
  • 当前围绕 AI 的讨论同样包含两个方向：
  1. 对知识、文化与人类价值的重新理解；
  2. 对未来科技和新能力边界的持续探索。
  • AI 的重要价值不只是帮助人类完成更多任务，也包括帮助人们重新获得时间、注意力、创造空间和生活自主权。

3. 持久智能与主动智能：Dot 的产品定位和实践

3.1 什么是“持久智能”或“主动智能”？

  • 核心理念是让智能体在后台全天候运行，与用户的系统和信息环境连接，主动发现并处理事务。
  • 与传统聊天机器人不同，这类智能体不必等待用户明确发起请求，而是能够：
  1. 持续理解用户背景；
  2. 识别当前最需要关注的事项；
  3. 主动筛选和整合信息；
  4. 在合适的时间提醒用户；
  5. 代表用户推进后续任务。
  • 这一方向被认为是未来 AI 产品的重要发展领域。

3.2 Dot 如何帮助用户重新掌控时间和注意力？

  • Dot 可以判断哪些事情需要用户立即关注，哪些事项可以延后，哪些任务可以直接由智能体处理。
  • 其价值不是单纯提升处理速度，而是减少用户查看手机、Slack、邮件等渠道后产生的注意力中断。
  • 对管理者而言，清晨通常是最适合深度思考和创造性工作的时间，但企业运营中的紧急情况又要求其随时关注信息。
  • Dot 可以在紧急事务与非紧急事务之间进行分流，使用户既不会错过重大问题，也不必被大量日常信息占据注意力。
  • 由此可以释放更多时间，用于创造性工作、复杂项目或陪伴家人。

3.3 Dot 在生产事故和日程管理中有哪些实际案例？

  • 在 Dev Day 主题演讲期间发生了严重的 SEV 1 生产事故。
  • Tibo 的 Dot 在演示开始前5分钟主动提醒：
  1. 已识别用户正在参加 Dev Day 主题演讲；
  2. 了解用户一直在为演示做准备；
  3. 通过 Space 等系统了解了演示内容；
  4. 判断该事故可能影响现场演示；
  5. 主动询问是否需要尝试修复。
  • 当前版本尚不能直接修复生产事故，但未来版本可能具备在生产环境中直接解决问题的能力。
  • 在另一场景中，Dot 识别到用户连续忙碌一天、工作进度滞后，并在短暂空档中主动指出一项必须处理的关键事务，避免了潜在混乱。
  • Dot 还可以从 Slack 中识别没有进入日历的会议，并在用户改签航班时提醒其存在行程冲突。

3.4 Dot 如何支持创意形成和持续迭代？

  • 用户可以在散步、工作间隙或睡前，通过文本或语音随时记录原始想法。
  • Dot 可以基于这些想法自动构建5至6个不同版本，接受反馈后继续迭代。
  • 用户晚上留下较长的语音笔记后，第二天早晨不仅能看到想法已经被构建出来，Dot 还可能主动完成后续多个步骤。
  • 这种方式降低了高不确定性项目的尝试成本，使过去因表达困难、执行复杂或耗时过长而被放弃的想法有机会落地。
  • Dot 的意义在于形成近乎持续的“想法—构建—反馈—再构建”循环。

3.5 Dot 如何处理传统搜索无法解决的问题？

  • 用户曾尝试通过 Codex 搜索一项 Slack 内容，连续调整搜索方式10至20分钟后仍未找到，最终放弃。
  • Dot 注意到搜索失败后，在后台持续分析，并于次日找到目标内容。
  • 原因是相关信息并非 Slack 文本，而是一张截图；Dot 对截图进行了图像识别，最终定位到正确内容。
  • 这一案例体现了主动智能的核心优势：
  1. 能够跨文本、图片和不同信息源处理内容；
  2. 不会因为一次搜索失败而立即停止；
  3. 可以在后台持续尝试；
  4. 能在恰当时间将结果重新提供给用户。
  • Dot 尤其适合处理 Slack、电子邮件和其他渠道构成的信息洪流。

3.6 Dot 当前的成熟度和技术基础如何？

  • Dot 目前仍处于非常早期、相对粗糙的阶段，存在功能局限和使用问题。
  • 产品可以在移动端、电脑端及独立应用程序等多个界面中使用。
  • 后续计划以周为单位快速改善，但彻底理顺跨系统、跨信息源和跨终端协作仍需要时间。
  • 从研究角度看，Dot 是一个复杂系统，需要模型、工具调用、信息连接和任务执行等多项能力。
  • 最关键的基础之一是 Astra，即首先要让底层模型的智能水平跨过关键门槛。

4. Space 与人机协作办公体系

4.1 为什么要一次推出多款办公套件类工具？

  • 这一计划并非最初就被设定，而是在实践中发现，现有软件总体上并不是围绕人类与 AI 紧密协作设计的。
  • 传统软件通常支持两种模式：
  1. 用户亲自使用；
  2. AI 代替用户操作。
  • 但当多人及其各自的 AI 需要共同协作时，传统软件中的文档、权限、流程和协作抽象便难以适用。
  • 因此，Space 的核心探索方向是建立适合“多人+多个 AI”协同工作的全新空间。

4.2 用户与 Dot 在 Space 中如何分工？

  • 当出现新想法时，用户仍倾向于自己完成初始写作，因为写作本身有助于思考和梳理逻辑。
  • 初稿形成后，再由自己的 Dot 或其他人的 Dot 完成整理、扩展、更新和后续执行。
  • 这意味着 AI 并非完全替代人的原创过程，而是承担协同、补充、维护和持续推进的职责。

4.3 什么是“实时文档”？

  • “实时文档”会根据人员互动或外部环境变化自动更新，而不是保持静态。
  • 多个 Dot 可以共同处理同一份文档，既共享信息，也能够协作生成新内容。
  • 例如，7个人各自头脑中的想法可以通过多个 Dot 的协作被整合，最终形成任何单一个体都未完整提出的涌现式成果。
  • 这种能力尤其适用于：
  1. 新功能探索；
  2. 跨团队规划；
  3. 动态项目管理；
  4. 公司经营信息汇总；
  5. 持续变化的决策文档。

4.4 动态仪表盘如何改变管理方式？

  • 过去管理者往往与多人共同使用统一仪表盘；现在可以拥有仅为个人服务的动态仪表盘。
  • 该仪表盘会根据用户不断变化的关注点，对业务情况进行个性化总结。
  • 它可以读取 Slack 等信息源，生成新的分析内容并持续更新。
  • 管理者的关注点会随时间变化，例如：
  1. 6个月前可能主要关注收入、增长和业务指标；
  2. 当前则更多关注安全、对齐和安保挑战。
  • 未来希望能够对管理者数年间关注重点的变化进行可视化，并进一步感知用户情绪，判断某条信息适合立即查看还是延后处理。

5. 平台、应用市场与开发者生态

5.1 Dev Day 发布内容为什么持续增加？

  • 本届 Dev Day 共发布约22项新内容，明显多于去年约9项和前年约4至5项。
  • 原计划发布的内容更多，但为了把主题活动控制在50分钟内，部分内容被删减。
  • 发布数量增长体现了 OpenAI 对自身理念的实践：
  1. AI 工具可以显著提高生产力；
  2. 生产力提升会推动人们创造更多产品；
  3. 市场本身也需要更多新产品和新服务；
  4. OpenAI 自身同样应利用 AI 构建更多产品。
  • 如果当前模式持续有效，未来将由更多团队和个人共同开发，产品发布数量还会进一步增加。

5.2 OpenAI 希望建立什么样的平台？

  • 平台目标是让人们可以像 OpenAI 一样，在 ChatGPT 中开发应用。
  • 用户可以在任何希望使用的场景中携带自己的订阅，而不是为每项服务重复订阅。
  • 平台将建设应用市场，帮助用户接触开发者未来创造的各种产品和服务。
  • 核心理念是平台所创造的生态价值应大于平台自身获取的价值。

5.3 OpenAI 是否已经找到成熟的应用商店模式？

  • 当前尚未找到与传统应用商店相对应的成熟模式。
  • 但平台已经帮助数百万人开发和创造新产品、新服务与新公司。
  • 现阶段的成功不应只用应用商店收入衡量，更重要的是平台是否降低了开发门槛、扩大了创新规模。
  • OpenAI 对应用商店模式仍在持续探索，但开发平台本身已经创造了显著价值。

5.4 AI 模型公司会不会最终只剩一家？

  • 行业内大致存在两种观点：
  1. 未来全球最终只会剩下一家主导公司；
  2. AI 将推动公司和创业项目迎来复兴。
  • OpenAI 更认同第二种观点，认为创业门槛会大幅降低，一人公司和小型团队也能创造出重要产品与服务。
  • 模型实验室不可能覆盖全部行业、场景和创意，OpenAI 内部能够想到的愿景只占整体机会的一小部分。
  • 平台的战略任务不是吞噬所有应用，而是让更多开发者利用同样的工具创造新价值。

5.5 为什么允许用户携带自己的 ChatGPT 订阅使用第三方应用？

  • 传统 AI 应用开发者需要控制用户使用量，否则模型成本可能难以承受。
  • 为降低成本，开发者可能被迫使用更便宜但体验较差的模型。
  • 用户携带自己的订阅后，可以在订阅范围内使用所需模型，降低开发者的成本压力。
  • 对用户而言，也不需要为不同 AI 服务注册大量独立订阅。
  • 核心原则是：订阅属于用户，用户应该能够在任何想使用的地方方便地使用。
  • 这一机制有望扩大应用层创新，并帮助开发者更直接地连接真正需要其产品的用户。

5.6 OpenAI 最期待应用层出现什么产品？

  • 最期待的是当前尚未被 OpenAI 想到、也无法明确预见的新产品。
  • OpenAI 相信外部开发者的优秀想法远多于公司内部。
  • 目前这些新平台能力刚刚出现，尚未产生明确的代表性应用。
  • 但过去两年已经证明，AI 模型公司并未吞噬一切，反而不断催生重要的新公司和优秀产品。
  • AI 创业公司取得成功的速度，已经达到前所未有的水平。

6. 模型、Decisions API 与技术路线布局

6.1 Decisions API 的推出背景是什么？

  • Diogo 在 OpenAI 工作期间便长期探索相关思路，公司也持续研究如何将其产品化。
  • Luna 用户的首要诉求依然是模型更便宜、速度更快、能力更强。
  • 即使用户已经非常喜欢现有模型，也仍会持续要求降低成本和提升速度。
  • 市场对 Jev 的积极反馈进一步提升了 OpenAI 对这一方向的优先级。
  • Decisions API 的目标之一，是让 AI 在常见使用场景中实现极高速度和极低成本。

6.2 OpenAI 如何应对新模型架构和新实验室的竞争？

  • Jev 可能采取了与 OpenAI 不同的技术方法。
  • OpenAI 不确定是否会从头构建完全类似的技术，因为公司还需要推进其他核心事项。
  • OpenAI 的目标是在成本、速度、模态组合等帕累托曲线的不同位置，提供尽可能优秀、便宜、快速和能力强的模型。
  • 未来一定会持续出现新的架构、方法和技术，任何一家实验室都不可能覆盖全部路线。
  • OpenAI 将重点做好作为主线和核心工具的模型，同时通过平台为不同技术路线和应用创新提供空间。

7. AI 创业、组织规模与产品开发方式变化

7.1 当前是否处于 AI 创业的黄金时代？

  • 当前是一个令人兴奋的创业时期，初创公司可以以前所未有的速度获得成功。
  • AI 大幅降低产品开发和实验成本，使小团队甚至个人能够推进过去需要大型组织才能完成的项目。
  • 对投资而言，最重要的判断因素仍然是创始人：
  1. 是否具备突出能力；
  2. 是否在推进宏大的项目；
  3. 是否愿意承担足够大的风险。
  • 技术方向固然重要，但优秀创始人仍然是投资决策的核心。

7.2 “模型实验室会终结应用公司”的说法为什么没有成为现实？

  • 这类说法容易传播，是因为悲观叙事更容易吸引注意力，但实际上并未出现模型公司吞噬所有创业公司的情况。
  • OpenAI 的明确战略是赋能开发者，而不是成为包揽所有业务的庞大垄断公司。
  • OpenAI 向开发者提供与内部使用相同的工具，并持续扩大模型访问能力。
  • AI 带来的机会空间极大，单一公司无法覆盖所有领域。
  • AI 更像一种改变可能性边界的基础工具，OpenAI 希望将其交给所有人使用，而不是限制在自身内部。

7.3 AI 时代哪些创业原则不变，哪些原则需要重新审视？

  • 不变的原则是必须创造人们真正需要的产品。
  • 即使产品未来服务于智能体，最终仍然需要有人对相关产品或结果产生需求。
  • 需要重新审视的方面包括：
  1. 是否必须拥有传统意义上的联合创始人；
  2. 一人或两人团队能够完成多少工作；
  3. 创业融资结构是否仍适合新的成本结构；
  4. 团队规模、产品验证和增长路径是否需要重构。
  • 硅谷现有的创业流水线尚未充分适应个人和小团队生产力大幅提升的新现实。

7.4 AI 如何改变大型组织负责人的产品开发方式？

  • AI 显著降低了从想法到原型再到发布的阻力。
  • 借助 Dots，管理者可以利用零散时间或集中时间直接推进产品。
  • 过去使用 Codex 构建的项目可能主要供个人使用；现在则有机会跨过正式发布门槛，形成插件、扩展程序或真正的公司产品。
  • AI 不仅提升普通开发者效率，也使公司负责人重新获得直接参与产品创造的能力。
  • 即使大量尝试中最终只有一项真正出色，只要总体创造的社会效用提高，这种开发模式就有价值。

8. Ultrafast：速度、反馈循环与推理成本

8.1 是否所有提示词操作都使用 Ultrafast？

  • 回答者目前所有提示词操作都在 Ultrafast 上完成。
  • 由于已经适应极快的响应速度，其本人很难再切换回普通模式。
  • 同时也意识到，并非所有用户都能在所有任务中承担 Ultrafast 的使用成本。
  • 为避免与普通开发者的真实体验脱节，其本人也在主动为使用方式设置限制。

8.2 Ultrafast 为什么会显著改变工作方式？

  • 创作者应与正在创造的事物保持即时联系，速度和反馈循环对创造过程非常重要。
  • 快速响应不仅节省等待时间，更会改变人的迭代思考方式。
  • 无论是构建产品还是分析问题，低延迟都可以让用户：
  1. 更快尝试不同方案；
  2. 保持思维连续性；
  3. 获得更密集的反馈；
  4. 降低中途放弃的概率；
  5. 在单位时间内完成更多迭代。
  • 速度因此将成为继模型智能之后的另一个核心竞争维度。

8.3 高速模型是否会影响 AI 的普惠性？

  • 过去 OpenAI 主要关注降低“IQ 的价格”，即在提升模型能力的同时持续降低使用成本。
  • 当前公司已经意识到，速度也需要像智能能力一样被普惠化。
  • 自研芯片将发挥重要作用，帮助更多用户获得高速推理服务。
  • 模型研究、推理技术栈和基础设施也将共同推动速度提升。
  • 长期目标不是取消高价前沿产品，而是持续提高每1美元所能获得的智能和速度。

8.4 Ultrafast 未来的速度和价格趋势如何？

  • 当前用户可以付费获得 Ultrafast，但成本可能超出多数人的承受能力。
  • 预计不久后可以以极具竞争力的价格实现约8倍速度提升。
  • 同一时期，前沿产品可能已经达到接近100倍的速度，或出现类似“GPT7 Galaxy”的更高阶产品。
  • 在智能水平、速度和其他维度上，市场始终会存在价格更高的真正前沿产品。
  • 但每1美元所能创造的价值将持续快速提升，并呈现复利式增长，其速度可能超过传统摩尔定律。
