Meta Muse（M Agent）专家访谈纪要

1. 战略定位与发展目标

a) M Agent 的总体战略目标是什么，如何融入 Meta 生态？

  • Meta 将该项目的长期方向称为“North Star”，核心愿景是打造“Personal Super Intelligence（个人超级智能）”
  • 当前先进 AI 能力主要集中在管理者、白领和开发者等少数人群，Meta 希望依托约40亿月活用户，将智能能力分发给更广泛的普通用户
  • Muse 的定位不是单纯的聊天机器人，而是能够主动理解用户需求、调用工具并完成现实任务的个人 Agent
  • 长期来看，Muse 将与 Facebook、Instagram、WhatsApp、Messenger、Meta AI，以及未来的智能硬件深度融合，成为 Meta 面向用户的统一智能入口
  • 如果发展顺利，Muse 可能从美国市场开始逐步替代部分 Meta AI 和传统 Chatbot 的使用场景

b) Muse 与传统 Chatbot 的本质区别是什么？

  • Chatbot 主要销售模型的“智能水平”，不同产品之间的功能差异相对有限
  • Agent 在模型智能之外增加了 Tool Call、Computer Use、Connector、电话、长期任务管理等能力，销售的是“模型能够替用户完成什么”
  • Muse 可以主动读取信息、拆解任务、操作浏览器、持续追踪目标，并推动任务实现端到端闭环
  • Agent 的产品差异化空间明显大于 Chatbot，因此模型厂商有动力从 Chatbot 向 Agent 演进
  • 目前尚无 Chatbot 真正实现盈利，Agent 有望通过交易、广告及数据闭环建立更可持续的商业模式

2. 用户数据、增长表现与用户结构

a) Muse 当前的下载量和日活跃用户数是多少？

  • 产品上线初期，单日下载量不足10万，但随后增长较快
  • 每经过一个周末，下载量都会出现明显跃升，周末两天的下载量甚至可能超过工作日五天
  • 第二周开始，iOS 下载排名快速升至美区第二；访谈前约三天已连续位居美区下载榜第一
  • 当前日活跃用户数约为100万
  • 单日下载量尚未达到100万量级
  • 目前仅在美国市场开放，因此相关数据均为美国市场口径

b) 各终端用户占比如何？

  • iOS 用户约占70%
  • Android 用户约占15%
  • 网页端用户约占15%
  • 当前增长明显由移动端，尤其是 iOS 端驱动

c) 当前留存率、月活和使用时长如何？

  • 产品上线时间较短，目前尚未形成可靠的留存率和月活数据
  • 用户日均使用时长暂未掌握
  • 数据科学团队尚未完成完整的用户场景和行为分析报告

d) 当前付费用户和付费率如何？

  • 付费用户刚超过1,000人，付费率显著低于 ChatGPT 约6%的参考水平
  • Muse 提供每月20美元和100美元的订阅档位，但订阅目前不是主要变现渠道
  • 免费额度非常高，会议后文口径为每周约1亿 Token，普通生活场景用户很难耗尽
  • 只有将 Muse 用作生产力工具的重度用户，才较可能产生订阅需求
  • 因此，当前高免费额度虽然有助于快速获客，但也抑制了付费转化

3. 用户快速增长的核心原因

a) 为什么 Muse 能在短期内快速登顶下载榜？

  • 主要有三方面原因：
  1. 免费 Token 额度直观且具有营销吸引力
  1. 产品面向所有普通消费者，而非只面向技术、金融等专业人群
  1. Computer Use、Persistent VM 和生活服务闭环的体验较好

b) 免费 Token 策略为什么有效？

  • 其他 Coding Plan 或 Chatbot 的 Usage Credit 较抽象，用户难以直观判断可使用多少资源
  • 其他主流 Chatbot 的免费用户通常可以使用即时模型，但推理模型往往需要至少每月20美元的订阅
  • Muse 直接向用户展示约1亿 Token 的免费额度，让用户明显感知到“获得大量免费资源”
  • 这一策略可以快速吸引用户尝试，并降低新产品的使用门槛
  • 但该策略对应较高的 GPU、虚拟机和存储成本，长期需要商业化能力支撑

c) 面向普通消费者的设计体现在哪些方面？

  • Muse 从设计阶段就希望覆盖不熟悉 AI 的普通用户，包括中老年用户
  • 产品重点解决购物、餐厅预订、酒店预订、旅行规划、退货、联系客服等日常问题
  • 用户不需要理解模型、Token、Connector 或工作流，只需表达自然语言需求
  • 当前绝大部分任务集中于生活场景，几乎没有用户使用 Muse 编写代码

d) Computer Use 为什么成为关键体验？

  • Muse 可以在云端沙箱中通过浏览器执行点击、搜索、填写表单和下单等操作
  • 手机端能够可视化展示 Agent 的执行过程，用户可以看到其逐步完成任务
  • 相比只返回文字结果，可视化执行过程更容易建立“机器人正在替我办事”的感知
  • Muse 的执行速度较快，更符合移动端用户希望迅速获得结果的需求
  • Persistent VM 能够保存任务状态，支持长任务连续执行
  • 该能力技术壁垒并非不可复制，其他大厂看到模式成功后可能快速跟进

4. 核心应用场景与产品能力

a) 当前用户主要使用 Muse 完成哪些任务？

  • 初步观察中，电商购物和出行是两大头部场景
  • 电商场景包括：
  1. 商品研究与筛选
  1. 跨平台比价
  1. Coupon 和优惠券组合
  1. 下单购买
  1. 退货及与客服沟通
  • 出行场景包括：
  1. 机票和酒店预订
  1. 行程规划
  1. 餐厅推荐及预订
  1. 市内打车
  1. 本地游玩及餐饮建议
  • 订阅管理、省钱、理财和健康追踪等场景也有一定使用量
  • 目前整体仍以个人生活服务为主，而非工作和代码生产力场景

b) Muse 的购物能力与 ChatGPT、Gemini、亚马逊 Rufus 有何区别？

  • Muse 不仅完成购物研究，还能继续进行比价、优惠组合和下单操作
  • 同一商品可能在多个经销商处销售，Muse 可以跨平台寻找更优惠的交易
  • ChatGPT 等产品即使具备购物能力，也更多依赖接口查询，端到端操作体验相对有限
  • 亚马逊 Rufus 仅限于亚马逊平台，无法满足美国用户跨平台比价的需求
  • Muse 可以在手机端可视化展示搜索和点击过程，增强用户参与感和信任感
  • Muse 的优势是速度、执行闭环和跨网站操作，而非单纯提供商品推荐

c) Muse 的电话功能能够解决哪些问题？

  • Muse 可以代表用户致电企业，例如：
  1. 预订餐厅座位
  1. 获取修车报价
  1. 联系商家客服
  1. 处理退货或售后问题
  • 当前仅允许拨打美国黄页中的企业电话，不能拨打个人电话，以降低骚扰风险
  • Agent 会在通话开始时说明自己是 AI，并表示代表某位客户
  • 商家反馈不一：部分商家抵触 AI 电话，部分商家愿意积极响应
  • 当前电话功能上线时间较短，错误率仍然较高，商家和接听人员也处于适应阶段
  • 长期来看，愿意接受 Agent 电话的商家可能获得更多客户和更高转化

d) Muse 如何连接社交和通信工具？

  • Muse 通过 Connector 与 WhatsApp、Messenger 等产品连接
  • Connector 本质上是 API，可以读取和发送消息
  • Muse 不仅等待用户指令，还可以定时检查是否有新消息或待处理任务
  • 例如，Muse 可以定期查看工作群中的新信息，并主动完成其能够处理的事项
  • 很多生活任务的起点和终点都在社交媒体或即时通信工具中，这是 Meta 的重要生态优势

e) 理财和健康场景的进展如何？

  • Muse 理论上可以处理账户、投资组合和订阅管理等理财需求
  • 但用户需要提供较多敏感信息，建立信任仍需时间
  • Meta 尚未完成部分金融服务 Connector，例如 IBKR 等券商已经与 OpenAI、Claude 合作，但尚未与 Meta 打通
  • 对已经与其他 AI 平台建立 Connector 的服务商，通常可直接向 Meta 提供 API，主要障碍可能是分成和商务谈判
  • 健康方面已经接入 Apple Health、Fitbit 和部分跑步健身应用，可总结运动和卡路里消耗
  • 食物摄入追踪目前仍依赖用户拍照，自动化程度有限

5. 长期任务、记忆与个性化机制

a) Consistent Goal 功能是什么？

  • Muse 可以主动将用户的随口提问转化为长期目标
  • 例如，用户询问春假去佛罗里达哪里合适、哪几天价格便宜，Muse 可能自动建立 Goal
  • 建立目标后，Muse 可以每天持续查询机票价格、天气等信息
  • 与 Coding Agent 不同，用户通常不需要明确拆解 Deliverable，Muse 会主动规划任务
  • 该功能有助于处理长期、持续性任务，但也可能过度主动，用户需要手动取消不需要的 Goal

b) Ideas、Skills、Mini Chat 等功能使用情况如何？

  • Ideas 和 Skills 等高级功能当前使用量较低
  • 使用程度与用户的 AI Native 水平密切相关
  • 当前阶段的优先目标是扩大用户规模，没有通过强制 Tutorial 教育用户
  • 很多功能依赖用户自行探索，因此短期渗透率不高
  • 如果未来允许用户自由定义和添加 Skills，Muse 可能成为类似 App Store 的 Agent 能力分发平台
  • 这也有望帮助 Muse 进入程序员和生产力用户群体

c) Muse 是否会通过用户交互持续学习？

  • Muse 会比传统 Chatbot 主动记录更多上下文，包括：
  1. 用户做过什么
  1. 哪些任务最终完成
  1. 用户兴趣和偏好
  1. 长期目标及任务进展
  • 系统会持续运行 LM Call 和 Tool Call 循环，对用户行为进行上下文管理
  • 但这并不属于严格意义上的“持续学习”，因为模型权重并未针对单个用户发生变化
  • Muse 本质上仍是 Context Management，而不是为每位用户训练专属模型
  • 足够丰富的上下文能够支持高度个性化的下一步行动

d) Feed 功能未来如何发展？

  • Muse 计划推出类似 Meta AI 的 Feed
  • 由于产品高度私人化，不会直接展示其他用户的 Prompt 和生成内容
  • Feed 可能基于匿名化结果、社区趋势和用户历史上下文，向用户推荐可探索的内容及 Prompt
  • 当前 Ideas 主要围绕个人上下文生成想法，尚未形成成熟推荐系统
  • 长期可结合 Meta 擅长的搜索、推荐和广告能力，形成新的内容及商业分发入口

6. 隐私、数据安全与信任问题

a) Muse 如何处理用户登录信息和敏感数据？

  • 用户登录密钥被置于隔离沙箱中，Meta 理论上无法直接查看
  • 信息经过加密处理，采用类似 WhatsApp 的端到端加密技术
  • 但即便技术上实现隔离，用户对金融、健康等敏感场景建立信任仍需要时间

b) Meta 会保留哪些 Muse 数据？

  • 根据用户条款，如果用户没有主动选择退出，Meta 会保留用户与 Agent 的交互数据
  • Mac 桌面端推出后，Meta 不会直接保留用户电脑中的本地内容
  • 用户与 Agent 的对话、任务执行及相关交互数据可能用于改进模型和产品
  • Muse 的重要价值在于获得从需求产生到最终交易转化的端到端数据

c) Computer Use 存在哪些合规风险？

  • Muse 能够处理部分 CAPTCHA 或人机验证环节
  • 在某些情况下，Agent 可能以类似真人的方式通过验证，存在违反网站条款的风险
  • 随着任务规模扩大，网站封禁、平台限制、隐私和自动化合规可能成为重要约束
  • 亚马逊已经对 Muse 采取封禁措施，反映传统平台对 Agent 抓取和执行行为的警惕

7. 商业化路径与盈利模式

a) Muse 当前的成本结构如何？

  • Muse 仍处于亏损投入阶段
  • 免费 Token 即使考虑 Cache Read、Cache Write 按较低成本计价，每位活跃用户仍可能对应数十美元的 GPU 资源
  • 每位用户还可能产生约10—20美元的 Virtual Machine 成本
  • 随着用户规模扩大，VM 状态、日志、对话和长期任务的存储成本也会快速增长
  • 订阅收入现阶段只能覆盖部分成本，难以成为主要盈利来源

b) Muse 未来有哪些主要变现方案？

  • 主要有三条潜在路径：
  1. 成为操作系统或交易入口，从交易中抽佣
  1. 向商家收取广告费
  1. 利用端到端转化数据提升 Meta 原有广告业务效率

c) 交易抽佣模式如何实现？

  • 最激进的设想是将 Muse 打造成类似 iOS 的平台和系统入口
  • 当用户在 Muse 中完成大量日常消费操作后，平台可以从交易中抽成
  • 即使不收取苹果式的30%，仅收取5%，在物理世界消费规模下也可能形成可观收入
  • 真正落地抽佣的前提是掌握支付环节
  • 当前交易通常通过 Stripe 等合作方完成，Meta 在支付环节被绕过，因此缺乏稳定的收费抓手
  • 未来可能需要发展自有支付能力，或与 Visa、Mastercard、American Express 等机构合作
  • 目前与 Shopify、Stripe 的合作可能更侧重打通支付闭环，尚无明确抽成信息

d) 广告模式可能如何运作？

  • 当用户要求 Muse 执行任务时，可以优先召回付费商家
  • 具体方式包括：
  1. 将赞助商家排在推荐列表前列
  1. 在多个选择中优先展示广告客户
  1. 明确标注 Sponsor，避免误导用户
  • 广告可通过 Tool Call 外挂实现，Web Search 阶段同时召回自然结果和广告清单
  • 该模式将使广告从“面向用户展示”转向“面向 Agent 决策”，即 B2A（Business to Agents）
  • 商家的广告投入会直接影响 Agent 的召回和推荐顺序，因此需要处理商业利益与用户最佳选择之间的冲突

e) 端到端数据对 Meta 广告业务有什么价值？

  • iOS 隐私限制实施后，Meta 通常只能掌握广告点击的 First Hop
  • 例如，Meta 可以知道用户从 Instagram 跳转至旅行网站，但无法确认其最终是否购买机票、花费多少、目的地在哪里
  • Muse 控制浏览器并帮助用户完成购买后，Meta 可以掌握最后一环的转化信息
  • 这些信息能够显著改善广告归因、商家定价和投放优化
  • 如果 Muse 全面铺开，专家判断 Meta 整体广告转化率提升10%并不困难
  • 广告价格也可能相应提高约10%，仅此一项增量就可能覆盖 Muse 的运行成本
  • 相比订阅，端到端转化数据对 Meta 的商业价值更大

f) Agent 广告与传统社交广告有何不同？

  • 传统社交广告主要提供 Impression，广告主很难完整确认后续转化
  • Agent 可以直接连接用户需求、推荐、下单和支付，提供结果型归因
  • 广告主可以明确计算每投入1美元带来多少实际订单
  • 未来2—3年，单纯依赖 Impression 的社交媒体广告可能相对落后，但不会完全消失
  • Agent 不受传统屏幕展示位稀缺性的限制，因此其广告定价机制可能不同于当前竞价广告
  • 行业尚未形成成熟的 Agent 广告定价方法

8. 商家、聚合平台与产业链影响

a) Agent 是否会削弱传统聚合平台的价值？

  • Agent 可以直接联系商家，但短期内不会完全绕过现有聚合平台
  • 例如，用户通过 Muse 点外卖时，系统通常仍会打开 Uber Eats 或 DoorDash，而非直接联系餐厅
  • 很多商家已经习惯聚合商提供的支付、履约和订单系统，甚至没有独立电子支付能力
  • 聚合平台可以主动与 Agent 建立更深连接，从而保持自身价值
  • Agent 更可能改变流量入口和排序权，而非立即消灭聚合平台

b) 为什么亚马逊率先封禁 Muse？

  • 亚马逊除电商收入外，广告也是重要利润来源
  • Muse 代替用户搜索和选择商品，会削弱亚马逊原有广告排名体系的价值
  • 美国综合电商市场集中度高，亚马逊拥有较强封禁底气
  • Uber Eats、DoorDash 等平台广告收入占比较低，更可能将 Muse 视为流量来源
  • 当市场存在多个竞争平台时，单个平台不敢轻易封禁 Agent，否则流量可能转向竞争对手
  • 如果用户高度依赖 Muse 完成购物，亚马逊未来也可能重新评估与 Agent 的合作关系

c) Agent 是否会扩大 Meta 的广告市场？

  • Meta 服务大量中小商家，其中很多过去没有能力直接投放广告
  • Agent 可以帮助这些商家更精准地触达有明确需求的用户
  • 对商家而言，Agent 广告具备更高的购买意图和更可量化的转化结果
  • 广告转化率和广告单价均可能提升
  • 是否快速发生取决于用户习惯变化速度，以及 Muse 等个人 Agent 的普及程度

9. C端市场空间与渗透逻辑

a) 个人 Agent 的长期用户规模可能达到多少？

  • Meta AI 当前已有超过10亿月活用户，因此 Muse 达到10亿月活具备生态基础
  • 如果 Agent 的使用体验接近 Chatbot，至少可以替代部分 Chatbot 需求
  • Muse 未来可能先在美国市场逐步渗透，再扩展至更大范围
  • C端 Agent 的最终用户规模有望与现有大众型 Chatbot 接近

b) C端 Agent 普及的主要驱动因素是什么？

  • 购物比价、旅行预订、表单填写、退货和联系客服等任务本身繁琐且高频
  • Agent 可以将用户从多个网站、账号和操作步骤中解放出来
  • 用户只需用一句话表达需求，就可以由 Agent 完成后续操作
  • 相比 B 端强生产力需求，C端付费意愿可能较弱，但用户规模和交易规模更大
  • 如果产品能够建立信任并形成使用习惯，C端市场可能成为更大的流量和交易入口

10. 竞争格局与 Meta 的核心优势

a) Muse 相比 AI Lab、OpenAI、Claude 等厂商有哪些优势？

  • Meta 的优势主要来自社交生态闭环，而非模型能力的绝对领先
  • 大量生活任务起点和终点位于 Facebook、Instagram、WhatsApp、Messenger
  • 用户可以从社交内容触发购物或旅行需求，完成后再回到社交平台分享
  • 家庭或工作群聊中的任务也可以直接交由 Muse 处理，再将结果返回群聊
  • Meta 同时拥有模型、社交关系、消息、推荐和广告能力，具备完整闭环基础

b) 模型智能是否构成决定性壁垒？

  • 生活任务对模型智能的要求不像 Coding 任务那样存在显著代际差异
  • Meta 已使用一款规模约为主模型四分之一的蒸馏模型处理大量请求
  • 在 Meta AI 中，超过一半请求可以由蒸馏模型处理，用户满意度仅相差几个百分点
  • 更强的大模型往往速度慢、成本高，不一定适合大规模 Personal Agent
  • 在个人 Agent 场景中，生态、成本、速度、Connector 和执行能力可能比单纯模型参数更重要

c) 苹果和手机厂商为什么是最强潜在对手？

  • 最具竞争力的 Agent 形态可能是直接运行在手机和操作系统层
  • 手机 OS 可以获得本地文件、消息、App 和系统权限，实现真正的本地执行
  • Muse 当前主要在云端沙箱运行，只能操作网页，无法直接操作手机 App
  • 在中国等 App 主导的市场，网页端可完成的任务有限，手机 OS 的优势更加明显
  • 苹果拥有庞大设备用户基础，Siri 的定位也可能升级为个人 Agent
  • Android 生态则取决于谷歌如何推进 Gemini 与系统权限融合

d) 苹果隐私政策对 Agent 竞争有何影响？

  • Agent 需要积极获取用户上下文，才能执行长链条任务
  • 如果每个步骤都反复请求授权，用户很难持续推动任务完成
  • 苹果对隐私较为保守，这可能限制 Apple Intelligence 和 Siri 的主动性
  • Meta 已与苹果沟通，并接入部分苹果第一方 Connector
  • 如果 Siri 与 Muse 形成直接竞争，苹果未来可能减少数据和 Connector 支持
  • 但 Muse 手机端对 iOS 系统权限依赖较低，大量操作在云端完成，因此苹果可直接限制的空间有限
  • 苹果也不太可能通过下架等恶性方式竞争，否则会破坏开发者生态信任

e) 未来竞争格局会由哪类企业主导？

  • 三类厂商均有胜出机会：
  1. 模型厂商：具备模型和 AI 产品创新能力
  1. 社交平台：掌握用户关系、消息和内容场景
  1. 手机及操作系统厂商：掌握本地权限和设备入口
  • Meta 虽具备社交和模型双重优势，但产品执行失败的风险仍然存在
  • 在中国市场，腾讯等社交平台、手机厂商、模型公司及拥有电商能力的阿里均具备竞争空间
  • 当前 Muse 的先发优势明显，但 Computer Use、Persistent VM 和电话能力并非不可复制

11. 技术架构、资源需求与基础设施

a) Muse 复用了哪些关键底层技术？

  • 最典型的底层能力是 Persistent VM
  • 该技术可以快速启动、暂停和保存虚拟机状态，而不需要让 VM 24小时持续运行
  • Persistent VM 使浏览器控制、工具调用和长任务连续执行成为可能
  • 早期相关理念来自先行团队的探索，后续 Computer Use Agent 主要由 Muse 团队自行研发
  • 当前直接复用的能力已经不多，主要继承了 VM 快速启动和状态保存方面的经验

b) Muse 对 GPU、CPU 和存储的需求如何变化？

  • 当前 GPU 和 CPU 的需求量大致相近
  • 长期来看，存储需求可能比 CPU 需求增长更快
  • 普通 Chatbot 主要保存日志、对话和 Memory File
  • Agent 还需要保存 VM 状态、浏览器环境、任务进度、Tool Call 记录和长期 Goal
  • 如果未来达到10亿用户规模，不能因用户暂时不使用就删除其 VM 状态和日志，因此存储压力会非常大
  • CPU 消耗主要随用户数量和每日 Session 数量增长，预计与 GPU 需求同步，不会出现数倍于 GPU 的增长

c) 是否会利用闲置 H100 开展云服务？

  • 闲置 H100 理论上可以出租
  • 但外部市场对 H100 租赁的兴趣有限
  • 自建新的云服务平台需要投入大量运营精力，因此目前是否推进尚不明确

d) Muse 的组织推动机制是什么？

  • 当前组织落地主要由企业团队推动
  • 会议未进一步披露具体负责人、跨部门协作方式及主要组织困难

12. 当前主要风险与关键待解问题

a) Muse 当前面临哪些核心风险？

  • 商业化尚未确定，免费额度和 VM 成本造成持续亏损
  • 用户留存、月活和使用时长尚未经过充分验证
  • 订阅付费率较低，短期难以依靠会员收入覆盖成本
  • 金融、健康等高价值场景需要用户提供敏感信息，信任建立较慢
  • Connector 数量仍少于主要竞争对手
  • 电话功能错误率较高，商家对 AI 通话接受度不一
  • CAPTCHA 处理及自动化操作可能违反部分网站条款
  • 亚马逊等平台可能采取封禁，限制 Computer Use 能力
  • 苹果等 OS 厂商可能减少 Connector 和数据开放
  • 广告排序可能影响 Agent 的中立性和用户信任
  • 交易抽佣需要解决支付入口问题，目前尚未看到明确落地路径
  • Computer Use 和 Persistent VM 的技术壁垒有限，竞争者可较快复制

我们的做法比较直接，明确告诉用户，免费Tier就有1亿token。从营销角度看，这会吸引很多用户来使用这1亿token，因为所有人都会认为这是免费获得的1亿token。

第2个原因是，我们从一开始就希望服务所有用户，而不仅是科技、金融等少数行业的用户。比如阿姨、大妈，甚至祖辈级用户，都可以轻松上手。因此，我们的一些功能也是按照这一目标设计的。

提问者：Mewss在满足用户日常生活需求、提供个人助手服务及提升模型运行效率方面有哪些特点？

回　答　者：Mewss非常贴合日常生活需求。尤其是在美国，很多功能需要通过网页端完成，不像中国主要通过APP完成。目前，大家发现Mewss最好用的功能包括在线购物、预订餐厅、预订酒店和安排行程等。它还可以连接社交媒体，例如WhatsApp和Messenger，整合相关信息并形成闭环。用户不需要将消息复制粘贴给AI chatbot，Mewss会主动查看信息。比如，用户的微信中有工作群，Mewss可以每隔1、2个小时查看1次，并主动处理它能够解决的问题，真正发挥个人助手的作用。

这也比较贴合美国的实际情况。在国内，通过淘宝购物非常简单，但在美国，用户需要前往各个品牌的官网购买商品，因此可能要创建100多个，甚至几1000、几10、几100个账号。退货也不像淘宝的7天无理由退货那么简单，用户需要分别在各个网页上进行操作。有时超过7天后仍想退货，还需要打电话与客服沟通，很多事情都需要通过电话完成。

Mewss有1个独特功能，即帮助用户打电话。据我所知，目前在美国还没有其他AI agent能够如此便捷地帮助用户完成打电话这件事。具备电话功能后，它可以帮助用户处理很多与客服沟通相关的问题。目前，该功能仅向美国黄页中收录的企业开放，不能拨打个人电话，以避免骚扰。因此，它可以致电企业，例如帮助用户向餐馆预订座位。这直接解决了用户日常生活中的很多问题。

第3点是Mewss背后所接模型的效率较高，其中很大部分涉及computer use。其他的NCP和connector功能已经被3家主要chatbot整合。通过NCP直接调用API以及通过connector API能够完成的事情，这3家主要chatbot也可以完成，Mewss同样可以完成，只是其connector的数量比它们少很多。

不过，Mewss的computer use使用体验非常流畅，并且会提供1个persistent VM，在1个shop中帮助用户通过浏览器完成操作。它甚至有可能处理接近小一半的captcha，即人机检测环节。相比之下，如果让Codex桌面端通过computer use处理这些问题，它有时会直接拒绝，并要求用户自行take over browser完成操作。但Mewss会帮助用户处理这些环节。这实际上可能涉及说谎，甚至违反部分网站条约，因为它明明是机器人，却声称自己不是机器人，以此解决相关问题。

提问者：我们去年已经观察到很多产品推出了类似功能，尤其是ChatGPT和谷歌Gemini，包括购物、订阅餐厅等功能。谷歌在过去2年也通过Gemini推出了打电话等功能，我记得它曾在某次I/O大会或其他场合展示过。ChatGPT去年年底也在开发购物功能。为什么Meta此次推出的Muse会比前2个产品获得更好的市场反馈？

回　答　者：我认为，这些产品的功能与我们所做的仍有较大差异，哪怕只是拖动滑块，这些不同之处也是Muse使用量能够快速上升的原因。

完成研究后，Muse有时会直接询问用户是否需要下单。普通消费者通常会要求它寻找最优惠的交易。Muse会通过小窗口给出3个最推荐的选项。用户可能选择第2款，并要求Muse进一步比较价格。由于美国市场不像国内购物主要集中在淘宝等平台，同一款商品可能有5、6、7、8个经销商，Muse可以比较不同经销商的价格，并综合考虑各种coupon和优惠券的叠加方式，而且能够快速返回结果。

亚马逊也有名为Rufus AI的assistant，但速度慢很多，而且仅限于亚马逊平台。美国用户通常希望跨平台比价。假如亚马逊类似于京东，用户肯定也希望在京东和淘宝之间进行比较，而Rufus AI无法做到这一点。

回　答　者：从API表现来看，Muse的速度是最快的。很多时候，用户在生活场景中希望快速获得结果，尤其是在手机端。电脑端用户可以打开1个标签页，先查看其他内容，之后再返回，但手机端的使用方式有所不同。

Muse能够快速以沙箱形式提供结果。即使ChatGPT能够完成类似任务，采用的仍是类似NCP的形式，通过相关接口进行查询。用户最享受的是观看1个Agent执行操作，因为手机端也可以呈现沙箱的可视化过程。用户可以看到它像机器人一样在窗口中进行操作、点击和逐个搜索产品。这种体验是目前其他几家Chatbot无法提供的。
