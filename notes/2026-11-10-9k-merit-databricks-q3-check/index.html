专家访谈纪要：Databricks增长、企业AI落地与竞争格局

1. Q3经营表现与ARR增长结构

a) Databricks Q3的收入及增速表现如何？

  • Q3观察到的整体经营增速较强：
  1. 同比增长约58%。
  2. 环比增长约18%。
  3. 合并口径下，Q3整体收入退出模型约为81亿美元。
  • 访谈中另提到“Q3 ARR约为18亿美元”，与前述Q2 ARR约70亿美元及Q3收入退出模型口径存在明显差异，可能涉及统计口径或转录误差，建议后续进一步核实。

b) ARR增长主要来自新客户还是现有客户？

  • ARR增长中，现有客户扩张是主要驱动力：
  1. 20%来自首次在Databricks部署的净新增客户。
  2. 80%来自现有客户增长。
  • 现有客户贡献的80%增长可进一步拆分为：
  1. 45%来自新增工作负载，包括新数据管道、数据仓库迁移、AI服务及Lakebase等。
  2. 35%来自现有工作负载自然增长，包括数据量增加、并发提升及部分资源规格优化。
  • 整体看，Databricks当前增长仍主要依赖存量客户不断扩充使用场景，而非单纯依赖新客户获取。

2. Token消费趋势与企业AI预算变化

a) 达到Token预算上限的客户，下半年消费是否放缓？

  • 部分客户上半年已经达到Token预算上限，下半年对价格更敏感，使用策略也更加精细化。
  • 上半年Token消费增长较快，但增速已有所放缓：
  1. 以Foundation Model API（FM API）为例，Q1增速高于Q2。
  2. Q1启动的部分试点项目已经进入生产阶段，推动整体推理费用增加。
  3. 尚处于试点阶段的客户则出现项目延期或推进速度低于预期的情况。
  • 客户并非完全没有Token预算，而是在有限预算下更加重视成本规划、模型选择和使用效率。

b) Token价格、使用量和客户总支出分别如何变化？

  • 当前Token经济模型呈现“量增价降、总支出下降”的特征：
  1. Token价格下降约25%。
  2. Token使用量增长约20%。
  3. 客户整体Token净支出下降约10%。
  • 客户原本可执行100个任务，现在可执行约120个任务；单位任务成本下降，使任务量增长尚未完全抵消价格下降。
  • Databricks此前已预期Token降价会对推理业务收入造成短期压力。

c) Unity AI Gateway如何帮助客户控制Token成本？

  • Unity AI Gateway可以将请求分配至不同模型，在高性能模型与低成本模型之间进行负载均衡。
  • 其主要能力包括：
  1. 模型路由与请求分配。
  2. Token成本控制。
  3. 使用量和预算跟踪。
  4. 限流与访问权限管理。
  5. 在多个模型供应商之间实现集中管理。
  • 客户可在保证性能的同时，将部分任务分配至成本更低的模型，从而提升整体AI投入效率。

d) 当前客户主要在哪些Databricks AI产品上产生Token支出？

  • 客户Token支出主要集中于：
  1. Agent Bricks，用于构建定制化智能体。
  2. FM API。
  3. Databricks托管模型。
  4. 其他基于Databricks构建的AI应用。
  • Genie Agent目前产生的Token成本仍由Databricks承担，客户暂时无须支付相关费用。
  • 因此，当前Token支出增长主要来自定制智能体和模型推理，而非Genie Agent。

e) Token支出下降是否意味着Databricks未来收入增速放缓？

  • 短期内，Token价格下降确实会对推理收入形成压力，但专家认为这一现象偏阶段性。
  • 预计未来两个季度模型支出将重新增长，原因包括：
  1. 当前大量POC和试点项目将逐步投入生产。
  2. 更多智能体及AI应用进入生产环境后，Token消耗将明显扩大。
  3. 数据迁移项目正处于高速增长期，更多数据进入Databricks后，客户更容易在数据之上构建智能体。
  4. 迁移带来的综合消耗增长预计在明年Q2集中体现。
  • 因此，短期“量增价降”可能压低账单，但中期生产级用例扩张有望重新推动总消费增长。

f) 为什么企业当前AI任务量低于预期？

  • 主要受预算周期和项目成熟度两方面影响：
  1. 多数客户年度预算已经耗尽或仅剩少量预算。
  2. 剩余预算通常仅能支持小规模POC或POV，无法支持全面生产部署。
  3. 客户倾向于将项目延后至明年2月或3月启动。
  4. 部分试点仍需完成技术、权限、治理及法律审批。
  • 当前客户未来两个月可使用的预算通常约为2.5万至20万美元，主要用于试点验证。

g) 明年企业AI预算和Token消耗预计增长多少？

  • 预计明年Q1，即2月至4月，Token消耗量较当前增长25%至30%。
  • 根据与客户的沟通：
  1. 企业整体AI预算预计同比增长约40%。
  2. 平均增幅可能达到40%至45%。
  3. 部分客户会优化传统基础设施工作负载，将更多预算转向AI。
  4. 企业也会适度增加整体IT预算，以匹配AI投入增长。
  • 明年增长的主要触发因素是预算重置，以及当前POC、POV逐步转入生产。

3. 企业AI应用场景与落地进度

a) 除编程外，Databricks上哪些AI场景正在加速？

  • Databricks客户当前主要投入并不集中于编程，而是集中在智能体和企业数据分析场景。
  • 排名靠前的应用包括：
  1. 员工知识助手，是当前最主要的智能体用例。
  2. 财务和运营分析，包括成本差异解释、库存异常调查等。
  3. 基于精选数据集或金表开展智能分析。
  4. IT服务台与支持运营，包括工单分类、运行手册检索和回复起草。
  5. 文档密集型后台工作流。
  • 智能体使用量增长主要由文档密集型任务驱动，编码场景占比相对较低。

b) Databricks以外，企业还在加速部署哪些通用AI应用？

  • Azure Databricks客户广泛使用Azure，通过相关平台或Azure Copilot构建智能体。
  • 在后端模型选择方面：
  1. 许多客户更倾向使用Claude。
  2. 访谈反馈认为，基于Anthropic模型的智能体在准确性和运行表现方面优于OpenAI模型。
  • AWS客户则更多采用可在图形用户界面或VDI中运行的智能体：
  1. 通过模拟点击、复制和录入完成跨系统流程。
  2. 适用于SAP等不便通过API直接提取数据的系统。
  3. 在医疗、发票处理、采购到付款等场景中日益普及。

c) 企业级智能体的部署规模和Token消耗量如何？

  • 文档密集型后台工作、VDI智能体等场景，采购方式正从企业集中采购转向部门或业务单元采购。
  • 单个智能体集群通常包含约30至50个智能体。
  • 对大型企业而言：
  1. 单一用例可能部署约40个智能体。
  2. 每月Token消耗量约为500亿至800亿。
  • 当前部署仍以单部门、单场景为主，尚未普遍形成企业级统一规模化应用。

d) 美国和欧洲企业AI用例的生产化程度如何？

  • 北美企业整体进展快于欧洲：
  1. 美国约25%至30%的AI用例已投入生产。
  2. 欧洲约18%至24%的用例已投入生产。
  • 欧洲进展较慢的主要原因是监管、法律和审批要求更严格。

e) 企业扩大AI部署面临哪些主要障碍？

  • 第一个障碍是权限与访问管理：
  1. 需要明确哪些用户能够访问哪些智能体和应用。
  2. Databricks UI更适合管理员，普通用户更多通过Teams、Copilot、Codex等入口调用应用。
  3. 企业需要建立跨平台的身份、权限和应用分发体系。
  • 第二个障碍是法律与治理审批：
  1. 需要明确使用哪些模型。
  2. 明确哪些数据会进入模型。
  3. 明确哪些数据不会向外部模型共享。
  4. 需要形成完整文档和审计保障。
  • 第三个障碍是组织所有权：
  1. 企业正在建立AI卓越中心。
  2. AI管理主体正从传统IT或数据工程团队转向跨部门治理组织。
  3. 多团队、多平台和多智能体环境的统一治理框架尚未成熟。
  • 多数客户只有在权限、合规和所有权框架建立完成后，才会将工作负载正式投入生产。

4. Databricks与Snowflake的增长差异及竞争格局

a) 为什么Databricks收入增速快于Snowflake？

  • Databricks不再依赖单一数据业务，而是围绕现代应用和AI智能体持续扩展产品边界。
  • 主要增长路径包括：
  1. 客户从Spark和数据工程开始使用。
  2. 进一步扩展至数据仓库。
  3. 增加模型服务和智能体服务。
  4. 引入PostgreSQL数据库及应用场景。
  5. 使用Lakehouse作为智能体记忆层。
  • 新产品和新市场包括：
  1. 面向营销场景的Customer Lake。
  2. 面向SIEM和安全场景的Lake Watch。
  3. Databricks Apps。
  4. Lakebase/PostgreSQL相关产品。
  • 相较Snowflake，Databricks数据仓库总体支出更低，也是部分客户迁移至Databricks的原因。
  • 更核心的差异在于，Databricks持续将收入或融资重新投入创新，通过新产品进入安全、营销、智能体工作流等增量市场。

b) 企业更倾向双平台并行，还是向单一平台整合？

  • 许多客户曾尝试同时维护Databricks和Snowflake，但双平台会削弱Lakehouse统一数据架构的价值。
  • 当前多数客户正在向其中一个平台整合。
  • 从实际迁移案例看，迁移至Databricks的案例更多，部分Snowflake客户正在转向Databricks。
  • 随着企业降低双平台成本和复杂度，两家公司之间的竞争预计将进一步加剧。

c) Databricks与Snowflake的能力差距会扩大还是缩小？

  • 专家判断差距可能扩大，主要原因包括：
  1. Databricks持续投入湖仓智能体和智能体记忆。
  2. Databricks正大力建设本体层，为智能体提供企业上下文。
  3. 本体层有望提升智能体准确性，并推动Databricks各类产品无缝协作。
  4. Databricks更倾向主动进入新市场，而Snowflake更多是在识别客户流失原因后补齐差距。
  • Databricks现有客户黏性较高，下一阶段重点是通过新产品获取更多客户并扩大市场覆盖。

5. Unity AI Gateway的战略价值与商业化路径

a) 为什么厂商都在投入模型路由和Agent权限管理？

  • 随着智能体进入生产环境，企业需要明确：
  1. 智能体可访问哪些模型。
  2. 智能体可调用哪些工具和技能。
  3. 不同部门可使用多少预算。
  4. 请求应如何在不同模型间分配。
  5. 如何监控、审计和治理MCP、Skill及其他AI资产。
  • AI Gateway正在成为企业生产级智能体环境的关键控制层。

b) Databricks在AI Gateway领域的优势是什么？

  • Databricks已有Unity Catalog，可治理数据、工具和AI函数。
  • Unity AI Gateway在Unity Catalog基础上扩展了：
  1. 模型路由。
  2. 模型成本控制。
  3. 请求负载均衡。
  4. 使用量及预算跟踪。
  5. AI Agent、MCP和技能治理。
  • Databricks约60%的销售或售前团队已经在与客户讨论Unity Gateway。
  • 如果客户的大部分数据和工作负载已经位于Databricks，通常不会再额外采购第三方Gateway工具。

c) Unity AI Gateway如何推动Databricks收入增长？

  • 收费方式取决于模型来源：
  1. 使用Databricks托管模型时，按Model Serving条款收取推理费用。
  2. 客户使用自有OpenAI、Anthropic或Bedrock合同时，Unity Gateway负责跟踪和估算用量。
  3. Gateway在使用跟踪、控制和治理过程中产生的计算资源消耗可向客户收费。
  • 商业化节奏预计分为两个阶段：
  1. 初期几个季度不直接对Gateway产品收费，优先提高采用率。
  2. 当客户大部分AI治理工作迁移至Unity Gateway后，再基于计算资源消耗收费。
  • 推广方式类似Genie Code和Genie Agent，先通过免费或低门槛培育用户习惯，再逐步商业化。

d) 哪类厂商最可能成为统一Agent管理入口？

  • 最终胜负取决于企业选择在哪个平台整合Agent及数据。
  • 对高度依赖Microsoft的企业：
  1. Microsoft具备默认Agent管理控制台优势。
  2. Azure Databricks是Azure上的第一方服务。
  3. 数据通常存储于Databricks或Microsoft Fabric。
  • 专家判断Microsoft与Databricks最有可能在统一Agent管理入口竞争中胜出。
  • 核心逻辑是“数据在哪里，Agent就会部署在哪里，Gateway也会随之部署在哪里”。
  • 相较之下，AWS Lake Formation、GCP BigQuery等湖仓产品的客户使用广度暂时较弱。

6. Genie Code采用情况及迁移价值

a) Genie Code当前企业客户渗透率如何？

  • Databricks计划在截至2027年1月前持续提供Genie Code免费额度，以推动采用率。
  • 当前采用情况包括：
  1. 约90%的客户已以某种形式接触或采用Genie产品。
  2. 约45%至50%的客户正使用Genie Code修改代码或在Databricks上部署服务。
  3. 已开始使用Genie Code的客户中，约40%保持持续使用。
  4. Genie Code请求量正以60%至70%的幅度增长。
  • 相较Claude或Codex，Genie Code的优势是无需额外集成，客户在Databricks内部即可直接使用。

b) Genie Code如何帮助客户加快迁移？

  • Databricks正将迁移产品和加速器围绕Genie Code构建，重点覆盖三类迁移：
  1. 数据仓库迁移：将Synapse等数据仓库迁移至Databricks。
  2. 报表迁移：将Tableau、Power BI、Qlik等报表迁移至Databricks。
  3. ETL迁移：将Informatica等ETL工具迁移至Databricks。
  • 在报表迁移中，客户可将仪表板截图导入Genie Code，并在Databricks上生成AI/BI仪表板。
  • Databricks也在推动合作伙伴使用Genie Code而非Anthropic或OpenAI产品构建迁移加速器，从而加强生态绑定。

7. 行业采用差异与重点增长领域

a) 哪些行业的Databricks采用最成熟？

  • 当前成熟度和支出较高的行业主要包括：
  1. 数字原生企业，包括软件、SaaS和数字商务企业。
  2. 金融、银行和保险企业。
  3. 医疗健康和生命科学企业。
  • 金融行业可在Databricks上运行信贷承保、支付、审计等大量场景。
  • 医疗健康和生命科学增长强劲，部分客户在Databricks上的ARR支出已超过1,000万美元。
  • 金融行业也存在类似的大额客户支出。

b) 哪些行业是下一阶段重点增长领域？

  • 制造、汽车和物流是增长较快但尚未充分开发的领域。
  • 核心驱动力包括：
  1. 这些企业拥有大量SAP数据。
  2. SAP与Databricks的合作关系正快速发展。
  3. 企业希望降低SAP数据许可和处理成本。
  4. 数据进入Databricks后，可进一步构建智能体和AI应用。
  • 当前Databricks承载和处理SAP数据的能力仍不够成熟，因此制造和汽车行业的完整迁移周期将长于金融和医疗行业。

c) 制造和物流行业主要部署哪些AI场景？

  • 制造业主要场景包括：
  1. 财务现代化及综合报告。
  2. 预测性维护，预测工厂设备故障。
  3. 视觉质检，识别缺陷、误拒和报废问题。
  4. ESG动态报告与碳排放管理。
  • 物流行业主要场景包括：
  1. 运力预测。
  2. 需求规划。
  3. 路线规划。
  4. 交付预计到达时间预测。
  5. 财务和税务现代化。
  • 物流企业希望通过AI将预测准确率在当前基础上再提升4%至5%。
  • 大量企业仍使用Excel进行数据处理，正尝试迁移至AI/BI仪表板，并通过智能体查询定价、转移定价及财务数据。
  • 当前采用仍以部门为单位，尚未形成全企业集中式部署。

8. FDE团队与企业AI落地效率

a) FDE能否加快传统行业的AI应用落地？

  • Databricks和Snowflake均在加大FDE团队投入。

  • FDE可以通过框架和智能体执行ETL、数据仓库及其他迁移工作，部分客户无法自行完成的智能体迁移也可由FDE实施。

b) Databricks如何向大客户配置FDE资源？

  • Databricks更关注客户3至5年的长期承诺，而非单年合同。
  • 对承诺金额在1,000万至8,000万美元的大客户：
  1. Databricks会提供较多成功积分。
  2. 成功积分通常约为40万至80万美元。
  3. 客户可使用成功积分部署FDE，推动具体用例落地。
  • 有FDE参与的项目，用例投入生产的速度比客户自行实施快约120%。
  • 当前FDE资源已经较为紧张，多数人员已部署或需要覆盖大量项目储备，Databricks正在继续扩大投入。

9. 明年Q2成为AI消耗拐点的原因

a) 为什么企业AI消耗可能在明年Q2明显加速？

  • Databricks销售团队倾向将项目启动延后至2月，以计入新财年的销售目标。
  • 预计项目从2月开始启动，经过部署和爬坡后，迁移与生产化带来的消费增长将在明年Q2更明显地反映出来。

10. Lakebase/PostgreSQL与传统数据库竞争

a) Databricks与PostgreSQL融合是否会侵蚀MongoDB等数据库厂商的份额？

  • 在使用PostgreSQL作为智能体记忆层的场景中，Databricks与MongoDB竞争激烈。
  • Databricks已拥有至少5至8个在智能体记忆场景中击败MongoDB的客户案例。

b) Databricks希望通过Lakebase进入哪些市场？

  1. Microsoft相关数据库和应用平台。
  2. MongoDB。

  • 战略目标是将数据层、应用数据库、智能体记忆、Unity Catalog和AI治理整合在同一平台上，进一步扩大客户工作负载覆盖范围。
