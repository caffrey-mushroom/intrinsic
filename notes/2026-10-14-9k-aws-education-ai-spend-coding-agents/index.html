摘要

2026 年第三季度，亚马逊云科技在教育技术领域的支出增长约为 2% 至 5%，保持在典型的 3% 至 5% 区间并符合行业预测与预算，没有出现负向偏差，但工作日减少限制了环比增长；AI 支出增长约为 10%，但仅占业务的约 7% 至8%，增量 AI 预算仍然有限，持续投入主要集中在编码工具、检索增强生成、语义搜索、文档处理和课程合规性方面；智能体式人工智能尚未超出有限的概念验证规模，原因在于 token 使用难以预测与控制，而 Amazon Nova 与 AWS Trainium 仍侧重于更简单、对成本敏感的工作负载

要点

  1. 在 2026 年第三季度，亚马逊云科技教育技术支出约增长 2% 至 5%，保持在典型的 3% 至 5% 区间，并与行业预测和预算吻合，未出现负向偏差，尽管较少的工作日限制了环比增长
  2. 教育技术领域的 AI 增长约为 10%，快于行业整体 2% 至 5% 的增长，但在不同客户间差异很大，从一些大客户的 1% 至 2% 到另一些客户的 100% 至 120% 不等
  3. AI 占比低于 10%，估计约为 7% 至 8%；例如年支出 1000 万美元的账户可能在 AI 上仅支出约 50 万美元，表明客户是在新增适度的增量预算，而非取代现有 IT 项目
  4. 试点之后的支出以 Claude Code、OpenAI Codex、文档与语义搜索、检索增强生成、智能文档处理，以及对课程与评分细则相对于州要求和共同核心州立标准的自动比对为主
  5. 在教育技术中仅有一到两个智能体项目和若干智能体式人工智能计划处于概念验证阶段，生产化扩展受限于难以预测、监控与控制 token 使用以及护栏不足
  6. 战略性客户继续偏好封闭和前沿模型，而 Amazon Nova 在模型分层架构中仅占极小份额，AWS Trainium 的采用主要集中于轻量级、低端的训练工作负载，未引发显著的客户转变或营收贡献

Q:今天的讨论聚焦于 AWS 和 Amazon 在 2026 年第三季度的企业 AI 业务。先从 AWS 开始，整体增长趋势如何？在相关领域或公司层面，AWS 在第三季度的支出有何变化？

A:总体来看，我认为趋势是积极的。教育技术领域的趋势也呈现积极，但这一评估仅限于该行业。

Q:你有具体数据吗？或者与上一季度相比，该领域大约录得了多少百分比的增长？如果你了解整体情况，你会将增长定性为强劲、适中，还是符合指引？

A:我没有公司层面的全盘数据。在教育领域，我认为增长大约在 5%，或在 2% 到 5% 的范围内。整体公司的增长率可能要高得多，但教育领域的增长通常在 3% 到 5% 之间，目前仍在该范围内。

Q:增长有多少来自 AI，多少来自非 AI 服务？在相关领域你观察到的情况如何？

A:AI 的增长在不同账户间差异很大。在一些大客户中，大约是 1% 到 2%，而在另一些则可能达到 100% 到 120%。总体上，AI 的渗透率仍然偏低，其增长率看起来在大约 10%左右。它的增长快于其他服务，需求强劲。例如，如果教育领域的整体增长为 2% 到 5%，AI 的增长大约是 10%。

Q:大致而言，有多少支出来自 AI 工作负载，相对于传统云使用？

A:AI 在整体业务账本中代表性不足。我估计其占比低于 10%，可能在 7% 到 8% 左右，因此仍有相当大的渗透空间。在此语境下，AI 包括 Amazon Bedrock 和搜索、基于 Amazon SageMaker构建的解决方案、agentic AI 以及原生 AWS AI 服务等。

Q:在该行业签署了较大 AWS 协议或承诺的客户中，使用在第三季度是否按预期增长？

A:是的。不过第三季度的工作日较少，所以绝对数值或环比增长自然会较低。与去年第三季度相比，今年第三季度按预期速度录得了增长。目前没有出现负面趋势。

Q:管理层表示 AWS 在第三季度整体增长超过 40%。在相关行业中，收入增长是符合还是超过了该指引？你有具体数字吗？

A:该指引是公司层面给出的。就相关区域而言，增长与该行业预测和预算的速度一致。

Q:这种评估是基于你的印象，还是你看到了实际数据？

A:这是基于实际业绩，没有负向偏差。例如，如果预测是 3% 的增长，实际增长也是 3%，与预算一致。

Q:这些目标是如何达成的？如果在季度末表现超过目标，是否会像销售部门那样通过财务调整来满足季度目标？更具体地说，你是看到有数据表明增长与预测一致，还是这一评估基于估计或印象？

A:实际业绩与该行业的投影和预测一致，正在以预测的速度推进。

Q:企业 AI 的资金来自哪里？是新增预算，还是从其他 IT 项目挪用资金？就你的客户而言，有多少 Q4 和 2027 的预算已获批？

A:很难说有多少 Q4 和 2027 的预算已获批准。关于客户是否将资金从其他项目转入企业 AI，目前投入到 AI 的金额并不高。例如，一个年支出为 1000 万美元的账户，可能在 AI 上每年只花大约 50 万美元。

我不认为客户在削减其他项目预算来投资 AI。可能有一两个客户在 AI 上花得更多，但总体上 AI 支出并未影响整体支出或挤出其他项目。

Q:那么客户是在为企业 AI 增加增量预算吗？

A:客户确实在签约更多的云、Amazon Bedrock 或类似 OpenAI 的基础模型使用，但相对于他们的整体云支出，体量和值仍然较低。例如，对于一个在云上花费约 1000 万到 2000万美元的大客户，相关云订阅和其他项目的年化运行率可能在约 60 万到 70 万美元，外加 token 成本。客户在增加预算，但这些新增并不显著。他们也不会削减其他支出，因为他们还有既有承诺需要满足。

Q:这是否意味着尽管渗透率在提升，但绝对的 AI 预算相对于总体预算仍然较小？

A:正确。它低于 10%。我不知道公司如何在整体上呈现该数字，但据我所知，AI 的渗透率约占整体收入的 10%，代表了 AI 的相对份额。

Q:哪些 AI 用例在试点阶段后能够推动客户持续投入？能否举例说明用例、业务成果以及每月的 AWS 账单？

A:一个持续带来更多支出的领域是 Claude Code 和面向开发者的使用。采用率很高，客户在购买更多开发者许可证，支出也较高。类似的编码工具，如 OpenAI Codex，也被用于提升开发者生产力。

第二个领域是基于 LLM 的用例，如文档搜索和语义搜索。客户使用基础模型、知识库和 RAG。智能文档处理结合基于 AI 的搜索也在被采用。针对学生的产品中，客户正在启用语义搜索而不是词汇搜索。

教育技术公司必须推出符合州政府标准的产品。过去，他们需要手动审核每门课程大纲以确定是否覆盖所有要求的标准。借助生成式 AI，他们正在自动化这一过程，将课程大纲和评分标准与州规定的标准进行比对。他们也使用 AI来评估教育技术产品和课程是否符合 Common Core State Standards 等要求。这些是在教育领域的常见用例。

Q:你提到了 Claude Code 和搜索。你有没有看到任何 agent 项目？随着这些项目走向生产，发生了什么？

A:非常少。只有一两个 agent 项目以及一些 agentic AI 项目处于概念验证阶段，在教育技术领域并未显著扩展。金融服务和生命科学领域似乎有更大规模的扩展。在教育技术中，涉及推理模型和多 agent 的 agentic AI还未大规模进入生产。

原因之一是 token 消耗。对于生成式模型，可以根据用例相对容易地预测 token 使用量。然而对于 agentic AI，预测、监控和控制 token 使用要困难得多。我认为这是 agentic AI未能扩展的一个原因，因为必要的护栏仍未建立。

Q:客户实际上在哪些开源或开放权重模型上运行生产工作负载？在第三季度这种情况有多普遍？这些模型用于哪些用例？为澄清，Anthropic 和 OpenAI 提供的是闭源模型；这里的问题是关于开源或开放权重模型的。

A:开源或开放权重模型的支出更常见于规模较小或 greenfield 的客户以及那些在云上支出不大的客户。相比之下，主要的战略客户主要使用闭源模型和编码平台，而非开源模型。

Q:客户在哪里运行这些模型？他们大多数是在 Amazon Bedrock 上运行，还是在 Amazon EC2 上运行？

A:编码和开发模型可以在 Amazon Bedrock 上运行，也可以在 Amazon Bedrock 之外或通过 marketplace 运行。它们并不专属于 Amazon Bedrock。

Q:你有没有看到任何客户，包括由你的同事负责的客户，从闭源模型的 API 转向开放权重模型？

A:在战略客户中没有。一些对云不太熟悉或更注重成本的小型客户在走那条路。

Q:在 Claude、OpenAI 的模型和亚马逊自有的 Amazon Nova 模型之间，第三季度的生产使用情况如何变化？促使这些选择的因素是什么——模型质量、价格、可靠性，还是其他因素？Claude 是否仍然是通过 Amazon Bedrock 消耗的主要来源，OpenAI 和 Amazon Nova 又是如何被使用的？

A:我不能对 Amazon Nova 的详细细节做评论，但其采用率并不高。进行概念验证的客户通常更倾向于领先的前沿模型。Amazon Nova 在模型分层架构中被使用，根据用例对模型进行升级或降级。对于较低端、非常简单的用例，客户可能会使用Amazon Nova Lite、Amazon Nova Micro 或 Amazon Nova Pro。这只占很小的一部分使用量。

Q:在除了最大的 AI 实验室之外，您账户中到底有多少客户在生产中使用 AWS Trainium，还是这个数字未知？

A:我不知道确切数字。在教育技术领域，规模不大。AWS Trainium 用于训练，而 AWS Inferentia 用于推理。AWS Trainium 在较低端环境中使用。它占有一定比例，但我不会称之为显著。

Q:据您所知，AWS Trainium 仍主要用于训练而不是广泛用于推理，对吗？

A:正确。使用 AWS Trainium 的主要原因是其性价比。当特征复杂度相对较低时，它能提供最大的性价比收益。我不认为它常用于前沿的、异构的、快速变化的或新一代的工作负载。它主要用于轻量级、较低端的用例，客户特别关注成本节约。

采用率在提高。AWS 还为 Linux 和其他工作负载提供 AWS Graviton 处理器，其采用率也在增长。由于与 NVIDIA 相比价格非常低，AWS Trainium 在训练方面的采用率也在增加。

Q:您知道客户通过使用 AWS Trainium 而不是 NVIDIA GPU 对相同工作负载实际实现了多少成本节省吗？

A:确实存在成本节省，但我没有观察到显著的转变。客户通常不会专门因为成本节省而要求使用 AWS Trainium，它似乎并未构成重大转变或显著的收入来源。
