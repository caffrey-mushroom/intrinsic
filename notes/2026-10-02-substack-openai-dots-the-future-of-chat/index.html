专家访谈纪要：OpenAI Dots 产品定位、主动智能体与商业化路径

1. 智能体行业阶段与 Dots 的诞生背景

a) 为什么个人智能体和主动型智能体会在当前阶段集中出现？

  • 行业正在经历三阶段演进：
  1. 第一阶段是聊天产品，用户通过对话从大语言模型中获取价值；
  2. 第二阶段是编程智能体，智能体开始真正执行任务，并逐步拓展到知识工作；
  3. 第三阶段是“主动智能”，产品不再完全依赖用户下达明确指令，而是能够主动判断可以提供什么帮助。
  • 现有编程智能体虽然能力很强，但更像一位“不看 Slack、不看 Linear、只有收到明确指令才行动”的首席工程师，仍然缺乏主动性。
  • 高级用户可以自行设置自动化流程和循环任务，但普通用户通常不具备相应能力。主动型智能体的核心价值，是降低用户发现和配置 AI 使用场景的门槛。
  • 当前趋势形成的技术基础包括：
  1. 模型能力已达到可支撑复杂任务执行的水平；
  2. 浏览器操作、计算机操作和代码执行能力快速成熟；
  3. 云端运行、连接器和持久任务框架逐步完善；
  4. 用户开始形成智能体使用习惯和最佳实践。
  • 主动智能体必须能够访问充分的上下文。如果不能连接用户的数据、工具和工作环境，就无法真正做到主动帮助用户。

b) Dots 最初希望解决哪些核心问题？

  • 产品团队早期形成了两个基本判断：
  1. 模型不能只回答问题，还应能够执行任务；
  2. 用户不应始终自行判断应该要求模型做什么，模型应主动识别可提供的帮助。
  • 即使是熟悉 AI 产品的高级用户，也可能因工具和能力快速增加而产生“自己使用得不够充分”的压力。
  • Dots 希望将高阶用户才能建立的复杂自动化能力，转化为普通用户也能直观使用的产品体验。

c) Dots 所需的底层能力是如何逐步形成的？

  • 团队早期曾尝试让桌面版 Chat 理解其他应用的界面，通过截图和计算机操作完成工作，但当时运行速度慢、实际效果有限。
  • 随后行业技术前沿转向编码，团队用约一年时间积累了帮助智能体完成复杂工作的能力。
  • 关键基础设施包括：
  1. 各类连接器，使智能体能够直接调用工具和数据，而不是依赖屏幕点击；
  2. 云端计算环境，使智能体不必占用用户本地电脑；
  3. Codex 框架和长期任务能力；
  4. 代码控制浏览器及计算机的能力。
  • 当前模型已经可以通过编写代码片段控制浏览器或计算机，这通常比逐帧截图、逐步点击更加高效。

2. Dots 的产品形态与核心能力

a) Dots 最核心的产品理念是什么？

  • 最关键的理念是“持久性”，即智能体能够持续运行并长期跟进任务。
  • 用户可以提出“持续跟进这个 PR”或“持续关注这个反馈渠道”等任务，而不必明确规定每一步应如何执行。
  • Dots 还具备三项重要特征：
  1. 可以长时间持续处理任务；
  2. 用户无论身处何处，都能通过不同工具联系它；
  3. 它拥有自己的云端计算机，可以完成用户能够在电脑上执行的操作。
  • 这种能力并非一次性跃迁形成，而是随着模型、框架和产品能力不断增强而逐步成熟。

b) 哪些内部实践推动团队决定正式推出 Dots？

  • Codex 中的 `/goal` 功能已经证明，用户对长时间持续处理单一问题的能力有较强需求。
  • OpenAI 内部曾发布多个长期运行的智能体原型，这些原型快速普及，并形成持续活跃的反馈渠道。
  • 内部用户不断分享原型的使用方式，以及它们对工作效率的显著提升。
  • 团队最初在两种方案之间进行选择：
  1. 将持久任务作为 Codex 本地对话线程的增强功能；
  2. 将其部署至云端，并赋予独立身份，使用户能够在 Slack 等平台联系它。
  • 最终团队认为，如果希望更多用户直观地将困难、耗时的任务交给智能体，云端运行和具象化身份是更合适的产品形态。
  • 团队随后围绕 Astra 的基础模型能力启动冲刺项目，重点完成云端运行和身份具象化两项调整。

c) 为什么要为智能体赋予名称和具体身份？

  • 具象化能够帮助普通用户理解，智能体不仅可以完成一次性任务，还可以持续跟进项目、关注进展并主动反馈。
  • 当智能体以明确身份出现在 Slack 等沟通工具中时，用户更容易向其分配持续数天或间歇性执行的复杂任务。
  • 具象化也能帮助用户理解跨渠道上下文的一致性：
  1. 用户可以通过语音、Slack 私信、Slack 线程或应用内对话与 Dot 交流；
  2. 无论使用哪个渠道，面对的都是同一个智能体；
  3. Dot 能够共享此前积累的上下文，而不需要把所有历史消息复制到每个界面。
  • 这类似于人类交流：面对面沟通后再通过短信联系，短信中不需要展示此前所有对话记录，但双方仍知道彼此是谁。

d) 每个用户未来会拥有一个智能体，还是多个智能体？

  • 当前判断是支持多个智能体，但普通消费者通常只需要一个，高级用户才可能创建多个。
  • 大多数人的个人智能体应当成为用户自身的延伸，而不是增加额外认知负担。
  • 如果每个用户都拥有多个名称各异的智能体，其他协作者将很难记住各个智能体的身份与职责。
  • Dots 在 Slack 或 Teams 中会采用用户名称前缀，例如用户 AE 的 Dot 会显示为“AE-Dot”，从而明确其归属。
  • 团队曾允许并鼓励用户创建多个随机命名的智能体，结果导致 Slack 中身份混乱，验证了统一归属标识的重要性。

3. 交互设计与 Spaces 协作工作区

a) 为什么 Dots 采用单一主线程和消息式交互？

  • 人类现有的沟通和协作工具已经形成成熟设计，智能体产品可以复用这些交互范式。
  • 消费端的 iMessage、WhatsApp 通常以人与人之间的单一线程为核心；工作端的 Slack、Teams 则通过频道和子线程分隔上下文。
  • Dots 希望保持类似“给另一个人发消息”的简洁体验，降低用户理解和使用成本。
  • 后续工作场景中会增加更多上下文分隔能力，其中 Spaces 将承担重要角色。

b) Space 是什么，其设计逻辑是什么？

  • Space 本质上是一个协作工作区，用于承载消息界面不适合展示的长篇内容。
  • 人类主要使用三类协作媒介：
  1. 实时沟通；
  2. 消息；
  3. 文档。
  • 第四类是 Salesforce、Figma 等面向特定工作流的功能型工具。
  • Dot 的消息界面适合快速沟通，但如果智能体需要输出长篇分析、多个方案或检查清单，全部以消息气泡呈现会影响体验。
  • Space 可以将复杂内容组织成页面、文档、检查清单、图表或原型，与消息界面形成互补。

c) Dots 与 Spaces 如何协同？

  • 用户可以先在 Space 中搭建文档结构，再直接标记 Dot，让其：
  1. 补充或完善内容；
  2. 提取和更新数据；
  3. 联系相关人员确认任务进度；
  4. 在任务完成后勾选复选框。
  • 页面可以设置智能体指令，类似代码仓库中的 `agent.md`，指导智能体持续维护和更新页面。
  • Space 在设计上给予智能体与人类大致同等的协作权重，使双方可以在同一个工作区深度协作。

d) AI 将如何改变文档形态？

  • 传统文档必须针对人类手动输入进行优化，因此格式和表达能力受到限制。
  • HTML 和 CSS 虽然不适合普通人直接创作，但表达能力远强于传统文档，而智能体非常擅长生成和修改 HTML。
  • Space 因此可以自然支持：
  1. 实时更新的可视化图表；
  2. 用户可通过自然语言定制的图表；
  3. 可直接交互的产品原型；
  4. 更丰富的动态页面。
  • 在 OpenAI 内部，部分指标页面已经由智能体持续更新，并嵌入实时图表和可点击原型。

4. 产品差异化、模型能力与安全机制

a) Dots 相较其他新型智能体产品的核心差异是什么？

  • 产品定位集中在两个方向：
  1. 打造能力最强的智能体；
  2. 打造最安全、最值得信赖的智能体。
  • Dots 并不以交易或简单操作为主要押注，而是希望帮助用户完成复杂、长期且具有较高价值的工作。
  • 典型任务包括协调 PR、评估硬件、规划产品发布以及持续跟进项目等。

b) Dots 如何平衡主动性与用户控制权？

  • 现阶段产品采取相对保守的默认策略，之后再根据实际使用情况逐步放宽限制。
  • Dot 可以主动：
  1. 调用已连接工具开展研究；
  2. 分析用户上下文；
  3. 判断能够提供哪些帮助；
  4. 提出下一步行动建议。
  • 但在用户确认之前，默认不会执行实际操作。
  • 团队会持续减少“过度确认”，即避免在用户可以合理预期和接受的场景中反复要求确认。
  • 早期测试中，Dot 在购物等任务上确认过于频繁，团队根据反馈对默认行为进行了大幅调整。

c) 为什么选择 GPT-6 Astra 作为 Dots 的模型？

  • OpenAI 选择了能力最强、同时对齐程度最高的 GPT-6 Astra。
  • 模型选择体现了产品的核心原则：在提供高能力的同时，优先保证安全性和可信度。
  • 团队没有为了更快扩大能力范围而使用更激进、对齐程度较低的模型。

d) Dots 的安全架构由哪些层级构成？

  • 安全体系采用纵深防御，主要包括：
  1. 高度对齐的 GPT-6 Astra 模型；
  2. 经充分测试和安全评估的 Codex 框架；
  3. 针对持久运行和子智能体委派重新设计的框架；
  4. 沙箱环境和权限隔离；
  5. 可定制的默认行为与规则；
  6. 规则执行机制；
  7. 向用户解释智能体行为和操作记录的透明机制。
  • 团队针对持久运行、电子邮件、提示词注入和数据窃取等场景开展了专项评估。
  • 公开披露的部分失控或攻击案例，使用的是原本不准备内部发布的模型，且未运行在对外产品同等级别的沙箱和安全框架中，与 Dots 的正式产品环境存在明显差异。

e) Dots 在多人协作和信息分享方面有哪些限制？

  • 在 Slack 中，Dot 默认只会在被标记时响应。
  • 除非用户明确授权，否则不会主动听取其他人的指令。
  • 团队希望未来支持多人协作，但需要谨慎界定：
  1. Dot 可以接受谁的指令；
  2. 可以向哪些人分享信息；
  3. 不同上下文和权限之间如何隔离。
  • 电子邮件功能也没有在首发阶段完全开放，因为允许所有人向 Dot 发邮件，或允许 Dot 向所有人发邮件，会带来提示词注入和敏感信息泄露风险。

f) 为什么 Dots 首先面向高阶付费用户发布？

  • 初期发布范围包括 Pro、Business、Enterprise 和 Business Premium 等 AI 素养相对较高的用户群体。
  • 团队希望先观察高阶用户如何使用产品，验证安全性、权限设计和规模化能力，再逐步扩大覆盖范围。
  • 这一策略不是受限于产品需求，而是主动采取的审慎发布方式。

5. 多渠道拓展与生态合作策略

a) Dots 将覆盖哪些沟通渠道？

  • 产品目标是覆盖用户工作的所有场景，即用户日常沟通所在的主要渠道。
  • 当前重点是工作场景，未来将逐步拓展至消费场景。
  • 短信功能即将推出，但具体上线时间和产品细节尚未披露。
  • 长期方向包括 Slack、Teams、电子邮件、短信以及其他主流消息平台。

b) OpenAI 如何处理智能体购物、支付和网站访问问题？

  • OpenAI 不希望采用“先大规模推出、再观察后果”的冒进方式，而是优先与合作伙伴和生态系统共同探索。
  • 智能体访问网站时会明确声明自己是机器人。
  • 在 Web Bot Auth 等领域，OpenAI 已与相关基础设施伙伴保持密切合作。
  • 购物和支付的具体机制仍在探索，重点是同时兼顾用户体验、网站权益及生态可持续性。

c) 智能体可能如何影响广告商业模式？

  • 智能体代替人类浏览网站、完成任务后，用户可能不再直接观看广告，从而影响依赖广告收入的平台。
  • 当前行业尚未形成成熟解决方案。
  • 受访者认为，提供服务的平台仍应获得合理回报，可能的方向包括：
  1. 延续某种广告收益机制；
  2. 为服务提供方设计其他补偿方式。
  • OpenAI 当前更倾向优先发展职场生产力场景，因为企业工具链中的各方通常具有更一致的目标和激励机制。

6. 定价原则与商业模式

a) Dots 是否会消耗用户现有套餐限额？

  • Dots 不会采用“限额耗尽后完全停止工作”的产品逻辑，这不是短期获客措施，而是长期原则。
  • 对持续运行的智能体而言，如果用户因前一天大量使用 Codex 而耗尽额度，导致 Dot 无法继续关注航班或执行其他持续任务，会严重破坏可靠性。
  • 因此，Dots 的核心定价原则是：
  1. 除滥用等特殊情况外，应当 24/7 可用；
  2. 应始终能够快速响应；
  3. 不能因为额度耗尽而完全失联。

b) Dots 未来可能采用什么定价方式？

  • 定价方式更接近“固定费用的承包商”或互联网服务，而不是简单按次数或按小时计费。
  • 用户每月支付固定费用，即可持续使用自己的 Dot。
  • 不同付费档位可对应不同能力：
  1. 更强的模型；
  2. 性能更高的云端计算机；
  3. 更快的运行速度；
  4. 更高的并行任务处理能力；
  5. 更大的实际工作量。
  • 即使接近当月资源边界，Dot 仍然保持可联系状态，并可能主动提出资源优化方案，例如：
  1. 使用更具成本效益的模型；
  2. 将非紧急任务安排在夜间执行；
  3. 询问任务是否紧急；
  4. 根据优先级调整计算资源。
  • 如果用户当月使用较少，Dot 还可能主动提醒用户，并建议其可以承担的任务。

c) Dots 与 Codex 的额度关系如何？

  • 长期来看，Dot 的工作额度将与主要 Codex 限额分开，采用全新的资源管理模式。
  • 未来一个月将提供较宽松的使用额度，用于建设、测量并调整该模式。
  • 产品还需要让 Dot 理解自己可以为用户完成多少工作，并在资源约束下保持持续可用。

d) 为什么不采用交易抽成模式？

  • 如果交易是智能体的主要用途，抽成模式可能成立。
  • 但 Dots 的核心押注不是购物或交易，而是帮助用户完成复杂、长期、有雄心的工作。
  • 大量高价值任务并不涉及商品购买，因此固定订阅和分层能力更符合产品定位。

7. Dots 与 ChatGPT、Codex、Work 的产品关系

a) Dots 是否会取代 ChatGPT？

  • ChatGPT 不会消失，仍将作为面向所有人的消费级助手。
  • 当前 ChatGPT 每周用户超过 12 亿，是增长速度最快的消费级助手之一。
  • Codex 和 Work 合计拥有约 3,500 万用户，并持续增长。
  • 当前产品定位大致为：
  1. ChatGPT：面向所有人的消费级助手；
  2. Codex：面向开发者的专业产品；
  3. Work：工作场景产品，未来应与 Chat 合并；
  4. Dot：率先承载主动智能体能力的高端独立产品。

b) Dots 的能力未来会如何进入大众市场？

  • Dots 将重复 Codex 的产品扩散路径：
  1. 先将前沿能力以谨慎、稳妥的方式提供给高阶用户；
  2. 观察真实使用方式并解决安全和规模化问题；
  3. 从 Pro 用户逐步拓展至 Plus 用户；
  4. 最终覆盖 Free 用户。
  • 要覆盖免费用户，需要将 Dots 的大量能力和经验逐步融入 ChatGPT。
  • OpenAI 不希望要求现有 12 亿用户改变已经形成的使用方式，而是希望在原有 ChatGPT 产品中渐进式升级能力。
  • 因此，Dot 未必直接成为所有人的统一界面，但其技术、交互和主动能力将持续进入 ChatGPT。

8. 产品路线图与未来发展方向

a) 未来几个月 Dots 的重点是什么？

  • 近期主要方向包括：
  1. 将用户范围逐步拓展至 Pro 之外；

c) 什么是专业型 Dot？

  • 未来 Dot 将分为两类：
  1. 助手型 Dot：归属于个人，作为用户自身能力的延伸；
  2. 专业型 Dot：归属于组织，负责特定职能或工作流程。
  • 专业型 Dot 的主要特征包括：
  1. 由组织或 IT 部门集中创建和管理；
  2. 拥有独立身份；
  3. 与个人用户完全分离；
  4. 专门承担某一类工作；
  5. 服务整个团队或组织，而非单个员工。
  • 未来几个月，OpenAI 将与少数客户合作推进专业型 Dot，但仍会保持小范围、低速和谨慎的发布节奏。

d) 最具代表性的主动执行案例是什么？

  • 一名工程师曾要求 Dot 持续关注反馈频道。
  • Dot 在反馈中识别出一个可能进入生产环境的缺陷，并主动创建了修复 PR。
  • Dot 还学习到该工程师通常直接创建 PR 并设置自动合并，因此沿用了这一偏好，并推动其他人员完成审批。
  • 最终缺陷在进入生产环境前被修复，该工程师醒来后才发现自己在 Slack 中获得了大量赞誉。
  • 该案例体现了持久运行智能体的潜力，但也暴露了安全边界问题：
  1. Dot 不应在用户不知情的情况下完成高影响操作；
  2. PR 理应先设为草稿，而非直接进入自动合并流程；
  3. 用户偏好不能自动等同于永久授权。
  • OpenAI 正围绕此类场景建立更严格的安全控制，这也是产品采用小规模测试和渐进式开放策略的原因。
