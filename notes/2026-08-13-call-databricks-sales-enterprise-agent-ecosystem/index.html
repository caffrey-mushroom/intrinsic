纪要总结

企业级AI智能体生态与Databricks专家访谈纪要

1. 专家背景与客户覆盖范围

a) 专家在Databricks的工作经历及目前覆盖哪些客户？

  • 专家在Databricks工作约4年：
  1. 最初负责制药行业客户。
  2. 随后负责公共部门客户。
  3. 过去1.5年负责比荷卢地区的数字原生企业和新兴企业团队。
  • Databricks对相关客户的定义：
  1. 数字原生企业：通常指2000年以后成立、诞生于云端，并在云服务及在线业务领域拥有较大业务规模的企业。
  2. 新兴企业：年营收约2.5亿至10亿的企业；该口径指客户自身营收，而非其为Databricks贡献的收入。
  • 访谈内容主要基于公开信息及专家个人工作经验，不涉及非公开信息。

2. 企业AI支出趋势与智能体生产化节奏

a) 企业AI及智能体支出是否会在2026年明显加速？

  • 专家判断整体支出会加速，但不同客户的进展取决于其技术成熟度。
  • 遗留系统较多的传统企业目前才开始系统性接触AI：
  1. 此前主要试用Claude、Claude Code等产品。
  2. 当前开始为智能体补充企业上下文。
  3. 同时推动数据在Lakehouse中结构化、互联，并建立治理体系。
  • 数字原生企业启动更早，为保持技术颠覆性，已经开始完善AI技术栈。
  • 2026年上半年的显著增长主要来自数字原生企业，但总体规模仍低于预期：
  1. 大多数项目仍处于试验阶段。
  2. 主要工作是连接首批数据源、建立治理体系。
  3. 应用通常局限于单个智能体、单个AI解决方案或单个部门。

b) 为什么目前多数企业AI试验未达到预期？

  • 部分项目已经取得成功，但多数项目效果仍不理想。
  • 核心问题并非模型能力不足，而是：
  1. 智能体缺乏充分的企业上下文。
  2. 企业数据之间没有正确连接。
  3. 数据访问、权限、血缘和使用过程缺乏治理。
  4. AI项目仍以孤立方式运行，难以形成完整业务闭环。
  • 企业早期通常允许员工自由试用AI，先探索应用场景，再考虑治理。
  • 这种方式正在暴露明显的成本问题，部分企业甚至在1个月内用完了全年AI预算。

c) 企业AI投资决策正在发生什么变化？

  • AI支出已开始受到董事会和高管层关注。
  • 管理层正在要求AI项目：
  1. 以可控、可监测的方式推进。
  2. 具备完整、准确的企业上下文。
  3. 建立数据和模型治理机制。
  4. 设置项目管理、成本管理等组织架构。
  5. 从无序试验转向可衡量回报的生产化部署。
  • 这一变化对Databricks有利，因为企业高层正在认识到，AI成功的关键不仅是模型，还包括上下文、数据连接和治理。
  • 企业也开始重新分配预算，将更多资金投向能够提供数据治理和智能体生产化能力的平台。

d) 为什么预计2027年AI支出会进一步加速？

  • 2026年仍将以试验、数据连接和治理体系建设为主，2027年预计会有更多智能体正式进入生产环境。
  • Databricks的客户沟通对象正在从数据部门和IT部门扩展至实际业务部门，包括：
  1. 人力资源部门。
  2. 市场营销部门。
  3. CFO办公室。
  4. 其他直接拥有业务需求的职能部门。
  • 首批AI仪表盘已经上线，后续用户可以直接与仪表盘交互，并基于其中的数据构建智能体。
  • 企业也在缩小智能体的应用范围，使其更加定制化、具体化，以提高成功率和投入产出比。
  • 随着项目从试验转向生产，支出将更多由实际用户规模、调用量和新增数据迁移驱动。

e) 当前企业智能体的生产化比例有多高？

  • 在专家负责的客户群体中：
  1. 约5%至10%的客户已经将智能体投入生产。
  2. 已生产化的客户通常也只部署了1至3个智能体。
  3. 其余客户仍在开展大量测试，尚未进入规模化生产阶段。
  • 因此，企业智能体市场仍处于非常早期的阶段，未来增长空间主要来自生产化率和单客户部署数量的提升。

3. 模型能力、开源模型与成本约束

a) 模型能力是否会成为复杂智能体部署的主要瓶颈？

  • 专家认为，市场上稍早一代的模型已经足以完成多数企业需要的相对简单或中等复杂度智能体任务。
  • 只有极其前沿、强调持续创新的企业，才需要不断采用最新一代模型。
  • 对大多数企业而言，当前模型能力已基本可以满足业务需求。
  • 专家尚未在实际客户场景中明显遇到模型能力无法完成复杂任务的情况。
  • 当前更现实的限制是成本，而非模型能力。

b) 开源模型未来会如何发展？

  • 专家预计开源模型的企业应用规模将快速增长。
  • 开源模型的主要优势是成本，其成本可能仅为Anthropic、OpenAI、Gemini等闭源模型的约1/10。
  • 大量企业任务并不需要调用最昂贵、规模最大的模型，未来可根据查询复杂度进行分层路由：
  1. 简单查询路由至低成本开源模型。
  2. 高难度任务路由至更强的大模型。
  • 开源模型能否大规模进入企业，取决于能否解决治理、安全、权限和合规问题。
  • 专家指出，领先开源模型中相当一部分来自中国，因此企业采用还会受到政治及监管环境影响。

c) 开源模型会对Anthropic产生什么影响？

  • 如果企业能够在适当治理和安全体系下使用开源模型，Anthropic可能难以长期保持当前增速。
  • 对于开源模型能够胜任的任务，Anthropic预计会流失部分业务。
  • 但Anthropic当前市场份额仍相对有限，专家引用的市场数据约为5%至10%，因此仍有较大的市场份额扩张空间。
  • 最终影响可能不是Anthropic支出绝对下降，而是：
  1. 简单及标准化任务逐渐转向低成本模型。
  2. Anthropic更多保留高价值、复杂任务。
  3. 企业通过模型路由降低整体推理成本。

4. 企业智能体技术栈与Databricks的平台定位

a) 企业部署智能体通常需要哪些技术层？

  • 智能体技术栈可以分为以下层级：
  1. 云基础设施层：计算、云身份与访问管理，由Azure、AWS、GCP等提供。
  2. 数据准备层：数据连接、清洗、结构化、向量索引和批量推理。
  3. 模型训练层：传统机器学习、生成式AI及大语言模型相关训练。
  4. 模型服务层：模型调用、部署及推理服务。
  5. 评估与运维层：效果评估、监控、扩缩容和生产运维。
  6. 智能体构建与编排层：记忆、检索、工具调用和任务编排。
  7. 治理层：权限、数据血缘、上下文、成本、审计及模型使用治理。
  • Databricks运行在Azure、AWS或GCP之上，不直接替代底层云计算和云身份访问管理能力。

b) Databricks最擅长哪些环节？

  • Databricks可以覆盖从计算层之上的数据环节到最终智能体部署的大多数流程。
  • 主要优势包括：
  1. 数据准备。
  2. 数据连接与清洗。
  3. 向量索引和批量推理。
  4. 模型训练。
  5. 模型服务。
  6. 模型与智能体评估。
  7. AI治理。
  • 专家认为，Databricks在数据准备和模型训练方面实力较强，在模型服务及评估方面也具备竞争力。
  • 但Databricks最重要、最具差异化的能力仍是治理，即通过Unity Catalog连接企业全部数据，为智能体提供完整上下文。

c) Databricks是否要求客户完全使用其原生技术栈？

  • Databricks不排斥第三方产品。
  • 客户可以根据具体任务使用：
  1. OpenAI、Anthropic、Gemini等模型。
  2. Elasticsearch等向量索引工具。
  3. 云厂商的Vertex、Bedrock、SageMaker或Azure AI Foundry等产品。
  4. 其他编程智能体和单点解决方案。
  • Databricks的核心要求并非替代所有工具，而是通过治理层统一管理数据、权限和上下文。
  • 如果单点产品更适合特定场景，客户仍可继续使用；Databricks通过合作和集成将其纳入统一平台。
  • 随着Databricks原生产品能力提升，越来越多客户倾向于将工作集中在一个平台上，以改善用户体验并降低管理复杂度。

d) 客户的数据连接通常如何完成？

  • Databricks通过Lakeflow连接不同的数据源，也与大量第三方供应商合作。
  • 对Salesforce、SQL Warehouse、Oracle等标准数据源，Databricks已支持约1000家供应商及相关产品的原生连接。
  • 使用原生连接的主要优势是，所有进入Unity Catalog的数据都能够自动纳入治理体系。
  • 对非常小众的数据源，第三方连接方案可能更合适。

5. Unity Catalog的核心价值与竞争壁垒

a) Unity Catalog是什么？

  • Unity Catalog是Databricks的统一数据和AI治理层。
  • 其主要功能包括：
  1. 对企业数据进行编目和标记。
  2. 管理用户及智能体的数据访问权限。
  3. 记录谁在何时访问了哪些数据。
  4. 追溯数据状态和处理过程。
  5. 提供数据血缘管理。
  6. 将智能体、模型和相关使用成本纳入统一治理。
  • 可以将其理解为企业访问、管理和审计数据的统一窗口。

b) 为什么Unity Catalog是Databricks的主要差异化优势？

  • 3至4年前，Databricks的主要差异化能力是通过Lakehouse统一管理和治理数据。
  • 当企业开始强调数据保护、权限追踪和数据血缘时，Unity Catalog成为推动Databricks增长的重要产品。
  • 随着大语言模型和智能体发展，企业进一步认识到，智能体必须获得经过治理的企业上下文。
  • 大量企业已经在Databricks上部署Lakehouse，因此可以直接将现有数据与智能体连接，减少重新建设治理体系的成本。
  • 专家认为，从企业高管视角看，Unity Catalog是Databricks最明确的差异化优势。

c) Unity Catalog能为企业高管解决哪些问题？

  • 企业高管最关注三个方面：

1. 成本控制

  • 控制并优化模型和智能体使用成本。
  • 监测不同人员、部门和智能体的资源消耗。
  • 未来通过模型路由，将简单查询转向更便宜的模型。

2. 上下文

  • 确保智能体可以访问经过授权的完整企业数据。
  • 使智能体理解公司内部专有术语、业务规则及历史信息。
  • 避免智能体因数据孤立或上下文不足而输出低质量结果。

3. 选择权

  • 企业不希望长期被锁定在单一模型或单一云厂商体系中。
  • 客户可以在OpenAI、Anthropic、Gemini和开源模型之间切换。
  • 企业能够根据模型能力、成本和创新速度调整供应商，而无需重建全部数据治理体系。

d) Unity Catalog开源后，客户为什么仍需要购买Databricks？

  • Unity Catalog以及Spark、Delta、MLflow等Databricks核心产品均有开源版本。
  • 理论上，企业可以自行将这些开源产品连接起来，搭建类似Databricks的平台。
  • 但实际操作存在明显障碍：
  1. Databricks通常将较旧版本开源，最新能力未必同步开放。
  2. 最新智能体框架和复杂治理能力往往仍在Databricks托管版本中。
  3. 自行集成、升级、运维和管理需要大量技术人员。
  4. 企业需要自行维护底层基础设施及产品之间的兼容性。
  5. 综合成本通常高于直接使用Databricks托管服务。
  • 使用Databricks可以确保客户持续获得最新版本、最新功能及最新集成，因此市场上很少有客户完全依靠开源产品自行搭建整个平台。

e) Unity Catalog是否已经成为行业标准？

  • 按专家个人观察，Unity Catalog已经具备行业标准地位。
  • 专家称约95%的相关用户会采用Unity Catalog，但这一比例应理解为其客户和市场观察，并非经审计的官方市场份额。
  • 其他可选方案包括：
  1. Microsoft Purview。
  2. AWS和Google的治理产品。
  3. Snowflake相关治理能力。
  • 专家认为Purview可满足部分客户需求，但其治理能力弱于Unity Catalog，并存在较强的Microsoft体系锁定。
  • Snowflake在独立数据治理层方面最为接近，但整体能力仍未达到Databricks水平。

6. Agent Bricks、Unity AI Gateway与Genie产品进展

a) Agent Bricks的定位是什么？

  • Agent Bricks是Databricks面向智能体构建和部署的综合性产品，可以覆盖从概念验证到生产环境的端到端流程。
  • 其主要组成包括：

1. 智能体构建

  • 管理数据推理和检索。
  • 用户可以作为智能体监督者，对智能体进行管理。

2. 智能体部署

  • 管理记忆、编排及自动扩缩容。
  • 连接OpenAI、Gemini等外部AI模型。

3. 机器学习与评估

  • 基于Databricks原生MLflow处理智能体的机器学习、评估和运维环节。

4. 模型及开发工具

  • 包括特征共享、模型训练、相关数据服务和开发者工具。
  • 所有功能最终统一由Unity Catalog进行治理。

b) Agent Bricks当前的客户普及程度如何？

  • Agent Bricks正在变得越来越普及。
  • 目前尚未成为Databricks最主要的产品之一，这与智能体市场仍处于早期阶段有关。
  • 随着智能体从试验进入生产，专家预计Agent Bricks的战略重要性将持续提高。

c) Databricks如何统一管理第三方模型？

  • Databricks自身并不拥有类似Anthropic、OpenAI或Google的基础大模型。
  • Unity AI Gateway可以集中管理企业的LLM使用和模型服务：
  1. 将模型调用纳入统一治理。
  2. 设置调用限制。
  3. 监控使用情况及成本。
  4. 保留切换模型供应商的能力。
  5. 为未来的查询路由提供基础。
  • 因此，模型本身仍由第三方提供，但调用、权限、监控和治理可以在Databricks平台上完成。

d) Databricks是否具备模型路由能力？

  • 专家对最新产品进展不完全确定，但表示Databricks正在开发自动化成本控制和模型路由功能。
  • 未来可以根据查询复杂度进行路由：
  1. 简单任务调用成本较低的开源模型。
  2. 复杂任务调用OpenAI、Anthropic等更强模型。
  • 专家举例，目前部分大型模型每百万token成本约14美元，而开源模型成本可能仅为其1/10。
  • 随着2027年更多智能体进入生产环境，模型路由将成为企业控制成本的重要功能，预计Databricks会原生强化这一能力。

e) Genie的产品定位及价值是什么？

  • Genie可以被理解为基于自然语言交互的自助式BI产品。
  • 用户可以：
  1. 直接通过自然语言向企业数据提问。
  2. 自动构建仪表盘。
  3. 要求系统定期发送营收报告。
  4. 识别异常峰值、重点客户和新产品表现。
  5. 针对报告中的具体数据继续追问。
  • Genie对C-level管理层具有较强吸引力，因为高管目前仍主要依赖BI仪表盘，而Genie可以直接把自然语言交互与完整数据上下文结合。
  • Genie也可以成为Databricks的产品切入点，推动企业进一步将数据迁移至Lakehouse，并采用治理和智能体产品。

f) Genie相较Power BI、Tableau等产品有何优势？

  • 主要竞争产品包括Microsoft Power BI、Tableau及云厂商的类似解决方案。
  • 专家认为，其他产品的主要问题是缺少完整数据上下文。
  • Genie的差异化在于：
  1. 回答质量更高。
  2. 不会为了给出答案而生成不可靠内容。
  3. 如果信息不足，会明确说明缺少必要匹配数据。
  4. 更容易获得C级管理层的信任。
  • 专家个人每天使用Genie，并认为其显著提高了数据洞察效率。

7. 智能体生产化对Databricks收入的影响

a) 智能体从POC进入生产后，客户支出通常增加多少？

  • 支出增长取决于用户数量、数据是否已在Databricks中，以及是否需要迁移新数据源。
  • 主要可分为三类：

1. 数据已在Databricks、用户规模较小

  • 如果只需将智能体连接到现有数据，且仅供某个部门的2名员工使用，支出不会明显增加。

2. 智能体面向全组织推广

  • 如果智能体从测试阶段扩展至1000名用户，调用量将大幅增长。
  • 支出可能达到测试阶段的10倍至20倍。

3. 需要迁移新的数据库

  • 如果智能体需要使用原本未存储在Databricks中的数据库，企业可能将该数据库迁移至Databricks。
  • 此时收入不仅来自智能体调用，还包括数据迁移、存储、计算和治理，支出增长会进一步加快。

b) 智能体规模化为什么会为Databricks创造更大收入机会？

  • 智能体相比传统BI或人工查询，会产生更高频的数据搜索和处理需求。
  • 生产化后的收入驱动因素包括：
  1. 使用人数增加。
  2. 查询频次上升。
  3. 更多数据源接入。
  4. 更多数据库迁移到Lakehouse。
  5. 模型服务、评估、监控和治理需求增加。
  6. 单客户智能体数量持续增加。
  • 因此，真正的收入弹性主要出现在智能体从局部试验转向全组织生产部署之后。

c) 已生产化客户对Databricks完整技术栈的采用率如何？

  • 在专家负责的客户中，已将智能体投入生产的客户里，约95%的相关工作是在Databricks上完成。
  • 该比例主要指数据、智能体和治理层，不包括第三方基础模型本身。
  • 模型仍通常来自OpenAI、Anthropic、Google或开源供应商。
  • 客户倾向于采用完整Databricks技术栈的原因包括：
  1. 数据已经存储在Lakehouse中。
  2. Unity Catalog能够统一治理。
  3. 集中在单个平台上的用户体验更好。
  4. 可以减少多供应商集成和管理复杂度。

8. 客户切入点与产品扩张路径

a) Databricks通常通过哪款产品进入客户？

  • 客户切入点较为多样，且随着市场变化不断演进：
  1. 传统上以数据科学为主要切入点。
  2. 随后转向Lakehouse，帮助企业集中数据并开展数据科学、机器学习和BI。
  3. 随着合规要求提高，治理和Unity Catalog成为新的切入点。
  4. 目前即使客户尚未使用Databricks，也可以通过生成式AI、智能体和自然语言数据交互能力切入。
  • 当前策略不一定是先争夺传统数据仓库，而是先围绕智能体、LLM和治理层赢得客户。

b) 生成式AI如何推动其他Databricks产品扩张？

  • 当业务部门和高管通过自然语言与数据交互，并认可回答质量后，通常会推动数据团队接入更多数据源。
  • 产品扩张路径可能为：
  1. 从Genie或生成式AI应用切入。
  2. 引入Unity Catalog建立治理。
  3. 将更多数据迁移至Lakehouse。
  4. 使用Lakeflow连接更多数据源。
  5. 采用Agent Bricks构建和部署智能体。
  6. 进一步使用MLflow、模型服务和评估产品。
  • AI因此不仅是一项新增产品机会，也会反向推动Databricks传统数据平台业务增长。

9. 市场竞争格局与Databricks胜率

a) Databricks在新增智能体项目中的竞争表现如何？

  • 基于专家在比荷卢市场的观察，Databricks目前很少输掉已参与的智能体项目。
  • 但这一结论存在样本偏差：
  1. Databricks无法看到所有未接触到的项目。
  2. 不能据此声称赢得全部市场。
  3. 专家的客户群体可能天然更适合Databricks。
  • 在部分客户中，企业会自行研究后认为Databricks是最符合逻辑的解决方案，先开始使用，之后再联系Databricks寻求支持。

b) 大型企业为什么不会立即采用Databricks？

  • 大型企业通常已有开发团队和长期形成的技术体系，习惯自行开发产品。
  • 它们需要在两种路径之间进行选择：
  1. 自行构建智能体及治理体系。
  2. 使用Databricks等平台快速搭建。
  • 平台化方案可能将过去需要20周完成的工作压缩至1周甚至更短。
  • 但大型企业的变革管理复杂，决策周期最长可能达到2年。
  • 促成迁移通常需要明确推动力，例如：
  1. 新任CTO曾在其他公司使用Databricks。
  2. 当前系统出现明显成本或治理问题。
  3. 企业受到竞争压力。
  4. AI试验无法产生足够回报。

c) Databricks与Google、AWS和Microsoft的竞争关系如何？

Google

  • 一些技术实力强、重视创新的客户多年前选择了Google。
  • 这些客户会评估迁移至Databricks的商业价值，也可能继续将数据留在GCP并使用Google产品。
  • 若客户当前痛点不足，Databricks仍可能输给Google的平台统一策略。
  • 专家认为，未来成本和治理压力可能推动部分客户重新评估Databricks。

AWS

  • Databricks更多将AWS视为合作伙伴而非直接竞争对手。
  • Databricks可良好运行在AWS之上，双方也会合作推动业务增长。

Microsoft

  • Microsoft拥有强大的C级客户关系及完整产品组合，是更具现实威胁的竞争者。
  • 在专家观察的约50个机会中，Databricks可能仅输掉1至2个，主要优势仍是治理能力。
  • Microsoft的竞争优势在于：
  1. 与企业高管关系深厚。
  2. Azure、Power BI、AI Foundry和Purview形成完整组合。
  3. 在公共部门和传统企业拥有强大既有基础。
  • Databricks的风险在于，部分客户即使认可其产品，也可能因既有合同和关系继续选择Microsoft。

d) Databricks与Snowflake的竞争情况如何？

  • 专家表示，在智能体领域很少看到Snowflake，正面竞争中也基本没有明显输过。
  • 传统上，双方主要在数据仓库领域竞争，各有胜负。
  • Snowflake正在尝试拓展数据科学和机器学习，但这些并非其传统核心业务。
  • 随着智能体需要完整上下文，数据仓库逐渐成为标准化能力，需要被纳入更广泛的数据和治理体系。
  • 专家观察到越来越多客户从Snowflake迁移至Databricks，但迁移周期较长。
  • 如果客户已经在Snowflake生态中投入大量资源，通常不会立即迁移，因为实施成本和组织阻力较高。

e) 为什么Snowflake难以直接采用Unity Catalog进行竞争？

  • 从战略角度看，Snowflake采用Unity Catalog可能等同于承认Databricks拥有更好的治理产品。
  • 虽然Unity Catalog开源，但最新功能、复杂智能体治理能力和平台集成仍由Databricks领先。
  • 因此，竞争者即使基于开源版本开发，也难以快速达到Databricks托管平台的整体质量。

f) 单点解决方案是否会威胁Databricks？

  • Databricks通常不会将单点解决方案视为完全直接的竞争对手。
  • 如果某个单点产品在特定任务上更优秀，Databricks倾向于将其集成至平台。
  • 只要Unity Catalog掌握治理层，无论最终使用哪种：
  1. 向量数据库。
  2. 编程智能体。
  3. 基础模型。
  4. 模型服务工具。
  • Databricks仍可从数据、上下文和治理环节受益。

10. 技术创新、开源生态与人才战略

a) Microsoft Fabric为什么仍未达到Databricks水平？

  • Microsoft投入数十亿美元打造Fabric，希望构建类似Databricks的数据平台和Lakehouse产品。
  • Fabric本身建立在Spark、Delta、MLflow等Databricks开源技术之上。
  • 但专家认为，Fabric使用的相关版本落后于Databricks。
  • 根据其客户反馈，Fabric推出约4年后，整体能力仍未达到Databricks水平。
  • 专家将差距归因于：
  1. 最新技术版本和集成能力不同。
  2. 产品管理和工程执行难度较高。
  3. 顶尖技术人才的密度存在差异。
  4. 创新不仅取决于资本投入，也取决于能否吸引和保留少数顶尖研发人才。

b) Databricks如何通过并购强化创新？

  • Databricks收购创新型公司的重点未必是客户规模或现有产品，而是人才。
  • 被收购团队通常会在Databricks继续工作2至4年，帮助开发新产品。
  • 典型案例包括：
  1. 收购Mosaic AI后，其团队帮助Databricks构建生成式AI产品套件。
  2. 在安全领域继续收购创新型公司，以强化相关产品能力。
  • 专家认为，持续吸纳顶尖人才是Databricks相对Microsoft、Snowflake等公司的核心差异化优势之一。

11. 行业渗透、市场限制与潜在风险

a) 哪些行业更容易采用Databricks？

  • 数字原生企业启动较早，是当前AI投入增长的重要来源。
  • 金融机构虽然保守，但由于监管严格，对治理和合规要求高，Databricks在该行业反而具有较强竞争力。
  • 大型银行通常是各国规模最大的Databricks客户之一。
  • 企业越重视数据权限、审计、血缘和合规，Unity Catalog的价值越明显。

b) Databricks目前最难突破的领域是什么？

  • 公共部门是Databricks尚未充分取得进展的最大领域。
  • 主要原因包括：
  1. 长期依赖Microsoft体系。
  2. 采购和投资周期更长。
  3. 既有合同和客户关系更稳固。
  4. 组织变革速度较慢。
  • Databricks正在逐步取得进展，但当前市场份额尚未达到公司期望水平。

c) Databricks占据更高市场份额面临哪些限制？

  • 主要限制包括：
  1. 企业存在大量遗留系统。
  2. 云厂商及软件商拥有长期合同和客户关系。
  3. 数据迁移成本较高。
  4. 大型企业变革管理周期长。
  5. 部分企业尚未感受到AI带来的竞争压力。
  6. 企业IT团队可能对现有工作方式满意，缺乏变革意愿。
  7. 竞争对手未来可能形成新的独立治理层。
  8. 政治、数据主权和监管要求可能限制开源模型或跨平台部署。
  • 某些机构可能还需要多年，甚至约10年，才会真正开始规模化投资AI。

12. 未来6至18个月的关键催化因素

a) 当前市场尚未充分认识到的关键因素是什么？

  • 专家认为，市场尚未充分认识到企业上下文对智能体成功率的重要性。
  • 目前多数企业仍在孤立环境中进行AI试验，没有充分连接企业数据和治理体系。
  • 当企业在年底看到高额AI账单时，预计会开始要求实际成果和投资回报。
  • 如果实际ROI低于预期，企业会重新分析失败原因，并逐渐认识到：
  1. 问题不一定在模型。
  2. 核心问题可能是缺少上下文。
  3. 智能体没有接入完整、准确且经过治理的数据。
  • 这一认知变化有望成为Databricks未来6至18个月增长的重要催化因素。

b) 对Databricks最理想的发展路径是什么？

  • 企业先因缺少治理和上下文而发现AI试验效果不佳。
  • 随后寻求统一的数据和AI治理平台。
  • 通过Unity Catalog整合企业上下文。
  • 将更多数据源迁移至Lakehouse。
  • 使用Agent Bricks等产品将智能体投入生产。
  • 随着用户数和调用量增长，进一步扩大计算、存储、模型服务及治理支出。

完善技术栈，从而持续保持颠覆性。我们在H1看到的显著增长正是来自这些企业，但规模仍未达到预期水平。可以说，它们才刚刚开始扩大投入，目前主要在开展试验、连接首批数据源并建立治理体系。大多数企业仍在相对孤立的环境中进行试验，基本局限于1个人工智能解决方案、1个智能体或1个部门。

目前情况正在发生变化。企业开始认识到，它们在测试阶段投入了相当多的资金。此前的方式是允许所有人自由使用人工智能，探索能够实现哪些成果，之后再考虑如何治理。如今，这些成本已经引起董事会层面的关注。例如，有些公司在1个月内就用完了全年的预算。

因此，董事会开始施加更大压力，要求以可控、可监测的方式推进相关工作，确保人工智能具备必要的上下文和适当的治理，并引入其他组织架构以开展项目管理等工作。当前确实正在发生这种转变。

这对Databricks非常有利，因为企业的高层管理者已经认识到，要取得成功，上下文和治理至关重要。企业也在调整预算，释放更多资金，用于采购能够帮助其实现这些目标的公司服务和平台。
