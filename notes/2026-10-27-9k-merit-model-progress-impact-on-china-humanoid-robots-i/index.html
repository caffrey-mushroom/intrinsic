人形机器人产业与宇树科技专家访谈纪要

1. 人形机器人产业近期变化与大模型影响

a) 近期人形机器人产业发生了哪些主要变化？

  • 大模型公司开始进入机器人领域
  1. 大模型厂商开始为机器人提供“大脑”，并逐步参与机器人高层任务规划。
  2. 相较传统机器人企业，大模型厂商在任务理解、高层规划和长链条推理方面更具优势，实际效果也更好。
  3. 机器人“大脑”开始具备外挂通用模型的可能，产业分工由机器人企业全栈自研逐渐转向外部大模型、内部轻量模型和硬件执行层协同。
  • 机器人演示与产出形式发生变化
  1. 过去机器人演示主要集中在简单物理动作。
  2. 当前演示更强调具体场景中的完整任务执行，尤其是工业等B端场景中的任务拆解、规划与落地。
  3. 行业关注点正从“动作展示”转向“真实任务成功率和场景可用性”。
  • 行业出货量与中国市场地位提升
  1. 今年上半年全球人形机器人出货量明显高于过去1—2年，部分产能开始释放。
  2. 中国企业在全球人形机器人出货中的占比约为60%—70%，处于较高水平。
  3. 过去出货主要流向科研、文娱及小规模C端市场，目前工业制造场景的占比开始提升。

b) Astra/Astro模型给机器人产业带来了什么影响？

  • 注：原始访谈中交替使用“Astribot”“Astra”“Astro”等名称，以下统一简称为“Astra模型”。
  • Astra模型的核心优势是：
  1. 具备较强的长任务规划能力。
  2. 对上下文的掌握能力明显提升。
  3. 在部分Benchmark中达到Top 1水平。
  4. 在仿真数据训练和真机训练中均表现出较好的应用效果。
  5. 能够更明确地输出物理力度、方向和力值等相关指令。
  • Astra模型的产业意义主要体现在：
  1. 证明机器人“大脑”可以通过外部通用模型外挂接入。
  2. 大模型能够作为高层策略模型，机器人企业不必再完全从零研发基础模型。
  3. 机器人企业的研发重点可转向通用指令与具体动作之间的“中间翻译层”，以及端侧执行和软硬件协同。
  4. Astra改变了行业的技术范式，但尚未改变人形机器人商业化放量的既定时间表。

c) Astra发布约1个月后，产业界是否已经取得实质性进展？

  • 理论与测试层面已有明显进步
  1. Astra发布约30—50天，部分Benchmark表现已达到行业领先水平。
  2. 无论使用仿真数据还是真机数据训练，实际效果均优于此前不少模型。
  3. 当前相关任务的平均成功率约为90%，此前同类方案约为70%—80%，整体提升约10个百分点。
  • 实际落地仍存在明显局限
  1. Astra更适合作为模型顶层“大脑”，不适合作为单一模块直接承担全部动作输出。
  2. 如果直接用于最底层控制和物理动作输出，仍存在延迟高、执行不足等问题。
  3. 当前物理执行效果尚未达到机器人在复杂场景中规模化落地的要求。
  4. Astra带来的最大确定性是验证“大脑可外挂”，而不是直接解决机器人全部落地问题。

2. 机器人大脑技术路线与架构演进

a) 人形机器人大脑主要经历了哪些技术路线？

  • 第一阶段：端到端VLA
  1. VLA即Vision-Language-Action，通过视觉输入、语言理解后直接输出动作。
  2. 优点是动作执行链路较短、速度较快。
  3. 缺点是内部机制偏黑盒，难以解耦和分模块研究，系统可控性较弱。
  4. 出现问题时较难判断是感知、规划还是动作执行环节造成。
  • 第二阶段：System 1/System 2分层架构
  1. 以Figure Helix等方案为代表，将高层任务规划、端侧动作控制和底层平衡控制进行分层。
  2. 云端主要负责复杂任务理解和规划，端侧负责动作管理，底层负责平衡及实时控制。
  3. 优点是工程解耦能力较强，能够适配端侧算力、系统操作和数据闭环需求。
  4. 缺点是链路变长后会产生延迟，而物理AI对延迟远比传统软件敏感。
  • 第三阶段：World Model
  1. World Model能够提前预演可能发生的情况，并据此决定下一步动作。
  2. 优点是具备一定的因果预判和提前准备能力，可弥补分层模型的部分不足。
  3. 局限在于更擅长生成Image或未来状态，尚不能真正生成完整Action。
  4. 对指尖、四肢发力及物理调节等执行问题，仍缺乏充分支持。
  • Astra阶段
  1. Astra在高层规划之外，进一步增加了物理力度、方向和力值等指标输出。
  2. 其意义是将System 1向System 2进一步延伸，增强通用模型与物理执行之间的连接。
  3. 但其仍无法替代轻量VLA、端侧控制器及底层执行系统。

b) “通用大模型+轻量VLA+执行层”的分层路线是否已经确定？

  • 技术路线已经基本明确：
  1. 未来1—2年以及3—5年，行业预计均将以分层架构为主。
  2. 通用大模型负责高层任务理解、常识推理和任务规划。
  3. 轻量级VLA或中间模型负责将通用指令翻译为机器人可以执行的动作。
  4. 执行层负责实时控制、力控、平衡及具体物理动作。
  • 尚未完全确定的部分包括：
  1. 通用模型和轻量模型各自承担任务的比例。
  2. System 1与System 2之间的具体分工边界。
  3. 云端和端侧的算力配置比例。
  4. 随着更高效率模型或新硬件出现，架构比例仍会动态调整。

c) 分层路线是在Astra出现后才形成的吗？

  • 分层路线并非由Astra首次提出。
  1. 端到端VLA存在黑盒和不可控问题后，行业已经开始向分层架构收敛。
  2. Figure Helix的System 1/System 2架构是较重要的转折点。
  3. Astra的作用是在已经明确的分层路线基础上，进一步拓展通用模型对物理指标和动作策略的支持。
  4. 因此，Astra强化了分层路线的可行性，但不是分层路线的起点。

d) 未来机器人企业是否都会接入Astra类模型？

  • 短期来看，大部分企业不会再完全从零研发机器人基础大模型。
  • Astra类模型可以通过API接入，企业会重点开发：
  1. 通用指令到机器人动作的翻译层。
  2. 针对具体场景的轻量级VLA模型。
  3. 云端与端侧的协同机制。
  4. 底层运动控制、力控和平衡系统。
  • 主流模式预计是“外部接入+内部自研”并行：
  1. 接入外部通用模型，快速获得高层规划能力。
  2. 内部保留自研团队，训练场景模型并构建云端能力。
  3. 未来1—2年若出现效率更高、动作成功率更高的模型，底层通用模型仍可能更换。

3. 模型能力、成功率与训练数据

a) 机器人通用大模型达到可落地水平需要具备哪些能力？

  • 通用模型至少需要具备：
  1. 任务理解能力。
  2. 任务常识和环境认知能力。
  3. 长链条任务规划能力。
  4. 长时序动作操作能力。
  5. 将高层任务传递给端侧执行的能力。
  • 机器人模型对成功率的要求显著高于语言模型：
  1. 语言模型输出错误时，用户可以自行判断和修正。
  2. 机器人直接作用于物理世界，错误可能造成生产中断、设备损坏或安全事故。
  3. 真正投入应用时，任务成功率至少需要达到90%—95%，理想标准为95%以上。

b) 当前Astra类模型的任务成功率处于什么水平？

  • 当前短时序和长时序任务需要分别评估，但平均成功率约为90%。
  • Astra出现前，同类方案成功率约为70%—80%。
  • 现阶段距离95%以上的规模化应用门槛仍有差距。
  • 单纯提高通用模型成功率并不充分，还要同步提升中间层、端侧执行与硬件能力。

c) 当前机器人训练数据的主要瓶颈是什么？

  • 最大瓶颈是高质量多模态对齐数据不足
  1. 高质量数据并非单纯追求数量，而是要求不同模态在同一时刻精确对齐。
  2. 需要对齐的数据包括视觉、语言、关节状态、关节角、力矩、IMU及触觉等。
  3. 国内外高质量机器人数据的缺口均在80%以上。
  4. 数据质量不足正在限制机器人模型进一步训练和提升。
  • 数据有效率偏低
  1. 即使每天采集8小时，真正有效的数据可能只有约3小时。
  2. 有效数据占比约为20%—30%。
  3. 数据采集成本高并不代表最终可用数据量高，清洗、标注和多模态对齐仍会造成大量损耗。

d) 真实数据和仿真数据的成本及使用方式有何差异？

  • 真实数据
  1. 主要来自真实工业场景、第三方制造企业合作及真机遥操作。
  2. 真机遥操作成本约为每小时500—1000元，接近每小时1000元。
  3. 成本高、有效率有限，但对模型后期校准和真实落地非常重要。
  • 仿真数据
  1. 主要通过已搭建的系统、工具或仿真框架生成。
  2. 在系统完成搭建后，边际成本接近于零。
  3. 适合大规模预训练，但与真实物理环境之间仍存在差异。

e) 模型训练不同阶段的数据配比如何？

  • 模型训练大致分为两个阶段：
  1. 前期框架训练以仿真数据为主，仿真数据占比约70%。
  2. 后期校准阶段以真实数据为主，真实数据占比可能达到60%。
  • 原始访谈中关于“前期真实数据与仿真数据为7:3”的表述与“前期仿真数据占70%”存在口径冲突。结合上下文，较合理的理解为：
  1. 前期仿真数据与真实数据约为7:3。
  2. 后期真实数据占比提升，真实数据与仿真数据的关系大致反转。

f) 轻量级VLA模型的数据需求与通用模型有何不同？

  • 轻量级VLA通常针对具体场景进行训练，例如：
  1. 工业分拣。
  2. 工业质检。
  3. 上下料。
  4. 巡检和零部件搬运。
  • 其训练数据以真实场景数据为主，因为最终需要在对应工业环境中落地。
  • 不同场景的复杂度、动作类型和执行要求差异较大，因此无法形成统一的数据量标准，也无法直接与通用VLA进行量级比较。

4. 延迟、硬件与软硬件协同

a) 接入云端大模型后，时延问题如何解决？

  • 当前主流架构是：
  1. 云端运行通用大模型，负责复杂任务理解和规划。
  2. 边端运行轻量控制器或小模型，负责实时动作执行。
  3. 底层硬件负责运动控制、平衡、力控和安全。
  • 时延是现阶段客观存在的问题：
  1. 软件应用可以接受等待，但机器人在物理世界中需要实时响应。
  2. 云端规划到端侧执行的链路较长，动作延迟会直接影响稳定性和安全性。
  3. 时延下降更多依赖端侧硬件、算力和控制系统提升，与通用模型本身的关系相对较小。

b) 为什么当前大模型能力提升后，机器人仍未达到理想效果？

  • 当前短板已经从单纯的模型能力扩展至软硬件整体协同：
  1. 全身电机的力控能力仍需提升。
  2. 灵巧手小型电机的精细控制能力不足。
  3. 六维力传感器、触觉传感器等硬件能力仍需完善。
  4. 装配线适配、任务协同及执行稳定性仍未成熟。
  5. 模型、中间层和硬件之间的延迟尚未得到根本解决。
  • 国内第三方硬件企业未来仍有较大提升空间，硬件可能成为下一阶段产业突破的重点。

c) 软硬件协同达到理想状态需要多长时间？

  • 硬件能力及软硬件延迟问题的改善不太可能以半年为单位完成。
  • 若要实现明显技术突破，预计至少需要接近1年。
  • Astra使大模型策略层取得进展，但机器人是否能够真正放量，仍取决于模型、中间层、执行控制和硬件的整体协同性。

5. 宇树科技的大脑能力与数据布局

a) 宇树是否仍然是“运动控制强、大脑能力弱”？

  • 过去这一评价需要适当调整。
  • 宇树硬件能力已经获得行业广泛认可，软件能力也在持续提升：
  1. 软件侧整体能力可进入Tier 1。
  2. 在运动控制、灵巧手和执行力控制方面具备较强能力。
  3. 软件和硬件团队能够形成整体闭环。
  4. 宇树既有内部自研团队，也与外部模型公司开展合作。

b) 宇树的大脑采用什么技术方案？

  • 当前采用“外部模型接入+内部自研+云端协同”的组合路线：
  1. 尝试接入Astra类外部通用模型。
  2. 在外部模型基础上开发云端高层规划能力。
  3. 内部继续训练轻量模型和场景模型。
  4. 保留自研团队，推动运动控制和模型能力持续迭代。
  • 现阶段仍处于尝试和验证阶段，尚不能认为已完全以某一外部模型作为唯一底座。

c) 宇树如何获取训练数据？

  • 真实数据来源
  1. 与第三方制造企业合作，在真实工业场景中采集数据。
  2. 与国内新能源车企等客户合作，将不同型号机器人部署至计划落地的场景。
  3. 采集分拣、上下料等任务中的场景数据、机器人动作数据和人工配合数据。
  4. 通过遥操作和训练场采集视觉、触觉及动作数据。
  • 仿真数据来源
  1. 使用仿真系统和框架开展训练。
  2. 通过仿真环境生成较大规模的动作和场景数据。

d) 宇树当前数据积累大致是什么量级？

  • 真机数据可能以千小时为单位，整体数量并不算大。
  • 仿真数据可能以万为单位。
  • 具体外部供应商、采购金额和场景拆分未披露。

e) 宇树相关研发支出的优先级如何？

  • 按支出规模排序：
  1. 模型侧支出最高。
  2. 数据侧支出其次。
  3. 第三方硬件采购支出占比相对较低。

6. 商业化场景、放量节奏与市场空间

a) 哪些场景最有可能率先实现批量落地？

  • B端工业场景将率先突破，重点包括：
  1. 工业分拣。
  2. 上下料。
  3. 巡检。
  4. 物料及零部件搬运。
  5. 汽车内饰和外饰装配。
  6. 与人工协同作业。
  • 汽车工厂是当前最成熟的应用场景之一：
  1. 国内新能源车企已开始进行部署。
  2. 美国部分传统车企也在推进相关应用。
  3. 部分第一梯队企业已经开始盈利并获得批量订单。

b) 工业场景何时能够实现更大范围的批量应用？

  • 当前部分工业场景已经实现小批量落地。
  • 若要达到不同制造企业普遍批量采用的程度，预计还需要接近1年。
  • 2026年相较2025年，真实应用落地预计会有所加速，但仍处于原有行业预期范围内。

c) Astra是否加快了机器人放量时间表？

  • Astra没有明显改变既定产业时间表。
  • 其主要作用是改变技术范式：
  1. 大模型可以直接承担策略模型角色。
  2. 企业对具体任务进行大量微调的需求可能下降。
  3. 场景开发效率理论上有望提升。
  • 但最终落地仍受制于：
  1. 机器人本体和硬件能力。
  2. 任务成功率。
  3. 软硬件协同性。
  4. 数据质量与数据效率。
  5. 真实产线适配能力。

d) 全行业何时能够达到100万台规模？

  • 100万台是较为理想化的长期目标。
  • 当前模型能力虽有提升，但硬件、装配线适配及实际任务协同仍未同步跟上。
  • 短中期更适合以10万台、20万台等规模进行判断。
  • 全行业达到100万台可能要到2030年前后或更晚，属于长期事件。

  3. 底层执行层负责实时物理控制。
