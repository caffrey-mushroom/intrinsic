专家访谈纪要

1. Agent推理集群的存储配置与发展阶段

a) 当前先进Agent推理集群的单卡存储配置大致如何？

  • 单卡典型配置如下：
  1. HBM约为256GB。
  2. DRAM约为500GB—1TB。
  3. SSD约为10TB。
  • 对应的容量比例大致为：
  1. HBM与DRAM约为1:2—1:4。
  2. DRAM与SSD约为1:10—1:20。
  • 当前整体配置已进入相对稳态，但SSD容量仍有进一步提升空间。

b) 为什么未来单卡SSD配置仍可能继续增加？

  • SSD此前主要用于存储KV Cache，包括模型计算缓存和历史上下文。
  • 随着Agent任务复杂度提升，SSD还需要承载更多数据：
  1. 多进程Agent运行产生的交互记录。
  2. Agent处理文件时产生的中间态数据。
  3. 网页、文档等内容的预计算结果。
  4. 多模态任务产生的关键帧、向量数据和非结构化数据。
  5. Agent调度过程中产生的中间文件和交互产物。
  • 当前推理集群尚未因中间状态和中间文件而大幅增加SSD，但随着视频理解、世界模型、3D渲染和具身智能等场景发展，相关需求会明显上升。

c) 未来DRAM和SSD中，哪一类存储的增长弹性更大？

  • DRAM配置的增长弹性预计不会特别大，未来主要增量将来自SSD。
  • 原因是Agent任务越来越长，需要保存的上下文、KV Cache和中间结果持续增加，而这些数据无法长期保留在成本更高的DRAM中。
  • 行业整体预计都会增加SSD配置，SSD将成为推理集群扩容的重要方向。

2. KV Cache命中率、存储分层与投资回报

a) 决定DRAM和NAND配置量的核心指标是什么？

  • Prefix Cache命中率是最关键的指标之一。
  • 当前行业头部参与者的命中率基本能够达到85%以上。
  • DeepSeek在阿里环境中的稳态命中率基本达到90%以上。
  • 用户使用越重、任务叠加轮数越多，缓存价值越高：
  1. 长任务每轮可能需要接近100万Token上下文。
  2. 任务过程中可能需要进行2—3次上下文压缩。
  3. 如果前文缓存能够被重复命中，就可以避免大规模重复计算。

b) 为什么长任务中的KV Cache Offloading具有较高ROI？

  • 对于长任务，只要历史KV Cache被成功命中一次，就可能节省大量重算成本。
  • Agent任务与Chatbot不同，通常可以容忍更高延迟，单次任务执行时间可能达到十几分钟甚至二十分钟。
  • 在Token规模持续扩大、任务Loop不断延长的情况下，将KV Cache从DRAM转移至SSD具有较高经济价值。
  • 因此，长期看SSD Offloading可能成为Agent推理集群的必要基础设施。

c) 当前内部如何评估KV Cache Offloading的ROI？

  • 目前评估方式仍相对粗放，尚未形成特别精细的ROI体系。
  • 0731版本V3 Flash需求大幅增长后，缓存存储压力迅速上升。
  • 当前主要问题包括：
  1. SSD缓存刷新速度过快。
  2. 缓存有效期较短。
  3. 新用户数据可能快速覆盖老用户缓存。
  4. 老缓存被覆盖后，无法继续命中，只能重新计算。
  • 公司正在逐步建立更精细的缓存价值和ROI评估体系。

d) 新用户覆盖老用户缓存，是软件调度问题还是容量问题？

  • 主要原因是NAND配置不足，而非单纯的软件调度问题。
  • 当存储池被打满后，只能使用新文件覆盖老文件。
  • 老文件被覆盖后，对应缓存无法再被检索，从而降低Prefix Cache命中率。
  • 这意味着当前SSD容量仍存在明显扩容需求。

e) DRAM与SSD之间如何确定数据迁移的时间边界？

  • 数据在DRAM中的保留临界点会动态调整，通常在3—10分钟之间。
  • 超过10分钟的数据，基本会考虑转移至SSD。
  • 这一策略兼顾了DRAM的低延迟优势和SSD的低成本、大容量优势。

f) 数据落盘至SSD后通常保留多久？

  • 一般不会主动立即丢弃，24小时是经验性的最长保留参考值。
  • 如果容量足够且没有新数据覆盖，缓存可以持续保留。
  • 但由于集群负载较高，实际缓存通常会在24小时内被新数据覆盖。
  • 实际策略会尽量按照8小时工作时长，或上午、下午两个工作时段安排缓存，使长任务能够在工作时间内接续执行。

3. SSD Offloading的软件栈与文件系统壁垒

a) 为什么部分推理服务商认为SSD Offloading延迟过高？

  • 部分厂商的文件系统和缓存机制没有针对AI原生推理场景进行充分优化。
  • 传统文件系统主要面向普通文件存储，而AI推理缓存具有以下特征：
  1. 高并发。
  2. 高碎片化。
  3. 大量小规模、动态读写。
  4. 需要快速寻址和并行读取。
  5. 单份缓存可能被拆分至10个甚至100个SSD中。
  • 如果沿用传统文件系统，SSD绝对带宽和数据搬运带宽可能不足，导致读取延迟过高，甚至不如丢弃缓存后重新计算。

b) 受访方在SSD Offloading方面的差异化能力是什么？

  • 受访方针对网页内容预计算、历史缓存和缓存调度建立了独立策略。
  • 核心优化包括：
  1. 对缓存进行分片，将同一份数据分散至多个存储块。
  2. 并行调用多个SSD的带宽。
  3. 优化缓存的快速寻址和逻辑拼接。
  4. 统一调度文件和向量化内容。
  5. 对历史缓存进行更精细的分层管理。
  • 经过软件栈和文件系统优化后，SSD Offloading可以达到工程可用状态，延迟也能够控制在合理范围。
  • 专家认为，智谱、千问等参与者目前尚未形成同等水平的能力。

c) AI原生缓存文件系统与传统云文件系统有什么区别？

  • 传统云存储强调数据可靠性和不丢失，架构更多围绕文件形态设计。
  • AI原生缓存系统强调极致性能和低成本，可以接受一定程度的缓存丢失：
  1. 缓存丢失后可以由计算卡重新计算。
  2. 可以牺牲部分SSD寿命换取更高读写性能。
  3. 可以牺牲部分稳定性，换取更激进的并发和分片能力。
  • 两类系统的目标不同，因此底层架构和优化方式存在明显差异。
  • 早期参与模型量化和推理优化的团队，通常对缓存可丢失性、低精度计算和存储分层有更深理解，由此积累了较强know-how。

d) 为什么阿里等云厂商在该方向进展相对较慢？

  • 云厂商原有文件系统更偏传统云存储架构，迁移到AI原生缓存系统需要进行较大改造。
  • SSD Offloading需要针对高碎片、高并发、向量化数据和缓存分片进行极致优化。
  • 云厂商如果集中资源攻关，理论上能够解决，但其整体业务体量较大，该项优化带来的边际收益未必足够显著，因此投入优先级可能有限。

4. 推理效率、MFU与毛利率差异

a) 除KV Cache Offloading外，推理服务商的效率差距还来自哪里？

  • 主要差距还来自算力自持率、硬件标准化程度和工程优化能力。
  • 智谱等厂商算力自持率不足，此前较多依赖英伟达计算卡。
  • 目前虽然开始引入国产推理算力，但首要任务仍是解决兼容性问题。
  • 其采用国产异构算力混配策略，难以在统一、标准化的大规模架构上充分优化。
  • 相比之下，标准化超节点更容易实现：
  1. 大规模推理。
  2. 大MoE模型运行。
  3. 单一模型多并发。
  4. 算力和通信效率的系统性优化。

b) 国产算力在大规模推理中的MFU能够达到什么水平？

  • 在华为万卡超节点大推理集群中，MFU可达到60%—70%，接近训练阶段水平。
  • 只有达到这一水平，国产万卡超节点整体算力才有机会与H系列GPU集群竞争。
  • 专家认为，国产卡的采购价格、推理MFU和集群效率需要同时被压榨到极致，才能建立经济性。

c) 英伟达GPU的MFU是否也可以提升到60%左右？

  • 如果模型厂商同时掌握模型和Infra，并愿意对系统进行深度优化，英伟达GPU的MFU同样有机会提升至约60%。
  • 受访方此前已经实现过类似水平。
  • 因此，决定推理效率的不只是硬件本身，还包括：
  1. 模型结构。
  2. 软件栈。
  3. 通信优化。
  4. 缓存管理。
  5. 低精度推理。
  6. 模型与硬件的协同设计。

d) 低精度推理对成本和毛利率有什么影响？

  • MXFP4、FP4等低精度方案会显著影响模型原生推理效率和毛利率。
  • 在保证模型效果的前提下，低精度推理可以降低单Token算力消耗。
  • 低精度方案需要模型、算子和硬件之间进行协同优化，不能只依靠硬件侧切换精度。

5. 海外厂商的KV Cache策略差异

a) OpenAI为什么积极采用缓存和SSD Offloading策略？

  • OpenAI拥有较大的C端用户规模和推理需求量。
  • 低端模型定价、套餐额度和个人AI业务会产生巨大的Token消耗。
  • 如果希望降低模型价格、提高Token供给量，就必须在以下方面进行基础设施储备：
  1. 内存分层。
  2. Prefix Cache。
  3. SSD缓存。
  4. 大规模低成本推理。
  • Personal AI如果进一步覆盖本地生活和移动生活场景，也会产生更多长上下文和持续缓存需求。

b) Anthropic为什么未表现出同等强度的SSD Offloading需求？

  • Anthropic采取更偏高端化的产品策略，强调：
  1. 模型高性能。
  2. 高能力。
  3. 高溢价。
  4. 高毛利率。
  • 其没有强烈动力通过大量缓存和增加Token消耗来降低模型价格。
  • 相比追求极致性价比，Anthropic更关注模型表现和高价值客户，因此缓存基础设施的优先级相对较低。

6. 多模态发展与存储采购需求

a) 明年NAND和DRAM需求可能增长多少？

  • 当前无法进行准确的采购量预测，只能定性判断增长倍数。
  • 专家认为，在现有基础上增长5—10倍仍属于偏保守估计。
  • 主要驱动因素不是传统文本推理，而是多模态能力扩张，包括：
  1. 3D渲染。
  2. 世界模型。
  3. 具身智能。
  4. 原生视频理解。
  5. 更复杂的Agent调度。
  6. 非结构化数据处理。

b) 为什么多模态会显著增加SSD消耗？

  • 视频上传后通常需要拆分关键帧，提取动作节点和关键节点，并丢弃冗余内容。
  • 即使最终只保留少量关键帧，处理过程中仍会产生大量中间结果。
  • 这些结果可能通过向量数据库或其他非结构化方式进行存储。
  • 多模态任务同时消耗显存、内存和SSD，其中SSD承担大量中间态和长期缓存存储。

c) 明年DRAM和NAND价格如何判断？

  • 专家判断价格较难下降，整体可能维持紧平衡并继续上涨。
  • 尽管国产存储产能增长较快，但需求端也在同步扩大：
  1. AI推理集群持续扩容。
  2. 国产算力需要配置更高规格显存。
  3. 多卡替代单卡会增加总显存需求。
  4. 多模态任务增加SSD和DRAM需求。
  • 因此，供给增长未必足以抵消需求扩张。

d) 国产算力为什么会进一步增加显存需求？

  • 国产卡单卡性能相对有限，通常需要通过“多打一”的方式弥补。
  • 例如，可能需要4张国产卡应对海外1—2张高端卡的任务。
  • 即使每张国产卡配置128GB显存，4张卡的总显存容量也会显著高于单张海外高端卡。
  • 因此，国产算力渗透率提升将同步带动国产显存需求增长。

e) 公司如何采购DRAM、NAND和集群设备？

  • 公司并不直接大规模采购DRAM和NAND。
  • 当前主要由华为提供完整超节点或机柜，并负责相关存储配置。
  • 公司在机柜基础上再配置独立存储池。
  • 独立存储池预计采用分级混配策略，可能根据性能、寿命和成本要求搭配不同类型NAND。

f) 明年Capex是否会明显增长？

  • 当前尚未形成明确预算。
  • 新融资可能刚刚到位，公司尚未决定具体资金分配方式。
  • 对明年是否建设上万卡集群，内部仍存在较大分歧。
  • 因此，目前无法量化明年Capex相较今年的增幅。

7. 算力限制、国产替代与行业竞争格局

a) 英伟达高端卡限制对受访方有什么影响？

  • 目前对受访方影响有限，原因是此前已经进行了多路准备：
  1. 建设自有推理算力。
  2. 全面拥抱华为算力体系。
  3. 推进国产超节点架构。
  • 华为明年的产能预计将获得较多国家层面的保障。
  • 相比之下，其他缺乏国产算力适配能力的厂商可能面临更大压力。

b) 海外算力租赁限制对国内大模型厂商有什么影响？

  • 此轮限制预计较为严格，过去部分可行的路径可能逐渐被封堵。
  • BAT等海外业务较多的厂商此前可能在海外租用了较多算力，后续使用可能受到限制。
  • 过去可以在海外训练Base Model，再迁移至国内进行合规增训；未来模型和算力跨境流动都将受到更严格限制。
  • 这可能对厂商明年的收入增长、模型Scale和迭代速度产生较大影响。

c) 哪些厂商受到的压力可能更大？

  • 大厂仍有较强资金和资源支持，但中小型模型公司将面临更大困难。
  • MiniMax等玩家即使具备资金，也可能难以获得足够可用算力。
  • 蒸馏路径也在变难，单纯依靠外部模型能力迁移的空间缩小。
  • 专家认为，算力和数据同时不足，已经影响部分新模型的实际发布效果。

d) 国内模型厂商是否仍有独立发展机会？

  • 专家认为仍存在独立发展路径：
  1. 通过更高效的模型结构，使3T参数模型具备与其他公司10T模型竞争的可能。
  2. 今年首批基于950的万卡集群有望支持3T参数级超大模型训练。
  3. 后续基于960DTI等算力形态建设万卡超节点，可能支撑5T参数级模型。
  4. 国内电力成本相对较低，可以通过更高功耗和更多卡数弥补单卡性能不足。
  • 国产替代的核心不是单卡性能对标，而是通过模型效率、超节点、通信架构和能源成本建立系统性竞争力。

8. TPU、国产超节点与英伟达GPU的架构比较

a) 为什么脱离英伟达可能反而适合部分大规模训练场景？

  • 专家认为，Anthropic模型能力突出，除团队和模型策略外，谷歌TPU大规模集群也提供了重要支持。
  • TPU集群有利于：
  1. 加快模型迭代速度。
  2. 开展更激进的RLHF。
  3. 并行运行大量强化学习环境。
  4. 提升超大规模张量计算效率。
  • Anthropic使用TPU的经验说明，非英伟达体系在超大集群训练中也可能形成优势。

  • 更早期的产品基因来自消费级游戏显卡，并非原生面向超大规模向量和张量训练。
  • 随着集群规模扩大，卡间通信、光互联和同步效率会成为限制因素。

c) 谷歌TPU的核心优势是什么？

  • TPU从设计之初就更偏向大规模向量计算和张量处理。
  • 谷歌在原生超算级计算架构、硬件调校和大集群互联方面积累更深。
  • 因此，TPU体系的AI Infra能力上限可能高于传统GPU集群。
  • 国产超节点也试图通过标准化大规模架构、通信优化和多卡协同，建立类似的系统性能力。

分析师：我理解，SSD本身存在硬件限制，不太适合小规模、灵活的读写，带宽也相对较低。因此，较为合适的方式包括2个方面：第1个方面是配套合理的软件栈进行统一调度；第2个方面是配置大量集群，将同样的1份文件分散在多个存储块中，同时进行读写，从而提升带宽。海外也有Weka等厂商采用类似方案。这个领域应该具备一定的know-how，而且非常mission critical，直接决定了推理业务的毛利率。我很好奇，为什么阿里没有做到？这个问题很重要，但其进展似乎非常缓慢，毕竟offloading已经发展了1年。

专家：最大的原因在于，构建固态存储文件系统时，有1类系统更多是基于AI原生需求，或者专门面向高性能推理、大量缓存以及向量化内容的存储进行设计，而不是按照传统FS或面向文件的存储架构进行设计。

这2类架构存在明显差异。传统互联网大厂或云厂商设计的架构，更多偏向传统文件形态。固态存储则需要应对大量高碎片、高并发场景，甚至可能将1个缓存拆分到10个乃至100个固态存储中，同时充分利用其带宽，实现快速分发。每1个固态存储中还需要进行专门设计，包括如何快速寻址、完成逻辑拼接，以及如何并行读取等，均需要极致优化。

这种设计相应会牺牲部分能力：1方面可能会牺牲固态存储的寿命，另1方面也会牺牲存储的稳定性。云存储的策略是数据不能丢失，但对于缓存而言，如果确实无法找到或检索失败，可以由计算卡重新计算。因此，这2种场景天然具有不同的优化策略。此前较早开展量化工作的相关参与者，对此也具备独特理解和know-how。上述2项因素结合，造成了目前的情况。

阿里等云厂商如果集中攻关，也能够解决这一问题，但对其而言，实际效益没有那么明显。
