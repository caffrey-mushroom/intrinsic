Q:你能简要介绍并详述甲骨文（Oracle）最近宣布与Cerebras达成的合作吗？

A:两家公司最近在 Oracle AI World 上宣布，甲骨文正在引入额外的合作伙伴，以扩大面向联合客户的快速推理机会。这将允许 OCI 为客户提供基于 Cerebras Wafer-Scale Engine 的高速 AI推理。该引擎将计算和内存共置于单个晶圆级处理器上，减少数据移动和所需的片间通信。预计它能够在长推理序列中实现更快的 token 生成，并改善多步骤代理式 AI 工作流。

Q:目前合作处于什么阶段？预计何时会在 OCI 上部署 Cerebras 服务？

A:已宣布 Cerebras 在 OCI 上的推理服务将在日历年 2027 年提供，但尚未给出具体日期。AI World 是甲骨文的旗舰年度大会，合作已在此宣布。我推测在该服务变为普遍可用之前，后台还会有相当多的工作需要完成。

Q:在此合作下，甲骨文会购买 Cerebras 的服务器或硬件，还是会购买 Cerebras 的云服务？换言之，商业模式将如何？

A:据我所知，甲骨文支持多种运营模式，并已在 OCI 中宣布了 BYOH（Bring Your Own Hardware）模式。例如，如果某个客户或潜在客户拥有特定类型推理硬件的配额，甲骨文可以提供客户部署并使用该硬件的基础设施。不过，针对Cerebras 的具体运营模式尚未正式宣布。目前并未披露甲骨文计划使用多少 Cerebras 硬件，也未披露任何特定的容量分配、定价或部署细节。现阶段的公告是双方团队将合作为联合客户提供服务。

Cerebras 销售的是称为 CS-3 的整套系统，每套都围绕一颗晶圆级芯片构建。关键问题在于谁将拥有这些系统。存在三种可能的模式。甲骨文可以购买这些系统并自行将推理服务货币化；Cerebras 可以拥有这些系统，而甲骨文托管可能称为Cerebras Cloud 的服务，并通过基于使用量或计量的定价来为联合客户提供服务；或者，这种安排可能类似于 BYOH 模式，即第三方拥有硬件，甲骨文提供周边基础设施。这类似于 AWS所称的混合模式，也反映了甲骨文近期交易中看到的趋势。

Q:为什么甲骨文会选择 Cerebras 作为其 ASIC 合作伙伴之一，同时还有 Google TPU、SambaNova 和 Jalapeño 等合作伙伴？

A:我认为这主要不是竞争问题，而是基于客户所选工作负载来创造客户选择。代理式 AI 正在成为甲骨文客户以及作为致力于 AI 的企业的甲骨文的一个重要工作负载。据我了解，Cerebras 适配甲骨文通过其 Fusion 和 NetSuite应用套件以及其数据库所推广的代理式工作负载。甲骨文还宣布了名为 AI Workspace 和 App Composer 的产品，旨在使企业终端用户能够进行更多代理式应用的开发和部署。Cerebras的方案直接对应这一需求：每个代理步骤都需要推理，而更快的推理可以让 AI 做更多事情而不让用户等待。

甲骨文将 Cerebras 描述为增加了一个超快且确定性的选项。确定性这一点对企业应用很重要。在大会上，负责应用 SaaS 业务的执行副总裁 Chris Leone 讨论了 Fusion CLAW 和 Fusion Agentic Applications，明确区分了模型推理的使用场景与更需要确定性动作的场景。合适的组合能使交互基于企业事实和上下文，这对建立终端用户信任至关重要。在可预测的响应时间与原始模型速度同样重要的场景下，专注于快速推理的供应商会进入候选名单。

Groq 曾是另一个提供超低延迟推理的厂商，几个月前作为许可交易的一部分被 NVIDIA 收购。这实际上使得除 NVIDIA 之外，Cerebras 成为主要的纯粹快推理供应商。从甲骨文提供客户选择的角度来看，与 SambaNova 和Cerebras 等供应商签约也为 Groq 或 NVIDIA 随后基于该技术发布的产品提供了替代方案。这里可能也存在与 OpenAI 的关联：Cerebras 在大规模环境中已被 OpenAI 证明可行，我了解到 OpenAI 同意购买750 兆瓦的 Cerebras 推理容量，而 OpenAI 也是甲骨文的一个重要基础设施客户。这可能是另一个驱动因素，尽管交易细节尚不清楚。

Q:确定性动作，或企业 AI 中的确定性部分，是什么意思？

A:确定性意味着在执行某项任务或动作时具有明确且可重复的过程。在企业 AI 中，有两个不同的概念：确定性行为和确定性性能。更大的企业问题是确定性行为。LLM 传统上是概率性的，因此如果两个人向相同的 LLM提出相同的问题，他们可能会得到相似但不完全相同的答案。这是概率性的，因为它不像两个人在计算器中输入 2+2 并总是得到 4 那样可重复、可审计和可控。

为管理概率性行为，企业必须对代理及其所读取的来源进行治理。必须将护栏、策略和规则以代码形式定义来验证 LLM输出，同时还要处理权限和身份。可能需要将人工插入循环以提供审批，并需要评估以创建反馈回路并验证已记录的模型输出是否与预期一致。这是概率性行为与确定性行为之间的基本区别。

另一个概念是确定性性能，意味着延迟的可预测性：相同的请求每次处理所需的时间相同。这是人们可能期望来自像 Cerebras 这样的快速推理基础设施的两类确定性之一。

Q:你能否描述与 Oracle 相关的加速器和 ASIC 相关产品的优缺点，包括 Google TPU、OpenAI 的 Jalapeño、SambaNova、Cerebras、OCI Acceleron 以及其他相关产品？

A:首先，对于 OCI Acceleron 有一个误解：它不是一款 ASIC 芯片。它是 Oracle 的网络解决方案，提供专用数据平面和优化的数据包路由，以消除大规模 AI 训练和实时推理过程中的瓶颈。它大约在 2024 年或 2025年左右宣布——确切年份不明确——现已普遍可用。OCI Acceleron 为要求苛刻的 AI 工作负载提供高性能云网络和加速互联，使分布式 AI 与数据处理环境中的数据移动更快、更高效。

OCI Acceleron 使用专用数据平面和硬件控制来路由信息并卸载网络开销，包括数据包处理，而不占用主机 CPU 资源。它本质上是硬件与算法的组合，能够在超高吞吐路径上以超低延迟动态路由工作负载数据包。NVIDIA 在 NVLink上也做了类似投资。NVIDIA 也放宽了此前在某些情况下要求客户与其芯片一同使用 NVLink 的限制，从而允许像 Oracle 这样的超大规模云提供商通过使用自身网络技术与推理和训练芯片搭配来改善利润率。

关于 Google TPU，Google 已展示了在大规模下执行非常大矩阵运算并在价格-性能上取得令人印象深刻的成就，尤其是在训练方面。Google 可能是目前在训练领域最强劲的竞争者，也是对 GPU的最为成熟的替代方案。主要风险在于软件迁移。客户从 NVIDIA 转向 Google TPU 可能需要将其在 CUDA 上构建的内容迁移到 Google 的基础设施上。这是通过迁移到 TPU实现成本降低策略时的主要风险，尽管对于全新工作负载而言其相关性较小。

Google 也拥有完整的技术栈。它可以在 TPU 基础设施上测试其 Gemini 模型，使用同一基础设施进行 AI 模式搜索，并对诸如 Google Photos、Google Maps 之类的大型存储库执行多模态训练与推理。Google为训练与推理配备了不同的芯片。训练芯片每 pod 的计算能力约为前代的 3 倍，而推理系统则针对由专门 agent 执行的迭代工作进行优化，且可扩展至每 pod 超过 1,152 片芯片。Google宣称在价格-性能上有优势，包括训练每美元性能接近提升 3%，推理相比前代最高可提升 80%。Oracle 计划一个多年期的扩展以达到千兆瓦级规模。需求很大，因为包括 Anthropic 和 OpenAI 在内的公司是 TPU的购买方，我认为这些公司在上市后会有财力按需支付基础设施。

在缺点方面，Google 的软件仍以 JAX 为先，原生 PyTorch 支持仍处于预览阶段，因此一些团队将面临端到端迁移的工作。Oracle 提供除芯片外的一切，包括电力、制冷和网络。因此 OCI 的利润率将在一定程度上取决于 OCI Acceleron，这一补充 Google 硅片的网络结构，系统级性能是否能满足客户目标仍有待观察。这些系统还在机架级别需要直接液冷。地区、实例类型和定价尚未公布。这些仍是悬而未决的问题，尽管 OCI- Google TPU的产品目标锁定为 2027 年。

OpenAI 的 Jalapeño 由 Broadcom 代工。尚未宣布发布日期，我也不认为其已宣布为 2027 年可用。Jalapeño 是由 OpenAI 定制委托的，并扩展了 Oracle与最大模型供应商之间的关系——该处的未决订单量最大。Oracle 可能会作为其主要基础设施客户之一来支持 OpenAI 的部署需求。Jalapeño 扩展了 OpenAI 的高效推理能力，并加深了 Oracle 作为 OpenAI基础设施提供者的角色。OpenAI 声称其在某些开源模型上的运行速度比竞争硅片快约 1.5 倍，Sam Altman 在十月的 AI World 大会上对此作了积极表述。

需要注意的是，Jalapeño 似乎并不是 OCI 客户可以租用的产品。目前来看，它主要面向其创造者 OpenAI 本身。因为 OpenAI 是 OCI 的租户，Jalapeño 很可能是为 OpenAI 自用而设计，目前尚不清楚OpenAI 是否计划像 Google 在 OCI 上提供 TPU 那样将其作为服务对外出售。它也是首代硅片和 OpenAI 的第一个定制推理加速器。它仅在今年六月发布，公开信息很少，且未宣布可用日期或定价。

对于 Cerebras，优势是极高的单用户速度，其声称约为下一个最快 GPU 云的 6 到 7 倍，同时具备可预测的延迟与确定性性能。主要的注意点是每个系统的内存有限：每个晶圆有 44GB的片上内存，因此大型模型必须跨多系统分布。这在机房占地和资本投入方面代价高昂，意味着 Cerebras 可能不会提供最低的每 token 成本。客户可获得超高性能和确定性，但需要为此付出代价。

Cerebras 的商业模式也在很大程度上依赖于 OpenAI 作为客户。这些工作负载可能最初会为 OpenAI 的利益而扩展，这或许可以解释为何其商业模式尚未对外披露。这只是局外人的揣测，并非内部信息。意图可能是服务一个已经同意使用Cerebras 的大客户。如果 Cerebras 与 OpenAI 正在开发的知识产权相关，OpenAI 将需要相应的基础设施来部署它，而 OCI 作为可信的基础设施合作伙伴，将负责实施。

关于 SambaNova，尚未公布日期。其优势包括易于部署且适合使用多个模型的 agent。它具有三层内存设计，结合了 432MB 的片上 SRAM、64GB 的 HBM 和 256GB 到 2TB 的 DDR5内存。据称，驻留在内存中的模型可以在毫秒级完成切换，有助于频繁在模型之间切换的 agent。模型切换变得越来越重要，因为运行大量代码的 agent 团队需要选择不同模型来优化每 token 成本或计算成本。SambaNova的分层内存模型旨在支持这一需求。

据报道，SambaNova 的机架平均功耗约为 20 千瓦，足以通过空气冷却。这意味着它们可以适配大多数现有数据中心，而无需液冷。公司声称支持 10 兆亿参数模型和 1000 万 token 的上下文窗口，且拥有比 GPU低三倍的总拥有成本。不过这些基准数据是公司自报的，我并不了解有公开基准可以支持这些说法。SambaNova 还使用 HBM2e，而不是更新一代的 HBM3，并寄希望于其架构能弥补代际差距。目前尚不清楚其架构是否足够优于GPU。SambaNova 也是相对较小的厂商，带来耐久性风险，并且有关于英特尔可能收购其的讨论。

另一款已可用的产品是 Positron 的 Atlas。Atlas 今天已在 OCI 上普遍可用，而 Positron 的 Titan 产品预计在 2027 年推出。Atlas 被描述为基于 ASIC 的系统，能效较高且易于采用，通过与OpenAI 兼容的 API 支持开源 Hugging Face 模型。这一点很重要，因为企业客户越来越倾向于使用开源模型以优化成本。Positron 针对 Llama 3.1 80亿参数模型发布了头条级别的结果，其优势似乎在于更小规模的模型。这类模型可用于部门级的项目，当大型模型并非必需时，可使部署更高效且可能成本更低。Positron是小型厂商、规模有限，但其专注于易于采用的开源模型具有吸引力，并可能使其在边缘计算用例中也具备实用性。

Q:你认为最新 GPT 6.1 版本的超速模式为何使用 NVIDIA GPU 而非 Cerebras 硬件？早期 GPT 5.6 的超速模式据称使用了 Cerebras 并达到了约 750 token/s，而 GPT 6.1 的 NVIDIA 支持模式大约为 300 token/s。

A:我不会过分解读这个。如果 OpenAI 发现了严重问题，Cerebras 可能就不会成为该合作的一部分。OpenAI 还需要与 NVIDIA 保持良好关系，而 NVIDIA 是其投资者之一。OpenAI可能在为不同模型或不同硬件/GPU 平台并行推进路线。目前 OpenAI 和 Cerebras 都没有给出正式解释，眼下也没有明显的危险信号。Cerebras 可能只是没有可用的产能。GPU 也可能让新模型更快上市，因此 OpenAI可能在快速上线时使用 GPU，而待 Cerebras 的部署赶上来。

大型模型需要大量的 Cerebras 硬件，因为每片晶圆只有 44 GB 的片上内存。据报道 GPT 5.6 在 70 到 100 片晶圆上以每晶圆一层模型的方式运行。GPT 6.1 的上下文窗口扩展到 500,000 token，因此对长上下文的内存需求对片上内存设计造成了额外压力。NVIDIA 可以通过片外的 HBM 进行扩展。如果 GPT 6.1 的上下文窗口大幅增长，连接大量 Cerebras 晶圆级芯片可能成为瓶颈。

这是一个先有鸡还是先有蛋的权衡。Cerebras 可以在晶圆上共置内存，但随着模型变得更强大，它无法在单片晶圆上装入足够的内存来支持非常大的上下文窗口。要解决这些内存限制，就需要连接更多的 Cerebras 晶圆级芯片。
