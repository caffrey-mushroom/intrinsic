专家访谈纪要：北美企业AI应用、预算与实施趋势

1. 北美企业AI应用与规模化进展

a) 北美企业AI应用是否正在加速，更多项目是否已从试点进入生产环境？

  • 北美企业采用AI的范围仍在扩大，越来越多客户已经部署概念验证（POC）或试点项目。
  • 当前市场已经从“是否尝试AI”进入“如何规模化应用AI”的阶段。
  • 从试点进入全企业规模化应用仍然困难，主要障碍包括：
  1. 难以证明可持续的财务价值和业务价值；
  2. Token及整体运营成本缺乏可预测性；
  3. 跨部门流程涉及复杂的治理、审批和责任划分；
  4. 员工采用率不足，技术部署后可能无法得到充分使用。
  • 营销等局部职能中的AI应用相对容易落地，而财务、人力资源等后台职能涉及更复杂的跨部门协作，规模化难度更高。

b) 试点项目进入企业级规模化应用的成功率大约是多少？

  • 约有三分之一的试点项目能够跨越试点与规模化应用之间的鸿沟。
  • 即平均每部署3个试点项目，约有1个能够在整个组织内扩大应用。
  • 其余项目可能停留在局部场景，或因成本、数据基础、治理和员工采用率等问题未能继续推广。

c) 当前企业AI应用主要集中在哪些场景？

  • 当前应用主要集中在两类领域：
  1. 特定功能场景的实用型智能体
  • 目标明确，服务于单一职能或具体任务。
  • 例如在营销组织中整合创意广告内容、辅助内容生产或优化营销流程。
  1. 多智能体编排及端到端流程协调
  • 面向需要多个团队参与的企业流程。
  • 涉及审核、审批、治理、决策以及不同平台之间的协同。
  • 需要建设知识层、本体层、向量数据库和索引体系。
  • 第二类场景的价值空间更大，但建设难度、投入规模和组织协调复杂度也更高。

2. AI预算、Token支出与未来趋势

a) AI项目规模化后，Token使用量和实际支出是否增长？

  • 对于已经落地并在全企业推广的项目，Token使用量和整体支出通常会明显增长。
  • 项目规模扩大后，总拥有成本（TCO）并不透明，客户难以准确预测资本性支出和运营支出。
  • 根据实际项目经验，全面扩展后的平均实际支出通常比原预算高约25%。
  • 超支的主要原因包括：
  1. 大模型定价和商业模式缺乏透明度；
  2. 企业对调用量和Token消耗估计不足；
  3. 上下文层、数据检索和嵌入内容持续扩大；
  4. 安全、治理、数据基础设施和系统集成成本被低估。

b) 2025年至2027年的企业AI预算呈现怎样的趋势？

  • 2025年，许多企业希望快速进入AI领域，重点是启动首批试点和应用场景。
  • 由于早期项目范围较小、规模有限，当时成本相对可控。
  • 过去一年，客户开始重新评估此前大量试点究竟创造了多少实际价值，并逐步认识到：
  1. 长期成本和预算压力较大；
  2. 企业级实施难度高；
  3. 从局部试点扩大到全组织应用并不容易。
  • 预计2026年和2027年整体AI支出将基本保持平稳，而非继续高速增长。
  • 支出重点将从“追逐增长”转向“强调价值”，并非简单削减AI预算。
  • 到2027年，客户会更加关注能够在短期内提升效率、降低成本的项目，并以此建立更可预测的价值框架。

c) 企业AI应用场景的预算导向发生了什么变化？

  • 此前的应用场景更多偏向收入增长，例如：
  1. 获取更多客户；
  2. 进入新市场；
  3. 利用非传统第三方数据源创造增长机会。
  • 当前客户更关注生产力、效率和成本节约，例如：
  1. 优化现有职能流程；
  2. 改善企业后台运营；
  3. 减少未来新增岗位需求；
  4. 将资源重新配置到更高价值领域。
  • 企业并非停止投入，而是要求每项AI投资都能对应更清晰、更可衡量的价值。

d) AI前期资本投入和后续运营支出分别来自哪里？

  • AI项目的前期资本投入通常来自企业现有预算，而非完全新增预算。
  • 客户更偏好能够直接改善利润、且投入相对可预测的项目。
  • 例如，某项业务原本每年投入100万美元，如果AI项目可降低20%的成本，则可以形成20万美元的短期可量化收益。
  • 后续运营支出更多属于新增成本，主要包括：
  1. Token使用成本；
  2. 存储和计算成本；
  3. 模型及平台订阅成本；
  4. 持续维护、安全和治理成本。
  • 很多企业在完成前期资本投入后，才意识到财务报表中新增了一项持续性的“Token运营支出”。

3. 企业规模化部署的架构与组织挑战

a) 与2025年相比，客户是否更清楚希望利用AI解决什么问题？

  • 当前企业各职能部门对AI及智能体的应用场景已经具备一定认知。
  • 市场营销、IT、人力资源和财务等部门通常已经开展过某种形式的POC或试点。
  • 客户现在面临的主要问题已不再是“AI能做什么”，而是：
  1. 如何以适当方式扩大应用规模；
  2. 如何将多个局部应用整合为企业级能力；
  3. 如何建立统一的数据、知识与治理体系；
  4. 如何明确投资主体和责任主体。

b) 为什么跨职能场景比单一职能场景更难部署？

  • 发票对账、薪资管理等流程往往同时涉及人力资源、财务和第三方供应商。
  • 跨职能场景需要：
  1. 更多部门之间的流程协同；
  2. 更复杂的上下文结构；
  3. 更完善的向量数据库和索引；
  4. 跨平台的数据调用和权限管理；
  5. 统一的审核、审批和治理机制。
  • 当AI从某个业务单元的工具升级为整个组织的能力后，“由谁出资、由谁负责”通常会成为重大挑战。

c) 企业级知识层和本体层的投资回报周期有多长？

  • 企业级知识层并非短期即可产生回报的项目。
  • 人力资源、财务、技术和市场营销等部门必须就建设目标和使用方式形成共识。
  • 第1年通常难以取得正向收益。
  • 项目可能需要到第3年至第5年才能实现盈亏平衡，并在此基础上继续扩大价值。
  • 因此，企业需要在最高层面明确AI愿景、目标、潜在机会和衡量框架。

4. ROI衡量与组织运营模式变化

a) 企业对AI项目的ROI要求是否提高？

  • 企业并非单纯提高传统财务ROI门槛，而是正在改变AI价值的衡量方式。
  • 在北美，企业通常不会公开将“裁员人数”作为AI项目的主要指标，因为相关话题较为敏感。
  • 当前更常见的衡量方式包括：
  1. 节省工时；
  2. 避免新增招聘；
  3. 重新配置人力和预算；
  4. 提升现有员工产能；
  5. 将资源投入更高价值的能力领域。

b) 企业如何通过AI重新配置人力资源？

  • 某大型公用事业公司原本计划通过项目节省100万工时，并减少约80人的人员需求。
  • 该公司CIO并未将目标定义为裁减80个岗位，而是希望将未来一年原本用于招聘80人的预算重新配置到其他业务或能力领域。
  • 这与直接将100人的团队压缩至20人存在本质区别。
  • 企业更倾向于：
  1. 取消部分新增岗位；
  2. 将节省的预算用于更重要的招聘；
  3. 对现有员工进行培训和认证；
  4. 推动员工技能提升和岗位转型。

c) AI对传统技术岗位会产生什么影响？

  • 例如，一个原本拥有5名数据工程师的团队，采用生成式AI后可能仅需3人即可维护代码库。
  • 企业未必直接裁减其余2人，而可能将节省出的资源用于：
  1. 招聘更高水平的数据工程师；
  2. 提升其他技术领域能力；
  3. 推动现有员工向更高价值岗位转型。
  • AI带来的核心变化是资源重新部署，而不一定是简单减少人员总数。

d) 客户最担心AI部署带来哪些问题？

  • 客户的主要顾虑集中在以下三方面：
  1. 成本问题
  • 包括实施服务、Token使用、现有员工投入时间，以及项目对正常运营的干扰。
  1. 运营模式问题
  • 当智能体释放团队产能后，企业应裁员、重新配置人力，还是调整未来岗位规划。
  1. 采用率问题
  • 企业担心投入大量咨询和技术成本后，员工不使用相关工具，导致项目被搁置和投资浪费。

5. 成本控制与模型选择

a) 企业在预算受限时会如何控制AI成本？

  • 所有客户都希望使用更便宜的模型，但模型价格只是总拥有成本的一部分。
  • 技术成本之外，还包括数据、系统集成、安全、治理、组织变革和人员投入等成本。
  • 最有效的成本控制方式不是单纯优化模型，而是首先明确具体使用场景。
  • 企业需要清楚界定：
  1. 哪些功能是真正必需的；
  2. 哪些数据需要纳入上下文；
  3. 哪些流程不需要调用大模型；
  4. 哪些环节需要人工审批。
  • 如果使用场景不清晰，企业容易将过多内容纳入上下文层，进而推高检索、嵌入和Token成本。
  • 专家建议在设计阶段充分定义需求；按照访谈口径，前期每投入1单位设计精力，可能节省约10单位的后续实施或平台成本。

b) 北美企业通常如何选择模型？

  • 大多数客户并未采用特别复杂的模型评估框架。
  • 由于长期成本难以预测，客户通常优先选择自己熟悉的技术生态。
  • 典型选择逻辑包括：
  1. 已使用Azure和Databricks的企业，倾向于在相应平台上构建模型；
  2. 已使用AWS的企业，倾向于继续在AWS上部署；
  3. 已使用GCP的企业，倾向于采用Gemini。
  • 约10年前云迁移时期形成的供应商选择，正在产生连锁效应，形成生态系统和供应商锁定。
  • 当前转换成本仍然较高，但未来可能下降，因为客户会要求云服务商和AI供应商提供更透明、更可预测的成本体系。

c) 企业应用是否需要最先进的前沿模型？

  • 大多数企业初期应用并不需要最先进的前沿大模型。
  • 典型需求是加速或改进已有的重复性流程，例如将处理效率改善50%至60%。
  • 对此类应用而言，客户触达、原生集成、治理、安全和既有数据访问能力，可能比模型本身的领先程度更重要。
  • 模型能力并非不重要，但在大量企业应用中并不是唯一或最主要的决策因素。

d) 微软Copilot在企业市场具有什么优势？

  • 微软的优势来自Office、Teams、Outlook、Word和Active Directory等产品形成的完整企业生态。
  • 对于政策查询、会议摘要和企业知识管理等简单场景，Copilot可以原生访问相关文档，实际效果较好。
  • 如果企业已经全面采用微软软件栈，继续使用微软产品在治理、安全和集成方面具有明显便利。
  • 微软在公共部门和政府机构中也具有较强优势，这类客户风险偏好低、技术体系更换速度慢，有助于微软获得稳定且可预测的收入。
  • 但对于需要整合企业第一方数据、ERP和第三方数据源，并进行自然语言查询和对话式分析的场景，Databricks Genie等产品可能更合适。
  • 最终产品选择仍应取决于具体应用场景，而非单纯依赖某一家供应商。

6. 企业AI价值链中的高增长环节

a) 哪些AI相关支出增长最快？

  • 预计增长最明显的领域主要有两个：
  1. 系统集成、战略与实施服务
  2. 数据基础设施、安全与治理
  • 专家所在机构面向客户的战略和实施服务业务，今年预计同比增长约17%。
  • 明年实施服务的增长目标约为25%。

b) 为什么系统集成和实施服务会保持较快增长？

  • 越来越多客户已经完成POC，下一步需要将其扩展到全企业。
  • 部分客户自行开展POC后效果不理想，需要咨询公司介入完善。
  • 另一些客户已验证需求并形成内部推广意愿，但缺少规模化部署能力。
  • 因此，未来服务需求将更多来自：
  1. 修复效果不佳的试点；
  2. 扩大已验证项目的部署规模；
  3. 建立跨部门的知识层和治理体系；
  4. 推动组织采用和运营模式调整。

c) 为什么数据基础设施投入会增加？

  • AI从营销等单一部门推广到整个组织，需要从根本上调整企业数据模型。
  • 企业需要建设：
  1. RAG管道；
  2. 向量数据库；
  3. 更灵活的数据关系和上下文结构；
  4. 企业级知识层和本体层。
  • 传统数据架构通常以仪表盘和主键、外键关系为核心，而AI时代的数据组织方式更强调语义、上下文和复杂关系。
  • 许多客户对这些技术仍较陌生，因此需要新增基础设施和实施投入。

d) AI为什么会放大企业原有的数据问题？

  • AI能力无法掩盖个人身份信息（PII）未脱敏、安全缺口或数据质量问题。
  • 相反，AI会扩大数据访问和使用范围，从而放大原有风险。
  • 企业要获得预期结果，必须先夯实数据基础，并同步完善安全和治理机制。

7. AI安全、可信与负责任AI

a) 企业是否正在增加AI安全投入？

  • 预计安全支出将显著增加。
  • 近期多起服务中断虽然并非网络攻击，但强化了企业对系统韧性和安全风险的关注。
  • 网络安全需要持续领先威胁一步，而AI带来的部分风险此前从未出现，传统最佳实践未必能够完全覆盖。

b) 哪些安全领域最具增长潜力？

  • 未来重点增长领域包括：
  1. 数据安全；
  2. 红队测试；
  3. 威胁检测与监控；
  4. 负责任AI；
  5. AI可信框架；
  6. 隐私、治理和决策标准。
  • 数据安全本身并非新领域，但仍将长期保持良好需求。
  • 负责任AI和AI可信业务增长会更加显著，相关业务今年已经快速增长，未来几年预计还会进一步扩大。

c) 人类与智能体协作将带来哪些治理要求？

  • 企业的人员结构将从单纯由人类组成，转向人类与智能体共同协作。
  • 隐私和治理部门需要制定明确的准则、政策和决策框架，区分：
  1. 哪些工作可以由智能体自主运行；
  2. 哪些工作需要人工审批；
  3. 哪些结果必须由人审查；
  4. 哪些关键决策必须由人推动。
  • 该问题目前仍被明显低估，但几次严重事故就可能阻碍企业整体AI发展。

8. 咨询公司、技术供应商与前沿部署工程师

a) 咨询公司的前沿部署工程师与技术供应商的工程师有何区别？

  • 咨询公司与Anthropic、OpenAI等模型厂商正在建立合作伙伴关系。
  • 咨询公司员工可以接受模型厂商培训和认证，补充内部技能缺口。
  • 从技术能力看，咨询公司的前沿部署工程师与供应商内部工程师差异有限。
  • 两类人员都会逐渐熟悉特定厂商的产品和技术，不可能同时精通所有技术栈。
  • 咨询公司工程师的主要差异在于：
  1. 更了解客户的业务背景；
  2. 更关注项目最终产生的业务成果；
  3. 能够基于多个客户项目进行横向观察；
  4. 更擅长将技术能力与组织流程、ROI和运营模式结合。

b) 增加前沿部署工程师数量是否有助于提升企业AI渗透率？

  • 增加具备认证和实施经验的工程师，有助于提升可部署人才供给。
  • 模型厂商希望借助大型咨询公司的员工网络接触更多客户，并要求咨询人员能够使用其产品和技术语言。
  • 因此，咨询顾问接受厂商培训确实有助于提高产品在不同客户中的渗透率。
  • 但渗透率提升并不只是前沿部署工程师数量增加的结果。
  • 更重要的需求侧驱动因素包括：
  1. 咨询公司与模型厂商建立正式合作关系；
  2. 双方共同创造客户机会；
  3. 围绕具体合同和交易联合销售；
  4. 利用咨询公司的客户触达能力推动规模化采用。
  • 人才扩张主要解决供给侧问题，而合作伙伴关系和共同销售才是需求侧的核心驱动力。

c) 为全体咨询员工配置AI工具可能面临什么问题？

  • 为员工配置Claude等工具可以帮助咨询公司建设技能体系，并满足客户对AI能力的要求。
  • 但大型咨询公司可能低估为数十万名员工提供许可证的总成本。
  • 例如，拥有约70万名员工的组织，为全员配置AI工具会形成显著的持续性费用。
  • 咨询公司自身同样需要面对AI工具成本、采用率和投资回报问题。

9. 公共部门与Palantir相关判断

a) 如何看待Palantir企业业务剩余履约义务增长放缓？

  • 专家并不了解Palantir本季度增长放缓的具体原因，因此无法判断是合同金额下降还是合同数量减少。
  • 从其自身经验看，美国政府相关业务近期存在较大不确定性。
  • 受政府削减支出影响，部分公共部门合同出现缩减，相关咨询业务也经历了人员转岗和裁员。
  • 如果企业收入高度依赖美国政府，业务可能面临较强波动。

b) 公共部门业务的增长属性如何？

  • 公共部门业务通常较为稳定，但更多属于运营型项目。
  • 该领域一般随通货膨胀温和增长，较难长期实现20%、30%或40%的高速增长。
  • 一旦某一公共部门垂直领域趋于饱和，后续增长空间可能接近上限。
  • 相比之下，银行、金融服务、零售和消费品等行业更容易产生高收益增长型项目，但这些行业也具有更明显的周期性。
  • 专家所在机构的公共部门业务占比已有所下降，目前未观察到该领域存在明显增长。
